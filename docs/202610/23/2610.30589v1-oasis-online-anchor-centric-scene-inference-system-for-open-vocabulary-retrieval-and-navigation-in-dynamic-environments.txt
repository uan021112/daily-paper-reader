Abstract
Reliable robotic mapping in dynamic real-world environments is
essential for embodied intelligence and long-term autonomy. How-
ever, existing methods often involve a trade-off: lightweight online
mapping is efficient but captures limited semantic context, while
dense mapping provides richer semantics at higher computational
cost and is more vulnerable to distractors. They also struggle to
relocalize objects after scene changes. To address these challenges,
we propose the Online Anchor-centric Scene Inference System (OA-
SIS), a unified system for online mapping, complex open-vocabulary
retrieval, and navigation in dynamic environments. Motivated by
the observation that indoor scenes are organized around stable se-
mantic anchors, OASIS represents the environment using a sparse
set of anchor nodes, each maintaining a unified multimodal rep-
resentation that integrates semantic descriptions, visual features,
and geometric states for reasoning, verification, and navigation.
Its compact anchor-centric memory supports on-demand evidence
extraction and hierarchical retrieval, reducing redundant storage
while improving retrieval reliability. To handle scene dynamics,
OASIS further reuses transient observations collected during navi-
gation to relocalize moved objects. Experiments in both simulation
and real-world environments, including standard retrieval bench-
marks and navigation tasks under both static and dynamic settings,
demonstrate that our system can perform complex open-vocabulary
retrieval and navigation, while also enabling relocation of displaced
objects after scene changes.

Introduction
Modern embodied agents face increasingly complex tasks in un-
structured environments, where instructions involve rich, open-
vocabulary descriptions beyond simple object categories. A user
might command a robot to “find the sealed silver can on a round
table” or “locate the bed with a lit lamp.” Fulfilling such requests
requires a scene representation that transcends traditional geomet-
ric mapping, demanding fine-grained attribute recognition (e.g.,
color, material, state) and spatial relationship reasoning. Crucially,
these capabilities must remain robust in dynamic real-world set-
tings where objects are frequently repositioned. Consequently, the
challenge has shifted from static mapping to constructing a dy-
namic, semantic-rich scene graph capable of supporting intricate
queries and adapting to environmental changes on the fly.
However, deploying semantic maps in real-world systems still
involves a practical trade-off between efficiency and reasoning capa-
bility. Dense mapping approaches [6, 18, 28] embed rich semantics
into many spatial elements, providing detailed understanding but
sometimes introducing clutter and distractors, while also requiring
relatively high computational and memory resources. Conversely,
lightweight methods [9, 15] are more efficient, but may not preserve
enough spatial context for complex reasoning, making it harder to
distinguish visually similar objects based on their surroundings or
attributes. A remaining challenge appears in dynamic environments.
Although some methods address object relocalization, they often
depend on repeated re-observation. During active navigation, rapid

To bridge this gap, we propose the Online Anchor-centric Scene
Inference System (OASIS) for robust open-vocabulary retrieval
and dynamic object relocalization. As illustrated in Figure 1, OA-
SIS avoids processing redundant context globally through an on-
demand retrieval strategy. Our key insight is that indoor envi-
ronments are inherently structured around stable, large-scale ob-
jects (e.g., beds, tables, sofas), which we define as semantic an-
chors. Inspired by human episodic memory, OASIS constructs an
anchor-centric graph rather than a dense per-pixel map, retaining
only salient semantic descriptions and high-quality representa-
tive frames. During retrieval, a Large Language Model (LLM) first
reasons over the semantic anchors to filter irrelevant regions, fol-
lowed by on-demand Vision-Language Model (VLM) verification
of the retrieved representative frames. This strategy keeps memory
lightweight while preserving the ability to distinguish fine-grained
visual attributes. In dynamic settings, OASIS additionally main-
tains transient observations along the navigation trajectory in a
lightweight buffer; if a target is missing at its initial anchor, the sys-
tem queries this buffer and re-verifies candidate views for reliable
relocalization.
Our main contributions are summarized as follows:
• We present OASIS, an online anchor-centric scene infer-
ence system that unifies online mapping, open-vocabulary
retrieval, and navigation in dynamic environments.
• We propose a human-inspired episodic memory cura-
tion mechanism that uses scale-aware scoring and spatio-
semantic clustering to select representative frames, yielding
a multimodal anchor-centric scene graph with integrated
semantic, visual, and geometric representations.
• Built upon this scene graph, OASIS supports hierarchical
coarse-to-fine retrieval and view-driven navigation, and
introduces a Transient Visual Buffer to reliably relocalize
moved objects after scene changes.
• We conduct extensive simulation and real-world experiments
on retrieval and navigation under static and dynamic set-
tings, demonstrating strong performance and reliable object
relocation after scene changes.

Related Work
2.1
Open-Vocabulary 3D Scene Understanding
Closed-set semantic mapping relies on detectors trained for fixed
object categories [8, 16, 17, 24]. Open-vocabulary methods instead
distill features from vision-language models (e.g., CLIP [20]) into
3D representations. Dense mapping methods [6, 18, 28] project
pixel-aligned features into 3D space, enabling fine-grained queries
but incurring high computational and memory costs. Conversely,
object-centric or lightweight semantic point cloud methods [9, 15]
construct sparse maps by aggregating features at the instance level.
While these approaches are significantly more efficient, they of-
ten discard the surrounding visual context required for complex
reasoning. Our work builds upon the efficiency of lightweight repre-
sentations but augments them with an implicit storage mechanism
to retain rich contextual details without the overhead of dense
fields.
2.2
Retrieval and Reasoning on Scene Graphs
Recent advancements in open-vocabulary scene understanding
have focused on reasoning about and locating objects within com-
plex environments using foundation models. Early approaches pri-
marily utilized CLIP-based matching [6, 19, 26, 27], which directly
computes cosine similarity between text queries and stored visual
features. While efficient for simple identification, these methods
lack the capability for multi-step reasoning or handling spatial
relationships. To overcome these limitations, LLM-based meth-
ods [7, 13, 23, 28, 31] leverage the reasoning power of LLMs to
infer potential locations or generate navigation plans based on
textual abstractions of the scene. However, relying solely on text
descriptions often results in the loss of critical visual details (e.g.,
object states or specific textures) necessary for precise identifica-
tion. More recently, VLM-based approaches [18, 35] have emerged,
directly processing images to retain visual fidelity. Despite their
superior understanding, these methods typically suffer from high
latency and computational costs, making them less practical for
real-time applications. Our work bridges these gaps by introducing
an efficient VLM-driven mechanism that operates on implicit stor-
age, enabling detailed visual reasoning without the heavy overhead
of full-image processing.

2.3
Object Navigation
Object navigation requires agents to locate and move towards spe-
cific target instances within an environment [2, 3, 5, 12, 14, 21, 30,
32–34]. Traditional approaches typically rely on static semantic
maps, assuming that objects remain fixed throughout the mission.
These methods combine SLAM with semantic segmentation to build
a persistent representation, allowing the agent to plan paths to pre-
viously observed locations. However, real-world environments are
inherently dynamic. Existing works on dynamic navigation [9, 27]
typically address this by relying on continuous fine-grained mod-
eling and geometric matching of objects along the trajectory to
update the map. This strategy faces significant challenges: navi-
gation often involves transient observations, making it difficult to
capture and update the state of small objects accurately in real-time.
Furthermore, when a target is missing from its expected location,
these methods often lack the active reasoning capability to deduce
its whereabouts. In contrast, our proposed method leverages sub-
tle visual details observed along the path, enabling the system to
infer the new location of displaced objects based on semantic con-
text, even if the new location lies outside the immediate navigation
trajectory.
3
Method
3.1
Overview
As illustrated in Figure 2, OASIS addresses the challenge of simul-
taneous online mapping and open-vocabulary retrieval in dynamic
environments. From the RGB-D stream and robot localization, it
first performs online semantic mapping [9] to maintain an instance
set, identify stable anchors, and associate observations with an-
chors; in parallel, it curates a compact episodic memory through
spatial-visual clustering and scale-aware scoring that adaptively bal-
ances local fidelity and global richness to keep only high-value rep-
resentative frames; finally, it fuses anchors, representative frames,
structural relations, and navigable poses into the OASIS graph
for coarse-to-fine candidate retrieval, VLM-based verification, and
navigation, while a relocation branch handles target relocaliza-
tion when objects are moved. For full reproducibility, exhaustive
implementation details—including complete LLM/VLM prompts,
exact mathematical formulations, and hyperparameter settings—are
provided in Appendices B–G.
3.2
Episodic Memory Curation
Inspired by the human cognitive process of episodic memory, which
retains only significant events and high-quality visual snapshots
rather than continuous redundant streams, we design a dynamic
memory curation mechanism. This module processes the input
frame sequence F = {𝑓1, 𝑓2, . . . } to maintain a set of spatial-visual
clusters C = {𝐶1, . . . ,𝐶𝑁}, where each cluster 𝐶𝑘is represented by
a single optimal frame 𝑟𝑘.
LLM-Driven Anchor Definition. Prior to memory curation,
we explicitly define the set of target objects—termed Anchor Ob-
jects—to align with human spatial cognition. Instead of manual
selection, we leverage an LLM to identify object categories that
satisfy three key criteria: (1) Volumetric Prominence (occupying
significant space), (2) Stationarity (structurally static or heavy), and
(3) Associative Utility (serving as natural landmarks for referenc-
ing nearby items). This LLM-driven approach ensures our system
can generalize across diverse indoor environments by focusing on
semantically stable landmarks (e.g., bed, sofa) while filtering out
less informative observations to keep the representation focused.

3.3
Anchor-Centric Scene Graph Construction
Building upon episodic memory, we construct the Anchor-Centric
Scene Graph (the OASIS graph). This process integrates dense 3D
information from the geometric mapping stream with high-quality
visual snapshots from the memory stream into a unified multimodal
representation.

3.4
Hierarchical Object Retrieval
Leveraging the structured OASIS graph, we propose a three-stage
coarse-to-fine retrieval algorithm. This approach avoids the compu-
tational cost of scanning the entire scene by prioritizing semanti-
cally relevant anchors before performing detailed visual verifica-
tion.
Stage 1: Semantic Anchor Proposal (LLM-based). Given a
user query Q (e.g., “Find the mug near the laptop”), the system first
reasons about the most probable locations using only the textual
layer of the OASIS graph. An LLM functions as a planner, taking the
query and the global anchor list as input. For each anchor 𝐴𝑖, the
LLM analyzes its semantic category and the summary of its related
objects (both supported-list and nearby-list). The LLM outputs a
ranked list of candidate anchors A𝑐𝑎𝑛𝑑(Top-3 by default) where
the target is most likely to appear. This step purely relies on textual
reasoning, effectively pruning the search space without processing
any images.
Stage 2: Visual Verification with Cross-Anchor Reason-
ing (VLM-based). The system iterates through candidate anchors
in A𝑐𝑎𝑛𝑑. For each queried anchor 𝐴𝑖, it retrieves representative
frames and projects 2D boxes with IDs for all visible anchors (not
only 𝐴𝑖), enabling cross-anchor disambiguation in shared views
where multiple anchors co-occur. The VLM then verifies target pres-
ence for query Q, identifies the associated anchor 𝐴𝑠𝑒𝑙𝑒𝑐𝑡𝑒𝑑(which
may differ from 𝐴𝑖), and outputs the selected anchor ID, the target
relation to 𝐴𝑠𝑒𝑙𝑒𝑐𝑡𝑒𝑑(i.e., self, on, or nearby), and a detailed visual
description with predicted class for subsequent instance matching.
Stage 3: Precise Instance Localization (CLIP-based). Once
the VLM confirms a detection and identifies the reference anchor
𝐴𝑠𝑒𝑙𝑒𝑐𝑡𝑒𝑑, we map the high-level perception back to a specific 3D
instance UID (𝑢𝑡𝑎𝑟𝑔𝑒𝑡). When the returned relation is self, the
UID of 𝐴𝑠𝑒𝑙𝑒𝑐𝑡𝑒𝑑is directly returned. Otherwise, for relations on or
nearby, we retrieve the corresponding candidate list (the supported-
list or nearby-list) from node 𝐴𝑠𝑒𝑙𝑒𝑐𝑡𝑒𝑑and first filter candidates by
the VLM-predicted class. When class-matched candidates exist,
ambiguity (e.g., multiple mugs) is resolved by cosine similarity
between candidate CLIP embeddings and the text embedding of
the VLM-generated Visual Description; when no class match exists
(e.g., open-vocabulary mismatch), we compute CLIP similarity over
the full candidate list and select the highest-scoring instance as the
final target.
Global Fallback Mechanism. In cases where the hierarchi-
cal search fails (i.e., the target is not found in any candidate an-
chor’s view), the system triggers a global fallback. We perform a
global CLIP-based search across all scene instances using the visual
description generated during the failure analysis (or the original
query). To ensure efficiency, instances already examined during
Stage 2 are excluded.

4
Experiments
4.1
Overview
In our implementation, we use GPT-5.2 for LLM planning and Gem-
ini 3 Pro for VLM verification. Since our main contribution is to
improve semantic understanding and dynamic relocation capabili-
ties, our evaluation across diverse retrieval and navigation tasks
focuses on answering three key questions: (1) Complex Retrieval
Capability: Can OASIS accurately retrieve objects based on com-
plex language queries? (2) Dynamic Adaptability: Can the system
effectively relocate objects that have moved after the initial mapping
phase? (3) Component Efficacy: What is the contribution of each
module to the overall performance? Crucially, OASIS preserves the
real-time efficiency required for online operation; detailed system
profiling (e.g., mapping speed and inference latency) is provided in
Appendices D and F.
4.2
Object Retrieval
4.2.1
Experimental Setup. To comprehensively evaluate OASIS, we
conduct experiments on three benchmarks spanning Replica [25],
HM3D [22], and ScanNet [4] scenes, each targeting a different
retrieval capability.
1. Fine-grained Object Retrieval. We utilize the OpenLex3D
benchmark [11] (Replica subset) to assess fine-grained object-level
retrieval performance. Its human-annotated queries cover all scene
objects and combine pure-synonym and synonym+descriptor forms,
including fine-grained pattern, cultural, and brand cues (e.g., “floral
cup”, “ironman portrait”, “nike sneaker”), making the retrieval task
more realistic and challenging.

the left.”), and View-Independent (viewpoint-free; e.g., “The large
cabinets directly above the fridge and oven.”).
Metric: Following CORE-3D [18], we report grounding accuracy at
IoU thresholds of 0.1 and 0.25 (A@0.1, A@0.25).
4.2.2
Results and Analysis. As presented in Table 1, our method
achieves the best performance in Fine-grained Object Retrieval
(6.58 mAP). The margin over DualMap is modest because both meth-
ods share the same instance-level scene construction pipeline. Our
gain mainly comes from finer-grained attribute recognition, which
yields higher feature similarity for the true target and pushes it to
earlier ranks; this improves per-query AP and, consequently, leads
to a slightly higher overall mAP. In Functional Region Retrieval
(Table 2), our method effectively handles this task. Although our
scene graph has no explicit room-level hierarchy, our system deter-
mines functional areas by semantic reasoning over objects around
each anchor together with visual verification of background layout.
Table 3 details the Spatial Relation Retrieval results. Our method
excels in the “Easy” and “View-Independent” splits, outperform-
ing the specialized baseline CORE-3D. This confirms that our LLM
planner effectively resolves local spatial constraints (e.g., “next to”).
In the “Hard” split, CORE-3D remains stronger, which suggests a
natural boundary of our current design. These hard queries often
involve long-range relationships (e.g., “farthest from”) that span
multiple anchors. Because each anchor representative frame usually
captures objects near that anchor, our anchor-centric verification
can be less effective when the required spatial relation is between
far-apart objects.

4.3
Navigation and Relocation
4.3.1
Experimental Setup. We evaluate closed-loop navigation per-
formance on the HM3D dataset [22], adhering to the protocol estab-
lished in DualMap [9]. The evaluation encompasses three scenarios:
Static, where the environment remains unchanged; In-Anchor
Dynamic, where target objects are moved within the same an-
chor region (e.g., shifted on a table); and Cross-Anchor Dynamic,
where objects are relocated to entirely different rooms or distant
anchors. We report Success Rate (SR), defined as the percentage
of queries in which the agent stops within 1 meter of the queried
object. In dynamic scenes, a query is counted as successful only if
the target is found within three attempts.
4.3.2
Results and Analysis. Table 4 summarizes the navigation re-
sults, where our method consistently outperforms all baselines. In
the Static setting, our method achieves an impressive average Suc-
cess Rate (SR) of 85.9%, significantly surpassing DualMap (70.5%)
and ConceptGraphs (61.5%). This substantial performance gain
stems primarily from the superior retrieval accuracy of OASIS.
Our approach also shows clear advantages in dynamic scenarios.
For In-Anchor moves, our method maintains a high SR of 81.5%,
demonstrating robustness to local object displacements. The most
meaningful performance gain, however, is observed in the challeng-
ing Cross-Anchor setting, where our method achieves 77.4% SR
compared to DualMap’s 60.3%. DualMap adopts a strategy of con-
tinuous scene graph updating during navigation, which generally
requires intentional scanning to capture small objects along the
trajectory. By contrast, our Transient Visual Buffer (Sec. 3.5) pas-
sively captures transient object observations during robot transit,
enabling efficient visual relocalization of displaced targets. Even
if no new target location is detected along the navigation path,

4.4.1
Memory Curation Strategy. We analyze the interplay be-

that combines three clustering methods (Spatial-Only, Visual-Only,
Hybrid) with three selection scores (Global, Local, Adaptive Fusion).
We report Instance Coverage, defined as the fraction of ground-

and the average cluster count; all results are averaged over eight
scenes.
As shown in Table 5, Visual-Only clustering yields the fewest
clusters but lower coverage because global CLIP features neglect
spatial structure, causing confusion between distinct yet visually
similar frames and different viewpoints. Spatial-Only provides mod-
erate coverage but cannot distinguish semantically different frames
in close proximity. In contrast, Hybrid achieves the highest coverage
(>89%) across all selection methods with a moderate cluster count.
For frame selection, Local underperforms and Global remains stable,
whereas Adaptive reaches 91.13% coverage, confirming the benefit
of combining global context with local quality.

limited performance (56.6% SR) as pure semantic inference lacks
reliable visual cues. Ablating semantic reasoning achieves moder-
ate results (73.6% SR) but suffers from inefficient random fallback.
In contrast, our full framework integrates both components and
achieves the best performance of 77.4% SR with only 1.6 average
attempts, validating the effectiveness of our dynamic relocalization
mechanism.

5
Conclusion
We introduced OASIS, an online anchor-centric system for open-
vocabulary retrieval and navigation in dynamic environments. Its
multimodal memory and hierarchical LLM–VLM pipeline balance
semantic expressiveness with online efficiency, while transient
navigation observations support moved-object relocalization. Sim-
ulation and real-world experiments demonstrate improvements in
retrieval accuracy, navigation success, and relocalization robustness
over baselines, establishing anchor-centric memory as a practical
foundation for long-horizon embodied intelligence.

Anchor Definition Prompt
To determine the Anchor Object categories, we query the LLM with
the predefined common indoor scene categories from DualMap [9]
and ask it to select only the categories suitable as anchors.
System Instruction: You are an expert in Spatial AI and
Indoor Navigation. Your task is to identify which categories
can serve as “Anchor Objects” from a given category list.
Input: A Python list of category names from DualMap’s
predefined common indoor scene categories.
Selection Criteria:
(1) Large Volume: The object must have a significant
physical footprint.
(2) Immovable: The object is heavy or structurally fixed
(e.g., furniture that is rarely moved).
(3) Cognitive Landmark: Humans naturally use this object
to locate other smaller items (e.g., “The keys are on the
table”).
Negative Constraints (Do NOT include):
• Pure background surfaces such as wall, floor, and ceiling.
• Small movable furniture (e.g., dining chair, stool).
• Any category not present in the provided category list.
Output Format: Return strictly a Python list of strings
containing only selected anchor categories from the input
list, in lowercase. Do not add new categories that are not in
the input. Example output format: [’bed’, ’sofa’,
’wardrobe’, ’refrigerator’]
Using this prompt, our anchor-category output includes: sofa,
table, bed, desk, cabinet, shelf, television stand, refrigerator, oven,
sink, washing machine, dryer, stove, dishwasher, toilet, shower,
bathtub, door, window, air conditioner, heater, dresser, nightstand,
wardrobe, closet, coat rack, staircase, and drawer.

E
Default Top-𝐾Settings
Our system uses three default Top-𝐾settings during retrieval and
relocalization.
Top-3 anchor candidates. In the LLM-based anchor proposal
stage, we keep the top-3 candidate anchors for subsequent verifica-
tion. This choice provides a practical balance between search-space
reduction and retrieval robustness: using too few anchors may pre-
maturely discard plausible target regions, while using too many
anchors increases VLM calls and overall latency.
Top-5 representative frames per anchor. For each anchor, we
retain at most 5 representative frames ranked by frame score. This
setting is intended to preserve diverse yet high-quality observations
of the same anchor without introducing excessive redundancy. In
practice, a small set of representative views is sufficient to cover
common viewpoint variations around stable indoor anchors.
Top-5 transient visual buffer (TVB) relocation candidates.
During dynamic relocalization, we first rank TVB entries by CLIP
similarity and keep the top-5 candidate full frames for VLM veri-
fication. This design limits the verification cost while preserving
enough diversity to recover relocated objects from transient obser-
vations along the navigation path.
Unless otherwise specified, these Top-𝐾values are fixed through-
out all experiments. They were selected based on preliminary de-
velopment experience to provide a reasonable trade-off between
robustness, memory usage, and inference latency.

Retrieval and Relocalization Example and
Latency Analysis
To improve reproducibility, we provide an overview of one full ex-
ample session from retrieval to dynamic relocalization. The detailed
prompt example is provided in Sec. G.
F.1
Prompt Example Overview
Stage 1: LLM-based anchor proposal prompt.
In Stage 1, the LLM takes the user query and structured anchor
metadata as input, then proposes and ranks candidate anchors by
relevance to the target object. The prompt explicitly constrains
the output format and anchor-ID validity, enabling deterministic
downstream parsing.
Stage 2: anchor-based VLM verification prompt.
In Stage 2, the VLM inspects representative frames from the se-
lected anchors and performs fine-grained verification to determine
whether the target can be visually confirmed. The output includes

Kaiyao Liao et al.
completion status, best frame, and target attributes (anchor ID,
relation, class, and compact visual description).
Stage 3: post-navigation target existence verification prompt.
After navigation and camera rotation toward the previously con-
firmed target location, Stage 3 verifies whether the target still exists
in the current view. If not found, the model reports disappearance
and provides a comparison-based explanation between reference
and current observations.
Stage 4: TVB-based candidate re-identification prompt.
When the object is missing at the original location, Stage 4
queries the TVB and re-verifies candidate views for relocalization.
Specifically, the original images of the candidate instances are com-
pared with the target reference image to select the best-matching
relocated candidate.
Stage 5: same-instance relocalization verification prompt.
In Stage 5, the agent navigates to the newly retrieved location
and performs a second verification pass to confirm successful dy-
namic object relocalization. This prompt explicitly checks whether
the current view matches the previously retrieved candidate and
whether the target can be confirmed as the same instance at the
relocated position.
This example illustrates the complete loop: anchor proposal, fine-
grained target verification, disappearance detection, TVB query,
and final dynamic object relocalization verification.

To provide a comprehensive understanding of system perfor-
mance during deployment, we report a stage-wise latency break-
down of the hierarchical retrieval pipeline. Table S3 shows the
average time spent on cloud-based LLM/VLM interactions across

currently dominated by cloud API inference and network I/O (using

scene-graph traversal, node filtering, and TVB updates execute in

of offboard multimodal reasoning models.
Importantly, this latency does not interfere with low-level robot
control. Our architecture decouples high-level semantic reasoning
from low-level motion execution: the API-induced delay occurs
during the reasoning and verification phase, while the underlying
navigation stack runs locally on the compact scene graph. Moreover,
passive observations for the TVB are processed locally during move-
ment without requiring heavy VLM calls, ensuring uninterrupted
navigation. Therefore, the reported latency should be understood
primarily as a deployment artifact of cloud-based multimodal mod-
els rather than a structural limitation of the OASIS framework.
As edge-side multimodal models continue to improve, the same
pipeline can be migrated to onboard deployment with substantially
lower reasoning latency.
