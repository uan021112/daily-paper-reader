## 摘要
点云 Transformer 旨在以可控的计算成本捕获精细的局部几何结构及场景内的关系。两种常见方法是窗口注意力和全局注意力。二者在实现全场景交互的方式上有所不同；全场景交互是指场景中不同位置的 token 之间交换信息。窗口注意力将自注意力限制在称为窗口的 token 组内，从而降低计算成本；在序列化设计中，每个窗口包含空间排序序列中固定数量的连续 token。由于每个模块仅直接连接同一窗口内的 token，跨窗口的信息交换依赖于不同模块间窗口成员关系的变化以及分层池化。相比之下，全局注意力直接连接场景中的所有 token，但当 token 数量较大时，对所有 token 对计算注意力的成本可能很高。为平衡计算成本与全场景交互，我们提出 MixPT，这是一种点云 Transformer，采用交错的窗口注意力与全局注意力模块，同时为窗口注意力模块保留单一且固定的序列化模式。对于 token 数量较多的场景，MixPT 对空间池化后的 token 应用全局注意力，并将残差更新传回原始分辨率的特征流。在室内和室外基准测试中，与具有代表性的窗口注意力和全局注意力基线相比，MixPT 以更低的延迟实现了具有竞争力的准确率。我们进一步展示了通过重复交错的窗口注意力和全局注意力模块模式，在深度方向扩展注意力阶段的可行性。

## Abstract
Point cloud transformers aim to capture detailed local geometry and relationships across a scene at a manageable computational cost. Two common approaches are window attention and global attention. They differ in how they enable scene-wide interaction, which refers to information exchange among tokens across a scene. Window attention reduces computational cost by restricting self-attention to groups of tokens called windows; in serialized designs, each window contains a fixed number of consecutive tokens from a spatially ordered sequence. Because each block only directly connects tokens within the same window, information exchange across windows relies on changes in window membership across blocks and hierarchical pooling. Global attention, in contrast, directly connects all tokens within a scene, but computing attention over all token pairs can be costly when the number of tokens is large. To balance computational cost and scene-wide interaction, we introduce MixPT, a point transformer that uses a mix of window and global attention blocks in an interleaved schedule, while retaining a single fixed serialization pattern for its window blocks. For scenes with a large number of tokens, MixPT applies global attention to spatially pooled tokens and returns residual updates to the original-resolution stream. Across indoor and outdoor benchmarks, MixPT achieves competitive accuracy with lower latency than representative window and global attention baselines. We further demonstrate the feasibility of scaling the attention stage in depth by repeating the interleaved pattern of window and global attention blocks.

## 1. 核心问题与整体含义

- **研究问题：**点云 Transformer 需要在捕获局部几何细节和实现跨场景信息交互之间取得平衡。
  - **窗口注意力**只在固定大小的 token 窗口内计算，成本较低，但不同窗口之间不能直接交换信息；已有序列化方法通常依靠改变各层的序列化顺序和层级池化来促进跨窗通信。
  - **全局注意力**可直接让场景中任意 token 交互，但 token 数量较大时，对所有 token 两两计算注意力会带来较高的计算和内存开销。
- **论文观察与动机：**作者分析发现，窗口注意力模型即使经过多层传播，也未必能让所有 token 在结构上互相可达；而全局注意力虽然每层都具有全场景支持，其实际注意力权重在某些层仍可能集中于局部区域。因此，未必需要每一层都使用全局注意力。
- **整体思路：**提出 MixPT，在固定序列化顺序的窗口注意力块之间周期性插入全局注意力块，以较少的全局交互实现跨窗口直接通信。对于大规模场景，再先将 token 空间池化后执行全局注意力，以控制其成本。

## 2. 方法论

### 2.1 整体架构与注意力安排

- MixPT 保留 LitePT 的高分辨率稀疏卷积编码阶段和主要解码结构，将原有多个注意力阶段合并为一个注意力阶段，移除中间池化转换及相应的解码上采样。
- 在注意力阶段中：
  - 所有窗口块复用**同一种固定序列化顺序**，默认采用 Trans Z-order（TZ）。
  - 窗口块（W）和全局块（G）按周期性交错方式排列。MixPT-S 的默认八块布局为 **WWGWWGWW**，即六个窗口块、两个全局块。
- 固定顺序可复用序列化和窗口索引映射，减少不同层之间反复重排 token 的开销；全局块则提供跨固定窗口的直接信息交换。

### 2.2 窗口注意力

- 将空间序列化后的连续 token 按固定窗口大小 \(N_w\) 分组，每个窗口独立计算自注意力。
- 其注意力交互复杂度由全局注意力的 \(O(N^2)\) 降为约 \(O(NN_w)\)，其中 \(N\) 为 token 数量。
- 每个窗口块采用标准 pre-norm 残差结构：先对输入特征做 LayerNorm，再执行窗口内自注意力并加残差，随后经过 LayerNorm 和 MLP，再加残差。
- 默认窗口大小为 **1,024 个 token**。所有窗口块在整个注意力阶段使用相同的序列化顺序，而不是像部分先前方法那样逐块改变顺序。

### 2.3 带空间池化的全局注意力

- token 数量较少时，可在原分辨率上直接计算全局注意力；token 数量较多时，MixPT 在全局块前进行空间网格池化。
- 具体流程为：
  1. 将原分辨率 token 按池化网格聚合，得到较少的粗尺度 token；
  2. 在粗尺度 token 上计算全局自注意力，并执行 MLP；
  3. 将全局块产生的残差更新投影回原分辨率，并广播至对应网格中的 token；
  4. 与原始分辨率特征流的残差相加。
- 池化步幅记为 \(s\)：\(s=1\) 表示不池化，\(s>1\) 表示先做空间池化。池化过程包括线性投影、网格内通道最大池化和批归一化；更新回传时使用另一线性投影及保存的网格归属关系。
- 该设计的要点是：**全局交互发生在较少的粗尺度 token 上，而细粒度特征仍保留在原分辨率流中。**

### 2.4 位置编码

- 使用面向 3D 点的轴向 RoPE，将每个注意力头的通道维度分配给 \(x,y,z\) 三个空间轴。
- 默认采用非对称分配，例如 MixPT-S 的 RoPE 维度为 \((d_x,d_y,d_z)=(8,8,6)\)，而不是在三轴上平均分配。

## 3. 实验设计

### 3.1 数据集与任务

- **语义分割：**
  - 室外激光雷达场景：SemanticKITTI、Waymo、nuScenes。
  - 室内 RGB-D 场景：ScanNet。
  - 主要指标为 mIoU 和 mAcc。
- **实例分割：**
  - ScanNet、ScanNet200。
  - 使用 PointGroup 作为共同实例分割头，报告 mAP25、mAP50 和 mAP。

### 3.2 Benchmark 与对比方法

- 语义分割的主要对比方法包括：
  - **PTv3、LitePT-S：**窗口注意力基线。
  - **Volt-S：**全局注意力基线。
  - **MixPT-S、MixPT-B、MixPT-L：**本文方法的不同规模版本。
- 实例分割比较 PTv3、LitePT-S*、Volt-S 和 MixPT-S*。
- 语义分割分别提供不使用测试时增强（TTA）和使用 TTA 的结果；主结果强调不使用 TTA 的比较。
- 还报告延迟、参数量，以及池化步幅变化带来的精度、延迟和显存变化。

### 3.3 主要结果概览

- 在不使用 TTA 的语义分割测试中，MixPT-S 的 mIoU 为：
  - SemanticKITTI：70.0%
  - Waymo：72.1%
  - nuScenes：80.6%
  - ScanNet：76.0%
- 在对应延迟测试中，MixPT-S 的前向延迟分别为 28.2、42.8、19.2、17.5 ms；四个数据集上均低于 PTv3、LitePT-S 和 Volt-S。
- MixPT-B、MixPT-L 通常进一步提升语义分割指标，但参数量和延迟也增加。
- 在实例分割中，MixPT-S* 整体与基线具有竞争力，但并非在所有指标、数据集上都占优。

  - 未明确列出训练 GPU 的型号；RTX A6000 是推理延迟测试所用型号，不能据此认定训练也使用该型号。
  - 未报告每个实验的训练总时长、GPU 小时数或能源消耗。

## 5. 实验数量与充分性

- 论文覆盖 **4 个语义分割数据集**及 **2 个实例分割数据集**，涉及室内和室外场景。
- 主要实验还包括：
  - 多种模型规模（S、B、L）比较；
  - 窗口注意力、固定序列化、交错注意力及全局注意力等结构对比；
  - 多种窗口/全局块排列，例如 WWGWWGWW、WWWGWWWG、WWWWGGGG、WGWGWGWG；
  - 全局池化步幅 \(s=1,2,4,8\) 的精度、延迟和显存分析；
  - 多种 3D RoPE 轴向维度分配；
  - 多种序列化顺序（Z、TZ、H、TH）；
  - 使用和不使用 TTA 的结果。
- **充分性评价：**
  - 跨数据集覆盖较广，也有针对核心设计选择的消融，能够支持“交错全局交互”和“池化降低全局注意力成本”这两项主要论点。
  - 但块布局和池化策略的搜索仍有限，作者也明确承认尚未系统优化最佳交错位置；实验未提供多随机种子均值、方差或显著性检验。
  - 因此，实验足以展示方法的可行性和有竞争力的表现，但不足以证明该注意力安排对所有任务、数据集或模型规模都最优。

## 6. 主要结论与发现

- 在固定序列化的窗口注意力中插入周期性全局块，可为不同窗口之间提供直接的信息传递路径，并改善单一固定序列化窗口模型的表现。
- MixPT-S 在四个语义分割数据集上的单次前向延迟均低于所比较的窗口与全局注意力基线，同时保持有竞争力的分割精度。
- 全局注意力不一定需要作用于完整分辨率：空间池化可降低其延迟和显存需求，在部分设置下还能保持或提升精度。
- 增加模型规模通常可以改善部分数据集的表现，但增益并不在所有指标和数据集上完全一致。
- RoPE 的三个空间轴无需采用对称维度分配；在论文实验中，某些非对称分配以较少参数取得了相当或更好的结果。

## 7. 优点

- **设计目标清晰：**直接针对窗口注意力跨窗通信弱、全局注意力成本高这一权衡展开。
- **结构简单且易解释：**通过注意力块交错获得全局交互，而非对所有层都使用昂贵的全局注意力。
- **计算优化与信息路径相结合：**固定序列化减少重复重排，池化全局注意力控制长场景计算成本。
- **评测覆盖面较广：**包含室内外语义分割及实例分割，不局限于单一场景类型或任务。
- **效率报告相对具体：**给出硬件、推理精度、批量大小和计时流程，并区分模型前向时间与 TTA/碎片聚合开销。
- **消融围绕关键设计展开：**考察块排列、池化步幅、序列化顺序和 RoPE 分配，有助于理解性能来源。

## 8. 不足与局限

- **最优结构尚未充分搜索：**不同任务、数据集和模型规模可能需要不同的全局块位置或频率；论文评估的排列组合有限。
- **池化可能损失细节：**全局块只在粗尺度 token 上工作，虽然残差更新回传到原分辨率，但池化仍可能压缩局部信息；其适用程度可能依赖场景密度和几何分布。
- **公平性仍有解释空间：**延迟测试使用统一的 RTX A6000 推理设置，但基线部分结果结合作者报告结果与作者复现结果，并在语义分割中统一应用 EMA；不同方法的训练配置和预训练来源并非完全相同。实例分割中 Volt 的初始化与其他方法也不完全一致。
- **统计稳定性信息有限：**未见多次独立运行的均值、标准差或显著性分析，部分指标的小幅差异不宜视为稳健优势。
- **算力报告不完整：**训练 GPU 型号、总训练时长、GPU 小时数及能耗未明确报告，难以完整比较训练成本。
- **延迟结论有适用边界：**报告的是单个 voxelized 场景的一次模型前向，排除了数据预处理、数据传输和预测聚合；实际部署时的端到端延迟可能不同。论文亦指出，不使用 TTA 仍可能需要对多个 fragment 分别前向。
- **任务与应用范围有限：**主要验证的是三维语义和实例分割，尚不能据此推断在检测、时序建模或其他点云任务上的效果。
