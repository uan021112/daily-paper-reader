# Alpha: Systematic Fault Injection and Robustness Evaluation for LLM-Driven Embodied Manipulation 

Jona Joy 

Abstract —Large language models (LLMs) are increasingly integrated into embodied robotic planning, combining natural-language goal decomposition with physical execution. However, standard evaluations typically focus on end-to-end task com-pletion in nominal environments, obscuring where and why failures occur across the perception, planning, kinematic, and actuation stack. We present Alpha, a systematic fault-injection and robustness-evaluation framework for LLM-driven embodied manipulation in simulation. Alpha injects calibrated faults across four operational boundaries: perception (sensor lag), actuation (grip slip), kinematics (unreachable inverse-kinematics targets), and planning (planner-output corruption), alongside concurrent fault conditions. To cleanly separate environmental and phys-ical fault vulnerabilities from planner-pipeline sensitivities, we introduce a matched evaluation methodology pairing an LLM agent (Llama-3 via Ollama) against a deterministic Scripted Oracle planner under identical seeds, task geometries, physics parameters, and safety-monitoring criteria across a balanced 150-episode matrix (75 episodes per planner). Across the full matrix, the Scripted Oracle achieves 64.0% (48/75) success while the LLM planner achieves 44.0% (33/75) (paired McNemar 

p = 3 .01 × 10 −4). Crucially, when excluding planner-output cor-ruption, performance across all physical and kinematic conditions is identical: 55.0% (33/60) for both planners with zero discordant pairs (McNemar p = 1 .00 ). This demonstrates that physical ac-tuator slip, kinematic reach boundaries, and perceptual staleness affect deterministic controllers and LLM planners equivalently. The aggregate performance difference is driven entirely by planner-output corruption (100% Oracle vs. 0% LLM), isolating the serialization and schema-validation sensitivity of the prompt-to-JSON interface rather than an intrinsic cognitive reasoning deficit. We also audit 169 historical pilot attempts to establish complete discard-bias transparency. Key limitations include a single simulated tabletop pick-and-place task, evaluation on a single local open-weight model, and n = 5 sample sizes per intensity cell. 

Index Terms —Embodied AI, robotic manipulation, systematic fault injection, robustness evaluation, large language models, safety monitoring, simulation-based testing, failure taxonomy.

In such systems, high-level task planners translate natural-language objectives and perceptual scene descriptions into structured action plans (e.g., approach, grasp, transfer, and release). While recent benchmarks have demonstrated impressive nom-inal task-completion rates across multi-step household and

industrial manipulation tasks [4], [5], these evaluations over-whelmingly measure aggregate end-to-end success in nominal, unperturbed environments. Consequently, when an embodied agent fails, existing evaluation protocols rarely localize the failure to its causal origin: did the failure stem from noisy or delayed sensor observations, physical actuator slip, kinematically infeasible joint commands, syntax errors at the serialization boundary, or flawed semantic reasoning? In real-world deployments, autonomous robots routinely encounter hardware degraded states, communication latencies, grasp disturbances, and me-chanical limits [10], [11]. Understanding how embodied LLM architectures degrade under controlled, reproducible faults is essential before these agents can be safely deployed in safety-critical human environments. Controlled fault injection provides a principled methodol-ogy for answering these questions. In distributed software engineering and cloud infrastructure, chaos engineering and active fault injection systematically subject running systems to synthetic faults to observe failure signatures and evaluate automated containment boundaries [16], [17]. However, trans-lating this methodology to embodied robotic agents introduces fundamental challenges: physical simulation dynamics, closed-loop contact mechanics, non-deterministic language genera-tion, and complex API interfaces must all be monitored syn-chronously without confounding the agent’s internal control logic. Furthermore, evaluating an LLM planner in isolation leaves open a critical counterfactual question: is a given failure caused by an intrinsic limitation of the language model, or is it an unavoidable physical consequence of the injected dis-turbance that would equally thwart any competent controller? Without a strictly matched baseline, environmental physics failures (such as a slippery block falling out of a gripper) are easily conflated with planner cognitive failures. To address these challenges, this paper presents Al-pha , a reproducible fault-injection and robustness-evaluation harness for LLM-driven embodied manipulation in simu-lation. Alpha couples a modular middleware fault wrap-per ( ChaosRoboticsWrapper ) with a high-rate validated safety monitor, structured telemetry logging, and an explicit counterfactual evaluation protocol. Embodied LLM Planning and Robotics Benchmarks. 

The integration of large language models as high-level plan-ners for embodied manipulation has expanded rapidly. Say-Can [1] combined LLM plan generation with learned value-function affordances to constrain language outputs to physi-cally executable behaviors. Inner Monologue [4] and Code as Policies [6] demonstrated that textual environmental feedback and direct Python code generation enable closed-loop task execution. Multimodal vision-language-action (VLA) founda-tion models such as PaLM-E [3] and RT-2 [2] directly map visual tokens and task instructions to continuous robot actions. Standard benchmarks in this domain (e.g., VirtualHome [7], ALFRED [8], and BEHAVIOR [9]) evaluate task completion across complex multi-step sequences. However, these bench-marks evaluate agents under nominal environmental conditions and do not inject controlled component failures at intermediate execution boundaries. 

Robotics Fault Injection and Middleware Reliability. 

Classical dependability and fault injection in robotics have a long history in safety-critical domains [10], [11]. Researchers have investigated hardware bit-flips, sensor noise injection, and network packet loss in ROS/ROS 2 middleware archi-tectures [12], [13]. In industrial manipulators, fault-tolerant control architectures typically rely on analytical redundancy, threshold-based disturbance observers, and emergency joint braking [14], [15]. Alpha extends physical fault injection to the emerging paradigm of LLM-orchestrated manipulation, bridging low-level simulation physics with modern prompt-based serialization interfaces. 

Structured LLM Output, Pydantic Schema Validation, and Failure Handling. When language models are deployed in autonomous decision loops, unstructured text must be con-verted into strictly typed, executable representations. frameworks and libraries such as Pydantic [21] enforce schema constraints over LLM-generated JSON payloads. However, recent empirical software engineering studies indicate that small perturbations, token dropouts, or syntax deviations fre-quently trigger unrecoverable JSON decoding or validation errors [22]. In this work, Alpha explicitly formalizes serialized output corruption as an operational fault class, demonstrating how schema validation acts as a rigid boundary that prevents corrupted trajectories from reaching physical joints at the cost of complete episode abortion. 

Autonomous Safety Monitoring and Contact Taxonomy. 

In physics simulation environments such as PyBullet [19], de-tecting safety violations is non-trivial: contact points, reaction impulses, and joint limits are sampled at high simulation rates (e.g., 240 Hz). Naive thresholding on raw contact points results in severe overcounting, where a single mechanical contact lasting 0.5 seconds generates over 100 violation events. Prior safety-monitoring frameworks in autonomous driving and ma-nipulation propose temporal filtering and state-based incident clustering [23], [24]. Alpha implements an explicit contact taxonomy with an audited deduplication window to distinguish transient contact oscillations from sustained, unique safety incidents. 

Chaos Engineering in Cyber-Physical Systems. Formal-ized by Netflix to verify high-availability cloud microservices [16], [17], chaos engineering proactively introduces localized component outages to verify automated failover and system resilience. While cyber-physical systems have begun adopting chaos-testing principles for IoT and automotive communi-cation [18], embodied manipulation introduces continuous spatial geometry and irreversible mechanical actions (e.g., dropping a fragile object). Alpha adapts the core principles of chaos testing to robotic manipulation by defining repro-ducible fault hooks across perception, kinematics, actuation, and serialization. III. S YSTEM ARCHITECTURE AND METHODOLOGY 

Alpha structures autonomous robotic execution around a modular Brain/Body design pattern, instrumented by an ex-ternal fault wrapper and an autonomous safety monitor, as illustrated in Fig. 1. 

A. Execution Pipeline and Information Flow 

The complete data flow of an execution episode proceeds across six sequential stages: 1) Scene Observation and Perception Hook: The physi-cal simulator ( PyBullet DIRECT mode) instantiates table surfaces and manipulators. The ground-truth block positions are captured as a snapshot dictionary: 

S = {c : ( xc, y c, z c) | c ∈ { red , green , blue }} . (1) Before reaching the planner, this state is intercepted by 

wrap_observation() , which maintains an internal ring buffer of historical state snapshots. If sensor lag (F1) is active, a delayed historical snapshot Sstale is returned instead of the fresh observation. 2) Planner Action Generation: The active planner re-ceives a task specification T = ( block , place zone ) and the observation dictionary. The planner generates an ac-tion plan consisting of sequential sub-goals: MOVE_TO 

(hover position), MOVE_TO (block grasp coordinate), 

GRIP , MOVE_TO (lift hover), MOVE_TO (place zone), and RELEASE .3) Planner Output Interception and Schema Validation: 

In the LLM pipeline, the generated plan is serialized as a JSON string. The intercept_planner_output() 

hook intercepts this text stream. If planner-output corruption (F4) is active, required keys are re-moved or syntax corruption is injected. The result-ing payload is validated against a Pydantic schema (ActionPlan.validate_raw_plan ). If schema validation fails, the episode aborts cleanly by yielding an empty action plan, preventing malformed targets from reaching the robot controller. The Scripted Oracle bypasses JSON serialization, generating internal domain objects directly. 4) Control Layer and Kinematic Interception: Validated action plans are executed by ControlService . Com-manded Cartesian end-effector targets are intercepted by 

move_end_effector() . If unreachable IK (F3) is enabled, a deterministic spatial reach offset ⃗ δ is added to commanded positions, pushing the target outside the manipulator’s physical reach envelope. Inverse kinemat-ics are resolved using damped least-squares in PyBullet. 5) Actuation and Contact Mechanics: Joint velocity and grip commands are forwarded to the simulator. When an object is actively gripped via PyBullet point-to-point or fixed constraints, the simulation step hook checks for actuation disturbances. If grip slip (F2) is active, the grip constraint is dynamically weakened or detached on lift. 6) Telemetry Logging and Safety Monitoring: Through-out the entire trajectory, an autonomous safety monitor scans contact forces and link poses at 240 Hz, recording structured telemetry rows upon episode completion. 

B. Matched Counterfactual Baseline (Scripted Oracle Plan-ner) 

To distinguish physical and environmental constraints from LLM cognitive or structural vulnerabilities, Alpha imple-ments ScriptedOraclePlanner . The Scripted Oracle reads ground-truth block coordinates directly from the scene service and computes kinematically valid, collision-free linear trajectories through standard pick-and-place waypoints. Critically, the Scripted Oracle is executed inside the iden-tical simulator environment, under the identical per-episode master seed, utilizing the identical robot kinematics, con-trol parameters, and safety monitor. C. Safety Monitoring Architecture and Deduplication Engine 

The safety monitor ( PyBulletSafetyMonitor , version 1.1.0) executes synchronously at each 240 Hz simulation step. Contact forces between the manipulator links (IIWA/Franka links 0 through 6) and non-gripped scene objects are extracted via p.getContactPoints() . To ensure physical validity, expected support contacts (arm resting on the table base) and normal grasp reaction forces on gripped objects are explicitly excluded. A contact is classified as a violent collision if the normal contact force exceeds Fthresh = 3000 .0 N, calibrated above nominal grasp reaction impulses ( 2000 –2600 N). An out-of-workspace violation is triggered if any block departs the admissible spatial workspace: 

X ∈ [0 .15 , 0.95] m, Y ∈ [−0.45 , 0.55] m,Z ∈ [0 .55 , 1.25] m. Alpha defines four isolated fault classes (F1–F4) and one concurrent multi-fault condition, formalized in Table I. Fault intensities are parameterized by a normalized scalar I ∈{0.33 , 0.66 , 1.00 }, corresponding to nominal low , medium ,and high labels. 

A. F1: Sensor Lag (Perception Boundary) 

Sensor lag models communication delays, frame drops, or asynchronous processing in vision perception pipelines. When invoked, wrap_observation() queries the observation ring buffer for a historical scene snapshot matching timestamp 

ttarget = tcurrent − τlag , parameterized by: 

τlag = 0 .10 + 1 .40 · I [seconds ]. (4) Nominal calibrated parameters correspond to requested delays of 0.562 s ( I = 0 .33 ), 1.024 s ( I = 0 .66 ), and 1.500 s ( I =1.00 ). 

Realized Experimental Behavior: At episode initialization, the simulation steps physics for 120 steps ( 120 /240 Hz =0.500 s) to allow scene objects to settle under gravity before the initial observation is captured. Because the ring buffer contains at most 0.500 s of simulation history at the moment the planner queries the scene, the observed and applied lag saturates at 0.500 s across all three intensity levels. During the drop-and-settle interval, the target block descends from its initial drop spawn height ( z = 0 .675 m) to its settled table resting height ( z = 0 .650 m), producing a measurable spatial staleness divergence of exactly ∆pos = 0 .0250 m ( 2.50 cm) across all F1 runs. F1 is therefore classified as validated fault delivery with measurable temporal and spatial staleness, but severity saturation at the available history-buffer limit .

B. F2: Grip Slip (Actuation Boundary) 

Grip slip simulates surface contamination, oil film, or inad-equate grasp pressure causing mechanical slippage after grasp acquisition. The fault evaluates grip constraints when an object is held, with slip probability calibrated by: 

Pslip = 0 .10 + 0 .85 · I. (5) Calibrated nominal probabilities are 0.270 (I = 0 .33 ), 0.525 

(I = 0 .66 ), and 0.865 (I = 1 .00 ). 

Realized Experimental Behavior: To prevent high-frequency sampling artifacts where per-step rolling guaranteed 100% slippage regardless of configured probability, Alpha evaluates slip probability strictly once per lift event via an internal 

_slip_evaluated latch. If slip triggers, the constraint force factor is weakened or removed entirely, allowing Py-Bullet contact friction and gravity to determine whether the block drops.

Unreachable IK simulates miscalibrated camera-to-base ex-trinsics, coordinate frame transform errors, or joint limit sin-gularities that command the end-effector outside its physical workspace. E. F4: Execution Path and Serialization Sensitivity 

Under F4 planner-output corruption, the Scripted Oracle achieved 100.0% (15/15) success, whereas the LLM agent achieved 0.0% (0/15) success. Fig. 6 details the execution path that explains this diver-gence. When F4 corrupts the LLM output string, the Pydantic schema validator intercepts missing keys or invalid syntax, catching ValidationError and generating an empty ac-tion plan ( actions=[] ). The control service halts execution immediately, preventing erratic joint motions and cleanly logging task failure. Conversely, because the Scripted Oracle generates compiled in-memory domain objects directly, it never enters string serialization or schema parsing, completely bypassing F4. The empirical findings from Alpha yield six core principles for evaluating LLM-driven embodied manipulation: 

1. Not Every Embodied Failure is an LLM Failure. 

The matched 60-episode physical cohort demonstrates that when actuator slip (F2) or kinematic barriers (F3) occur, an LLM agent and a perfect deterministic oracle fail in identical proportions and on the exact same episodes. Attributing such dropouts to “LLM reasoning fragility” without a matched baseline is scientifically invalid. 

2. Physical Actuator Faults Dominate Independently of Planning. F2 grip slip exhibited monotonic degradation governed entirely by mechanical contact friction and grav-ity. Semantic replanning cannot recover from mid-air block detachment unless the agent possesses closed-loop regrasp recovery routines. 

3. Perceptual Staleness Can Be Measurable Without Im-pairing Task Success. In static tabletop tasks, sensor latency that produces measurable spatial staleness ( ∆pos = 2 .5 cm) is completely absorbed by gripper mechanical compliance and grasp aperture tolerance. Perceptual faults must be evaluated against physical actuator envelopes. 

4. Continuous Metrics Reveal Severity Beyond Binary Success. In F3 unreachable IK, reporting binary success (0%) conceals meaningful kinematic degradation. Continuous placement distance demonstrated that placement error scaled with reach offset magnitude, distinguishing monotonic oracle reaches from non-monotonic LLM deflections. 

5. Serialization and Validation are Primary Failure Interfaces. F4 demonstrated that the prompt-to-JSON inter-face is exceptionally brittle. Pydantic validation successfully prevented malformed targets from commanding erratic robot motions, demonstrating safe fail-stop behavior at the cost of task completion. 

6. Matched Counterfactual Baselines are Indispensable. 

Without the Scripted Oracle baseline, the 44% success rate JONA JOY: ALPHA — SYSTEMATIC FAULT INJECTION AND ROBUSTNESS EVALUATION FOR LLM-DRIVEN MANIPULATION 9

of the LLM planner might have been misconstrued as general unreliability. The oracle localized the 20% performance gap exclusively to serialization handling. IX. T HREATS TO VALIDITY AND LIMITATIONS 

Sample Size per Intensity Cell (n = 5): While the aggregate paired comparisons ( N = 75 and N = 60 ) provide high precision, cell-level comparisons possess wide confidence intervals (e.g., F2 Low 95% CI is [23 .1% , 88 .2%] ). Cell-level trends are descriptive and must not be claimed as isolated statistically significant effects. 

Buffer-Bounded Sensor Staleness: Due to the single-shot pick-and-place structure, history depth prior to grasp was capped at 0.500 s. Investigating larger multi-second latencies requires dynamic closed-loop tracking tasks. 

Serialization vs. Cognitive Testing: F4 evaluates schema parsing and syntax rejection. It does not measure subtle cogni-tive degradation under partially incorrect semantic reasoning. 

Single Simulated Task and Model: Evaluations were conducted on a single pick-and-place task in PyBullet with an open-weight model (Llama-3). Findings should not be extrapolated universally to closed frontier models or real-world hardware without empirical validation. X. C ONCLUSION 

Alpha provides a reproducible fault-injection harness and matched-baseline methodology for evaluating LLM-driven robotic manipulation. By pairing an LLM agent against a de-terministic Scripted Oracle across 150 controlled episodes, we demonstrated that physical actuator slip, perceptual staleness, and kinematic reach boundaries produce identical failure rates across both controllers. The performance divergence between language planners and deterministic systems is localized to se-rialization and schema validation interfaces.
