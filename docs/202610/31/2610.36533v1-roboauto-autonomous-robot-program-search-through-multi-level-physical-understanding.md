## 摘要
近年来，基于大语言模型（LLM）的自主智能体在迭代生成、评估和改进可执行方案方面展现出强大能力。在机器人操作领域，Code-as-Policy 使这类智能体能够搜索模块化且可编辑的机器人程序。然而，有效的程序搜索离不开对物理世界的理解：智能体必须理解物体如何被操纵、场景几何如何限制动作，以及交互为何成功或失败。现有方法主要依赖执行反馈来改进程序，往往未能解决这些物理层面的问题。我们提出 RoboAuto，这是一种机器人程序搜索框架，通过三个组件，在物体、场景和交互三个层面明确组织物理理解。首先，分层知识库将可执行技能与以物体为中心的知识相结合，其中涵盖可供性、空间关系和动作效果；这些知识从具身数据和在线任务求解中习得。其次，场景落地将这些知识与当前环境关联起来，识别相关物体并确定对动作至关重要的参数。第三，多阶段规划结合自主设计的实验，检查每个阶段是否产生预期的物理效果，并主动检验相互竞争的假设，以消除物理层面的不确定性。RoboAuto 在五类基准测试中取得了优异表现：在短时程 LIBERO-PRO 任务上成功率达到 89.1%，在 LIBERO-PRO Long 和 LIBERO-Plus 上的平均成功率超过 ASPIRE 的两倍。在需要精确操作的三项具有挑战性的长时程真实机器人任务中，RoboAuto 的表现也优于 ASPIRE 和 $π_{0.5}$。我们进一步表明，该知识库能够跨模拟器和具身平台迁移，且程序搜索性能会随知识库规模扩大而提升。项目页面：https://roboauto-ai.github.io/

## Abstract
Recently, LLM-based autonomous agents have shown strong capabilities in iteratively generating, evaluating, and refining executable solutions. In robotic manipulation, Code-as-Policy lets these agents search over modular and editable robot programs. However, effective program search requires physical understanding: agents must understand how objects can be manipulated, how scene geometry constrains actions, and why interactions succeed or fail. Existing methods rely mainly on execution feedback for program refinement, often leaving these physical questions unresolved. We introduce RoboAuto, a framework for robot program search that explicitly organizes physical understanding at the object, scene, and interaction levels through three components. First, a hierarchical knowledge base combines executable skills with object-centric knowledge of affordances, spatial relations, and action effects, learned from embodied data and online task solving. Second, scene grounding connects this knowledge to the current environment by identifying relevant objects and resolving action-critical quantities. Third, multi-stage planning with self-designed experiments checks whether each stage produces its expected physical effects and actively tests competing hypotheses to resolve physical uncertainties. RoboAuto achieves superior performance across five benchmark families, attaining an 89.1% success rate on short-horizon LIBERO-PRO tasks and more than twice the mean success rate of ASPIRE on LIBERO-PRO Long and LIBERO-Plus. It also outperforms ASPIRE and $π_{0.5}$ on three challenging long-horizon real-robot tasks requiring precise manipulation. We further show that the knowledge base transfers across simulators and embodiments, and that program search performance scales with its size. Project page: https://roboauto-ai.github.io/

  1. **物体层面**：对象适合怎样的抓取、放置或交互；
  2. **场景层面**：当前对象的具体尺寸、位置、朝向等关键量是什么；
  3. **交互层面**：动作是否造成了预期的状态变化；如果原因不明，如何主动设计实验来查明。
- **核心主张**：程序搜索的改进不应只靠不断重写代码，还应依靠可迁移的物理知识、对当前场景的测量，以及针对不确定性的诊断实验。

## 2. 方法论：核心思想与技术流程

RoboAuto 由三个相互配合的部分构成。

### 2.1 分层知识库

知识库分为两个层次：

- **物体中心的物理知识**：按一般物体类别组织，而非针对某个特定实例或任务，主要包括：
  - **可供性与约束**：物体适合的交互方式及不适合的策略，例如杯子可从杯沿夹持，薄书本适合沿书本平面夹取；
  - **空间关系**：支撑、容纳、相邻、插入等任务相关的物体配置；
  - **动作效果与前提条件**：动作会导致什么状态变化，以及变化成立所需的条件，例如旋钮转动后应检查炉灶是否点亮。
- **可执行技能**：已经验证过的机器人程序或程序片段，可直接复用或组合。

物体知识从具身演示数据中提取，也会依据在线任务搜索中获得的证据持续修订；经验证的程序则沉淀为可执行技能。知识条目还会列出需要在当前场景重新测量的参数，而不把某一场景的具体数值当作普遍规则。

### 2.2 物理场景落地

给定任务指令和当前观测，系统会：

1. 找出任务相关对象并确定它们在目标交互中的角色；
2. 检索匹配的知识条目，检查其中的适用条件；
3. 使用视觉模型、分割工具和深度相机等，测量动作所需的场景量，例如抓取位置、物体尺寸与朝向、空间关系；
4. 将测量结果交给程序生成过程，用于选择策略并确定动作参数。

如果初始视角信息不足，系统还可以主动调整观察视角。场景落地不是一次性步骤：执行结果若表明测量或适用性判断有误，系统可以重新测量和修订。

### 2.3 分阶段规划、验证与自主实验

- **分阶段规划**：将长时程任务拆解为一系列物体状态变化阶段，并按物理依赖关系排列。例如“打开炉灶”必须在“放置锅具”之前完成。
- **阶段验证**：每一阶段都配有检查预期物体状态的验证程序。只有当前阶段确认完成，系统才继续执行后续阶段；失败则集中修改最早未完成的阶段，避免错误传播。
- **独立审查**：程序内的验证器可能判断错误，因此系统还使用独立审查器，结合执行日志与场景、腕部相机视频，判断各阶段的物体状态。审查器的判断可以覆盖程序验证器的结果。
- **自主设计实验**：若执行结果仍无法说明失败原因，系统提出相互竞争的物理假设，预测各假设下会观察到什么，再编写独立于任务程序的实验代码进行测试。实验得到的证据可用于修正当前程序和知识库。
- **搜索循环概括**：检索知识 → 场景测量 → 分阶段生成程序与验证器 → 执行 → 审查失败阶段 → 必要时设计诊断实验 → 更新程序和知识 → 将验证过的程序存为技能。

  - 组件消融采用逐步累加而非完整因子设计，难以完全分离组件之间的交互效应；知识库规模实验也不能直接归因到某一条具体知识。
  - 自主搜索依赖强语言模型和复杂工具链，模型、提示、感知工具与知识质量共同作用，单独归因于“物理理解”的难度较高。
  - 真实机器人每项任务 20 次评估，但论文报告的主要指标为阶段完成分数，不能直接等同于整项长程任务的完整成功率。

## 6. 主要结论与发现

- **总体仿真表现领先**：RoboAuto 在论文报告的五类 benchmark 中表现突出。其 LIBERO-PRO 总体成功率为 **89.1%**，LIBERO-PRO Long 为 **73.4%**，LIBERO-Plus 为 **90.3%**，Robosuite 平均为 **90.6%**。
- **长程任务改善明显**：LIBERO-PRO Long 上，RoboAuto 的 73.4% 高于 ASPIRE 的 30.8%；LIBERO-Plus 上，90.3% 高于 ASPIRE 的 44.7%。
- **知识迁移有效**：LIBERO 知识库迁移到 RoboTwin 2.0 后，平均成功率为 **91.5%**；不保留知识时为 **24.5%**。
- **知识规模与搜索表现相关**：在五项消融任务上，完整知识库的最终平均成功率为 **91.2%**，随机半量知识库为 **65.2%**，无知识库为 **19.2%**。这支持更丰富的知识有助于提升搜索效果，但不能据此判断每条知识的独立因果贡献。
- **组件具有互补作用**：消融实验中，基础循环平均成功率为 5.2%，加入搜索与探索后为 19.2%，再加入知识库后为 38.4%，完整系统加入场景落地后为 91.2%。特别大的增幅说明，仅有抽象知识而没有当前场景测量，通常不足以可靠执行。
- **真实机器人结果积极但指标需区分**：论文报告 RoboAuto 在 Sort Balls、Stack Dishes、Erase Board 上的阶段完成分数分别为 **100%、100%、95.83%**，高于 ASPIRE 和 π0.5；这些数值是阶段完成分数，不应误读为三项任务各自的完整成功率。
- **推理 token 消耗**：在长程 LIBERO 与 LIBERO-Plus 的匹配设置上，RoboAuto 的平均成功率高于 ASPIRE 和 CaP-Agent0，报告的几何平均 token 使用量也较低；但这些比较采用各方法自身的搜索流程和停止规则。

## 7. 优点

- **把“物理理解”落实为可操作的搜索机制**：分别建模交互策略、场景参数和动作效果，而不是只把执行失败当作代码错误。
- **知识抽象具有迁移导向**：知识条目提供定性策略和待测量参数，不依赖某个场景中的固定坐标或数值，便于在新对象和新环境中重新落地。
- **阶段验证能定位失败**：根据物体状态而非机械臂是否到达某个位姿判断阶段是否成功，减少长程任务中的错误级联。
- **将主动实验纳入程序搜索**：专门设计诊断实验来区分可能原因，使反馈有机会解释“为什么失败”，而非仅仅记录失败。
- **评估维度较丰富**：除基准成功率外，还包含消融、知识迁移、知识规模、模型能力、搜索随机性、token 消耗及真实机器人测试。
- **提供了部分机制层面的案例分析**：书本抓取、杯沿测量、炉灶状态验证等案例展示了系统如何改变搜索策略，为理解性能差异提供了具体例证。

## 8. 不足与局限

- **真实部署自主性有限**：论文明确指出，真实机器人仍需要人工在每轮 rollout 后重置场景，并由人工负责安全监控；完整自主的现实世界搜索尚未实现。
- **对模型和工具链依赖较强**：系统使用能力较强的闭源语言模型，并依赖视觉模型、分割、深度相机及控制接口。其成本、复现门槛及工具替换后的表现仍需更多研究。
- **物理知识的质量与错误传播值得关注**：知识从演示和在线试错中提取；若证据不足、判断错误或适用条件描述不充分，错误知识可能影响后续任务。论文提到会标注知识证据状态，但未能消除此类风险。
- **跨域实验仍有限**：虽然展示了跨模拟器、双臂平台和真实机械臂迁移，但具体任务数量较少，真实机器人覆盖三项任务，尚不足以证明对广泛开放环境都具有稳健泛化能力。
- **成功率不等于安全或效率**：主要评估聚焦任务成功或阶段完成，未系统报告碰撞风险、硬件磨损、执行时间、能耗等部署指标。
- **基线对比仍有不对称**：不同基准的基线来源和可复现程度不一致；π0.5、RHO 等方法也未覆盖全部任务，因此“全面优于所有方法”的结论应限定在论文实际比较的设置内。
- **计算资源报告不完整**：未报告 GPU 等硬件和训练时长，难以完整估算系统的计算成本；虽然提供了 token 使用分析，但不足以替代端到端资源报告。
- **组件因果归因有限**：累积式消融显示完整系统明显更强，但各组件可能存在交互效应，当前实验设计不能精确回答每一部分的独立贡献大小。
