Abstract: Open-world mobile manipulation requires a robot to find an object, ap-proach it, and move it to a target receptacle from a language instruction. Training vision-language model (VLM) agents for these tasks requires demonstrations of both action selection and active vision. Existing pipelines often convert planned trajectories into high-level action labels, but shortest-path progress provides lim-ited supervision for deciding where to look. We introduce Agent-Interface Data Alignment (AIDA), a data collection pipeline in which a teacher directly selects and executes actions through the deployed agent’s skill interface. For mobile ma-nipulation, we design teachers that maintain target visibility, recover lost targets, and approach for picking or placing. We add template-based spatial reasoning supervision and use a shared harness to organize observations, history, and out-puts during training and inference. The resulting agent, AIDA-OWMM, achieves 71.76% full-task success on 170 held-out OWMM episodes. Teacher sensitivity analysis shows that active-vision demonstrations improve student success. The simulation-trained agent achieves 38% end-to-end success on a real mobile robot without additional training. Applying AIDA to a navigation subset of Embod-iedBench further demonstrates the pipeline’s utility for navigation tasks. Project website. 

Keywords: Open-world mobile manipulation, vision-language model agents, im-itation learning 

1 Introduction 

Open-world mobile manipulation (OWMM) studies how robots can follow language instructions to find objects and move them to target receptacles in everyday environments [1, 2]. Solving these tasks requires coordinating perception, navigation, and manipulation: the robot must decide where to look, how to approach a target, and when it is ready to pick or place. In an agentic mobile manipulation system, a vision-language model (VLM) selects high-level actions from visual observations, task instructions, and interaction history, while dedicated controllers execute the corresponding motions. A central challenge is training the VLM to make effective decisions as the robot moves, its view changes, and new actions become possible. Prior work constructs training data by converting planned or executed robot trajectories into high-level action labels [2, 3]. When these trajectories are driven primarily by shortest-path progress, they can provide limited supervision for active vision: keeping a target visible during approach, recovering it after it leaves view, and obtaining a suitable view for manipulation. This motivates collecting demonstrations from a teacher that actively decides where to look and how to move. To this end, we introduce Agent-Interface Data Alignment (AIDA) , a pipeline for constructing demonstrations through the deployed agent’s decision interface, and apply it to mobile manipula-

At each step, the teacher selects a skill and its arguments, executes the call, and uses the resulting observation to choose the next action (Figure 1). High-level actions thus guide demon-stration collection instead of being inferred afterward from motion trajectories. The teacher can use privileged simulator information, while the student’s inputs contain only observations and context available at deployment. Within AIDA, we design the teacher to demonstrate active target acquisition . Finding a target is only the beginning: it may leave view during approach or remain out of reach when the robot stops. Building on active perception [4, 5], the teacher moves to collect useful views, turns to recover lost targets, and approaches to prepare for picking or placing. These behaviors teach the student to coordinate looking and moving in preparation for manipulation. We further provide spatial reasoning supervision to make the judgments behind these actions ex-plicit. For each teacher action, an offline annotator describes whether the target is visible, where it lies relative to the robot, whether the next skill can be executed, and how far the task has pro-gressed. A shared agent harness assembles prompts, maintains episode memory, and defines the model’s output format consistently during training and deployment. We use supervised fine-tuning to teach the VLM to predict spatial state, reasoning, and actions from its observations and history. At deployment, the model generates these outputs itself. Our mobile manipulation agent, AIDA-OWMM , achieves 71.76% full-task success on 170 held-out OWMM episodes. Teacher sensitivity analysis shows that demonstrations from teachers that maintain visibility and recover lost targets yield better student performance than those from a simple approach policy; harness ablations further support action history and spatial reasoning supervision. Trained entirely in simulation, the agent also performs pick-and-place tasks on a real mobile robot in an office environment without additional model training. Finally, we evaluate the approach on short-horizon navigation tasks in EmbodiedBench to examine its applicability beyond the OWMM benchmark. Our contributions are: • A pipeline for agent-aligned data collection : AIDA generates teacher demonstrations directly through the deployed agent’s high-level action interface. • A teacher for active-vision demonstrations : we design behaviors for maintaining visi-bility, recovering targets, and approaching for manipulation, and evaluate their effect on student performance. • A harness for spatial reasoning supervision : structured target state and task progress guide action learning through a shared prompting and memory interface. 2Pick  cycle  Place  cycle

2 Related Work 

VLM agents for mobile manipulation. Mobile manipulation systems combine semantic task rea-soning with physically grounded navigation and manipulation. Prior work grounds language plans in skill affordances and learns language-conditioned robot policies from large demonstration cor-pora [6, 7, 8, 9], with recent extensions to cross-domain generalization and unseen manipulation tasks [10, 11, 12]. Open-vocabulary mobile-manipulation systems combine language, perception, maps, and robot APIs to complete household tasks [1, 13, 14, 15, 2], while whole-body work high-lights stage-dependent perception demands under changing viewpoints [16]. These systems estab-lish the usefulness of modular high-level skills and open-vocabulary perception. Our focus is differ-ent: we study what form of synthetic supervision teaches the VLM controller to use those skills as a closed-loop active target-acquisition policy. 

Embodied VLM navigation and view control. VLM navigation methods train agents to follow instructions, use visual history, and select navigation actions from partial egocentric observations. Recent systems study visual history, map use, and action prediction for embodied VLM naviga-tion [17, 18, 19, 20, 21, 22, 23]. Object-goal navigation and active VLN further use spatial ab-straction, exploration, and viewpoint correction to search for open-vocabulary targets or reduce route-following uncertainty [24, 25, 26]. These works show that VLMs can learn route following, memory use, and action prediction, but OWMM target acquisition has a different endpoint: the policy must stop in a robot-object relation from which manipulation can succeed. AIDA-OWMM therefore trains active view control around task entities and manipulation readiness rather than route progress alone. Active perception and next-best-view methods choose viewpoints or paths to reveal occluded struc-ture, reduce grasp uncertainty, or improve reachability [27, 4, 28, 29, 5]. Here, view control is distilled into a VLM high-level policy that decides when to search, turn, approach, pick, and place from the deployed agent interface. 

Spatial reasoning as policy state. Spatial-VLM work studies depth, metric relations, object ground-ing, cross-view correspondence, and persistent spatial memory [30, 31, 32, 33, 34, 35, 36]. Other work turns visual-spatial understanding into points, visual prompts, or multi-turn state-and-transition reasoning for robot actions [37, 38, 39]. AIDA-OWMM uses spatial reasoning in a narrower way: object-centric state is an intermediate policy variable for deciding whether to search, turn, approach, pick, or place. The novelty is using spatial state inside active target-acquisition demonstrations generated in the deployed OWMM agent interface. 33 Method 

AIDA-OWMM trains a VLM to select high-level skills for mobile manipulation. The pipeline has three components: a teacher collects demonstrations through the agent’s action interface, an annota-tor adds spatial reasoning targets, and a shared harness organizes prompts and episode memory for training and deployment (Figure 3). 

3.1 Problem Formulation 

An OWMM episode is specified by an instruction q, such as moving an object from a source re-ceptacle to a goal receptacle. Following the OWMM benchmark [2], we assume a pre-mapped environment and known robot localization. The map provides scene geometry for navigation; the agent identifies the object and goal receptacle through RGB key frames with known camera poses and its own visual exploration. At decision step t, the VLM receives ot = ( Ict , q, A, H t−1, R t), where Ict is the current head-camera RGB image, A is the skill vocabulary, and Ht−1 contains prior skill calls and their arguments. Rt

contains scene key frames during source-object or goal-receptacle search and is omitted during local navigation and manipulation. The VLM outputs yt = ( rt, a t, u t, m t), where rt is explicit reasoning about spatial relations and task progress before selecting skill at and argument ut, and mt is a generated step summary that is not included in subsequent history. Teacher and student share five skills. A fixed executor E converts each call into low-level robot actions, alow

= E(at, u t, I ct , D ct ), using the geometric map, robot localization, and stored key-frame poses as context. Here, Dct is the depth image used to ground pixel coordinates in 3D. The skills are: • search scene frame selects a key frame by its displayed ID; the executor uses its asso-ciated pose as the navigation destination. • turn specifies an angle for the controller to rotate the robot in place. • nav to point specifies a normalized pixel coordinate; the executor back-projects it using depth and camera pose to obtain a navigation destination. • pick specifies a normalized pixel coordinate on the object; the manipulation controller moves the end effector toward the corresponding 3D location and grasps the object. • place specifies a normalized pixel coordinate on the destination; the controller moves the held object toward the corresponding 3D location and releases it. In simulation, grasping is simplified: the object is attached to the gripper when the end effector is within the configured grasp distance.

During search, the teacher selects the scene key frame whose viewpoint is closest to the target and issues search scene frame ; the search phase completes after this call. During navigation, the teacher actively searches for the target and relevant visual cues, choosing between turn to adjust the view and nav to point to approach the target. When the target is visible or recently visible, navigation points favor keeping it in view while moving within reach. When the target has not been seen recently, projected paths guide the selection of navigable points. For object pickup during collection, the target must be within 1.0 m with a visible mask exceeding 100 pixels; the teacher uses the 15 ◦ bearing threshold to align its view. At deployment, the VLM decides when to pick from its observation. For pick and place , the teacher obtains the object or goal-receptacle mask and uses its centroid, expressed as a normalized pixel coordinate, as the action argument. A teacher may fail to complete an episode, for example by losing track of the target or exceeding the step budget. Such unsuccessful trajectories are excluded from the training dataset. Teacher thresholds, filtering rules, and recorded fields are detailed in Appendix A. 

3.4 Spatial-State Annotator 

After collection, each teacher trajectory provides a sequence of observations and high-level actions. The spatial-state annotator supplements each step with the reasoning that the student is trained to produce before selecting that action. It generates this reasoning offline using deterministic templates and the simulator information recorded during collection. The templates describe target visibility, relative direction, readiness for the next skill, and task progress, then connect these judgments to the teacher’s action. Visibility and direction are de-rived from the target mask; when the target is outside the image, its direction is obtained from the recorded robot pose and target position. Readiness describes whether the robot should adjust its view, approach, pick, or place, while progress identifies the current part of the task. For example, a template may state that the target is visible on the left but too far away to pick, motivating further approach. These descriptions form the pre-action reasoning target rt, complementing the recorded skill at and argument ut. The resulting supervision teaches the student to reason explicitly about spatial relations and task progress before acting. Label sources and template details are provided in Appendix A. 

3.5 Shared Agent Harness and Training 

The shared harness uses the same prompt format, history representation, and output schema for train-ing and inference. Each prompt xt contains the instruction, current RGB image, skill definitions, 5history Ht−1, and scene key frames during search. Privileged simulator information is excluded from the prompt in both training and inference. OWMM-style history recursively carries forward the latest summary [2]. Our history retains previ-ous skill calls and their arguments (ai, u i), keeping an explicit record of the agent’s actions without including generated step summaries. The prompt specifies the output format for yt = ( rt, a t, u t, m t), including the available skills and their argument formats. 4 Experiments 

Our experiments examine whether AIDA improves mobile manipulation, how teacher behavior and agent supervision contribute to performance, and whether the learned policy transfers to a real robot. We then use a navigation subset of EmbodiedBench to test whether the AIDA pipeline also applies to navigation tasks. 

4.1 Experimental Setup 

All AIDA policies trained in our experiments use Qwen3-VL-8B-Instruct [40] as the base model and are fine-tuned with LoRA using LLaMA-Factory [41]. The OWMM comparisons vary the demonstration policy, skill set, or harness while keeping the base model, fine-tuning method, and low-level executors fixed. The teacher sensitivity study uses four skills, excluding turn to match the OWMM action interface. The main AIDA-OWMM model and harness ablations use all five skills: adding turn lets the agent orient toward targets without translating, expanding the viewpoints it can reach. The three AIDA teachers in the sensitivity study each provide 28,480 training examples. The main model and all harness variants use the same larger AIDA dataset of 67,183 examples. Unless varied in the harness ablation, agents use the shared harness described in Section 3.5. Following the OWMM evaluation protocol [2], we evaluate on 170 held-out episodes in pre-mapped simulated homes. Table 1 reports the fraction of episodes that retrieve a relevant object image (Image Retrieval, Object), pick up the object (Object Picked), retrieve a relevant receptacle image (Image Retrieval, Goal), and approach the receptacle (Robot Close to Goal). Full Task measures successful completion of the object transfer, including placement. Training and evaluation settings are listed in Appendix D. 

4.2 OWMM Benchmark 

We first compare AIDA-OWMM with existing OWMM systems (Table 1). Results for OWMM-VLM-38B, OWMM-VLM-8B, GPT-4o+PIVOT, and GPT-4o+RoboPoint are taken from OWMM-Agent [2, 42, 38, 37]. The following studies examine teacher behavior and harness design under the shared training setup. AIDA-OWMM achieves 71.76% full-task success, compared with the reported 21.90% for OWMM-VLM-38B and 9.45% for OWMM-VLM-8B. Object-image retrieval is similar for AIDA-OWMM and OWMM-VLM-38B (90.59% versus 88.56%), while object pickup reaches 82.35% versus 38.56%. The larger difference in pickup shows that the overall improvement extends beyond finding a relevant scene image to approaching and manipulating the object.

4.5 Real-Robot Evaluation 

To test transfer from simulation to physical mobile manipulation, we deploy AIDA-OWMM on an Atribot S1 without further model training. The office environment contains two office rooms and an open tea room, with five movable objects and five receptacles. The agent uses RGB observations and scene key frames through the same high-level skill interface; the robot’s controllers execute navigation and manipulation. Hardware and execution details are given in Appendix B. The robot achieves 38% end-to-end success with a 15-step horizon, including low-level grasp fail-ures in the evaluation. This result demonstrates transfer from simulation to physical mobile manip-ulation without additional model training. Figure 4 shows the resulting sequence of viewpoint changes, navigation, and manipulation. Failure analysis is provided in Appendix C. 

4.6 EmbodiedBench Navigation 

To test whether the AIDA pipeline extends beyond mobile manipulation, we apply it to the naviga-tion subset of EmbodiedBench [43] used in our evaluation, which consists of language-conditioned, single-room tasks in AI2-THOR. We train a policy on 1,200 navigation episodes constructed with the AIDA pipeline. We also include the OWMM-trained policy as a zero-shot reference. Evaluation uses 60 episodes from each of the base and common sense splits, with results averaged over two runs. Hosted-model baselines use the same prompt format, action parser, skill executor, and 10-step horizon. Evaluation protocol details are provided in Appendix B. The EmbodiedBench-trained policy reaches 0.84 average success, while the OWMM-trained policy reaches 0.55 without additional training (Table 4). The zero-shot Qwen3-VL-8B-Instruct base model reaches 0.02 under the same evaluation interface. 5 Conclusion 

We presented AIDA, a pipeline that collects demonstrations through the high-level skill interface used by the deployed agent. For mobile manipulation, we combine active-vision teachers with spatial reasoning supervision and a shared training and inference harness. The pipeline supports different teacher policies, with visibility-aware approach and target recovery improving student suc-cess. Real-robot deployment without additional training and the application to a navigation subset of EmbodiedBench extend the evidence beyond simulated mobile manipulation. Together, these re-sults highlight the value of designing demonstrations around the decisions an embodied agent must make, including where to look and how to move before manipulation. 

6 Limitations 

AIDA-OWMM uses an offline teacher with privileged simulator state, so generalization is bounded by the teacher data diversity across scenes, objects, embodiments, sensors, and skills. The OWMM simulator abstracts contact-rich grasping, slip, force control, and recovery; real-robot results show that low-level pick reliability remains a bottleneck. For navigation, our evaluation is limited to relatively short episodes in the evaluated navigation subset of EmbodiedBench. Whether agent-interface-aligned supervision provides similar benefits for longer instruction-following and search-based navigation settings, such as VLN-CE [44] and ObjectNav [45], remains an important direction for future work. 9Acknowledgments

Teacher navigation rules. The teacher turns when the target or path-segment bearing exceeds 

15 ◦. Heading errors above 40 ◦ are split across multiple turns. When aligned, the teacher selects a 

nav to point goal. For a visible or recently visible target, it selects floor points that preserve vis-ibility and approach a reachable region around the object or receptacle. Otherwise, it samples floor points near the projected short-horizon path, favoring points away from navigability boundaries. 

Trajectory selection and records. For the full AIDA dataset, collection attempts cover 13,608 episodes, of which 11,740 succeed. Removing 1,528 successful episodes longer than 16 steps leaves 10,212 episodes and 67,183 training examples. Each step stores the RGB observation, instruction, scene-key-frame order, task phase, skill, and argument. Additional simulator records—robot pose, target positions, mask statistics, turn mode, and navigation pixel—support offline annotation and diagnostics. 

Annotation and output format. The templates use masks for visible-target descriptions and recorded poses for out-of-view direction labels (Section 3.4). The five output fields map to the agent representation as follows: state estimation and reasoning together represent the pre-action reasoning rt; action and action information encode (at, u t); and summarization stores the step summary mt.

B Additional Evaluation Details 

EmbodiedBench. We use the navigation subset from the VAGEN/EmbodiedBench split [39, 43]. Hosted models share the prompt, output schema, parser, invalid-action handling, executor, and 10-step horizon. Scores average two runs; Table 4 lists public model family names [46, 42, 47, 48, 49, 50, 40]. 

Real-robot perception and navigation. We map the office with FAST-LIO2 [51] and manually select 15 scene key frames. The VLM receives RGB observations from the torso RGB-D camera. The search scene frame skill navigates to the selected key-frame pose. For nav to point , the executor back-projects the selected pixel using depth and plans an obstacle-free path with the fast marching method. 

Real-robot manipulation. The executor expresses each pick or place target in the robot base frame and sends an end-effector pose command to the Atribot whole-body controller. Grasping uses a predefined pose. Near the object, head-camera visual servoing uses SAM 3 [52] to refine the grasp position. Low-level grasp failures count toward the reported end-to-end failure rate.
