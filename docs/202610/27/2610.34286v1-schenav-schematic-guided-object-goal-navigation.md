## 摘要
物体目标导航要求具身智能体在复杂环境中定位并抵达目标物体。人类常依赖成本低廉但信息丰富的示意图，例如粗略草图或方向标注。我们提出一种由示意图引导的具身导航工作流程，包含两个部分：训练数据生成流程和闭环导航框架 ScheNav。轻量级数据生成流程将二维平面图转换为导航训练环境，构建了 Furnished-RPLAN 数据集，其中包含 3.3 万余个带家具的布局，以及与之配对的导航片段和噪声可控的示意图。ScheNav 借助 SchemaField 将粗略示意图引导转化为探索与停止决策。SchemaField 是一种学习型空间模块，可融合引导信息与累积观测，并预测空间价值场。随着探索推进，该框架会持续更新这些价值场；基于轨迹的训练与跨帧一致性目标则有助于在视角变化时保持引导连贯。ScheNav 完全利用模拟平面图学习如何使用示意图引导，并将这一能力迁移至未见过的具身环境。实验表明，在示意图、目标椭圆和指向方向等多种引导形式下，该方法均能提升导航成功率和路径效率，同时能够适应经过测试的示意图扰动与信息缺失。总体而言，这些结果表明，粗略的示意图引导为改善具身导航提供了一种实用途径。

## Abstract
Object goal navigation requires an embodied agent to locate and reach target objects in complex environments. Humans often rely on low-cost yet informative schematic maps, such as rough sketches or directional annotations. We develop a workflow for schematic-guided embodied navigation with two components: a training-data generation pipeline and ScheNav, a closed-loop navigation framework. Our lightweight data-generation pipeline turns 2D floorplans into navigation training environments, yielding Furnished-RPLAN, a dataset of over 33k furnished layouts with paired navigation episodes and noise-controllable schematic maps. ScheNav turns rough schematic guidance into exploration and stopping decisions by using SchemaField, a learned spatial module that fuses the guidance with accumulated observations and predicts spatial value fields. The framework updates these fields as exploration proceeds, with trajectory-based training and a cross-frame consistency objective supporting coherent guidance across changing viewpoints. ScheNav learns to use schematic guidance entirely from simulated floorplans and transfers this ability to unseen embodied environments. Experiments show improved navigation success and path efficiency across schematic maps, goal ellipses, and pointed directions, together with tolerance to the tested schematic perturbations and omissions. Together, these results demonstrate that rough schematic guidance offers a practical way to improve embodied navigation.

## 2. 方法论

### 2.1 数据生成：Furnished-RPLAN

- 以 **RPLAN** 的二维矢量平面图为基础，利用视觉语言模型生成并整理机器可读的家具布局，覆盖约 40 类 Habitat 家具类别。
- 根据布局生成导航环境、导航片段、局部观测、空间价值场监督，以及与任务配对的示意图。
- 示意图支持可控噪声和信息缺失。整个生成与训练流程在二维模拟平面图上完成，不需要构建三维场景或收集真实具身导航轨迹。
- 最终数据集包含 **33,992 个带家具布局**，训练与验证按平面图 ID 划分。

### 2.2 ScheNav 闭环框架

- 智能体每一步接收语义观测、位姿、目标类别，以及可选的示意图输入。引导形式包括：
  - 带起点或目标标注的示意地图；
  - 目标椭圆；
  - 指向方向；
  - 不提供示意图。
- 主机导航系统维护累积地图，并提供前沿候选点和可见目标实例。ScheNav 通过以下循环工作：**融合引导与当前地图 → 预测空间价值场 → 选择探索目标或判断停止 → 执行移动并更新地图**。

### 2.3 SchemaField：预测距离场与走廊场

- SchemaField 是框架中新引入的唯一学习模块。它接收示意图、部分观测地图、位姿和目标类别，将观测、示意图和目标编码为 token，再经联合 Transformer 融合。
- 模块一次前向传播预测两个空间场：
  - **距离场** \(V_t\)：按可通行的测地距离评估位置与目标的接近程度；越接近目标，价值通常越高。
  - **走廊场** \(C_t\)：突出从当前位置通往目标的近似最短路径，以便在多个探索前沿之间形成更清晰的选择差异。
- 对走廊场的监督目标结合当前位置至候选点的距离、候选点至目标的距离及最短路径长度，并通过前向门控抑制智能体身后对称方向上的错误分支。

### 2.4 决策规则与跨帧一致性

- **探索决策**：从地图记忆提供的前沿候选中，选择走廊场得分最高者。
- **目标验证与停止**：检测到目标类别的实例后，检查其位置处的距离场值；若连续两个步骤超过停止阈值，系统即进入最终接近阶段并锁定停止承诺，随后抵达目标后停止。阈值在模拟验证集上按引导条件校准，部署时固定。
- **跨帧一致性训练**：
  - 论文指出，逐帧独立训练可能产生“单帧看起来合理、闭环决策却不稳定”的问题：不同朝向下预测的场映射回世界坐标后不一致，导致连续的前沿选择互相抵消。
  - 为此，训练样本来自模拟导航轨迹；此外，利用不同视角或相邻轨迹帧的相对位姿，将预测场变换到共同坐标系，并对共同可见区域施加一致性约束。
  - 论文报告，该设计将大角度转向后的方向翻转率从 **45.6% 降至 10.1%**，世界坐标下预测相关性从 **−0.15 提升至 +0.80**。

## 6. 主要结论与发现

- 在完整主 benchmark 上，ScheNav 使用示意地图取得 **61.4% SR、36.3% SPL**；目标椭圆取得 **60.4% SR、35.5% SPL**；仅方向指引取得 **34.6% SR、19.3% SPL**；无示意图时为 **21.9% SR、5.8% SPL**。
- 论文报告，方向指引条件的成功率高于所列文本驱动基线；但这类比较仍需考虑两者输入信息差异。
- 组件分析显示，单帧价值场预测本身不足以改善闭环导航；轨迹训练、跨帧一致性和走廊场等设计组合后，加入目标验证进一步提升性能。
- 失败分析显示：引导较强时，问题主要集中在停止时机和停止精度；引导较弱时，同类别实例歧义和感知误检更突出。
- 整体结论是：粗略示意图可在不要求精确全局地图的情况下提供有用空间先验；要稳定利用这些先验，模型需要在连续视角变化下保持预测一致。

## 7. 优点

- **问题设定实用**：研究的不是理想化的精确地图导航，而是对粗略、不完整的人类空间提示进行利用，更接近实际交互场景。
- **训练流程成本相对可控**：从二维平面图生成环境和监督信号，避免三维场景构建及具身轨迹采集，同时提供超过 3.3 万个布局。
- **闭环设计清晰**：SchemaField 负责空间预测，前沿选择和停止由明确规则完成，便于接入既有导航系统，也便于拆分分析各模块作用。
- **识别并处理关键失效模式**：论文不仅提出模型，还指出逐帧预测在闭环中的跨视角不一致会导致决策反复，并通过轨迹训练与坐标对齐损失直接处理这一问题。
- **评估维度较丰富**：除成功率和路径效率外，还分析方向翻转、前沿质量、停止错误及不同引导强度下的表现。

## 8. 不足与局限

- **主对比存在信息不对等**：ScheNav 部分设置获得了显式空间引导，而多数基线主要依赖文本目标描述。因此，性能提升不能完全归因于导航算法本身；论文的引导条件梯度有助于理解信息价值，但不能消除该差异。
- **模拟到真实的覆盖仍有限**：训练依赖二维平面图，具身迁移虽在 HM3D 中评估，但给定内容未显示对真实机器人、真实手绘输入或多种传感器误差进行系统验证。手绘地图展示主要是补充演示。
- **资源报告不足**：缺少硬件、训练时长和推理开销，限制了计算成本判断和复现。
- **噪声鲁棒性证据不够细化**：论文声称对测试中的扰动与缺失具有容忍度，但正文未充分给出扰动类型、强度区间和逐级性能曲线，难以判断鲁棒性的边界。
- **停止与实例歧义仍是瓶颈**：强引导下仍有不少失败来自晚停；弱引导下，错误提交和同类别目标实例混淆增加。类别级空间引导并不能总是确定具体目标实例。
- **部署依赖主机系统**：地图记忆、前沿提取、感知、局部规划和执行由宿主导航系统提供；实际表现会受到这些组件的能力与错误影响，ScheNav 并非独立解决完整导航链路。
- **外部有效性仍待扩展**：现有具身评估集中于 HM3D 与 UniGoal 协议。对其他环境、目标定义、真实交互方式及不同导航主机的泛化能力，仍需要进一步实验。
