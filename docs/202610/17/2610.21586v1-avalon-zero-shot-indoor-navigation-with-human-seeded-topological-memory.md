## 摘要
室内服务机器人常常需要进入尚未绘制地图、但其布局和任务约束对用户而言已十分熟悉的建筑。针对这种“人熟悉、机器人未见过”的场景，我们提出 AVALON，一种拓扑导航框架，其核心包括由人类播种的分层空间记忆、经节点验证的拓扑执行，以及由任务触发、以证据为门控的人机记忆协同更新。机器人无需事先在现场行走，也无需针对特定场地进行训练。部署仅需一份平面图、地点线索，以及初始的拓扑—里程计对齐。视觉深度点目标导航利用经验证的节点到达来实现平移重锚定，无需构建由机器人生成的全局 SLAM 地图。人机记忆协同更新融合互补的信息来源：人类操作员指定无法通过视觉观测的任务约束，并报告非任务期间发生的环境变更；机器人则通过主动现场验证提供物理状态证据。任务相关性决定在当前任务执行期间，是否需要由机器人验证人类报告的环境变化。现场采集的感知证据作为记忆更新的门控条件，从而明确区分人类指定的通行许可与机器人观测到的可通行性。在 Unitree Go2 上开展的实验表明，AVALON 与 X-NavDP 结合后，在无地图条件下以 46.4 秒完成 12.81 米的“交叉口至餐厅”任务（5/5）；与 DimOS-Go2（78.5 秒，4/5）相比，机器人耗时减少 40.9%，而仅使用策略的 X-NavDP 在 5 次运行中均超时。这些结果证明了所提出的拓扑导航框架具有优越性。

## Abstract
Indoor service robots often enter unmapped buildings whose layouts and task constraints are already familiar to users. We address this human-familiar, robot-unseen setting with AVALON, a topological navigation framework organized around human-seeded layered spatial memory, node-verified topological execution, and task-triggered, evidence-gated human--robot memory co-updating. The robot has no prior on-site traversal or site-specific training. Deployment requires only a floor plan, place clues, and an initial topology-odometry alignment. Visual depth point-goal navigation leverages verified node arrivals to perform translational re-anchoring, without requiring a robot-constructed global SLAM map. Human--robot memory co-updating fuses complementary sources of information. Human operators specify task constraints that are unobservable via vision and report offline environmental modifications, whereas the robot provides physical-state evidence through active in-situ validation. Task relevance governs whether human-reported environmental changes undergo robot validation during the active mission. Field-collected perceptual evidence gates memory updates, maintaining an explicit separation between human-specified permissions and robot-observed traversability. Our experiments on a Unitree Go2 show that AVALON with X-NavDP completes a 12.81 m Intersection-to-Dining mission in 46.4 s (5/5) with no mapping, 40.9% less robot time than DimOS-Go2 (78.5 s, 4/5), while policy-only X-NavDP times out in all of the 5 runs. These demonstrate the superiority of the proposed topological navigation framework.

## 1. 核心问题与整体含义

- **研究场景**：室内服务机器人进入一栋用户熟悉、但机器人从未到访的建筑。机器人没有现场地图，也没有针对该建筑的训练；但用户可以提供楼层图、地点线索和任务约束。
- **核心问题**：如何将人类掌握的空间与任务信息转化为机器人首次任务即可使用的导航记忆，并在执行中验证这些信息、发现环境变化、据此更新记忆。
- **整体思路**：AVALON 不要求机器人先完成一次专门建图，而是用人类提供的楼层图构建拓扑骨架；机器人沿图执行局部导航，并通过到达节点时的语义验证修正平移定位；对环境变化报告，则在其与当前任务相关时进行现场核验，以机器人证据更新物理状态。
- **重要区分**：人类提供的通行许可与机器人观测到的实际可通行性分开存储。人类可决定“任务是否允许经过”，但只有机器人现场证据才能确认“当前是否畅通”。

## 2. 方法论：核心思想与关键技术

### 2.1 人类播种的分层空间记忆

- 从 CAD 或楼层图栅格中提取可行走区域：通过墙体阈值处理、外部区域填充、连通区域筛选等方式获得自由空间，再进行骨架化。
- 将骨架端点、交叉点及必要的中间路点组成节点和边，形成拓扑图 \(G=(V,E)\)。若直连线段不在自由空间内，则插入中间路点；只有在连线仍位于自由空间内时，才允许删除路点。
- 图中的节点分为：
  - **语义节点**：附有人类提供的照片、文字描述等线索，可用于地点识别和到达验证。
  - **连接路点**：主要用于路线几何细分，不一定具有识别线索，因而不承担语义验证或重定位功能。
- 用户还可在节点或边上附加 RoadBook 备注、路线偏好及任务约束。节点、边采用稳定 ID，使路线执行、人工编辑和机器人证据更新指向同一空间元素。
- 楼层图生成的几何骨架用于路线规划，但不等价于精确的机器人全局地图，也不替代机器人在线避障和安全控制。

### 2.2 节点验证的拓扑执行与平移重锚定

- 系统先在拓扑坐标系与机器人里程计坐标系之间完成一次初始对齐；随后在图上规划节点序列，由局部导航策略逐段执行机器人坐标系下的点目标。
- 文中以 NavDP 和 X-NavDP 作为局部导航策略：它们接收实时 RGB-D 观测和机器人坐标系下的目标点，输出短时域运动路点。到达几何路点只表示路线进度推进，并不代表节点身份已确认。
- 进入带有视觉线索的语义节点验证区域后，机器人停止并保持位置，通过多视角现场图像与节点存储的图像、文字参考进行比较。候选节点限制在上一个已确认语义节点及其语义邻居，避免仅因几何距离近而误认地点。
- 节点接受需要同时通过两个门控：
  1. **视觉匹配**：视觉语言模型判断现场观测与该节点参考线索是否匹配。
  2. **里程计距离检查**：从上一个已确认节点累计的里程计距离，须处于名义路线长度乘以容许比例区间内。
- 两项条件必须同时满足；仅视觉相似或几何接近都不足以触发确认。通过后，系统以该节点的图上位置和确认时刻的里程计位置计算平移修正，并用于后续点目标。系统保持初始朝向对齐不变，因此**只校正平移，不校正航向**。
- 论文还给出一个条件性误差关系：在两个已验证节点之间，目标误差上界由验证残差、里程计漂移随行程的累积、楼层图位置误差及航向误差共同构成；只有当该上界低于局部策略对目标扰动的容忍度时，接口才具有条件上的兼容性。作者指出，这不是导航成功保证，策略容忍度也未在系统中在线估计或强制满足。
- 对物体搜索任务，抵达候选节点并不等于任务完成；还需由实时目标检测器确认目标存在。

### 2.3 任务触发、证据门控的人机记忆协同更新

- 每个图节点或边分别记录三类信息：机器人可观测的物理状态（未知、畅通、受阻）、语义描述，以及由人类设置的任务许可（允许、禁止）。
- **权限字段由人类管理，物理状态字段由机器人证据更新**。用户报告环境变化先作为待核验信息，而不是直接写成已确认的物理状态。
- 若报告涉及当前路线上的节点或边，机器人会在本次任务中进行现场核验；若与当前任务无关，则暂缓处理，等待后续相关任务。
- 节点状态更新需要关联到明确的图 ID，并有空间定位的机器人观测支持；若要更新边的可通行性，则还需覆盖相应边及其两端的证据。证据冲突或过期时，更新保持待处理状态。

## 3. 实验设计、场景与对比方法

### 3.1 场景和任务

- 实验平台为 **Unitree Go2**，在一个办公室环境中构建了含 8 个节点的楼层图，中央主通道长 24.11 米，并由用户提供 5 张地点照片。
- 测试两条房间间路线：
  - **交叉口至餐厅**：12.81 米、6 个节点。
  - **餐厅至会议室**：20.43 米、7 个节点。
- 每种方法、每条路线各运行 5 次；每次从可比的起始姿态出发，超时上限为 120 秒。任务成功要求到达目标区域并由 YOLO-World 检测到目标。
- 第二条路线还用于人机记忆更新案例：用户报告办公室入口有推车，机器人前往该节点核验后记录入口节点状态，并继续前往会议室。

### 3.2 对比方法与指标

- **DimOS-Go2**：先进行现场建图，再导航。
- **NavDP（policy-only）和 X-NavDP（policy-only）**：提供路线终点点目标，但不使用 AVALON 的拓扑图、节点验证和重锚定。
- **AVALON + NavDP、AVALON + X-NavDP**：将对应局部策略接入 AVALON 的图导航与验证流程。
- 主要指标包括成功率、成功试次的平均执行时间、建图时间和总部署时间。报告的部署时间为建图时间与执行时间之和；人工先验制作、地图输入和初始位姿对齐不计入该指标。

### 3.3 主要结果

- 交叉口至餐厅：
  - AVALON + X-NavDP：**5/5 成功，46.4 秒**，无机器人建图。
  - DimOS-Go2：**4/5 成功，78.5 秒**，其中建图 45.2 秒、执行 33.3 秒。
  - X-NavDP（policy-only）：**0/5，均超时**。
  - AVALON + NavDP：3/5 成功，平均执行 83.4 秒。
- 餐厅至会议室：
  - AVALON + X-NavDP：**5/5 成功，78.7 秒**。
  - DimOS-Go2：**5/5 成功，112.5 秒**，其中建图 60.2 秒、执行 52.3 秒。
  - X-NavDP（policy-only）：0/5，均超时。
  - AVALON + NavDP：1/5 成功，平均执行 93.6 秒。
- 里程计扰动测试只在交叉口至餐厅路线、AVALON + X-NavDP 配置上进行：名义条件为 5/5；噪声强度 0.02 时为 3/5；噪声强度 0.04 时为 1/5。
- 记忆协同更新案例中，5 次餐厅至会议室试验均完成“报告—现场验证—更新入口节点状态—到达会议室”的流程。作者特别说明，节点层面的观察并不自动证明相邻边可通行。

## 5. 实验数量与充分性、客观性和公平性

- 主要对照实验覆盖 **2 条路线 × 多种方法，每种方法每条路线 5 次**；另有 3 种里程计条件下的 5 次试验，以及 5 次记忆协同更新案例。
- **优点**：同一办公室、相近起始姿态、统一 120 秒超时；局部策略对照中，policy-only 与 AVALON 配对使用；作者报告成功率和成功试次平均时间，并区分建图时间、执行时间和部署时间。
- **局限**：每个配置仅 5 次试验，样本规模较小；没有置信区间、显著性检验或跨场地复现，因此成功率差异的不确定性较大。里程计噪声实验主要表明完整系统对噪声敏感，并未单独隔离节点重锚定的因果效果。
- **公平性需结合指标解释**：AVALON + X-NavDP 与 DimOS 的机器人总部署时间比较包含建图成本，因此可体现“首任务是否需要建图”的差异；但二者的执行时间并非完全可比。AVALON 会暂停验证节点，速度上限为 0.50 m/s，DimOS 设为 0.55 m/s。另一方面，AVALON 的总部署时间不计入人类先验制作和初始对齐成本。论文对这些成本有披露，但“总部署时间”并非包含全部部署劳动的端到端成本。
- 整体上，实验能够支持**特定办公室、特定机器人和特定配置下的可行性证据**，但不足以充分证明跨建筑、跨布局或跨平台的普遍优势。

## 6. 主要结论与发现

- 人类提供的楼层图、地点线索和任务信息能够在机器人首次到访前构成可执行的拓扑记忆，减少对机器人专门建图遍历的依赖。
- 通过语义节点到达验证和位置重锚定，拓扑图能够为局部点目标策略提供长程路线结构；在报告的测试条件下，AVALON + X-NavDP 明显优于不带拓扑引导的 X-NavDP。
- 人机协同更新能够将人类对变化的报告转化为机器人现场核验任务，并以机器人证据更新物理状态；但权限与物理状态需要保持分离。
- 对主要短路线，AVALON + X-NavDP 在不进行机器人现场建图的情况下实现 5/5 成功，且总机器人部署时间低于 DimOS-Go2。该结果是小规模场景实验，不应直接外推为广泛环境下的性能保证。

## 7. 优点

- **面向实际首次部署问题**：明确针对“用户熟悉、机器人未见”的建筑，避免把专门建图当作使用前提。
- **信息来源与权限边界清晰**：将结构先验、人类许可、语义线索和机器人观测证据分层管理，避免把“允许通行”误当成“实际畅通”。
- **路线与地点识别相结合**：拓扑图负责全局路线，局部策略负责短程运动，语义节点验证负责确认进度，结构较清晰。
- **验证机制有约束**：视觉匹配与里程计距离门控同时成立才允许重锚定；候选节点还受拓扑邻接约束。
- **对记忆更新的触发条件明确**：仅在报告与当前任务相关时安排现场验证，减少无关检查。
- **进行了真实机器人验证**：不仅给出框架描述，也在 Go2 上报告导航、里程计扰动和记忆更新案例。

## 8. 不足与局限

- **实验覆盖有限**：仅一个办公室环境、一台 Go2、两条路线及少量试次；缺少跨建筑、跨楼层、不同人流、光照、家具布局和机器人平台的验证。
- **依赖较高质量的人类先验**：楼层图需要可用且具有已知尺度与原点，还需地点照片、文字线索及初始拓扑—里程计对齐。先验制作和初始对齐时间未计入部署时间。
- **抗定位误差能力有限**：重锚定只校正平移，不修正航向；噪声扰动结果显示成功率随噪声增加显著下降。
- **地图与现实不一致仍可能造成问题**：拓扑骨架来自楼层图，部署期间图结构固定；复杂动态变化或图结构错误可能需要人工在后续部署前编辑。
