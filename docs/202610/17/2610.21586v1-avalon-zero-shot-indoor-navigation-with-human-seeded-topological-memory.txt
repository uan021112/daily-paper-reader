I. INTRODUCTION
Indoor service robots often enter unmapped buildings
whose layouts, routes, and closures are already familiar to
users. This human-familiar, robot-unseen setting offers a
remarkable opportunity for rapid deployment of robots. Users
can supply a floor plan and delivery instructions before the
first mission (Fig. 1). The robot must turn these priors into
executable navigation memory and detect disagreements with
observations.
Dedicated pre-mapping and online topological explo-
ration [1]–[3] both require robot data collection that may
delay service. Existing CAD, BIM [4], and user knowledge
offer alternative spatial priors, but these must be grounded
in observations and updated as conditions change.
In this paper, we propose AVALON (Asymmetric Visual-
Architectural Layered Online Navigation), built around seed,
execute, and co-update. A spatial memory framework is
constructed based on floor-plan topological skeletons with
visibility-aware constrained traversal hops, and paired with

The topological skeleton provides global route planning
priors for the robot, while the attached multi-modal clues
serve as verification signatures to validate the arrival at
target topological nodes. Local point-goal control governs
the robot’s inter-node navigation, and node arrival is rigor-
ously validated via fused visual-semantic observations and
odometry measurements.
Successful arrival confirmation enables translational re-
anchoring and progressive route execution. In case of visual
observation mismatch with the expected node template, the
robot adaptively refines its localization hypothesis. For ob-
ject search tasks, real-time perceptual inference is deployed
to verify object presence within the corresponding spatial
regions, and the collected perceptual evidence is archived
to support subsequent downstream missions. Robot onboard
observations continuously record environmental physical
states, whereas human operators supplement task-specific
constraints and update unobserved environmental variations.
Benefiting from the initialized prior memory seed, the system
can execute initial missions without standalone dedicated
mapping procedures. Furthermore, human-robot collabora-
tive memory updating maintains the timeliness and accuracy
of the memory bank, accommodating dynamic changes in
workspace layouts and task specifications.
AVALON replaces globally precise localization with
human-seeded, task-sufficient spatial grounding. Topology
specifies where to go, sparse semantic anchors re-ground
route progress, and terminal perception confirms what the
task seeks. AVALON turns human-held spatial knowledge
into executable memory for a robot’s first mission by cou-
pling a human-seeded structural prior, node-verified local
execution, and task-triggered evidence acquisition through
stable graph IDs. The main contributions of this paper can
be summarized as follows.
1) Human-Seeded Layered Spatial Memory. We pro-
pose to decouple a floor-plan skeleton from editable
task memory, and use shared node-edge identifiers to
associate human-provided clues, task constraints, and
robot sensory evidence. This design eliminates the
requirement for a dedicated pre-mapping traversal prior
to deployment.
2) Node-Verified Topological Execution. The robot nav-
igates along human-seeded routes via local graph
transitions. Node-associated visual and textual clues

II. RELATED WORK
Table I compares the first-mission memory in terms of
the categories including what prior exists, whether the robot

A. Floor Plans and CAD Priors
Floor plans have been used to localize a camera [6], [7]
and to condition a learned navigation policy [8]. Imperfect
drawings can also guide exploration [9]. Other user-provided
sketches include posted signs [10], [11] and hand-drawn
maps [12]. CAD and BIM can initialize a workspace model
before any robot visit [4], [13].
osmAG-Nav demonstrates how CAD priors can support
planning on the passage graph together with structure-aware
LiDAR localization [14]. In contrast, AVALON addresses
a different first-deployment question, i.e., how architectural
priors and user-held task knowledge can become executable
shared memory before the robot traverses the site. It con-
verts a floor plan into a visibility-constrained point-goal
skeleton, while stable node and edge IDs bind user photos,
language descriptions, and RoadBook notes to that structure.
During execution, these clues verify semantic progress and
gate translational re-anchoring. The same IDs subsequently


organize robot evidence and user edits. AVALON there-
fore couples first-mission routing, semantic grounding, and
human-robot memory co-updating without a dedicated robot
mapping pass or LiDAR-map localization.
B. Two-Stage Mapping and Exploration
A common first-mission pattern is two-stage, i.e., the
robot maps or explores, then executes. Metric SLAM such
as RTAB-Map builds a global map in a dedicated pass
and later localizes against it [15]. Topological methods
such as NTS, TSGM, and HGR grow a node-edge graph
while exploring [1]–[3]. SSMG-Nav and MG-Nav likewise
construct semantic or geometric memories online [16], [17].
OPENNAVMAP fuses multi-session image trajectories into
a shared graph with full-pose estimates [18]. In all of these
cases the robot must traverse the site before it has an
executable map. In contrast, AVALON seeds the backbone
from the floor plan so the first mission already has nodes and
edges. Verified arrivals re-anchor translation at those nodes.
C. Map-Free Policies
Goal-directed policies can run with no site map [19]–[23],
and zero-shot semantic navigation seeks objects in unseen
scenes [24]–[26]. AVALON interfaces with NavDP and X-
NavDP through robot-frame point goals and evaluates both
policies without its graph. These policies receive no user
floor plan and are not treated as object-goal benchmarks.
osmAG-LLM uses map-guided object confirmation, while
Bee-Nav separates transit from terminal visual guidance [27],
[28]. AVALON instead reaches a graph-associated candi-
date region and confirms the requested object from current
observations. Timed trials are room-to-room with terminal
confirmation, not open-ended search. Here, zero-shot means
no on-site mapping or site-specific training, given only a
human-provided floor plan and initial topology-odometry
alignment.
D. Human-Robot Memory Updates
Human-in-the-loop semantic SLAM lets operators correct
geometry and labels on a robot-built map [29]. In contrast,
AVALON’s co-updating is at task level. Human users encode
navigational permissions and environmental updates that
are inherently unobservable via onboard vision, while the
robot grounds memory entries with physical occupancy mea-
surements acquired in situ. Human-reported modifications
relevant to the active task undergo on-site robotic validation
before physical-state memory is rewritten; other reports
remain pending until a later relevant task. We validate this
closed-loop human–robot memory update pipeline in real-
world Dining-to-Meeting-Room navigation deployments.
III. METHOD
A. Problem Formulation and System Overview
Assuming that a CAD or floor-plan drawing is given, we
build a node-edge skeleton G = (V, E) with stable IDs
from it. Place photos, language descriptions, and RoadBook
notes are then attached to the nodes on this graph. A single
alignment between the topology frame and robot odometry is
required at initialization. The robot has no on-site traversal,
site-specific training, or robot-built global SLAM map. A
mission specifies a room, an object description, or a reference
image [26], which the memory associates with one or more
graph nodes. For room navigation, success is declared when
the destination node passes arrival verification. For object
search, verified arrival at a candidate node determines where
to search, but success is declared only after live perception
detects the requested object.
Figure 2 outlines the three stages of user-seeded mem-
ory construction, verified execution, and evidence-gated co-
updating. Section III-B first builds the CAD-derived skele-
ton, then attaches human clues. Section III-C follows the
graph through a robot-frame point-goal interface, instantiated
here with RGB-D local policies [22], [23], and re-anchors
translation at verified semantic nodes. Section III-D keeps
human permissions separate from physical state and accepts
physical-state updates only with localized robot evidence
(Fig. 3).
B. Human-Seeded Layered Spatial Memory
In the construction, a CAD or floor-plan raster first pro-
duces the node-edge skeleton, and photos, language descrip-
tions, and RoadBook notes are attached by users to the nodes
in the graph. Route connectivity is therefore separate from
the evidence used to recognize places.
1) Structural backbone: In contrast to CAD-to-osmAG’s
area-passage representation [13], our visibility-constrained
skeleton construction produces straight local hops. Wall
thresholding, exterior flood fill, and connected-component
filtering extract a walkable pixel set F ⊂Z2 from a floor-
plan raster with known resolution and origin. We skeletonize
F, group endpoints and junctions into vertices, and prune
short or low-clearance branches. When an endpoint chord
leaves F, intermediate waypoints are inserted along the
chain. Shortcutting removes a waypoint only if the resulting
segment remains in F. The vertex set V comprises these
endpoints, junctions, and inserted waypoints. Edges in E join
successive vertices on retained chains, not every mutually
visible pair. Each hop is a free-space raster segment:

C. Node-Verified Topological Execution
The system develops a hierarchical execution pipeline as
follows. The topological graph schedules sequential node
transitions, a local navigation policy executes point-goal
tracking, and semantically verified arrivals correct transla-
tional alignment. For object-search tasks, terminal perceptual
validation independently confirms target presence to com-
plete mission execution.
1) Graph Route and Point-Goal Execution: Given a task
associated with one or more nodes, we compute a route
on G from the current topological neighborhood to a goal-
associated node. Semantic nodes and connection waypoints
both participate in routing. Only semantic nodes later serve
as recognition anchors. RoadBook entries may bias route
costs but do not authorize unsafe motion.

D. Task-Triggered, Evidence-Gated Human-Robot Memory
Co-Updating
AVALON links memory maintenance to execution through
verified graph IDs. Human and robot inputs exhibit asym-
metric authority. Specifically, user configure permissions and
log environment changes beyond robot observations, whereas
the robot supplies localized physical evidence. A pending
update becomes a sensing objective when its corresponding
node or edge affects the current route, allowing execution to
selectively refresh memory for subsequent missions. During
a mission, the operational model Mt = (V, E, Φt) updates
only the state features Φt, while the deployed topology
(V, E) remains fixed. Authorized users may revise the graph
before a subsequent deployment.

1) Complementary authority: Localized robot evidence
may revise st(x) and attach an observed ℓt(x), but cannot

semantic correction does not itself establish traversability. A
robot-observed blockage always stops execution.
2) Task-relevant verification: If the affected node or edge
is required by the current route, the robot checks it during
that mission. Otherwise, the report remains pending for
a later relevant task. Onboard open-vocabulary detections
identify object-related conditions, while depth and local fea-
sibility checks assess immediate geometric clearance. These
checks update memory evidence but never replace the online
safety controller.
3) Evidence-gated reuse: A physical-state update requires
a resolved graph ID and localized robot evidence. A doorway
observation may update its entrance-node condition, whereas
edge traversability additionally requires both endpoints and
evidence covering that hop. Node-reference promotion still
requires At(v) = 1 from Section III-C. Records retain
source, time, and evidence. Stale or conflicting revisions re-
main pending. Memory identifies where evidence is needed,
and verified execution determines which observations can
revise it without replacing online safety checks.
IV. EXPERIMENTS
A. Experimental Setup
Experiments use a Unitree Go2 with an Insta360 X3 360◦
camera, an Intel RealSense D455F RGB-D camera, and
an NVIDIA Jetson AGX Orin. NavDP and X-NavDP send
RGB-D observations over ROS 2 to an RTX 5090 work-
station, which returns local waypoints at 6 Hz. Semantic-
node verification calls Qwen3.5-Omni [35] through its API.
YOLO-World [34] runs on the Jetson at 15 Hz for object-
related memory verification and endpoint target confirmation

Baselines. DimOS-Go2, based on the DimOS agentive
operating system [5], maps a region slightly larger than
the task workspace (onboard odometry, WebRTC LiDAR,
VoxelBlockGrid with column carving, height/slope costmap,

graph, node verification, or re-anchoring. We pair each

0.50 m/s speed limit, and 120 s timeout.
Metrics. We report success rate, mean execution time
over successful trials, and robot deployment time Tdep =
Tmapping + Texecution. For all methods, success requires
reaching the goal region and detecting its target with YOLO-

ment equal the timeout. Human-prior production, map I/O,
and pose initialization are excluded from Tdep.

D. Memory Co-Updating Case Study
In this experiment, a node ID is specified, while an am-
biguous edge requires the other endpoint. Across five Dining-
to-Meeting-Room deployments (Fig. 5(b)), a user reports a
cart at the office entrance. In each trial, the robot travels
to that node, observes that the doorway is clear, records
the entrance-node condition, and reaches the meeting room.
The report triggers verification rather than being treated as
confirmed occupancy. This node-level observation does not
certify an unobserved edge. These five deployments illustrate
how a reported change is verified before it updates memory.
V. CONCLUSION
This paper proposes AVALON, a topology-first indoor
navigation framework that decouples task execution from
rigid global map alignment. A floor-plan-derived topological
skeleton paired with editable task memory enables hierar-
chical mission execution. Topological routing outputs robot-
frame point goals for a local navigation policy, and verified


node arrivals update translational alignment without requir-
ing yaw correction. For object-search tasks, terminal percep-
tual validation confirms target presence in contrast to treating
node arrival as task completion. Verified robot observations
feed into reference-memory updates and enable auditable
memory refinement. On a Unitree Go2 first-mission de-
ployment (12.81 m Intersection-to-Dining, workspace trunk
24.11 m, five trials), AVALON with X-NavDP succeeds in
all five runs in 46.4 s without robot mapping, 40.9% less
robot time than DimOS-Go2 (45.2 s mapping + 33.3 s mean
execution, 4/5 success). Policy-only X-NavDP fails in all
five trials under a 120 s timeout, pacing near the start without
a long-horizon route. DimOS’s unsuccessful trial drifted
in odometry into a dead end. In the five AVALON + X-
NavDP Dining-to-Meeting-Room trials reported in Table II,
user reports of environmental changes trigger on-site robot
verification before the entrance node condition is updated.
AVALON successfully completes the report–verification–
update sequence and subsequently reaches the meeting room
in all five trials. These demonstrate the superiority of the
proposed topological navigation framework.
