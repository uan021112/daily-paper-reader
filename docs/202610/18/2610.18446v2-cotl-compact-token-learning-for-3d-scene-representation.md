## 摘要
我们提出 CoTL，这是一种能够从无位姿多视图图像中学习紧凑 token 集合的框架，该集合可保留场景几何结构与外观。我们的编码器将输入图像压缩为每个视图一组小规模的潜在 token，并通过跨视图聚合信息，形成视图一致的场景表示。每增加一个视图，表示仅需扩展一小组与分辨率无关的 token，因此其容量能够随可用观测数量增长。为促使这一紧凑瓶颈保留充分的场景信息，我们采用基于查询的 Gaussian 解码器：该解码器使用与场景无关的查询对学习到的 token 进行注意力计算，并恢复出一组显式且可渲染的 3D Gaussian 基元。新视角渲染监督通过重建得到的 Gaussian 场景对紧凑表示进行端到端训练。在 RealEstate10K 和 ACID 上的实验表明，所得紧凑、无结构的 token 集合能够支持具有竞争力的新视角合成，并可作为生成 3D Gaussian 场景的生成模型的潜在空间。综上，这些结果表明，3D Gaussian 重建是学习紧凑场景表示的有效目标，而所学习的 token 空间也为 3D 视觉领域更广泛的下游任务奠定了基础。

## Abstract
We present CoTL, a framework that learns a compact set of tokens that preserves scene geometry and appearance from unposed multi-view images. Our encoder compresses the input images into small per-view sets of latent tokens that aggregate information across views to form a view-consistent scene representation. Each additional view expands the representation with only a small, resolution-independent set of tokens, allowing its capacity to grow with the available observations. To force this compact bottleneck to retain sufficient scene information, a query-based Gaussian decoder uses scene-independent queries to attend to the learned tokens and recover an explicit, renderable set of 3D Gaussian primitives. Novel-view rendering supervision trains the compact representation end to end through the reconstructed Gaussian scene. Experiments on RealEstate10K and ACID show that the resulting compact, unstructured token set supports competitive novel-view synthesis and can serve as the latent space of a generative model for 3D Gaussian scene generation. Together, these results show that 3D Gaussian reconstruction is an effective objective for compact scene representation learning and the learned token space provides a basis for broader downstream tasks in 3D vision.

# CoTL：用于 3D 场景表示的紧凑 Token 学习

## 1. 核心问题与整体含义

- **研究问题：**如何从无位姿的多视图图像中学习一种紧凑的场景表示，同时保留重建可渲染 3D 场景所需的几何与外观信息？
- **研究动机：**不少前馈式 3D 重建方法虽能输出较少的 Gaussian 基元，但解码器仍读取每个视图的稠密图像特征。因而，输出紧凑不等于编码器与解码器之间的场景表示紧凑；稠密特征也不便直接作为下游生成模型的潜空间。
- **整体思路：**CoTL 在稠密视觉特征与场景解码器之间设置明确的信息瓶颈，将每个输入视图压缩为少量潜在 token。解码器只能读取这些 token，并据此恢复显式、可渲染的 3D Gaussian 场景。训练目标是新视角渲染质量，而不是直接对 token 内容施加人为定义的监督。

## 2. 方法论

### 核心流程

1. **输入与编码：**给定 \(N\) 张无位姿上下文图像，使用从预训练几何基础模型 VGGT-Ω 初始化的多视图编码器提取特征。每个视图保留 16 个 register token 和 1 个 camera token。
2. **相机参考条件化：**将各视图相机参数转为 Plücker 射线图，并池化为与 16 个 register token 对应的射线嵌入。射线嵌入与 register 特征相加，提供粗略的空间坐标参考。推理时相机参数由模型的相机头预测，因此不要求外部输入相机位姿。
3. **形成紧凑场景表示：**每个视图贡献 16 个场景 token 和 1 个相机 token，共 **17 个 token**。场景表示可写为
   \[
   S=[S_1;\ldots;S_N],\qquad S_i=[\tilde z_{i,1},\ldots,\tilde z_{i,16}],
   \]
   其中每个视图的 token 数量不随图像分辨率变化；增加视图时，表示容量按视图数线性扩展。
4. **查询式 Gaussian 解码：**解码器使用跨场景共享的可学习查询，不以输入图像特征或 3D 锚点初始化。查询通过交叉注意力读取紧凑表示，再经过查询自注意力与前馈网络，最终预测 Gaussian 属性。由于解码器不能访问稠密 patch 特征，场景相关信息必须通过紧凑表示传递。
5. **渲染与训练：**将预测出的 Gaussian 场景渲染到目标相机视角，以渲染图像与真实目标图像之间的损失端到端训练编码器和解码器。总损失包括 RGB 光度损失、SSIM 损失、可见性正则项和相机监督损失。

### 关键实现细节

- 每个解码器查询预测 32 个 Gaussian；共使用 1,024 个查询，输出预算固定为 **32,768 个 Gaussian**。
- Gaussian 参数包括三维位置、外观系数、各向异性尺度、旋转四元数和不透明度。
- 解码器有 12 个 Transformer 层，隐藏维度 1,024、16 个注意力头。
- 场景尺度以相机距离进行归一化；训练时使用真实相机姿态构造射线参考，推理时使用相机头预测结果。
- 主要训练损失为：
  \[
  L=L_{\rm rgb}+\lambda_{\rm ssim}L_{\rm ssim}
  +\lambda_{\rm vis}L_{\rm vis}
  +\lambda_{\rm cam}L_{\rm cam}.
  \]

### 下游生成

- 冻结重建模型作为第一阶段编码器与 Gaussian 解码器。
- 以 8 个视图得到的 \(8\times16=128\) 个场景特征作为目标，训练 flow-matching 模型生成潜在场景表示。
- 生成的 latent 加上相机参考后，由冻结的 Gaussian 解码器一次性解码为显式 3D Gaussian 场景。

## 6. 主要结论与发现

- CoTL 能用每视图 17 个 token 形成场景记忆，相比每视图 16×16 的稠密 patch 网格约少 **15 倍**。
- 新增上下文视图带来的收益主要出现在 6 到 12 个视图之间；超过 24 个视图后，指标变化较小。
- 在 RealEstate10K 上，CoTL 获得有竞争力的 PSNR 和 SSIM；在部分设置下接近稠密记忆的 ZipSplat，但 LPIPS 仍有明显差距，说明局部纹理保真度仍偏弱。
- RealEstate10K 训练模型可直接迁移到 ACID，提供了零样本跨数据集泛化证据。
- 通过 flow-matching 在 token 空间生成表示，再用冻结解码器生成 Gaussian 场景，初步证明该表示不仅用于重建，也可作为 3D 场景生成的潜空间。

## 7. 优点

- **明确的信息瓶颈：**解码器无法访问输入稠密特征，较清楚地验证了紧凑 latent 是否真正承载场景信息。
- **表示可扩展：**每个视图只增加固定数量 token，容量随观测数增长，而不依赖图像分辨率。
- **显式且可渲染的输出：**最终重建为 3D Gaussian 场景，而非仅针对查询视角生成 RGB 图像。
- **兼顾无位姿设置：**通过相机头预测相机参数，并用射线嵌入为 latent 提供空间参考。
- **下游用途有展示：**将重建 latent 用于生成，并由同一 Gaussian 解码器恢复三维场景，体现出表示接口的复用潜力。
- **评估维度较丰富：**不仅评估不同视图数和重叠程度，也考察跨数据集迁移、token 规模及关键设计消融。

## 8. 不足与局限

- **场景与数据覆盖有限：**主要定量评估集中在 RealEstate10K 和 ACID；对室内场景、动态场景、复杂遮挡及更广泛开放世界环境的证据不足。
- **细节质量存在差距：**与使用稠密特征且额外读取 RGB 外观信息的 ZipSplat 相比，CoTL 的 LPIPS 较弱，细粒度纹理恢复仍是短板。
- **生成评估偏定性：**场景生成仅展示样例，未提供生成质量、多样性、几何一致性或与基线的系统量化比较。
- **工程成本仍高：**token 数减少并不意味着模型轻量；模型约 1.116B 参数，解码器含 1,024 个查询，且输出 32,768 个 Gaussian。论文没有报告完整训练时长、推理吞吐或显存占用。
- **坐标参考依赖相机估计：**推理时需要相机头预测准确；相机误差可能影响 token 的空间锚定与场景重建。
