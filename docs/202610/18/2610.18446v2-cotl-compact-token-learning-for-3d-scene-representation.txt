Abstract
We present CoTL, a framework that learns a compact set
of tokens that preserves scene geometry and appearance
from unposed multi-view images. Our encoder compresses
the input images into small per-view sets of latent tokens
that aggregate information across views to form a view-
consistent scene representation. Each additional view ex-
pands the representation with only a small, resolution-
independent set of tokens, allowing its capacity to grow with
the available observations. To force this compact bottle-
neck to retain sufficient scene information, a query-based
Gaussian decoder uses scene-independent queries to at-
tend to the learned tokens and recover an explicit, render-
able set of 3D Gaussian primitives. Novel-view rendering

1. Introduction
Learning a scene representation from multi-view images
requires compressing view-dependent observations into a
compact encoding of the underlying 3D world. This rep-
1

resentation must preserve shared geometry and appear-
ance across views while discarding redundant view-specific
information.
Yet many recent feed-forward reconstruc-
tion models retain dense feature representations produced
by pretrained multi-view geometry backbones, comprising
hundreds of patch tokens per image.
A dominant class
of feed-forward reconstruction methods uses dense pixel-
aligned features as the visual memory, predicting pixel-
aligned Gaussian primitives from dense per-view feature
grids [20, 64, 65]. Other approaches decouple the Gaus-
sian output budget from the input grid using clustered vi-
sual tokens, global latent tokens, adaptive 3D anchors, or
learned queries [1, 17, 18, 28, 35, 46]. This indicates that
the explicit scene output need not inherit the size and layout
of the image grid, but the decoder still retrieves scene in-
formation from dense per-view patch features. A compact
Gaussian output therefore does not imply a compact latent
scene representation.
Compact scene representations provide a practical in-
terface for downstream models. In 3D scene understand-
ing, vision–language models often aggregate dense scene
features into a compact set of tokens, enabling scene-level
representations to be efficiently processed within the con-
text budget of a language model [7, 14, 29]. Compact rep-
resentations are particularly useful for generation because
they allow scene distributions to be modeled in a lower-
dimensional latent space rather than directly over high-
dimensional signals [37]. Some existing 3D object-level
generation models operate on 1D shape tokens [66, 74], and
recent work compresses entire scenes into 1D tokens for
generation or reconstruction [2, 8, 56]. In these methods,
however, the tokens either encode geometry without appear-
ance [8, 66, 74] or are decoded directly into target views
without yielding an explicit, renderable 3D scene [2, 56].
These designs leave open how to learn a compact scene-
level representation that jointly carries geometry and ap-
pearance and can be decoded into an explicit, renderable
3D scene.
This raises a fundamental question: can a small set of
learned tokens replace the dense feature grid at the encoder–
decoder interface, while preserving the geometry and ap-
pearance needed to reconstruct an explicit, renderable 3D
scene?
In this work, we explicitly study compact scene repre-
sentation learning from unposed multi-view images. We
present CoTL, a framework that places a strict representa-
tion bottleneck between dense visual encoding and down-
stream tasks. Given N unposed images, our encoder repre-
sents each view with a small, fixed set of latent tokens that
aggregate information from its dense visual features. The
resulting scene representation is view-scalable: its capac-
ity grows with the number of observations, while its per-
view token budget remains independent of image resolu-
tion. These tokens are jointly contextualized across views
to form a compact, scene-dependent representation. Cru-
cially, after this compression stage, downstream prediction
no longer accesses the original dense patch features.
Since the contents of a latent scene representation are not
specified by a direct supervision target, we instead learn the
representation by decoding it into an explicit 3D Gaussian
scene and supervising the rendered novel views. For this
objective to require the latent memory to carry the scene in-
formation needed for reconstruction, the Gaussian decoder
must receive no other input-dependent visual scene content
derived from the input. It therefore has no access to dense
patch features, and its Gaussian queries are learned globally
across scenes rather than initialized from image features
or 3D anchors. The controlled interface forces all scene-
specific visual evidence through the latent memory, while
rendering supervision trains the memory to encode the in-
formation required for novel-view reconstruction.
We build the encoder on a pretrained multi-view geom-
etry foundation model [48], which maintains a small num-
ber of tokens per view that participate in cross-view atten-
tion alongside its dense features. We adopt these tokens
as the compact scene representation, initialize the encoder
from the pretrained weights, and optimize it jointly with the
Gaussian decoder. Joint optimization adapts the representa-
tion to the reconstruction objective.
We evaluate the novel-view synthesis quality supported
by the learned representation across different numbers of
context views and overlap regimes on RealEstate10K [76].
Across the evaluated settings, the compact representa-
tion supports competitive novel-view synthesis.
Ex-
periments across view counts show that the representa-
tion incorporates additional observations through a small,
resolution-independent set of tokens per view.
The
RealEstate10K [76]-trained model also supports novel-view
synthesis on ACID [31] without fine-tuning, providing ev-
idence of zero-shot cross-dataset transfer.
As a down-
stream proof of concept, we train a flow-matching model
in the learned token space and decode its generated latents
into explicit 3D Gaussian scenes using the frozen Gaus-
sian decoder. Together, these results show that rendering-
supervised 3D Gaussian reconstruction is an effective ob-
jective for compact scene representation learning and that
the resulting latent space provides a basis for broader down-
stream tasks in 3D vision.
2. Related Work
Latent Scene Rrepresentations.
Scene representations
can be learned from multi-view observations through ren-
dering supervision. [11] aggregates posed observations into
a fixed-size global scene representation and decodes it di-
rectly into the image at a queried viewpoint. [25] sim-
2


ilarly infers a global scene latent from posed observa-
tions, but decodes it through a conditional radiance field.
Some approaches [24, 38, 39, 43] retain spatial features
for each input view, so their memory grows with both the
number of views and the encoder feature-map resolution.
The encoder–decoder variant of LVSM [21] instead com-
presses all observations into a fixed set of latent tokens, and
RayZer [19] extends this fixed-latent design to unposed im-
ages. In such designs, additional observations must share
the same latent budget. [55] condenses dense features into
ray-anchored tokens and allows the token budget to be se-
lected at inference.
Although these approaches allocate
representational capacity differently, their decoders synthe-
size each requested view from target-camera or ray queries,
rather than first decoding an explicit 3D scene.
Other work develops compact 3D token spaces for mod-
eling and generation. At the object level, [26, 66, 69, 73]
learn latent representations of shape geometry, while ap-
pearance is generated separately from the shape latent. At
the scene level, Nova3R [8] and Surflo [13] decode fixed
global tokens into geometry, whereas Can3Tok [12] autoen-
codes preconstructed per-scene 3D Gaussians. 3DRAE [56]
and SceneTok [2] learn fixed-size scene token sets from
multi-view observations and model their distributions in to-
ken space. Their target-camera-conditioned decoders pro-
duce RGB images, or RGB images together with point
maps. Other scene generation systems retain spatially struc-
tured latents: [36] uses sparse voxels, whereas [15, 62] uses
multi-view RGB-D latents tied to image grid.
Scene features can also serve as token interfaces for
downstream models. [7, 14, 29, 45] provide tokenized scene
features to language models for 3D understanding. Against
this background, our formulation learns a view-scalable, un-
structured scene memory from unposed images through 3D
Gaussian reconstruction, with each input view contributing
a small, resolution-independent token set. A separate Gaus-
sian decoder maps this memory once into an explicit, ren-
derable 3D scene that carries both geometry and appear-
ance.
Feed-forward
3D
Gaussian
Reconstruction.
Feed-
forward 3D Gaussian reconstruction methods predict 3D
Gaussian primitives from multi-view images in a single
pass [67] rather than optimizing a separate 3DGS represen-
tation for each scene [23]. A major family ties primitive
prediction to the input image grid [41, 42, 44, 61, 68], ag-
gregating cross-view features through epipolar attention [5]
or multi-view cost volumes [9, 10, 32, 59]. VolSplat [51]
instead produces Gaussians from a learned 3D voxel grid,
providing a voxel-aligned alternative to image-grid-based
prediction.
Other variants modify the predicted primi-
tive or the inference procedure through variational fea-
ture Gaussians, oriented triangle primitives, or recurrent
refinement [52, 57, 58]. Pose-free methods extend feed-
forward reconstruction to images without using camera
poses as input [16, 20, 60, 64, 65, 71]. Several build on
pretrained geometry models and inherit priors for multi-
view correspondence, camera estimation, and 3D struc-
ture [3, 4, 6, 22, 27, 47, 49, 54]. For pixel-aligned methods,
the native primitive count grows with both the number and
resolution of the input views. Subsequent work reduces this
redundancy through fusion, pooling, selection, or compres-
sion [34, 40, 53, 70].
A second group decouples Gaussian allocation from
the input image grid.
Some methods use free learnable
queries [1, 18, 28, 35], while others derive tokens by clus-
tering visual features or construct them from depth-based
3D anchors [17, 46, 72]. These designs reduce or adapt
the Gaussian output budget, but several retain dense per-
view features in the Gaussian-prediction path. A compact
Gaussian output therefore does not by itself establish a com-
pact latent scene representation. Our method instead defines
a compact, view-scalable scene memory at the encoder–
decoder interface, with a small, resolution-independent to-
ken allocation per view, while its Gaussian output budget is
controlled separately. Rendering-supervised 3D Gaussian
reconstruction provides the learning objective for this mem-
ory, while its separation from the Gaussian output makes it
available as a latent interface for downstream 3D tasks.
3. Method
Our method learns a compact latent representation that sum-
marizes scene information across multiple unposed images.
We learn this representation through pose-free 3D Gaussian
reconstruction, using novel-view rendering supervision to
optimize it end to end. Figure 2 summarizes the pipeline.
Our model first encodes the input views, into a small
set of scene tokens, which form the only source of visual
scene content available to the Gaussian decoder. Learned
queries shared across scenes then retrieve information from
this memory and decode it into an explicit set of 3D Gaus-
sians, which can be rendered from novel viewpoints. Dur-
ing training, the loss between rendered novel views and
their corresponding ground-truth target views, together with
the auxiliary terms in Sec. 3.4, is backpropagated through
the decoder into the encoder and optimizes the scene repre-
sentation itself.
In the following, Section 3.1 formalizes the task setting.
Section 3.2 describes how the encoder constructs the com-
pact scene representation. Section 3.3 presents the Gaussian
query decoder, and Sec. 3.4 the training objective.

3.3. Gaussian Query Decoder
The Gaussian decoder maps the compact scene memory S
to a set of 3D Gaussians G via cross-attention. Specifically,
the decoder consists of a stack of Transformer layers initial-
ized with M scene-agnostic, learnable queries Q ∈RM×d.
To improve computational efficiency, the scene memory S
is projected into key and value representations once and
reused across all decoder layers. Each layer performs cross-
attention over S and query self-attention, followed by a
feed-forward network. Importantly, because the queries Q
are shared across scenes without any input-derived spatial
initialization or 3D anchors, all scene-specific information
is forcibly bottlenecked through the compact memory S.
A lightweight prediction head subsequently decodes
each final query token into KG 3D Gaussians. Each Gaus-
sian is parameterized by its 3D position, appearance coef-
ficients, anisotropic scale, rotation quaternion, and opac-
ity. The total number of generated Gaussians is fixed at
NG = M · KG, ensuring a constant computational budget
for downstream rendering regardless of the number of con-
text views N. Further architectural details, parameter set-
tings (M, KG, depth), and output parameterization heads
are provided in Sec. 4.1 and the supplementary material.
3.4. Training Objective
Our model is trained end-to-end under joint rendering su-
pervision, geometric regularization, and auxiliary pose su-
pervision. The total loss function is formulated as follows:
L = Lrgb + λssimLssim + λvisLvis + λcamLcam,
(4)
where Lrgb denotes the L2 photometric loss between the
rendered and ground-truth target views, and Lssim measures
structural similarity.
Auxiliary Regularization.
To eliminate unconstrained
Gaussians in invisible regions, we incorporate the visibil-
ity regularization loss Lvis from TokenGS [35], which pe-
nalizes Gaussians projecting outside the visual frustums of
all supervision cameras. Additionally, following VGGT-
Ω[48], Lcam is a Smooth L1 loss between the predicted
and ground-truth 9D camera representations. We empiri-
cally set the loss weights to λssim = 0.2, λvis = 1.0, and
λcam = 0.05.
4. Experiments
We first describe the implementation, architecture, and
training setup of CoTL in Sec. 4.1. We then evaluate the
novel-view synthesis quality supported by the learned com-
pact scene representation and examine its zero-shot transfer
to out-of-domain data in Sec. 4.2. Next, Sec. 4.3 quantifies
the compactness of the representation, and Sec. 4.4 demon-
strates its downstream utility for 3D Gaussian scene gen-
eration. Finally, Sec. 4.5 studies the role of camera refer-
ences in anchoring the latent scene features and the choice
of scene normalization.
4.1. Implementation Details
4.1.1. Architecture
We initialize the encoder from the pretrained VGGT-Ω[48].
For each input view, the 16 final-layer register tokens are
augmented with pooled Pl¨ucker-ray embeddings and con-
stitute the compact scene memory. We retain the VGGT-Ω
camera head to estimate the intrinsics and extrinsics of the
context views, while discarding all dense prediction heads.
The Gaussian decoder consists of 12 Transformer blocks,
each comprising cross-attention to the compact scene mem-
ory, query self-attention, and an MLP. It has a hidden di-
mension of 1,024 and 16 attention heads, and operates on
M = 1,024 learned scene-independent queries. Each query
predicts KG = 32 Gaussians, resulting in a fixed output
budget of NG = MKG = 32,768 Gaussians. The encoder
and Gaussian decoder are optimized jointly end to end.
4.1.2. Training
We train our model on the official RealEstate10K training
split [76] using four NVIDIA H100 GPUs with a per-GPU
batch size of 6, corresponding to a total batch size of 24.
Each training sample is constructed from a temporal win-
dow of a training video. The first and last frames serve
as the context endpoints, additional context views are sam-
pled from the intermediate frames, and six of the remain-
ing frames are used as rendering targets. Training is per-
formed at a resolution of 256 × 256 with a patch size of
16.
We express all camera poses and scene coordinates
in a canonical frame anchored at the first context camera
and apply camera-distance normalization. We use AdamW
with β1 = 0.9 and β2 = 0.95, together with a OneCycle
learning-rate schedule.

4.2.2. Evaluation Protocols and Metrics
Following the C3G evaluation protocol [1], we start from
the NoPoSplat [64] two-view RealEstate10K [76] index and
uniformly insert frames between the two indexed context
endpoints. This produces context sets of 6, 12, 24, and
36 views while keeping the three indexed target views un-
changed. Novel-view rendering quality is evaluated using
PSNR, SSIM, and LPIPS.
4.2.3. Baselines
To contextualize the novel-view rendering quality supported
by the learned representation We report two pose-free meth-
ods for generalizable novel view synthesis that decode
global Gaussian sets as reference points: C3G [1] and Zip-
Splat [46]. C3G uses a fixed output budget of 2K Gaussians.
We configure ZipSplat with the same 32K-Gaussian output
budget as CoTL.
4.2.4. Reconstruction Quality
As shown in Tab. 1, reconstruction quality improves most
from 6 to 12 context views across all three overlap regimes
and changes little beyond 24 views. The endpoint views and
Gaussian output budget are held fixed. Under this control,
the additional observations can affect the Gaussian decoder
only through the compact scene representation. The im-
provement therefore provides direct evidence that the mem-
ory integrates additional visual evidence across views and
retains both geometric and appearance information useful
for rendering.
C3G provides a lower-output-budget reference with 2K
Gaussians; CoTL achieves higher PSNR and SSIM across
all settings and lower LPIPS with at least 12 context views.
ZipSplat provides a dense-memory reference at the same
Gaussian output budget. With 12 or more context views
in the large-overlap regime, CoTL approaches ZipSplat in
PSNR and exceeds it in SSIM, although a clear LPIPS gap
remains. Qualitative comparisons in Fig. 3 are consistent
with this metric pattern: CoTL retains the overall scene
structure and appearance, while ZipSplat preserves finer lo-
cal textures in some regions.
The differences between CoTL and ZipSplat should also
be interpreted in light of their distinct decoder interfaces.
ZipSplat is designed primarily for 3D reconstruction and
does not isolate a compact latent scene representation at
the encoder–decoder interface: its decoder reads dense per-
view features, and its Gaussian head additionally receives
color features obtained by cross-attending directly to patch-
embedded RGB inputs. In contrast, we explicitly separate
the compact scene representation from the Gaussian de-
coder that reads it. This separation exposes a reusable latent
interface for downstream modeling beyond reconstruction.
The results in Tab. 2 show that the RealEstate10K-
trained model supports novel-view synthesis on ACID with-
out fine-tuning, providing evidence of zero-shot cross-
domain transfer.
Together,
these results show that
rendering-supervised 3D Gaussian reconstruction learns a
compact scene memory that retains sufficient visual infor-
mation for pose-free novel-view synthesis.

4.4. 3D Scene Generation
We further demonstrate that the compact, unstructured
scene representation learned through reconstruction can
serve as the latent space of a generative model [37] for 3D
scene generation. We use the trained reconstruction model
as a frozen first stage. During second-stage training, the
frozen encoder maps eight views of each scene to the la-
tent scene features Z ∈R(8n)×d.
These features serve
as the training targets for a second-stage flow-matching
model [30], which generates Z conditioned on the first of
the eight images supplied to the encoder, together with the
camera parameters of all eight views.
The network ar-
chitecture, conditioning mechanism, and training details of
the flow-matching model are provided in the supplementary
material.
At inference, the generated features are combined with
the corresponding camera references to form the scene rep-
resentation S, following Eq. (3). The frozen Gaussian de-
coder then maps S to an explicit 3D Gaussian scene, which
can be rendered from novel viewpoints in real time. Fig-
ure 5 shows six generated scenes, each rendered from multi-
ple viewpoints. The samples show plausible scene comple-
tions that remain coherent across the rendered views, pro-
viding evidence that the learned token representation sup-
ports downstream 3D scene generation.

This section examines two design choices for learning the
compact, unstructured scene representation: the camera ref-
erence used to anchor its latent features and scene-scale nor-
malization.

reference. In the global camera anchor variant, each view’s
camera token is concatenated with its latent scene features.
In our pooled ray-map references variant, each latent scene
feature is associated with a pooled ray-map reference de-

4.5.2. Scene Normalization
We now compare three difference scene normalization
choices. Our camera-distance normalization uses ρscene =
maxi∥ci −c1∥2 —the maximum distance from any context
camera to the first—as the scene scale. We divide all camera
translations and scene coordinates by this scale. The point-
cloud-radius normalization instead uses the 95th-percentile
radius of the point cloud obtained by unprojecting the pre-
computed context-view depth maps.
The no normaliza-
tion variant retains the raw dataset scale. The point-cloud
and unnormalized variants lead to less stable early opti-
mization, with the latter showing the largest degradation.
Camera-distance normalization instead defines a consistent
scale from the context-camera configuration. We therefore
use camera-distance normalization in all experiments.
5. Conclusion
In this work, we present CoTL, a framework for learning a
compact, view-scalable scene representation directly from
unposed multi-view images via 3D Gaussian reconstruc-
tion. By compressing multi-view inputs into a concise set of
view-wise tokens, CoTL establishes an explicit information
bottleneck: the scene memory serves as the sole condition
for a set of scene-agnostic queries, forcing it to retain only
the essential scene tokens required for high-fidelity geomet-
ric and appearance reconstruction.
Furthermore, we demonstrate that this compact token
representation provides an effective latent space for 3D gen-
erative modeling. Compared to video-diffusion-based scene
synthesis, generating scene latents directly in this space sig-
nificantly accelerates inference while enforcing strict cross-
view geometric consistency. Once generated, the latent rep-
resentation is decoded in a single feed-forward pass into an
explicit 3D Gaussian scene, enabling real-time novel-view
rendering without the per-view decoding overhead inherent
to prior approaches.
Looking forward, we anticipate several promising direc-
tions. Future work includes scaling up the pre-training data
to explore whether this compact representation is able to
generalize to open-world environments. Additionally, we
plan to extend the generative latent space to support flex-
ible view counts and multi-modal controls (e.g., text con-
ditioning). More broadly, we envision this compact scene
memory acting as a general-purpose, reusable interface for
downstream 3D understanding, interactive editing, and per-
sistent spatial memory in embodied intelligence.

B. Additional Implementation Details
B.1. Gaussian Output Head
We build on the Gaussian output head of TokenGS [35].
A linear prediction layer maps each decoded query fea-
ture to 32 raw Gaussian parameter vectors, which are
mapped through attribute-specific activation functions. The
raw center outputs use the signed-exponential activation
sign(x)(e|x| −1). We then add a constant offset of one

B.2. Training Details
The complete model comprises the VGGT-Ω[48] encoder,
a 12-layer Gaussian decoder, and the retained camera head,
with 1,116 M parameters in total.
We initially train the
model for 500,000 steps using AdamW (β1 = 0.9, β2 =
0.95) and a OneCycle learning-rate schedule with a peak
learning rate of 4 × 10−4 and a 5,000-step warm-up. This
training uses eight context views and spherical harmonics
of degree zero. We subsequently fine-tune the model us-
ing a randomized number of context views and spherical
harmonics of degree three.
We initialize the DC coeffi-
cients from the learned degree-zero color readout and set the
newly introduced higher-order coefficients to zero. For each
batch, the context-view count is sampled uniformly from
6–12 with probability 0.75 or from 13–24 with probability
0.25.
C. Evaluation Protocol
C.1. Image Preprocessing
We prepare the input images for each method at the reso-
lution used during its training. Starting from the original
640 × 360 frames, CoTL and C3G [1] resize each frame to
a height of 256 pixels while preserving its aspect ratio, fol-
lowed by a 256 × 256 center crop. ZipSplat [46] follows
the same procedure at its native training resolution, resizing
each original frame to a height of 252 pixels before taking
a 252 × 252 center crop.
C.2. Pose Alignment
Pose alignment and metric evaluation are performed at
256 × 256 for all methods. For ZipSplat [46], target images
processed at its native 252 × 252 resolution are upsampled
to 256 × 256 for evaluation, while its reconstructed scene is
rendered directly at 256 × 256.
The ground-truth target cameras are first transformed
into each method’s canonical reconstruction frame accord-
ing to its scene canonicalization and normalization conven-
tion. Starting from these transformed target cameras, we re-
fine each target pose photometrically while keeping the re-
constructed Gaussians fixed. For C3G [1] and ZipSplat [46]
we use their officially released evaluation scripts. Across
all methods, we use shared alignment settings: rotation and
translation learning rates of 0.005, 100 optimization steps,
and no early stopping.

E. Scene Generation
The generative model performs single-image-conditioned
3D scene generation. The reference image provides the ob-
served scene content, while the camera parameters of eight
views define the spatial extent of the generated scene. Con-
ditioned on both, the model produces a 3D scene that can
be rendered from novel viewpoints throughout this extent.
Latent Space.
The flow-matching model operates on the
latent scene features Z of the reconstruction model. The
reconstruction encoder maps eight views of each scene to
12


8 × 16 = 128 features of width 1024, extracted before the
camera reference in Eq. (3) is added. We normalize the fea-
tures per channel using statistics estimated over the training
split and denote their interpolated state at flow time t by Zt.
The model is conditioned on the first of the eight images
and the camera parameters of all eight views, expressed in
the canonical frame anchored at the first camera.
Flow-matching Network.
The flow-matching network
follows the transformer architecture of LightningDiT [63].
Its backbone contains 12 blocks of width 1024 with 16 at-
tention heads. Following [56, 75], we append a two-block
DDT head [50] of width 2048 to the backbone for high-
dimensional velocity prediction.
Conditioning.
The image and camera conditions enter the
flow-matching network through separate paths. A frozen
DINOv2 ViT-L/14 [33] encodes the reference image into
18 × 18 patch features, which are combined with the corre-
sponding Pl¨ucker-ray embeddings to form 324 conditioning
tokens. These tokens are prepended to Zt, and the com-
plete sequence is processed jointly by self-attention. Cam-
era control is applied directly to Zt: the Pl¨ucker ray map
of each view is patch-embedded and average-pooled into a
single vector, which is added to all 16 latent features of that
view.
Training.
Following
the
general
strategy
of
noise-
augmented decoding [75], we fine-tune the reconstruction
model with additive Gaussian perturbations applied to the
latent scene features, improving its robustness to latent per-
turbations. We then freeze the adapted encoder and Gaus-
sian decoder during flow-matching training.
The flow-
matching network regresses the velocity using a mean-
squared-error objective [30].
Timesteps follow a logit-
normal distribution with a dimension-dependent shift, fol-
lowing [56].
During training, the image condition is
dropped with probability 0.1 to enable classifier-free guid-
ance at sampling time.
We train the flow-matching network for 100,000 steps
using the full reference image and then fine-tune it for a
further 50,000 steps using random crops covering one quar-
ter of the image area. Both training periods use a per-GPU
batch size of 32 and a peak learning rate of 1 × 10−4 with
1,000 warm-up steps. Each crop is resized to the original
conditioning resolution before tokenization, preserving the
324-token layout.
Sampling and Decoding.
We sample with 50 Euler steps
using classifier-free guidance with a scale of 1.5. The gen-
erated latent scene features are denormalized and combined
with the camera references of the requested views to form
the compact scene representation S, following Eq. (3). The
frozen Gaussian decoder maps S in a single forward pass to
an explicit 3D Gaussian scene, which can subsequently be
rendered from any viewpoint in real time.
