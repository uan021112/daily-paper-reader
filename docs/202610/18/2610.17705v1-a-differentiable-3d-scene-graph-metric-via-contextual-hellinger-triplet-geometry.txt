## Abstract 

3D scene graph prediction is commonly supervised with local object and predi-cate classification losses. Although effective for slot-wise label prediction, this formulation does not provide a graph-level semantic distance between a predicted scene graph and its ground truth: semantically mild label errors and structurally disruptive relational errors can be treated similarly, and subject-predicate-object facts are not compared as scene-level units. We propose Contextual Hellinger Triplet Geometry , a graph-level supervision objective that measures the semantic and structural discrepancy between 3D scene graphs. Our key idea is to reinterpret the conventional classifier outputs of a 3D scene graph predictor as an aligned probabilistic scene graph field, where object and predicate predictions jointly define contextual subject-predicate-object facts. This formulation yields a differentiable metric-based training objective with an efficient factorized implementation and can be applied to existing 3D scene graph prediction architectures without modifying their network design. Experiments on 3DSSG demonstrate that our supervision im-proves downstream graph-conditioned 3D scene generation, while ablation studies confirm the complementary roles of the proposed graph-level terms and user studies show better graph descriptiveness, relation plausibility, and structural preservation. 

## 1 Introduction 

3D semantic scene graphs [40] represent a scene as a structured object-relation system, where object instances are encoded as nodes and semantic or spatial relationships are encoded as edges. This representation provides an object-centric abstraction of 3D environments and supports relational reasoning beyond dense point clouds, meshes, or voxelized reconstructions. Since the introduction of 3D semantic scene graph prediction from indoor reconstructions [40], subsequent work has explored incremental RGB-D scene graph construction [42], knowledge-guided relation prediction [45], visual-linguistic semantic assistance [41], multimodal spatial knowledge accumulation [12], heterogeneous graph learning [28], transformer-based graph modeling [27], open-vocabulary 3D scene graph generation [8, 23], object-centric representation learning [17], and edge-centric relational reasoning [29]. These advances have significantly improved the modeling capacity of 3D scene graph systems. In this paper, we study a fundamental question: How to define similarity or distance between two 3D scene graphs? The standard supervised formulation of 3D scene graph prediction [12, 17, 27–29, 40, 41] is expressed over object instances and directed object-pair slots. A model predicts object labels for nodes and predicate labels for directed object pairs, and the training objective typically supervises these outputs through local object and predicate classification losses. Such losses are effective for slot-wise label prediction and provide a natural measure of local target agreement. A natural alternative would be to use general graph distance formulations, but they are difficult to use in neural training [31]. Graph edit distance compares graphs through edit operations and is closely related to inexact graph matching [14, 34]. Approximate graph edit distance methods often rely on combinatorial assignment procedures, such as bipartite graph matching [32, 33]. These formulations are suitable for comparing arbitrary graphs [14, 33], but they are not well aligned with supervised 3D scene graph prediction [12, 40, 41]. Without fixed correspondences, graph similarity must first decide which nodes and edges should be matched [14, 33], and the resulting comparison can be ill-posed for scene graph learning because semantically related scenes may differ in topology, indexing, or object decomposition. Moreover, generic edit operations do not directly encode scene-specific semantics, such as object roles, predicate contexts, or subject-predicate-object facts [29, 41, 45]. Our method is inspired by the observation that supervised 3D scene graph prediction provides structure that general graph similarity does not have. In the common object-instance-based setting, the predicted graph and the annotated graph are defined over the same object-instance slots and the same directed object-pair slots. It removes the ambiguity of arbitrary node matching and makes it possible to define a well-specified distance between probabilistic 3D scene graphs. To this end, we introduce Contextual Hellinger Triplet Geometry , a differentiable metric for fixed-correspondence 3D scene graph prediction. The method constructs contextual semantic probability measures for object and relation labels from the training scene graph database. Predicted object and relation distributions are lifted into these contextual measure spaces and compared using Hellinger geometry of probability measures [1, 15]. For each directed object-pair slot, the lifted subject measure, predicate measure, and object measure are composed into a subject-predicate-object product measure. The proposed objective then aligns both corresponding triplet semantics and scene-internal triplet geometry, thereby turning local classifier outputs into a graph-level semantic field. Our contributions are fourfold. First, we formulate supervised 3D scene graph learning as a differen-tiable fixed-correspondence graph metric problem, avoiding the correspondence ambiguity of general graph similarity while preserving the relational nature of scene graphs. Second, we introduce contex-tual semantic probability measures for object and relation labels, including a canonical treatment of no-relation. Third, we define a Hellinger triplet geometry distance that compares subject-predicate-object semantic facts and aligns their scene-internal geometry. Fourth, we show that, under fixed correspondence and identity-anchor assumptions, the square root of the proposed squared loss defines a metric on aligned probabilistic 3D scene graphs, and we provide an exact factorized implementation that avoids explicitly constructing high-dimensional tensor product features. 22 Preliminaries and Problem Formulation 

Fixed-Slot 3D Scene Graph Prediction. We consider supervised 3D scene graph prediction from a 3D scene input X, represented by n object instances or segments as graph nodes. We denote the node slot set by

R0 = R ∪ { ∅}. (3) A 3D scene graph prediction model produces an object distribution for each node slot, 

pi ∈ ∆|C| , i = 1 , . . . , n, (4)

sa ∈ [0 , 1] |R| . (6)

3.2 Subject-Predicate-Object Triplet Representation 

Instead of supervising subject, predicate, and object independently, we represent each directed object-pair slot as a contextual subject-predicate-object semantic fact. For an edge slot a ∈ A from Eq. (2), the triplet product measure is 

ρa = αs(a) ⊗ βa ⊗ αt(a). (25) 

Its Hellinger feature is 

za = √ρa = vs(a) ⊗ ua ⊗ vt(a). (26) 

Here α, β, v, u denote either predicted or ground-truth quantities, depending on the graph under consideration. For two edge slots a, b ∈ A , the triplet affinity factorizes as 

⟨za, z b⟩ = ⟨vs(a), v s(b)⟩⟨ ua, u b⟩⟨ vt(a), v t(b)⟩. (27) 

This factorization follows from the product structure in Eq. (25) [4]. It lets us compare subject-predicate-object semantic facts without explicitly constructing the high-dimensional tensor product in Eq. (26).

3.4 Metric Property and Efficient Computation 

We summarize the main theoretical property of Eq. (35) in Theorem 3.1. A full proof is provided in Appendix F. 

Theorem 3.1. Assume that the graphs under comparison share the fixed node and edge slots defined in Eqs. (1) and (2) , that A contains all directed object pairs with n ≥ 2, and that the contextual semantic measures in Eqs. (15) and (16) contain exclusive class-specific identity anchors with positive mass, as specified in Appendix D.3. Also assume the canonical no-relation measure in Eq. (17) . Then 

Dmetric in Eq. (35) is a metric on aligned probabilistic 3D scene graphs, where graph identity is defined under the fixed node and edge correspondence. Proof (Summary). The exclusive class-specific identity anchors make the semantic lifting maps in Eqs. (18) and (20) injective; the explicit recovery argument is given in Appendix F.2. The square root of the aligned term in Eq. (28) is an ℓ2 product metric of Hellinger distances over corresponding triplet product measures. The square root of the geometry term in Eq. (34) is a Euclidean pseudometric between off-diagonal contextual triplet distance-geometry descriptors, equivalently computed through the Gram representation by Eq. (33). Their direct-sum form in Eq. (35) therefore satisfies non-negativity, symmetry, and the triangle inequality. If Dmetric (G, H ) = 0 , then D2align (G, H ) = 0 , so all aligned triplet product measures in Eq. (25) are equal. Taking marginals gives equality of all lifted node and relation measures, and injectivity of the semantic lifting gives equality of the original node and edge distributions. Hence G = H under fixed correspondence. Finally, Eq. (27) gives an exact implementation of each Gram entry without explicitly constructing 

za. Thus, all aligned and geometry terms can be computed from object and relation affinity matrices. The full matrix implementation and complexity analysis are given in Appendix H. □

4.1 Experimental Details Dataset. We evaluated on 3DSSG [40], built on 3RScan [39]. Following recent 3D scene graph prediction protocols [17, 41], we used the standard train/validation split with 1,553 indoor scenes, 160 object categories, and 26 predicate types. 

Metrics and Task Description. Because our objective targets graph-level semantic similarity, the primary downstream evaluation is graph-conditioned scene generation: predicted graphs are fed to the same generator, and generated 3D scenes are compared with references using multi-view FID [18], KID [5], and user studies over descriptiveness, relation plausibility, faithfulness, and structural preservation. 4.2 Graph-Conditioned 3D Scene Generation Evaluation 

To evaluate predicted 3D scene graphs from a downstream generation perspective, we used OCRL [17] as the 3D scene graph prediction backbone and EchoScene [44] as the graph-conditioned 3D scene generator. The OCRL baseline is trained with the original local classification objective Lcls in Eq. (9), whereas our variants are trained with the proposed graph-level supervision terms in Eq. (36). For all methods, predicted graphs are decoded using the same rule and passed to the same generator under an identical generation protocol. Following Appendix B.5, we compute FID [18] and KID [5] between multi-view renderings of 3D scenes generated from ground-truth graphs and those generated from predicted graphs. The quantitative comparison and ablation results are summarized in Table 1. Additional comparisons across different prediction backbones and graph-conditioned generators are provided in Appendix C.1, and the candidate-edge setting is studied in Appendix C.4. 

Graph-Conditioned Reconstruction Results. Our full model achieves the best performance among the compared variants in both FID and KID. Because the same scene generator, graph decoding rule, and rendering-based evaluation protocol are used for all methods, the improvement indicates that the proposed supervision produces predicted graphs that are more effective as conditions for downstream 3D scene generation. In particular, our method better preserves the semantic composition and spatial organization required to generate plausible 3D indoor scenes, rather than optimizing only independent object and predicate predictions. The qualitative results in Figure 2 confirm these findings: scenes generated from our predicted graphs exhibit more plausible object composition and relational layout, and are closer to the scenes generated from ground-truth graphs than those generated from the OCRL predictions. 

Ablation Study. We further analyze the contribution of the two graph-level terms in Eq. (36). The variant using only the aligned triplet term D2align improves over the local classification baseline, suggesting that matching subject-predicate-object facts in the contextual triplet space provides a more scene-aware semantic training signal than independent local classification. The variant using only the scene-internal triplet geometry term D2geom also improves the generation metrics, indicating that preserving the relative geometry among relational facts helps maintain scene-level structural coherence. The full model performs best, demonstrating that the two terms are complementary: 

D2align encourages aligned semantic faithfulness, while D2geom regularizes the internal relational organization of the predicted graph.

For each input scene, participants compared two generated scenes obtained by feeding the predicted graphs into the same graph-conditioned 3D scene generator, and evaluated faithfulness to the input scene and structural preservation . The consistent preference for our method suggests that our graph predictions provide more effective conditions for downstream 3D scene generation. In particular, the preference in structural preservation suggests that the proposed supervision helps retain scene-level spatial organization, which is difficult to capture using only independent local prediction objectives. 

## 5 Conclusion 

We presented Contextual Hellinger Triplet Geometry , a graph-level supervision objective for 3D scene graph prediction. By reinterpreting conventional object and predicate classifier outputs as an aligned probabilistic scene graph field, our method compares subject-predicate-object facts and their scene-internal relational geometry through an efficient differentiable metric-based objective. 9Experiments on 3DSSG show that the proposed supervision better preserves scene-level semantics and spatial organization, improving predicted graphs as conditions for graph-conditioned 3D scene generation. While the current formulation focuses on supervised instance-level prediction with contextual statistics from training annotations, future work may extend it to partially matched, open-vocabulary, or dynamically constructed scene graphs.

## A Related Work 

A.1 3D Semantic Scene Graph Prediction 

3D semantic scene graph prediction has been studied across multiple input modalities and modeling paradigms. Wald et al. [40] established the benchmark formulation of learning 3D semantic scene graphs from indoor reconstructions, and SceneGraphFusion [42] extended the idea to incremental RGB-D observations. For point-cloud-based 3D scene graph prediction, subsequent work improved relational prediction through knowledge-guided reasoning [45], visual-linguistic supervision [41], and multimodal spatial knowledge accumulation [12]. More recent methods further strengthened relational modeling using heterogeneous graph learning [28], transformer-based graph reasoning [27], object-centric representation learning [17], and edge-centric relational reasoning [29]. These methods differ substantially in backbone architecture, feature construction, and auxiliary supervision. However, they largely share the same underlying prediction setting as our work: object predictions are defined on fixed object-instance slots, and relation predictions are defined on directed object-pair slots. Our work is complementary to this literature. Rather than proposing a new 3D scene graph backbone, a new multimodal fusion module, or a new language-guided reasoning component, we focus on the structure of the training objective itself and ask how a predicted graph should be compared to its aligned ground truth at the scene level. 3D scene graphs are also used as structured scene representations beyond recognition alone. For example, graph-conditioned 3D scene generation and diffusion-based synthesis have been studied in CommonScenes [43] and EchoScene [44]. More broadly, diffusion-based generative modeling has also been combined with adversarial learning in both image and autoencoded latent spaces [19, 20]. These downstream uses further motivate supervision that reflects semantic and structural graph similarity, rather than only exact agreement of local object and predicate labels. 14 A.2 Graph Similarity and Graph Edit Distance 

A natural starting point for graph-level supervision is the literature on graph similarity, graph matching, and graph edit distance. Classical graph edit distance formulations measure dissimilarity through node and edge edit operations on attributed relational graphs [34], and later work clarified its connection to maximum common subgraph formulations [7]. More broadly, graph matching has been studied for several decades as a central problem in structural pattern recognition, where the main challenge is to establish correspondences between graph elements before meaningful comparison can be carried out [10]. This correspondence problem is precisely what makes general graph similarity difficult to use as a differentiable training objective. For scene graph learning, this difficulty is reflected in the fact that generic graph edit distance is typi-cally combinatorial and expensive to optimize, while approximate solvers often rely on assignment-based relaxations such as bipartite graph matching [32]. Surveys of graph edit distance emphasize both the expressivity and the computational burden of such methods [14]. An alternative family of similarity measures is given by graph kernels, which compare graphs through positive definite similarity functions rather than explicit edit sequences [24]. However, both graph edit distances and graph kernels are primarily designed for comparing arbitrary graphs whose correspondences are not fixed in advance. Our setting is different. In supervised 3D scene graph prediction, prediction and annotation are defined over the same object-instance slots and directed object-pair slots. Hence, the challenge is not to solve arbitrary graph matching, but to design a differentiable distance on aligned scene graphs that respects scene semantics, contextual subject-predicate-object structure, and scene-internal relational organization. This fixed-correspondence structure places our formulation closer to metric design on aligned probabilistic graph fields than to generic graph matching or arbitrary graph similarity. 

A.3 Hellinger Geometry and Gram Matrices 

Our construction is also related to the literature on probability metrics, information geometry, and kernel-based representations. The Hellinger distance is a classical probability metric introduced by Hellinger [1, 15], while the corresponding affinity can be written through the Bhattacharyya coefficient [3]. Modern treatments of probability metrics discuss Hellinger distance alongside other statistical distances and emphasize its favorable geometric and boundedness properties [15]. From the viewpoint of information geometry, the square-root representation maps probability distributions to a spherical geometry, providing a natural Hilbert-space interpretation of Hellinger comparisons [1]. The Gram-matrix side of our method is connected to classical kernel theory. Gram matrices collect pairwise inner products in a feature space, and their role in kernel methods is rooted in reproducing-kernel theory [2] and its practical machine-learning formulation [36]. In our case, the relevant feature space is not a generic kernel embedding but the Hellinger triplet product space induced by contextual subject-predicate-object measures. Finally, our geometry term is closely related to classical results linking inner-product representations and distance geometry. Schoenberg established a fundamental connection between metric structure and positive definite functions [35], while Gower showed how Euclidean configurations can be recovered from distance information and corresponding Gram-type representations [16]. A modern treatment of this distance-geometry viewpoint, especially through multidimensional scaling and Euclidean configuration recovery from dissimilarity data, is given by Borg and Groenen [6]. These results motivate our use of triplet Gram matrices not merely as regularizers, but as equivalent descriptors of scene-internal contextual triplet distance geometry [6]. In this sense, the proposed geometry term aligns the internal arrangement of semantic relational facts rather than only matching raw pairwise affinities.

B.4 3DSSG-to-Generator Interface for 3D Scene Generation Evaluation 

Our generation-based evaluation uses pretrained graph-conditioned 3D scene generators, i.e., Com-monScenes [43] and EchoScene [44], as downstream evaluators of predicted 3D scene graphs. These generators are built on a 3D-FRONT-style graph representation [13], whereas 3D scene graph predic-tion methods are commonly trained and evaluated on 3DSSG [40]. The two graph protocols differ in object vocabulary, predicate vocabulary, object granularity, and supported room-domain coverage. Therefore, raw 3DSSG graphs cannot be directly used as generator inputs without introducing vocab-ulary and domain mismatch. To avoid confounding graph prediction quality with generator-interface incompatibility, we define a deterministic 3DSSG-to-generator graph conversion protocol. Importantly, we do not retrain CommonScenes or EchoScene on 3DSSG, nor do we modify their architectures. Instead, both ground-truth and predicted 3DSSG graphs are converted into the generator-compatible graph representation before generation. The conversion rule is fixed before evaluating any prediction model and is applied identically to all compared methods. Thus, the downstream generation results compare the quality of the predicted graphs under a common interface, rather than the ability of a method to exploit a method-specific conversion or filtering rule. 

Deterministic Conversion Operator. Let Φ denote the downstream graph-conditioned scene generator. We define a deterministic conversion operator TΦ that maps a 3DSSG graph into the graph format accepted by Φ. The operator consists of an object-label map and a predicate-label map. Each 3DSSG object or predicate label is either mapped to a generator-compatible label or assigned to a null symbol ⊥ when no reliable semantic counterpart exists. Labels mapped to ⊥ are removed from the converted graph. The mapping is defined at the class-label level and does not depend on the scene, the prediction method, or the prediction confidence. 

Object Label Mapping. For each object node, we first check whether its 3DSSG object label is directly supported by the generator vocabulary. If so, the label is preserved. For example, generator-compatible furniture categories such as armchair , bookshelf , cabinet , chair , and coffee table are used without modification. If the exact 3DSSG label is not present but has a clear synonym or super-category in the generator vocabulary, we map it to the corresponding generator label. For instance, 

couch is mapped to sofa , couch table to coffee table , bedside table to nightstand , and computer desk 

to desk . For labels that are represented by a more fine-grained set of generator categories, such as 

bed , we use the canonical category specified by the generator protocol. Object nodes are removed when their 3DSSG labels have no reliable generator-compatible counterpart. This includes unsupported architectural or structural annotations such as ceiling , door , doorframe , and 

pipe ; small clutter objects such as backpack , bag , book , bottle , box , and folder ; and facility-specific objects such as basin , bathtub , bidet , shower , and sink . When an object node is removed, all predicate edges incident to that node are also removed. This step reflects the furniture-centric graph interface of the 3D-FRONT-based generators and prevents unsupported object labels from being passed to the generator. 

Predicate Label Mapping and Edge Cleanup. After object label mapping, we convert predicate labels between the remaining object nodes. If a 3DSSG predicate label is directly supported by the generator vocabulary, it is preserved. For example, geometric predicates such as left , right , front ,19 and behind are retained when supported by the generator. If the 3DSSG predicate label has a clear generator-compatible synonym, we map it to the corresponding predicate label. For example, higher than is mapped to taller than , lower than to shorter than , same symmetry as to symmetrical to , and 

supported by to standing on .Predicates without a reliable layout-level counterpart in the generator vocabulary are removed. Examples include attached to , belonging to , build in , and connected to , which are meaningful in 3DSSG annotations but are not part of the generator-compatible predicate interface. No-relation edges are never provided to the generator. If multiple mapped predicate labels remain for the same directed object pair, duplicate labels are merged; when the generator requires a single predicate per directed object pair, we apply the same deterministic edge-collapsing rule to the converted reference graph and to all converted predictions. The conversion does not infer new predicates from 3D coordinates or room layout; it only maps or removes existing graph labels. 

Reference-based Scene Filtering. We select the generation-evaluation dataset using only the converted reference graphs. For each 3DSSG validation scene s, let Ggt s = ( V gt s , E gt s ) be the original reference graph and let eGgt s = TΦ(Ggt s ) = ( eV gt s , eEgt s ) be its converted graph. A scene is included in the generation-evaluation dataset only when the converted reference graph satisfies all of the following conditions: • the converted graph contains at least five object nodes; • the converted graph contains at least five positive predicate edges; • the object node retention ratio is at least 0.5.The object node retention ratio is defined as 

ρs = | eV gt s ||V gt s | . (42) This filtering avoids degenerate generator inputs whose object or predicate content is too sparse after conversion. It also prevents scenes whose original 3DSSG content is mostly outside the generator vocabulary from dominating the evaluation. For example, room domains dominated by unsupported facilities or small clutter objects are naturally excluded when their converted reference graphs fail the node-count, predicate-count, or retention-ratio criteria. Conversely, if a generator-compatible indoor scene contains only a small number of unsupported objects, those nodes are removed while the scene remains in the evaluation subset as long as the converted reference graph satisfies the above criteria. This filtering is performed once using the reference graphs only. Predicted graphs are never used to decide whether a scene is included or excluded. Therefore, all compared methods are evaluated on the same fixed scene dataset, and no method receives an advantage from method-specific scene selection. 

Applying the Protocol to Predicted graphs. For each selected scene and each prediction method 

M , the decoded predicted graph bGMs is converted using the same operator TΦ. Unsupported predicted object labels are removed, unsupported predicted predicate labels are removed, and predicate edges incident to removed object nodes are discarded. The resulting converted prediction TΦ( bGMs ) is then provided to the same downstream generator Φ under the same sampling and rendering protocol. Scenes are not filtered again based on the converted predicted graph. Under this protocol, the ground-truth graph and all predicted graphs are evaluated through the same generator-compatible interface. The resulting FID/KID scores should therefore be interpreted as generation-based scene-level fidelity. Conventional 3DSSG prediction metrics are reported separately in Appendix C.3. This separation allows us to evaluate two complementary aspects: standard exact-label prediction on the original 3DSSG vocabulary, and downstream 3D scene-level coherence under a controlled graph-to-scene generation interface. 

B.5 Multi-view Rendering-based 3D Scene Generation Evaluation 

The standard supervised formulation of 3D scene graph prediction evaluates object, predicate, and subject-predicate-object triplet prediction using recall and mean recall [12, 17, 27–29, 40, 41]. These 20 metrics measure whether each local object or predicate label exactly matches the ground-truth annotation. However, exact local label agreement does not fully capture whether a predicted 3D scene graph preserves the scene-level semantics and relational structure of the ground-truth 3D scene graph. For example, two predicted graphs may have similar recall scores while inducing substantially different global scene layouts when used as conditions for 3D scene generation. Therefore, we report conventional recall-based metrics only as supplementary results in Appendix C.3, and use graph-conditioned 3D scene generation as our main quantitative evaluation. Our key assumption is that a predicted 3D scene graph is more semantically and structurally faithful to the ground-truth graph if it induces a similar distribution of generated 3D scenes when passed to the same graph-conditioned 3D scene generation model. Before generation, both ground-truth and predicted graphs are converted into the generator-compatible graph representation using the fixed protocol in Appendix B.4. Following recent 3D scene graph-to-3D scene generation methods such as CommonScenes [43] and EchoScene [44], we convert both ground-truth and predicted 3D scene graphs into generated 3D scenes, and compare their rendered distributions using Fréchet Inception Distance (FID) [18] and Kernel Inception Distance (KID) [5]. This evaluation provides a downstream quantitative proxy for how well the predicted graph preserves the semantic composition and spatial organization required for plausible 3D scene generation. For each validation scene s, let Ggt s denote the ground-truth 3D scene graph and ˆGMs denote the 3D scene graph predicted by method M . Using a fixed graph-conditioned 3D scene generator Φ and the deterministic conversion operator TΦ, we generate a reference 3D scene Φ( TΦ(Ggt s )) and a predicted-graph-conditioned 3D scene Φ( TΦ( ˆGMs )) . The same generator, sampling protocol, renderer, and camera configuration are used for all methods. Thus, the evaluation focuses on the quality of the input 3D scene graph rather than differences in the generation or rendering pipeline. Each generated 3D scene is rendered at 256 × 256 resolution from five views: one top-down view and four oblique side views. The four oblique views use azimuth angles of 0◦, 90 ◦, 180 ◦, and 270 ◦

with a fixed elevation angle of 30 ◦. The camera configuration is determined from the reference scene coordinate frame and reused for the corresponding predicted-graph-conditioned generations, preventing method-specific camera fitting from hiding scale or layout errors. Compared with a single top-down rendering, this multi-view protocol better reflects 3D scene structure, including object arrangement, relative scale, occlusion, and side-view geometric consistency [21, 22]. To reduce nuisance factors that are not directly related to 3D scene graph quality, such as texture, material, and illumination, we use semantic-color rendering. Each object instance is rendered with a category-consistent color, and the same category-to-color mapping is used for all ground-truth-graph-conditioned and predicted-graph-conditioned scenes. This makes the image-based metrics more sensitive to semantic composition and spatial layout rather than photorealistic appearance. Let Igt denote the set of multi-view renderings obtained from the 3D scenes generated with ground-truth graphs, and let IM denote the set of multi-view renderings obtained from the 3D scenes generated with the predicted graphs of method M . For each method, we pool renderings over all validation scenes and all five camera views, and compute FID and KID between Igt and IM using standard Inception features. Lower FID and KID indicate that the predicted graphs induce a generated 3D scene distribution closer to the distribution induced by ground-truth 3D scene graphs. The ±

values reported in the FID/KID tables denote scene-level bootstrap standard errors computed with 

B = 1000 resamples of the generator-compatible validation scenes. Each bootstrap resample samples scenes with replacement and keeps all five rendered views of a sampled scene together, so camera views are not treated as independent validation samples. Although FID and KID do not directly measure pairwise graph correctness or individual predicate accuracy, they are appropriate for this setting because graph-conditioned 3D scene generation is inherently multimodal: multiple valid 3D scenes can correspond to the same scene graph. This contrasts with single-image 3D reconstruction settings that explicitly target geometric recovery from a visual observation [30]. Therefore, an exact pairwise 3D reconstruction metric would be overly restrictive and would not reflect the distributional nature of the task. We use FID and KID as distribution-level quantitative evidence for downstream 3D scene generation quality, and complement them with the user studies in Sec. 4.3 and Appendix B.6. 21 B.6 User Study Design and Protocol 

We conducted a user study to evaluate whether the proposed graph-level supervision improves the perceptual quality of predicted 3D scene graphs and their downstream graph-conditioned 3D scene generation results. The study was designed as a pairwise preference test between the baseline method, 

i.e., OCRL [17], and our method. Our protocol is motivated by prior perceptual evaluations in graph-to-3D and indoor 3D scene generation, which commonly use anonymized or randomized comparative displays and perceptual criteria related to scene realism, condition consistency, graph correctness, and structural plausibility [11, 37, 43]. We use pairwise comparison rather than absolute rating because the quality of a 3D scene graph or a generated 3D scene can be difficult to calibrate across participants with a fixed numerical scale. Pairwise comparison reduces scale bias and directly measures which method is preferred under the same input 3D scene. 

Participants. We recruited 32 participants, consisting of 16 female and 16 male participants aged between 24 and 32. The participants were students or researchers with backgrounds in computer vision, computer graphics, or related fields. All participants had normal or corrected-to-normal vision and had no prior exposure to the compared methods or the evaluated results. 

Stimuli. The study was organized into two response blocks: scene-graph comparison and scene-scene comparison . For both response blocks, we sampled the same 30 scenes from the 3DSSG validation split. For each sampled scene, we constructed one pairwise comparison trial between the OCRL baseline and our method. Each trial displayed the input 3D scene, two predicted 3D scene graphs, and the two corresponding graph-conditioned generated 3D scenes. Thus, each participant evaluated 30 comparison trials, yielding 30 scene-graph comparisons and 30 scene-scene comparisons. In the scene-graph comparison block, participants judged which predicted graph better described the input 3D scene. The input 3D scene was visualized using the same rendering style for all methods. Each predicted graph was visualized with object category labels as nodes and positive predicate labels as directed edges; no-relation edges were omitted for readability. The same graph decoding rule, node display format, font size, and edge visualization rule were used for both methods. In the scene-scene comparison block, participants judged which generated 3D scene better preserved the input 3D scene. The generated scenes were obtained by feeding the predicted graphs of baseline and our method into the same graph-conditioned 3D scene generator, EchoScene [44]. Before genera-tion, the predicted graphs were converted using the same deterministic 3DSSG-to-generator protocol described in Appendix B.4. The generator, sampling procedure, renderer, camera configuration, and visualization style were fixed across the two methods. The generated 3D scenes were shown with the same semantic-color rendering style and fixed camera configuration, so that participants could compare object composition, relative positions, and structural consistency without method-specific visualization differences. 

Procedure and Controls. The study was conducted using a controlled web-based interface. For each comparison trial, the two alternatives were anonymized as Program A and Program B, and participants were not informed which result was produced by which method. The assignment of the baseline and our method to Program A/Program B, corresponding to the left/right columns in the interface, was randomized independently for each participant and each stimulus to reduce positional bias. The order of comparison pairs was also randomized for each participant. The ground-truth scene graph was not shown to participants; participants made their judgments based on the input 3D scene and the two compared outputs. A tie option was provided to avoid forcing a preference when the two results were perceptually similar or equally inadequate. Participants were instructed to judge the scene-graph criteria from the predicted graphs and the input scene, and to judge the scene-scene criteria from the generated scenes and the input scene. Consistent with the generator-compatible evaluation protocol, the scene-scene judgments focused on object composition and spatial layout rather than texture, illumination, wall geometry, or unsupported clutter. The exact instruction text shown to participants before the trials was as follows:

## C Additional Experiments 

C.1 Generalization across Scene Graph Backbones and Generators 

We further examine whether the proposed graph-level supervision is tied to a particular 3D scene graph prediction backbone or to a particular graph-conditioned scene generator. To this end, we evaluate four 3D scene graph prediction backbones, SGPN [40], SGFN [42], VL-SAT [41], and OCRL [17], with two downstream graph-conditioned 3D scene generators, CommonScenes [43] and EchoScene [44]. 24 These backbones cover a broad range of 3D scene graph prediction paradigms, from PointNet/GCN-based prediction and feature-fusion-based graph construction to visual-linguistic assisted training and cross-modal contrastive object representation learning. For each backbone, the baseline is trained with its original local object and predicate classification objective, while the corresponding “+ Ours” variant is trained with the proposed graph-level supervision under the same network architecture, graph decoding rule, and downstream generation protocol. Thus, each baseline-to-ours comparison isolates the effect of the supervision objective while keeping the prediction model and generation pipeline fixed. More detailed experimental settings are provided in Appendix B.1. Following the protocol in Appendix B.5, we compare the distribution of multi-view renderings of scenes generated from ground-truth graphs with that of scenes generated from predicted graphs. Thus, lower FID and KID indicate that the predicted graphs induce generated scenes closer to those conditioned on ground-truth scene graphs. The quantitative results are summarized in Table 6, and qualitative comparisons are shown in Figure 4. Here, CommonScenes and EchoScene are used as fixed downstream evaluators of predicted graph quality. The reported FID/KID values are therefore not intended to be directly compared with the original FID/KID numbers reported by those generators under their own benchmarks. 

Backbone-Agnostic Improvement. Across all prediction backbones and both downstream genera-tors, applying our graph-level supervision consistently improves both FID and KID. With Common-Scenes, the proposed supervision reduces FID by 4.44 –6.02 and KID by 1.04 –1.08 in the ×10 −3

scale. With EchoScene, it reduces FID by 4.69 –5.92 and KID by 0.88 –1.13 in the same scale. This consistent improvement across SGPN, SGFN, VL-SAT, and OCRL shows that the proposed objective is not specialized to a single backbone architecture. The trend across backbones is also broadly consistent with the relative strength of the underlying 3D scene graph predictors. Backbones with stronger conventional prediction performance generally yield lower generation errors, and this ordering is preserved after applying our supervision. Importantly, our method improves both earlier backbones such as SGPN and SGFN and stronger recent backbones such as VL-SAT and OCRL. This suggests that the proposed graph-level objective is complementary to backbone-level representation learning. Rather than relying on a particular feature extractor or relation classifier, it provides an additional supervision signal that makes the predicted graph more useful as a structured condition for downstream scene generation. 

Generator-Agnostic Robustness. The same improvement pattern is observed with both Com-monScenes and EchoScene. Although the two generators have different graph-conditioning and generation mechanisms, the relative advantage of our method remains stable. Under this protocol, EchoScene yields lower absolute FID and KID values than CommonScenes for the same predicted-graph inputs; however, the key observation is that the baseline-to-ours improvement is preserved for every backbone in both generator settings. This indicates that the gains are not an artifact of a specific generator architecture, sampling behavior, or conditioning interface. This robustness is important because graph-conditioned scene generation evaluates the predicted graph through a downstream consumer. If the improvement were observed only with a single generator, it could be attributed to generator-specific biases. In contrast, the agreement between CommonScenes and EchoScene suggests that the gains originate from improved predicted-graph conditions rather than from a generator-specific artifact: the generated scenes become closer to the ground-truth-graph-conditioned scenes regardless of which downstream generator consumes the graph.

Discussion. The results support the central motivation of our method. A 3D scene graph is not merely a collection of independent object and predicate labels; it is a structured set of mutually dependent subject-predicate-object facts. When such a graph is used as a condition for 3D scene generation, local prediction errors can propagate into global errors in object composition, spatial arrangement, and relational plausibility. Therefore, optimizing only local classification losses may be insufficient, even when the resulting object or predicate predictions are individually reasonable. Our graph-level supervision directly addresses this issue. The aligned triplet term D2align encourages each predicted subject-predicate-object fact to be close to its ground-truth counterpart in the contextual Hellinger triplet space, while the scene-internal geometry term D2geom encourages the predicted graph to preserve the relative distance geometry among relational facts within the scene. As a result, the predicted graph better captures both aligned semantic facts and their scene-internal relational geometry. The quantitative FID/KID improvements and qualitative reconstructions jointly demonstrate that this structured supervision improves the downstream usability of predicted 3D scene graphs, without requiring any change to the graph-conditioned scene generator.

C.3 Consistency with Conventional 3D Scene Graph Prediction Metrics 

For completeness, we additionally evaluate our method under the conventional 3D scene graph prediction protocol used in prior 3D scene graph prediction studies [12, 17, 27–29, 40, 41]. Fol-lowing this protocol, we report recall (R) [26] and mean recall (mR) [9] for object, predicate, and triplet prediction on the 3DSSG [40] validation set. Recall measures overall exact-label retrieval performance, while mean recall averages recall over classes and therefore reflects class-balanced performance under the long-tailed label distribution. For triplet prediction, a prediction is counted as correct only when the subject, predicate, and object labels all match the ground-truth triplet. The results are summarized in Table 7. Our method remains highly competitive under this standard evaluation protocol. Among the compared methods, it achieves the best performance in 10 out of 12 reported metrics. For object prediction, our method improves R@5, mR@1, and mR@5 over the strongest competing results by 1.27 , 0.28 ,and 1.05 , respectively. For predicate prediction, it improves R@3 and mR@1 by 0.34 and 0.55 ,respectively, and achieves the best mR@3 with a 0.25 improvement over VL-SAT [41]. Most notably, our method achieves the best result on all triplet metrics, improving R@50, R@100, mR@50, and mR@100 over OCRL [17] by 0.38 , 0.48 , 0.93 , and 1.38 , respectively. These results are particularly meaningful because our objective is not a direct local object and predicate classification loss. Prior methods are typically trained with node- and edge-level classification objectives, such as object cross-entropy and predicate cross-entropy or binary cross-entropy variants. In contrast, our method supervises the prediction through a graph-level distance between the predicted and ground-truth probabilistic scene graphs. The aligned triplet term D2align compares subject-predicate-object semantic facts in the contextual Hellinger triplet space, while the scene-internal geometry term D2geom encourages the predicted graph to preserve the relative distance geometry among relational facts. Despite not being explicitly optimized for independent top-1 object and predicate classification, our method achieves state-of-the-art-level conventional recall. The only metrics where OCRL obtains higher scores are object R@1 and predicate R@1. This is expected because top-1 exact-label recall is the metric most directly aligned with local classification supervision. However, the gaps are small, and our method outperforms OCRL in higher-rank recall, mean recall, and all triplet metrics. The improvements in mean recall suggest that the proposed graph-level supervision does not simply favor frequent classes, but improves class-balanced prediction quality. The triplet improvements are especially important because triplet prediction better reflects whether object and predicate predictions are jointly consistent. This agrees with the design of our objective, which treats each directed object pair as a contextual subject-predicate-object fact rather than supervising object and predicate labels independently. This supplementary comparison also clarifies the role of our main evaluation protocol. Conven-tional recall and mean recall are valuable for verifying exact-label prediction performance and for maintaining comparability with prior 3D scene graph prediction methods. However, they primarily measure local label agreement and do not directly evaluate whether the predicted graph preserves the semantic composition and relational organization needed to reconstruct a coherent 3D scene. For this reason, our main experiments evaluate predicted graphs through graph-conditioned scene generation, qualitative reconstruction, and user studies, as reported in Tables 1, 6, and 2. Together, these results show that the proposed graph-level supervision is compatible with standard 3D scene prediction metrics while providing stronger scene-level graph fidelity for downstream 3D scene generation. 29 C.4 Ablation on the Candidate-Edge Setting 

The main experiments use the all-pair edge setting, where the active edge-slot set is the complete directed object-pair set A defined in Eq. (2). This setting provides the most direct instantiation of our fixed-slot graph distance because every object pair can contribute to the contextual triplet field. In practical 3D scene graph systems, however, relation prediction is often performed over a restricted set of candidate object pairs for computational efficiency or architectural compatibility. We therefore further evaluate whether the proposed graph-level supervision remains effective when the active relation slots are restricted from A to a fixed candidate edge set E∗, as used in the candidate-edge objective in Eq. (37). For a fair comparison, all variants in this ablation use the same OCRL backbone [17], the same EchoScene generator [44], the same 3DSSG train/validation split, and the same downstream graph-conditioned generation protocol as in Sec. 4.2. We also keep the training schedule, inference procedure, graph decoding rule, and rendering-based FID/KID evaluation unchanged. Thus, the comparison isolates the effect of the edge-slot setting and the corresponding supervision objective. 

Candidate-edge Construction. We construct E∗ using only geometric information from object bounding boxes, without using ground-truth relation labels or model predictions. First, we select spatially nearby object pairs based on bounding-box center distance. For each object, we compute its center distance to the other objects in the scene and add the K nearest neighboring objects as candidate pairs. This nearest-neighbor component is intended to cover relation candidates that are likely to arise from spatial proximity or relative layout, such as close by , left , right , front , and behind .Second, we include an overlap-based component to better cover support or contact-related pairs that may not be selected by center distance alone. For each object, we compute its 3D bounding-box overlap with the other objects and add the M objects with the largest overlap scores as additional candidates. This component is useful for pairs such as chair–floor , table–floor , or shelf–wall , where relations such as standing on , lying on , attached to , or part of may be important even when object centers are not the closest. The final candidate edge set is the union of the center-distance-based and overlap-based candidates. Because 3D scene graph predicates are directed, each selected object pair is converted into bidirec-tional relation slots. We then remove self edges and duplicated directed pairs. In our experiments, we use K = 3 and M = 2 . The resulting E∗ is fixed during both training and evaluation, and is independent of the ground-truth relation annotations and predicted relation scores. 

Compared Settings. Table 8 compares three settings. The first row, All-pair (Full) , corresponds to the main objective in Eq. (36), where D2align and D2geom are computed over the complete directed edge-slot set A. This is the main setting used in our experiments. The second row, Candidate-edge w/o D2node , replaces A with the fixed candidate set E∗ and computes the aligned triplet and geometry terms only over the active candidate relation slots. This variant tests whether the proposed graph-level supervision remains useful when relation coverage is restricted, but without explicitly adding a separate node-level metric block. The third row, Candidate-edge w/ D2node , uses the candidate-edge objective in Eq. (37). That is, it combines D2align ,E ∗ and D2geom ,E ∗ with the node-augmented term D2node . The node term is not a local cross-entropy loss; it is the squared Hellinger metric block between lifted object measures, as defined in Eq. (38). Its role is to preserve object-level semantic information when the active edge set is incomplete.

Discussion. These results show a clear trade-off between relational coverage and practical candidate-edge restriction. The all-pair objective remains the strongest setting because it compares predicted and ground-truth graphs over the complete directed object-pair structure. This is particularly important for our graph-level distance: D2align aligns each contextual subject-predicate-object fact, while D2geom 

preserves the scene-internal geometry among relational facts. Both terms become most informative when they are computed over the full relational field. At the same time, the candidate-edge results demonstrate that our formulation is not limited to the all-pair setting. Even when the active edge set is restricted to E∗, the graph-level objective still improves downstream scene generation quality compared with local OCRL supervision. This suggests that the proposed supervision captures structure that is useful for graph-conditioned generation beyond independent object and predicate classification. The predicted graph becomes a better condition for the generator because the training objective compares relational facts as contextual triplets and regularizes their scene-internal arrangement. The node-augmented term is especially important in this restricted setting. In the all-pair formulation, object semantics are repeatedly embedded into triplet measures through all directed object-pair slots. In contrast, under candidate-edge supervision, each object participates in only a subset of relation slots, and in degenerate cases an object may have very limited relational participation. The term 

D2node compensates for this loss of coverage by directly preserving the lifted object distributions while remaining in the same Hellinger-based metric framework as the triplet terms. As a result, the candidate-edge variant with D2node substantially reduces the gap to the all-pair full objective. Overall, this ablation validates two design choices. First, using the all-pair edge set as the main setting is justified because it yields the best downstream generation quality and provides the most complete graph-level supervision. Second, the proposed framework can be adapted to candidate-edge systems by adding the node-augmented metric block. This makes the method compatible with practical relation-candidate pipelines while preserving its central advantage: training the predictor to produce scene graphs that are semantically and structurally useful as graph-conditioned generation inputs. 31 C.5 Failure Cases and Limitations 

Although the proposed graph-level supervision consistently improves scene-level graph fidelity, it is not free from failure cases. Figure 6 shows a representative example where our method preserves the overall semantic and relational structure of the scene, but fails to recover a contextually atypical object and some fine-grained directional relations. The input scene is a kitchen-like environment containing a counter, sink, wall, floor, and multiple cabinet-like structures. In the reference graph, however, one object is annotated as a commode , which is relatively unusual in this surrounding context. Our prediction preserves most of the global graph scaffold, including the standing on , build in , attached to , and higher than relations, but predicts the commode as a kitchen cabinet . It also relaxes the directional predicates front and right into the broader proximity predicate close by .This example illustrates an important property of our method. The contextual Hellinger triplet representation encourages the predicted graph to be semantically coherent with the surrounding scene context and to preserve the scene-internal relational geometry. This is beneficial in most cases, as shown by the quantitative improvements in Tables 1 and 6, the qualitative results in Figures 2 and 4, and the user study in Table 2. However, when an object or relation is rare, ambiguous, or weakly supported by the surrounding context, the same contextual consistency can bias the prediction toward a more common scene-compatible alternative. In Figure 6, the predicted kitchen cabinet is not a random or implausible label; rather, it is a contextually plausible substitution given the nearby kitchen counter, sink, wall, and cabinet structures. The limitation is therefore not a collapse of the graph structure, but a loss of fidelity to an atypical fine-grained annotation. A similar effect appears in relation prediction. Fine-grained directional predicates such as front and 

right require precise geometric disambiguation and can be difficult to distinguish in cluttered indoor layouts where several objects are spatially adjacent. In such cases, our graph-level objective may prefer a more stable proximity relation such as close by , which preserves the fact that the two objects are spatially related but loses the exact directionality. This behavior is consistent with the design of our objective: D2align encourages semantic agreement of aligned subject-predicate-object facts, while 

D2geom encourages the relative organization among relational facts to remain coherent. As a result, the predicted graph may remain useful for downstream scene reconstruction even when some exact object or predicate labels are softened. These observations suggest two main limitations. First, because the contextual semantic measures are estimated from the training scene graph distribution, rare object-context combinations and long-tailed relation patterns can still be challenging. Second, relations that depend on subtle metric geometry or viewpoint-sensitive orientation may require stronger geometric cues than those captured by the current graph-level semantic objective alone. A promising direction is to combine the proposed graph-level supervision with rare-context calibration, uncertainty-aware multi-hypothesis prediction, or explicit geometric constraints for directional predicates. Such extensions could improve fine-grained label fidelity while retaining the main advantage of our method: producing semantically coherent and structurally useful scene graphs for downstream 3D scene generation. 

C.6 Broader Impacts 

This work studies graph-level supervision for fixed-correspondence 3D scene graph prediction and evaluates predicted graphs through downstream graph-conditioned 3D scene generation. Potential positive impacts include improved structured 3D scene understanding for robotics, AR/VR, embodied AI, indoor scene simulation, and assistive spatial reasoning systems. By encouraging predicted scene graphs to preserve scene-level semantic composition and relational geometry, the proposed objective may help downstream systems use more coherent symbolic representations of 3D environments. Potential negative impacts arise from the broader use of 3D scene understanding and graph-conditioned indoor scene generation. More accurate scene graph prediction may support privacy-sensitive mapping of indoor spaces, surveillance-oriented spatial analytics, or synthetic reconstruction of private environments if deployed without appropriate consent and access control. The method can also inherit biases from the underlying 3DSSG/3RScan data and from the restricted vocabularies of graph-conditioned generators, potentially underrepresenting uncommon room layouts, cultural variations in indoor spaces, rare object categories, or unusual object-relation configurations. In safety-critical embodied applications, plausible but incorrect predicted relations could also lead to inappropriate downstream planning decisions. 32 Reference 3D Scene Graph

D.4 Canonical No-Relation Measure 

As stated in Eq. (17), the no-relation predicate is represented by the canonical absence measure. This row is not estimated from empirical negative-pair counts. The reason is that, in all-pair formulations, absent directed object pairs are overwhelmingly more frequent than positive predicate occurrences. Estimating the no-relation row from empirical negative statistics would therefore entangle the semantic meaning of no-relation with dataset-level object co-occurrence priors and could dominate the geometry of the contextual predicate space. By using the canonical measure in Eq. (17), no-relation acts only as an explicit absence symbol. G.6 Numerical Stability 

The constructions above are mathematically straightforward but benefit from a few implementation details for numerical robustness. First, the sigmoid-to-single-label conversion in Appendix G.3 involves Bernoulli odds sa(r)/(1 −

sa(r)) . Although sigmoid outputs are mathematically in (0 , 1) , finite-precision implementations can produce values extremely close to 0 or 1. In practice, we use score clipping only as a numerical approximation to the weights in Eqs. (157) and (158). We set ε = 10 −6 and define 

¯sa(r) = min {1 − ε, max {ε, s a(r)}} , r ∈ R . (168) The log-space weights are then 

log eqa(∅) = 0 , (169) and 

log eqa(r) = log ¯ sa(r) − log  1 − ¯sa(r), r ∈ R . (170) Normalization in Eq. (159) is implemented through a log-sum-exp denominator. This implementa-tion converges to the exact conditional Bernoulli conversion as ε → 0, while avoiding undefined logarithms and overflow from near-unit sigmoid scores in finite-precision arithmetic. Second, the square-root embedding in Eq. (24) is well-defined at zero coordinates, so exact zeros do not create a mathematical problem. In finite precision arithmetic, however, clamping to a small nonnegative floor before the square root can prevent negative values caused by rounding. Third, when the active edge-slot set is too small to define off-diagonal pairs, the geometry term is set to zero by convention. In particular, if 

|E| < 2, (171) then Eq. (162) is undefined as an off-diagonal average, and the implementation uses the degenerate assignment 

D2geom ,E (G, H ) = 0 . (172) If E = ∅, the aligned edge average is also undefined. In this degenerate candidate-edge case, we set 

D2align ,E (G, H ) = 0 . (173) Together with Eq. (172), the objective uses only the node block in Eq. (38). This case cannot occur in the canonical all-pair setting under n ≥ 2. This convention is consistent with the candidate-edge treatment in Section 3.3: if there is no nontrivial edge-domain triplet comparison to compute, the objective reduces to the remaining metric blocks. Finally, for large scenes, the sampled estimators in Eqs.
