introducing discrete state changes that no current framework can model.

In inverse rendering, Gaussian Splatting (3DGS) [Kerbl et al. 2023]
has emerged as the leading representation for real-time, high-fidelity

novel-view synthesis, enabling a new generation of interactive ap-
plications. Its combination of fast training and efficient rendering
has driven broad adoption across academia as well as industry, from
Matterport’s digital twins and Niantic Scaniverse’s mobile recon-
struction to Meta’s Hyperscape1.
While early 3DGS pipelines required meticulous data acquisi-
tion (fixed exposure and white balance, controlled lighting, and a
perfectly static scene), recent works like 3DGRT [Moenne-Loccoz
et al. 2024] and FullCircle [Foroutan et al. 2026] have unlocked
casual capture: viewpoints need not be carefully curated – made
possible by 360◦cameras held in a single hand – and the capturer’s
pixels are automatically masked out to satisfy the static-scene as-
sumption. This freedom naturally invites users to interact with the
environment during capture – opening doors, toggling switches,
or repositioning objects – turning the operator into both an active
agent and a dynamic distractor within the scene.
Yet no existing reconstruction framework is equipped to handle
these interactions. Many contemporary 3D representations enforce a
strict static-world assumption: when an operator triggers a discrete
state change – opening a door, flipping a switch, relocating an
object – the model has no mechanism to account for the resulting
geometric variation. As a result, even state-of-the-art pipelines can
only represent a single, frozen scene configuration, and capturing
multiple stable states requires re-recording the scene from scratch.
One could argue that the natural candidate to address this limi-
tation is the family of 4D Gaussian Splatting methods [Yang et al.
2024b], which extend 3DGS to dynamic scenes by conditioning
the scene representation on time. However, this design choice fun-
damentally conflates when a state was observed with what state
the scene is in: the model learns to replay a specific sequence of
observations, not to understand independent object configurations.
As a result, 4D methods are largely limited to novel-viewpoint
synthesis of seen sequences; composing an unseen combination of
object states—e.g., door open and light on—is not directly supported,
since no single timestamp in the training data corresponds to that
configuration. What is needed instead is a representation that de-
correlates scene state from time, allowing the user to freely specify
both the viewpoint and the desired configuration of each object
independently.
To address these challenges, we propose SwitchSplat, a method
that learns “state-aware” representations from casual captures fea-
turing human-object interactions; see Figure 1. SwitchSplat orga-
nizes the scene into a static base – the parts that never change
throughout the capture – and a set of slots, one per interactable
object. Each slot holds two 3D representations corresponding to the
binary states of that object (“on” and “off”). For example, if a room
was captured while a closet door was closed for part of the record-
ing and open for another, a single slot would hold both the “off”
state (door closed, interior hidden) and the “on” state (door open,
interior visible), while the walls, floor, and furniture – unchanged
throughout – are handled by the static base. To assign each Gaussian
primitive to the right part of the scene, we attach a small learnable

score vector that controls how strongly the primitive belongs to the
base, or to either state of each slot.
This decomposition avoids data redundancy: without a shared
static base, one would need to duplicate the full scene geometry
for every slot, with no reusable structure across states. Instead,
SwitchSplat shares the base across all configurations and only stores
the geometry that actually differs per state.2 Because the full pipeline
is differentiable end-to-end, the model learns simultaneously which
Gaussians belong to which slot and when each slot is active – directly
from the input video, without any manual annotation. At inference,
the user can query any combination of slot states independently –
e.g., closet door open and desk lamp on – and render the resulting
scene from any viewpoint.
To summarize our contributions: (1) We identify a novel prob-
lem in the 3DGS literature: existing representations cannot model
scenes with discrete, user-triggered state changes (e.g., objects that
can be opened, switched, or moved), and we show that naïvely
applying dynamic methods such as 4DGS fails to address this. (2) We
propose SwitchSplat, the first 3DGS representation to address this
problem via a base+slot decomposition, where a shared static base
captures the invariant scene and each slot independently models
the binary states of one interactable object. (3) We demonstrate on a
new casual-capture dataset that SwitchSplat improves novel-view
synthesis quality over static and dynamic baselines, and uniquely
supports rendering arbitrary combinations of object states from
unseen viewpoints.

Related Work
3D Gaussian Splatting (3DGS) [Kerbl et al. 2023] has become the
dominant representation for novel-view synthesis, optimizing a set
of anisotropic Gaussian primitives that render at real-time rates.
Extensions beyond the standard perspective-camera model are par-
ticularly relevant to our setting: 3DGRT [Moenne-Loccoz et al.
2024] reformulates rendering via ray tracing, and 3DGUT [Wu et al.
2025a] adds support for highly distorted cameras and secondary
rays, enabling casual capture with wide field-of-view sensors. Full-
Circle [Foroutan et al. 2026] further shows that raw dual-fisheye
360◦video suffices for high-quality reconstruction, automatically
masking the camera operator. Despite these advances, all of these
pipelines represent the scene as a single, fixed configuration. When
multiple object states are present in the capture—a door open in
some frames and closed in others—the model either conflates them
into averaged geometry and ghosting artifacts, or learns to discard
the minority state as a distractor [Sabour et al. 2025]. Either way,
only one configuration survives in the final model; there is no mech-
anism to retain, switch between, or compose multiple stable states
at inference time.
Dynamic Gaussian Splatting. A large family of methods extends
3DGS to dynamic scenes by conditioning the representation on time.
Dynamic 3D Gaussians [Luiten et al. 2024] tracks persistent prim-
itives across frames, while Deformable 3D Gaussians [Yang et al.

Decomposed Gaussian Splatting. More recent dynamic Gaussian
methods, such as SDD-4DGS [Sun et al. 2025], observe that applying
deformation models to the entire scene is often inefficient, since most
real-world scenes are largely static. This motivates methods that de-
compose scenes into static and dynamic components: GauFRe [Liang
et al. 2025] combines a static Gaussian component with deformable
dynamic Gaussians, while Swift4D [Wu et al. 2025b] improves effi-
ciency by passing only dynamic Gaussians through the deformation
model. DeGauss [Wang et al. 2025a] further uses dynamic-static
decomposition to improve robustness to transient distractors. This
observation is closely aligned with our setting, since object inter-
actions usually affect only a small part of a 360◦environment. In
contrast to our method, existing decomposition methods still treat
the dynamic component as a temporally varying foreground: they
separate dynamic regions from a static background, but provide no
mechanism to independently switch or compose object states at
inference time.
Controllable Scene Representation. A parallel line of work stud-
ies controllable and articulated 3D representations. Pre-Gaussian
methods such as Watch It Move [Noguchi et al. 2022] discover ar-
ticulated structure from object motion; PARIS [Liu et al. 2023] goes
further by decoupling static and movable parts from two multi-view
captures of the same scene. Gaussian-based approaches extend this
to photorealistic settings: SC-GS [Huang et al. 2024] enables motion
editing via sparse control points, Template-free Articulated Gauss-
ian Splatting [Wan et al. 2024] supports re-posing with super-points,
and RigGS [Yao et al. 2025] adds rig-based editing and interpolation.
ArtGS [Liu et al. 2025a] and ArticulatedGS [Guo et al. 2025] further
focus on part-level modeling of individual objects. Crucially, all of
these methods aim to encode object motion or articulation—they
model how parts move, rather than discarding motion entirely to
focus on the discrete stable configurations of the scene. In contrast,
our method treats object interactions as a nuisance to be factored
out, retaining only the clean on/off states and ignoring the transient
motion between them.
State-aware Scene Reconstruction. Closest to our setting are meth-
ods that reconstruct scenes across discrete object states. IGFuse [Hu
et al. 2026] and RecurGS [Hu et al. 2025] address this by using se-
mantic cues to detect state changes and aligning them via rigid
transformations. GaussianCut [Jain et al. 2024] and DecoupledGaus-
sian [Wang et al. 2025b] contribute related tools for object segmenta-
tion and scene decomposition. However, all of these methods assume
that state changes can be described as rigid motions of segmented
object entities—an assumption that breaks down for casual capture,
where interaction boundaries are fuzzy and deformations are non-
rigid. In contrast, SwitchSplat learns which Gaussians belong to
each state directly from photometric supervision, without requiring
object masks, or rigid-body assumptions.
3
Method
SwitchSplat learns a state-aware 3D representation from casual cap-
tures by decomposing the scene into controllable, state-conditioned
components. In the following subsections, we detail our methodol-
ogy by first formulating our state-conditioned Gaussian primitives
and describing their integration within volume rendering (Sec. 3.1).
We then introduce the parameterization of the differentiable slot-
table (Sec. 3.2), followed by our slot initialization procedure (Sec. 3.3).
Finally, we describe our training pipeline and objectives that facili-
tate granular, state-controlled visualization during inference (Secs. 3.4
and 3.5).
Terminology. A slot corresponds to one interactable object and
holds two 3D representations for its binary states: “off” (e.g., door
closed) and “on” (e.g., door open). A slot activation is a per-frame
binary variable indicating which state is currently observed. All
parts of the scene that remain constant throughout the capture are
handled by the static base, which is shared across all configurations.

State-aware Gaussian Splat
Each 3D Gaussian primitive in our model is defined by its standard
geometric and appearance attributes: mean 𝜇, covariance Σ, opacity
𝛼, and view-dependent appearance c. To make our representation
state-aware, we augment every Gaussian with a learnable categori-
cal state distribution p = softmax(ℓ) over 1 + 2𝐾channels, where 𝐾
is the total number of object slots. These channels comprise a single
static base channel ℓ[0], together with a pair of off (ℓ[2𝑘−1]) and
on (ℓ[2𝑘]) channels for each slot 𝑘∈{1, . . . , 𝐾}. The two channels
per slot — rather than one — let the softmax assign each Gaussian
to a single configuration, so that disjoint subsets of primitives can
independently model the geometry and appearance of an object
in each of its two states (see Figure 3). This separation is essential
because the on/off configurations of an object generally differ not
just in appearance, but also in spatial extent — a closed door and an
open door, for instance, occupy different parts of the scene — which
a single shared primitive simply cannot represent.

3.3
Initialization
In a casual capture setting, neither the total number of slots 𝐾, nor
the precise slot transition timestamps are known a priori. Requiring
the user to annotate them would defeat the very premise of a “ca-
sual” capture. To address this, we leverage the reasoning capabilities
of Vision-Language Models (VLMs), and in particular GPT 5.6, to
provide an approximate initialization for the slot-table. By prompt-
ing GPT 5.6 with a sequence of frames, we extract semantically
grounded start and end timestamps for each distinct object interac-
tion. These timestamps serve as the initial values for the endpoint
parameters (𝑡𝑙,𝑡𝑟) in our slot-table. This VLM-informed initializa-
tion allows the system to bypass exhaustive temporal searches or
complex diagnostics, providing a clean and efficient configuration
for final full-resolution training. To facilitate a robust optimization
process, we initialize each interaction slot with a high tempera-
ture value 𝜏. This high-temperature initialization ensures that the
Bernoulli random variable S𝑘,𝑡begins with smooth transitions at
the boundaries, allowing the gradients to flow more effectively over
a wider temporal range during the initial stages of optimization.
3.4
Optimization
Leveraging the initial parameters derived from the VLM-based slot
discovery phase, we proceed to optimize our final state-aware scene
representation. We build our state-aware framework upon the 3D
Gaussian Unscented Transform (3DGUT) architecture [Wu et al.
2025a]. Following the 3DGUT pipeline, we initialize the 3D Gauss-
ian primitives using COLMAP-derived point clouds and augment
each primitive with the learnable state logits ℓ. To provide an un-
biased starting point for optimization, these logits are initialized
such that the base/on/off state channels are assigned equal mem-
bership probabilities. Throughout this stage, we jointly optimize
the geometric attributes of the Gaussians, their state logits, and the
temporal parameters of the slot-table (𝑡𝑙,𝑡𝑟,𝜏). We strictly adhere
to the optimization schedule established by 3DGUT, including its
specialized densification and pruning protocols. To ensure consis-
tent state behavior during optimization, we modify the standard
densification process: whenever a Gaussian primitive is cloned or
split, its state logits are inherited by the resultant primitives. This
inheritance mechanism ensures that state-aware attributes remain
spatially coherent even as the underlying scene geometry increases
in complexity.

Experiments
To validate the effectiveness of our proposed algorithm in the ab-
sence of an existing dataset with variable object interactions, we
collected a custom dataset using a consumer-grade Insta360 X4 dual-
fisheye 360◦camera. This hardware choice reflects the typical setup
of casual users. During capture, we emulated non-expert behaviors,
moving through the scene and interacting with objects—transitioning
them from resting to active states and back.
Our dataset comprises 12 scenes organized into two groups. The
standard set contains 10 casually captured scenes (8 indoor and 2 out-
door), each featuring 3–9 object interactions. The golden set contains
2 additional scenes for which we acquire controlled test sequences
with novel camera trajectories and object-state combinations. We
preprocess the raw dual-fisheye data following FullCircle [Foroutan
et al. 2026] to mask the capturer. The calibration is performed in
COLMAP using the masked fisheye frames, and then the fisheye
images are undistorted into standard pinhole images.
For evaluation, we adhere to standard NeRF procedures, holding
out every 8th frame as a test set. Crucially, we exclude test samples
that coincide with state transitions (i.e., frames where an object is
actively being moved) to reduce noise in our metrics, though these
transition frames are retained within the training set to measure
whether models can learn robustly from casual capture data. For the
golden set sequences, we additionally evaluate novel camera frames,
which show state configurations observed during training from
new camera trajectories, and novel state-combination frames, which
contain object-state configurations not observed during training.
This set is used to demonstrate our method’s ability to generalize
beyond the training configurations, and provide true state-aware
control.

Conclusion
We presented SwitchSplat, a 3D Gaussian Splatting framework that
learns state-aware scene representations directly from casual video
captures. By decomposing the scene into a shared static base and a
SA Conference Papers ’26, December 01–04, 2026, Kuala Lumpur, Malaysia.


8
•
Xie, Foroutan, Shramko, Rebain, Govindarajan, and Tagliasacchi
set of independently controllable slots, each modeling the binary
“on”/“off” states of one interactable object, SwitchSplat decouples
scene state from time – enabling a capability that time-conditioned
dynamic methods fundamentally cannot provide: free composition
of object configurations at inference, including combinations never
observed during capture. The slot table is initialized via a VLM and
jointly refined end-to-end through differentiable rendering, requir-
ing no manual annotation. Experiments on our new casual-capture
dataset show that SwitchSplat outperforms static and dynamic base-
lines in novel-view synthesis quality, and uniquely generalizes to
out-of-distribution camera paths and unseen state combinations.
Limitations and future work. The current model assumes binary
object states with the constraints of single-operator capture with
one free hand. Extending to continuous or multi-valued states by
multiple operators – would broaden the applicability of the frame-
work. The slot count and approximate interaction windows are
currently seeded by a VLM; a fully unsupervised discovery of both
the number and timing of interactions from raw video remains an
open problem. Finally, SwitchSplat focuses on novel-view synthe-
sis; combining our state-aware decomposition with physics-based
priors or generative models could enable downstream applications
such as scene editing and simulation.

A.1
Dataset Capture and Preprocessing
We captured twelve real-world scenes using an Insta360 X4 dual-
fisheye 360 camera, comprising ten standard scenes and two golden
scenes. Video frames were extracted at 4 FPS. We use the raw fisheye
frames for reconstruction to avoid propagating stitching artifacts
into the scene representation. Camera-holder masks are automati-
cally obtained using the FullCircle masking pipeline. These masks,
together with the fisheye frames, are passed to COLMAP for camera
pose estimation and subsequent image undistortion. Input images
are downsampled by a factor of two. An overview of the object-
interaction intervals and temporal structure of all twelve scenes is
provided in Figure 15.
A.2
Benchmark Construction and Evaluation Splits
We evaluate reconstruction and generalization using four evaluation
splits.
Base-state test frames. This split contains held-out frames in
which all objects remain in their initial base state. It evaluates re-
construction of the canonical scene configuration and provides a
natural comparison point for static reconstruction methods.
All standard test frames. For each scene, we hold out every eight
frame from the original capture sequence. Frames occurring during
object transitions are excluded, such that evaluation is performed
only on stable object configurations. The remaining frames con-
stitute our standard test set and cover the object states observed
throughout the original capture.
For the two golden scenes, Kitchen 2 and Oslo, we additionally
perform controlled recaptures under prescribed binary object states
and new camera trajectories, as illustrated in Figure 8. These recap-
tures define two additional evaluation splits.
Novel camera frames. We recapture object-state configurations
observed during the original training sequence using new camera
trajectories. This split evaluates generalization to novel viewpoints
while keeping the scene configuration within the set observed dur-
ing training.
Novel state-combination frames. We additionally recapture joint
object-state configurations that never occurred during the training
sequence, again using new camera trajectories. This split evalu-
ates whether the learned representation can compose individually
observed object states into previously unseen scene configurations.
Dynamic-baseline evaluation. DeGauss and 4DGS represent scene
variation using a continuous timestamp and cannot directly con-
dition on the prescribed state code of a Golden-set test image. For
the novel-camera and novel state-combination splits, we therefore
evaluate both methods using the same per-image oracle-over-time
protocol. We first evaluate 30 uniformly spaced timestamps over

A.3
Additional Training Details
For fair comparison, all methods use corresponding undistorted
pinhole images for both training and rendering, with the camera-
holder exclusion masks mapped into the respective undistorted
image representation.
We initialize our Gaussians from the COLMAP SfM point cloud
and use the same densification and pruning schedule as 3DGUT.
Gaussian parameters and state logits are optimized with fused Adam,
while the slot-window endpoints and temperatures use a separate
Adam optimizer; both optimizers are stepped jointly. SwitchSplat,
FullCircle, and 4DGS are trained for 30,000 iterations with batch
size 4. DeGauss uses batch size 4 with a 1,000-iteration coarse stage
followed by a 30,000-iteration fine stage. The learning rates for
opacity and state logits are both 5 × 10−2.
The state-sparsity loss has weight 10−4, starts at iteration 18,000,
and ramps linearly over 1,000 iterations. The compactness loss has
weight 5 × 10−4, starts at iteration 21,000, and also ramps linearly
over 1,000 iterations. For each slot, both states are measured relative
to the opacity- and assignment-weighted centroid of the active
state. After iterations 18,000 and 21,000, we mean-center the state
logits and scale them by 0.3, reducing assignment confidence as the
corresponding regularizer becomes active.

You are estimating object interaction times from an ordered sequence

Task:
- The camera observes a user moving through an environment.
- For each interacted object, the user changes the object from off to
on, leaves it on for a while, then changes it from on to off.
- Events happen consecutively.
- Each image has its exact frame number rendered on its pixels as
t=FRAME.
- Return rough midpoint frame numbers for every visible on transition
and off transition.
Rules:
- The top priority is the correct number of interacted
objects/events. Rough timing within about 50 frames is still
useful.
- Prefer including a low-confidence event over omitting a plausible
object-state episode.
- Do not merge two adjacent object episodes just because they look
visually similar.
- Detect each distinct localized manipulation episode. Different
movable parts or controls of the same larger object are
separate events and must not be merged merely because they
belong to the same object.
- The sequence may begin with a setup or base-capture traversal in
which the camera circles or surveys the scene. Do not count
that traversal unless a specific part or control is manipulated
and changes state.
- When the manipulated part is obscured, repeated
approach-manipulate-withdraw cycles, separated by clear
disengagement or repositioning, may establish separate episodes.
- Estimate the midpoint of the user's state-changing action, not only
the first frame where the object is perfectly stable or
unobstructed.
- Use the rendered t=FRAME labels for transition timing.
- If a transition is uncertain, still give the best approximate frame
and lower confidence.
- Keep events in chronological order.
- Do not invent events with no visual support, but missing an event
is worse than reporting a plausible low-confidence one.
- Valid frame range is {N_FRAME}
Timestamp convention:
- The attached images are in chronological order.
- They are sampled every 8 frames, with the first and final frames
included.
- Each image has its exact frame number rendered on its pixels as
t=FRAME.
- The rendered t=FRAME label is authoritative; use the stride only as
a consistency check.
Analyze only the attached images. Do not inspect the filesystem, run
commands, or use external tools. Return only the JSON object
required by the output schema.
