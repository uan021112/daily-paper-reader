tldr: 现有世界动作模型能够预测机器人操作的视觉未来与动作，却缺少组合式技能复用；基于代码的机器人智能体虽能规划和复用技能，却缺乏对物理动态的预测支撑。AW-0在统一混合专家架构中联合建模代码、未来视频和机器人动作，让代码既组织多步预测与控制，也表示可复用技能。其自动化流程为机器人及人类视频轨迹标注程序，并汇总重复程序形成技能库。在RoboTwin 2.0和实体双臂任务上，模型优于视觉语言动作及世界动作基线，提升语言跟随、语义推理与鲁棒性，连接规划、预测和执行。

## 摘要
近期的世界动作模型能够为机器人操作提供视觉前瞻与未来预测，但缺乏明确的组合式技能复用机制。智能体机器人技术将基于代码的规划与推理同可复用技能相结合，但往往缺少以物理动力学为基础的预测能力。我们提出 AW-0，这是一种智能体世界动作模型框架，将基于代码的规划与视频和动作联合预测相结合。我们在统一的混合变换器架构中，将代码、未来视频和机器人动作建模为三个相互耦合的生成流。在该架构中，代码专家生成参数化技能程序与控制逻辑，而视频专家和动作专家则生成未来视觉状态与低层电机指令。代码发挥两种互补作用：在世界模型中组织多步预测与控制，并将技能表示为可供后续智能体执行的可复用程序。我们进一步提出一套自动化整理流程，为机器人和人类视频轨迹标注与之对齐的程序，并将反复出现的操作程序整合为可复用的技能库。在 RoboTwin 2.0 和真实物理双臂操作任务上的评估表明，与 VLA 和 WAM 基线相比，该方法提升了任务表现，同时在语言遵循、语义推理和鲁棒性方面也有所提高。这些结果表明，智能体代码能够在 WAM 中连接规划、预测与执行。

## Abstract
Recent world action models provide visual foresight and future prediction for robot manipulation, but lack explicit mechanisms for compositional skill reuse. Agentic robotics combines code-based planning and reasoning with reusable skills, but often lacks predictive grounding in physical dynamics. We introduce AW-0, an agentic world action model framework that integrates code-based planning with joint video and action prediction. We jointly model code, future video, and robot actions as three coupled generative streams within a unified mixture-of-transformers architecture. Within this architecture a code expert generates parameterized skill routines and control logic while video and action experts generate future visual states and low-level motor commands. Code serves two complementary roles: it structures multi-step prediction and control within the world model and represents skills as reusable programs for subsequent agentic execution. We further introduce an automated curation pipeline that labels robot and human video trajectories with aligned programs and consolidates recurring routines into reusable skill libraries. Evaluations on RoboTwin 2.0 and physical bimanual manipulation tasks show improved task performance over VLA and WAM baselines, alongside gains in language following, semantic reasoning and robustness, demonstrating that agentic code enables connection between planning, prediction and execution within WAMs.

- **整体含义：**论文尝试以“代码”作为规划与预测之间的结构化接口：让计划不仅描述要做什么，也能影响模型对未来物理状态和机器人动作的生成。

## 2. 方法论

### 2.1 核心建模思路

AW-0 将生成任务表示为：在当前多视角观察、语言指令、机器人状态和历史程序记忆的条件下，联合生成三类结果：

1. **代码 \(C\)：**描述技能调用、参数及控制逻辑；
2. **未来视频潜变量 \(Z\)：**表示未来场景和物体状态；
3. **动作序列 \(A\)：**表示机器人未来一段时间的连续控制。

论文将这一联合条件生成过程写作：

\[
p_\theta(C_0,Z_0,A_0\mid O_t,L,S_t,M_t),
\]

其中 \(O_t\) 是当前观测，\(L\) 是语言指令，\(S_t\) 是机器人状态，\(M_t\) 是此前生成的程序切片压缩成的记忆。

### 2.2 混合变换器架构

- 模型采用 **Mixture-of-Transformers（MoT）**，包含代码、视频和动作三个专家。
- 各专家保留各自的注意力投影、归一化层和前馈网络，但通过联合注意力交换信息。
- 专家间采用按 **代码 → 视频 → 动作** 排列的分块因果注意力：
  - 视频专家可读取代码，使计划影响未来视觉预测；
  - 动作专家可读取代码与视频，使控制同时受到语义计划和预测状态的引导。
- 代码专家使用预训练语言模型组件，并以视觉编码器提供场景语义信息；视频专家基于预训练视频扩散模型初始化；动作专家生成连续动作块。

### 2.3 三种模态的联合去噪

AW-0 对不同模态采用相应的生成方式：

- **代码：离散掩码扩散。**训练时随机遮蔽程序中的部分 token，仅对被遮蔽位置计算交叉熵损失；生成时逐步填入模型置信度较高的 token。
- **视频和动作：连续流匹配。**将干净目标与高斯噪声按噪声程度混合，由模型预测对应的速度场，再通过迭代去噪得到未来视频潜变量和动作序列。
- **联合生成：**每个去噪步骤同时预测代码 token logits、视频速度场与动作速度场，使程序、视觉预测和控制在生成过程中相互条件化，而不是先独立生成某个模态再单向传给另一个模态。

代码的默认推理画布为 128 个 token；视频和动作生成也在联合迭代过程中进行。论文报告，默认联合去噪采用 4 个步骤。

### 2.4 自动标注与技能库构建

论文提出自动化程序标注流程，为大规模机器人和人类操作演示生成与动作片段对齐的代码：

1. 先从每项任务抽取代表性轨迹，由视觉语言模型为子任务编写程序，程序使用预定义的机器人原语 API。
2. 协调智能体分析反复出现的操作模式，将其整理成任务通用的技能函数。
3. 冻结技能库，再用固定技能词汇重新标注样本，并建立子任务到程序的缓存。
4. 对其余数据，若接触和运动模式匹配已有标注则复用；否则生成新标注并写回缓存。

预训练数据共包含约 **2,913 小时**：约 1,919 小时双臂机器人数据和约 994 小时第一人称人类操作数据。技能库共含 **50 项技能**，分别来自 YAM 机器人数据和人类演示。

### 2.5 训练目标与混合执行

- 训练中联合优化视频流匹配损失、动作流匹配损失和代码掩码交叉熵损失。
- 视频噪声采样采用混合分布，兼顾视频生成目标与为动作预测提供信息的需求。
- 默认部署时，生成代码主要作为子任务计划，动作专家的动作块直接驱动机器人。
- 论文还研究**混合执行**：在每次重新规划时，检查代码切片是否满足阶段、依赖、语法、函数白名单等条件；若通过则尝试执行代码，否则使用动作专家生成的动作块。执行代码后，模型在下一次规划点重新观察并规划。

## 6. 主要结论与发现

- AW-0 表明，在 WAM 中加入结构化代码规划，可以同时引导未来视频预测与动作生成；代码不只是输出文本，也能作为模型内部的语义与技能条件。
- 在 RoboTwin Clean 设置和实体任务平均分上，AW-0 优于所列基线；其提升主要体现为更好的任务语义理解、语言跟随和技能执行。
- 专家注意力顺序重要：让代码在视频与动作之前提供条件，即 \(C\rightarrow V\rightarrow A\)，优于让代码仅在视频之后参与规划的变体。
- 完整程序、技能调用和解释性注释均对表现有贡献；仅使用自然语言子目标或去除技能抽象通常会降低结果。
- 混合执行表现出互补性：在仿真随机化设置中，它将成功率从 20.6% 提升至 29.2%，但在 Clean 设置中从 80.8% 降至 63.1%。这说明代码执行可能改善分布外鲁棒性，但未必优于动作专家在熟悉分布内的表现。
- 联合去噪相较自回归代码生成取得更高的实体任务平均分和更低报告延迟，但这一结果来自论文所采用的任务和实现配置，不宜直接推断为所有生成任务中的普遍优势。

## 7. 优点

- **问题切入明确：**针对 WAM 缺少可组合技能、代码智能体缺少物理预测的互补缺陷，提出统一方案。
- **建模接口有整体性：**不是简单地把代码规划器放在 WAM 外部，而是在同一生成过程中联合建模代码、未来视频与动作。
- **技能标注流程系统化：**通过技能发现、冻结技能库、缓存复用和必要时重新标注，降低为大规模轨迹建立程序监督的工作量。
- **评估较广：**同时涵盖仿真、不同环境随机化、两种机器人形态以及语义与接触密集任务。
- **分析不仅限于总分：**论文进行了注意力顺序、视觉特征、代码内容、联合去噪等消融，并讨论生成质量、混合控制行为及失败模式。
- **对局限有所披露：**作者指出代码可能存在参数错误或格式错误，也说明混合执行依赖底层感知和控制原语，Clean 与 Random 表现存在取舍。

## 8. 不足与局限

- **程序生成尚不等于可靠执行：**预训练代码专家虽有较高 teacher-forced token accuracy 和 parse rate，但实体与原语 F1 较低；有效语法并不保证对象、参数或动作逻辑正确。论文示例中也出现参数维度错误和注释格式错误。
- **技能库和标注存在依赖：**规划能力受自动标注准确度、API 设计及技能覆盖范围制约。技能库是离线构建并冻结的，系统尚未通过交互自主发现、验证并持续扩展技能。
- **视觉分布外鲁棒性有限：**AW-0 在 RoboTwin Random 上的 20.6% 低于 π0.5 的 27.7%；说明加入代码并未消除 WAM 对图像外观变化的敏感性。
- **混合执行的仲裁较粗糙：**主要根据阶段、语法、白名单和依赖等有效性条件决定是否执行代码，并不估计代码执行是否会优于动作块；代码原语自身的失误可能使混合模式在 Clean 设置中退化。
- **真实场景覆盖仍有限：**实体任务数量较少，混合执行的真实机器人实验只覆盖 YAM 平台上的折叠与堆叠毛巾任务，尚未在灵巧手平台上系统验证混合代码执行。
- **个别任务的成功判据与语义泛化仍需关注：**例如魔方任务的评测描述涉及随机打乱的面或层，但论文展示的程序示例是较短的操作序列；现有内容不足以据此判断模型在一般解法规划上的能力。
- **对照实验仍可能有混杂因素：**不同基线使用不同预训练模型、架构、训练配置和算力；仿真混合模式还改变了演示采集方式，因此部分性能差异无法完全归因于单一设计因素。
- **资源成本披露不完整：**虽报告了 GPU 数量和部分训练配置，但缺少墙钟时间、总 GPU 小时和能耗，难以评估整体计算效率。
- **尚未实现持续自主学习：**系统主要依赖离线演示与下游微调，尚未证明能够通过真实交互反馈自动修订程序、扩充技能库或长期提升策略。
