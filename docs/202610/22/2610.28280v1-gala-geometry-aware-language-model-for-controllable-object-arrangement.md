对精细化摆放约束（如支撑与包含关系）进行推理，对于创建逼真的 3D 场景至关重要。然而，现有方法通常依赖有向包围盒（OBB）等简化的物体表示，无法感知详细几何结构，因此这一问题仍然颇具挑战。为克服这一局限，我们提出 GALA，这是一种具备显式点云感知能力、面向可控物体摆放的几何感知语言模型。模型采用自回归方式，每次预测一个目标物体的 6D 位姿，并以场景上下文和摆放指令为条件。我们采用两阶段训练策略：第一阶段通过预训练任务对齐几何与文本模态，第二阶段针对摆放任务对模型进行微调。为推动这一任务的发展，我们还整理了一个多源场景数据集，涵盖多种房间类型和精细化家具布局，并计划向社区开放。基准测试实验表明，与不具备显式几何推理能力的基线方法相比，我们的模型性能显著更优。此外，我们还构建了一个多阶段“规划—摆放—验证”智能体流程，利用该模型生成文本驱动的场景。项目主页：https://xccelephant.github.io/paper/gala/

## Abstract
Reasoning about fine-grained placement constraints, such as support and containment, is essential for realistic 3D scene creation. It remains a significant challenge for existing methods that rely on simplified object representations like oriented bounding box (OBB), which are blind to the detailed geometry. To address this limitation, we introduce GALA, a geometry-aware language model with explicit point cloud perception for controllable object placement. Our model performs autoregressively by predicting the 6D pose of one target object at a time conditioned on the scene context and placement instruction. We utilize a two-stage training strategy: the first stage aligns geometric and textual modalities through pretraining tasks, and the second stage fine-tunes the model for placement. To facilitate this task, we also curate a multi-source scene dataset covering diverse room types and fine-grained furniture arrangements, which will be open-sourced for community benefit. Experiments on our benchmark show our model significantly outperforms baselines without explicit geometric reasoning. We further develop a multi-stage plan-place-verify agent pipeline that uses the model for text-driven scene generation. Project Page: https://xccelephant.github.io/paper/gala/

# GALA 论文总结

## 1. 核心问题与整体含义

- **研究问题**：如何根据场景上下文和自然语言指令，为 3D 场景中的新物体预测合理的六维位姿（位置与旋转），尤其是处理“放在……上”“放入……内部”“置于……下方”等细粒度摆放关系。
- **研究动机**：许多现有场景布局方法以定向包围盒（OBB）表示物体。OBB适合描述粗略位置和尺寸，却看不到物体内部或表面的真实几何结构，因此可能无法判断：
  - 椅子能否从桌腿间放入桌下；
  - 小物体能否放进柜子、书架的内部空间；
  - 物体是否由曲面或局部支撑面正确承托。
- **整体思路**：论文将问题视为“几何感知不足”，而非单纯缺少更复杂的布局算法。GALA把物体及场景的点云显式输入语言模型，使模型结合文本关系和真实几何信息，逐个预测物体位姿。论文还整理了用于训练与评测的多源场景数据，并将模型纳入文本驱动的场景生成流程。

## 2. 方法论

### 2.1 几何感知模型

- GALA由三部分组成：
  1. **预训练语言模型**：使用 Qwen3-0.6B 作为文本骨干；
  2. **点云编码器**：采用预训练的 Utonia，对场景地面、已放置物体和待放置物体分别编码；
  3. **几何—文本投影器**：用两层 MLP 将点云特征映射到语言模型的嵌入空间。
- 每个物体单独编码，以保留实例级几何信息，避免将整个场景压成单一特征而混淆不同物体。
- 模型输入包括场景边界、地面点云、已放置物体的类别/尺寸/位姿/点云、目标物体的类别/尺寸/点云，以及摆放指令。文本与相应点云 token 按顺序交错组成上下文。
- 目标物体点云采用规范坐标；地面和已放置物体点云则处于世界坐标。模型自回归地产生目标位姿：
  \[
  \mathbf p=(x,y,z,\phi,\theta,\psi)
  \]
  即三个平移量与 roll、pitch、yaw 三个旋转量。

### 2.2 两阶段训练

- **第一阶段：几何—语言对齐**
  - 冻结点云编码器，训练投影器。
  - 通过几何问答类辅助任务，使点云特征对应到语言空间；任务涉及边界描述、物体属性、中心位置、尺寸、旋转，以及物体间距离或位移等。
- **第二阶段：摆放任务微调**
  - 按场景中的设计顺序构造逐物体摆放样本。
  - 给定已放置物体、目标点云和关系指令，训练模型以文本形式输出目标 6D 位姿。
  - 点云编码器仍保持冻结，联合训练投影器和语言模型。
- 两阶段均使用 teacher forcing 和因果语言建模目标，以目标序列的负对数似然作为训练损失。

### 2.3 数据构造与摆放流程

- 数据来源包括 3D-FRONT、Imaginarium、SpatialLM-PCG，以及作者制作的 300 个场景。
- SpatialLM-PCG 将语义盒布局替换为资产库中的模型，再在家具表面或内部程序化增加小物体，以丰富支撑、包含和邻近关系。
- 场景先经物理/几何检查和 VLM 质量评估，再提取空间关系，建立以地面为根的依赖树。依赖关系包括 `on`、`within`、`under` 和绝对位置关系；另有 `next to` 等邻近关系用于生成指令。
- 通过广度优先遍历生成摆放顺序，使家具等结构性物体通常先于依赖它们的小物体出现。推理时，每一步将模型预测的新物体加入场景，再预测下一个物体。
- 当场景中的已放置物体较多时，训练和推理会筛选参考物体以控制上下文长度；训练侧优先保留支撑、包含等依赖对象，推理侧则保留语义依赖、较大的场景锚点和近期物体。

### 2.4 文本驱动的场景生成智能体

- 论文设计了“**规划—摆放—验证**”流程：
  - 规划器将用户要求拆成有序物体清单；
  - 资产检索模块据描述和尺寸匹配模型；
  - 指令生成器为当前目标生成关系指令；
  - GALA 输出目标位姿；
  - 验证器检查越界、碰撞、悬浮和关系是否满足，并将失败反馈给指令生成器。
- 其中规划器和指令生成器使用现成的 LLM；GALA 是经训练的位姿预测模块。

## 3. 实验设计

### 3.1 数据与基准设置

- 数据来源为 **3D-FRONT、Imaginarium、SpatialLM-PCG 和 300 个手工制作场景**。论文图示统计总量约为 **285K 条指令**；正文未在所给内容中进一步明确这一统计口径。
- 场景按来源分层，以 **18:1:1** 划分训练、验证和测试集，并以测试集进行评估。
- 评估采用单物体插入协议：给定固定场景、目标物体几何与摆放指令，测试模型预测目标位姿的能力。
- 主要指标：
  - **Instruction Valid Rate**：位姿可解析、指令关系满足、无碰撞且不悬浮的样本比例；
  - **Within Valid Rate**：上述有效率在包含 `within` 关系的子集上的结果；
  - **Floating Rate**：悬浮或下沉的比例；
  - **Support Ratio**：目标物体底部点得到支撑的平均比例。
- 碰撞检测直接对点云体素化后计算重叠，避免用凸包将柜体、书架等中空结构填实；文中采用 0.02 米体素分辨率，并以目标点云重叠比例超过 20% 判为碰撞。

### 3.2 对比方法

- **不接收显式关系指令的 OBB 方法**：ATISS、ReSpace。
- **指令条件方法**：LayoutVLM 的受控适配版本，以及零样本 GPT-OSS-120B。
- 补充材料还比较了 PlaceIt3D、DeepSeek-V4-Flash、Qwen3.5-397B-A17B，以及图像生成与位姿估计流程 Nano-Banana + SAM + FoundationPose。
- 论文还进行了整场景逐步摆放的定性比较，并开展用户评分研究。

### 3.3 主要结果

- 单物体插入主实验中，GALA 报告：
  - Within Valid Rate：**65.62%**
  - Instruction Valid Rate：**78.59%**
  - Floating Rate：**4.63%**
  - Support Ratio：**96.03%**
- 相比 LayoutVLM（Within 10.96%、Instruction 37.71%）和 GPT-OSS-120B（分别为 22.53%、42.29%），GALA在指令有效率和包含关系有效率上显著更高。
- ATISS 的悬浮率和支撑指标更好，但论文指出它倾向于将物体放在地面上，不能说明其能完成细粒度的包含或支撑摆放。
- 用户研究有 **30 名参与者**。GALA的单物体物理合理性和指令遵循评分均为 4.5/5；整场景物理合理性评分为 3.9/5、美观度为 4.1/5。
- 附录中的点云消融用户研究另有 **24 名参与者**，点云版本均分为 4.14，文本版本为 1.91。

## 4. 资源与算力

- 模型约 **0.7B 参数**，由 Qwen3-0.6B、点云编码器和投影器组成。
- 训练使用 **8 张 NVIDIA H20 GPU**，bfloat16，约 **7 小时**。
- 第一阶段训练 3 个 epoch，batch size 256；第二阶段训练 4 个 epoch，batch size 128。点云编码器冻结，第二阶段联合微调语言模型与投影器。
- 推理时，GALA 单物体摆放约需 **1 秒**，使用约 **3 GB 显存**，测量硬件为单张 H20。
- 端到端智能体的总耗时主要来自远程 LLM 调用：规划器约 100 秒/场景，指令生成器约 70 秒/物体；因此不能将整个场景生成流程的速度等同于 GALA 本身的推理速度。

## 6. 主要结论与发现

- 点云几何感知与文本指令结合，能够提升模型处理细粒度包含、局部支撑和避碰问题的能力；仅增大零样本 LLM 的规模并未在实验中达到相近的位姿有效性。
- 点云的收益并非只体现在综合有效率上。对于 `within` 样本，点云版本的目标中心高度误差为 **0.0747 米**，不使用点云时为 **0.0868 米**，约降低 14%；论文报告配对 Wilcoxon 检验 \(p=6.7\times10^{-20}\)。
- 对齐预训练和高质量场景数据也带来收益。去掉高质量场景后，包含关系有效率下降，且下降主要集中在 Imaginarium 与手工制作的高质量测试子集。
- GALA 可用于逐步构建完整场景，并可接入规划、资产检索和验证模块形成文本驱动的生成流程。但该智能体流程的表现不仅由 GALA 决定，也受到上游规划、指令生成和资产选择的影响。

## 7. 优点

- **针对性明确**：聚焦 OBB 无法表达的几何细节，问题定义与方法设计一致。
- **点云显式入模**：模型能直接接收地面、已有物体和目标物体的几何特征，而不是只依据物体类别与包围盒推断。
- **训练流程清晰**：先做几何—语言对齐，再针对位姿预测微调；点云编码器冻结，训练成本相对可控。
- **评估较贴近目标任务**：除指令遵循外，还测量碰撞、悬浮和支撑，并对 `within` 子集单独评估；点云体素碰撞检查也考虑了容器的中空结构。
- **实验证据较多**：除基线对比外，还有模块消融、用户研究、分层分析、资产泛化和系统流程展示。
- **可组合的应用流程**：将语义规划与几何位姿预测拆开，提供了从文本到场景的端到端使用范例。

## 8. 不足与局限

- **关系词汇受限**：论文明确指出，GALA目前依赖预定义摆放关系，尚不支持开放式、任意表达的摆放请求。
- **泛化仍有限**：在未见容器实例上，包含有效率仅小幅下降，但物理指标退化较明显：浮动率由 16.41% 升至 31.25%，支撑比例由 84.21% 降至 68.34%。该测试仅覆盖 8 个未见容器资产和 128 个样本，且是已知类别内的新实例，不代表未见类别泛化。
- **自回归误差可能累积**：前序位姿错误会进入后续场景上下文，影响后续摆放；验证与反馈流程可缓解，但并未消除这种风险。
- **关系监督依赖 OBB 派生标签**：数据中的 `within`、`on` 等标签主要由 OBB 几何谓词生成，可能与真实可用空间、家具功能区域或复杂形状的实际接触关系不完全一致。
- **数据与模型仍有域差异风险**：数据主要来自合成/整理的场景及资产库；对真实扫描场景中的噪声、缺失点云和现实尺度误差，论文尚未给出充分验证。
- **场景规划能力并非 GALA 本身提供**：自动生成流程依赖外部 LLM、资产库和验证器；上游调用耗时较长，且整体输出质量可能受资产检索或指令生成错误影响。
- **评测覆盖仍有边界**：用户研究规模有限；基线输入能力不完全一致；对未见物体类别、复杂室外场景、交互式编辑及更开放指令的实验仍不足。论文也指出，未来可增加部件级监督或显式几何推理过程，以增强几何落地能力。
