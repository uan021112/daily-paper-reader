ABSTRACT
Reconstructing high-quality, renderable 3D scenes from long videos is essential for robotic perception
and embodied intelligence. Many feed-forward Gaussian reconstruction methods rapidly predict 3D
scenes from a small set of images, but extending them to longer sequences presents two bottlenecks:
jointly processing all views increases GPU memory requirements, while accumulating pixel-aligned
predictions redundantly represents the same surfaces and increases storage and rendering costs. We
present LonGaussian, a streaming feed-forward framework that reconstructs compact, globally
renderable Gaussian scenes from long image sequences with known intrinsics and unknown camera
poses. Built on a pretrained streaming 3D reconstruction backbone, LonGaussian decodes long-
context geometric features into dense Gaussians. Within each chunk, multi-frame point tracks link
repeated observations of the same surface and guide a learned merger to consolidate the corresponding
Gaussian predictions. Rendered-depth consistency filtering further suppresses Gaussians from other
chunks that incorrectly occlude locally reconstructed surfaces. On DL3DV and RealEstate10K
benchmarks, LonGaussian improves novel-view rendering quality while using substantially fewer
Gaussians than the evaluated feed-forward baselines.

Introduction
Reconstructing renderable 3D scenes from long videos supports applications in robotic perception, embodied intel-
ligence, and immersive media. 3D Gaussian Splatting (3DGS) represents scenes with explicit Gaussian primitives,
enabling high-quality novel-view synthesis and real-time rendering (Kerbl et al., 2023). Optimization-based re-
construction methods produce high-quality scene representations but require time-consuming per-scene iterative
optimization (Mildenhall et al., 2021; Kerbl et al., 2023; Huang et al., 2024; Wu et al., 2024; Zhang et al., 2025).
Feed-forward Gaussian reconstruction improves efficiency by directly predicting renderable 3D representations from
multiple images through network inference (Charatan et al., 2024; Chen et al., 2024). However, many existing models
jointly process the input views (Charatan et al., 2024; Chen et al., 2024; Xu et al., 2025a; Jiang et al., 2025), causing
computational and GPU memory requirements to grow rapidly with sequence length. These demands limit long-video
inference, whose memory requirements may exceed GPU capacity.
Scaling to long sequences is constrained by both the inference backbone and the explicit scene representation. Online
approaches alleviate joint-view computational bottlenecks by updating an accumulated Gaussian scene or a compressed
historical state (Chen et al., 2026a; Cheng et al., 2026; Song et al., 2026; Huang et al., 2026). However, many
feed-forward Gaussian predictors still associate one primitive with each input pixel. Accumulating predictions from
repeated surface observations retains overlapping Gaussians for the same geometry, increasing representation size and
rasterization workload with sequence length. Figure 2 illustrates this redundancy. Although LoGeR enables streaming
long-context geometric reconstruction through chunk-wise processing and hybrid memory (Zhang et al., 2026a), it
predicts dense geometry and camera trajectories rather than maintaining a compact renderable scene. Extending
feed-forward reconstruction to long videos therefore requires both streaming geometric processing and explicit control
of redundancy caused by repeated observations.
Tracking foundation models offer a natural prior for addressing this redundancy. A point trajectory links image
observations of the same physical surface across frames and records surface visibility (Harley et al., 2022; Doersch
et al., 2023; Karaev et al., 2024, 2025; Xiao et al., 2024; Harley et al., 2025). These trajectories can guide Gaussian
grouping across repeated observations. In contrast to spatial strategies that aggregate primitives according to voxel
occupancy or Euclidean proximity, track-based grouping uses explicit cross-frame correspondences, providing a more
direct and interpretable basis for consolidation.
To this end, we propose LonGaussian, a streaming feed-forward Gaussian reconstruction framework for long image
sequences. LoGeR provides the backbone for predicting renderable 3D Gaussians, using chunk-wise hybrid memory
to process local chunks while retaining long-range geometric context. An independent tracker within each chunk
groups corresponding pixels into multi-frame trajectories. A learned merger consolidates their Gaussian predictions into
representative primitives, reducing redundancy while integrating geometric and appearance evidence. Rendered-depth
consistency filtering further suppresses residual cross-chunk floaters. Together, these components reconstruct compact,
globally renderable scenes from long sequences while preserving detail for high-quality rendering. Figure 1 provides a
qualitative example of scene reconstruction and novel-view rendering from an ultra-long unposed sequence.

Related Work
2.1
Feed-Forward and Long-Context 3D Reconstruction
Feed-forward 3D reconstruction has progressed from pairwise point-map regression and matching models such as
DUSt3R and MASt3R (Wang et al., 2024; Leroy et al., 2024) to architectures that process larger image collections
or streams. Offline models such as VGGT and π3 jointly reason over all input views through global attention, whose
computational and memory costs grow rapidly with sequence length (Wang et al., 2025a, 2026b; Yang et al., 2025;
Cabon et al., 2025; Tang et al., 2025; Lin et al., 2026; Keetha et al., 2026; Wang et al., 2026a). CUT3R instead processes
observations sequentially while maintaining a persistent recurrent state (Wang et al., 2025b; Wang & Agapito, 2025; Liu
et al., 2025; Chen et al., 2025; Lan et al., 2026). TTT3R reinterprets CUT3R’s recurrent update as test-time training and
derives a confidence-aware learning rate to improve generalization to longer sequences (Chen et al., 2026b). Separately,
LaCT improves the hardware efficiency and state capacity of test-time training by updating fast weights over large
token chunks (Zhang et al., 2026b; Elflein et al., 2026; Jin et al., 2026). LoGeR combines chunk-wise bidirectional
reasoning with sliding-window attention for uncompressed local context and TTT fast weights for compressed global
context (Zhang et al., 2026a). These models primarily predict point maps, depth, and camera parameters; a suitable
bridge to compact, explicit Gaussian scenes remains missing. We build on LoGeR’s long-context geometry to address
this complementary problem of feed-forward reconstruction of compact, globally renderable scenes.
2.2
Feed-Forward Gaussian Reconstruction
Feed-forward Gaussian reconstruction predicts image-conditioned 3D Gaussians from multi-view inputs (Charatan
et al., 2024; Chen et al., 2024; Xu et al., 2025a; Smart et al., 2024; Ye et al., 2025; Kang et al., 2025; Xu et al., 2025b;
Huang & Mikolajczyk, 2025; Ye et al., 2026), with AnySplat further supporting uncalibrated image collections (Jiang
et al., 2025). Because these predictions are commonly pixel-aligned, overlapping views may assign redundant or
inconsistent primitives to the same physical surface, causing the accumulated representation to grow with sequence
length (Park et al., 2026; Zhang et al., 2026c; Miao et al., 2025; Xia et al., 2025; Guo et al., 2026; Smart et al., 2026).
Recent approaches support online or long-sequence reconstruction through recursive fusion, rendering feedback, or
persistent scene memory (Chen et al., 2026a; Cheng et al., 2026; Song et al., 2026; Huang et al., 2026; Li et al., 2025),
but preserving geometry and rendering quality remains challenging as sequences grow. Our framework builds on
LoGeR’s established long-context backbone. Bidirectional within-chunk reasoning and global TTT memory establish
coherent geometry before Gaussian consolidation, separating long-context inference from explicit scene maintenance.
2.3
Compact Gaussian Representations
Compression of optimization-based 3DGS commonly relies on pruning, quantization, codebooks, or entropy coding (Lee
et al., 2024; Fan et al., 2024; Hanson et al., 2025). These methods operate on per-scene optimized representations
and often need training-view statistics or refinement, complicating integration into feed-forward reconstruction with-
out additional per-scene processing. Feed-forward approaches instead control the number of primitives through
geometry-adaptive allocation (Fei et al., 2024; Park et al., 2026; Moreau et al., 2026), anchor- or voxel-aligned represen-
tations (Zhang et al., 2026c; Guo et al., 2026), and matching-based fusion (Xia et al., 2025). Such strategies typically
consolidate Gaussians according to importance, spatial proximity, or local matches (Smart et al., 2026), but do not ex-
plicitly organize repeated observations of the same surface through consistent multi-frame correspondences. In contrast,
LonGaussian uses tracker-produced trajectories as explicit consolidation units, grouping track-supported observations
across an entire chunk before fusing their Gaussian predictions. Resolving correspondence before consolidation targets
the source of long-sequence redundancy rather than a post-hoc density problem, while preserving efficient feed-forward
inference without per-scene refinement.

4
Experiments
4.1
Experimental Setup
Baselines.
We compare LonGaussian with the offline methods AnySplat (Jiang et al., 2025) and WorldMirror (Liu
et al., 2026), and the streaming methods OF3GS (Chen et al., 2026a) and ReCoSplat (Cheng et al., 2026). For
ReCoSplat, we report both its released low-resolution checkpoint and a locally resolution-adapted checkpoint; the latter
is an accommodation for our evaluation resolution rather than an official training reproduction. StreamSplat (Song
et al., 2026), SaLon3R (Guo et al., 2026), and StreamGS (Li et al., 2025) are omitted because runnable official
implementations were unavailable at the time of evaluation.
Datasets and Metrics.
We train on DL3DV and use 150 sequences from the official RE10K training split for final
adaptation. We evaluate on DL3DV-140 and 180 eligible sequences from the official RE10K test split; identity-level
audits confirm zero overlap between training and evaluation sequences. Images are resized to 280 × 490; each scene is
constructed from up to 128 context frames, and held-out views serve as targets. LonGaussian uses two-pass unposed
evaluation: the first pass processes context and target images to estimate camera poses, while the second resets the
TTT states and SWA cache and constructs the scene from context images only. We align the first-pass trajectory to the
second-pass scene using shared context cameras and render held-out views at the aligned target poses (Appendix D.2).
Methods share frame indices whenever their interfaces permit, and ReCoSplat retains its prescribed first-chunk scale
matching. We average PSNR, SSIM, LPIPS, and the final Gaussian count over all held-out views and scenes.
Implementation Details.
We initialize and freeze the public LoGeR backbone and set L = 12, O = 3. With a global
batch size of four, Stage IIa trains only the merger on DL3DV for 900 steps; Stage IIb adapts for 300 steps, updating
the attribute head only at 16 frames and the merger at every length. Both uniformly sample |C| ∈{16, 64, 96, 128}.
Training uses AdamW on 24-GB RTX 3090 GPUs. Depth filtering and the far-field shell are enabled in final-stage
training and evaluation; the appendix provides the remaining settings.

4.2
Results
Table 1 and Figure 4 compare reconstruction across sequence lengths. WorldMirror and AnySplat exceed the GPU
memory budget even at the shortest evaluated length. Reconstructions from both ReCoSplat variants remain blurred or
geometrically distorted, while OF3GS preserves coarse layout but loses fine detail and accumulates many Gaussians.
LonGaussian instead achieves the best PSNR and SSIM at every length, produces sharper and more coherent renderings,
and uses the fewest Gaussians. OF3GS retains a slight LPIPS advantage on RE10K at the shortest evaluated sequence
length. As sequences grow, LonGaussian adds substantially fewer Gaussians than the streaming baselines on both
datasets, supporting more compact reconstruction while preserving rendering quality. Videos on the project page
provide side-by-side novel-view rendering comparisons for all evaluated methods.

4.3
Long-Sequence Scalability
We evaluate six cumulative prefixes of the scene in Figure 1, extending to 3,768 input frames. Unlike the complete-scene
rendering in Table 1, image metrics here average 15 held-out views per prefix, each rendered from its owner chunk
and up to three adjacent chunks on either side. This seven-chunk scope reduces interference from distant chunks
misregistered by LoGeR’s loop-closure errors. Gaussian count and construction resources measure the complete
accumulated prefix.
Table 2 shows approximately linear growth in construction time and representation size, with peak construction
memory remaining nearly constant on this sequence. Local rendering quality generally decreases as the prefix expands.
Appendix D.4 provides protocol details and scaling curves.
4.4
Ablation Studies
We ablate the components of LonGaussian on DL3DV-140 using 96 context frames and 13 target views per scene, with
the same checkpoint, two-pass protocol, resolution, and split as Table 1. Dense accumulation retains pixel-aligned
predictions, deterministic merging replaces the learned merger with fixed within-track aggregation, and each remaining
variant removes one component.
Table 3 shows that the full model substantially reduces Gaussian count while improving PSNR and SSIM, with a slight
LPIPS trade-off relative to dense accumulation. Learned refinement improves rendering quality over deterministic
merging at a similar representation size. Removing the dense complement yields a smaller representation but degrades
reconstruction quality, demonstrating the importance of preserving content without reliable track support. Depth
filtering provides the largest PSNR gain by suppressing cross-chunk occluders, while the far-field shell addresses
unstable sky geometry (Figure 5). Disabling either reduces reconstruction and evaluation time but lowers rendering
quality: despite retaining more Gaussians, these variants run faster because they omit processing stages. Thus, Gaussian
count alone does not determine total runtime.
5
Discussion and Limitations
LonGaussian assumes static scenes and reliable tracks. Motion, geometric errors, and fragmented tracks may cause
reconstruction errors, while within-chunk tracking may duplicate surfaces revisited after long gaps. Depth voting and
shell construction add overhead. On long-range revisits, LoGeR pose errors can misalign accumulated Gaussians
and cause global rendering ghosting. The seven-chunk metrics reduce interference from distant misregistered chunks
and therefore do not measure full-scene global rendering fidelity. Multi-scene benchmarks cover at most 128 frames;
Section 4.3 extends a single-scene quantitative case study to 3,768 frames and a qualitative example to 3,773 frames.

Conclusion
LonGaussian reconstructs compact, globally renderable Gaussian scenes from long sequences by combining LoGeR’s
chunk-wise hybrid memory with track-guided consolidation and artifact filtering. Tracker-derived correspondences
merge repeated surface observations, while rendered-depth filtering and far-field modeling suppress cross-chunk and sky
artifacts. Experiments on DL3DV and RealEstate10K show that LonGaussian improves rendering quality while using
substantially fewer Gaussians than feed-forward baselines, connecting long-context geometry to efficient renderable
representations.

A
Architecture and Consolidation Details
A.1
Dense Gaussian Prediction Head
The Gaussian branch follows a DPT-style dense prediction design. It reassembles four intermediate decoder features
at complementary spatial scales, fuses them from coarse to fine, and produces a 256-channel full-resolution feature
map. Separate two-layer convolutional heads predict a 3D offset, anisotropic scale, unit-quaternion rotation, opacity,
and degree-2 spherical-harmonic coefficients for every context pixel. The heads therefore predict 3, 3, 4, 1, and 27
values per pixel for these attributes, respectively. The opacity-head bias is initialized to −2, while the final offset layer
is initialized close to zero, preventing opaque or strongly displaced primitives at the start of training.
A.2
Track Validation and Ownership
AllTracker is run independently in each LoGeR chunk with four recurrent inference iterations and a confidence threshold
τtrk = 0.1. Tracked coordinates are rounded to the dense Gaussian grid. When multiple tracks map to the same
frame–pixel location, only the observation with the highest opacity-weighted visibility is retained, so a dense prediction
cannot be consumed by more than one representative. A track is eligible for consolidation when it contains at least
two retained observations, has a mean opacity of at least τα = 0.05, and has a root-mean-square distance of its 3D
centers from their arithmetic mean of at most τgeo = 0.3. The threshold τgeo is an absolute distance in the backbone
reconstruction coordinates, not a calibrated distance in meters or a scene-normalized quantity. Intrinsics calibration
preserves predicted depth, and SE(3) alignment does not change this scale. We additionally restrict observations to an
adaptive neighborhood around the query-frame anchor. Its radius is
rtrk = clip(6d1NN, 0.02, 0.5) ,
(11)
where d1NN is the median nearest-neighbor distance estimated from at most 5,000 points in the chunk. This neighbor-
hood gate adapts to local point spacing within the clipping bounds; it does not make the separate absolute threshold
τgeo scale invariant. We keep τgeo fixed across scenes and do not independently evaluate its sensitivity.
A.3

For every accepted track, the base center, scale, and SH coefficients are opacity-weighted averages of its observations.
The base opacity is obtained by alpha compositing, and the base rotation is computed by weighted quaternion averaging.

B
Scene-Level Artifact Handling
B.1
Rendered-Depth Consistency Filtering
For each chunk, we render its Gaussian predictions in its contributing context views and use the resulting depth and
opacity as local references. Gaussians originating from other chunks are projected into these views and compared with
the median depth in a 3 × 3 neighborhood. A comparison is ignored when fewer than five neighbors have sufficient
opacity or when their relative depth spread exceeds 0.15. Otherwise, the comparison contributes an occlusion vote
when the projected Gaussian lies at least 1% in front of the reference surface and an agreement vote when the relative
depth difference is at most 1%. A Gaussian is removed only if it receives at least one occlusion vote, occlusion votes
constitute at least 30% of all reliable comparisons, and they also constitute at least 30% of the combined occlusion
and agreement votes. The reference-opacity threshold is 0.5. A chunk never votes against its own predictions. These
conservative ownership and support tests prevent a single uncertain depth sample from deleting locally consistent
geometry.

B.3
Far-Field Gaussian Shell
We use the public skyseg.onnx checkpoint hosted by Jianyuan Wang.2 Each RGB frame is resized to 320 × 320,
normalized with ImageNet statistics, and processed by the fixed ONNX model. Its score map is min–max normalized
per image to unsigned values in [0, 255] and bilinearly resized to the input resolution; pixels with scores greater than
160 are classified as sky. The resulting mask first suppresses finite-depth Gaussian predictions. We define the shell
center as the coordinate-wise median of the input camera centers and estimate the scene radius as the 90th percentile of
the distances from scene Gaussians to this center. The shell radius is rsky = 50rscene. Sky pixels are sampled with
stride 2, converted to world-space rays, and quantized into 512 × 256 azimuth–elevation bins. Each occupied bin
produces one isotropic Gaussian with opacity 0.98. Its direction and RGB color are averaged from the observations in
the bin; RGB is represented by degree-zero SH, while the remaining coefficients are zero. The Gaussian scale equals
the shell radius times the angular bin size, with an overlap factor of 1.0.
C
Training Details
C.1
Two-Stage Optimization
All stages keep LoGeR and AllTracker frozen and use a global batch size of four. Stage I trains the Gaussian decoder
and attribute heads for one complete pass over the 8,590 eligible scenes in the DL3DV training split after excluding
all scenes that overlap with DL3DV-140; each sample is a dense 16-frame clip. Stage II initializes from Stage I
and freezes the feature decoder. In Stage IIa, we additionally freeze the Gaussian attribute head and train only the
learned merger on DL3DV for 900 optimizer steps. Stage IIb initializes from the Stage IIa checkpoint and performs a
300-step low-learning-rate adaptation with a balanced 1:1 schedule over 150 sequences from the official RE10K training
split and 118 DL3DV training scenes; neither adaptation set contains an evaluation identity. In both substages, we
sample uniformly from four sequence-length buckets: a 16-frame sparse sequence sampled at interval 8 and contiguous
sequences of 64, 96, and 128 frames. During Stage IIb, the merger is updated in every step, whereas the attribute head
is updated only for the 16-frame bucket; this corresponds to approximately 75 head updates under uniform sampling.
At most three context views and three held-out target views are rendered in each update.

D
Evaluation Protocol and Baselines
D.1
Dataset Preparation and View Sampling
DL3DV uses its downsampled images, while RealEstate10K frames are center-cropped to the target aspect ratio and
resized to 280 × 490 with corresponding updates to the intrinsics. For evaluation with C context views, every eighth
frame in a contiguous source prefix is held out as a target. The prefix therefore contains C + ⌊C/7⌋frames: the 64-,
96-, and 128-frame context settings contain 9, 13, and 18 target views, respectively. Scene lists and frame indices are
fixed before evaluation and shared across methods whenever their interfaces permit.
D.2
Two-Pass Unposed Evaluation
Our unposed evaluation separates camera estimation from scene construction. The first pass processes the complete
packed sequence to estimate a camera trajectory for both context and target views. The second pass reinitializes the
TTT fast-weight states and SWA cache, receives only context images, and constructs the Gaussian scene with tracking,
consolidation, filtering, and shell generation. The first-pass camera trajectory is aligned to the second-pass scene
coordinate system using the shared context cameras, after which the aligned held-out target poses are used for rendering.
Consequently, target images provide camera-pose observations in the first pass but never contribute Gaussian primitives,
tracking correspondences, appearance attributes, depth-filter references, or sky-shell samples. This protocol evaluates
renderable reconstruction from unposed context images without using target appearance in the reconstructed scene.

D.3
Baseline Configuration
For the baselines with numerical results in Table 1, target poses are predicted independently by each method rather
than shared with LonGaussian or taken directly from the dataset. Both ReCoSplat checkpoints use a first pass over
context and target images for pose estimation and a separate context-only pass for Gaussian construction. Their target
translations are rescaled using the predicted context-camera scale ratio between passes, with a shared first-camera
coordinate frame; the prescribed first-chunk scale matching is retained. OF3GS likewise predicts poses from context
and target images, constructs Gaussians from context images, and applies its native context-based translation-scale
matching before target rendering. These image metrics therefore reflect both scene reconstruction and each method’s
pose-estimation errors, and are not equivalent to evaluation with fixed ground-truth target poses. WorldMirror and
AnySplat yield only OOM entries at the reported lengths.
WorldMirror (Liu et al., 2026) and AnySplat use their native joint-view inference. OF3GS uses its native streaming
construction. For ReCoSplat, we report both the released low-resolution checkpoint and a locally adapted checkpoint
trained at 280 × 490 on a single 24-GB GPU. Starting from the released weights, adaptation comprises 1,000 updates
of the Gaussian decoder and output head, 2,000 updates that additionally train the recurrent-guidance projections,
and 1,000 mixed-context updates over 32, 64, 96, and 128 frames. All three phases use a learning rate of 10−5 and
approximately 975 DL3DV training scenes disjoint from DL3DV-140; the backbone and camera and point prediction
paths remain frozen. The final checkpoint is selected using non-RE10K DL3DV development evidence before RE10K
evaluation. This procedure preserves the released architecture and inference protocol but is a local resolution adaptation
rather than an official ReCoSplat reproduction. All available methods use the same prepared scene and target-view lists.

Tracks on moving objects may link observations that do not share a single 3D location, while textureless, reflective,
