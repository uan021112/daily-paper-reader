MonoMIP: Multi-Height Inverse Perspective
Mapping for Monocular 3D Object Detection
Emir Ulurak1 and Furkan Kıraç1
Ozyegin University, Istanbul, Turkey
emir.ulurak@ozu.edu.tr, furkan.kirac@ozyegin.edu.tr
Abstract. Monocular 3D object detection methods increasingly rely on
depth-guided transformers, but they operate entirely in the perspective
image plane where spatial relationships are distorted by foreshortening.
We propose MonoMIP, a dual-decoder framework that adds complemen-
tary 3D geometric reasoning through Bird’s-Eye View (BEV) features
constructed via Multi-Height Inverse Perspective Mapping. We perform
IPM at K elevation planes spanning ground to rooftop, producing an
ordered stack of height-conditioned metric BEV features that reduces
above-ground misprojection and exposes depth-dependent appearance
variation across planes. A BEV decoder with multi-scale deformable at-
tention aggregates this multi-height evidence per query, while a depth-
guided 3D decoder provides complementary perspective-space predic-
tions. Without extra training data, MonoMIP attains 25.84% Moderate
AP3D|R40 on KITTI val and 21.66% on the official test set for Car, out-
performing recent published monocular methods on both the KITTI and
Waymo benchmarks.
Keywords: Monocular 3D Object Detection · Bird’s-Eye View · Inverse
Perspective Mapping

Introduction
Monocular 3D object detection estimates the 3D position, size, and orientation
of objects from a single RGB image. A lone camera is far cheaper and simpler to
deploy than the LiDAR [16,40] or stereo [5,8] rigs used elsewhere, which makes
it appealing for autonomous driving and robotics. The difficulty is geometric: a
single perspective image fixes bearing but not range, so infinitely many 3D scenes
project to identical pixels and absolute depth cannot be recovered directly.
Depth-guided transformers have advanced monocular 3D detection. Mon-
oDETR [52] uses depth-aware position encodings and decoder attention to in-
corporate global context. MonoDGP [35] decouples 2D and 3D queries and refines
depth with geometry-error priors. Both operate in the perspective image plane,
where foreshortening distorts spatial relationships.
Bird’s-Eye View (BEV) representations provide a metric coordinate sys-
tem where spatial relationships are preserved regardless of depth. Multi-camera
methods [20,34] have demonstrated the power of BEV for 3D detection, but con-
structing BEV features from a single image remains an open challenge. Inverse

Perspective Mapping (IPM) [31] uses only the known camera calibration to map
image pixels onto a world plane by pure projective geometry, with no learned
parameters and no depth to estimate. This determinism has long made IPM a
workhorse of driving perception, spanning obstacle detection, lane detection [6],
and semantic BEV mapping [38].
Key insight. Multi-height IPM projects image features to several elevation
planes instead of committing every feature to the ground plane. For a fixed
BEV cell, the planes sample the same image column at different rows, forming
an ordered vertical appearance profile: above-ground parts are represented near
their correct BEV locations on matching planes, and row offsets follow the 1/Z
law derived in Section 3.2. The BEV decoder aggregates this height-conditioned
evidence per query; learned features preserve this structure (Figure 1, r=0.75),
and test-time height-order interventions show that the trained level arrangement
matters (suppl. Sec. E).
We instantiate this idea in MonoMIP (Monocular 3D Detection via Multi-
Height Inverse Perspective Mapping), a dual-decoder framework combining: (1)
a 3D detection decoder built on depth-guided deformable transformers [35, 52]
that produces object proposals with depth estimates in image space, and (2) a
BEV decoder that constructs height-conditioned BEV features via multi-height
IPM and refines metric object centers through deformable cross-attention over
the stacked BEV features. Both decoders share a common backbone and are
trained jointly end-to-end.
Our main contributions are:
– We introduce Multi-Height IPM, a parameter-free, calibration-grounded
image-to-BEV transform that projects encoder features onto K fixed ele-

Related Work
2.1
Monocular 3D Object Detection
Early monocular 3D detectors predicted boxes from keypoint heatmaps or geo-
metric priors on 2D detections [1,27,56] and modeled depth confidence through
geometry uncertainty [29]. Pseudo-LiDAR [48] converts estimated depth to point
clouds, whereas DD3D [32] uses depth pretraining without this intermediate rep-
resentation. Others handle truncated objects [53], analyze localization error [30],
or fuse probabilistic and geometric depth cues [41,46,47].
Transformer-based detectors [2,57] include MonoDETR [52], which predicts
foreground depth and feeds it to the decoder through depth-aware positional
encodings. MonoDGP [35] separates 2D and 3D query streams and refines depth
using geometry-error priors. Others target occlusion [12], learnable sample se-
lection [19], diffusion-based box generation [36], top-down denoising [25], and
global depth encoding [11]. More recently, MonoCoP [54] models inter-attribute
correlations with an uncertainty-guided selector on the MonoDGP framework,
while MonoIA [55] uses language and foundation-model intrinsic conditioning
for unseen focal lengths and multi-dataset training. Our approach adds a BEV
decoder over geometry-based IPM features, providing metric spatial reasoning
difficult to achieve in image space alone.
2.2
Bird’s-Eye View Representation
Constructing BEV features from images has been approached through depth-
based lifting [10,17,18,34], which predicts per-pixel depth distributions to “lift”
image features into 3D then collapses them onto BEV; attention-based projection
with BEV queries [20]; and geometric projection [31,39], which uses known cam-
era geometry for deterministic image-to-BEV mapping. PETR [26] instead uses
object queries over 3D position-aware image features. CaDDN [37] combined cat-
egorical depth distributions with BEV projection for monocular detection. Our
multi-height IPM belongs to the geometric-projection family but extends classi-
cal IPM [31], which assumes a single flat ground plane (exact only for road-level
content, as used in lane and free-space estimation [38, 51]), from one plane to

3
Method
3.1
Motivation and Overview
Given a monocular image I ∈R3×HI×WI, camera intrinsics K ∈R3×3, and a
calibrated camera height Hcam relative to the ground plane, MonoMIP estimates
3D bounding boxes parameterized by center (x, y, z), dimensions (h, w, l), and
heading angle θ.
Figure 2 shows the shared backbone and the image-space and metric BEV
decoders, connected by multi-height IPM.
Why Inverse Perspective Mapping. IPM offers a direct, learning-free path
from image to BEV: given the camera calibration, it maps each pixel onto a world
plane by pure projective geometry, predicting no depth and adding no param-
eters. The prevailing alternative is depth-based lifting, such as Lift-Splat-Shoot
(LSS) [34] and related depth-then-splat methods [10, 18, 37], which predict a
per-pixel depth distribution, lift features into a camera frustum, and splat them
onto the BEV grid. With multi-view or LiDAR-supervised depth this can be
effective, but monocular metric depth remains ill-posed: a single image does not
uniquely determine range, and uncertain pixel-depth estimates can spread evi-
dence across incorrect BEV cells. MH-IPM instead places features using known
calibration and assumed height planes, avoiding predicted pixel depth in the
view transform. This does not resolve monocular depth ambiguity; the detec-
tor still predicts object depth. A single ground plane misprojects above-ground
content, which motivates the multiple-height projections below.

Height Plane Selection. We place the K=4 planes at near-uniform 0.5 m
intervals, spanning the ground plane Y4=Hcam=1.65 m up to the upper plane
Y1=0.25 m in the rectified camera frame. The graded spacing lets each level con-
tribute distinct height-conditioned evidence, so the decoder can combine samples
aligned with different object parts rather than near-duplicate ground-plane pro-
jections. Uniform spacing needs no per-part tuning; only the overall range is
scene-dependent, and K is validated by ablation (Table 3a).
BEV Occupancy Map. We add a lightweight BEV occupancy head that
averages the K height features and predicts a single-channel confidence map,
supervised by BCE + Dice loss against rasterized ground-truth occupancy. It is
an auxiliary read-out that shapes the shared BEV features during training; it is
not fed back into the decoder and is unused at inference.
3.3
3D Detection Decoder
Following MonoDETR [52], the image branch is a depth-guided decoder. The
multi-scale image features carry sinusoidal position encodings, and a depth pre-
dictor produces a per-pixel foreground depth distribution over Nd LID bins [37].
An Nenc-layer multi-scale deformable encoder [57] enriches the features, and each
of the Ndec decoder layers applies depth cross-attention to the dense depth fea-
tures, query self-attention, multi-scale deformable cross-attention to the image
features, and a feed-forward network. Prediction heads output class, 2D box, 3D

does not predict heading. The 12-bin/residual angle head belongs only to the

3.4
Dense Depth Prediction
A dense depth prediction module fuses multi-scale backbone features through a
lightweight convolutional encoder and predicts per-pixel depth distributions over
Nd + 1 bins (including background). The dense depth features serve as context
for the decoder’s depth cross-attention. Beyond depth awareness, this attention
anchors image-space queries on object regions, balancing 2D localization with
3D attribute regression.

BEV Transformer Decoder. The BEV decoder is a stack of Nbev layers, each
applying self-attention among queries, multi-scale deformable cross-attention
over the multi-height BEV features, and a feed-forward network. The K height
levels are treated as separate “scales” in deformable attention [57]: each query
samples npoints offsets from every level and softmax-weights all K×npoints sam-
ples into one output. Each level samples a different image row for the same BEV
cell (Eq. (4)), so the fused evidence is height-conditioned with depth-dependent
1/Z spacing, and deformable attention learns which levels are most useful per
query.
Following DAB-DETR [23], each query’s positional embedding is generated
from its 4D anchor (X, Z, W, L) by sinusoidal encoding and a small MLP, and
added to the content query in self- and cross-attention with the anchor center
as the deformable reference; encoding (W, L) makes the prior size-aware. An-
chors are initialized from the unprojected 2D proposals (Eq. (7)) rather than
learned from scratch, a geometric warm start that stabilizes optimization. At
each layer the BEV box head (a small MLP) regresses a residual update to
the axis-aligned box (X, Z, W, L) and a bounded residual to its log-scale log σz,
initialized from the depth head; heading is predicted from the BEV decoder fea-
tures by a separate 12-bin/residual angle head, supervised at every BEV layer.
Anchor and log σz are updated and detached between layers, so both are itera-
tively refined under deep supervision and the regenerated positional query tracks
the improving estimate. At inference, image-predicted centers are unprojected
using the BEV-refined depth. The final dimensions retain image-predicted height
and BEV-refined width/length. We select top-50 detections by class score and
export uncertainty-weighted scores scls · exp(−log σz)=scls/σz, without NMS.
Both decoders train jointly end-to-end.
3.6
Loss Function
Following Group DETR [3], we replicate queries into G groups during training,
each independently matched via the Hungarian algorithm [14]. This increases
effective supervision without changing inference (single group of Nq queries).
BEV-Aware Matching Cost. Standard DETR matchers assign each ground-
truth object to the query that is closest in the image plane (classification score,
2D box ℓ1, and GIoU). Our BEV decoder, however, localizes objects in metric
space, so an image-plane assignment can supervise a query whose perspective box

5
Conclusion
We presented MonoMIP, a monocular 3D detector pairing depth-guided image-
space and metric BEV reasoning from multi-height IPM. Projecting features to
fixed planes reduces above-ground misalignment and exposes ordered, depth-
dependent evidence the BEV decoder aggregates into metric centers, improving
monocular 3D localization on both KITTI and Waymo.
Limitations and Future Work. MonoMIP assumes known calibration and
fixed height planes, with far-range evidence limited by feature stride (suppl.
Sec. J). Matched focal tests attribute most sensitivity to geometric depth, while
camera-height error remains an MH-IPM limitation. Pitch and non-planar roads
remain unvalidated. A 192×160 grid improves Cyclist by 0.79 AP but Pedestrian
by only 0.12, so resolution is one factor rather than a complete explanation of
small-object errors. Reported Waymo results retain KITTI-default planes (suppl.
Sec. H). Scene-adaptive heights and uncertainty-aware calibration are future
directions.

Failure Cases and Limitations
Height coverage. The plane range is shared across categories, but a finite
set does not cover arbitrary scene geometry. Section E distinguishes the plane-
placement results, inference-only order changes, and trained coverage variants.
The latter omit an exact ground plane yet retain useful performance. Their dif-
ferent placements and equal spans show why neither ground coincidence nor
span width alone explains accuracy. The reported Waymo benchmark uses un-
changed KITTI-default planes; the qualitative shifted-plane comparison does not

establish calibration-free transfer. Scene-adaptive plane selection remains future
work.
Calibration and camera height. MonoMIP assumes known calibration and a
roughly fixed camera height. Tables S8 and S9 examine complementary sources
of calibration sensitivity. Table S8 reports the camera-height study: all IPM
planes are shifted together, and a ±0.10 m offset costs roughly 2–3 AP. This is
a limitation of the assumed height in MH-IPM.
Table S9 reports the focal-sensitivity results and their component attribution.
The full-network rows scale both fx and fy in the network input for each detector.
The component rows change only the geometric-depth fx term or the MH-IPM
(fx, fy) sampling coordinates, keeping all other calibration uses unchanged. The
larger effect comes through geometric depth, consistent with its inherited focal
dependence. These component effects should not be summed or equated with the
full-network intervention. Images and ground truth stay unchanged, and final
coordinate decoding retains the original calibration. This is a metadata-error
test, not a pitch or sloped-road evaluation.

Range limits. Two geometric limits remain. At far range the cross-height row
separation shrinks toward the feature stride, so the planes become hard to distin-
guish and the BEV cue weakens, consistent with the narrowing 40–60 m gains in
the main paper. At the strict IoU3D ≥0.7 operating point on Waymo, the resid-
ual gap concentrates in the near range, where vehicles are large and frequently
truncated at the image border, so small height, dimension, or truncation errors
incur a disproportionate IoU penalty; we verified this is geometric rather than a
ranking or post-processing artifact (sweeping top-k, toggling BEV NMS, altering
the score, and filtering tiny boxes all leave it unchanged).
Small and hard classes. The coarse 96×80 grid can limit spatial detail for
thin objects, but resolution is not a complete explanation of small-class errors.
The finer-grid experiment in Sec. K improves Cyclist more than Pedestrian, at
greater latency and memory cost. MonoDGP [5] also discusses irregular Cyclist
shape and greater projection uncertainty. That is a plausible factor, not a cause
isolated by our resolution ablation.

Additional Ablations
This section reports additional ablation studies. Detection scores are KITTI val
Moderate R40 AP, at IoU 0.7 for Car and 0.5 for Pedestrian/Cyclist. Additional
trained variants use the full 250-epoch recipe and report three-seed means. The
reported 25.84 reference is the best of ten runs, whose distribution is reported
in Sec. F.
Decoder composition. The 2D-only stage predicts class and box fields, without
depth cross-attention. The 3D stage is our depth-guided image decoder, and the
BEV stage uses the same metric refinement as the full model. Adding a 2D stage
before 3D+BEV increases parameters and latency without an observed accuracy
gain. The 24.99 result is close to the full model’s ten-seed mean, so it does not
establish an accuracy difference beyond seed variation. The 2D+BEV variant
initializes metric coordinates from projected features without perspective depth
and size anchors. Its lower result supports the value of these anchors, but does
not rule out other 2D+BEV designs. Published MonoDGP supplies the 2D+3D
reference in the main benchmark tables; it is not a controlled retraining.
Controlled depth lifting. The LSS-style replacement keeps the fused features, pre-
dicted 80-bin depth distribution, BEV range and 96 × 80 grid, queries, decoder,
losses, matching, augmentation, and schedule fixed. Its three-seed mean is 24.05
AP and maximum 24.17, below all ten MH-IPM runs (24.80–25.84). MH-IPM has
7.9% lower measured latency at the same parameter count and allocated mem-
ory. This supports the IPM representation within the hybrid pathway, rather
than attributing the entire gain to an added decoder. The seed comparison is
descriptive, not a paired statistical test.
