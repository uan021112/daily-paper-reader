Abstract
Feed-forward 3D Gaussian Splatting (3DGS) methods enable efficient reconstruc-
tion of 3D scenes from sparse multi-view images in a single forward pass, with-
out scene-specific optimization. However, existing feed-forward scene-coding
pipelines first generate a complete Gaussian representation and then encode its
geometry and appearance attributes separately, often involving non-differentiable
operations. The resulting ‘generate-then-compress’ pipeline requires complex
attribute-specific codec designs and limits rate–distortion performance by restrict-
ing the exploitation of cross-attribute redundancy. We propose multi-view feature
coding for Gaussian splatting (MFGS), an end-to-end feed-forward framework
for scene coding. Instead of compressing an explicit Gaussian representation,
MFGS extracts multi-view features from the input images and encodes them into
a compact bitstream. Through end-to-end rate–distortion training, MFGS learns
compact multi-view features that jointly represent geometry and appearance, en-
abling the receiver to predict Gaussian attributes from the decoded features. We
further introduce importance-guided Gaussian selection to accommodate different
rendering budgets, allowing the receiver to adjust the number of Gaussians used
for rendering from the same bitstream. Across RE10K, ACID, and DL3DV, MFGS
achieves 99.76–99.86% bitrate savings over the generate-then-compress pipeline,
as measured by BD-rate, while reducing total GMACs by 52–55% and providing
an approximately 12× end-to-end speedup.

Introduction
3D Gaussian Splatting (3DGS) [Kerbl et al., 2023] enables high-quality novel-view synthesis with
real-time rendering, but its large explicit representations incur substantial storage and transmission
costs. Optimization-based 3DGS compression methods [Chen et al., 2024a, 2025b, Wang et al.,
2024b, Navaneet et al., 2024, Wang et al., 2024a], which optimize Gaussian representations for each
scene, achieve strong rate–distortion performance at the cost of time-consuming iterative optimization.
This limits their applicability to live applications that require rapid reconstruction and transmission of
newly captured scenes.
Feed-forward methods [Charatan et al., 2024, Chen et al., 2024b, Xu et al., 2025, Liu et al., 2025,
Zhang et al., 2025] address this limitation by reconstructing Gaussian representations directly from
sparse input views in a single pass. Scene transmission then follows the ‘generate-then-compress’
pipeline in Figure 1, which encodes the predicted Gaussian attributes through specialized coding paths.
For example, FCGS [Chen et al., 2025a], a representative feed-forward 3DGS compression model,
uses G-PCC [Schwarz et al., 2019] for positions and learned coding for the remaining attributes.
This separation complicates the architecture and limits joint compression of shared geometry and
appearance information, while non-differentiable operations hinder end-to-end rate–distortion training.

Our main contributions are summarized as follows:
• We introduce the MFGS framework as an alternative to generate-then-compress for feed-
forward 3D scene coding. By encoding multi-view features and reconstructing Gaussians at
the receiver, the framework unifies attribute-specific coding paths, enabling joint compres-
sion of geometry and appearance and end-to-end rate–distortion optimization.
• We instantiate the proposed framework in the MFGS-Base model and demonstrate substan-
tial bitrate savings together with lower computation, peak GPU memory, and runtime than
the generate-then-compress baseline across RE10K, ACID, and DL3DV. The joint reduction
in bitrate and processing time supports the potential of multi-view feature coding for 3D
live streaming.
• We extend the baseline with the MFGS-Adaptive model, enabling receiver-side adjustment
of the number of rendered Gaussians from a single bitstream. Experiments demonstrate
limited quality degradation across rendering budgets, allowing a shared bitstream to serve
receivers with different rendering capacities.

Related Work
2.1
Optimization-based 3DGS compression
Optimization-based 3DGS compression methods optimize a compact Gaussian representation sepa-
rately for each scene. HAC [Chen et al., 2024a] models the relationship between unstructured anchors
and a structured hash grid, while HAC++ [Chen et al., 2025b] further captures dependencies among
attributes within each anchor. ContextGS [Wang et al., 2024b] introduces a hierarchical autoregressive
context model across anchor levels. CompGS [Navaneet et al., 2024] applies K-means-based vector
quantization while optimizing the Gaussian parameters, whereas RDO-Gaussian [Wang et al., 2024a]
combines pruning and entropy-constrained vector quantization under a rate–distortion objective.
These methods achieve strong compression performance but require scene-specific optimization,
limiting their use in live applications.
2.2
Feed-forward 3DGS generation
Feed-forward 3DGS methods predict explicit Gaussian primitives from input multi-view images
without per-scene optimization. pixelSplat [Charatan et al., 2024] models Gaussian depth using a
probabilistic parameterization, while MVSplat [Chen et al., 2024b] estimates depth using plane-
sweep cost volumes. DepthSplat [Xu et al., 2025] further combines multi-view cost volumes
with features from a pretrained monocular depth model. MonoSplat [Liu et al., 2025] adapts
monocular depth features into multi-view representations, whereas TranSplat [Zhang et al., 2025]
combines confidence-guided feature matching with monocular depth priors. ZPressor [Wang et al.,
2025] aggregates information from support views into a compact anchor-view latent representation,
improving scalability to dense input views.
2.3
Feed-forward 3DGS compression
FCGS [Chen et al., 2025a] encodes an existing Gaussian representation without scene-specific
fine-tuning using a multi-path entropy module and inter- and intra-Gaussian context models. The
MPEG-GSC test model TMCV [Ricard et al., 2025] also provides coding tools for explicit Gaussian
parameters. These codecs retain the generated Gaussians as the coded representation, so coding
operates on explicit geometry and appearance attributes. In contrast, our approach moves coding
before Gaussian prediction and jointly compresses the shared information in an image-like multi-view
feature representation.
2.4
Gaussian pruning
Gaussian pruning reduces the number of primitives, thereby lowering storage and rasterization costs.
LightGaussian [Fan et al., 2024] ranks Gaussians using a global significance score computed over the
training views and removes the least significant primitives. It then recovers rendering quality through
SH distillation with pseudo views and applies vector quantization. PUP-3DGS [Hanson et al., 2025]
3


uses a second-order approximation of reconstruction sensitivity with respect to the spatial parameters
of each Gaussian and applies a multi-round prune–refine procedure. EcoSplat [Park et al., 2025]
introduces a two-stage training scheme for feed-forward 3DGS. It first learns pixel-aligned Gaussian
prediction and then ranks and adjusts the predicted primitives according to a target primitive count.
2.5
Learned image compression
Learned image compression uses neural analysis and synthesis transforms, quantized latent rep-
resentations, and entropy models trained under a rate–distortion objective. The scale hyperprior
model [Ballé et al., 2018] predicts spatially varying scale parameters for the latent distribution. Joint
autoregressive and hierarchical priors [Minnen et al., 2018] combine a hierarchical prior with causal
autoregressive context to improve entropy modeling. Attention-based image compression [Cheng
et al., 2020] uses discretized Gaussian mixture likelihoods to model the latent distribution. AuxT [Li
et al., 2025] introduces wavelet-based linear shortcuts that support feature decorrelation and energy
modulation, accelerating the training of nonlinear transforms.

3.2
End-to-end multi-view feature coding (MFGS-Base model)
The MFGS-Base model is designed to improve compression efficiency while simplifying the coding
process. Whereas generate-then-compress pipelines encode the attributes of spatially unstructured
Gaussians through separate coding paths, MFGS-Base encodes multi-view features on regular image-
like grids. This representation supports a unified codec whose entropy model operates on compact,
downsampled latents, reducing computation and memory usage. End-to-end rate–distortion training
further enables the codec to exploit redundancy between geometry and appearance within this unified
coding path.

view features F, each plane of which has the spatial dimensions H × W of the input multi-view
images. Since the Gaussian prediction head produces one Gaussian per spatial location, this yields
N = V HW Gaussians, independent of C. We denote the generator’s multi-view feature extractor

Each multi-view feature plane is a three-

3.3
Decode-time budget adaptation (MFGS-Adaptive model)
The MFGS-Adaptive model extends MFGS-Base to accommodate receivers with different rendering
capacities. Unlike post-hoc pruning, it jointly optimizes feature coding, budget-conditioned recon-
struction, and Gaussian selection using the additional modules shown in green in Figure 3. Training
across keep ratios k ∈(0, 1] limits quality degradation as the rendering budget decreases. At each
trained rate point, the bitstream remains independent of k, allowing the receiver to adjust rendering
cost after transmission.

4
Experiments
4.1
Experimental setup
We train the MFGS-Base and MFGS-Adaptive models on RealEstate10K (RE10K) [Zhou et al.,
2018] using 12 input views and 8 target views per scene at a resolution of 256 × 256. We evaluate
the trained checkpoints in-domain on RE10K and conduct cross-dataset evaluation without dataset-
specific fine-tuning on ACID [Liu et al., 2021] and DL3DV [Ling et al., 2024], using 8 input views
for RE10K and ACID and 12 for DL3DV, with 8 target views for all three datasets. We train each
model separately for each λ ∈{0.0256, 0.1024, 0.4096, 1.6384}. By default, we use 6 cluster views,
yielding 393,216 Gaussians per scene. We report PSNR, LPIPS, arithmetic-coded bitstream size, and
BD-rate [Bjøntegaard, 2001]. Additional evaluation details are provided in Appendix A.3.

two generate-then-compress baselines, FCGS and the MPEG-GSC test model TMCV. Both compress

We compare the complexity of the MFGS-Base model and the
MVSplat+FCGS generate-then-compress pipeline (Table 2), with Gaussian generation by MVS-

stages, averaged over the three datasets. MFGS-Base also achieves an approximately 12× end-to-end

5
Conclusion
We presented the MFGS framework as an alternative to generate-then-compress for end-to-end
feed-forward 3D scene coding. It encodes multi-view features that jointly represent geometry and
appearance and reconstructs Gaussians from the decoded features at the receiver. The MFGS-
Base model uses an established learned image codec to exploit cross-attribute redundancy through
end-to-end rate–distortion training. This design improves compression efficiency while reducing
computation, memory usage, and runtime. The MFGS-Adaptive model further enables the receiver
to adjust the number of rendered Gaussians from a single bitstream at each trained rate point,
accommodating different rendering capacities with limited quality degradation.
Across RE10K, ACID, and DL3DV, MFGS-Base achieves an approximately 500× bitrate reduction
based on average BD-rate, roughly halves total GMACs, and runs about 12× faster end to end than the
generate-then-compress baseline. This bitrate advantage also extends to other Gaussian generators,
suggesting that the effectiveness of the MFGS framework is not tied to a specific generator. At
reduced rendering budgets, MFGS-Adaptive preserves quality more effectively than the evaluated
post-hoc pruning methods, even when retaining only 20% of the Gaussians. These results support the
MFGS framework as a promising approach to low-latency 3D scene delivery.
6
Future Work
These findings are based on sparse input views at low resolution, primarily in a narrow-angle setting,
and extending the framework to higher resolutions and wider camera coverage requires further
investigation. Since the multi-view features are learned jointly with the Gaussian generator, deploying
the framework with a different generator also requires offline retraining. At reduced rendering
budgets, MFGS-Adaptive still predicts the full Gaussian candidate set before selection, so lowering
the keep ratio reduces rendering cost but not decoding cost; decoding strategies whose computation
scales with the rendering budget would remove this overhead. Finally, because the multi-view features
11


share the regular layout of images, the framework extends naturally to video coding, where temporal
prediction and entropy modeling could exploit redundancy across multi-view features over time.

A.1
Architecture details
The multi-view feature extractor uses UniMatch [Xu et al., 2023] features and six transformer blocks.
ZPressor projects the cost-volume representation to 128 multi-view feature channels and concatenates
RGB, disparity, and the maximum depth probability, yielding F ∈RV ×133×H×W . The Gaussian
prediction head refines these multi-view features with a U-Net and predicts Gaussian attributes,
disparity corrections, and density values that are mapped to opacity. A camera-based Gaussian
adapter converts depth and image-plane offsets into world-space centers and transforms the predicted
scales and rotations into world-space covariances. Tables 3 and 4 summarize the multi-view feature
codec and the additional modules used in MFGS-Adaptive.
In MFGS-Adaptive, the keep-ratio embedding provides FiLM conditioning to the synthesis transform,
Gaussian prediction head, and decoder-side importance predictor. The encoder-side importance
predictor receives F and a detached copy of its first RGB channel as an auxiliary input. The decoder-
side predictor receives the decoded multi-view features, the predicted density before opacity mapping,
and nine raw channels from the Gaussian-attribute head encoding offsets, scales, and rotations.
The density and geometry inputs are detached, preventing importance-prediction gradients from
propagating through these auxiliary inputs.

A.3
Evaluation protocols
Main evaluation.
The standard evaluation sets contain 7,067 RE10K, 1,810 ACID, and 140
DL3DV test scenes. For the rate–distortion comparisons in Figure 4 and Table 1, we retain scenes
with completed evaluations and finite quality and bitstream-size measurements for every method and
operating point, including the frozen-generator variant and MFGS-Adaptive at k = 1. This yields
6,235 RE10K, 1,597 ACID, and 140 DL3DV scenes, using identical input and target views for all
methods. Reported rates and quality metrics are arithmetic means over this shared scene set, so the
comparisons characterize the matched subset rather than the full test sets.
BD-rates in Table 1 are computed from these matched-scene curves by integrating piecewise cubic
Hermite (PCHIP) interpolants of log bitstream size over the common PSNR interval of each method
pair; no BD-rate is reported when the intervals do not overlap. The bitrate values in Figure 2 use the
same BD-rates. Other experiments retain their stated evaluation sets.
16


FCGS implementation and scene exclusions.
The FCGS rate–distortion results are obtained with
the original FCGS implementation. Some scene–rate pairs could not be evaluated because of CUDA
execution errors. We exclude any scene lacking a measurement at even one operating point from all
compared methods and curves, rather than averaging each curve over a different scene set. Scene
selection depends on measurement availability, not reconstruction quality.
Separate reproducibility checks identified encoder–decoder discrepancies in some completed FCGS
runs, associated with floating-point differences in channel-context computation. This discrepancy
also occurs with the original FCGS code and its specified PyTorch and CUDA versions. Completion-
based filtering therefore does not certify bit-exact decoding for every retained scene; the reported
curves characterize the original implementation in our evaluation setting. The fixed-tiling entropy
computation used for complexity profiling is described separately in Appendix A.7.
Baseline settings.
FCGS is evaluated at λ ∈{0.0001, 0.0002, 0.0004, 0.0008, 0.0016} in Figures 4
and 6. TMCV is evaluated at attribute QP ∈{0, 8, 16, 24, 32} with the position QP fixed to 0. In Fig-
ures 4 and 5, both baselines compress the Gaussians produced by the standalone MVSplat+ZPressor
generator, trained without a codec.
Entropy-coding reproducibility.
The encoder and decoder must compute matching entropy pa-
rameters hs(ˆz) to select identical probability-table indices. The rate–distortion, seed-robustness,
and importance-allocation evaluations therefore use deterministic GPU settings, and each scene is
re-encoded from its inputs with fixed trained weights and the unchanged bitstream format.
Gaussian-generator architecture evaluation.
Each MonoSplat- and TranSplat-based MFGS-Base
model is trained on RE10K with 2 input and 4 target views per scene and evaluated on ACID with
2 input and 3 target views. For each generator, we use a fixed ACID scene set across all four
MFGS-Base and five FCGS operating points. Some runs did not complete all 1,595 scenes, so we
retain only scenes with results for both methods at every operating point, yielding 1,560 scenes for
MonoSplat and 1,418 for TranSplat. BD-rates are computed from these matched-scene curves using
PCHIP interpolation over each method pair’s common PSNR interval, without extrapolation.
Importance analysis.
The importance-allocation statistics use all 1,810 ACID test scenes at each
rate point, with valid measurements for both encoder- and decoder-side rankings. At each spatial
location in the main latent, we sum the entropy model’s negative log-probabilities across channels to
estimate the coding cost. Encoder- and decoder-side importance maps are average-pooled to the same
latent resolution. Locations from all multi-view feature planes are ranked together within each scene;
bin costs are normalized by the scene’s total estimated y-stream cost before averaging across scenes.
Multi-view image coding.
The MIV comparison uses the intersection of scenes successfully
processed at every operating point of the MFGS-Base model and MIV: 7,066 RE10K, 1,809 ACID,
and 140 DL3DV scenes.

A.5
Pruning settings and latent-gating ablation
Post-hoc pruning settings.
PUP-3DGS ranks Gaussians by a Fisher-information score that mea-
sures the sensitivity of rendered images to their spatial parameters. We compute this score with
its CUDA rasterizer at the original image resolution, using a patch size of 1. LightGaussian uses
deterministic pixel-contribution counts weighted by opacity and by normalized Gaussian volume
raised to vpow = 0.1. Both methods prune the Gaussians reconstructed by MFGS-Base, without
per-scene fine-tuning, distillation, or post-pruning quantization.
Encoder-side latent-gating ablation.
We compare the full MFGS-Adaptive model with a variant
that omits encoder-side latent gating and the associated importance-alignment loss. Both retain
keep-ratio conditioning and decoder-side selection and are trained from the corresponding Stage 3
checkpoint under the same Stage 4 schedule. Figure 10 shows that the full model generally achieves
a better rate–distortion trade-off, with a small reversal at the highest-rate DL3DV point. The main
effect of gating is a narrower PSNR range across keep ratios.

Even within the learned modules, parameter count alone does not determine computational cost.
Weights are reused at each spatial location, so a small network can be expensive when applied
repeatedly. For example, the hyperprior synthesis transform hs contains nearly 60% of MFGS-Base’s
decoding parameters but accounts for only 2% of its decoding GMACs. A single evaluation of hs
predicts the entropy parameters for all main-latent locations on compact, downsampled grids (see
Appendix A.8 for their sizes). FCGS’s smaller entropy networks process per-Gaussian latents and
spatial/channel contexts across a much larger set of primitives. During decoding, spatial contexts
19


are updated using previously decoded Gaussian groups, while channel contexts depend on preceding
channel groups. This entropy-model cost dominates the profiled FCGS decoding GMACs even
without G-PCC, explaining why MFGS-Base can use more learned parameters yet require less
computation.
Peak memory also depends on intermediate tensors and temporary workspaces. Avoiding FCGS’s
Gaussian-domain context grids and per-Gaussian entropy tensors reduces these working-memory
demands. The additional model weights occupy only tens of MiB, whereas the measured stage
peaks decrease by several GiB. Raw tensor sizes alone do not determine peak memory, and our
measurements do not isolate the contribution of each allocation. Over the full encode–decode–render
pipeline, MFGS-Base takes about 0.5 s per scene compared with 6.4 s for MVSplat+FCGS, an
approximately 12× speedup.
Runtime excluding G-PCC.
To assess runtime beyond the cost of G-PCC, we subtract G-PCC
encoding and decoding times, measured separately on the same 340 scenes, from the MVSplat+FCGS
timings. This estimate excludes only the G-PCC executable calls and retains Gaussian generation,
neural coding, geometry preprocessing, format conversion, and rendering. Averaged across RE10K,
ACID, and DL3DV, the estimated full-pipeline runtime decreases from 6.41 s to 2.99 s per scene,
compared with 0.52 s for MFGS-Base. The approximately 5.7× speedup indicates that the runtime
advantage extends beyond the cost of G-PCC.
Measurement protocol.
We measure both methods on the same scenes and views using RTX 3090
GPUs: 100 randomly sampled test scenes from each of RE10K and ACID, and all 140 DL3DV test
scenes. We follow the input-view settings described in the experimental setup. Each stage is timed
three times after a warm-up run, and results are averaged across the three datasets. Encoding covers
input images through bitstream construction, including Gaussian generation for MVSplat+FCGS;
decoding ends at Gaussian reconstruction. Timings include bitstream I/O and FCGS’s G-PCC
and format conversion, but exclude data and model loading. FCGS uses float32 entropy-model
computation with fixed GEMM tiling for bit-exact decoding. Peak memory is the maximum allocated
GPU memory within each stage, including model weights; it excludes CPU memory, including that
used by the external G-PCC process. Parameters count learned weights once per deployed module
on each side. G-PCC remains part of the executed pipeline, but its cost is reflected only in runtime
among the reported metrics. MFGS-Adaptive is omitted because it predicts the full candidate set
before selection.
GMACs in Table 2 count executed convolution, linear, matrix-product, and attention operations,
with one multiply–add counted as one MAC. They exclude rendering, normalization, interpolation,
entropy-coder byte operations, and FCGS’s G-PCC and custom CUDA operations. Table 7 uses
fvcore [FAIR, 2022] estimates on RE10K, weighting FCGS branches by their mean routing fraction

A.10
Assets and broader impact
Assets.
The experiments use RE10K [Zhou et al., 2018], ACID [Liu et al., 2021], and DL3DV [Ling
et al., 2024]. RE10K and ACID provide camera metadata and source-video identifiers; the corre-
sponding videos remain subject to the dataset instructions and YouTube terms. DL3DV is used under
21


the DL3DV-10K Terms of Use. We follow the licenses and terms of the baseline implementations
and do not release a new dataset.
Broader impact.
Compact feed-forward scene transmission can reduce bandwidth and storage re-
quirements for telepresence and immersive media. However, captured imagery may introduce privacy
risks, including unauthorized scene reconstruction. Practical deployments should obtain consent for
data capture, follow dataset and platform terms, and restrict access to sensitive reconstructions.
