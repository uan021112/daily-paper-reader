## 摘要
多模态智能体（MMA）通过推理、记忆、工具和反馈维持交互，最典型的形态是计算机使用智能体；而机器人系统（RS）则在物理动力学约束下耦合感知与执行。我们将多模态具身智能体（MMEA）定义为一种目标导向系统，它将多模态任务推理与物理行动相结合，并根据由此产生的反馈修正决策。这引出了一个核心问题：多模态智能体从计算机使用转向机器人使用时，究竟发生了什么变化？我们提出 PAPAV——一个以能力为中心的统一框架，涵盖五项反复出现的功能：感知当前状态（Perceive）、预判行动效果（Anticipate）、规划可行方案（Plan）、通过接口或身体执行行动（Act），以及验证结果（Verify）。PAPAV依据功能而非架构定义这些能力，因此既能识别三类系统的共同点，也能比较 MMEA 与 MMA、RS 之间的差异。从部分可观测性到结果无法验证，五项物理约束使得更少的选择能够预先固定，也压缩了纠正错误的空间。在 64 项基准测试中，显式评估主要集中于 Act；仅有 5 项评估 Anticipate，3 项评估 Verify，因此这两项能力在很大程度上仍被任务成功这一指标所掩盖。这些约束也构成了我们所指出的开放挑战的背景。因此，PAPAV 为可靠物理智能体的设计，以及从全部五项能力而非仅从任务成功角度衡量进展，提供了共同基础。

## Abstract
Multimodal agents (MMAs) sustain interaction through reasoning, memory, tools, and feedback, most visibly as computer-use agents, while robotic systems (RSs) couple sensing and actuation under physical dynamics. We define multimodal embodied agents (MMEAs) as goal-directed systems that couple multimodal task reasoning with physical action and revise decisions from the resulting feedback. This raises a central question: what changes when a multimodal agent moves from computer-use to robot-use? We introduce PAPAV, a unified capability-centric framework of five recurring functions: Perceive the current state, Anticipate action effects, Plan a feasible course, Act through an interface or body, and Verify the outcome. Defined by function rather than architecture, these capabilities let PAPAV identify what all three share and then compare MMEAs with MMAs and with RSs. Five physical constraints, from partial observability to unverifiable outcomes, leave fewer choices fixed in advance and less room to reverse errors. Across 64 benchmarks, explicit evaluation centers on Act; only 5 assess Anticipate and 3 assess Verify, leaving both largely hidden behind task success. These constraints also frame the open challenges we identify. PAPAV therefore provides a common basis for designing reliable physical agents and measuring progress across all five capabilities rather than task success alone.

- **核心问题：**多模态智能体从电脑、网页等数字环境转向机器人等物理环境时，智能体的任务闭环发生了什么变化？
- **研究背景：**
  - 多模态智能体（MMA）已能通过推理、记忆、工具调用和反馈进行持续交互，常见代表是计算机使用智能体。
  - 机器人系统（RS）则需将感知与执行置于物理动力学、身体结构和安全约束下。
  - 这两条研究路线各有成熟积累，但仅把软件接口替换成机器人接口，并不能解决物理环境中的状态不确定、动作后果复杂和错误难以撤销等问题。
- **论文的整体主张：**要理解从“计算机使用”到“机器人使用”的变化，应比较两类系统在任务闭环中承担的功能，而不应只按模型架构或动作形式分类。为此，论文提出 **PAPAV** 框架，并用它分析多模态智能体、机器人系统及两者交叉形成的多模态具身智能体（MMEA）。
- 论文强调，物理环境中的行动更难预测、执行过程更受时间和身体约束，且结果可能无法被直接确认。因此，可靠性取决于完整闭环的协调，而不只是单项模型能力或最终任务成功率。

## 2. 方法论：PAPAV 能力框架

### 2.1 核心思想

PAPAV 按照任务循环中的**功能角色**定义能力，而非按照具体模块、模型或系统架构定义。一个模块可以承担多项能力，一项能力也可以分布在多个模块或工具中。

五项能力依次为：

1. **Perceive（感知）**：综合多模态观测和交互历史，形成与任务相关的状态信念。
2. **Anticipate（预判）**：在行动前，估计候选行动可能带来的状态变化、任务进展、风险等后果。
3. **Plan（规划）**：根据目标、当前信念、预测后果及可行性约束，选择并组织可执行的行动方案。
4. **Act（行动）**：将方案转换成接口操作或身体动作，并执行、报告进度。
5. **Verify（验证）**：依据行动后的证据判断预期结果是否实现，并输出继续、成功、重试、重规划或失败等判定。

### 2.2 任务闭环与关键形式化

论文将 MMEA 的任务循环概括为：

> 交互历史与目标 → 感知形成当前信念 → 预判行动后果 → 规划行动方案 → 执行并获得反馈 → 验证结果 → 回到下一轮决策。

其中，感知形成当前的任务信念；预判生成与候选行动相关的可能后果；规划选择行动及其顺序；行动产生环境变化和执行进度；验证则将行动后证据与任务预期进行比较，并将判定反馈给后续决策。

论文特别区分了两个容易混为一谈的环节：

- **Anticipate 与 Plan：**预判回答“某个候选行动可能导致什么”，规划回答“基于这些后果应选择什么行动”。
- **Act 与 Verify：**行动可报告执行进度或底层故障；验证则判断任务后置条件是否满足，不能仅以“动作已发出”或“控制器已停止”代替。

### 2.3 MMEA 的界定与物理可行性

论文将一个完整系统判定为 MMEA 时，要求其满足三类条件：

- 任务状态能够跨多轮物理执行持续保留，且行动会对物理环境产生可观察影响；
- 所声称的 PAPAV 能力能够输出信息，并影响后续任务级决策；
- 决策考虑了部署身体和环境带来的可行性、执行时间及控制约束。

物理行动还要满足几何、动力学、安全和时间限制。论文用可行行动集合表达这一点：在当前信念和具体身体条件下，只有满足几何可达、动力学限制、安全条件和执行时限的行动才可选。文中将这些约束概括为：

- **部分可观测性**
- **有限可模拟性**
- **不可逆性**
- **实时耦合**
- **结果难以验证**

这些约束使物理环境中的行动更难预先固定，也减少错误发生后的回退空间。

### 2.4 比较方式

论文分别从两条关系分析各项能力：

- **MMEA 与 MMA 的差异：**同一能力从数字环境转入物理交互后，证据获取、预测可信度、错误恢复和执行可见性如何改变。
- **MMEA 与 RS 的差异：**机器人系统已有的感知或控制能力，是否被纳入一个持续的、目标导向的任务闭环，并能影响任务级决策。

## 6. 主要结论与发现

- 在 64 项基准中，**Act 的显式评估最普遍**：
  - MMEA：10/10（100%）
  - MMA：16/23（70%）
  - RS：29/31（94%）
- **Anticipate 和 Verify 的显式评估明显不足：**
  - 只有 **5/64** 项基准显式评估 Anticipate；
  - 只有 **3/64** 项显式评估 Verify。
- **Plan 的评测在系统类别间差异较大：**
  - 7/10 项 MMEA 基准显式评估 Plan；
  - MMA 和 RS 基准没有显式评估 Plan 的案例，但不少基准以任务表现隐式涉及规划。
- **任务成功率无法充分诊断能力：**一个任务可能同时需要感知、规划和行动，但单一成功分数不能区分失败来自错误感知、错误预测、不当计划还是执行失误。
- **物理具身改变的不只是动作接口：**物理环境中的部分可观测、难模拟、难撤销、实时执行和结果不确定性，迫使智能体在交互过程中持续作出更多判断。
- 因此，论文主张将端到端任务评估与能力级、过程级评估结合，尤其加强对预判、验证、错误识别和恢复过程的测量。

## 7. 优点

- **提供跨领域共同坐标：**PAPAV 以功能而非架构划分能力，便于同时讨论多模态智能体、机器人系统和两者的交叉形态。
- **概念边界较清晰：**明确区分预判与规划、执行与验证，以及任务级规划与运动控制，减少能力统计中的过度归类。
- **不仅罗列工作，也分析评测缺口：**64 项基准的覆盖统计揭示了研究社区更容易测行动结果，却较少直接测预测与验证的问题。
- **重视物理条件：**把可观测性、可模拟性、可逆性、实时性和结果可验证性纳入统一讨论，解释了为什么数字智能体的经验不能简单移植到机器人操作。
- **提出可操作的评估方向：**建议记录能力输入输出、行动进度、验证证据来源、错误判定和恢复效果，而不只报告最终成功率。
- **明确系统分类与能力证据的区别：**某项工作为某个能力提供证据，并不自动意味着其完整系统就是 MMEA；这有助于避免概念泛化。
