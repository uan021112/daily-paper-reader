Abstract: Robot corrections allow people to adjust a robot’s behavior, but a sin-gle correction changes many features. Also, preferences about object attributes and relationships between objects cannot be expressed by moving the robot. We propose environment edits as a complementary form of feedback. The robot’s motion is held constant as the human edits the scene, so the only explanation for the edit is the moved object. We introduce Feature Learning from Environmental and Robot-Relational Edit Traces (FERRET), which learns preferences from both robot and environment corrections. We show that environment edits are able to disambiguate features and learn preferences that robot corrections alone cannot. 

# 1 Introduction 

Robots that work beside people should support the ability for the people in their surroundings to correct their behavior. When a robot does something wrong, a human can take the robot arm and move it, indicating how they would like the robot to behave and updating its objective [1, 2, 3]. Corrections like this are quick and they identify preferences about the robot’s motion, such as speed or posture, well. Feature-learning methods such as Feature Expansive Reward Learning (FERL) [4] extend this idea to features that the robot does not already know through asking the human to move the robot along a feature trace from where the feature is strongly expressed to where it is not. A correction is less clear about the world around the robot. When a person drags a robot arm away from a laptop on a table, the drag also moves the arm from the table edge, lengthens the path, and changes the arm’s posture. Each of these is a candidate explanation for what the human way trying to convey, and the learner can fit the correction while learning the wrong one. With several objects on the table, the ambiguity compounds as the correction does not say which object mattered, whether it mattered because of the type of object or state state of the objet, such as a cup being full of water or not. Some preferences are not able to be expressed by moving the robot in the first place. “Keep the cup away from the laptop” does not change when the robot moves, so no robot correction carries it. We ask what happens if the person corrects the environment instead. The robot’s motion is fixed and replayed while the person edits the scene until the current motion is acceptable. Interventions can happen on either the robot trajectory or the scene, where a scene intervention leaves every motion feature unchanged, so the edit can only be explained by the object that moved. These two com-ponents are not competitors, but compliments with scene edits capturing preferences about objects, their attributes, and their relations to one another while robot corrections capture preferences about

Additionally, a robot correction or a scene edit placed at the boundary of acceptability can reveal how much a preference is worth against the cost of moving. We propose FERRET (Feature Learning from Environmental and Robot-Relational Edit Traces), which learns preference features from either kind of trace. We explore two different model architec-tures, one with hand-built relations that capture relationships in the scene, and a graph model that learns important relations within its network. Our contributions include: 1) an exploration of envi-ronment edits as a means of human feedback for preference learning, 2) a proposal of two distinct model architectures for learning human preferences from both robot or environment feature traces, 3) an experimental comparison of these model architectures showing their strengths and weaknesses relative to each other and existing work. 

# 2 Related Work 

In this section, we discuss prior work related to learning from corrections. We discuss FERL [4] in greater detail since it provides the foundation for our work. 

2.1 Learning from Robot Trajectory Corrections 

Corrective demonstrations have long been a tool used to allow humans to express their preference over how a robot should behave in a given environment. Typically these demonstrations are given by physically correcting the robot’s behavior. Bajcsy et al. [1, 3] treat pushes on the robot as evidence of a human’s implicit reward function and learn weights online. Losey et al. [5] adds uncertainty over those weights. StROL [6] improves online learning by using stability analysis to make the learning dynamics more robust to noisy and suboptimal human feedback. Corrections have also been combined with demonstrations and comparative preference rankings in a single learner [7, 8]. All of these methods share the assumption that the human’s feedback is the displacement of the robot. We keep that option and add a second one in which the human displaces the scene instead. 

2.2 Ambiguity in Corrections 

A single correction changes many features. Bajcsy et al. [2] showed that updating only the feature that changed most reduced unintended learning. Bobu et al. [9] recognized that scenarios often occur when human corrections may attempt to convey features the robot is unaware of and propose a method for reasoning about how well human feedback is explained by known features. Our approach addresses ambiguity with respect to features related to the environment directly by enabling the user to use the objects to express their preference. Because environment edits hold robot motion fixed, the only explanation for the feature is the object that moved. 

2.3 Feature Expansive Reward Learning 

Feature Expansive Reward Learning (FERL) [4] proposes an approach to learning new features pre-viously unknown to the robot using human feedback. Instead of asking for full task demonstrations, the human provides a few feature traces , robot trajectories that move from areas of high feature expression to low feature expression. For example, to demonstrate that the robot should not move over a laptop, the human may provide feature traces that start over the laptop and move away. Given a set of feature traces, a neural network learns the feature using a loss based on a Bradley-Terry preference model that encourages feature values to decrease monotonically along each trace and starting and ending feature values for each trace to be indistinguishable. Using feature traces allows FERL to learn more generalizable rewards with small amounts of human data. Our method builds off of FERL and adds support for feature traces consisting of moving objects in the environment.

3.2 Learning from Environmental and Robot Edits 

The feature traces used in FERL [4] consist of the robot state and the x, y, z positions of objects in the scene. We augment this with additional inputs and explore two different models for reward learning. One, our relational model , is a set encoder that operates on end effector-object relation vectors. The other, our graph model , is a graph neural network, which uses a scene graph, that moves relational computation into the network rather than relying on hand-designed model inputs. 

3.2.1 Relational Model 

The relational model represents each state as a set of end effector-object relations rather than a single state vector as in FERL [4]. For every object, o ∈ O , in the scene we compute a relation vector ro(x)

consisting of the end effector’s position relative to the object, its distance to the object’s center, its signed distance to the object’s footprint, the object’s attribute bits and type, and the attributes of any object being carried by the robot. Attribute bits indicate, e.g., if the object is open, fragile, or hot. The object type is given by a one-hot vector with options like laptop, cup, and vase. We manually specify these values; however, this could be extended to use object embeddings [11]. A shared three-layer MLP, gθ , scores each relation independently. 3.2.2 Graph Model 

The graph model removes the hand-built relation vector and computes relations inside the network. Each state is a scene graph with one node for the end effector, one node per object center containing the object’s attribute bits and type, and eight corner nodes per object at the vertices of its foot-print. Node embeddings are initialized from the type and attributes. Object position is incorporated through edge features, which consist of the relative position between two nodes and a log-scaled dis-tance, which, like the relational model, makes the feature permutation-invariant and agnostic to the number of objects. Edges run from each corner node to its object center, between object centers, and from every node to the end effector. Each message passing round computes a message from the two endpoint embeddings and the edge attributes, aggregrates incoming messages with attention weights normalized per destination node, and applies a residual update. The end effector embedding is then input to an MLP and passed through the same softplus and min/max scaling as the relational model. We consider two variants of the graph model which differ in how the relative position on each edge is scaled and in the number of message passing rounds. The Graph model scales each relative position by a fixed value and runs two rounds. The SoftGraph model divides each relative position by a fixed amount plus the distance itself, so the displacement is approximately preserved near the object but is bounded by one and reduces to a unit vector when far away. SoftGraph runs one message passing round. The Graph model keeps the full amplitude of the displacement, which the network needs to train reliably in a compact workspace, but it lets larger or distant objects dominate the edge inputs. The second round of message passing lets object interact before the end effector reads them. Alternatively, SoftGraph’s soft scaling bounds every edge input by one, so no object can dominate by size or distance, making it less prone to taking a large object such as the table as a proxy for absolute position, at the cost of a weaker signal. The single round of message passing limits it to pairwise reasoning. Relative to the relational model, both graph model variants learn the feature from raw geometry with no hand-computed relation, and the object-object edges can express interactions between objects that a pairwise model cannot. However, the ability to mix any object’s geometry into the feature can make them less robust than the relational model’s hand-built relations.

4.2 Learning Object Proximity Features 

Figure 2 shows the ground truth and an example of FERL’s learned features using both robot and environment feature traces over the arm’s reachable space, projected to 2D. Figure 3 shows the MSE, PR-AUC, and Spearman correlation. From robot feature traces, all models converge to learning the feature, though the Graph model requires more data to achieve this. Considering environmental traces, FERL’s input does not contain enough information about the scene to learn the feature values; however, the PR-AUC and Spearman correlation support that it is able to learn small regions of higher feature values directly over the laptop. The Graph and SoftGraph models learn a much wider area of high feature expression than the ground truth. The Relational model is the only one that learns a consistent feature model between robot and environmental edits. 

4.3 Disambiguating Spurious Correlations 

Figure 4 shows the ground truth and an example of the Relational model’s learned features for the ambiguous scenario. Figure 5 shows the MSE, PR-AUC, and Spearman correlation. From the robot corrections, no model was able to learn that the feature related to the laptop itself and all learned high feature expression near the initial position of the laptop and the cup. Using environment traces, which moved the laptop away, the Relational model is able to learn a feature similar to the ground truth. The graph models again, similar to the previous scenario, learned wider areas of high feature expression than the ground truth. FERL was unable to associate the feature with the laptop. 

4.4 Attribute-Specific Features 

Figure 6 shows the ground truth for the open cup condition of avoiding the laptop when carrying an open cup and not a closed cup. The ground truth for the closed condition is uniform over the space. Figure 7 shows the MSE for both conditions and PR-AUC and Spearman correlation for the open condition. For this, we modified each model to support ’no preference’ traces where the loss function encourages each state in the trace to have an equal feature value. We provided robot feature traces while carrying an open cup and an equal number of ’no preference’ traces while carrying a closed cup. FERL does not take object attributes and learns the same feature for both conditions. The Relational, Graph, and SoftGraph models learn similar features for the open and closed conditions, with the Graph and SoftGraph models recovering close to zero error on the closed condition. This may indicate that graph models are able to better learn feature dependence on object attributes. 

# 5 Conclusion 

We introduce environment edits as a corrective signal for reward learning and present FERRET, which learns features from both robot and environment traces. We show that FERL is unable to learn features that require information from environment traces to disambiguate spurious correlations. We explore two different architectures for implementing FERRET, a relational model and two variants of a graph model. Our experiments show that the Relational model’s hand-built input features make it consistent across trace types, while the graph models learn from the scene geometry itself and are better able to capture attribute dependent preferences but are prone to over-wide feature expression. Considering future work, we plan to explore replacing hand-specified attributes with learned object embeddings, using boundary-of-acceptability edits to recover feature weights, and conduct a user study to explore how people naturally choose between correcting the robot and correcting the scene. 6Acknowledgments
