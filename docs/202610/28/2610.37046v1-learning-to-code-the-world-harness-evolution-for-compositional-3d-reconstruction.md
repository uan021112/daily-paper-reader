## 摘要
从真实图像重建可编辑且具有组合性的 3D 场景，需要对几何形状、物体结构和空间关系进行联合推理。我们提出 SceneEvolve，这是一个将 3D 场景表示为可执行代码，并通过演化一个小型开源智能体周围的 harness 来改进重建效果的框架。SceneEvolve 将 SceneAct 与 SceneHarness-RSI 相结合：前者是一种组合式语义动作接口，基于参数化基本图元、层次化组合和语义空间关系构建；后者利用更强大的教师智能体，根据开发集重建结果提供的反馈，迭代演化 harness。在整个 harness 演化过程中，模型参数、动作语义和执行后端均保持固定。最终得到的 harness 提供了一套可复用的重建流程，使小型开源模型无需更新参数或教师协助，即可重建未见过的场景。在两个同领域数据集和一个跨领域数据集上，与基础模型相比，采用相对紧凑的 Qwen3.8-27B 模型的 SceneEvolve 在所有四项评估重建指标上均有提升，同时将平均推理时间降低了 47.0%。更值得注意的是，尽管依赖的模型规模小得多，SceneEvolve 的重建质量仍比大型专有模型 GPT-5.6-Sol 高出 32.3%，同时将平均等效部署成本降低了 59.8%。此外，使用 Qwen3.8-27B 演化得到的 harness 也能泛化至 Kimi-K3，其重建性能与 GPT-6-Astra 相当。项目主页：https://haoyu-agent.github.io/SceneEvolve。

## Abstract
Reconstructing editable and compositional 3D scenes from a real image requires jointly reasoning about geometry, object structure, and spatial relationships. We introduce SceneEvolve, a framework that represents 3D scenes as executable code and improves reconstruction by evolving the harness around a small open-source agent. SceneEvolve combines SceneAct, a compositional semantic action interface built on parameterized primitives, hierarchical composition, and semantic spatial relations, with SceneHarness-RSI, which leverages a stronger teacher agent to iteratively evolve the harness using feedback from development-set reconstructions. Throughout harness evolution, the model parameters, action semantics, and execution backend remain fixed. The resulting harness provides a reusable reconstruction procedure that enables the small open-source model to reconstruct unseen scenes without parameter updates or teacher assistance. Across two in-domain datasets and one out-of-domain dataset, SceneEvolve with the comparatively compact Qwen3.8-27B model improves all four evaluated reconstruction metrics while reducing mean inference time by 47.0% relative to the base model. More notably, despite relying on a substantially smaller model, SceneEvolve achieves 32.3% higher reconstruction quality than the large proprietary GPT-5.6-Sol model, while reducing mean equivalent deployment cost by 59.8%. Furthermore, the harness evolved using Qwen3.8-27B also generalizes to Kimi-K3, achieving comparable reconstruction performance to GPT-6-Astra. The project page is https://haoyu-agent.github.io/SceneEvolve.

## 1. 核心问题与整体含义

- **研究问题：**如何从单张真实室内图像重建出可编辑、具有组合结构的 3D 场景，同时恢复场景几何、物体组成、空间关系、外观及相机视角。
- **研究动机：**直接让多模态模型生成 Blender 代码，往往难以同时处理精确几何、物体层级和空间布局；反复渲染、检查和修改又会增加推理时间与成本。大型专有模型可能有较强能力，但部署成本较高。
- **核心主张：**提升重建能力不一定要更新模型参数，也可以优化模型周边的 **harness**——包括指令、工具接口、执行流程和可复用技能。论文提出 SceneEvolve，用结构化的场景操作接口降低代码生成难度，再以开发集反馈演化重建流程。演化完成后，固定 harness 可在未见场景上运行，无需教师模型参与。

## 2. 方法论

### 2.1 SceneAct：将场景意图转化为结构化操作

SceneAct 是连接高层场景理解与 Blender 执行的语义接口，主要包含三类抽象：

- **参数化几何图元：**用预设图元（如 Box、Cylinder、Curve）及其几何、外观参数表示物体部件，避免直接操作网格顶点和面。
- **层次化组合：**以 `Scene → Asset → Part → Primitive` 组织场景。场景管理资产，资产由语义部件组成，部件再由几何图元构成，便于模块化构建与局部修改。
- **语义空间关系：**通过 `under`、`attached to`、`align(...)`、`distribute(...)` 等关系描述布局，再由解释器依据几何特征、锚点和参考系计算具体变换。例如，可要求桌腿位于桌面下方并对齐桌角，而不必分别猜测每条桌腿的精确坐标。

总体而言，SceneAct 将任务从低层几何编程转为选择图元、设定参数、组织部件并表达空间关系。

### 2.2 SceneHarness-RSI：教师引导的 Harness 演化

论文将 harness 的优化形式化为一个带开发集评估的候选搜索过程：

1. 从初始 harness \(H_0\) 开始，冻结学生模型、SceneAct 操作语义及 Blender 执行后端。
2. 学生模型在开发集上执行重建，产生场景代码、渲染结果和执行轨迹。
3. 教师模型分析这些证据，提出若干 harness 修改候选，例如改进诊断逻辑、工具处理或可复用的操作流程。
4. 同一冻结学生在相同协议下评估候选；只有当候选开发集分数严格高于当前保留版本时才予以保留。
5. 重复“提出—执行—评估—保留”，并将历史候选、得分及执行轨迹存入档案，供后续提案参考。最终冻结选出的 harness，用于测试集和跨数据集评估。

开发集综合分数 \(Q(H)\) 由 SSIM、反向 LPIPS（\(1-LPIPS\)）和映射到 \([0,1]\) 的 DINOv2 相似度取平均。按论文公式，它是在开发集图像上的逐样本均值。该保留规则保证**已记录的开发集分数不下降**，但不保证未见数据上的表现也单调提升。

## 6. 主要结论与发现

- 在学生模型、动作语义和执行后端固定的条件下，仅通过结构化接口和 harness 演化，可以改善小模型的场景重建结果。
- 相对基础 Qwen3.8-27B，SceneEvolve 在作者报告的平均指标上提升重建质量，同时将推理时间降低约 47%，部署成本降低约 20.5%。
- 在论文选定的对照条件下，SceneEvolve 的平均 SSIM 高于 GPT-5.6-Sol none 配置；同时论文报告部署成本低 59.8%。但这不代表它在所有指标、所有推理强度下都优于 GPT-5.6-Sol 或 GPT-6-Astra。
- 从 Qwen3.8-27B 演化出的 harness 迁移到 Kimi-K3 后，三个数据集上的表格结果均显示相对 Kimi 基线有改善，说明其中部分流程具有跨模型复用潜力。
- 论文也承认，系统并未稳定超越 GPT-6-Astra 等强模型；改进的是任务执行流程，而非底层模型本身的能力。

## 7. 优点

- **问题定位有价值：**将重建效果与智能体执行流程联系起来，研究模型参数之外的系统级改进路径。
- **接口设计清晰：**参数化图元、层级结构和语义空间关系共同降低了低层几何代码生成负担，也保留了场景的可编辑性与组成结构。
- **优化过程可检验：**候选 harness 由同一冻结学生执行，并在共同协议下评估；严格保留规则使开发集得分记录可追踪。
- **泛化测试有所覆盖：**不仅在两个同领域数据集测试，也测试域外数据与跨模型迁移，降低了结论仅依赖单一数据集或单一骨干模型的风险。
- **同时报告效率与成本：**不仅展示图像质量指标，也考察推理时间和部署成本，并通过消融分析两项主要组件的作用。

## 8. 不足与局限

- **开发集反馈可能导致适配偏差：**反复用开发集反馈筛选 harness，仍有过拟合开发场景分布的风险；仅有 20 个域外场景，尚不足以证明广泛的真实场景泛化能力。
- **3D 质量评价不够直接：**主要指标针对渲染图像，而论文强调的是可编辑、组合式 3D 重建；缺少几何精度、资产结构正确性、关系准确性及可编辑性等直接量化评估。
- **效率结论的边界需明确：**单场景推理更快、部署成本更低，并不意味着包含教师调用和数十轮开发搜索的总生命周期成本更低；相关账目未报告。
- **与强模型比较存在系统配置差异：**演化后的完整工作流与零样本基线并非同等程度的任务适配，结论更适合解释为“该方法构成的系统在特定设置下有竞争力”，而非单纯模型排名。
- **推理流程描述不完全统一：**论文强调减少反复渲染修改，但附录仍描述迭代执行与修复；若迭代轮数影响质量和时间，需更明确报告其测试阶段使用方式与预算。
- **实验统计报告有限：**未见显著性检验、重复实验方差、完整 API 成本或演化时长；场景抽样规模也较小。
- **能力上限仍受基础模型约束：**harness 优化能改善模型如何规划、构建和执行，却不能直接弥补模型视觉理解与空间推理能力的根本限制。
