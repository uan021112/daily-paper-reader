ABSTRACT
Reconstructing editable and compositional 3D scenes from a real image requires
jointly reasoning about geometry, object structure, and spatial relationships. We
introduce SCENEEVOLVE, a framework that represents 3D scenes as executable
code and improves reconstruction by evolving the harness around a small open-
source agent. SCENEEVOLVE combines SCENEACT, a compositional semantic
action interface built on parameterized primitives, hierarchical composition, and
semantic spatial relations, with SCENEHARNESS-RSI, which leverages a stronger
teacher agent to iteratively evolve the harness using feedback from development-
set reconstructions. Throughout harness evolution, the model parameters, action
semantics, and execution backend remain fixed. The resulting harness provides a
reusable reconstruction procedure that enables the small open-source model to re-
construct unseen scenes without parameter updates or teacher assistance. Across
two in-domain datasets and one out-of-domain dataset, SCENEEVOLVE with the
comparatively compact Qwen3.8-27B model improves all four evaluated recon-
struction metrics while reducing mean inference time by 47.0% relative to the
base model. More notably, despite relying on a substantially smaller model, SCE-
NEEVOLVE achieves 32.3% higher reconstruction quality than the large propri-
etary GPT-5.6-Sol model, while reducing mean equivalent deployment cost by
59.8%. Furthermore, the harness evolved using Qwen3.8-27B also generalizes to
Kimi-K3, achieving comparable reconstruction performance to GPT-6-Astra. The
project page is https://haoyu-agent.github.io/SceneEvolve.

INTRODUCTION
Compositional 3D scene reconstruction enables interactive and editable representations of real-
world environments, with applications in robotics, embodied AI, AR/VR, and digital content cre-
ation (Ma et al., 2026; Wang et al., 2026; Yeh et al., 2022). Given a single image of an indoor
environment, the goal is to reconstruct an editable, compositional 3D scene that captures its geome-
try, constituent objects, spatial layout, and lighting (Ma et al., 2026; Yeh et al., 2022).
Existing approaches address this problem through several strategies. Procedural and generative
methods synthesize diverse 3D environments (Raistrick et al., 2024; Yang et al., 2024), while multi-
stage reconstruction pipelines divide the task into scene understanding, asset generation, and object
placement (Ma et al., 2026). More recently, code-based agents have represented scenes as executable
programs, enabling explicit manipulation of objects and spatial relations (Yin et al., 2026; Wang
et al., 2026). Despite these advances, reconstructing a specific real-world scene with high fidelity
often requires carefully engineered intermediate stages (Ma et al., 2026; Yeh et al., 2022) or repeated
render-and-refine iterations (Yin et al., 2026; Huang et al., 2024).
Frontier models such as GPT-6-Astra (OpenAI, 2026b) suggest a more direct approach: generating
editable 3D scene programs from a single image with limited iterative refinement. However, their
deployment costs motivate us to investigate whether a substantially smaller open-source model can
achieve comparable image-to-3D programming capabilities through harness design rather than pa-
rameter updates (Khattab et al., 2024; Agrawal et al., 2026a). Our goal is to enable direct scene-code
generation while reducing reliance on costly render-and-refine loops.
Achieving this goal presents two main challenges. First, compact models have limited visual and
spatial reasoning capabilities, making it difficult to infer coherent 3D structures and translate visual
observations into executable scene representations. Second, effective reconstruction also depends on
the external harness: the instructions, tools, and control logic that govern how the model observes,
plans, constructs, and executes a scene program (Yin et al., 2026; Khattab et al., 2024). Addressing
these challenges requires both an interface that reduces the demands on geometric reasoning and a
reusable procedure that guides reconstruction.
To address these challenges, we introduce SCENEEVOLVE, as shown in Figure 1, a framework
that combines a compositional scene interface, SCENEACT, with a teacher-guided harness evolution
framework, SCENEHARNESS-RSI. SCENEACT translates high-level scene intent into executable
operations through parameterized geometric primitives, hierarchical object composition, and se-
mantic spatial relations. These abstractions reduce the need for low-level geometric programming
while preserving explicit scene structure. Building on this interface, SCENEHARNESS-RSI uses a
stronger teacher model to analyze the frozen student’s development-set reconstructions, execution
traces, and evaluation feedback, then propose revisions to the shared reconstruction harness. Can-
didate harnesses are evaluated under a common execution budget, and revisions are retained when
they improve the development score. Throughout this process, the student parameters, action se-
mantics, and execution backend remain fixed. The optimization target is the reusable reconstruction
procedure, which is subsequently frozen and deployed on unseen scenes without teacher assistance.
Our contributions are summarized as follows:
• We formulate compositional 3D scene reconstruction as an executable harness-optimization
problem, targeting direct code generation without parameter updates or repeated iterations.
• We introduce SCENEACT, a compositional interface that maps scene intent to executable 3D
scene code using parameterized primitives, hierarchical composition, and semantic spatial
relations, providing explicit control over object geometry and scene structure.
• We propose SCENEHARNESS-RSI, a teacher-guided recursive evolution method for opti-
mizing reusable reconstruction harnesses. Teacher guidance is used only during evolution,
allowing the resulting harnesses to generalize to unseen scenes without teacher assistance.
• Across in-domain and out-of-domain datasets, SCENEEVOLVE with Qwen3.8-27B outper-
forms GPT-5.6-Sol, reducing cost by 59.8% and inference time by 47.0% relative to the
baseline. The evolved harness also transfers to Kimi-K3, achieving results competitive with
GPT-6-Astra and demonstrating its transferability across different backbone models.

RELATED WORK
3D Generation for Compositional 3D Scene Reconstruction.
Single-image reconstruction and
generative models recover object geometry and appearance (Hong et al., 2024; Xu et al., 2024;
Xiang et al., 2025), while scene-level methods model object layouts and relations using semantic
priors (Lin & Mu, 2024; Lin et al., 2025) or jointly predict multiple objects and their spatial config-
urations (Huang et al., 2025; Meng et al., 2026). SCENEACT unifies object construction and scene
composition in an executable program with primitives and spatial operators.
Multi-stage Pipelines for Compositional 3D Scene Reconstruction.
Compositional reconstruc-
tion represents object geometry and scene layout as separately editable components. Prior work
aligns CAD models or jointly estimates layout, poses, and geometry (Izadinia et al., 2017; Nie et al.,
2020), with inverse rendering further recovering materials and lighting (Yeh et al., 2022). Recent
methods combine single-image scene analysis, object generation, and spatial refinement (Ardelean
et al., 2025; Ma et al., 2026; Zhang et al., 2026b), leverage multi-view evidence for assembly (Xia
et al., 2026; Qin et al., 2026), or jointly generate object geometry and spatial configurations (Huang
et al., 2025; Meng et al., 2026). SCENEEVOLVE instead realizes object-centric reconstruction as an
executable scene program built from parameterized primitives, part hierarchies, and spatial relations,
enabling a frozen agent to construct and edit the scene.
Programmatic Coding Agents for Compositional 3D Scene Reconstruction.
Procedural and
language-guided generators use reusable assets and spatial constraints for controllable scene syn-
thesis (Deitke et al., 2022; Raistrick et al., 2024; Yang et al., 2024). Related representations encode
hierarchical assemblies as executable programs (Jones et al., 2020) or predict structured scene de-
scriptions from visual or point-cloud observations (Avetisyan et al., 2024; Mao et al., 2025). Visual
coding agents further generate and refine graphics programs through rendered feedback, reusable
libraries, and execution-guided iteration (Hu et al., 2024; Huang et al., 2024; Yin et al., 2026; Yang
et al., 2026; Wang et al., 2026). SCENEACT exposes a fixed set of semantic construction operators,
while SCENEHARNESS-RSI optimizes the reusable procedure.

METHODS
3.1
OVERVIEW
We propose SCENEEVOLVE, a framework for compositional image-to-3D reconstruction of in-
door scenes, as illustrated in Figure 2.
The framework comprises two components: SCENE-
ACT, a compact semantic interface that maps high-level scene intent to executable actions, and
SCENEHARNESS-RSI, a teacher-guided procedure that ens the reconstruction harness using end-
to-end reconstruction feedback. SCENEACT defines the executable interface through which the
frozen student agent reconstructs 3D scenes. SCENEHARNESS-RSI iteratively refines the harness
through a propose–execute–evaluate–retain cycle to improve how the student uses SCENEACT while
keeping the student parameters fixed.
3.2
SCENEACT: A COMPACT SEMANTIC INTERFACE FROM INTENT TO ACTIONS
SCENEACT provides a compact semantic interface between high-level scene reasoning and low-
level Blender execution. It enables the student agent to use semantically meaningful actions that
are deterministically translated into executable Blender operations, reducing the need to directly
specify low-level geometric operations and numerical parameters. The action space comprises three
complementary abstractions: composable parameterized primitives, hierarchical composition, and
semantic spatial relations. Together, these abstractions support progressive scene construction from
local geometry to object structure and scene-level layout.

The primitive classes share a common interface for translation, rotation, and scaling, allowing their
instances to be composed into higher-level scene structures. For example, a tabletop can be repre-
sented by a thin Box, its supporting legs by Box or Cylinder instances, and a curved lamp arm by
a Curve. These primitives can then be transformed and assembled into semantic parts and assets.
This design expresses reconstruction as a sequence of compact, executable decisions and shifts the
student’s reasoning from low-level mesh programming to structured geometric construction. In this
way, the student’s geometric reasoning is reduced to two interpretable decisions: which primitive
best explains each visible part, and what geometric and appearance parameters characterize it?
Hierarchical Composition.
We organize the reconstructed scene using an explicit semantic hier-
archy implemented in the scene program. The Scene class manages a collection of assets through
interfaces such as scene.add_asset(...). The reusable Asset base class encapsulates object-level struc-
ture and provides asset.add_part(...) for composing semantic parts. Each Part is constructed from
one or more parameterized geometric primitives. This hierarchy separates scene-level composition,
object-level structure, and part-level geometry: the Scene supports adding, removing, transforming,
and duplicating complete assets, while each Asset controls the construction and refinement of its
internal parts. For example, a table asset may contain a tabletop and several legs, each constructed
independently from geometric primitives. This program structure supports modular construction
and localized editing while preserving a direct correspondence between visually identifiable entities
in the input image and their executable representations.
Semantic Spatial Relations.
SCENEACT specifies spatial structure through semantic relations,
reducing the need to predict explicit coordinates. This design is motivated by the observation that
VLMs are more reliable at inferring relations such as under, attached to, and facing than at pre-
dicting the precise 3D translations and rotations needed to realize them. Accordingly, each scene
4


element exposes geometric features with semantic meaning, including center, extent, support, an-
chor, and boundary, together with relational operators such as align(...) and distribute(...).
These operators encode spatial constraints relative to scene geometry. For example, four table legs
can be positioned below a tabletop and aligned with its corners without predicting their coordinates
independently. The SCENEACT interpreter resolves such relations into deterministic transformations
based on current geometry, reference frames, extents, and anchors. Since the constraints are defined
structurally rather than in fixed world coordinates, they can be re-evaluated after edits, allowing
dependent elements to update automatically. This separates relational reasoning from numerical
transformation computation, reducing direct coordinate prediction while preserving precision.
3.3
SCENEHARNESS-RSI: A TEACHER-GUIDED RECURSIVE HARNESS EVOLUTION
SCENEHARNESS-RSI improves the execution harness of a frozen student through teacher-guided
revisions. Starting from an initial harness H0, the student reconstructs development-set scenes
through SCENEACT, producing Blender programs, rendered outputs, and execution traces.
A
teacher uses this evidence to identify limitations of the current harness and propose targeted revi-
sions. The same frozen student then evaluates the revised harnesses under a fixed protocol, and only
revisions that improve the recorded development-set reconstruction score are retained. Repeating
this propose–execute–evaluate–retain cycle defines an outer-loop search over executable harnesses.

EXPERIMENTS
4.1
EXPERIMENTAL SETTINGS
Datasets.
We use three indoor scene datasets comprising 160 scenes in total: ScanNet (Dai et al.,
2017) and CA-1M (Lazarow et al., 2025) for in-domain development and evaluation, and ARK-
itScenes (Baruch et al., 2021) for out-of-domain evaluation. The resulting split consists of 100
development scenes, 40 in-domain test scenes, and 20 out-of-domain test scenes.
In-domain Datasets.
ScanNet (Dai et al., 2017) provides RGB-D sequences with camera poses,
reconstructed indoor geometry, and semantic annotations, while CA-1M (Lazarow et al., 2025) con-
tains handheld egocentric captures registered to high-quality laser scans with dense 3D object anno-
tations. From each dataset, we randomly sample 70 scenes and partition them at the scene level into
disjoint development and test sets of 50 and 20 scenes, respectively. All views and repeated captures
of the same physical scene are confined to a single split. The development sets are used for recursive
harness search, while the test sets are reserved exclusively for in-domain evaluation.
Out-of-domain Dataset.
ARKitScenes (Baruch et al., 2021) contains mobile RGB-D indoor cap-
tures with laser-scanned geometry and 3D object annotations. We randomly sample 20 scenes
for out-of-domain evaluation.
The harness developed on ScanNet (Dai et al., 2017) and CA-
1M (Lazarow et al., 2025) is transferred directly to these scenes with the student weights, harness
code, and inference configuration fixed. No ARKitScenes (Baruch et al., 2021) data or feedback are
used during harness development, enabling a clean evaluation of cross-dataset generalization.
Evaluation Metrics.
We evaluate all methods along three dimensions: reconstruction quality, in-
ference efficiency, and equivalent cost. Reconstruction quality is measured by PSNR (Wang &
Bovik, 2009), SSIM (Wang et al., 2004), LPIPS (Zhang et al., 2018), and DINOv2 similarity (Oquab

Baselines.
We benchmark proprietary multimodal models as zero-shot agents for compositional
image-to-3D scene reconstruction, without task-specific fine-tuning. Our baseline suite includes
GPT-5.6-Sol (OpenAI, 2026a) and GPT-6-Astra (OpenAI, 2026b), Claude-Opus-5 (Anthropic,
2026), and Gemini-Flash-3.8 (Google DeepMind, 2026). For models with configurable reasoning
effort, we evaluate all supported settings among none, low, medium, and high, treating each model–
effort pair as a distinct baseline configuration. We also evaluate Qwen3.8-27B (Qwen Team, 2026)
at xhigh, using the same model and reasoning configuration as the frozen student in our method. We
additionally use Kimi-K3 (Kimi Team, 2026) at high as a cross-model validation harness.
Implementation details.
We use Qwen3.8-27B (Qwen Team, 2026) at xhigh as the frozen student
and GPT-6-Astra (OpenAI, 2026b) at medium as the harness proposer, running K = 30 rounds
with M = 2 proposals each. Candidates are conditioned on archived development evidence and
evaluated on equally weighted ScanNet (Dai et al., 2017) and CA-1M (Lazarow et al., 2025) scenes,
with input frames selected by a space-aware frame sampling strategy following Spatial-MLLM (Wu
et al., 2025). The selected harness and inference configuration are frozen at test. All models are
accessed exclusively via API calls, without using additional third-party harnesses such as Codex,
Claude Code, or pi. To evaluate the cross-model transferability of the self-evolved harness, we
apply the harness evolved with Qwen3.8-27B directly to Kimi-K3 (Kimi Team, 2026) at high.

4.2
QUANTITATIVE RESULTS
4.2.1
COMPARISON WITH THE BASE MODEL
Reconstruction Quality.
As shown in Table 1, SCENEEVOLVE consistently outperforms
Qwen3.8-27B across all four reconstruction metrics and three datasets under fixed student weights
and reasoning effort. Averaged across datasets, DINOv2-S increases from 0.198 to 0.392, while
SSIM improves by 6.7%, LPIPS decreases by 6.1%, and PSNR increases by 0.118 dB; these gains
also transfer to the unseen ARKitScenes dataset without target-specific adaptation.
Inference Time.
As Figure 4 and Figure 5 illustrate, SCENEEVOLVE reduces mean per-scene
inference time by 37.5% on ScanNet, 55.1% on CA-1M, and 46.8% on ARKitScenes relative to the
base Qwen3.8-27B xhigh. Across the three datasets, mean inference time decreases from 1,510.7 to
800.2 seconds, a reduction of 47.0%, alongside improvements in all four reconstruction metrics.
Deployment cost.
As shown in Figure 4 and Figure 5, SCENEEVOLVE achieves lower deploy-
ment costs across datasets, reducing the mean equivalent deployment cost by 20.5% relative to the
Qwen3.8-27B xHigh baseline and by 22.7% on both ScanNet and CA-1M. Overall, SCENEEVOLVE
provides a more favorable trade-off between reconstruction quality, inference time, and cost.
Cross-Model Harness Transfer.
To evaluate the cross-model generalizability of harness evo-
lution, we directly transfer the harness evolved using Qwen3.8-27B to Kimi-K3 under the high
reasoning-effort setting, without any target-specific search, fine-tuning, or manual adaptation. As
shown in Table 1, the transferred harness consistently improves all four reconstruction metrics across
all three datasets compared with the Kimi-K3 baseline without the transferred harness. These results
demonstrate that harness evolution can discover reconstruction strategies that generalize beyond the
model used during the search, rather than merely exploiting model-specific behaviors.
4.2.2
COMPARISON WITH FRONTIER MODELS
Reconstruction Quality.
Qwen3.8-27B with SCENEEVOLVE outperforms GPT-5.6-Sol with none

We introduced SCENEEVOLVE, a framework for editable, compositional 3D scene reconstruction

EXPERIMENT DETAILS
A.1
DATASET DETAILS
To evaluate the effectiveness of SCENEEVOLVE, we conduct experiments on three representa-
tive indoor-scene datasets covering different capture settings: ScanNet (Dai et al., 2017), CA-
1M (Lazarow et al., 2025), and ARKitScenes (Baruch et al., 2021). ScanNet and CA-1M serve
as in-domain datasets for harness development and evaluation, while ARKitScenes is reserved for
out-of-domain evaluation. We use 160 scenes in total, comprising 100 development scenes, 40
in-domain test scenes, and 20 out-of-domain test scenes. All methods are evaluated on the same
held-out scenes under a consistent single-image reconstruction protocol. Input views are selected
using a space-aware frame sampling strategy following Spatial-MLLM (Wu et al., 2025). For each
in-domain dataset, all views and repeated captures of the same physical scene are kept within a
single split to prevent development–test overlap. Detailed descriptions are provided below.
• ScanNet. ScanNet (Dai et al., 2017) provides RGB-D sequences of indoor environments
with camera poses, reconstructed 3D geometry, and semantic annotations. We randomly
sample 70 scenes and divide them into 50 development scenes and 20 held-out in-domain
test scenes.
Its indoor layouts and object arrangements make it suitable for assessing
whether a reconstruction agent can recover coherent scene geometry, constituent objects,
and spatial relationships from a single image. The development split supplies reconstruc-
tion feedback for harness evolution, whereas the test split is used exclusively for evaluation.
• CA-1M. CA-1M (Lazarow et al., 2025) contains handheld egocentric indoor captures reg-
istered to high-quality laser scans, together with dense 3D object annotations. We randomly
sample 70 scenes, assigning 50 to harness development and 20 to held-out in-domain eval-
uation. Compared with ScanNet, its capture and annotation setting provides a complemen-
tary test of object-level geometry, relative proportions, and spatial composition. As with
ScanNet, only the development scenes are used to evaluate candidate harness revisions; the
held-out test scenes are not used during harness search.
• ARKitScenes. ARKitScenes (Baruch et al., 2021) consists of mobile RGB-D captures
of indoor environments with laser-scanned geometry and 3D object annotations. We ran-
domly sample 20 scenes and use them exclusively for out-of-domain evaluation. Unlike the
two in-domain datasets, ARKitScenes contributes no images or reconstruction feedback to
harness development. The student parameters, selected harness, and inference configu-
ration are transferred without modification, making this benchmark a test of whether the
reconstruction procedure generalizes to previously unseen data.

The proprietary models are evaluated as zero-shot agents for compositional image-to-3D scene re-
construction without task-specific fine-tuning. For models supporting configurable reasoning effort,

• Qwen3.8-27B. Qwen3.8-27B (Qwen Team, 2026) serves as the open-source backbone and
the primary base-model counterpart. We evaluate it at xhigh reasoning effort, matching the

changing the underlying student model parameters.
• Kimi-K3. Kimi-K3 (Kimi Team, 2026) is an open-weight multimodal model evaluated at

Specifically, we directly transfer the harness evolved with Qwen3.8-27B to Kimi-K3 with-
out additional harness evolution, model fine-tuning, or target-model-specific optimization.
We compare Kimi-K3 equipped with the transferred harness against its unevolved counter-
part under the same reasoning effort, reconstruction protocol, and execution budget. The

SCENEACT interface and execution backend remain unchanged throughout the evaluation.
This setting isolates the transferability of the learned reconstruction procedure across differ-

model can generalize to another without model-specific adaptation.

We evaluate its low, medium, and

• Claude-Opus-5. Claude-Opus-5 (Anthropic, 2026) is a proprietary multimodal counter-

assessment of reconstruction fidelity and inference resource requirements.
• Gemini-Flash-3.8. Gemini-Flash-3.8 (Google DeepMind, 2026) is another proprietary

We evaluate its low,

allowing us to examine the trade-offs among quality, inference time, and cost.

ADDITIONAL RELATED WORK
B.1
SELF-IMPROVING AGENTS AND HARNESS OPTIMIZATION
Self-improving agent systems leverage feedback from prior executions to iteratively refine the mech-
anisms that govern subsequent behavior. Existing approaches differ primarily in the components
they optimize and the forms of feedback they exploit.
Reflexion (Shinn et al., 2023) records
natural-language reflections in episodic memory to inform future decisions, whereas STOP (Ze-
likman et al., 2024) recursively improves an executable scaffold. A complementary line of work,
including TextGrad (Yuksekgonul et al., 2025), ProTeGi (Pryzant et al., 2023), GEPA (Agrawal
et al., 2026b), and Feedback Descent (Lee et al., 2025), optimizes textual components using natural-
language feedback. More recently, Meta-Harness (Lee et al., 2026) and Self-Harness (Zhang et al.,
2026a) extend the optimization target to agent source code, using execution outcomes to guide it-
erative code revisions. Their evaluations span diverse tasks: Meta-Harness considers classification,
mathematical reasoning, and terminal-based coding, while Self-Harness evaluates performance on
Terminal-Bench, SWE-bench, and AppWorld. Although these methods differ in their optimization
targets and feedback mechanisms, they share a common objective: improving agent performance
through iterative system-level refinement rather than relying exclusively on conventional model
training. SCENEEVOLVEextends this line of research to code-based 3D scene reconstruction, where
agent performance depends not only on the underlying model but also on the execution logic that
translates reconstruction objectives into executable code and rendered scenes.

HARNESS DESIGN AND EVOLUTION
D.1
INITIAL HARNESS
We use a minimal initial harness as the shared baseline for all models in our benchmark. For base-
line evaluation, every model is assessed under the same harness and prompt protocol to ensure
comparability. Each example is processed through a direct model call only; we do not use external
coding-agent harnesses or frameworks such as Codex, Claude Code, or Pi. The harness consists
exclusively of the system prompt and the user prompt shown below. It does not include MCP tools,
skills, an agent-loop architecture, memory, or other external tool-use or orchestration components.
For each example, the model receives a single textual prompt together with the reference image and
is expected to return a complete, executable Blender Python program. As specified in the system
prompt, file saving and rendering are handled by a separate local evaluation script rather than by an
agent framework. The exact prompts used in this baseline are provided below.
System Prompt
You are an expert in reconstructing indoor scenes from reference images using Blender Python.
Return only complete, executable Python code, with no explanations or Markdown. Accu-
rately recreate the scene using actual 3D geometry, materials, lighting, and a camera. Do not
use the input image as a background or substitute for 3D modeling. Explicitly set the active
scene camera. Handle scene modeling and configuration only. Do not save files or render the
scene, as these operations will be handled by a separate local script.
User Prompt
Reconstruct the indoor scene from the input image using Blender 3D modeling. Preserve the
original spatial layout, architectural structures, furniture, objects, proportions, positions, orien-
tations, and occlusion relationships. Strictly match the original camera viewpoint, perspective,
composition, and framing. Retain the original materials, colors, and textures. Do not redesign
the scene or invent off-frame content. The input image is <image>.
D.2
THE EVOLVED FINAL HARNESS
Planning Stage. Given the reference image and reconstruction instruction, the harness first ana-
lyzes the scene to identify visible architectural structures, furniture, and object instances, estimating
their geometry, proportions, appearance, camera viewpoint, and key spatial relationships, including
relative positioning and occlusion. Based on this analysis, it constructs a hierarchical scene plan that
organizes the scene into individual assets and their constituent parts, while specifying relevant object
attributes, spatial configurations, and inter-object relationships. The resulting plan is then serialized
into a structured JSON document that serves as a machine-readable intermediate representation for
downstream code generation. By explicitly encoding the scene hierarchy, object properties, and spa-
tial constraints, this document provides a clear and consistent specification for the subsequent code
generation stage. Throughout the planning process, the harness grounds its decisions in visible evi-
dence, treating uncertain or occluded regions conservatively and avoiding unsupported assumptions.
Code Executing Stage. The coding agent translates the scene plan into executable Blender Python
through SCENEACT interface. Parameterized primitives represent local geometry, the asset–part hi-
erarchy captures object structure, and semantic spatial operators express relations such as alignment,
distribution, support, and attachment. The harness encourages the agent to construct objects compo-
sitionally, reuse consistent reference frames, and specify the camera, materials, colors, and lighting
explicitly. This organization reduces reliance on independently guessed low-level coordinates and
makes it possible to localize later edits to particular objects or parts.
Inspect and Render Feedback. The harness evaluates the generated scene through iterative exe-
cution, rendering, and inspection. After executing the Blender script, the harness first checks for
syntax errors, runtime failures, and other execution issues. If the script runs successfully, the result-
ing scene is rendered from the target camera viewpoint and inspected against the reference image
and the structured scene plan. The inspection combines visual assessment with spatial validation: a

modifications to components that already satisfy the reconstruction requirements.

LIMITATION
SCENEEVOLVEprovides an effective approach to harness optimization, while leaving room for fur-
ther improvement. First, harness evolution incurs substantial computational costs due to repeated
teacher-guided analysis, candidate generation, scene reconstruction, rendering, and evaluation, high-
lighting a trade-off between harness quality and search efficiency. Second, harness optimization
improves task execution but does not directly enhance the underlying model’s capabilities, and the
evolved system does not consistently outperform strong models such as GPT-6-Astra. Future work
could jointly evolve RSI harnesses and adapt RSI models to improve reconstruction quality.
