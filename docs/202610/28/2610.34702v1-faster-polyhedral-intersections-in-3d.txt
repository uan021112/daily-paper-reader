Abstract 

The operation of intersecting two polyhedra, which can be reduced to clipping one polyhedron with a series of planes formed from another polyhedron, is central to intersection based mesh interpolation and material interface reconstruction. R3D is a robust library for such operation which implements the algorithm of Sugihara. In this paper, we present J3D, a new implementation of the clipping algorithm of Sugihara that provides substantial performance improvements over R3D. 

Keywords: Polyhedral clipping, Computational physics, Algorithms, Data structures 

# 1 Introduction 

In the implementation of fluid simulations, especially when shocks are involved, the Arbitrary La-grangian Eulerian (ALE) method is heavily relied upon to reliably simulate flows [3, 13]. At a high level, the ALE method operates as follows. First, the mesh is deformed with the fluid until it is no longer viable. Then, to continue the simulation, the fields of the deformed mesh are conservatively interpolated onto a higher quality mesh and the simulation continues. A commonly used method to conservatively interpolate the field values from a source mesh to a target mesh is intersection based remap [10]. In this procedure, each cell of the target mesh is intersected with cells of the source mesh, and the resulting moments of intersection are used as weights in the interpolation of source cell values onto the target cell. Intersecting two polyedra reduces to the problem of assuming that one of them is convex and intersecting the planes of the convex polyhedron with the other. Another operation commonly operation found in ALE simulations is material interface reconstruction [4, 9, 15, 11]. In interface reconstruction, the volume fractions and, possibly centroids, of materials in a cell must be used to recover the geometry of the interfaces between the materials. This is done by repeatedly clipping the polyhedron with a plane to find the optimal material geometry. As suggested from the descriptions of the two aforementioned procedures, intersecting a polyhedron with a plane is funda-mental. In fact, while polyhedral intersection is typically a very small algorithm within the context of a larger ALE method, it has significant performance impacts. This is exacerbated by the fact that as the mesh deforms in ALE, the faces of a polyhedron may no longer be planar. To resolve this, faces of a polyehedron are “facetized” which adds to the problem complexity. That is, the faces of one polyhedron are decomposed into triangular faces by adding a point in the center of each face and joining it with each of the edges making up the original face.

# 2 Background 

The landscape of algorithms to intersect two polyhedra is already rich. Existing algorithms offer vary-ing results in terms of asymptotic performance, floating point accuracy, and practicality. Algorithms such as [14, 8] while providing impressive asymptotic performance, are difficult to implement and are thus not considered for practical applications. On the other hand, algorithms that use a Binary Space Partitioning (BSP) Tree like [5] are numerically accurate and fast for very large geometries. However, they require the initialization of a BSP-tree which is an overhead we cant afford since our use cases require intersections to be called many times on polyhedra known to be relatively small. Ultimately, we settled on Sugihara’s clipping algorithm [18] which we also refer to as clip-n-cap. The algorithm is very simple and practical to implement. Moreover, to address robustness, the only floating point operations required are to determine if a vertex is on the positive or negative side of the plane. It is well known that differences in classification of a vertex as being in front or behind the plane in the Sugihara algorithm can result in a different topology for the polyhedron. In particular, when clipping non-convex polyhedra, these errors can yield a resulting graph with small independent polyhedral pieces with possibly negative volumes. If the only goal is to extract out the moments of intersection as needed in conservative remapping, these small positive or negative poyhedral fragments do not make a significant difference. On the other hand, in the case of interface reconstruction, if one needs to recover the polyhedron topology for further reuse, then one needs to do some cleanup of the small fragments using a tolerance which only needs to be done once after clipping with all the planes is done. In the Sugihara clipping algorithm [18], the polyhedron is represented as a graph G = ( V, E ) where 

V is the set of vertices and E is the set of edges. When a plane “clips” G, the vertices are partitioned into two sets V1 and V2. V1 is the set of vertices on the positive side of the plane and V2 is the set of points on the negative side of the plane. We reconstruct the polyhedron on the positive side of the plane as follows. 1. Each edge with one endpoint in V1 and one endpoint in V2 is split in two by a new vertex generated at the intersection of the edge and the clipping plane. 2. Next, a cycle separating V1 and V2 is generated by connecting the aforementioned new vertices. This cycle represents the capping face. 23. Finally, the vertices in V2 and their incident edges are removed from the graph. With the Sugihara algorithm in mind, we will now introduce two common representations of a polyhedron. A boundary representation (BREP) describes a hierarchy between a cell, its faces, and the vertices on each face ordered in the outward normal direction to the face. # 3 R3D 

R3D is a C library which was introduced to conduct conservative voxelization and later refined at Los Alamos National Laboratory for more general polyhedral clipping [17, 16]. Here, we describe some of the details of the R3D implementation of clip-n-cap and their effect on performance. R3D represents its polyhedra as a graph but imposes an additional restriction that every node has a valence of three, which is not present in the original Sugihara paper. This restriction was introduced to enhance vectorization of computations but handicaps the algorithm in other ways. Most notably, if a polyhedron has vertices with a valence greater than three, the algorithm has to duplicate vertices and create edges to initialize the internal representation (Figure 4). # 4 J3D 

We present a revised implementation of the Sugihara clip-n-cap algorithm that aims to remove some of the restrictions of R3D with an eye to improved performance on conventional CPUs and porting the algorithm to modern GPUs. We introduce new data structures suited for this purpose and describe new algorithms to take advantage of these constructs. Given a face from a BREP and the ordered set of nodes forming that face, a directed edge is a pair of sequential nodes. From this, the data structures we introduce are two maps P and N . These maps serve the dual purpose of cycling through the vertices of a face as well a cycling through the neighbors of a graph vertex, both in an ordered manner. P maps a directed edge to the vertex preceding it in the face walk and N maps a directed edge to the vertex succeeding it in the face walk. Each of these maps are represented as a |V | × | V | array of vertex indices where V is the set of vertices in the polyhedron. 1 234

## 4.1 Graph Initialization 

For initializing the graph from a BREP, we also define a map S : V → V which for a vertex v simply returns a neighbor of v. This map, along with P, is used to initialize the graph representation. First, the algorithm to initialize S and P is as follows. 

Algorithm 1 Initialization of the Maps S and P

Require: BREP representation B.

Ensure: S and P are initialized. 

function InitializationSetup (B, S, P)

prev ← 0

curr ← 0

next ← 0

for f ∈ B.f aces do for i = 1 : f.num vertices do 

prev ← f.vertices [( i − 1) mod f.num vertices ]

curr ← f.vertices [i]

next ← f.vertices [( i + 1) mod f.num vertices ]

S[curr ] ← next 

P[curr ][ next ] ← prev 

end for end for end function 

From here, the algorithm to initialize the graph with counter-clockwise vertex neighbor ordering is as follows. 6Algorithm 2 Counter-Clockwise Neighbors Initialization 

Require: P, S.

Ensure: Graph G with counter-clockwise neighbor ordering. 

function NeighborsInitialization (G, P, S)

for v ∈ G.vertices do 

G.neighbors [v].append (S(v)) 

vprev ← P (v, S(v)) 

while vprev ̸ = S(v) do 

G.neighbors [v].append (vprev )

vprev ← P (v, v prev )

end while end for end function 

## 4.2 Clip-N-Cap 

Before describing the clip-n-cap implementation in J3D, let’s recall some details of the Sugihara algorithm from section 2. When a plane clips a graph G = ( V, E ), V is partitioned into two sets V1

and V2. V1 is the set of vertices on the positive side of the plane and V2 is the set of vertices on the negative side of the plane. Our goal is to reconstruct the polyhedron on the positive side of the plane. First, new vertices are generated on each edge connecting a vertex from V1 to a vertex from 

V2. Now a detail which is important to mention is that after this step, clip-n-cap in R3D and J3D is implemented such that for each new vertex, the edge connecting it to a vertex in V2 is deleted and the edge connecting it to a vertex in V1 is kept. Moreover, at this point, each new vertex has a singular neighbor which is a vertex in V1. This singular neighbor is the first element in the list of neighbors of a new vertex. Before being able to execute clip-n-cap efficiently, we need to initialize N so we can walk from one new vertex to the next efficiently along a path of vertices in V1. So, we will initialize N

by visiting each neighbor of each vertex in V1. We will take advantage of the fact that the neighbors of each vertex in V1 are ordered counter clockwise relative to the exterior of the polyhedron. 

Algorithm 3 Initialization of the Map N After Initializing V1, V2, and New Vertices 

Require: Graph G with a subset V1 of the vertices with connectivity to the new vertices. 

Ensure: N is initialized. 

function CapSetup (G)

prev ← 0

next ← 0

for v ∈ V1 do for i = 1 : G.num neighbors [v] do 

prev ← v.neighbors [i]

next ← v.neighbors [( i − 1) mod v.num neighbors ]

N [prev ][ v] ← next 

end for end for end function 

Next, the algorithm to execute step two in Sugihara’s clip-n-cap algorithm with the help of N is as follows. 7Algorithm 4 Generating a Cycle Separating V1 and V2

Require: N

Require: Graph G has a set of new vertices G.new vertices ⊂ V s.t. each new vertex has a singular neighbor in V1.

Ensure: The cycle of new vertices separating V1 and V2 is generated. 

function Cap (G, N )

for vnew ∈ G.new vertices do 

prev ← vnew 

curr ← prev.neighbors [0] 

next ← N (prev, curr )

while next / ∈ G.new vertices do 

prev ← curr curr ← next next ← N (prev, curr )

end while 

vnew .neighbors [1] ← next next.neighbors [2] ← vnew 

end for end function 

## 4.3 BREP Traversal for Moment Calculation 

The map N will also prove necessary for efficient moments computation. To compute the volume or the zeroth order moment, for example, we traverse each face and construct triangular facets from a starting vertex on the face. Like in Figure 2, we begin with a starting vertex A and the next two vertices B and C around the face of a polyhedron to form the first triangular facet. So, in terms of the map N we defined earlier, we have that N (A, B ) = C and the next facet we construct will be defined by the points A, C, and N (B, C ) and so on. This high level idea is leveraged by J3D to efficiently compute the moments of a polyhedron. Before computing moments however, we need to initialize the map N as follows. This algorithm is almost identical to how we initialized N before clip-n-cap except we consider all vertices in the polyhedron rather than just the vertices in V1.

Algorithm 5 Initialization of the Map N

Require: Graph G representing the polyhedron with neighbors around each vertex ordered ccw relative to the exterior 

Ensure: N is initialized. 

function VolumeComputationSetup (G)

prev ← 0

next ← 0

for v ∈ G.vertices do for i = 1 : G.num neighbors [v] do 

prev ← v.neighbors [i]

next ← v.neighbors [( i − 1) mod v.num neighbors ]

N [prev ][ v] ← next 

end for end for end function

## 4.4 J3D Implementation 

J3D is a C library which only uses static allocations for its working buffers. However, since we have no restrictions on the valence of nodes, J3D has two compile time variables J3D MAX VERTS and 

J3D MAX EDGES to statically size its working buffers. Since the graph representing a polyhedra is always isomorphic to a planar graph and is therefore sparse, J3D MAX EDGES can be set to a positive integer multiple of J3D MAX VERTS . The adjacency of the graph is stored in a compressed sparse rows (CSR) array [7]. That is, rather than storing the neighbors of an vertex in an individual array for each vertex, neighbors are stored in a contiguous chunk of a larger array and a separate row index array is used to index into the correct chunk of a vertex. 9typedef struct { double verts[J3D_MAX_VERTS][3]; /*!< Vertex positions. */ int dir_edges[2 * J3D_MAX_EDGES]; /*!< CSR array of the graph adjacency. */ int indices[J3D_MAX_VERTS + 1]; /*!< Offsets for the CSR array. */ int num_dir_edges; /*!< Number of directed edges. */ int num_verts; /*!< Number of vertices. */ } j3d_poly;

## 4.5 Additional Implementation Improvements 

In moments calculation, J3D explicitly computes the zeroth, first, second, and third order moments and falls back to the recursive method in [12] for higher order moments whereas R3D uses the recursive method for all moments. ## 4.6 Within The Context of Modern Day Computing 

R3D was implemented primarily with CPU computation in mind but did make some optimizations for vectorization. Since its development, the computational power of new supercomputers is com-ing primarily from GPUs (over 95%) while the memory capacity of both CPUs and GPUs is still constrained. J3D is optimized on both counts for the GPU. # 7 Conclusion 

In this paper, we began by discussing the motivations for performant polyhedral clipping especially within the context of mesh to mesh interpolation and material interface reconstruction. We then went into the implementation details of R3D as well as its performance limitations. To address this, we introduced a novel use of data structures to implement more performant algorithms for clipping and we discussed some lessons learned in pursuit of this. Finally, we presented some benchmarks on various problems which demonstrate J3D’s impressive performance gains over R3D.
