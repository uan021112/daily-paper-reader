Abstract
Feed-forward geometry models such as VGGT recover
camera parameters, depth maps, and point maps from
one to hundreds of views in a single forward pass, mak-
ing them powerful backbones for multi-view 3D percep-
tion. However, VGGT’s global attention is quadratic in
the number of frames and dominates end-to-end run-
time on long sequences, which has motivated a range of
training-free efficiency methods such as token merging.
These methods, however, come with a drop in accuracy
that makes them hard to use in place of VGGT. We pro-
pose GPA-VGGT, a training-free acceleration method
that replaces global attention in early blocks with frame
attention augmented by a shared cross-frame K/V set.
In the remaining blocks, we merge only keys and values
while preserving all queries, restore the attention mass
of the tokens each merged key represents, and randomly
project the matching metric to 128 dimensions to re-
duce matching cost. Across diverse multi-view geom-
etry tasks, GPA-VGGT provides training-free acceler-
ation at speedups comparable to prior work while pre-
serving the information required for precise geometric
estimation, retaining over 99% of VGGT’s pose accu-
racy under AUC@3. Our project page is available at
https: // noheat61. github. io/ GPA-VGGT/ .

We introduce GPA-VGGT, a training-free accelera-
tion method designed to preserve the information re-
quired for accurate geometric estimation. GPA-VGGT
merges keys and values only, retaining every query so
that each token continues to produce its own output.
It further adds log s to the logit of each merged or
pooled key, restoring the attention mass of the tokens
it represents. In early blocks, GPA-VGGT preserves
cross-frame context through a compact shared cross-
frame K/V set comprising the camera and register to-
kens from all frames, together with a small number of
content-adaptive pooled patch summaries. Finally, be-
cause the retained similarity is used only for an argmax
operation, we reduce matching cost through a fixed
low-dimensional projection of the matching metric.
Without additional training, GPA-VGGT processes
a 200-frame sequence in approximately 34 s, compared
with 87 s for vanilla VGGT, while matching the run-
time of other baselines. Across all benchmarks evalu-
ated using AUC@3, GPA-VGGT remains within 1% of
vanilla VGGT on benchmarks and shows a particularly
large advantage over existing acceleration methods on
the more challenging setting.

2. Related Work
2.1. VGGT Acceleration
VGGT [1] is a feed-forward multi-view geometry model
that takes a set of unposed images as input and jointly
predicts camera parameters, depth maps, point maps,
and tracking features for all views. Each view is to-
kenized by a DINOv2 [24] encoder, and its Trans-
former [25] alternates between frame attention and
global attention. Although global attention is essential
for establishing multi-view consistency, its quadratic
complexity with respect to the number of tokens makes
it the primary computational bottleneck for long image
sequences.
FlashVGGT [5] compresses the global aggregator
using learned descriptors.
LiteVGGT [4] introduces
geometry-aware cached token merging, preserving ge-
ometrically important tokens while reusing merge in-
dices across adjacent blocks. Co-Me [9] uses an aux-
iliary confidence predictor, trained by distillation, to
identify tokens suitable for merging. QuantVGGT [7]
and QVGGT [8] improve computational and memory
efficiency through reduced-precision inference. Because
these methods rely on additional training or reduced
precision, they are not the target of our training-free
architectural design.
FastVGGT [2] was the first method to introduce to-
ken merging into VGGT. To address token collapse in
long sequences, it uses a partitioning strategy tailored
to the multi-frame layout and preserves a subset of
salient tokens from merging. FasterVGGT [6] replaces
dense global attention with training-free block-sparse
attention, retaining selected block interactions based
on coarse attention patterns and geometrically mean-
ingful correspondences.
AVGGT [3] replaces early
global blocks with frame attention and applies uniform
grid-based subsampling to patch tokens in the remain-
ing global blocks. Its design is motivated by the obser-
vation that global attention supports cross-view align-
ment through sparse spatial correspondences rather
than dense token-to-token interactions.
HTTM [10]
performs head-wise temporal token merging with tem-
poral reordering to preserve feature diversity after head
concatenation. Although these methods provide sub-
stantial acceleration, their accuracy degradation be-
comes more apparent under strict metrics such as
AUC@3, which are sensitive to fine-grained camera-
pose errors. Our method instead preserves the infor-
mation required for precise geometric estimation and
pose accuracy at AUC@3.

2.2. Token Merging
ToMe [15] was first introduced as a training-free ap-
proach to improve the throughput of vision transform-
ers, and was later extended to diffusion, video, and lan-
guage models. ToMe partitions tokens in each block
into source and destination sets and merges tokens
based on the similarity of their attention keys. Since a
merged key represents multiple tokens, ToMe adds the
logarithm of the group size to the attention logit so
that the merged key receives their combined attention
mass. ToMeSD [16] adapts this procedure to Stable
Diffusion by selecting destination tokens from a fixed
2D grid and computing similarity from the block input
rather than attention keys. It also omits this correction
and uses a merge–unmerge scheme to preserve dense
outputs. FastVGGT adopts this ToMeSD-style token
merging for a 3D geometry backbone, where such de-
sign choices can lead to fine-grained information loss
and accuracy degradation in precise geometry estima-
tion.
3. Analysis
3.1. Token Merging Disrupts Token-Specific Pre-
dictions and Attention Mass
FastVGGT [2] merges queries together with keys and
values, then restores the original sequence length by as-
signing each merged output to all tokens in its group.
Consequently, non-representative tokens receive out-
puts that were not computed from their individual
queries.
This differs fundamentally from an imper-
fect approximation that can be corrected after merging.
FastVGGT preserves salient tokens from merging, but
this only partially mitigates the loss of token-specific
predictions.
Figure 2 (top) plots the member-token
outputs associated with twelve representative merge
slots selected from block 12, projected onto the first
two principal components of the unmerged output field.
Query merging collapses within-group output diversity
to zero, whereas K/V-only merging closely overlaps
with the unmerged outputs in this diagnostic.
The number of original tokens represented by each
merged key, its token size s, is accounted for by adding
+ log s to the corresponding attention logit. Following
ToMeSD [16], FastVGGT omits this correction, so a
merged key receives the mass of only a single token. In
VGGT, this omission introduces an asymmetric bias
because the first frame consists predominantly of des-
tination tokens; attention is therefore progressively bi-
ased toward the first frame across merged blocks. Fig-
ure 2 (bottom) shows that, without the correction, the
first frame receives nearly twice as much attention mass

3.2. Early Blocks Still Need Cross-Frame Context
AVGGT’s layer-wise analysis [3] concludes that early
global-attention blocks do not form meaningful cross-
view correspondences, motivating their conversion to
frame attention. This finding supports replacing dense
global attention, but does not establish that early
blocks can dispense with cross-frame context entirely.
The absence of token-level correspondences does not
preclude informative interactions at the regional level,
where compact cross-frame context can still support
geometric estimation.
Figure 3 demonstrates that the principal limitation
of early frame attention is not merely representational
drift, but the disruption of a shared geometric refer-
ence across views. In the top row of Figure 3, frame
attention displaces the block-8 output field by 15.5%
of its radius relative to the full-global-attention refer-
ence, whereas the shared cross-frame K/V set reduces

this displacement to 7.8%.
The bottom row further
reveals that this drift is view-specific rather than glob-
ally shared: the pairwise cosine similarities between
per-frame drift directions exhibit a broad distribution,
with some views moving coherently and others in op-
posing directions. Their mean similarity is −0.09, close
to zero, indicating the absence of a common drift direc-
tion. Whereas a common drift preserves relative geom-
etry, such inconsistent view-specific perturbations alter
inter-view relationships and degrade relative-pose esti-
mation. Adding shared special tokens and pooled patch
summaries progressively aligns the per-frame drifts,
thereby preserving the shared geometric reference.
Early blocks require cross-frame context because
frame attention induces view-specific representational
drift, disrupting the relative geometry required for pose
estimation.
Preserving this shared geometric refer-
ence, however, does not require the full cross-frame
key set; a compact shared context is sufficient. Incor-
porating cross-frame special tokens partially mitigates
the drift, and augmenting them with image-token sum-
maries yields further improvement.
4. GPA-VGGT
4.1. Query-Preserving K/V Merging with Token-
Size Compensation
We merge keys and values while preserving the full
query sequence. Each token therefore attends to the
reduced key set using its own query and retains an in-
dividual output. In contrast to FastVGGT [2], which
computes attention over Nmerged ×Nmerged tokens, our
formulation has complexity N×Nmerged. This increases
the attention cost by a factor of N/Nmerged relative to
merging queries, but avoids the accuracy loss caused by
replacing token-specific outputs with shared ones. For
the remaining configurations, we follow FastVGGT, us-
ing the same grouping rule and merge ratio of 0.9.
After K/V merging, the remaining approximation is
the replacement of s keys by their mean. The merged
key then has token size s but receives the attention
mass of a single key. We correct this bias by adding
log s to the attention logit of each merged key, without
altering the merged key vector. Let Gj be the set of

4.3. Core-Block Sensitivity-Aware Merging
The aggregator is not uniformly tolerant to merging:
blocks 13–16 are substantially more sensitive than the
remaining merged blocks, and errors introduced in this
range are amplified rather than corrected by subse-
quent blocks. This sensitivity follows from the atten-
tion patterns.
In the middle blocks, queries attend
sharply to a small number of keys, particularly cross-
view correspondences; averaging keys can therefore di-
lute the information carried by the most relevant key.
In later blocks, attention is more diffuse and primar-
ily directed toward global sink tokens, making merging
less disruptive. We consequently use a merge ratio of
0.2 for blocks 13–16 and retain the ratio of 0.9 for all
other blocks in the merging window.

the forward-pass time for a 200-frame sequence when
using the full C = 1024 representation.

4.5. Custom Kernels
Two custom Triton [22] kernels implement the design:
a FlashAttention [21]-style kernel that adds the + log s
bias inside its online-softmax loop, since passing it as
a mask makes PyTorch [23] SDPA fall back to a slower
backend, and a matching kernel that computes the
source–destination argmax without storing the score
matrix. Both are numerically equivalent to their Py-
Torch references; Appendix A gives details.
5. Experiments

Does GPA-VGGT preserve camera-pose accuracy un-

sequence grows longer? (2) Does the same preservation
carry over to other tasks? (3) How does its runtime
speedup compare with existing acceleration methods?
(4) Which components are responsible for accuracy re-
covery and acceleration?

6. Conclusion
We identify three sources of accuracy degradation in
accelerated VGGT: information loss from query merg-
ing, incorrect attention mass after K/V merging, and
the removal of early cross-frame context. GPA-VGGT
addresses these issues through Query-Preserving K/V
Merging with + log s correction, Pooled Cross-Frame
Broadcast, and low-dimensional matching. Across di-
verse multi-view geometry evaluations, GPA-VGGT
reduces inference time while preserving vanilla VGGT’s
accuracy under both standard and strict metrics.

A. Custom Triton Kernels
A.1. Attention with a Per-Key Additive Bias
The standard attention interface treats the + log s cor-
rection as a mask and therefore falls back to a slower
implementation. For a 200-frame sequence, this fall-
back takes 2,142 ms, compared with 948 ms for un-
biased fused attention—more time than key merging
saves in the merged global-attention block.
Because the correction depends only on the key in-
dex, our Triton kernel adds it directly to each score tile
inside the online-softmax loop, preserving the stream-
ing structure of FlashAttention [21]. We avoid masked
loads by clamping out-of-range key indices and as-
signing duplicate columns a −109 bias.
This avoids
padding and copying K/V tensors; only the small bias
vector is padded. The bias is also pre-scaled on the
host, avoiding conversion within the inner loop. For a
200-frame sequence, our kernel takes 984 ms: only 4%
slower than unbiased fused attention and 2.18× faster
than the fallback.
A.2. Memory-Efficient K/V Matching
Bipartite matching requires only the row-wise maxi-
mum similarity and argmax index, not the full simi-
larity matrix. Materializing the full matrix would re-
quire 27.25 GiB for a 200-frame sequence. Even a chun-
ked PyTorch [23] reference, which materializes 5,000
rows at a time, requires a 1.20 GiB temporary buffer.
Our Triton kernel keeps each score tile in registers and
writes only the two required outputs, reducing this
temporary memory to 0.003 GiB.
The kernel trades a modest increase in runtime for
substantially lower memory use: the similarity kernel
itself takes 482 ms against 330 ms for the chunked refer-
ence at this shape. This overhead of roughly 150 ms is
small relative to the memory saved, since materializing
similarity tiles incurs a large transient VRAM cost and
can become the limiting factor for long sequences.

B. Peak VRAM Footprint
Table S1 reports the peak VRAM of the full forward
pass, using the VRAM-efficient VGGT implementation
introduced by FastVGGT [2] as the vanilla baseline.
GPA-VGGT remains within 0.02 GiB of vanilla VGGT
across all sequence lengths and AVGGT matches it ex-
actly, whereas at 500 frames FastVGGT uses 6.02 GiB
more VRAM; FasterVGGT already uses 13.72 GiB
more at 400 frames and exceeds device memory at 500.
Although K/V merging reduces the K/V sequence
length in global attention, the full-model peak is
set by the unchanged feed-forward sublayer within
a global-aggregator block.
Moreover, FlashAtten-
tion [21] does not materialize an N × N score ma-
trix, so the memory used by the modified global-
attention sublayer is already linear in the number of
tokens. GPA-VGGT therefore reduces attention com-
putation without changing peak VRAM, while keeping
attention memory nearly identical to vanilla VGGT
and below the feed-forward-memory peak.
In con-
trast, FastVGGT merges queries as well as K/V tokens
and subsequently restores the original token resolution.
The associated full-length token copies and unmerging
buffers raise its attention-memory peak above that of
the feed-forward sublayer.
AVGGT incurs essentially no additional peak-
memory overhead.
Its subsampled global attention
drops keys rather than copying tokens back, so it allo-
cates neither FastVGGT’s unmerging buffers nor any
workspace that scales with the dropped set, and its
peak equals vanilla VGGT’s at every sequence length
and at both subsampling settings.

C. Pooling for the Shared Cross-Frame
K/V Set
Each frame’s queries attend to local K/V tokens,
shared special tokens, and pooled image-token sum-
maries. The first two groups are held fixed in this ab-
lation; this section studies how to construct the sum-
maries. Table S2 compares pooling strategies on CO3D
using a fixed 8×8 pooling window. Fixed-window mean
pooling performs worst, while content-based clustering
is more effective.
Per-head clustering performs best
and is used in our model.
D. Merge-Operator Ablation
The merge operator independently determines whether
to merge queries with K/V tokens and whether to cor-
rect each merged key’s logit by its token size. Table S3
isolates these choices under an otherwise fixed config-
uration.
Merging queries forces all tokens within a
group to share the same output, whereas preserving
queries retains within-group diversity but does not ad-
dress the attention-mass bias caused by K/V merging.
The + log s correction restores the mass of the tokens
each merged key represents and provides the larger
accuracy gain. Together, query preservation and the
+ log s correction nearly recover no-merging accuracy,
with the benefit becoming larger at higher merge ra-
tios.
Figure S1. Core-block selection on VGGT. Each point
shows how much the final global-block output changes from
the unmerged model when the indicated contiguous block
set is protected from merging; lower values mean smaller
changes. The criterion is computed without ground-truth
annotations across four datasets. Blocks 13–16 consistently
give the smallest change and are selected as the core-block
set.
E. Selection of the Core Blocks
We choose the core blocks by measuring how much
merging changes the aggregator’s final representation.
For each candidate set, we leave those blocks unmerged
and apply merging to every other block. We measure
the relative Frobenius-norm deviation between the fi-
nal global-block outputs of the merged and unmerged
models on the special tokens, and normalize it by the
deviation obtained when all blocks are merged.
Be-
cause this measurement uses no ground-truth annota-
tions, the core blocks are selected without reference to
task labels.
We evaluate block sets rather than individual blocks.
Simply ranking individual blocks and selecting the top
k does not reliably find the best set. A single-block
measurement considers one block while all other blocks
remain unmerged, whereas the full model applies merg-
ing across multiple blocks. Merging in one block can
therefore change the token representations and source–
destination assignments used by later blocks.
For VGGT, this criterion selects blocks 13–16. Fig-
ure S1 shows that this set gives the smallest output
change on all four datasets. No three-block set matches
this result. We apply the same procedure to π3 and
VGGT-Ω; Figure S2 shows the resulting core-block se-
lections, which are used in Section H.

F. Matching Feature Dimension
Table S4 evaluates the fixed random projection used for
K/V matching. Projecting the matching features from
1,024 to 128 dimensions lowers the cost of each match-
ing call from 469 ms to 64 ms. Although only 76.6% of
source tokens select the same destination as under the

only 0.56% similarity relative to the full-metric opti-
mum, indicating that most disagreements occur among
near-equivalent candidates. We therefore use 128 di-
mensions, the smallest projection size that maintains
accuracy close to the full-dimensional metric.
G. Comparison with AVGGT
GPA-VGGT and AVGGT [3] share a two-stage struc-
ture: both replace early global-attention blocks with
frame attention and reduce the K/V set in later
blocks while preserving all queries. In the early stage,
AVGGT restricts attention to within-frame tokens,
whereas GPA-VGGT augments each frame with a
pooled shared cross-frame K/V set. In the later stage,
AVGGT retains K/V tokens at fixed spatial strides,
whereas GPA-VGGT selects them through bipartite
merging.
At an equal token budget, AVGGT sum-
marizes all removed tokens with a single unweighted
mean K/V pair, whereas GPA-VGGT aggregates each
removed token into the retained token it most closely
matches and restores the corresponding attention mass
through the + log s correction.
The 128-dimensional
Gaussian projection reduces matching overhead, en-
abling GPA-VGGT to retain fewer K/V tokens than
AVGGT(2) while achieving both lower runtime and
higher accuracy.
H. Transfer to Other Backbones
The proposed design applies to backbones that alter-
nate frame attention and global attention over a token
layout comprising special tokens followed by a patch
grid. Both π3 [13] and VGGT-Ω[14] follow this struc-
ture. We adjust only model-specific properties, includ-
ing the block layout, the number of special tokens per
frame, and patch size. Each adaptation uses the same
128-dimensional Gaussian projection for K/V match-
ing.
Table S5 reports the incremental ablation on π3. We
retain the early-block setting used by AVGGT: global
attention in blocks 0–9 is replaced by frame attention,
and K/V merging is applied in blocks 10–17, with a
lower merge ratio in core blocks 13–15. However, π3 re-
quires a lower overall merge ratio than VGGT because
it has fewer global-attention blocks. Each merged block
therefore has a larger effect on the information propa-
gated through the remaining global-attention blocks.
Table S6 reports the same ablation on VGGT-Ω,
which contains five register blocks at raw indices 2, 6,
9, 14, and 20 that do not perform cross-frame atten-
tion over patch tokens.
We therefore replace global
attention with frame attention in raw blocks 0, 1, 3,
4, 5, 7, and 8, and apply K/V merging in the subse-
quent non-register blocks, with a lower merge ratio in
raw blocks 12, 13, 15, and 16. As in π3, patch tokens
participate in global attention in fewer blocks than in
VGGT, requiring a lower overall merge ratio.
On both backbones, the shared cross-frame K/V set
mitigates the accuracy loss caused by replacing early
global attention with frame attention.
The adopted
configurations accelerate all three backbones while re-
taining most of the accuracy of their vanilla models.
