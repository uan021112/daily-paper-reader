## 摘要
前馈3D高斯泼溅现可从无位姿、未标定图像中重建可渲染场景。然而，大多数模型仅以光度一致性进行监督，并逐像素预测高斯，这使全局结构变得脆弱，且将基元数量与图像分辨率和视图数量绑定。为此，GrapeSplat 将多视图线索融合为体素对齐的场景表示，并直接从学习到的网格解码高斯，无需逐场景优化或后处理。Atlas 编码器将所有视图提升为锚定在预测3D点上的逐像素几何与外观特征。PEACH-Vox 通过具有精确闭式逆的平滑逐轴映射，将无界场景压缩为有界稀疏网格。随后，稀疏解码器利用稀疏卷积整合该网格，并将完整场景解码为每个占用单元多个高斯。这种融合表示利用了稀疏体素占用，其中高斯数量随占用单元变化，并随着视图覆盖场景而饱和，而网格分辨率决定其上限。GrapeSplat 通过单次前向传播将无位姿图像转换为可渲染的高斯场景。在8视图序列上使用2D和3D监督训练后，它可零样本泛化到室内和无界场景中4至64个视图。代码与训练权重见 https://github.com/VAISR/GrapeSplat

## Abstract
Feed-forward 3D Gaussian Splatting now reconstructs renderable scenes from unposed, uncalibrated images. Yet, most models supervise only photometric consistency and predict Gaussians pixel by pixel, which leaves global structure fragile and ties primitive count to image resolution and view count. To this end, GrapeSplat amalgamates multi-view cues into a voxel-aligned scene representation and decodes Gaussians directly from the learned grid, requiring no per-scene optimization or post-processing. An Atlas Encoder lifts all views into pixel-wise geometry-and-appearance features anchored at predicted 3D points. PEACH-Vox compands the unbounded scene into a bounded sparse grid through a smooth per-axis map with an exact closed-form inverse. The Sparse Decoder then consolidates the grid with sparse convolutions and decodes the full scene as multiple Gaussians per occupied cell. This amalgamated representation exploits sparse voxel occupancy, where the Gaussian count follows the occupied cells and saturates as views cover the scene, while grid resolution sets its ceiling. GrapeSplat turns unposed images into a renderable Gaussian scene in a single forward pass. Trained with 2D and 3D supervision on 8-view sequences, it generalizes zero-shot from 4 to 64 views across indoor and unbounded scenes. Code and trained weights are available at https://github.com/VAISR/GrapeSplat

## 1. 核心问题与研究动机

- **背景**：从稀疏、无位姿照片恢复3D几何并合成新视图是计算机视觉的基础难题，广泛应用于机器人、AR、3D内容创作。3D高斯泼溅（3DGS）以显式图元实现实时渲染，但传统变体依赖耗时的逐场景优化或迭代生成，且需预先标定相机。
- **核心矛盾**：
  - 前馈3DGS虽将重建摊销为单次网络前向，但多数框架仍要求真值位姿与内参；获取这些参数需SfM等预标定，其延迟和跟踪失败会抵消前馈的速度优势。
  - 即便在无标定前馈方向（如 AnySplat、Depth Anything 3），**几乎所有方法都逐像素预测高斯**，导致图元预算与图像分辨率、视图数强绑定，大量容量浪费在同一表面的冗余观测上，跨视图一致性只能靠2D特征隐式约束。
  - 已有放宽像素约束的尝试（TokenSplat、AnchorSplat 等）仍受限于图像空间结构或不规则锚点，**全局结构一致性与高斯总数控制均难保证**。
- **论文主张**：GrapeSplat 将高斯预测从**图像空间**迁移到**统一的场景级体素网格**，实现无位姿、无标定、单次前向、无需后处理的可渲染场景重建，并让高斯数量由稀疏体素占用决定。

## 2. 方法论

### 2.1 总体流程
- 输入 S 张无位姿、未标定 RGB 图像，单次前向联合输出：相机编码、逐像素深度、统一3D高斯场景（均值、协方差、不透明度、球谐系数）。
- 规范坐标：所有输出位于第一相机坐标系，尺度规范化为单位平均点距离（消除相似变换的规范自由度）。
- 流程：Atlas Encoder → PEACH-Vox → Sparse Decoder → 逆压缩回世界空间 → 可微光栅化。

### 2.2 Atlas Encoder（2D-3D 标记化）
- 基于适配的 **VGGT-1B** 聚合器联合编码所有视图；3D head 解码每视图几何：DPT 头预测逐像素深度及置信度，相机头输出九参数编码（旋转、平移、视场角）。
- 逐像素射线由相机编码闭式导出，无需专门头部；用无参数反投影 `p = D·r_d + r_o` 将每个像素锚定到3D点，构建"点级图谱"，使每个像素背后都有3D位置。

### 2.3 PEACH-Vox（场景自适应压缩体素化）
- **特征桥接**：用 DPT 式融合主干将视图标记从 patch 分辨率提升到像素分辨率。
- **归一化**：以点云质心 c 为中心，用各向同性标量 s（中心化点平均幅值）归一化，保证方向无关。
- **代数 sigmoid 压缩**：`ψ_s(x) = x / √(s² + x²) ∈ (−1,1)`，将无界坐标映射到有界开区间；近质心近似线性 `≈ x/s`，远处以 `1 − s²/2x²` 的**代数尾部**逼近边界（区别于 tanh/erf 的指数塌缩，能保留远景分辨）。
- **稀疏体素化**：压缩坐标按每轴 G=448 量化，仅占用单元实体化；每个单元融合多视图线索（图谱特征、log深度与置信度、图像颜色、射线），并条件于吸收点数与场景尺度 s。
- **闭式逆与协方差传播**：`ψ_s⁻¹(u) = s·u/√(1−u²)`，`Σ = J Σ_v Jᵀ`，其中 `J = diag(s(1−u²)^(−3/2))`，无需数值优化或矩阵求逆。
- **梯度处理**：决定单元归属的点坐标从几何分支 detach，量化处不回传梯度；深度、射线、标记仍作为可微线索进入融合。

### 2.4 Sparse Decoder
- 在占用单元上运行稀疏卷积 U-Net（3个下采样编码层 + 瓶颈 + 3个转置解码层 + 跳连接），传播多尺度上下文，先形成全局一致布局再解码。
- **每占用单元解码 L=4 个高斯**：L 个并行分支，各带固定嵌入打破对称；每属性一个 MLP，输出不透明度、球谐颜色、单元内位置、旋转（6D + Gram-Schmidt 正交化）、逐轴尺度（有界 log 尺度激活）；谐波带几何衰减。
- 解码结果以体素单位输出，经逆压缩回世界空间。

### 2.5 训练
- 损失：`L = λ_cam L_cam + λ_depth L_depth + λ_point L_point + λ_rgb L_rgb + λ_lpips L_lpips + λ_dr L_dr`，深度/点监督按预测置信度加权，并加 `−m log C_D` 正则。
- 2D 与 3D 监督共同将体素网格锚定到观测表面，为高斯解码提供结构基础。

## 6. 主要结论与发现

- **质量随视图数持续提升**：NRGBD 上 LPIPS 从 4 视图 0.524 降至 32 视图 0.262（AnySplat 仅从 0.580 降至 0.443）；ScanNet++ 16 视图达 0.380（AnySplat 0.499）。
- **几何与位姿领先**：渲染深度 δ1 在所有 benchmark 一致优于基线；相对位姿保持顶尖水平，且随视图数增加而保持或提升。
- **可扩展性**：像素对齐基线随视图数增加纷纷 OOM（StructSplat 止于16、2Xplat 止于32、SplatWeaver 止于64），GrapeSplat 全设置无 OOM；64 视图时 LPIPS 0.271 vs AnySplat 0.432，显存 12.4 GiB vs 25.5 GiB，高斯 5.3M vs 6.8M。
- **图元数量饱和特性**：高斯数由占用单元决定，4→64 视图仅增 4.4×，而 AnySplat 增 11.3×；资源消耗曲线在约16视图处交叉。
- **消融结论**：PEACH 与聚类在房间级数据集上有轻微取舍，但在大范围 DL3DV 上收益显著；聚类在密集视图下整体最优。
- **附录发现**：Depth Anything 3 在 PSNR/SSIM 上领先（GrapeSplat 渲染偏软），但 GrapeSplat 在 LPIPS 室内套件领先；语义分支收益微小却增加 840.6M 冻结参数，故未采用。

## 7. 优点

- **预测空间层面的创新**：不在图像格点上做局部改良，而是把高斯预测整体迁移到场景级稀疏体素网格，从根本上解耦图元数与图像分辨率/视图数。
- **数学优雅的压缩函数**：全局平滑、逐轴可分、单参数控制的代数 sigmoid，兼具**精确闭式逆**与**解析协方差传播**，无观测被丢弃、无畸变残留；代数尾部相比 tanh/erf 能保留远景分辨。
- **端到端无位姿**：单次前向完成相机、深度、高斯联合预测，推理时完全无标定、无逐场景优化、无后处理。
- **显式容量控制**：网格分辨率 G 与每单元高斯数 L 提供两个清晰的容量旋钮，可只在薄结构处花费算力。
- **评估严谨**：统一 harness、统一对齐与度量代码，主动披露并检验背景色偏差，OOM 情况如实标注，附录提供完整指标与成本表。

## 8. 不足与局限

- **稀疏视图/小场景劣势**：4 视图时初始显存开销高于像素对齐方法（7.0 vs 4.6 GiB）；7-Scenes 这类单房间、帧间重叠大的序列上排名最低，因体素锚定所要消除的冗余本就很薄。
- **DTU 表现最差**：物体中心、实验室机械弧线捕获场景下，所有变体渲染偏大偏软，严格位姿阈值精度约降至宽松阈值的一半；作者归因于相机弧尺度的一致误估，而非场景本身。
- **固定分辨率非自适应**：压缩器按场景自身范围归一化，同一单元数拉伸到广场或压缩进房间，保持恒定的是**预算**而非物理尺度；逐场景自适应分辨率仍是未来方向。
- **主对比覆盖有限**：Depth Anything 3 因系统性质不同被排除在主表之外，但其在 PSNR/SSIM 上领先，主文仅报 3 项指标，完整比较需查附录。
- **背景色敏感**：白/黑底选择会系统性影响 PSNR、SSIM、LPIPS 与严格位姿精度，作者仅以"按各自发布背景读取"处理，未彻底消除该混淆因素。
- **算力信息不完整**：未报告训练总时长与总 GPU 时，难以评估训练成本。
- **应用限制**：初始固定开销大，稀疏视图或小场景下性价比不如逐像素方案；对需要度量精确的场景（如 DTU 式实验室捕获）泛化受限。
