## Abstract 

RGB-based category-level 9D pose estimation remains highly challenging because a monocular system must generalize across unseen object instances while jointly inferring 3D translation, 3D rotation, and 3D size. Unlike instance-level pose estimation, the category-level setting requires the network to learn both what is shared across objects within a category and how individual instances vary in structure. This challenge is amplified in the RGB-only setting, where pose cues, category-level commonality, and instance-specific variation are entangled in appearance without direct geometric constraints, making it difficult for existing frameworks to learn a representation that is truly aligned with the category-level estimation objective. To address this problem, we propose SchemaPose, a schema-guided framework for RGB-based category-level pose estimation. SchemaPose equips the estimation pipeline with an explicit parametric schema for modeling category-level regularities together with structured instance variation, and uses the inferred schema variables to guide pose-related prediction in an end-to-end query-based framework. The same formulation also supports template instantiation, synthetic annotation, and pose learning within a unified framework. Experiments on synthetic and real data show that SchemaPose achieves state-of-the-art performance among RGB-based methods for category-level 9D pose estimation. 

## 1 Introduction 

Object pose estimation is a fundamental problem in computer vision, with broad applications in robotic manipulation [1–4], augmented reality [5–7], and embodied perception [8–10]. Compared with instance-level pose estimation, category-level pose estimation aims to recover the poses of previously unseen object instances within a predefined category, making it both more practical for real-world deployment and substantially more challenging [11]. This challenge becomes especially pronounced in the RGB-only setting, where a monocular system must jointly infer 3D rotation, 3D translation, and 3D size from a single image alone, despite large structural variation across object instances within the same category [12–14]. A key difficulty of category-level pose estimation is that the network must learn not only pose, but also the category-level structure shared across instances and the ways in which individual objects deviate from it [12, 15]. This requirement is especially demanding for RGB-based methods, because

without direct geometric constraints from depth, pose cues are tightly entangled with instance-specific shape, part configuration, and object extent in monocular RGB observations [13, 16]. Consequently, structural differences across instances can affect the interpretation of 3D size and spatial layout, and further complicate rotation and translation estimation, making it difficult for existing frameworks to learn an internal representation aligned with the category-level pose objective. A representative line of RGB-based methods [16–18] builds on NOCS maps [11], which provide a shared canonical coordinate space for different instances of the same category. Pose is then recovered from the predicted 2D–3D or 3D–3D correspondences using geometric solvers [19, 20]. However, recent studies [12, 15] show that NOCS maps can be suboptimal for category-level direct prediction, since different object instances may produce different NOCS maps under similar category-level poses, making the mapping from canonical coordinates to pose unnecessarily complex. Moreover, the predicted coordinates often retain substantial instance-specific geometric detail that is not directly aligned with stable pose prediction. Recent methods [21, 22] therefore move toward more direct end-to-end prediction and avoid explicit canonical maps. However, without an explicit structural variable, pose-relevant category structure and instance variation are typically absorbed implicitly into latent or query features, making them hard to supervise, control, or consistently use across the estimation process. This observation suggests that RGB-based category-level pose estimation requires an explicit struc-tural variable that can capture both category-level regularity and instance-level deviation, and can be used directly throughout the estimation process. In cognitive science [23–25], such structured abstractions are often described as schemas: internal organizational models that preserve what is stable across a category while accommodating lawful variation across instances. Rather than focusing on the surface details of individual objects, a schema captures the shared structure of a category together with the factors along which instances differ. Motivated by this, we propose SchemaPose, a structure-aware framework for RGB-based category-level 9D pose estimation. SchemaPose introduces a parametric category schema as an explicit structural layer in a unified query-based pipeline, allowing category-level regularity and instance-level variation to be modeled and used directly for pose prediction. We develop a dual-stage schema-guided mechanism so that inferred schema participates in both proposal-stage coarse pose prediction and decoder-stage pose refinement, making structural information available throughout the estimation process rather than only as an auxiliary target. Beyond pose prediction, the same parametric formulation supports template instantiation and synthetic data generation, providing structurally consistent supervision for training. We evaluate SchemaPose on CAMERA25 and REAL275, covering both synthetic and real-world settings. SchemaPose consistently outperforms existing RGB-based category-level pose estimation methods across all metrics. In particular, compared with the strongest prior RGB-based method, SchemaPose improves the 10 ◦10cm metric from 38.7 to 43.1 on CAMERA25 and from 52.8 to 68.4 on REAL275. Further ablation studies verify that the strong performance of SchemaPose benefits from using meaningful schema information as an explicit structural condition for pose decoding, rather than relying solely on implicit visual features to absorb category-level structural variation. To summarize, our contributions are as follows. First, we propose SchemaPose, a schema-guided framework for RGB-based category-level 9D pose estimation, enabling the estimation pipeline to better learn category-level commonality and instance variation for pose prediction. Second, we introduce a parametric category schema to explicitly model category-level structure and instance variation, and build a schema-driven data generation pipeline to provide accurate synthetic supervision for SchemaPose training. Third, we develop a dual-stage schema-guided mechanism, where schema inference participates from proposal generation to decoder-level pose prediction, allowing category-level structural information to directly influence the full pose estimation process. Finally, we validate the proposed framework on synthetic and real benchmarks, where SchemaPose surpasses the strongest prior RGB-based method by a large margin, especially on real-world pose accuracy. 22 Related Work 

2.1 RGB-Based Category-Level Pose Estimation 

RGB-based category-level pose estimation aims to recover poses of unseen object instances from monocular images without requiring instance-specific CAD models at inference time. A representative line of work remains geometry-guided. NOCS [11] establishes a shared canonical space and recovers pose through canonical correspondences, forming the basis of many later RGB-based extensions. MSOS [18] jointly predicts metric-scale shape and NOCS and renders depth for similarity alignment. OLD-Net [17] estimates object-level depth together with canonical coordinates and recovers pose through geometric alignment. DMSR [16] further decouples metric-scale recovery from rigid pose recovery and solves pose from learned correspondences via PnP. Recent methods increasingly move toward direct regression or more unified prediction. LaPose [13] performs end-to-end pose regression with uncertainty-aware NOCS modeling, while GIVEPose [12] argues that instance-specific NOCS maps are suboptimal for direct category-level regression and pro-gressively transforms NOCS toward IVFC. YOPO [21] formulates category-level 9D pose estimation as DETR-style joint detection and pose prediction from object queries without an explicit alignment stage. LanCOPE [26] further introduces language-guided multimodal fusion for monocular pose prediction, and Fischer et al. [22] propose a unified RGB-only framework based on 3D prototypes, dense 2D/3D matching, and multi-model RANSAC PnP. Despite their differences, existing methods either organize pose estimation around canonical geometry and explicit geometric solving, or absorb pose-relevant structural factors implicitly into learned features. Our method instead introduces schema as an explicit structural variable inside the pose estimation framework. 

2.2 Canonical Coordinates and Intermediate Representations 

Canonical coordinates are a central design choice in category-level pose estimation because they provide a shared reference space for unseen instances. NOCS [11] is the most influential formulation and serves as the basis for many subsequent methods. Recent studies refine this line from different perspectives. SOCS [15] improves semantic consistency under large intra-category variation through keypoint-guided non-rigid warping. LaPose [13] models uncertainty over canonical coordinates under monocular ambiguity. GIVEPose [12] progressively transforms NOCS toward IVFC for direct regression, and DiffusionNOCS [27] keeps NOCS as the target while replacing deterministic prediction with diffusion-based estimation under multi-modal inputs. These methods improve pose estimation mainly by redesigning the canonical space, the uncertainty model, or the prediction process of canonical maps. In contrast, our method does not pursue another coordinate-space variant. Instead, it introduces schema-guided structural abstraction as a framework-level conditioning variable, aiming to explicitly represent category-level commonality and instance-level variation in a form that can directly support pose prediction.

In SchemaPose, the parametric category schema serves two connected roles: it defines an ex-plicit structural variable for category-level pose learning, and it provides the generative specifi-cation for constructing synthetic training data with aligned schema and pose annotations. 

Parametric Category Schema. We define the schema for category c as a parameterized ab-straction that models object structure using geo-metric primitives (e.g., cuboids, cylinders, rings) and semantic part templates (e.g., body, handle, lid). Each object instance is specified by a full schema variable zc = ( dc, x c), i.e., the complete discrete-continuous encoding of its structure under the category schema. The discrete variables dc select the active part configuration and template choices, while the continuous variables xc specify the geometric attributes of the selected templates, such as radius, thickness, height, offset, or curvature. Formally, the instance is generated by 

Mc = Φ c(dc, x c), (1) where Φc is the instantiation function that analytically constructs the object by composing the selected part templates and their geometric relations. This formulation represents a category as 4a valid, category-consistent family of object instances rather than a fixed prototype, providing a structural basis for both schema-driven data generation and schema-guided pose learning. Fig. 1(a) illustrates an example of the schema abstraction. 

Compact Schema Vector for Learning. As shown in Fig. 1(b), we distinguish the full schema variable used for object instantiation from the compact schema vector used for network learning. The full schema variable zc = ( dc, x c) specifies all active part templates and geometric parameters required to analytically construct a valid object instance. For pose estimation, however, directly regressing the full instantiated schema would introduce excessive output dimensionality and template-dependent parameter subsets. We therefore derive, for each category, a compact schema vector 

gc = Ψ c(zc), (2) where Ψc(·) is a category-specific compression function. This function retains pose-relevant structural factors, such as object extent, proportions, and coarse part configuration, while removing low-level geometric details used only for exact instantiation. Continuous parameters are further normalized by category-specific reference scales or valid parameter ranges, and inactive optional-part parameters are zero-padded to form a fixed category-wise layout. As a result, gc provides a compact, normalized, and stable structural target for pose estimation without requiring the network to predict the full instantiable schema. More details on schema implementation, including geometric primitive construction, part-template composition, and compact schema compression, are provided in Appendix A. 

Schema-Driven Synthetic Data Generation. As shown in Fig. 1(c), our pipeline contains two stages. First, schema-driven object generation. Given a valid full schema variable zc, we instantiate a category-consistent object by activating the selected part templates and assigning the corresponding continuous parameters. Varying zc within category-consistent ranges yields structurally diverse objects. Since each object is generated from known schema parameters, we compute its compact schema vector gc = Ψ c(zc) and use it as the schema annotation for network supervision. Second, compositional scene rendering. Generated objects are sampled from the object pool, randomly scaled and posed, and placed on supporting surfaces under collision and visibility constraints. We reject placements with severe interpenetration, extreme truncation, or insufficient visible area, and render RGB images in BlenderProc [30] with varying viewpoints, lighting, materials, textures, and backgrounds. Since the full scene state is known, each rendered image provides aligned pose labels and compact schema annotations for training SchemaPose. More implementation details of the data generation pipeline can be found in Appendix B. 

3.3 SchemaPose Framework 

In this section, we present SchemaPose, whose core design comes from the relationship between object schema and pose: as illustrated in Fig. 2, parametric category schema provides a structural basis for category-level pose estimation. Given an RGB image, SchemaPose explicitly infers pose-relevant structural factors in the form of a compact schema vector and uses them to guide pose prediction. 

Overall Architecture. As shown in Fig. 3, SchemaPose adopts an end-to-end query-based ar-chitecture consisting of a backbone, a multi-layer Transformer encoder, a multi-layer Transformer decoder, and a Schema-Guided Pose Head (SGPH). Given an input RGB image, the backbone extracts multi-scale features, which are further enhanced by the Transformer encoder to produce the encoder memory Qenc . The SGPH is first applied to the encoder memory to produce proposal-level predictions, including object category, bounding box, schema, and pose-related quantities. The top-K proposals are then selected according to their classification scores and used to initialize decoder queries. The Transformer decoder refines these queries through cross-attention with the encoder memory, and the same SGPH is applied to the refined query features Qdec at each decoder layer to produce decoder-level predictions. We refer to this design as a Dual-Stage Schema-Guided Mechanism , where “dual-stage” denotes schema guidance at two internal stages of the same end-to-end network: the proposal-generation stage and the decoder-refinement stage. At the proposal stage, a compact schema vector is inferred from encoder memory and used to guide initial pose prediction, ensuring that even the earliest object representations benefit from explicit structural supervision. ## 4 Experiments 

4.1 Experimental Setup Benchmarks. We conduct experiments on the widely used category-level 9D pose estimation benchmarks CAMERA25 and REAL275 [11], following the standard six object categories: bottle ,

bowl , camera , can , laptop , and mug . CAMERA25 is a synthetic dataset containing 275K training images and 25K evaluation images, covering 1,269 object models from ShapeNetCore[34]. REAL275 is a real-world dataset consisting of 4.3K training images from 7 scenes and 2.75K test images from 6 scenes, with 6 object models in each category. We evaluate SchemaPose on the standard test splits of CAMERA25 and REAL275. 

Training Data. Our training data are organized as a mixture of three sources. First, we use our schema-driven synthetic dataset, denoted as SchemaData , generated by the pipeline introduced in Sec. 3.2. SchemaData provides scene-level synthetic RGB images with aligned pose labels and schema annotations. Unless otherwise specified, we instantiate 10K objects for each category and render 135K training images in total. Second, we use REAL275 training images with additional schema annotations provided by us, which helps schema-supervised learning transfer to real RGB observations. Third, we include CAMERA25 training images without schema annotations to further strengthen pose learning. By default, the mixed training set consists of 135K images from SchemaData , 135K randomly sampled images from the CAMERA25 training split, and the 4.3K REAL275 training images repeated 6 times. Schema supervision is applied to SchemaData and REAL275 samples, and is masked out for CAMERA25 samples, while detection and pose supervision are retained for all training sources. 

Evaluation Metrics. Following prior work [11, 16, 21], we report mean Average Precision (mAP) under 3D IoU thresholds and pose accuracy thresholds. Specifically, we use 3D IoU at 50% and 75%, and the standard pose metrics under the 10 ◦ rotation error threshold, the 10 cm translation error threshold, and the combined 10 ◦10 cm criterion. 

Implementation Details. We use Swin-L [35] as the backbone and initialize the detector from a DINO [29] model pretrained on COCO. We train the network with AdamW [36] for 12 epochs on the mixed dataset and apply standard data augmentations, including resizing, color augmentation, random translation, and random flipping. 4.2 Comparison with State-of-the-Art 

We compare SchemaPose with previous RGB-based category-level 9D pose estimation methods on CAMERA25 and REAL275. As shown in Table 1, SchemaPose achieves the best results on all reported metrics across both benchmarks. On CAMERA25, SchemaPose improves over the strongest prior method YOPO [21] by 5.8 IoU 50 and 4.4 under the 10 ◦10cm metric. On REAL275, the gains are more pronounced: SchemaPose improves IoU 50 from 71.6 to 86.3 and 10 ◦10cm from 52.8 to 68.4, corresponding to relative improvements of 20.5% and 29.5%, respectively. The consistent gains across both synthetic and real benchmarks validate SchemaPose as a strong approach for RGB-based category-level 9D pose estimation. Qualitative results are shown in Fig. 4. Compared with YOPO, SchemaPose produces more accurate pose estimates in several challenging cases, especially under difficult viewpoints and cluttered real-world scenes. As highlighted by the light-blue arrows, YOPO often suffers from inaccurate pose prediction or even missed detections for small or heavily occluded instances, while SchemaPose can still localize these objects and estimate poses that better match the ground truth. We attribute the strong performance to the schema-guidance design of SchemaPose, whose motivation comes from the coupling between pose and object structure. The compact schema vector provides explicit cues about object extent, proportions, part layout, and symmetry, which help the pose head interpret monocular observations under intra-category structural variation. This allows the network to use a structured intermediate representation instead of relying solely on implicit query features for pose decoding, thereby making pose prediction more stable and better aligned with category-level structural variation.

We presented SchemaPose, a schema-guided framework for RGB-based category-level 9D pose estimation. The core idea is to introduce a parametric category schema as an explicit structural variable that captures category-level commonality and instance-specific variation, and to use the inferred schema to guide pose prediction in a query-based network. To support schema learning, we further constructed a schema-driven data generation pipeline that provides aligned pose and schema annotations. Experiments on CAMERA25 and REAL275 show that SchemaPose achieves state-of-the-art performance among RGB-based methods, and ablation studies verify the effectiveness of dual-stage schema guidance, category-aware schema masking, structured schema representation, and balanced mixed training. These results suggest that explicit structural modeling is a promising direction for reducing monocular ambiguity and improving category-level pose estimation under large intra-category variation.

## A Implementation of Parametric Category Schema 

A parametric category schema consists of three components: (1) a primitive library, (2) semantic part templates, and (3) category-level schema composition. The primitive library defines basic geometries such as Cuboid , Cylinder , and Ring . Semantic part templates instantiate and assemble these primitives according to continuous geometric parameters. Category-level schema composition selects active part templates according to discrete variables and assembles them into a complete object model. In addition, a compression function maps the full schema variable to the compact schema vector used for network learning.

## B Details of Schema-Driven Data Generation 

This section details how we construct SchemaData. The pipeline has two stages: (1) procedural object generation from parametric category schemas, and (2) compositional scene rendering with BlenderProc[30]. 

B.1 Procedural Object Generation 

For each category c, we generate object instances from the full schema variable 

zc = ( dc, x c),

where dc specifies the discrete template choices and xc specifies the continuous geometric parameters. Given zc, the instantiation function Φc constructs an object mesh 

Mc = Φ c(dc, x c).

During generation, we save both the full schema variable zc for reproducibility and the compact schema vector 

gc = Ψ c(zc)

as the schema annotation used for network supervision. 

Discrete template choice sampling. We first sample the discrete variables dc from the valid template choices of each category. These variables determine which semantic part templates are instantiated. For example, in the mug category, we sample the body type from cylindrical, prismatic, or multilevel templates, and sample the handle type from curved, trifold, or none. Similar optional or alternative templates are used for other categories, such as the lid of bottles, pull ring of cans, base of bowls, connector of laptops, and accessory parts of cameras. If a template is set to none , the corresponding part is not instantiated and its compact schema slots are zero-padded. 

Continuous parameter sampling. After the active templates are selected, we sample their continu-ous parameters from category-specific valid intervals. These parameters control object dimensions, proportions, thicknesses, offsets, rotations, and part attachment geometry. For a parameter xj , we sample 

xj ∼ U (lj , u j ),

where lj and uj are defined in the schema configuration. Some bounds are conditional on other sampled parameters. For example, inner radii are constrained to be smaller than outer radii, wall thickness is constrained by the corresponding body extent, and optional-part offsets are constrained to keep the part attached to the supporting body. 16 Rendered RGB Training Images (135K in total)

Structure-preserving variation. To increase intra-category diversity, we vary schema parameters at three levels. First, we vary global object proportions, such as height, width, depth, and overall scale. Second, we vary part-level geometry, such as bottle neck size, bowl opening radius, laptop screen angle, camera lens length, or mug handle size. Third, we vary structural configuration through template choices, such as switching between different body or handle templates. These variations are applied within category-specific constraints so that the generated objects remain valid instances of the target category. 

Validity checking. Each sampled schema variable is checked before export. We reject or resam-ple objects with invalid geometry, including non-positive dimensions, invalid inner–outer relations, excessive thickness, degenerate levels, disconnected optional parts, severe primitive interpenetra-tion, or floating components. This step prevents unrealistic meshes caused by extreme parameter combinations. 

Mesh export and metadata. For each valid object, we export the mesh in the category canonical coordinate system. We also save its category label, full schema variable zc, compact schema vector 

gc, object scale, and reference scale. The compact vector gc is computed by selecting pose-relevant schema factors, normalizing continuous parameters by category-specific reference scales or valid ranges, and zero-padding inactive optional-part slots. 

B.2 Compositional Scene Rendering 

Given the generated object pool, we use BlenderProc to render RGB training images. The goal is to construct cluttered multi-object scenes that expose the network to diverse object poses, layouts, occlusions, and appearance conditions. 

Scene initialization. Each training scene is initialized with a supporting surface, such as a table plane or a floor-like plane, together with a background environment and rendering assets. We randomize the supporting surface geometry and its material appearance so that the rendered scenes 17 do not overfit to a fixed tabletop texture or color. The scene may also contain additional non-target objects or background clutter, depending on the rendering configuration. 

Object subset sampling. For each image, we sample a variable number of generated objects from the object pool. The sampled objects may come from different categories, which produces mixed-category scenes. For each sampled object, we load both its mesh and its metadata, including category label, full schema variable, compact schema vector, and canonical size. This ensures that every rendered instance remains associated with its structural annotation throughout the rendering process. 

Physics-aware object placement. After object sampling, we place the objects into the scene in a physically plausible manner. Concretely, each object is first assigned a random initial position above the supporting surface and a random initial orientation. We then use BlenderProc’s rigid-body simulation to let the objects settle under gravity until a stable scene configuration is reached. This step automatically resolves many unrealistic placements and produces natural object contacts and occlusions. To avoid degenerate scenes, we reject configurations with severe object interpenetration, unstable placements, or an excessive number of objects falling outside the camera view. 

Pose and scale variation. Before or during placement, each object is additionally assigned random scale and pose variation within category-consistent limits. The scale variation is applied to simulate intra-category size diversity, while the 3D rotation and translation are varied to cover a broad pose distribution. Since these transformations are applied to schema-generated objects whose canonical geometry is already known, the final rendered pose labels remain exactly aligned with the instantiated mesh. 

Layout diversity and occlusion control. To improve robustness to cluttered scenes, we explicitly vary the number of objects, their relative distances, and their degree of overlap. This produces images ranging from isolated-object cases to heavily cluttered scenes with partial occlusion. During rendering, we keep only visible instances whose projected area exceeds a minimum threshold and whose truncation is not excessively large. This avoids adding nearly invisible objects as noisy supervision. 

Camera sampling. We sample the camera pose around the scene by varying azimuth, elevation, and distance relative to the object layout region. The camera is oriented toward the scene center so that most sampled objects remain within view. For each rendered image, the intrinsic matrix K and the camera extrinsic parameters are recorded. This allows us to export pose labels directly in the camera coordinate system and to train the network under the same monocular RGB setting used at test time. 

Appearance randomization. To reduce the domain gap between synthetic and real images, we randomize multiple rendering factors independently of the schema parameters. These factors include: • light source type, position, intensity, and color; • material properties such as roughness, metallicness, and specularity; • object colors and surface textures; • background appearance and environment illumination. This decouples structural variation from appearance variation, so that the generated dataset covers both shape diversity and rendering diversity. 

Rendering outputs and annotation export. For each scene, BlenderProc renders an RGB image together with instance-level visibility information. Since the complete scene state is known, we export for every visible target object its category label, 2D bounding box, segmentation mask, 3D rotation, 3D translation, and 3D size. In addition, the compact schema vector gc is directly inherited from the object metadata generated in the previous stage. Therefore, the rendered training images provide aligned supervision at both the pose level and the schema level. 18 Filtering and quality control. After rendering, we apply a final filtering step to remove low-quality annotations. Specifically, an object instance is discarded if its visible area is too small, if its projected bounding box is below a minimum size, or if the visible portion is too heavily truncated. This filtering prevents extremely hard or ambiguous synthetic samples from dominating the supervision signal. 

B.3 REAL275 Schema Annotation 

In addition to schema annotations generated automatically for SchemaData, we also provide schema annotations for the REAL275 training split to support schema-supervised learning on real RGB images. The annotation is performed only on the REAL275 training objects and does not use any REAL275 test images, test object instances, or test annotations. For each REAL275 training object, annotators assign the discrete template choices and continuous schema parameters according to the predefined category schema. The annotation follows the same schema definitions used for synthetic object generation. Specifically, annotators first select the part templates that best match the object structure, and then adjust the continuous parameters so that the object instantiated from the schema is as close as possible to the corresponding real object model. This process produces a compact schema vector through the same compression function Ψc, which is used as schema supervision during training. REAL275 contains six object categories, with three training object instances per category. In our annotation process, each object takes about 20 minutes on average. Since the annotation is performed at the object-instance level rather than the image level, the resulting schema label can be reused for all training images containing the same object. At inference time, SchemaPose does not require any schema annotation or object model; it predicts the schema vector directly from the input RGB image. 

## C Details of Architecture and Training Configuration 

This section provides additional implementation details for reproducing SchemaPose. Unless other-wise specified, all settings follow the configuration used for the main results. 

C.1 Network Architecture 

Following the design of DINO[29], SchemaPose is implemented with a two-stage query-based detector with box refinement. We use Swin-L[35] as the backbone and initialize the detector from a DINO model pretrained on COCO. The backbone uses an embedding dimension of 192, depths of [2 , 2, 18 , 2] , attention heads of [6 , 12 , 24 , 48] , a window size of 12, and a drop-path rate of 0.2. Feature maps from four backbone stages with channel dimensions [192 , 384 , 768 , 1536] are projected by a ChannelMapper neck to 256 channels and expanded to 5 feature levels. The Transformer encoder and decoder both contain 6 layers. The hidden dimension is 256, the feed-forward dimension is 2048, and the decoder uses 8 attention heads. The sine positional encoding uses 128 positional features. At the proposal stage, encoder-side classification scores and boxes are predicted from encoder output features, and the top-100 proposals are selected by maximum classification score to initialize decoder reference queries. In parallel, SGPH is applied to encoder-side features to produce auxiliary detection, schema, and pose predictions for training. During inference, only the predictions from the last decoder layer are used as final outputs. 

C.2 Schema-Guided Pose Head 

The Schema-Guided Pose Head predicts object category, 2D bounding box, compact schema, pro-jected center, depth, rotation, and 3D size. It is applied at both the proposal stage and the decoder stage. The prediction branches are not shared across decoder layers; each prediction layer has its own branch parameters following the standard DINO-style refinement design. The classification branch is a linear layer from the 256-dimensional object feature to 6 category logits. The 2D box branch is a 2-layer MLP with ReLU activations and predicts a normalized box 

(cx, c y , w, h ). The compact schema branch takes the object feature concatenated with the predicted 2D box as input and predicts a 60-dimensional unified schema vector, consisting of 44 continuous dimensions and 16 discrete dimensions. 19 The compact schema vector is organized as category-wise slots. The continuous dimensions for bottle ,

bowl , camera , can , laptop , and mug are (11 , 5, 6, 7, 7, 8) , respectively. The discrete dimensions are 

(3 , 4, 2, 2, 1, 4) , respectively. During schema conditioning, we construct a category-specific binary mask from the predicted category and keep only the schema slots corresponding to that category. This masked schema vector is then used as the effective structural condition. For pose prediction, the projected center, depth, rotation, and size branches are implemented as MLPs with two hidden layers. The predicted 2D box and the effective schema vector are concatenated to all four pose branches, serving as spatial and structural guidance, respectively. Therefore, all pose-related branches take a 320-dimensional input, formed by concatenating the 256-dimensional object feature, 4-dimensional 2D box, and 60-dimensional effective schema vector. Rotation is represented by the continuous 6D representation [38]. We use class-wise rotation and size heads: the rotation branch outputs 6 × 6 = 36 values, and the size branch outputs 6 × 3 = 18 values. ## D Discussion on Parametric Category Schema 

Schema as a Pose-Oriented Structural Prior. The parametric category schema provides an explicit structural context for category-level pose estimation. In the RGB-only setting, the same image evidence may correspond to different 3D interpretations because object extent, proportions, part layout, and symmetry vary across instances within the same category. Schema makes these factors explicit. Continuous schema parameters describe metric-relevant properties such as object size, aspect ratio, thickness, and part offsets, which help the network reason about 3D scale and translation under monocular ambiguity. Discrete schema variables describe structural choices such as part existence, template type, and coarse configuration, which provide cues for resolving orientation ambiguity caused by symmetry or anisotropic object layouts. This structural information complements visual query features. Without schema, the network must encode category-level commonality, instance-specific shape variation, and pose cues in the same latent representation. This can make pose prediction sensitive to irrelevant appearance details or instance-specific geometry. By contrast, schema separates pose-relevant structure into an explicit 21 intermediate variable. The pose head can then condition its prediction on both visual evidence and structured object information, making rotation, translation, and size estimation more aligned with the category-level 9D pose objective. Importantly, schema is not a fixed prototype or a substitute for visual learning. It represents a parameterized family of valid category instances, while the network still learns to infer schema and pose from RGB observations. Its role is to organize the structural variation that affects pose prediction, so that the estimator does not need to recover all such factors only through unconstrained latent features. 

Expressiveness from Primitive Composition. Parametric Category Schema can comprehensively describe the structural information of various objects encountered in daily life. This expressive power of schema comes from the composition of reusable geometric primitives and semantic part templates. Basic primitives, such as cuboids, cylinders, rings, and other simple parameterized shapes, describe common local geometry, while semantic templates organize these primitives into meaningful object parts. This design follows the observation that many man-made objects can be described as combinations of basic geometric components, where each primitive captures a family of shapes through its parameters and their composition yields diverse object structures[23, 25]. As a reference, PartNet-Mobility [9] is a large-scale articulated object dataset collected from real-world manufacturer-level 3D models, covering substantial intra-category structural variation. For the six pose-estimation categories considered in this work, our parametric category schemas can represent nearly all corresponding instances from Xiang et al. [9] by composing the predefined primitives and part templates with category-specific parameter ranges. This coverage suggests that the proposed schema representation is expressive enough to capture the major structural variations required for category-level pose estimation, while remaining compact and analytically controllable. 

Scalability of Schema Construction. As mentioned above, the strong expressiveness of reusable geometric primitives and semantic part templates enables parametric schema to easily scale to novel object categories. Extending SchemaPose to a new category usually starts by identifying reusable components from the existing part templates, and then specifying category-specific composition rules and parameter ranges. For example, handle-like templates can be reused for mugs, drawers, or containers, while cylindrical body templates can support many container-like categories with different proportions and attachment rules. If the existing library is insufficient, a new template can be implemented by inheriting from existing part templates and invoking basic geometry templates. In our implementation, developing parametric schema for a novel category takes about 2 hours on average. Once implemented, the new templates are added back to the schema library and can be reused by later categories, making the construction process cumulative and increasingly efficient as the library grows, rather than a from-scratch design process for every category. 

Consistency Between Generation and Learning. The same schema formulation is used both for object generation and for network learning. During data generation, the full schema variable specifies template choices, geometric parameters, and analytic relations needed to instantiate valid object meshes. During learning, a compact schema vector derived from the full schema variable provides pose-relevant structural supervision. This consistency is important: the structural variables used to generate synthetic object instances are the same variables that the network learns to infer and use for pose prediction. As a result, schema provides not only a generative specification for constructing diverse training data, but also an explicit intermediate representation that connects image observations with category-level pose estimation. 

## E Limitations and Future Work 

While SchemaPose demonstrates the effectiveness of introducing explicit schema information into RGB-based category-level pose estimation, several directions remain open for future exploration. 

Automatic Schema Construction. In the current implementation, category schemas are designed manually based on geometric primitives, semantic part templates, and category-level structural analysis. This design makes the resulting schema interpretable and directly usable for both object generation and pose prediction. A promising future direction is to reduce the amount of manual design by developing semi-automatic or data-driven tools for schema construction. For example, 22 candidate primitives, part templates, or parameter ranges could be proposed from collections of 3D models or generated instances, and then refined into compact schema definitions with minimal human intervention. 

Expanding the Schema Library. The current schema library is constructed for the object categories studied in our experiments. Since schemas are built from reusable geometric primitives and semantic part templates, the library can be extended cumulatively as more categories are considered. Future work will expand the collection of primitives, templates, and category-specific composition rules, so that a broader range of object categories can share and reuse existing schema components. Such an expanding library would also make schema construction increasingly efficient, as newly defined templates can benefit later categories. 

Improving Synthetic-to-Real Transfer. The schema-driven data generation pipeline provides accurate schema and pose annotations by construction, but the visual distribution of synthetic data can still differ from real RGB observations. Although mixed training and rendering randomization reduce this gap, future work can further improve synthetic-to-real transfer through stronger domain randomization, more realistic material and lighting simulation, or image-level adaptation. This direction is particularly important for making schema-supervised learning more effective in real-world deployment. 

Temporal and Multi-View Extensions. SchemaPose estimates category-level 9D pose from a single RGB image. In many practical scenarios, however, multiple frames or multiple views are available. Extending schema-guided pose estimation to temporal or multi-view settings could provide additional constraints for resolving ambiguity in monocular observations. Since schema represents stable object structure, it can naturally serve as a consistency variable across frames or views, enabling more robust pose estimation under occlusion, viewpoint change, and clutter. Overall, these directions suggest that schema-guided pose estimation is not limited to the current implementation, but can be further developed through more automatic schema construction, richer schema libraries, improved synthetic-to-real transfer, and stronger temporal or multi-view reasoning.
