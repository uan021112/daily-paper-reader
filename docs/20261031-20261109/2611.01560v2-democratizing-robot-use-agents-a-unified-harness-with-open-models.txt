Abstract
Robot-use agents (RUAs) have shown promising zero-shot manipulation capabilities, but re-
liance on frontier, proprietary models limits research into further training. To democratize RUA
research, we introduce uni-robot-agent, a unified harness for competitive open-weight robot
use that supports further training. Without privileged inputs, an out-of-the-box Qwen3.8-Flash-
Next achieves a RoboDojo Score of 31.39, surpassing the published GPT-6 Astra–RoboProbe
result of 28.97 and many VLA/WAM baselines, and performs competitively on 19 real-world
tasks. Our analysis across model generations, families, and sizes links effective robot use to four
general capabilities, suggesting that future RUA training should develop them jointly.

1. Introduction
Recent breakthroughs in frontier foundation models (e.g., GPT-6 Astra (OpenAI, 2026b), Opus
5.5 (Anthropic, 2026)) have shown surprising zero-shot performance in robotic manipulation,
highlighting robot-use agents (RUAs) (Isola, 2026) as a promising approach for robotics (Chen
et al., 2026b; Qu et al., 2026; Zhang et al., 2026b). This approach effectively transfers the models’
generic problem-solving capabilities, such as task decomposition and failure recovery, which
are hard to learn from limited robotics data alone, yet extremely useful for robotics (Chu et al.,
2026; Isola, 2026; Jia et al., 2026).
However, because these frontier foundation models are proprietary, research on RUAs has
been limited to using the models as-is, such as harness design (Li et al., 2026; Si et al., 2026;
Zhang et al., 2026b). Without access to their weights, researchers cannot directly explore how
further training of these models can advance RUA capabilities. Moreover, API dependence
makes large-scale interaction costly (OpenAI, 2026b) and restricts model-level optimization,
such as efficient caching, despite inference speed being a major bottleneck for RUA (Isola, 2026).
The main challenge in adapting open-weight models for robot use is the capability gap
between open-weight and closed-weight foundation models. Robot use demands strong spatial
understanding and agentic capabilities, which existing open-weight models often lack. Con-
sequently, prior work has focused on ad-hoc improvements, including leveraging privileged
information such as ground-truth simulator states or oracle task-success feedback (Fu et al., 2026;
Zhang et al., 2026c), or incorporating task-specific skills (Lu et al., 2026). Before attributing these
limitations to the models themselves and pursuing ad-hoc improvements, we argue that we
must first establish a generalizable and effective robot-use harness to systematically understand
and maximize their existing capabilities, laying the foundation for future RUA training.
In this paper, we take a first step toward democratizing robot-use agent research by laying
this foundation for both competitive open-weight agents and future robot-specific training. We
introduce uni-robot-agent, a general-purpose RUA harness. It provides Unified tool interfaces
and feedback formats across models, embodiments, tasks, and environments, supporting joint
training on simulation and real-world interaction data. For future large-scale training, we em-
phasize Efficiency by overlapping model reasoning with tool execution to accelerate interaction,
and Modularity through interchangeable agent runtimes, tools, and robot backends. Together,
these designs provide a scalable, extensible foundation for RUA research.
The proposed uni-robot-agent enables competitive manipulation performance with open-
weight models, including Qwen and DeepSeek, in both simulation and physical environments. A
key finding is that well-structured information, such as camera calibration and robot descriptions,
together with reliable tool interfaces that provide informative feedback, are sufficient for
effective robot use. As a result, without privileged inputs, Qwen3.8-Flash-Next with uni-robot-
agent achieves a Score of 31.39, surpassing GPT-6 Astra’s result (28.97) on RoboDojo (Chen
et al., 2026a) from the RoboDojo team (Zhang et al., 2026a). To the best of our knowledge,
this is the first system to outperform closed-weight foundation models on RoboDojo using
open-weight models, without privileged informations or distillation from those closed-weight
models. In real-world experiments on 19 tabletop manipulation tasks, Qwen3.8-Flash-Next with
uni-robot-agent achieves a Score of 53.50, outperforming Dream-1 (43.50; Dream Labs, 2026)
and matching fine-tuned 𝜋0.5 (47.75; Physical Intelligence et al., 2025).
Having established the competitiveness of open-weight RUAs, we further compare models
across generations, families, and sizes to investigate the capabilities underlying robot use.

2. uni-robot-agent: A Unified and Modular Harness
In this section, we introduce the key mechanisms of uni-robot-agent. We describe how the
harness connects diverse agents, robot environments, and embodiments through shared tools
and supports interaction based on information only available in real-world deployments.
2.1. System Overview
uni-robot-agent connects different agent runtimes to a shared toolkit for simulation and physical
robots. The agent selects operations using task instructions and observations, while the harness
executes them and returns feedback. We organize this interaction around four principles:
5


• Unified. Shared tools give operations and feedback a common meaning across environ-
ments, with adapters handling native APIs (Section 2.2). The resulting interaction records
can also be combined for subsequent training.
• Efficient. Reasoning should overlap physical execution, while operations that share a
resource retain their required order (Section 2.3).
• Realistic. Agents and tools should rely on information available in physical deployments,
without simulator-provided depth or task-verifier feedback (Section 2.4).
• Modular. Explicit interfaces should allow researchers to replace runtimes, tools, and
perception models independently. We introduce this architecture below.
These principles guide how we organize the system, but reliable interaction also requires
care in how observations, actions, and feedback are handled. We first describe the architecture,
then examine these practical design choices in Section 2.5.
Modular Architecture.
A tool call passes through five layers with explicit interfaces (Fig-
ure 2). The agent layer manages model interaction and context, passing tool requests to the
orchestration layer for scheduling and dispatch. The tool layer implements shared robot
operations and accesses environment, perception, and action-model capabilities through the
service layer, which manages their runtime resources. The backend layer supplies the concrete
simulator, robot, and model implementations used by these services. Results return through
these interfaces to the agent, completing the interaction.

2.3. Efficient Execution
The orchestration layer determines how agent interaction proceeds while tools are running.
Waiting for every movement to finish delays reasoning that could proceed independently, yet
successive movements may still need to execute in order. We combine background tool calls
with resource-aware scheduling to satisfy both requirements, forming a pipeline between agent
reasoning and tool execution.
Two Levels of Concurrency.
The agent need not wait for every tool, but its next call may still
need to wait for a resource:
• Between agent and tools. A background call returns a job handle, allowing the agent to
continue independent reasoning and retrieve the result later; an immediate call waits for
completion. Decisions that depend on the result must still wait.
• Among tool calls. Calls sharing an exclusive resource execute in submission order;
parallel calls run outside that queue. Two move calls on the same resource therefore
run sequentially, while reading an existing snapshot can overlap movement.

2.4. Interaction Without Privileged Inputs
Efficient execution alone does not ensure that simulation performance carries over to physical
robots: the information supporting each action also matters. Existing systems provide depth-
based geometry and completion checks (Li et al., 2026), or construct object models to maintain a
virtual scene (Wang et al., 2026). In physical settings, depth measurements can vary or be missing
even in a static scene, and simulator task-verifier feedback is unavailable. These differences
motivate testing whether agents can infer spatial relationships and assess progress from more
limited observations.

Keeping Observations and State Consistent.
When a robot moves after an image is captured,
interpreting a selected pixel using a newer camera pose mixes two physical states. We bind
images, camera calibration, and robot state to an immutable snapshot and use that snapshot for
localization (Figure 5a). The agent and tools thus work from the same recorded state.
Preventing Repeated Actions After Communication Failures.
The agent must also know
which actions have occurred: a missing reply may mean lost feedback, so retrying could repeat a
physical action. We record request identities and execution status to reject duplicates (Figure 5b).
If completion is uncertain, further actions are blocked while the session attempts to recover the
execution record; unresolved requests remain explicitly marked as uncertain.
Coordinating Motion and Gripper Control.
Separate movement and gripper commands
prevent the agent from adjusting the opening during a movement. Our move tool accepts a
target pose and an optional gripper opening together, allowing the arm and gripper to act
simultaneously (Figure 5c).
Detecting When Motion Should Stop.
During execution, a fixed step count may stop motion
too early or waste steps on an unreachable target. Our move tool generates intermediate targets
8


from measured poses and checks progress after each step (Figure 5d). This lets the tool adjust
motion locally, stop on arrival, and return control when motion stalls or reaches an execution
limit. Appendix D gives the algorithm and stopping criteria.
Making Action Outcomes Diagnosable.
Reaching a target pose does not establish that an
object was grasped or placed successfully. We return numerical motion feedback, including
pose errors and stopping reasons, alongside images of the outcome (Figure 5e). The numbers
distinguish a small residual error from rejected or stalled motion; the images show the effect
on the object. Together, they help the agent decide whether to refine the motion or change its
manipulation strategy.
Managing Growing Visual Histories.
This feedback accumulates, but old images may lose
relevance while task instructions and action records remain useful. Our sliding window replaces
old images with text placeholders, preserving recent images and the surrounding text (Figure 5f).
We evict images in batches to keep the prompt prefix stable between evictions and support cache
reuse. If the context still exceeds budget, we compact the history with the same model that we
use for the policy, using the compaction prompt of the codex CLI (OpenAI, 2026a).
3. Can Open Models Use Robots in Simulation and the Real World?
Effective robot use has largely been the preserve of frontier, closed-source models. In this
work, however, we show that open-weight models can also achieve competitive performance in
simulation and on physical robots. In particular, on RoboDojo, Qwen3.8-Flash-Next surpasses
most fine-tuned VLA and WAM baselines in a zero-shot setting without privileged information,
and also the GPT-6 Astra’s result reported by the RoboDojo team. On real robots, a less-explored
setting in prior works, open-weight models also achieve competitive performance, showing
their real-world applicability. These results highlight the viability of open-source robot-use
agents and the importance of a properly designed harness for supporting these models.
3.1. Simulation Evaluation
3.1.1. Setup
We evaluate 42 RoboDojo (Chen et al., 2026a) tasks spanning generalization, memory, precision,
long-horizon execution, and open-vocabulary instruction following. We report the success
rate and the score (incorporating partial success, scaled to 0–100) following the RoboDojo’s
evaluation protocol. The result is averaged over three seeds with two layouts (six episodes per
task, 252 episodes in total). Appendix G examines Score stability across rollout counts. The 12
generalization tasks pair equally weighted standard and randomized layouts per seed to test
robustness to object and scene changes. Following the official protocol, we average the results of
each task within the dimension, and average those results over the five dimensions. We allow
up to 3h of wall-clock time per episode, as aggregate performance largely plateaued by the third
hour in four-hour runs.
No Privileged Inputs. Our simulation uses the inputs of realistic robotics applications,
providing only RGB images and camera calibration, robot proprioception and descriptions, and
task instructions. We do not allow access to ground-truth depth from simulators, CAD assets of
the object, hidden scene annotations, task-verifier feedback, and external web access. We also
manually check that the models did not made any invalid access to the prohibited information

3.2. Real-World Evaluation
3.2.1. Setup
We design an in-house benchmark with 19 tasks across five equally weighted dimensions: spatial

4. What Capabilities Enable Robot-Use Agents?
The results in Section 3 establish the feasibility of robot use with open-weight models, but leave
an important question: what enables these models to work? To investigate this, we examine
three comparisons. First, we revisit earlier model generations, including Qwen3.5–3.7 and
GPT-5.6. Second, we compare recent models from different families, including Qwen, DeepSeek,
GLM, and GPT. Third, we examine Qwen models of different sizes within the same generation.
We evaluate the additional models on RoboDojo’s 42 tasks and report SR and Score using
the same aggregation as Section 3. We reuse the Section 3 results for Qwen3.8-Flash-Next,
DeepSeek-V4.1-Flash, and GPT-6 Astra. The additional evaluations use one seed and one layout.
4.1. Performance Across Generations, Families, and Model Sizes

4.2. Four Major Failure Modes
Our trajectory analysis identifies four major failure types: general visual understanding, such
as misinterpreting objects or action outcomes; fine-grained pointing and spatial grounding, such
as selecting inconsistent corresponding points across views; localization and pose computation
code, involving errors in geometric calculations, coordinate transformations, or orientation
construction; and embodied reasoning, such as proposing physically inappropriate grasp poses.

corresponding features. Task performance tends to be negatively associated with this failure

task success. GPT-6.1 Sol achieves the lowest spatial-grounding failure rate among the evaluated
models (31.5%), but this substantial remaining error rate highlights precise spatial grounding as
a common challenge for further improvement (Figure 8b).

Coding in geometry
Coding skill is also closely correlated with task performance, as illustrated
by geometry computations involving coordinate transformations and orientations. Earlier Qwen
models frequently reverse coordinate transforms or mix quaternion conventions, with such
errors affecting 47.3–81.8% of executed calculations across the earlier Flash and Plus cohorts. In

Embodied reasoning.
Beyond perceiving and computing a target pose, robot use requires
embodied reasoning to propose appropriate interactions, including grasp poses. Because this
broad capability is difficult to measure, we restrict our analysis to pick-and-place and use
GPT-6 Astra to assess whether proposed grasp poses are physically reasonable. We report the
rate at which the model proposed unnatural or infeasible grasping poses and failed to correct
them in these tasks (Figure 8d). To our surprise, even recent models can lack this capability:
GLM repeatedly fails to reorient its wrist for grasping, contributing to many unsuccessful trials
and a 26.2% error rate. Such errors are less frequent in newer Qwen and GPT models, which
more often select appropriate grasp orientations. However, the grasp-pose proposal is only
one instance of embodied reasoning. GPT-6 Astra still struggles with other skills, including
bimanual coordination, where inappropriate interaction plans limit performance. Embodied
reasoning therefore appears to improve across model generations, but remains a substantial
bottleneck beyond this narrow grasping analysis.
In conclusion, these failure patterns suggest that effective robot use draws on a combination
15


of visual understanding, spatial grounding, geometric coding, and embodied reasoning, rather
than a single robot-specific capability. This suggests that general model capabilities provide
a substantial foundation for robot use. We therefore argue that future RUA training should
develop these capabilities jointly – for example, by using robot data to construct training tasks
targeting each capability – rather than focusing solely on fitting action outputs.
4.3. Relationship to General Model Capabilities
Having identified four key capabilities underlying effective robot use, we next ask: To what
extent can these capabilities be captured by existing foundation-model benchmarks?
To investigate this, we compare RoboDojo performance with scores on four corresponding
benchmarks: MMMU-Pro (Yue et al., 2024) for general visual understanding, ERQA (Gemini
Robotics Team et al., 2025) for embodied reasoning, ScreenSpot-Pro (Li et al., 2025) for spatial
grounding, and LiveCodeBench v6 (Jain et al., 2024) for code generation (Figure 9). We observe
positive correlations across all four benchmarks, with particularly strong correlations for em-
bodied reasoning and general visual understanding, while spatial grounding exhibits a weaker
correlation, potentially because ScreenSpot-Pro evaluates 2D screen-based grounding rather
than the 3D spatial grounding required for robotic manipulation. These findings further support
the role of general-purpose model capabilities in robot use, suggesting that advances in these
capabilities may translate into improved robotic performance.
5. Analysis on Privileged Information
As discussed in Section 2.4, privileged inputs such as precise simulator-provided depth and
oracle task-success feedback can assist robot interaction. Although uni-robot-agent operates
without these inputs, it remains important to understand how much they affect robot-use per-
formance. We first challenge whether depth, a commonly used source of geometric information,
is necessary for better performance (RQ1). Second, since skill libraries can encode privileged
information or task-specific solutions, we ablate our skill library to test whether performance
depends on such a leak of privileged information (RQ2).
5.1. RQ1: How Does Depth Affect Robot Use?
We compare three levels of geometric information for depth: RGB images with depth and
camera parameters, RGB images with camera parameters, and only RGB images. With depth
and camera parameters, the agent can infer 3D coordinates directly from the pixel. Having
only camera parameters requires the agent to find the pixel of corresponding points in multiple
cameras. Without either, the agents should infer the coordinates through spatial relationships
of the objects in the image. We evaluate GPT-6 Astra and Qwen3.8-Flash-Next on the same 42
benchmark tasks. The evaluation uses three seeds and two layouts per task for Qwen and one
seed and one layout per task for Astra due to limited evaluation costs.
Without depth, agents can still recover object positions with the camera parameters by
triangulating the corresponding points across views. Evidently, Astra’s score changes from
55.83 to 55.04, and Qwen’s score changes from 35.89 to 31.39, retaining 98.6% and 87.5% of
their depth-enabled scores, respectively (Figures 10a and 10b), reflecting a minimal loss in
performance, especially with stronger model capabilities. The cases in Appendix E further
show that Qwen writes and executes its own geometry code to infer 3D coordinates, such as
triangulating object positions across views and testing candidate table heights with the images.

7. Related Work
Vision-Language-Action and World-Action Models.
Vision-language-action (VLA) models
extend robot policies beyond task-specific demonstrations by transferring pretrained visual-
language representations and learning from diverse robot data (Brohan et al., 2023; Kim et al.,
2024). Training on heterogeneous sources has further improved generalization: 𝜋0.5 performs
manipulation in previously unseen environments by combining robot experience with semantic
supervision and web data (Physical Intelligence et al., 2025). World-action models (WAMs)
explore a complementary route through predictive modeling. Joint video and action generation
enables DreamZero to generalize to unseen tasks and environments (Ye et al., 2026), while
Cosmos Policy uses predicted future states and values to support test-time planning (Kim et al.,
2026). These advances broaden where learned policies can operate and what behaviors they can
perform. Reliable use of past observations and recovery from failures over extended interactions
nevertheless remain important areas for further investigation.
20


Tool-Using Agents for Robot Control.
Tool use allows language models to organize decisions
around observations and feedback. In computer environments, agents operate graphical inter-
faces through repeated observation and action, combining visual grounding with planning and
context management (Agashe et al., 2025; Anthropic, 2024; Wang et al., 2025). Robotics research
has explored related ideas through skill selection and programmatic composition of perception
and control APIs (Ahn et al., 2022; Liang et al., 2022). Environment feedback enables replan-
ning (Huang et al., 2022), while spatial representations connect language instructions to physical
motion (Huang et al., 2023). Together, these studies establish ways for general-purpose models
to direct interaction through tools. In robotics, this interaction must also account for a world
that changes while actions are running, making the coordination of observation, reasoning, and
execution a central concern.
Robot-Use Agents and Harnesses.
Recent studies show that general-purpose multimodal
models can operate robots through tools without task-specific robot training (Isola, 2026; Zhang
et al., 2026a). This has prompted efforts to design the harness through which a model observes
the scene, issues actions, and receives feedback. RoboDawn and Robo-Harness K1 provide
motion and geometric perception tools (Guo et al., 2026; Li et al., 2026), while OpenRUA gives
coding agents access to native ROS 2 interfaces through a terminal (Chu et al., 2026). Beyond
these interfaces, Harness VLA and GAP investigate how agents can guide learned policies
through memory-based planning and corrections to policy-generated actions (Su et al., 2026;
Zhang et al., 2026c). ORA also demonstrates robot use with open-weight models, combining
robot tools with environment information and context management (Yang et al., 2026). As
robot use expands to more models and environments, reusing these components becomes an
important system-design question. We develop uni-robot-agent around this need, separating
shared robot tools from model runtimes and environment adapters so that changing one does
not require rebuilding the others. We also coordinate tool execution and feedback to let agents
continue reasoning while physical actions are underway.
8. Conclusion
We presented uni-robot-agent, a unified and modular harness with efficient execution and
reliable tools for robot-use agents. Evaluations demonstrate strong performance with GPT-6
Astra in both simulation and real-world manipulation. More importantly, our results show
that an open-weight model can also achieve strong robot-use performance: Qwen3.8-Flash-
Next reaches a RoboDojo Score of 31.39, exceeding the published Astra–RoboProbe result of
28.97. These findings support further investigation of open-weight models that can be deployed
locally and adapted through training on robot experience. Precise manipulation and reliable
long-horizon execution remain challenges in our evaluations. By providing shared interaction
interfaces, replaceable components, and structured execution feedback, uni-robot-agent offers
a unified foundation for collecting robot interaction data, developing training methods, and
evaluating their effects on agent behavior and task performance.

A. Experimental Setup and Reproducibility Settings
Simulation benchmark and baselines.
RoboDojo provides 42 tasks in Isaac Sim (Chen et al.,
2026a). We compare agent harnesses using Qwen3.8-Flash-Next as the planner. GPT-as-Policy
(GAP) (Su et al., 2026) uses its hybrid configuration with 𝜋0.5; RoboProbe (Zhang et al., 2026a) and
RPent (Zhang et al., 2026c) use their default configurations. Table 1 also includes the published
Astra–RoboProbe results and representative vision-language-action (VLA) and world-action
models (WAM) from the RoboDojo leaderboard (RoboDojo Team, 2026).
Reasoning effort.
We use medium reasoning effort for GPT-6 Astra, high for both GPT-5.6 Sol
and GPT-6.1 Sol, xhigh for all Qwen-series Models, and max for DeepSeek-V4.1-Flash.
B. Real Eval Benchmark Details
Real Eval evaluates tabletop manipulation on a dual-arm gripper platform through five capa-
bility dimensions: spatial understanding, object generalization, instruction following, compositional
generalization, and unseen tasks. Its test catalogue contains 19 evaluation entries, with 20 points
allocated to each dimension and 100 points in total. An evaluation entry specifies an opera-
tion together with the variation being tested: bowl stacking, for example, appears both as an
object-generalization test and as a direction-following test. The catalogue therefore distinguishes
changes in objects, language, and task structure even when they share a manipulation primitive.
Table 3 gives the complete test catalogue and its scoring criteria.
B.1. Hardware and Baselines
All methods run on an ARX AC one dual-arm platform with two X5 arms and three Intel
RealSense D405 cameras, comprising a head view and a wrist view on each arm. We evaluate
uni-robot-agent with GPT-6 Astra and Qwen3.8-Flash-Next as planners and compare both
configurations with 𝜋0.5 (Physical Intelligence et al., 2025), fine-tuned on demonstrations from
the same platform. We also include Dream-1 (Dream Labs, 2026), a world action model evaluated
zero-shot through its public API (dreamlabs/dream-1-beta). In the real-world evaluation,
uni-robot-agent additionally uses the D405 depth stream, whereas 𝜋0.5 and Dream-1 natively
consume only RGB images.
B.2. Training Task Catalogue and Collection Protocol
The accompanying training catalogue lists 30 task templates and 1,550 trajectories: 27 templates
specify 50 trajectories each, while bag zipping, coin insertion, and tissue extraction specify
100, 80, and 20, respectively. The templates span stacking and sorting, object transfer and
handover, container loading, cloth manipulation, surface wiping, and operation of buttons,
switches, drawers, and a microwave door. Collection protocols vary object placement, material,
color, container arrangement, and table appearance at task-specific intervals. For example,
paper-cup stacking uses four to six inverted cups at different positions, changes cup material
every five trajectories, and changes the table mat every ten. Test-tube transfer uses three to
four tubes of different sizes and reverses the transfer direction every five trajectories. Cloth
folding includes two folds per trajectory, changes cloth orientation every three trajectories,
and changes the cloth every six. These collection settings establish the reference operations
and variations against which the test catalogue defines new objects, instructions, and action
26


combinations. The catalogue is collected to fine-tune end-to-end embodied policies such as 𝜋0.5,
whereas uni-robot-agent does not use any of these demonstrations; for uni-robot-agent, every
entry is therefore evaluated zero-shot, and the five dimensions characterize the type of variation
that each entry introduces.
B.3. Evaluation Dimensions
Spatial understanding.
This dimension includes one simple entry (fruit transfer), two interme-
diate entries (cloth folding and plate extraction), and two complex entries (test-tube transfer and
mug hanging). Fruit transfer moves cherries, bananas, apples, oranges, and melons from bowls
or plates into a basket. Cloth folding varies size and orientation. Plate extraction requires one
arm to lift a bottle while the other removes and stacks the plate beneath it. Test-tube transfer and
mug hanging further distinguish acquiring an object from completing the subsequent placement.
Object generalization.
The operation remains bottle handover or bowl stacking while the ma-
nipulated objects change. Handover introduces tea, coconut-water, and bottled-water containers,
together with handled stainless-steel and plastic cups. Bowl stacking introduces stainless-steel
bowls, small and large paper bowls, ceramic bowls, and large salad bowls. These variations
probe differences in shape, size, material, and available grasp geometry.
Instruction following.
Three tests separate color, object, and spatial-language grounding.
Color-conditioned cup stacking places two or three differently colored cups on the table and
specifies which color should be stacked onto which other color. Object-conditioned pick-and-
place uses a toy car, five fruit types, blocks, and three tableware types, with bowls, plates,
and baskets as target containers. Direction-conditioned bowl stacking requests left-to-right
or right-to-left arrangements. These tests evaluate whether a physically feasible operation is
directed toward the requested object, destination, and spatial relation.
Compositional generalization.
Four entries recombine familiar operations, objects, and se-
mantic constraints. Tissue extraction followed by disposal chains two actions into one objective.
Stacking upward-facing cups changes the object configuration relative to the inverted-cup train-
ing template. Wiping a whiteboard with a rag combines the wiping operation with an object
used elsewhere in the task catalogue, replacing the whiteboard eraser specified for training.
Arranging cubes by color changes the criterion from the size ordering specified in the train-
ing catalogue. Together, these cases test action sequencing, object substitution, and semantic
recombination.
Unseen tasks.
The final dimension organizes transfer by its relation to the training catalogue.
Closing the microwave door isolates a sub-action of the microwave loading routine. Taking a
bowl out of the microwave and unfolding a rag reverse the corresponding loading and folding
operations. Stacking books is listed as a combined action, while building a three-level Tower of
Hanoi is listed as a new action.

an episode. Uncached and cached input are billed separately. Reasoning tokens are already
included in output usage and are counted only once. Recorded retries are included; requests
without recoverable usage are left unestimated.

D. Monitored Motion Execution
The execution monitoring described in Section 2.5 addresses a basic difficulty in robot control:
issuing a motion command does not establish that the robot has reached its target. Planning
may reject a command, or execution may stop making progress. The move tool therefore
advances through bounded waypoints, checks the state returned after each step, and reports
why execution ended so that the agent can decide what to do next.

def intersect_rays(pairs):
    A=np.zeros((3,3)); b=np.zeros(3)
    for cam,uv in pairs:
        o=center(cam); d=ray(cam,uv)
        M=np.eye(3)-np.outer(d,d)

The depth ablation in Section 5.1 raises a practical question: how does an agent obtain

different ways of constructing localization estimates: matching features across views and testing
geometric assumptions against image evidence.
E.1. Recovering Tube Positions Across Views
In insert_tubes, the agent must place three tubes into a rack. After obtaining image-space
segmentation boxes, it captures additional camera views and writes a Python function to
intersect viewing rays in a least-squares sense. It then selects corresponding tube-cap pixels and
computes their world coordinates. Figure 16 follows one cap: the calculated position reprojects
within 0.46 and 1.94 pixels of the selected points in the two views. This gives the agent a way to
check whether its chosen correspondences agree geometrically.
The cap positions are only the beginning of the manipulation sequence. The agent subse-
quently estimates tube axes, chooses grasp poses, and uses observations and action feedback
to guide lifting and insertion. The episode ends with all three tubes in the rack. Here, code
execution turns image correspondences into coordinates that the agent can inspect and use in its
action planning.

G. Sensitivity to the Number of Rollouts
How many rollouts are needed to obtain a stable aggregate Score? We examine this question
using a depth-enabled Qwen3.8-Flash-Next evaluation, comparing smaller samples with the
full evaluation while keeping the model, harness, and input conditions fixed.
The pool contains 50 rollouts for each of 54 task variants (2,700 episodes): standard and
randomized versions of the 12 generalization tasks, plus the other 30 tasks. All results in this
appendix come from this depth-enabled configuration; the main simulation results in Section 3.1
use no depth.
For each sample size 𝑛= 1, . . . , 50, we independently draw 𝑛episodes without replacement
from each variant and recompute the Score, averaging within each of the five capability dimen-
sions and then equally across dimensions. We repeat the procedure 10,000 times. Figure 20
shows the resulting central 95% range and the full-pool reference of 34.59.
With six rollouts per variant, the mean sampled Score is 34.59, while the central 95% range is
30.65–38.51. Taking the first six recorded rollouts instead, ordered by pass and layout identifiers,
yields 36.55, an upward difference of 1.96 points from the full-pool reference. Thus, a small
evaluation can recover a similar aggregate Score on average while individual subsets still vary
by several points. Increasing the number of rollouts reduces this variation. The shaded range
describes subsampling from the observed pool and collapses at 50 by construction; it does not
directly validate the three-seed, two-layout design used in the main evaluation.
