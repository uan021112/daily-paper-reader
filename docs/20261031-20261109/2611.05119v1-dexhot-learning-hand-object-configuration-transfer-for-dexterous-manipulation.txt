Abstract— Dexterous manipulation involves not only moving
objects, but also arranging the hand around them to main-
tain useful contacts and enable subsequent actions. Yet many
learning-based systems specify goals primarily through object
poses or trajectories, leaving hand–object configurations to
emerge implicitly. We introduce DexHOT, which formulates
dexterous manipulation as hand–object configuration transfer:
moving between feasible configurations that jointly specify hand
articulation and object pose relative to the wrist. DexHOT
learns a reusable relation-conditioned transfer primitive from
synthetic feasible configuration pairs, without human reference
motions, and composes long-horizon behaviors through closed-
loop tracking of configuration subgoals. On DexHOTBench
with 120 objects, a single policy achieves 80.5% transfer
success on seen objects and 69.4% on unseen objects; on a
real dexterous hand, it achieves 61.5% success over 200 real-
robot transfers and 90% task success across six demonstration-

I. INTRODUCTION
Dexterous manipulation depends on both object motion
and hand arrangement. A mug held by its rim, handle,
or body can have the same pose, yet differ in stability,
functionality, and subsequent manipulation options. Object-
state goals cannot express these differences.
Recent learned systems span increasingly complex capa-
bilities, from dexterous grasping [1]–[3] and task-specific
in-hand reorientation [4]–[10] to tool manipulation [11]
and more general dexterous skills [12]–[14], together with
robust sim-to-real transfer under challenging contact dynam-
ics [15]–[19]. Many use target object orientations or pose
trajectories. These compact goals make learning tractable but
leave the hand–object relation implicit: hand configurations
reaching the same object goal can differ substantially in
usefulness for subsequent interaction.

This limitation becomes particularly important in long-
horizon manipulation. Regrasping, tool use, and functional
interaction often require intermediate hand–object configu-
rations that enable the next phase of the task [20]–[23].
Contact-switching behaviors such as finger gaiting [24] can
emerge in object-goal systems [4], [7], [18], but the goal
does not explicitly prescribe the resulting hand configuration,
and discovering these behaviors through exploration remains
challenging [25].
We therefore formulate dexterous manipulation as hand–
object configuration transfer. A configuration specifies the
hand articulation together with the object pose relative to
the wrist, and a transfer seeks to move from one feasible
configuration to another. This changes the unit of goal-
conditioned control from an object state to a hand–object
relation, allowing both object motion and the resulting hand
configuration to be specified explicitly.
Based on this formulation, we present DexHOT, a frame-
work for learning reusable hand–object configuration transfer
(Fig. 1). DexHOT is built on the idea that long-range in-
hand transfers can be composed from short, locally reach-
able transfers. We synthesize diverse pools of physically
feasible configurations, train a single relation-conditioned
controller using local-goal sampling and population-based re-
inforcement learning (RL), and reuse it through hierarchical
chaining of configuration subgoals. The resulting controller
exhibits dexterous skills such as finger gaiting and finger piv-
oting without planner-guided rollouts, an explicit exploration
manifold, or skill-specific supervision during training.
To evaluate configuration transfer directly, we introduce
DexHOTBench, comprising 120 objects with physically
validated configuration pools and fixed transfer pairs span-
ning different distances. The 80 held-out objects contain 40
unseen objects from training categories and 40 objects from
unseen categories. A single policy achieves 73.1% success
averaged over close and far transfers of all 120 objects,
with 80.5% on seen and 69.4% on held-out objects, and
61.5% success over 200 real-robot transfers spanning seen
and unseen objects.
Our contributions are threefold:
• We introduce Hand–Object Configuration Transfer
(HOT), a dexterous manipulation formulation in which
goals explicitly specify both hand articulation and the
relative hand–object pose.

II. RELATED WORK
A. Dexterous Manipulation and Goal Representations
Large-scale sim-to-real reinforcement learning has en-
abled robust in-hand object reorientation on real dexterous
hands [4]–[6], [15]. Palm-up manipulation mitigates object
dropping, a common failure mode in in-hand manipulation,
whereas downward-facing manipulation is more challenging
because gravity increases the risk of object loss [6], [16],
[18]. DexHOT focuses on palm-down transfer, where the
hand must actively maintain the object against gravity. Prior
work has also explored point-cloud policies for object gen-
eralization [19] and sampling-based predictive control [9].
SimToolReal [11] learns a shared tool-manipulation policy
conditioned on object-pose goals and a coarse grasp-region
bounding box, but it does not explicitly prescribe the target
hand articulation. By contrast, DexHOT uses hand–object
configurations that jointly specify hand articulation and the
object’s pose relative to the wrist.
DexterityGen [12] and UniDexFPM [26] also reason at
the level of hand–object configurations. DexterityGen uses
a low-level controller to refine externally provided motion,
whereas UniDexFPM provides a closed-loop interface for
functional pre-grasp manipulation using tabletop support.
DexHOT instead learns configuration transfer directly and
can follow planner-generated configuration subgoals in palm-
down manipulation without a continuous human motion
reference.
Geometry-aware curricula and goal-conditioned grasp
proposals improve generalizable dexterous grasp acquisi-
tion [27]–[29]. Population-based training improves explo-
ration in hand–arm manipulation, including regrasping and
reorientation [30]. DexHOT focuses on a reusable hand–
object configuration interface for continued in-hand manip-
ulation.
B. Hand–Object Interaction Modeling
DexTrack [31] learns a generalizable controller for
tracking human–object reference motions. DexRepNet and
DexRepNet++ explicitly encode hand–object geometry and
spatial relations for dexterous manipulation [32], [33].
Interaction-aware methods such as DexHandDiff [34] like-
wise model contact structure to avoid physically inconsistent
object motions, while FlowHOI and PKDA generate or
transfer hand–object interaction trajectories from human-
centric inputs [35], [36]. TeleDexter [37] also uses hand–
object co-tracking subgoals and trains object-specific con-
trollers from human reference motions. DexHOT instead
learns a shared transfer policy across objects from synthetic
feasible configuration pairs, without demonstrations during
policy training. At deployment, demonstrations provide the
approach, wrist trajectory, and configuration goals.

target that specifies both the hand articulation and the object
pose relative to the wrist. This makes the desired arrangement


of the hand on the object an explicit control objective and
provides a reusable goal interface for manipulation.

IV. DEXHOT
Our key insight is to learn short transfers between nearby
feasible hand–object configurations and compose them into
longer manipulation behaviors. Such local transfers are easier
to discover through exploration, while still requiring nontriv-
ial changes in hand articulation and contact.
DexHOT builds on this insight in three steps (Fig. 2). It
synthesizes dense pools of physically feasible configurations
for each object (Sec. IV-A), trains one policy to transfer
between neighboring configurations in these pools (Sec. IV-
B), and composes the learned transfers through hierarchical
chaining to execute tasks specified by a human demonstration
or a planner (Sec. IV-C). The same pools define DexHOT-
Bench, our benchmark for configuration transfer (Sec. IV-D).
A. Feasible Configuration Synthesis
We construct configurations that stably hold the object,
satisfy penetration constraints, and place it within the hand’s
manipulable region. Each retained configuration can serve as
a training target or reset state.
We use 40 objects from 40 Omni6DPose categories [38].
For each object, BODex [39] optimizes full-hand and finger-
tip grasps from surface-sampled seeds under varied object
orientations, producing pre-grasp, grasp, and squeeze poses.
Following the BODex validation procedure, we filter candi-
dates in Isaac Gym [40] with our training simulation param-
eters and collision geometry, yielding 825,473 configurations
organized into per-object training pools Do.

Population-Based Exploration.
In our setting, a single
proximal policy optimization (PPO) policy [43] tends to
concentrate on a limited set of configuration-transfer behav-
iors, restricting coverage across initial–target pairs even with
many parallel environments. We therefore use EPO [41],
which combines PPO-based updates and shared experience
across 64 exploration blocks with distinct learned 32-D latent
codes and shared network weights. Genetic updates preserve
the designated leader and replace low-fitness follower codes
through elite crossover and Gaussian mutation. In our imple-
mentation, genetic fitness is an exponential moving average
of episode-level transfer throughput: completed transfers di-
vided by control steps. This fitness is distinct from the shaped


return used for policy-gradient learning. For deployment, we
select the policy with the highest empirical transfer success
rate among all 64 blocks, including the leader, and freeze
the shared weights and selected latent code to obtain the
controller πθ in (4). The same selected policy is used across
all objects.
Training Details. The actor uses a single-layer 1024-unit
long short-term memory (LSTM) network, layer normaliza-
tion, and a multilayer perceptron (MLP) with exponential lin-
ear unit (ELU) activations and widths [1024, 1024, 512, 512].
An asymmetric feedforward critic [44] with the same MLP
widths receives noise-free state with privileged joint, fin-
gertip, and object velocities and contact information. Both
networks receive the exploration block’s latent code. Fol-
lowing prior work [11], we randomize object mass, scale,
friction, and restitution, hand friction and link masses, and
joint stiffness and damping; apply random forces and torques
to the object; add noise to object-pose, joint, and fingertip
observations and to actions; delay observations and actions
by zero to two control steps; and ramp gravity from 0.2g
to g at the start of training. The hand is nominally palm-
down; at each reset we additionally apply a random tilt
of up to 30◦to the whole hand–object pair, which varies
the direction of gravity relative to the hand. Training uses
524,288 environments with 60 Hz physics and 30 Hz control.

V. EXPERIMENTS
We evaluate DexHOT in simulation and on real hardware
to assess Any2Any hand–object configuration transfer across
objects and its extension to long-horizon manipulation. Our
experiments address four questions: Q1: How well does Dex-
HOT generalize across transfer distances and objects? Q2:
Which training choices contribute to configuration-transfer
success? Q3: Can DexHOT perform real-world configura-
tion transfer without fine-tuning? Q4: Can the same policy
execute long-horizon tasks from human demonstrations?
A. Experimental Setup
Simulation Protocol.
We evaluate all 40 training and
80 held-out DexHOTBench objects (Sec. IV-D) with one
checkpoint and a fixed latent code, without object-specific
policy weights. Each held-out object uses its own offline-
generated configuration pool for evaluation endpoints and
planner candidates, while the policy weights, latent code,
and planner parameters remain fixed across objects. All
configuration-transfer evaluations use the greedy planner of
Sec. IV-C, with dstep = 50 mm and 1 Hz replanning.
Real-Robot Setup. We use the same 22-degree-of-freedom
(DoF) Sharpa Wave hand as in simulation, mounted on
a 7-DoF Franka Emika Panda arm. Joint encoders and
FoundationPose [45], using a third-person Intel RealSense
D435i RGB-D camera, provide the current configuration
ct in (1). The policy runs at 30 Hz without fine-tuning.
Configuration-transfer trials (Sec. V-D) fix the arm in a
canonical palm-down pose to evaluate finger-driven motion.
In demonstration-guided tasks (Sec. V-E), the arm also tracks
the demonstrated wrist trajectory at 30 Hz while the policy
controls the hand–object configuration.
B. Transfer Range and Object Generalization
Transfer Beyond the Training Band. Table I addresses Q1.
On the 40 seen objects, DexHOT achieves 90.9% success
on Neighbor transfers, 85.5% on close Any2Any transfers,
and 75.6% on far transfers. The close range extends to
70 mm, beyond the local-goal sampling band. Far-transfer
performance evaluates the learned controller with hierarchi-
cal chaining. These results show that training on local goals
supports transfer across the evaluated distance range.
Generalization to Unseen Objects. Averaged over close
and far transfers, success decreases from 80.5% on seen
objects to 74.4% on unseen objects of seen categories and
64.4% on unseen categories. Performance also decreases
with transfer distance in every split: on unseen objects of
seen categories and on unseen categories, Neighbor success
is 88.3% and 81.5%, respectively, while far-transfer success
is 67.3% and 56.7%. The most challenging condition com-
bines an unseen category with a large configuration change.

Population-Based Exploration. The W/O EPO variant re-
places EPO with a single PPO agent [43] at matched en-
vironment counts. Even its best training checkpoint reaches
only 11.5% success on Neighbor transfers and 2.5% on close
transfers, and it completes no far transfer, supporting the
importance of population-based exploration in this setting.
Local-Goal Sampling. The W/O LOCAL-GOAL SAMPLING
variant samples targets uniformly from the full configuration
pool. It performs worse in every distance range, including far
transfers, despite exposure to distant targets. This supports
local-goal sampling as an effective training strategy across
the evaluated transfer distances.
Dataset and Online Anchors. The W/ ONLINE ANCHOR
variant forms neighborhoods around the current configu-

Neighbor success remains high, but far-transfer success drops
from 75.6% to 52.8%, favoring dataset anchoring for distant
transfers. Dataset anchors also avoid online neighborhood
searches.

Failure Analysis. We observed four failure modes: (i) Slip-
page without recovery. On low-friction objects, slips or rota-
tions can develop too quickly for closed-loop adjustment to
recover. Higher-rate feedback or tactile sensing may help. (ii)
Initialization failure. Some configurations established by pre-
grasp interpolation and squeezing (Sec. IV-A) are marginally
stable on hardware and cannot be reproduced accurately
enough to begin transfer. (iii) Stalled reorientation. Progress
stops before reaching the target, possibly due to friction
mismatch, lateral Sharpa-joint motion, or discrepancies be-
tween simulated and physical collision geometry. (iv) Object-
tracking loss. FoundationPose occasionally loses tracking,
leaving no valid pose estimate. More frequent failures on
complex geometries motivate richer shape representations
and improved dynamics modeling and sensing.

Protocol.

(Sec. IV-C) executes six tasks with the same controller.
Each task uses one retargeted demonstration and five trials
from a fixed initial layout. We first follow the retargeted
demonstration trajectory up to its designated pre-grasp frame,
then switch hand control to the frozen policy for pickup and
subsequent configuration transfers. From this frame onward,
DexHOT tracks configuration subgoals in closed loop at
30 Hz, with subgoal updates at 1 Hz, while the arm continues
to track the demonstration-derived wrist trajectory.
Task Suite. Fig. 4 illustrates the tasks. Barcode scanning and
shelf placement rotate a bottle by 180◦, with shelf placement
requiring a pinch-to-power grasp transition. Block assembly
reorients a half-round block to align it with a slot. Salt
shaking turns the shaker dispensing-face down and back up.
Water pouring turns an inverted cup upright to receive water,
and screw driving reorients the drill bit downward.
Evaluation Metrics. We evaluate three equally weighted
task stages: (i) picking up the object; (ii) satisfying the task-
specific object-level constraint, such as directing the barcode
toward the scanner, the cup opening upward, or the drill
bit downward; and (iii) attaining the required hand–object
configuration, including the task-specific hand arrangement.
Task success requires completing all three stages. Stage
progress is the fraction of completed stages, averaged over
the five trials for each task, and is distinct from the geometric
transfer progress in (10). Stage-wise success counts use all
trials as the denominator.

Results and Baseline Comparisons. Table IV reports re-
sults under this criterion. DexHOT completes all three stages
in 27/30 trials (90%), including all trials of shelf placement,
block assembly, salt shaking, and water pouring.
Kinematic retargeting uses a tuned Manus-to-Sharpa map-
ping, followed by trajectory optimization to reduce self-
penetration and hand–object penetration while promoting
temporal smoothness. The resulting joint trajectory is re-
played without closed-loop hand–object correction. This
baseline succeeds at pickup in 24/30 trials but fails to follow
the subsequent hand–object configuration sequence, with
slipping and dropping during reorientation. Neither stage (ii)
nor stage (iii) is completed in any trial (0/30 each).
We evaluate a per-object adaptation of SimToolReal [11],
retaining its joint arm–hand control interface. In contrast,
DexHOT controls the hand while a separate arm controller
tracks the demonstration-derived wrist trajectory. Both se-
tups are evaluated using the same three-stage task criterion.
SimToolReal completes pickup in 21/30 trials and satisfies
the object-level constraint in 9/30 trials. Only 2/30 trials,
both in block assembly, also attain the required hand–object
configuration and satisfy the full three-stage criterion, despite
that configuration not being an explicit policy goal.
The gap between object-level and configuration-level com-
pletion illustrates that attaining an object-pose goal does not
ensure the specified hand arrangement. DexHOT achieves
higher task success under the shared three-stage evaluation
criterion.
VI. CONCLUSION
DexHOT learns reusable hand–object configuration trans-
fers from pairs of nearby, synthetically generated configu-
rations represented by hand keypoints in the object frame.
Hierarchical chaining with greedy planning reaches more
distant goals; demonstration-derived subgoals support tasks
without policy fine-tuning. Averaged over close and far
transfers, simulation success is 80.5% on seen objects and
69.4% on unseen objects; real-robot success is 61.5% over
200 transfers. Together with the six demonstration-guided
tasks, these results support hand–object configurations as a
practical interface for dexterous behavior.
