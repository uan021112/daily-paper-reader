# GeoPilot: Diagnosis-Guided Interventions and Geometric Evaluation for Aerial Reconstruction 

Pengyu Yin, Jie Pan, Junxiang Tan, Mengqi Fu, Kun Cheng, and Yifan Liu 

Abstract —When a mesh reconstructed from aerial remote-sensing imagery disagrees with reference geometry, deciding what to change requires a diagnosis of the reconstruction process. We present GeoPilot, a workflow that turns diagnostics and prior observations into executable program or camera-configuration interventions. A large language model proposes the change, numerical tools reconstruct the mesh, and an external evaluator measures its geometry under a stated coordinate and reference protocol. The main case tests a shared-intrinsics hypothesis pro-posed before the comparison. On 224 Metashape-raster develop-ment images, shared intrinsics improved all six native-coordinate measures and reduced mean surface-to-reference distance by 7.04%. Reference-assisted alignment fitted and evaluated on separate within-scene checkerboard samples reversed the mean-distance ranking, limiting that gain to native-frame delivery. A separate matched comparison on publisher-undistorted images favored fixed published cameras on all six measures, reducing mean distance by 12.11%; the cameras retain upstream image and laser-scanning adjustment information. With one reconstruc-tion per configuration, these comparisons provide conditional evidence for camera handling. Three end-to-end runs each delivered a mesh and six-metric evaluation from all 327 images of a second development scene. 

Index Terms —Large language models, aerial photogrammetry, mesh reconstruction, geometric evaluation, registration sensitiv-ity. 

I. I NTRODUCTION 

Geometric meshes reconstructed from aerial remote-sensing imagery depend on camera calibration, image preparation and surface reconstruction. A reconstruction may complete successfully while its mesh still disagrees with reference geometry. The next change could concern meshing, calibration or image preparation, depending on the suspected cause. COLMAP and OpenMVS provide the numerical components [1], [2]; choosing which component to change requires inter-preting the diagnostics and testing the resulting mesh. The shared-intrinsics case studied here illustrates that deci-sion on the Metashape raster track of Dataset-1, denoted M. The reconstruction assigned a separate intrinsic model to each image of a homogeneous image set. Camera-center residu-als directed attention to calibration flexibility, and the agent proposed sharing intrinsics before the matched comparison.

The shared-intrinsics reconstruction improved all six native-coordinate measures, yet reference-assisted alignment reversed the mean-distance ranking. A useful intervention therefore needs both a reason for trying it and a clear account of what its geometric result supports. We present GeoPilot, a workflow that connects these steps. A large language model (LLM) reads diagnostics, tool de-scriptions and selected prior results, then proposes a checked numerical program or a versioned camera configuration. Nu-merical tools execute the proposal, and an external evaluator measures the delivered mesh under a stated coordinate and reference protocol. Experience entries preserve the change, its outcome and the conditions under which it was observed (Figure 1). Matched camera comparisons provide the main empirical cases. They test a diagnosis-guided configuration change and examine how its interpretation depends on coordinate treat-ment. Restricted-program experiments exercise the checked execution path. Recommendation and optional-review studies, including Jev [3], examine how prior observations and seman-tic checks affect subsequent decisions and complete-system costs. GeoPilot changes numerical procedures and the external context supplied to the agent while keeping model weights fixed. We relate this distinction to recent work on recursive self-improvement [4], [5]. II. R ELATED WORK 

A. Reconstruction tools and geometric evaluation 

GeoPilot uses COLMAP for incremental structure-from-motion (SfM) [1] and OpenMVS for dense reconstruction, meshing and surface processing [2]. DUSt3R estimates ge-ometry through learned pointmaps and alignment [6], while numerical stereo methods adapt sampling and view selection [7]. GeoPilot works at the level of reconstruction decisions: diagnostics guide the configuration and execution of these numerical components. UseGeo already supports depth, point-cloud and triangle-mesh evaluation [8]. Its published analysis includes calibration controls and identifies focal-length estimation as difficult for nearly nadir imagery. Those SfM results use reference-based alignment, including iterative closest point (ICP) with scale, whereas our principal measurements retain native coordinates. The numerical scores therefore answer different questions. Our protocol specifies area sampling, separate forward and reverse reference support, and artifact identities; it does not introduce a new acquisition dataset. B. Configuration search and photogrammetric controls 

A parameter-only program edit belongs to a configuration-search domain. Random search explores parameter combina-tions [11], while photogrammetric factorial studies examine calibration, bundle adjustment and camera-positioning settings [12]. Shared and fixed camera intrinsics are established SfM controls, documented in COLMAP [13]. GeoPilot examines how reconstruction diagnostics motivate a particular interven-tion and how its geometric consequences can be measured under matched inputs. 

C. Agent workflows, feedback and experience 

ReAct interleaves reasoning, actions and observations [14]; Reflexion reuses verbal feedback and episodic memory with-out weight updates [15]. ExpeL extracts natural-language in-sights from successful and failed trajectories [16], while Memp studies the construction, retrieval and updating of procedural memory [17]. GeoPilot supplies curated experience entries that distinguish observations, interpretations and applicability con-ditions. These entries were fixed before the recommendation experiment. AstraLOD3 generates and revises building-specific Python/Blender procedures using images, calibrated cameras and SfM evidence [18]. HiRS-Agent organizes remote-sensing tasks through manager and specialist roles with intermediate verification and trained policies [19]. GeoPilot focuses on aerial reconstruction procedures and external experience. Reasoning occurs in the outer host, while its restricted numerical executor runs without online language-model calls. Commercial spatial agents also organize reconstruction workflows. The SpatialMind user manual describes natural-language task planning, coordination of specialist capabil-ities, local tool execution and artifact lineage. Its aerial-reconstruction example combines image quality checks, bun-dle adjustment, optional control-point marking, reconstruction and reporting [20]. These documented capabilities place task orchestration and result inspection within an agent interface. GeoPilot focuses on the diagnostic basis of specific program or camera interventions and the geometric conclusions supported by matched development comparisons. Dream-RSI updates exploration-policy code using discovery histories [4], and MetaRSI distinguishes changes to data, 3

harnesses and models [5]. GeoPilot modifies checked recon-struction programs or separately versioned configurations and adapters; numerical tools produce and evaluate the resulting geometry. III. G EO PILOT METHOD 

A. Task and system overview 

GeoPilot takes permitted scene inputs, tool knowledge and development observations and returns an executable procedure, an execution trace and, when execution succeeds, a mesh. Figure 2 separates the research agent from the numerical executor. The agent reads diagnostics and development scores, proposes a hypothesis and arranges its test. It can introduce di-agnostic code, a versioned configuration or an adapter. For the shared-intrinsics case, a Codex session and a diagnostic agent examined saved camera models and specified the comparison; fixed scripts then performed bundle adjustment, reconstruction and scoring. The numerical executor runs checked programs without online model calls. Its fixed interface registers 14 parameters for densification, meshing and refinement, including resolu-tion, view counts, support, decimation and face-area limits. P0, P1 and P2 use this interface with a fixed preparation stage. Intrinsic sharing was unavailable there, so the camera intervention uses the outer configuration path, with separately recorded capabilities and guarantees. The recorded hypothesis preceded the A/B test, but the historical controller was not specified prospectively (Supple-mentary Appendices A.1 and A.6). 

B. Evidence and experience for diagnosis 

An experience entry records what changed, what was measured and which inputs produced the observation. Those input conditions determine whether the result is relevant to a later reconstruction. Entries distinguish expected effects from measured outcomes and preserve unresolved alternatives. Tool descriptions identify inherited settings and stage-specific parameters. A history-building component supplies the proposer with earlier programs, their verified evaluation results and tool descriptions. P2 could read the P1 record while P0 remained the retained baseline. The component checks compatible par-ents and evaluation conditions, rejects duplicate candidate identities and preserves the intended history order. The outer workflow can additionally read diagnosis notes and unsuc-cessful research directions. In the camera case, poor reference agreement, camera diagnostics and homogeneous acquisition metadata motivated the shared-intrinsics hypothesis. Experience entries enter the model context without changing its weights. Source versions and the context supplied to each proposal allow later decisions to be traced to earlier obser-vations. The structured proposal interface in Supplementary Appendix A.1 records hypotheses, alternatives and predictions. It was not used in the shared-intrinsics experiment. Camera experience is specific to the image/calibration re-lationship. Shared intrinsics on M concern calibration flexi-bility; fixed cameras on the publisher-undistorted raster track (U) concern using a supplied solution for those pixels. The Dataset-2 packet retains both observations with their distinct input conditions. The recommendation experiment records how this context is used on a subsequent task.

The six measurements answer different questions about the delivered surface. Mean L1 summarizes surface-to-reference distance; root mean square error (RMSE) gives more weight to large distances. Best-90% summaries reveal the influence of the distance tail. E. Optional review and local information routing 

The host can review a proposal or interpretation before accepting it. A reviewer checks evidence support and tool semantics using SUPPORTED, CONTRADICTED or INSUF-FICIENT labels. Contradictions return to the proposer; unre-solved execution prerequisites require evidence. An untested quality prediction can motivate an experiment whose configu-ration passes validation. Review neither produces a geometric score nor expands the restricted executor’s numerical capabil-ities. A separate routing configuration first filters experience by stage, then asks Jev or a full language model to select experience and a read-only diagnostic. The host reads the di-agnostic source and sends the selected context to the common proposer. Unknown experience decisions conservatively retain the candidate set. Routing determines the context supplied to the proposer. Supplementary Appendices A.9–A.11 give the review and routing studies. The complete-system experiment in Section IV-F tests whether savings in review-call time translate into shorter complete episodes. IV. E XPERIMENTAL PROTOCOL

C. Comparison units and numerical implementation 

Each configuration delivers one reconstructed mesh. The million spatially related samples are evaluation queries on one mesh. Five-seed checks resample the same meshes; in-dependent reconstruction replicates were unavailable. We re-port paired raw differences without reconstruction confidence intervals or significance tests. P1 and P2 share the historical P0 score, which is one baseline observation. Their preparation and densification were rerun, so matching upstream settings does not fix realized upstream geometry. Principal scores use common six-metric definitions, ref-erence support and native coordinates. Image participation is checked separately from geometric completeness. Supple-mentary Appendices A.3, A.5 and A.7 account for proposal attempts, reconstructions, scoring invocations and environment differences. Integration fixtures and unscored proposals are excluded from performance comparisons. Reproduction re-quirements and the curated release’s distribution scope are 7

given in Supplementary Appendix A.2. 

Numerical implementation. Preparation uses CPU feature extraction and matching through pycolmap, with a SIM-PLE_RADIAL camera model and separate per-image cam-era entries. The inherited sparse configuration limits feature extraction images to 1600 pixels and features to 8192, uses sequential overlap 5, and adds spatial candidate pairs with at most 10 neighbors and a maximum distance of 10 9 m. Pair sets are united before incremental mapping. These preparation settings were fixed for the program comparisons. OpenMVS undistortion subsequently uses a separate 2400-pixel limit. The sparse reconstruction is fitted to the permitted cam-era centers using a similarity transformation. At least three corresponding centers and nondegenerate centered geometry are required; the transform must have a finite positive scale and a proper rotation. The fit uses the permitted camera centers and has no access to the evaluator’s LiDAR. The resulting transform is applied to mesh vertices on export, while OpenMVS continues to operate on its reconstruction scene. The adapter fixes eight OpenMVS threads and archive type 2. Densification disables estimated-region cropping and tower mode; mesh construction disables region cropping and exports OBJ before conversion to the final PLY. Explicit program parameters are added to these fixed arguments. Unspecified parameters follow the executed tool’s effective configuration. Stage-local settings do not necessarily control later operations: mesh-stage decimation and refinement-stage decimation be-long to different numerical calls. For OpenMVS 2.4.0 [2], mesh.decimate=1 disables that decimation operation; cleanup, hole filling and smoothing have separate controls and are not disabled by this setting. The densification parameter number-views-fuse sets the minimum agreeing-image support during fusion, whereas 

number-views controls depth-map estimation. Changing fusion support can alter the point cloud supplied to subsequent mesh reconstruction and processing, so its effect cannot be interpreted simply as removing erroneous triangles. 

D. Camera and experience comparisons 

For M, A and B start from one sparse reconstruction and reset intrinsics to the same initialization. A retains per-image intrinsics; B shares one intrinsic model. Both fix the principal point and refine focal length, radial distortion, poses and sparse points with identical solver settings. Each receives fresh undistortion, densification at resolution level 1 and meshing with decimation 0.5. Georeferencing uses the same permitted XYZ centers. For U, S-U and F-U share 224 published images, ex-tracted features and matches. F-U fixes published calibration and poses during triangulation; S-U estimates cameras from images. Published XYZ centers support pair selection and subsequent georeferencing where applicable. Both receive fresh downstream reconstruction with identical settings (Figure 4). The undistorted-image limit is 2400 pixels, distinct from the 1600-pixel feature-extraction limit. The complete camera conversion, initialization and model-selection rules are in Supplementary Appendix A.4. Local camera-byte bindings are recorded; the precise publisher-release and coordinate mapping remains uncertified. The Dataset-2 recommendation task was fixed before its F/S geometric outcomes were available. Direct analysis, the GeoPilot procedure without experience and the same proce-dure with experience received identical scene facts, tools and output requirements. Three fresh agent sessions per condition produced nine proposals, with randomized order within blocks. The available actions were F-U, S-U or a hold identifying missing information. No reconstruction score was associated with these recommendations; the subsequent end-to-end ex-periment was a separate study. 

E. Feedback-review validation 

We tested whether a reconstruction-specific rubric improves evidence checking and whether Jev reduces review cost rel-ative to a full language model. Across five separately frozen development batches, 133 live API calls compared MiniMax-M3 (F) with Jev-1.13.0 plus MiniMax fallback (J). Each reviewer used generic (G) and task-specific (T) criteria and re-ceived the same evidence and three-way target: SUPPORTED, CONTRADICTED or INSUFFICIENT. The generic rubric checks evidential sufficiency, internal consistency and executability while distinguishing observa-tions from predictions. The task rubric adds effective tool and stage semantics, inherited settings, numerical predicates, raster/calibration/coordinate consistency, experience applica-bility, complete delivery, geometric measurements and the scope of causal or cross-scene claims. Label definitions are identical. Because the task instructions are longer, the com-parison does not isolate domain content from prompt length. J used one fallback after a call failure or an insufficient answer when a decision was required. The nine researcher-defined questions came from four related historical task fami-lies used during rubric development. Repeated evaluations and two-question diagnostics were not independent samples. The earlier 12-claim shadow pilot, which includes a deterministic-rule comparator, provides historical feasibility evidence (Sup-plementary Appendix A.9). Each batch includes failures and fallbacks. Diagnostic re-runs and repeated questions are reported separately, with reference labels checked against the underlying records by the researchers. Timing includes request preparation, calls, parsing, fallback and response saving, but excludes rubric construction and reconstruction. Supplementary Appendix A.9 gives the batch results and complete timing definitions.

A. Agent-led shared-intrinsics intervention 

Under the per-image SIMPLE_RADIAL preparation, camera-center residuals were meter-scale. Together with the homogeneous acquisition metadata, these diagnostics moti-vated a shared-intrinsics hypothesis, documented before bun-dle adjustment and dense reconstruction began (Supplementary Appendix A.6). The comparison retained separately estimated poses and scene points and used the matched design in Section IV-D. Fresh dense reconstruction and meshing carried the camera change through to the delivered surface. Figure 5 summarizes the post-intervention camera diagnos-tics and native-frame mesh L1. Focal-length estimates vary across the per-image models; B has one focal length because sharing imposes that constraint. Camera-center residuals im-prove for some images and worsen for others, while mean point reprojection error increases from 1.400 to 1.523 pixels. The camera diagnostics therefore do not establish uniform calibration improvement; the delivered mesh must be evaluated separately. All six measures favor shared intrinsics (Table III). Surface L1 decreases by 0.139983 m (7.04%) and RMSE by 0.131085 m (5.48%); precision and completeness increase by 1.446200 and 0.704880 percentage points. The resulting L1 is 1.8497 m, with precision 7.8461% and completeness 3.0695% at 0.20 m. The gain improves agreement with the native-frame reference while substantial absolute residuals remain. C. Spatial evidence for the shared-intrinsics case 

The spatial maps and alignment diagnostic address two ambiguities in the scene-wide scores: where the differences occur and how coordinate treatment affects the ranking. Fig-ure 7 maps stored nearest-LiDAR distances for one million area-uniform samples per fixed mesh, with coordinates re-produced using the original sampling implementation and seed 20260925. Outside it, the mean decreases from 1.760 m to 1.707 m, while the 95th percentile increases from 3.924 m to 4.041 m. Thus the benefit is spatially uneven rather than a uniform correction. More than 99.8% of each mesh’s sampled points lie in 1 m XY cells containing at least one full-reference LiDAR point. Empty horizontal reference cells alone therefore do not explain the widespread large distances in this display. That occupancy proxy does not establish vertically corresponding or visible reference surfaces, and unsigned nearest-point dis-tances cannot separate global displacement, local shape error and reference mismatch. The remaining meter-scale distances require further diagnosis before a useful mapping-quality claim. The alignment diagnostic uses the same A/B area samples and the complete 105,922,149-point LiDAR reference. The sampling design was fixed before new distances were queried: 20 m world-XY checkerboard cells supply 6,000 fitting sam-ples from even cells and 12,000 validation samples from odd cells, drawn separately for each mesh with seed 20260928. These diagnostic fits are neither corrections applied to the reported meshes nor independent estimates of true coordinate offsets. A. Camera handling as a reconstruction decision 

The camera cases return to the decision posed in the introduction: where should the next reconstruction change occur? On M, the diagnosis concerned calibration flexibility, so the matched test compared shared and per-image intrin-sics. On U, the question was whether to reuse an available camera solution, so the comparison first required matching that solution to the pixels and coordinate conventions. Both interventions affected sparse geometry, undistortion and dense reconstruction before the mesh was evaluated. These ob-servations complement the calibration sensitivity reported in UseGeo evaluation [8]. GeoPilot makes the proposed explanation testable by con-necting it to an executable configuration and a matched geometric evaluation. That connection also constrains the conclusion. M improved in the native frame, but the fitted alignment diagnostic reversed its mean-distance ranking; U benefited from supplied cameras that retain upstream adjust-ment information. The results support different camera choices under different development inputs. Their absolute scores do not rank shared intrinsics against fixed cameras because M and U differ in pixels and camera information. 

B. Scope and limitations 

The camera gains concern matched development configu-rations, with one mesh per setting. Fixed-mesh resampling checks measurement variation rather than reconstruction un-certainty. The timestamped outer episode establishes a pro-posal preceding its outcome, but incomplete discovery-cost and backend metadata prevent estimating a discovery success rate. Coordinate and reference assumptions bound the geometric interpretation. Reference-assisted fits reverse the M ordering, so its native-frame gain does not isolate local-shape im-provement. Forward and reverse scores use different supports, the refined region is not a certified visibility mask, and supplied cameras retain upstream image–LiDAR adjustment dependence. The M residuals also remain too large to infer mapping suitability from the relative gain. Texture, radiometry and downstream application tolerances were not measured. 

C. Optional lightweight review 

Faster review calls did not shorten the observed complete episodes. Reconstruction, scoring and coordination dominated their elapsed times, and neither reviewer changed the F-U action. The routing replay matched the rule arm’s first di-agnostic choices but still produced downstream interpretation errors. In one review case, a direct execution fact corrected a decision that model fallback had not resolved. This suggests that acquiring the missing evidence may be more useful than adding another semantic check. VII. C ONCLUSIONS 

GeoPilot makes a reconstruction diagnosis actionable: the agent proposes a program or camera-configuration change, numerical tools execute it, and an external evaluator measures the delivered mesh. The shared-intrinsics hypothesis preceded the matched comparison on Dataset-1 M, where the resulting reconstruction improved all six native-coordinate measures and reduced surface L1 by 7.04%. A separate comparison on identical Dataset-1 U images favored fixed published cameras on all six measures, reducing L1 by 12.11%. Three complete runs each delivered a mesh and full evaluation from all 327 Dataset-2 images. The two camera results support different decisions. Shared intrinsics address calibration flexibility on M; fixed cameras reuse the supplied solution for U. The M gain concerns native-frame delivery, because the spatially split reference-assisted diagnostic reverses its mean-distance ranking. The U result retains the supplied cameras’ upstream image–LiDAR adjust-ment dependence. With one reconstruction per configuration, these are conditional findings for the two development raster tracks.

Algorithm A1. Implemented restricted-program update. 

1. Select the stable parent and read its actual program, diagnostics and valid development score. 2. Assemble the allowed actions, diagnostic definitions, tool knowledge and source-checked history. Keep each attempted child distinct from the stable parent and separate expectations from observations. 3. Request a complete program, hypothesis, expected effect, alternatives, risks and evidence references. For continuation, also request the proposed use of history and observable predictions under supporting and nonsupporting outcomes. 4. Validate program structure and the experiment’s edit domain. Reject unsupported actions, illegal parameters, inconsistent source bindings or out-of-scope changes. Apply the accepted program without rewriting its numerical content. 5. Execute the program on permitted inputs, record the actions and observations, validate the delivered mesh, and record its file hash to identify the evaluated artifact. 6. Evaluate the valid mesh under the parent’s frozen protocol and report all measurements and differences. Apply the declared promotion requirements; where these remain incomplete, retain the stable parent. 17

A program is a finite directed acyclic graph of tool, diagnostic-check and stop nodes. Tool nodes define parameters and success/failure successors; checks define a diagnostic, comparison, threshold and satisfied/unsatisfied/unknown successors. A.4. Camera-control implementation and sources 

A separate development control compares two complete camera-handling strategies on the same 224 publisher-undistorted images, denoted U. Both start from freshly extracted features and the same matched database, using the existing sequential and XYZ-neighbor rules, which yield 1766 distinct candidate image pairs. Feature extraction and matching use CPU execution, seed 917, and the resolution and feature limits in Section IV-C. Each image has a separate SIMPLE_RADIAL camera initialized with focal length 4636.912 pixels, principal point (3970.788, 2602.060) pixels and zero radial distortion. This initialization is tied to the 7953 × 5279 raster; it is not transferred to the differently sized Metashape images. In F-U, the published centers, orientations and calibration define fixed cameras. The adopted world-to-camera rotation is Rcw = diag(1 , −1, −1)( RxRy Rz )T , where the three rotations use the published omega, phi and kappa angles. The pixel-coordinate interpretation is (cx, c y ) = ( x0 +0 .5, −y0 +0 .5) ; the values above already include that offset. Triangulation includes point optimization while camera poses and intrinsic parameters remain fixed. In S-U, a fresh incremental reconstruction starts from the same feature and matching input and initial intrinsics. It estimates camera poses, focal lengths, radial distortion and three-dimensional points, keeping principal points fixed. It receives no published orientation angles or F-U geometry. Camera centers enter shared spatial pair selection and the subsequent similarity fit for georeferencing, so S-U is not a reconstruction without geographic information. The predeclared model-selection order is registered-image count, then point count, then native model ID; it does not use reference scores. 19
