# Abstract 

In many areas of AI, general-purpose models have increasingly replaced handcrafted methods and specialized architectures. We argue that embodied AI is poised for a similar shift. Our key claim is that embodied tasks can be formulated as interaction with digital software. Specifically, we build software that renders an agent’s view of a physical environment on a screen and provides controls for acting in it. A computer-use agent (CUA) can then perform embodied tasks through the same screenshots and keyboard and mouse actions that it uses to operate ordinary software. Using a single CUA design and changing only the software, our entries win first-, second-, third-, and sixth-place prizes across four ECCV workshop competitions, without any competition-specific agent tuning. These results suggest that the skills CUAs learn on software, such as visual grounding, precise clicking, and exploration, already carry over to embodied tasks, giving CUAs a far broader scope in embodied AI than previously realized. We therefore advocate that computer-use agents can be embodied generalists. Further, we advocate that, by following the training strategy that made computer-use agents general, embodied AI can converge on a single general model as well, ushering in a new era of general embodied AI. 1

# 1 Introduction 

In many areas of AI, general-purpose models have increasingly replaced handcrafted methods and specialized architectures (Sutton, 2019; OpenAI et al., 2025; Luong and Lockhart, 2025). We argue that embodied AI, which studies agents that perceive and act in physical environments, is poised for a similar shift (Open X-Embodiment Collaboration et al., 2024; Gemini Robotics Team et al., 2025). In particular, we explore connecting embodied AI with computer-use agents: general-purpose digital agents that operate diverse software applications through screenshots, mouse clicks, and keyboard inputs. Although operating a computer and acting in a physical environment may seem quite different, we observe that both involve similar challenges, including visual grounding, exploration, and adapting actions based on feedback from the environment (Yang et al., 2025a; Zhang et al., 2025a; Huang et al., 2022). Our key insight is that embodied tasks can be formulated as interaction with digital software. Specifically, we construct software that renders observations on a screen and provides controls for acting in the physical environment (Figure 1). A computer-use agent can then observe the environment, take actions, and inspect their consequences using the same interface that it uses to operate ordinary desktop software. Task-specific functionality resides in the software rather than the agent design, allowing us to use existing computer-use agents across different embodied tasks without developing specialized models. To investigate our approach, we develop software applications for four embodied AI tasks: vision-language navigation, dialogue-driven navigation, language-guided 3D segmentation, and referring video segmentation. Beyond these results, we argue that embodied AI can follow the same path that computer use has already taken. Only two years ago, computer-use agents faced the challenges that embodied AI faces today. They struggled to click precisely and relied on overlays or separate grounding models to locate targets (Yang et al., 2023; Zheng et al., 2024; Gou et al., 2025), much as most VLAs today add a dedicated action head for continuous control (Physical Intelligence et al., 2025; NVIDIA et al., 2025). They also lagged far behind agents with task-specific APIs (Xie et al., 2024; Aggarwal and Welleck, 2026c; Song et al., 2025). Today, the same model that writes code and solves mathematics problems can also operate computers by writing click coordinates as ordinary text (Anthropic, 2024; Quiros, 2026), and the strongest agents perform comparably whether they act through the screen or through APIs (NeoCognition, 2026). This progress came from training for precise visual grounding, building environments for reinforcement learning, and making interaction fast enough for real-time use (Gou et al., 2025; Aggarwal et al., 2026b; Wang et al., 2026; Aggarwal et al., 2026a). Each of these has a direct counterpart in embodied AI. Simulators can generate grounding data at scale (Yuan et al., 2024), embodied environments can be used for reinforcement learning (Li et al., 2026), and faster inference can enable real-time control (Black et al., 2025b). Since our approach exposes embodied environments through software, advances in computer-use agents can also transfer to embodied AI directly, and embodied tasks can become part of the training of future general-purpose agents . We therefore believe that embodied AI will converge on a single general model, just as computer use did (OpenAI, 2026c; Anthropic, 2026). 

# 2 Methodology 

Our goal is to provide sparks of evidence for our hypothesis that the capabilities computer-use agents learn on digital software also generalize to embodied environments. We entered four different ECCV workshop competitions, and evaluated a single computer-use agent on their official test sets. We first describe the computer-use agent shared across all four, and then the software we built for each competition.

2.2 VLNVerse: navigation through a 3D scene 

VLNVerse (Lin et al., 2025) requires navigating to a destination described in language. We construct a 3D scene viewer with a first-person image and controls for translation and rotation. The agent moves forward, backward, sideways, or vertically using keyboard shortcuts or on-screen buttons. It can turn, look up or down, and adjust the movement distance and rotation angle. Each operation updates the camera pose and renders a new image. The agent uses these observations to identify landmarks, explore rooms, and approach the target. The same viewer supports the coarse and fine tracks. Selecting the stop control saves the trajectory and final pose. 32.3 DialNav: navigation with a conversational guide 

DialNav (Han et al., 2025) requires reaching a destination through dialogue with a Guide. Our software displays a 360 ◦ panorama, numbered exits to adjacent viewpoints, a target clue, and a message panel. The agent types descriptions and questions, reads the Guide’s replies, and clicks exits to move. A Guide model within the software receives the destination, a scene atlas, and route previews in a separate context. It infers the agent’s location from its descriptions and returns natural-language directions. The agent uses these directions and the panorama to choose each movement. The stop control saves the trajectory and dialogue. 

2.4 OpenSUN3D: language-guided 3D segmentation 

The OpenSUN3D challenge (OpenSUN3D, 2026) uses SceneFun3D (Delitzas et al., 2024) tasks that describe an action and require a 3D mask of the corresponding interaction region, such as a handle for opening a drawer. Our software renders the colored Faro point cloud and provides free-camera movement, rotation, and point selection. Reference videos supply scene context and shortcuts to recorded camera poses. The agent explores the 3D scene, approaches the target, and clicks the relevant component. The renderer maps this click to a visible Faro point. Within the software, PinPoint3D (Zhang et al., 2025b) produces point-prompted masks, while a VOLT model fine-tuned on SceneFun3D supplies affordance-based proposals. The interface displays each candidate from four viewpoints. The agent can refine a selection with positive or negative points, move to another viewpoint, or make a new selection. It then chooses which masks to save, retaining their original Faro point indices. 

2.5 MeViSv2: referring video segmentation 

The MeViSv2 (Ding et al., 2025) text track requires segmenting the objects described by a motion expression throughout a video. Our software provides a video player, a frame selector, and controls for adding, refining, and removing objects. The agent receives the complete video and expression, chooses a frame, and clicks each target. SAM3 (Carion et al., 2025) segments these objects and propagates their masks through the video. The agent receives the complete tracked-mask overlay and can inspect individual frames. It can add positive or negative points, remove an object, or select another object before running propagation again. The save control exports the masks of all remaining objects. A no-target control exports an empty mask sequence. 

# 3 Results 

3.1 Competition results 

The same computer-use agent, with only its software changed, won prizes in all four competitions, spanning navigation, dialogue-driven navigation, 3D segmentation, and video segmentation. It placed first in OpenSUN3D, second in MeViSv2-Text, third in DialNav, and sixth in VLNVerse. We report the official test scores of our competition entries, together with the best other entry in each competition, in Table 1. In OpenSUN3D, the agent finished ahead of every other entry by more than 4 points in AP50 and 10 points in AP25. There, it explored a 3D scan and clicked the exact part to interact with, such as a drawer handle, much as it clicks a small button on a screen. In VLNVerse, the agent placed sixth on success but followed the reference routes more closely than all but two of the 74 entries, with the third-highest NDTW on both tracks. In MeViSv2-Text, it placed second ahead of an entry with a higher J &F , because it more often recognized when no object matched the expression (88.89 versus 83.33 no-target accuracy). Each of these results rests on abilities the agent already uses on digital software, namely locating targets, pointing at them precisely, and exploring its environment. 3.2 GUI operations or text APIs? 

A natural question is whether we need to construct GUIs or could instead provide direct text APIs for navigation and other operations. We view computer use as operating a digital interface. GUIs and APIs are two choices for that interface. We expect sufficiently capable computer-use agents to achieve the same task performance with either interface, although efficiency may differ. We evaluate this by comparing GUI and API interaction on a subset of tasks from each of the four competitions. Each pair uses the same model, task inputs, and software operations. We compare successive generations of Gemini Flash to examine how improvements in computer use affect the performance gap between interfaces. Table 2 shows the results on the validation sets. The two interfaces performed within four points of each other, and the GUI scored higher in two of the four competitions. # 4 Position: Computer-use agents are embodied generalists 

Claim 1: Representing physical interfaces in software lets us apply the methods that improved computer-use agents to embodied AI 

The challenges facing embodied AI/robotics today are similar to those faced by computer-use agents two years ago. Both require an agent to ground fine-grained actions in visual observations and adapt as its environment changes (Cheng et al., 2024; Yuan et al., 2024; Lee et al., 2026; Yang et al., 2025a) (Figure 3). For computer use, this means locating a target on a screen and clicking at the correct coordinates. For robotics, it means locating targets in three dimensions and coordinating motor commands to achieve the intended positions and orientations. Representing physical interfaces in software or simulations lets us apply the same methods for training agents to perform these interactions. Fine-grained motor control and real-time physical interaction may seem out of reach for computer-use agents. Yet only two years ago, precise clicking seemed equally out of reach: computer-use agents struggled to operate digital interfaces (Xie et al., 2024) and lagged behind agents equipped with task-specific APIs (Aggarwal and Welleck, 2026c; Song et al., 2025). As discussed in the previous section, the strongest agents now achieve comparable task performance through either interface (NeoCognition, 2026). We therefore argue for following the same development strategies in embodied AI, from learning precise, visually grounded actions to improving reliability and speed. 

Claim 2: Embodied AI will converge on a single general model, as computer use did 

Much of embodied AI today is built on vision-language-action models (VLAs), a special case of vision-language models further fine-tuned for robotic control (Brohan et al., 2023; Kim et al., 2024; Black et al., 2025a; Kawaharazuka et al., 2025). Since robot actions are continuous, and discrete tokens seem too coarse to express them precisely, most VLAs also add a dedicated action head, typically trained with diffusion or flow matching (Black et al., 2025a; NVIDIA et al., 2025; Li et al., 2024; Kawaharazuka et al., 2025). But computer-use agents faced exactly this problem only two years ago. A screen of a thousand by a thousand pixels is effectively a continuous space, and early agents could not act in it precisely on their own, relying instead on Set-of-Mark overlays (Yang et al., 2023; Xie et al., 2024) or separate grounding models (Gou et al., 2025). Yet with enough training, neither turned out to be necessary: today, a single model operates computers by simply writing click coordinates as ordinary text tokens, without any special head or tokenizer (Cheng et al., 2024; Qin et al., 2025; Bai et al., 2025). We therefore believe that embodied AI will follow the same path, and that specialized action heads will go the way of specialized grounding models (Goyal et al., 2025; Hancock et al., 2026). In fact, RT-2 and OpenVLA already show that robot actions can be expressed as tokens in the language model’s own vocabulary, without any action head (Brohan et al., 2023; Kim et al., 2024). To support this claim, we perform a preliminary investigation in Gym-Anything for Robotics (Aggarwal and Welleck, 2026a). We train 𝜋 0.5 (Physical Intelligence et al., 2025) and a standard vision-language model (Qwen3.5) with 9B parameters on the same 1,000 demonstrations for two tasks in a gift box simulation with two robot arms. We add no action head and do not even change the tokenizer. The only change is the format in which actions are written as text, similar to computer-use agents. Yet this plain vision-language model matches 𝜋 0.5, succeeding in 56% of attempts, against 59% for 𝜋 0.5

across 1000 unseen instances. The model is also fast. As with 𝜋 0.5, the model receives a new camera image every second and either writes an action, which can span a longer duration, or chooses not to act. The 9B model takes about 400 milliseconds on average to generate an action on a single L40S GPU. Because each action can span a longer duration, decoding takes up only about 20% of the total time and prefill about 10%, with the remaining 70% idle. However, this setting has only two robot arms. More complex robots, such as humanoids, have many more motors, and writing every state and action for them as plain text would make each action slower to generate. Such robots still need 6a more efficient format for states and actions, and possibly a better tokenizer (Pertsch et al., 2025; Kawaharazuka et al., 2025). And even if we use additional action heads, or whatever that format turns out to be, the most important thing is, embodied AI will end up exactly where computer use did, with a single model that writes code, solves mathematics problems, operates computers, and controls robots (Yang et al., 2025a; Reed et al., 2022; Gemini Robotics Team et al., 2025). 

Claim 3: The path to embodied generalists follows the same playbook as computer-use agents 

What enabled the progress of computer-use agents over the last two years? We view the development of computer-use agents in three phases, each with a direct counterpart in embodied AI. The first phase was visual grounding. Digital interfaces provide a way to generate supervision automatically: the underlying software can expose the identities and coordinates of interface elements, which can then be paired with screenshots. This approach has been used to generate grounding data at scale (Gou et al., 2025). Simulators offer the same opportunity for embodied AI: they can expose the identities and 3D positions of objects, which can be paired with rendered views to generate grounding data at scale (Yuan et al., 2024). Of course, this requires simulations with high enough visual fidelity, an area where coding models are clearly and continuously improving. The second phase was building environments for reinforcement learning, following concurrent approaches used in other domains such as coding (Pan et al., 2025; Yang et al., 2025b). Auto-mated pipelines made it possible to generate tasks, initialize environments, and verify outcomes at scale (Aggarwal et al., 2026b; Wang et al., 2026). These environments then let agents learn through reinforcement learning at scale. For embodied AI, this means creating such environments in the form of simulations with realistic physics, with tasks and verifiers available through software. We further argue that embodied environments have an even stronger asymmetry between task creation and verification Aggarwal and Welleck (2026a), which can be used to provide more accurate rewards or to increase task difficulty over time. We also note that reinforcement learning benefits from a strong initial policy, and training such a policy requires trajectories for pretraining or midtraining. We are therefore not advocating against teleoperation, whether in the real world or in simulation, or against egocentric videos, although this data may matter mainly in pretraining and midtraining, as in the training recipes of existing LLMs. How much of this data is needed also remains unclear, but based on preliminary results presented in this paper, we believe that perhaps much of it will not be needed, and that research on environments for reinforcement learning will remain more important. The third phase is speed and real-time interaction, which is especially important for robotics. An agent must choose and execute actions quickly enough to keep up with changes in its environment. This requires optimizing completion time alongside task success (Aggarwal et al., 2026a). Even without such optimization, the 9B model in Claim 2 took about 400 milliseconds per action and was idle for 70% of the time. We can pursue this through rewards for completing tasks successfully with less reasoning or in less time (Aggarwal and Welleck, 2025; Arora and Zanette, 2025), faster inference hardware (Lie, 2023; Abts et al., 2020; He et al., 2025), and harnesses that interleave quick actions with slower planning (Shi et al., 2025; NVIDIA et al., 2025). Such agentic harnesses organize how an agent plans, acts, and checks its progress (OpenAI, 2026a; Koh et al., 2026), and embodied tasks can reuse them once they are exposed through software. The sequence is therefore the same: learn grounding, build environments for reinforcement learning, and optimize for real-time interaction. 

So what should be next steps for Embodied AI? 

We therefore advocate for 3 research directions we believe would become fundamental for em-bodied AI research: a.) improving visual grounding through data generated automatically from simulators (Pfaff et al., 2026; Yuan et al., 2024), b.) building robotic environments as simulations for robotics, exposed through software that computer-use agents can operate and be RL trained on (Aggarwal and Welleck, 2026a; Wang et al., 2024; Hua et al., 2024), and c.) optimizing agents for real-time interaction (Aggarwal and Welleck, 2026b; Tang et al., 2026b) through architecture research (Choudhury et al., 2024; Tang et al., 2026a; Aggarwal and Welleck, 2026d) and by rewarding speed alongside task success (Arora and Zanette, 2025; Aggarwal and Welleck, 2025). These directions call on embodied AI researchers to expose their simulators and robots through software, and on developers of computer-use agents to include such software in training. 75 Conclusion 

In this paper, we argued that computer-use agents can already act as embodied generalists, because embodied tasks can be formulated as interaction with digital software. Using a single computer-use agent and changing only the software, we won prizes in four ECCV workshop competitions, from navigation to video segmentation. Operating that software through a GUI cost little compared to a text API, and a vision-language model with no action head matched 𝜋 0.5 when trained on the same robot demonstrations. We then traced how computer-use agents became general and superhuman over the last two years, through visual grounding, environments for reinforcement learning, and speed, and argued that embodied AI should follow the same playbook. We believe embodied AI is headed the same way, and that its generalist version will be the same model that already writes code, solves mathematics problems, and operates digital computers.
