Depth-to-RGB: Repurposing a Frozen Depth Estimator
for Geometry-Guided Compositing
Sanghyun Jo1,2,†, Chae Yeon Lim1,2, Donghwan Lee2, Sihyun Kim2, Soo Ye Kim3, Kyungsu Kim2,†
1OGQ
2Seoul National University
3Adobe Research
†Corresponding authors: shjo.april@gmail.com, kyskim@snu.ac.kr
Reference-based object compositing inserts or replaces an object using a background image, a reference
image, and a 2D compositing mask. These inputs guide appearance and placement but leave the completed
scene’s geometry implicit, which can distort object structure or alter the surroundings. Our Depth-to-RGB
(D2R) framework predicts composite depth for a scene not yet observed in the RGB inputs. It learns
reference-conditioned corrections to a frozen depth estimator using encoder features of paired completed
scenes as targets. The unchanged decoder maps the corrected representation to the intended scene’s depth,
which a separately trained renderer holds fixed during RGB synthesis. Under matched architecture and
training, encoder-feature supervision reduces OOD Stage-1 AbsRel by 31.4% relative to decoded-depth
supervision. We also introduce AnyInsertion++ with paired in-distribution and category-disjoint splits
to evaluate generalization beyond compositing training categories. The complete D2R system leads 12
open-source and 3 closed-source baselines in estimator-derived geometry and photometric quality on both
paired splits. On category-disjoint data, D2R reduces AbsRel by 43.7% and improves PSNR by 2.4 dB over
the matched RGB baseline. Across three unpaired benchmarks, D2R leads both identity metrics and reduces
mean CLIP reference cosine distance by 55% relative to the strongest baseline. Code and AnyInsertion++
are publicly available at the links below.

Introduction
Object compositing must preserve a reference object’s identity while adapting its shape and placement to a new scene.
The background provides scene context, and a 2D mask indicates the target region without specifying the intended
composite depth. Figure 1 illustrates the challenge: transferring reference appearance can produce distorted object
structure, incorrect placement, or changes to the surrounding scene. These errors motivate a geometric condition for the
completed scene, guiding appearance generation with an explicit description of the object and its surroundings.
Most reference-guided object compositing methods infer geometry implicitly during RGB denoising. Some approaches
with explicit geometric conditions use depth estimated from an input image [5, 42], assembled foreground and
background depth maps [27], or an RGB proxy rendered from a user-posed 3D object [14]. Depth estimated from an
input image describes its observed geometry, which does not determine the reference object’s depth and shape in the
completed composite. Assembling maps relies on rules for placing and rescaling reference depth within the background,
while rendering a proxy requires the object’s target pose to be specified before RGB generation. Our goal is to predict
post-composite depth from the background image, reference image, and 2D compositing mask, jointly estimating the
geometry of the reference object and its surroundings.
We call this field composite depth: the depth of the entire scene after compositing. Background depth omits the intended
object, while reference depth describes it in another scene and viewpoint. Neither map directly describes the object’s
shape and placement within the target scene. Predicting this field requires combining reference appearance with scene
context. We formulate this task as endogenous geometry provisioning: inferring this geometric condition from the given
inputs.

A pretrained depth estimator maps an observed image’s features to depth. Depth-to-RGB (D2R) freezes its encoder and
decoder while learning reference-conditioned residual corrections to the background representation. Training aligns the
resulting representation with encoder features extracted from paired completed scenes, enabling the unchanged decoder
to predict composite depth. This geometric condition remains fixed throughout RGB synthesis.
To evaluate geometry and category generalization, we curate AnyInsertion++ from AnyInsertion [48], expanding paired
evaluation from 38 to 426 cases with a category-disjoint split. Paired evaluation compares estimated depth and RGB
composites with paired targets. Additionally, we assess reference identity on TF-ICON [35], AIComposer [26], and
ComplexCompo [36], which collectively cover photographic, cartoon, and artistic backgrounds (Tab. 4). These unpaired
benchmarks test whether reference appearance is retained across different visual styles beyond the paired evaluation
setting. Our contributions are:
• Problem. We address the missing geometric condition in reference-based object compositing: predicting the
completed scene’s relative depth from a background image, reference image, and 2D compositing mask.
• Solution. We propose Depth-to-RGB (D2R). First, we learn reference-conditioned corrections to a frozen depth
estimator using encoder features of paired completed scenes as targets. Under matched architecture and training,
encoder-feature supervision reduces OOD Stage-1 AbsRel by 31.4% relative to decoded-depth supervision.
Second, we train an RGB renderer to use the resulting depth as a fixed geometric condition.
• Results. The complete D2R system reduces category-disjoint AbsRel by 43.7% and improves PSNR by 2.4 dB
over the matched RGB baseline. Across three unpaired benchmarks, D2R leads the 15 evaluated baselines on
both identity metrics, reducing mean CLIP reference cosine distance by 55% relative to the strongest baseline.

Related Work
Implicit Geometry in RGB Compositing. Paint-by-Example [62] and AnyDoor [6] transfer reference appearance;
Personalize-Anything [11], SHINE [36], and HiFi-Inpaint [33] improve identity through token substitution, sampling-
time control, and high-frequency detail cues (e.g., edges), respectively. Such 2D structural cues can preserve local
shape but do not specify scene-wide composite depth. D2R predicts this geometric condition before RGB generation.
Insert-Anything [48] provides our direct baseline because its in-context canvas and LoRA [17] support a matched
evaluation of adding depth prediction and supervision.

3.2
Stage 2: Synthesizing RGB with Fixed Composite Depth
Following canvas-based conditioning [48, 52], Stage 2 arranges the masked background, reference image, and composite
depth as composite, reference, and depth patches on one input canvas. At inference, RGB is generated only in the
masked region of the composite patch; the rest of the canvas remains fixed as conditioning input (App. B.3.1).
Training and Auxiliary Supervision. Auxiliary depth prediction trains the shared denoiser to represent composite
geometry. A frozen autoencoder encodes the input canvas and a supervision canvas whose three patches contain the
paired composite, reference image, and target depth D; only denoiser LoRA [17] is trained. The input depth patch
receives ˆD or D with equal probability, exposing the renderer to prediction errors while retaining the same supervision.
We add noise to the full supervision canvas during training and minimize Ltotal = Lpixel + Ldepth + Lcons. The RGB
loss supervises the composite and reference patches; the depth loss supervises the depth patch. At inference, only
the masked region of the composite patch is generated, while the supplied depth patch remains fixed. An accurate
depth patch does not ensure that the generated RGB image matches the target geometry. We therefore apply the frozen
estimator F to the one-step clean RGB estimate ˆIcomp and compare its depth with the paired target D:

condition after every update. The default pipeline takes 22.40 s per image on RTX PRO 6000 and preserves the
background image’s resolution (App. B.4).

Experiments
Datasets. AnyInsertion++ contains 52.9K curated training samples from AnyInsertion [48] and 426 paired evaluation
cases: 287 in-distribution (ID) and 139 from categories absent from compositing training (OOD). Thumbnail-hash and
confirmed perceptual-hash checks find no train/test image matches. For reference-identity evaluation without paired
targets, TF-ICON [35], AIComposer [26], and ComplexCompo [36] provide 332, 272, and 300 cases. Target regions
use object masks in AnyInsertion++ and coarse box masks in the unpaired benchmarks. Appendix C.1 details curation,
overlap checks, and evaluation protocols.
Implementation Details. Stage 1 uses a width-640 injector with frozen Depth Anything V2 ViT-L [65]. Stage 2 adapts
FLUX.1-Fill with Redux1, following the LoRA and sampling setup of Insert-Anything [48]. All trained variants use
final checkpoints after 50K iterations for Stage 1 and 100K for Stage 2. Insert-Anything∗is retrained on the same
AnyInsertion++ data. Other baselines use released checkpoints or public interfaces. Settings and seed checks are in
App. C.3.2; paired uncertainty and scorer robustness are in App. C.4.
Metrics. Full-frame AbsRel, δ1, and RMSE compare depths estimated from GT and generated RGB after background-
based scale and shift alignment. PSNR and LPIPS [71] measure photometric quality against GT composites. CLIP-I
and DINO-I use IsoCLIP [37] and DINOv3 ViT-L [47], respectively, to measure cosine similarity between generated
object crops and GT crops (paired) or reference crops (unpaired; App. C.4.4).
Paired and Unpaired Performance. D2R outperforms all 15 open- and closed-source baselines on every reported
geometric, photometric, and identity metric across both paired splits (Tabs. 2 and 3). Relative to the strongest baseline
for each metric, it reduces AbsRel by at least 22% and LPIPS by at least 19%, while improving PSNR by at least 1.0 dB.
D2R also leads both identity metrics on all three unpaired benchmarks, reducing mean reference cosine distance by
55.4% with CLIP and 22.6% with DINO over Insert-Anything∗(Tab. 4; App. C.1.3). These gains occur without an
identity-specific loss. We relate them to reference structure: objects with similar semantics and colors can differ in shape
and part arrangement, which D2R better preserves in the displayed examples (Fig. 1). Composite depth supplies these
structural cues while RGB supervision learns appearance. Their joint contribution is consistent with higher embedding
similarity.

Unpaired benchmarks further assess reference identity across real-world photographs and stylized scenes, extending
evaluation beyond paired image comparisons. Surprisingly, the same pipeline also produces geometry-aware composites

than distances within the depicted scene. A learned depth estimator instead infers relative depth from RGB cues.

Learning the Completed Scene’s Depth Features. Table 5 changes only the supervision target: both variants train the
same injector while keeping the depth encoder and decoder frozen. The paired composite supplies features that the
unchanged decoder already maps to the intended depth. Matching these features therefore teaches reference-conditioned
prediction within the pretrained representation, whereas depth-only supervision constrains the decoded map. Feature
targets lower ID and OOD Stage-1 AbsRel by 30.9% and 31.4%, while avoiding decoder backpropagation. With
the same trained RGB renderer, they also lower OOD rendered-image AbsRel from 0.089 to 0.067, connecting the
supervision choice to final RGB geometry. Adding decoded-depth loss to feature matching improves ID by about 5%
but worsens OOD by about 3% and reduces the largest single-GPU batch by about 30% (App. B.2.4).
Feature Correction Versus Diffusion-Based Depth Generation. Following the depth-generation approach in
3DIS [77], we build a compositing-specific diffusion baseline with FLUX.1-Fill and Redux. It denoises composite-
depth maps using the same Stage-1 training pairs. D2R reduces OOD AbsRel from 0.1740 to 0.0751 (56.8%) with one
feed-forward pass instead of 28 denoising steps. This compares depth-prediction strategies; Tab. 5 isolates supervision
within the same predictor (App. C.2.2).

Table 6(b) lowers AbsRel to 0.098 but reduces PSNR to 20.3 dB. Rescaling reference depth into the background supplies
observed geometry without predicting the object’s shape in its new scene, so this cue can conflict with the intended
composite.

Correcting Object and Scene Features Together. The mask localizes the compositing region, but relative depth also
depends on its surroundings. Restricting correction to masked tokens raises average Stage-1 AbsRel by about 2.5%,
with errors increasing inside and outside the mask. Sharing one injector across four layers raises ID and OOD error
by about 10% and 3%. These results favor scene-wide correction with separate layer parameters, letting reference
information influence both object and context features (App. B.2). Injection also improves all six depth backbones
against their own targets, supporting reuse across estimators without ranking absolute accuracy (Tab. C4).
Adapting Different RGB Generators. We supply identical Stage-1 depth to pretrained and adapted SD2 [46],
SDXL [43], Qwen [60], and FLUX.1-Fill. Adapted configurations reduce OOD AbsRel by 18% to 32% and increase
PSNR by 1.08 to 2.13 dB (Tab. 9). Because both versions receive the same depth, the gains reflect improved RGB
generation under that condition. This supports reuse of the depth interface across four generators (App. C.3.3).
Consistency Across Cases and Object Regions. D2R improves OOD full-frame AbsRel over Insert-Anything∗on
103 of 139 cases, with gains inside objects and along their boundaries. Appendix C.4.2 reports paired and image-cluster
uncertainty and sensitivity to the largest gains. Five default training runs per stage show about 1% average relative
variation across geometric, photometric, and identity metrics (App. C.3.2).
Generalization Beyond Rigid Objects. To test whether gains extend to objects whose shape can change, we evaluate
the annotated rigid and non-rigid groups separately. D2R improves OOD AbsRel and PSNR over Insert-Anything∗in
both groups; non-rigid AbsRel falls from 0.133 to 0.071. This evidence covers 20 non-rigid OOD cases (App. C.1,
Tab. C3).
Agreement Across Depth Scorers. We hold generated RGB fixed and change only the depth scorer. D2R ranks first
among sixteen methods on both splits under all five scorers, including Depth Pro and Metric-Anything, which supply
no training targets to the default model (App. C.4).
Computational Cost. On RTX PRO 6000, the complete Stage-1 predictor takes 56.5 ms and 5.21 GB peak inference
memory. Relative to 22.34 s for FLUX RGB synthesis, this adds about 0.25% latency. Predicted depth is reused
throughout all 28 RGB sampling steps. The injector adds 272.4M parameters. The lower-resolution SD2 configuration
takes 0.87 s overall, trading geometric and photometric quality for speed (Tab. 9; App. B.4).
Limitations. D2R keeps its predicted depth fixed during RGB synthesis, so errors in object shape or placement can
persist in the final image. Even with plausible geometry, an object may retain reference colors or textures that do not
match a grayscale or illustrated background. Depth describes spatial structure but does not specify the color and texture
changes needed to match the background. Appendix C.5 provides examples and further discussion.
6
Conclusion
D2R repurposes a frozen depth estimator by learning to predict encoder features of an intended composite from
its background and reference. Completed-scene feature targets improve both the intermediate depth and final RGB
geometry under the same renderer, linking the prediction objective to downstream compositing. The complete pipeline
also improves photometric quality and reference identity. The depth predictor also outperforms our diffusion-based
composite-depth baseline without iterative denoising. Feature correction adapts multiple depth estimators, while the
resulting depth condition supports different RGB generators. These results extend depth estimation from observed
images to intended composites, providing a reusable geometric condition for RGB synthesis without a depth sensor or
user-posed 3D proxy. We believe this interface can support future harmonization and relighting that adapt object color
and illumination to the surrounding scene while preserving the intended object shape and its spatial relationships with
nearby surfaces.

Comparison Criteria. Table A1 extends Tab. 1 for reference-based compositing and specialized insertion tasks. The
first three criteria ask whether depth describes the intended composite, is predicted rather than assembled, and is
predicted jointly across the scene. A full-frame map assembled from separate depths does not satisfy the third criterion.
The fourth tests use of standard compositing inputs alone, including dataset-provided reference masks (App. B.3.1).
The final criterion asks whether a geometric condition is fixed before RGB synthesis; this includes depth maps and
DIRECT’s rendered RGB proxy. Person-In-Situ is classified by its two-stage configuration; its rendered body-depth
condition is additional to the standard compositing inputs.
RGB Compositing Without Explicit Composite Depth. Paint-by-Example [62] and AnyDoor [6] preserve reference
identity through image features. Insert-Anything [48] places the reference and target on one canvas and adapts
an inpainting transformer with LoRA [17]. It provides our matched baseline because D2R retains this rendering
interface while adding depth prediction and supervision. Other mechanisms include token substitution in Personalize-
Anything [11], iterative identity control in SHINE [36], and high-frequency feature preservation in HiFi-Inpaint [33].
InsertFuse [25] maps the insertion mask and its distance transform to visual-token features, specifying the editing
region in 2D. Related appearance-conditioned methods include ObjectStitch [49], IMPRINT [50], ObjectDrop [58],
ObjectMate [59], Add-it [53], CareCom [4], and A2-Edit [76]. Their features can encode shape and geometry implicitly.
D2R makes scene-wide relative depth an explicit condition before RGB synthesis.
Separating Object Structure and Appearance. PAIR Diffusion [12] controls object-level editing with segmentation-
based structure and image-encoder appearance features. Refacade [19] learns to remove source texture while retaining
object geometry, then uses shuffled reference patches to transfer texture. These methods separate structure from
appearance through different conditioning mechanisms. D2R instead predicts the completed scene’s depth, including
the inserted object’s structure and spatial relationship to the background.
Depth from the Existing Scene. MimicBrush [5] transfers reference features through a second U-Net and optionally
uses depth estimated from the input background before masking the compositing region. Table 1 describes this
depth-enabled configuration. Its depth map provides the pre-edit geometry, including pixels later masked. Zero-shot
depth-aware editing [42] decomposes supplied depth into layers that a user transforms, requiring depth beyond the
three compositing inputs. Both methods start from existing geometry; neither predicts completed-scene depth from the
standard compositing inputs.
Geometry from Additional Inputs or Assembly Rules. In its instruction-driven branch, BIFRÖST [27] predicts an
object box and depth value from language, then rescales reference depth into the background map. Table A1 classifies
17


this branch, whereas our quantitative comparisons use mask-based inpainting (App. C.1.4). Table 6 separately tests
depth fusion in D2R.
Explicit pose and placement controls provide another way to specify the intended arrangement. DIRECT [14] uses
a rendered RGB proxy to specify object pose; SpatialHand [57] combines background depth with a user-selected
placement depth in the insertion mask and a numerical orientation condition for 6DoF object insertion. Its depth
assembly preserves nearer background occluders. FreeInsert [73] and the dual-branch GeoEdit [16] reconstruct and
manipulate an object already present. D2R uses only standard compositing inputs.
Geometric Editing and Cross-Image Compositing. FreeFine [78] separates object transformation, source-region
inpainting, and target-region refinement without training. Its cross-image extension refines coarse RGB composites
assembled from source objects and source/target masks, so its scope also includes compositing. The distinction from
D2R is how the target structure is obtained: FreeFine transforms and refines RGB content, whereas D2R learns to
predict scene-wide composite depth before RGB generation.
Depth-First Human Compositing. Person-In-Situ [38] predicts a scene’s depth with the reference person inserted, then
generates the RGB composite. Its two-stage configuration uses rendered 3D body depth, estimated scene depth, and a
body-derived box mask alongside scene and reference images. It fine-tunes diffusion models on depth and RGB targets
constructed from video frames. D2R instead uses a general monocular depth prior, learning reference-conditioned
feature corrections while keeping the estimator frozen. Encoder features from paired completed scenes supervise the
injector. This design requires no human-body representation and supports the diverse object types in our evaluation.
The distinction concerns the inputs and learned representation, rather than the depth-before-RGB ordering.
Our paired evaluation covers 107 distinct object tags (87 ID and 20 OOD; Tab. C2), with leading aggregate results on
both splits. Among the 426 cases, 4 carry the person tag (0.9%), whereas 49 carry accessory or garment tags (11.5%).
These counts use the literal person_person, accessory_*, and garment_* tags, without manually regrouping
other objects. The unpaired benchmarks do not provide reference-category tags, so identifying a person-only subset
would require manual annotation. We therefore provide a conceptual comparison with Person-In-Situ.

Depth-Conditioned Multi-View Canvases. SIGNeRF [8] edits NeRF scenes through depth-conditioned diffusion

implementations, rather than iterative control in general.

Feature Injection During RGB Sampling. Plug-and-Play Diffusion Features [55] preserves a guidance image’s
structure by injecting its spatial features and self-attention information during diffusion sampling, without training.
D2R learns residual corrections inside a frozen depth estimator, using encoder features of paired completed scenes as
targets. Feature injection is therefore a shared mechanism, while the learned prediction target and the network receiving
the corrections differ.
Predicting and Aligning Representations. I-JEPA [2] predicts target-region representations from image context, while
REPA [68] aligns diffusion features with representations from a pretrained visual encoder. These objectives provide
precedents for feature-level supervision. D2R instead targets the depth-encoder features of a paired completed scene,
19


predicting them from the background, reference, and mask before decoding them with the same estimator’s unchanged
decoder. Its supervision acts inside the depth predictor rather than aligning the RGB generator’s hidden states.
Encoder Adaptation and RGB Conditioning. ViT-Adapter [7] and ViT-CoMer [61] augment visual encoders for
dense prediction. D2R complements these architectural mechanisms by targeting features of the completed scene while
leaving the dense decoder [45] unchanged. Rendering conditions can enter through dedicated branches [21, 40, 70, 75],
canvas patches [52], or image-embedding adapters [66]. D2R supplies its predicted depth as a fixed patch on the
reference-guided inpainting canvas [48] and trains only renderer LoRA. Merged LoRA adds no renderer parameters.
Consistency Feedback for Conditional Generation. ControlNet++ [28] trains conditional generation by comparing
an input control with the condition recovered from a one-step denoised image through a frozen discriminative model.
D2R uses a related principle for RGB-depth consistency. Its supervision remains the paired target depth D, including
when Stage 1 supplies the conditioning map Din, and it combines this loss with depth-patch denoising. This separates
the accuracy of the training target from errors in the supplied condition (App. B.3).

B.2.4
Feature Targets Versus Decoded-Depth Targets
To isolate the effect of the supervision target, we start from D2R’s width-640 injector on frozen Depth Anything V2
ViT-L and replace only the encoder-feature objective with a decoded-depth objective. Both variants retain the same
injector architecture, frozen encoder and decoder, training data, optimizer, and batch size, and use final checkpoints after
50K training iterations (Tab. 5). The alternative uses the normalized ℓ1 depth discrepancy from the Stage-2 consistency
objective (App. B.3): the same normalization A is applied separately to predicted and target composite-depth maps,
without a background-based scale-and-shift fit. We score full-frame composite depth before RGB synthesis on both
paired splits.
The two objectives differ in where gradients enter the frozen estimator. Feature supervision compares decoder inputs
directly. Decoded-depth supervision must propagate gradients through the decoder to the injector, retaining decoder
activations for backpropagation even though the decoder weights remain fixed. Both variants deploy the same injector
and depth estimator, so this difference affects training computation rather than inference cost.

B.2.5
Backbone Interfaces and Parameter Sharing
Depth Anything V1 [64], V2 [65], and V3 [30] expose four decoder taps on one token grid. Metric-Anything [63] uses
a patch pyramid, requiring corrections to be broadcast before decoding. InfiniDepth [67] requires taps across token
resolutions, while Depth Pro [3] receives corrections in its image encoder alongside a separate patch encoder. The
design and objective are shared, with tap selection, mask placement, and feature dimensions adapted per backbone.
The weight-sharing ablation replaces the default backbone’s independent tap-specific injectors with shared parameters,
keeping width 640 and the other settings fixed (Sec. 5). Sharing reduces parameter count but executes the same number
of attention blocks. The adopted design uses independent parameters so each tap can learn a correction suited to its
encoder layer.

object-instance identity, and agreement between the background and the composite with that object absent. Aesthetics,
photographic quality, and difficulty are excluded, so difficult but correctly labelled samples are retained.

An exact thumbnail match means identical SHA-1 hashes of 64 × 64 grayscale thumbnails. For near duplicates, a
64-bit DCT-based perceptual hash selects candidates with Hamming distance at most 8; normalized cross-correlation
of at least 0.95 between the 64 × 64 thumbnails confirms a match. Neither test split contains a thumbnail match or a
confirmed near-duplicate image under these criteria (0/287 ID; 0/139 OOD).

Depth Anything V2 ViT-L [65] runs offline at 518-pixel input resolution. Its relative inverse depth, with larger values
denoting nearer surfaces, is independently min-max normalized to [0, 1], resized to the original image, and stored as
an 8-bit single-channel PNG. These maps supply the Stage-2 target patch and default geometric reference; Stage 1
instead learns from the same estimator’s encoder features. Background and reference depth maps for the alternative
provisioning strategies use the same extraction procedure.
At inference, Stage-1 predictions ˆD use only the three compositing inputs. They undergo the same normalization and
are rounded from a 16-bit intermediate to 8-bit PNGs for the depth patch, including on unpaired evaluation data. Thus
GT Composite Depth denotes the paired-image target, while deployed conditioning uses predicted composite depth.
Scorer dependence is tested in App. C.4.
To test whether improvements extend beyond rigid objects, we group garment, accessory, person, animal, food, and
plush tags as non-rigid and the remaining tags as rigid. This operational rule groups categories rather than assigning
physical rigidity to every instance. Table C2 lists 146 rigid and 141 non-rigid ID cases from 42 and 45 tags, and 119
rigid and 20 non-rigid OOD cases from 14 and 6 tags. The OOD result is therefore dominated by rigid objects, with a
smaller non-rigid sample.
D2R lowers AbsRel in all four groups (Tab. C3). Replacing predicted depth with depth from the paired composite

Unpaired Evaluation and Identity Margins
TF-ICON [35], AIComposer [26], and ComplexCompo [36] provide 332, 272, and 300 evaluation cases without paired
composites. We therefore compare generated objects with their references to measure reference retention. Predictions
use target-box crops, references use dataset-provided object masks, and both are placed on white. All methods use the
same complete case set for each benchmark, with scores averaged over its cases.
CLIP-I uses IsoCLIP [37] with a SigLIP2 [54] backbone; DINO-I uses the [CLS] token of DINOv3 ViT-L/16 [47].
Paired and unpaired evaluation share the encoder settings in App. C.4.4, but use different comparison targets and crops.
Object scale and residual background can affect embedding similarity, so these scores assess reference agreement
rather than scene geometry. D2R uses FLUX.1-Fill with injector-predicted Depth Anything V2 ViT-L depth; Insert-
Anything∗[48] leaves the depth patch empty.
To interpret the identity margins, let Sb be the highest similarity among the fifteen baselines for a given benchmark and
encoder, and SD2R the D2R score in Tab. 4. Cosine distance to the reference is d = 1 −S; its relative reduction is
100(SD2R −Sb)/(1 −Sb) percent. Matched Insert-Anything∗is the strongest baseline in all six comparisons.
We aggregate benchmarks by averaging their cosine distances with equal weight, then compute 100( ¯db −¯dD2R)/ ¯db.
Mean CLIP distance falls from 0.215 to 0.096 (55.4%), and mean DINO distance from 0.268 to 0.208 (22.6%); the CLIP
reduction rounds to 55% in the abstract. For example, on TF-ICON, CLIP-I rises from 0.760 to 0.902, corresponding to
a distance reduction from 0.240 to 0.098 (59.1%). Scores and distances are displayed to three decimal places, while
percentages use the four-decimal evaluation records.

Baseline Evaluation Protocol
Eleven open-source methods use released checkpoints and, unless specified below, official default settings: Paint-by-

Personalize-Anything [11], SHINE [36], DIRECT [14], and HiFi-Inpaint [33].
BIFRÖST. We run mask-based inpainting from the official repository’s main branch with default settings, using
bifrost.ckpt from lingxiao2049/Bifrost.
DIRECT. We adapt DIRECT [14] to automatic evaluation by selecting the 3D proxy rotation with the highest silhouette
IoU against the target mask. The dataset-provided reference mask becomes the reference image’s alpha channel, and
TRELLIS-image-large reconstructs a 3D Gaussian proxy from this RGBA input without a background-removal
model. Only rotation is optimized: the proxy retains its native TRELLIS scale, with no scaling operation or scale search,
and translation is reset to zero for every candidate rather than accumulated across trials.
The initial grid evaluates 12×5×2 = 120 unique rotations: y ∈{0◦, 30◦, . . . , 330◦}, x ∈{−60◦, −30◦, 0◦, 30◦, 60◦},
and z ∈{0◦, 180◦}. Each of the three highest-IoU candidates is refined with eight random rotation proposals at each
angular scale of 15◦, 6◦, and 2◦. A refinement is retained only when its best proposal improves IoU. The highest-IoU
final candidate is chosen after 120 + 3 × 24 = 192 orientation evaluations.
For the matched comparison, we retrain Insert-Anything [48] on AnyInsertion++ as Insert-Anything∗; its released
checkpoint is excluded because the original training corpus can overlap our evaluation splits. The retrained baseline
shares D2R’s data, backbone, canvas, Redux embedding, and LoRA configuration, but uses an empty depth patch and
only the RGB denoising loss. Both renderers use their final checkpoints after 100K training iterations and sample with
28 steps, guidance 30, and seed 0.

instruction below. Each request produces one image, and every evaluation case has one valid output. We do not choose

C.3.1
Backbones and Prompt Conditioning
The renderer comparison tests whether the same composite-depth interface can support SD2-Inpainting [46], SDXL-
Inpainting [43], Qwen-Inpainting [60], and FLUX.1-Fill. Each uses the three-patch canvas, with depth observed
throughout inference, a frozen autoencoder, and only LoRA trained. SD2 and SDXL predict noise; FLUX and Qwen
predict velocity. The conditioning formats below are used consistently during training and inference; App. C.3.2
specifies training and sampling settings.
FLUX.1-Fill receives reference appearance through both the canvas and Redux. The Redux embedding occupies the
text-conditioning stream, so this path constructs no text prompt. Any remaining text slots expected by the pipeline are
filled with zeros to preserve its tensor layout.
SD2-Inpainting [46], SDXL-Inpainting [43], and Qwen-Inpainting [60] receive reference appearance through the canvas
and use text instructions without a separate image-prompt encoder. Each instruction has exactly two variable slots: the
object noun {obj}, read from the sample’s file name, and the insertion or replacement phrase, denoted {verb} in the
compressed instruction or {action} in the full instruction. A single space serves as the negative prompt.
The CLIP text encoders of SD2-Inpainting and SDXL-Inpainting truncate at 77 tokens. Both therefore receive the
compressed instruction, which contains 42 to 56 tokens under that tokenizer across the released splits: “photorealistic
composite: left, a scene with the {obj} {verb}, cast shadow, reflections, natural contact and lighting; top right, reference
photo of the {obj}; bottom right, its depth map.” The {verb} slot is inserted for insertion and replacing the original
object for replacement.
The Qwen-Inpainting text encoder accepts 512 tokens for sampling and 1024 for training. Its full instruction contains
115 to 152 tokens under the Qwen tokenizer: “A composite image. Left half: a realistic scene where {action}. Top right:
a clean reference photograph of a single {obj} on a plain background. Bottom right: a grayscale depth map matching
the left half — bright pixels for nearby surfaces, dark pixels for distant surfaces — accurately reflecting the inserted
{obj}’s 3D placement and contact geometry. Maintain photorealistic quality.”
For Qwen-Inpainting, the {action} slot is “the {obj} from the top-right reference panel has been naturally inserted
into the highlighted region — with cast shadows on the ground and adjacent surfaces, surface reflections and specular
highlights, and physically plausible contact with the scene, all consistent with the existing lighting direction, materials,
perspective, and color temperature” for an insertion. For a replacement, it is “the original object has been replaced
with the {obj} from the top-right reference panel — preserving the original cast shadows, surface reflections, and
physical contact patterns of the scene while adopting the visual identity of the {obj}”.
The shorter instruction omits the full instruction’s explicit depth-polarity description. Both retain guidance on shadows,
reflections, contact, lighting, and the canvas layout. The instructions above are reproduced verbatim.

C.4.2
Paired Uncertainty and Regional Evaluation
We test whether D2R’s average geometric improvement persists across cases, rather than depending on a few large
gains. D2R uses Stage-1 predicted depth in all comparisons; the rendered-image cases are the same as in the main
paired evaluation. For each case, ∆= AbsRelD2R −AbsRelbaseline, so negative differences favor D2R. We compute
percentile intervals from 10,000 paired bootstrap resamples with seed 0, sampling individual cases while retaining the
paired method scores.
Insertion and replacement cases can share an image ID, but the primary bootstrap samples them separately. For the
OOD comparison with Insert-Anything∗[48], a cluster bootstrap over 82 image IDs gives [−0.0785, −0.0286], while
the bias-corrected and accelerated (BCa) interval is [−0.0749, −0.0354]. Both exclude zero, as does the case-level
percentile interval in Tab. C6. The improvement persists under both alternative bootstrap procedures.
Table C6 compares D2R with matched Insert-Anything∗and MimicBrush [5]. Wins exclude differences within the
AbsRel tie tolerance |∆| ≤0.001. To measure sensitivity to the largest gains, we remove the round(0.1n) cases most
favorable to D2R: 14 OOD or 29 ID cases. The remaining mean difference is negative in all four comparisons. Large
improvements contribute to the aggregate gain, but they do not account for the entire full-frame advantage.

C.4.3
Cross-Scorer Evaluation
We hold the generated images fixed and change the depth estimator used to score them. Depth Anything V1 [64],
V2 [65], V3 [30], Depth Pro [3], and Metric-Anything [63] each evaluate all sixteen methods on the same 287 ID and
139 OOD cases. Each scorer estimates depth from both the generated and ground-truth images, then applies Eq. (C2)
and full-frame scoring. D2R retains its adopted Stage-1 predictions throughout. Depth Pro and Metric-Anything provide
no training targets for this D2R configuration; their trained injector variants belong to the separate Stage-1 ablations.
This comparison uses floating-point depth maps, whereas the main protocol stores 8-bit PNGs, so its values are reported
separately. Tables C8 and C9 give AbsRel, ranks, and Spearman correlations relative to the Depth Anything V2 ordering;
DAv1 to DAv3 abbreviate the corresponding Depth Anything versions. Absolute errors should be compared within each
scorer, because their depth representations and scales differ.
D2R ranks first under every scorer on both splits, although the remaining methods change order. Across the four
alternative scorers, Spearman correlations with the Depth Anything V2 ordering range from 0.888 to 0.985 on ID and
from 0.824 to 0.976 on OOD. The leading result is therefore stable even where the broader ranking varies, supporting
the geometric improvement beyond the estimator that supplied training targets.

C.5
Limitations
Errors in the Geometric Condition. Fixed depth can pass an incorrect footprint, contact height, or occlusion order into
RGB. Viewing predicted depth beside the generated image helps distinguish the supplied geometry from the renderer’s
response. Target-depth substitution (Tabs. 2 and 3) measures the benefit of a better condition without assigning every
remaining error to one stage. Multiple geometries may fit the inputs, whereas paired evaluation uses one target. Relative
depth leaves metric scale undetermined, and thin or transparent structures remain difficult.
Color and Texture Harmonization. A geometrically plausible insertion can still mismatch the scene’s appearance.
The cat in Fig. D4 (row four) fits the target region but retains photographic fur shading in an ink drawing; the church
in Fig. D3 (row seven) retains color in a grayscale scene. D2R can reflect illustrated styles, yet larger palette and
texture changes remain difficult. Depth specifies structure rather than surface appearance, so it cannot alone resolve
RGB-to-grayscale harmonization. Photographic training may also favor reference retention, although its contribution is
not isolated here. These limitations motivate geometry-guided harmonization and relighting as future work.
Scope of the Evidence. Agreement across depth scorers supports the ranking without establishing physical accuracy
or local contact correctness. Regional evaluation (App. C.4.2) addresses errors hidden by full-frame averages. The
matched RGB baseline controls data and renderer but cannot separate the pretrained depth prior from the added 272.4M
injector parameters. Holding both fixed, the feature-versus-depth comparison isolates supervision (App. B.2.4).
