ABSTRACT 

Self-evolving language agents have emerged as a promising paradigm for con-tinuously improving agent behavior through experience. However, most exist-ing approaches evolve textual artifacts, which can influence action preferences but cannot reliably enforce action admissibility in embodied environments with discrete and often irreversible actions. We propose MetaAct, which shifts self-evolution from textual guidance to executable action constraints by synthesizing GEAR (Grounded Executable Action Rules) from execution feedback. Each rule is represented as a typed specification, compiled into a deterministic guard, and validated offline through trajectory replay without additional model calls or en-vironment interactions. Across four benchmarks, MetaAct improves task per-formance; on ScienceWorld and WebShop, violations drop from 70% to 0% and 40% to 1%, with score gains of +10.1 and +8.0. Our code is available at 

https://github.com/BaiCubed/MetaAct .

1 INTRODUCTION 

Language agents can improve by modifying textual artifacts, including specialist roles and com-munication structures (Hong et al., 2024; Wu et al., 2023), natural-language reflections and dis-tilled lessons from previous failures (Shinn et al., 2023; Zhao et al., 2024), and evolving task con-texts (Zhang et al., 2026). These methods alter the context from which the model generates its next output and have shown value in tasks where behavior is mediated primarily through text. Embodied interaction differs in a consequential way. At each step, an agent selects a discrete action from an environment-defined set; once executed, the action changes the environment and may be difficult or impossible to reverse. Figure 1 illustrates this distinction in ScienceWorld, where focusing on the object under test be-fore the thermometer can terminate the episode immediately. Distilling this failure into a natural-language lesson gives the planner the correct ordering rule, but leaves the violating action available. Compiling the same rule into an executable constraint instead removes that action from the admis-sible set until its prerequisite is satisfied. Prompt adaptation therefore reshapes which action the model prefers, whereas executable constraints directly restrict which actions can be executed, in the spirit of action masking and shielding in reinforcement learning (Huang & Onta˜ n´ on, 2022; Alshiekh et al., 2017). To address this gap, we introduce MetaAct, a framework that synthesizes executable action con-straints from execution feedback. Rather than letting the model write executable code directly (Wang

2 RELATED WORK 

2.1 TEXTUAL AND PARAMETER -S PACE ADAPTATION 

Most language-agent adaptation changes model context or parameters. Reflections, distilled lessons, and test-time memories reuse prior experience (Shinn et al., 2023; Zhao et al., 2024; Zhang et al., 2026); role, topology, and prompt optimization restructure how the model is queried (Hong et al., 2024; Wu et al., 2023; Wang et al., 2026b; Khattab et al., 2024); replanning intervenes during execu-tion (Sun et al., 2023; Kim et al., 2025); and fine-tuning updates weights (Zeng et al., 2024). How-ever, all of these act only through the model’s subsequent interpretation of the artifact; MetaAct’s advantage is that feedback is compiled into a deterministic action gate whose effect does not depend on the model’s compliance. 2Self-Evolving Executable Action Constraints for Embodied Language Agents 2.2 EXECUTABLE ARTIFACTS 

A complementary line generates artifacts that act directly: verified skill libraries (Wang et al., 2023a), policy code and situated programs for embodied planners (Liang et al., 2023; Singh et al., 2022; Liu et al., 2023), affordance-grounded closed-loop feedback (Huang et al., 2023), and pro-gram libraries validated by execution (Ellis et al., 2021). However, these methods add executable behavior that must be run to be assessed; MetaAct’s advantage is a subtractive guard whose effect on logged trajectories can be checked by replay before deployment. 2.3 GATING AND RUNTIME ENFORCEMENT 

Action-space control spans symbolic preconditions (Fikes & Nilsson, 1971), shielding and action masking in reinforcement learning (Alshiekh et al., 2017; Huang & Onta˜ n´ on, 2022), and constraints induced from traces (Yang et al., 2007; Guan et al., 2023; Mordoch et al., 2024). Closest to ours are runtime guards for LLM agents: AgentSpec enforces LLM-written rules (Wang et al., 2026a) and OntoGuard checks actions against ontologies mined from demonstrations (Liu et al., 2026). How-ever, both fix their rules before deployment without behavioral verification; MetaAct’s advantage is a gate synthesized from the agent’s own execution feedback and validated by replay. 

3 METHOD : S ELF -E VOLVING GEAR 

3.1 TYPED GEAR S PECIFICATIONS 

MetaAct places the LLM at the specification level rather than letting it write executable code: the model fills a typed specification and a fixed compiler produces the executable artifact. This trades some expressiveness for deterministic compilation and offline validation (Section 2). As illustrated in Figure 2, a GEAR specification contains three components: a rule primitive, typed parameters instantiated through extractor slots, and a trigger message shown to the planner when the rule fires. The primitive is selected from a fixed menu of six operators covering the failure patterns observed during development: ordered once enforces a one-time precedence between two action classes (the thermometer ordering in ScienceWorld); no op repeat blocks an immediate repeti-tion when the observation is unchanged; idempotence block rejects an option whose effect has already occurred, including alternating A–B–A–B patterns; revisit block forbids returning to a location visited since an anchoring action; generic deref resolves a generic reference such as “the substance” to the entity implied by the goal; and relevance filter restricts an action class to a candidate set extracted from the goal text. Extractor slots are likewise drawn from a fixed menu of predefined readers over the goal string, so model errors are limited to invalid primitive–extractor combinations and incorrect parameter values, both detectable during compilation and validation. The same restriction bounds coverage: failure patterns outside the primitive menu cannot be constrained (Appendix C.4). 3.2 EXECUTABLE ACTION GATING 

A compiled GEAR specification can be viewed as an execution-time action gate. Let ht denote the interaction history, A(ht) the actions exposed by the environment, and GΣ(ht, a ) ∈ { 0, 1} the deterministic decision produced by the compiled specification. The admissible action set is 

AΣ(ht) = {a ∈ A (ht) : GΣ(ht, a ) = 1 }. (1) Over a finite candidate set this is equivalent to masking actions with GΣ = 0 before selection; in free-form action generation, a violating proposal is rejected at the execution interface and the trigger message is returned for replanning. Unlike gating in neural systems, the gate here is neither latent nor learned: its implementation and blocking semantics are fixed, and what evolves is the explicit specification Σ. MetaAct thus learns 

what to gate, not how to gate . The guarantee is local to the represented constraint: actions rejected by the current guard cannot pass through it, but failures outside the expressivity or evidence of Σ

A candidate specification passes through two pre-deployment checks and one post-deployment mon-itor. The first check is a type contract applied during compilation: a contract T maps each primitive 

π to the extractor families it admits, COMPILE rejects any specification with e / ∈ T (π), and null 

parameters are replaced by declared defaults. This prevents the two implementation failures ob-served during development, primitive–extractor incompatibility and parameter-type mismatch. The second check is the replay gate , an empirical verifier in a counterexample-guided inductive synthesis loop (Solar-Lezama et al., 2006): each candidate is compiled and replayed, and a rejected candidate returns concrete counterexamples to the next synthesis round. Unlike classical CEGIS, no formal specification is assumed; previously logged trajectories serve as the evidence. Let F and S denote the failed and successful trajectories, respectively, recorded for task type τ on the training slice. Replaying a compiled guard g over a trajectory produces a blocking decision for each action. We define failure coverage and the effective-action block rate as 

cov( g) = |{ f ∈ F : g blocks at least one action of f }| |F | , eff( g) = |{ a ∈ A+ : g blocks a }| |A+| ,

(2) where A+ is the set of effective actions—those that change the observation—in the safety reference 

S ∪ { f ∈ F : score( f ) ≥ σmin }.

A deployment-time win-rate monitor additionally retires an accepted constraint whose observed utility falls below a threshold after four uses; only 2 of the 23 ScienceWorld constraints reach four uses, so it is inactive in all reported results. 3.4 REPLAY -G UIDED SEARCH IN SPECIFICATION SPACE 

Constraint synthesis is formulated as an iterative search over the specification space, with candidate quality evaluated by the replay gate. At round t, the model proposes 

Σt ∼ LLM( τ, F, S, M, r t−1), (4) where M denotes the available primitive and extractor menu, and rt−1 is the counterexample report returned by the previous round. The search uses three complementary mechanisms: contrastive evidence, counterexample-driven repair, and constraint union. 

Contrastive evidence. The model receives both failed and successful trajectories, allowing it to identify rules that separate ineffective behavior from effective behavior rather than merely describing patterns observed in failures. In an initial WebShop experiment that supplied only failed trajecto-ries, the synthesized candidate blocked both unproductive and successful behavior, mis-blocking 

61 .4% of successful trajectories. Including successful trajectories provides the evidence needed to distinguish wasteful actions from productive ones. 

Counterexample-driven repair. When the replay gate rejects a candidate, it produces a report 

rt containing concrete examples of incorrectly blocked effective actions and missed wasted steps. These examples are provided directly to the model in the next synthesis round rather than being reduced to a scalar score; unlike text-based optimizers (Yang et al., 2024; Yuksekgonul et al., 2024; Agrawal et al., 2026), the signal is generated from the behavior of the compiled artifact on logged trajectories. 

Constraint union. A single candidate may capture only part of the observed failure pattern. At each round, we therefore evaluate the incumbent specification, the newly proposed specification, and their union:

Because the union of two specifications is compiled into the conjunction of their guards, its coverage and false-block rates remain directly measurable through offline replay. Union lets complementary candidates accumulate across rounds: on WebShop it expands a minimal gate-passing candidate into the final constraint set, and repeated accumulation can grow a specifica-tion to 17 constraints for use-thermometer (Figure 9). Search terminates when the replay gate accepts the current specification and ρ ≥ 0.8, or after a maximum of T = 3 rounds. Appendix C.4 shows that the third round never produces the first accepted candidate, indicating that successful synthesis typically occurs within the first two rounds.

5 CONCLUSION 

We presented MetaAct, a framework that extends language-agent self-improvement from textual guidance to executable action constraints. MetaAct synthesizes typed GEAR rules from execution feedback, compiles them into deterministic guards, and validates them through offline trajectory replay before deployment. Across four embodied-language benchmarks, MetaAct consistently im-proves task performance; on SciWorld and WebShop, executable constraints reduce target-rule vi-olations from 70% to 0% and from 40% to 1% , while improving task scores by +10 .1 and +8 .0,respectively. These results show that self-evolution can extend beyond textual adaptation: execution feedback can be converted into reusable constraints that directly shape future action selection.

C.1 BEHAVIORAL STABILITY ACROSS SYNTHESIS RUNS 

We distinguish textual reproducibility of the emitted specification from behavioral reproducibility after compilation. Across three independent synthesis runs with identical evidence and settings, only 2 of 20 shared task types receive the same primitive set in all three runs, and 12 of 20 receive the same replay-gate verdict. Despite this textual variation, the compiled specifications agree on 86.1% of per-action decisions (949 /1102 ) when replayed over the same 60 held-out trajectories. The replay gate evaluates candi-date behavior rather than exact textual form, so different specifications may be accepted when they implement similar blocking decisions. C.4 ANALYSIS OF SYNTHESIS COVERAGE 

We evaluate three potential explanations for partial coverage: primitive expressiveness, replay-gate strictness, and the amount of failure evidence. First, adding a primitive targeted at a common rejected diagnosis does not increase aggregate cov-erage. Seven of ten gate-rejected candidates describe the agent leaving the task-relevant location, a pattern not expressible by the original five-primitive menu. We therefore add revisit block ,which keeps the agent at the location associated with the anchoring action, and rerun synthesis with the primitive menu as the only change. The new primitive is selected for 2–3 task types per run and corrects specific failures, but the six-primitive menu verifies 8/9/9 of the 16 shared types, com-pared with 8/9/10 for the five-primitive menu. Metrics aggregated over all actions can include behavior controlled by agent components that are unchanged across the compared conditions. We observe this issue in three forms. 

Dominance by an unchanged primitive. In the SciWorld fidelity calculation, 85 of 98 true posi-tives come from no op repeat , which is active in both variants. An aggregate F1 score therefore mostly reflects agreement on a rule family that is not under evaluation. 

Scope spillover. False positives can occur on non-focus actions outside the scope of the focus guard. Under the aggregate metric, increasing synthesis evidence appears to reduce fidelity ( F1 =0.222 ); under focus-isolated precision, the ordering reverses ( 0.778 versus 0.625 ). 

Violation-rate contamination. Using the unrestricted specification to evaluate Section 4.3 pro-duces 78 apparent violations in the constrained SciWorld variant. All are no op repeat disagree-ments on repeated look around actions, while the focus-family count is zero. 20 Self-Evolving Executable Action Constraints for Embodied Language Agents These cases show that action-level evaluation of a composite agent should be restricted to the scope of the sub-module being changed. Error types should also be interpreted according to their costs, because a false block and a missed block can have substantially different consequences in an irre-versible action space. D.5 SELECTION EFFECTS IN WIN -R ATE -B ASED VALIDATION 

The surviving lessons in the prompt-evolve variant can have high observed win rates (e.g., uses =6 and wins =4), but the retention rule itself keeps only lessons whose win rate exceeds 50%. High win rates among retained lessons are therefore partly a consequence of conditioning on survival. With a base success rate of 0.22, some retained lessons may reflect favorable short sequences rather than reliable improvements. Evaluations of win-rate-gated memories should therefore account for this selection effect. 21
