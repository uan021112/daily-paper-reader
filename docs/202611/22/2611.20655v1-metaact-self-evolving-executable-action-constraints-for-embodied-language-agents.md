## 摘要
自我演进语言智能体已成为一种颇具前景的范式，能够通过经验持续改进智能体行为。然而，现有大多数方法演进的是文本产物；这些产物虽能影响动作偏好，却无法在动作离散且往往不可逆的具身环境中可靠地约束动作是否可执行。我们提出 MetaAct，将自我演进从文本指导转向可执行动作约束，通过执行反馈合成 GEAR（Grounded Executable Action Rules，基于环境约束的可执行动作规则）。每条规则均以类型化规范表示，编译为确定性守卫，并通过轨迹回放进行离线验证，无需额外调用模型或与环境交互。在四个基准测试中，MetaAct 均提升了任务表现；在 ScienceWorld 和 WebShop 上，违规率分别从 70% 降至 0%、从 40% 降至 1%，得分分别提高 10.1 和 8.0。代码见 https://github.com/BaiCubed/MetaAct。

## Abstract
Self-evolving language agents have emerged as a promising paradigm for continuously improving agent behavior through experience. However, most existing approaches evolve textual artifacts, which can influence action preferences but cannot reliably enforce action admissibility in embodied environments with discrete and often irreversible actions. We propose MetaAct, which shifts self-evolution from textual guidance to executable action constraints by synthesizing GEAR (Grounded Executable Action Rules) from execution feedback. Each rule is represented as a typed specification, compiled into a deterministic guard, and validated offline through trajectory replay without additional model calls or environment interactions. Across four benchmarks, MetaAct improves task performance; on ScienceWorld and WebShop, violations drop from 70% to 0% and 40% to 1%, with score gains of +10.1 and +8.0. Our code is available at https://github.com/BaiCubed/MetaAct.

# 1. 核心问题与整体含义

- **研究问题：**具身语言智能体在 ScienceWorld、WebShop 等环境中执行离散动作，部分动作一旦执行便难以撤销。现有自我改进方法主要把失败经验转化为文本提示或反思，能影响模型的动作偏好，却不能保证模型真正遵守规则。
- **论文的核心主张：**在这类环境中，仅让智能体“知道”规则并不足够，还需要在动作执行接口处限制违规行为。MetaAct 因而把经验从文本指导转化为**可执行、可验证的动作约束**。
- **整体含义：**论文试图弥合智能体“知道规则”与“按规则行动”之间的差距：从失败和成功轨迹中提炼规则，编译为确定性动作守卫，再在后续任务中直接过滤不允许执行的动作。

# 2. 方法论

## 2.1 核心思想与 GEAR 表示

MetaAct 将大语言模型限制在**规则规范生成**层面，而不是让模型直接编写可执行代码。它提出 GEAR（Grounded Executable Action Rules）：

1. 模型根据失败、成功轨迹及任务类型，生成类型化规则规范；
2. 固定编译器检查规范是否合法，并将其编译成确定性守卫；
3. 在执行时，守卫过滤候选动作，或拒绝不合规动作并向规划器返回触发信息。

规则包含三类信息：规则原语、由预定义提取器读取的类型化参数，以及规则触发时反馈给规划器的提示消息。论文使用六种原语：

- `ordered once`：强制两个动作类别按指定先后顺序执行；
- `no op repeat`：观察未变化时阻止立即重复动作；
- `idempotence block`：阻止已产生效果的动作再次执行，包括某些交替重复模式；
- `revisit block`：在锚定动作后限制返回已访问位置；
- `generic deref`：将“该物质”等泛指解析为目标中对应实体；
- `relevance filter`：将某类动作限制在从任务目标提取出的相关候选集合内。

## 2.2 动作守卫与离线验证

设当前历史为 \(h_t\)，环境提供的候选动作集合为 \(A(h_t)\)，规则规范为 \(\Sigma\)。编译后的守卫判断动作是否允许：

\[
A_\Sigma(h_t)=\{a\in A(h_t):G_\Sigma(h_t,a)=1\}.
\]

也就是说，守卫为每个候选动作作出确定性的允许或阻止决策。对于离散候选集，系统可在模型选动作前直接屏蔽违规动作；对于自由格式动作，则可在执行接口拒绝违规提议，并要求规划器重新选择。

候选规范需要经过两类验证：

- **类型契约：**检查原语与参数提取器是否兼容、参数类型是否正确；无效组合会被拒绝，空参数按声明的默认值处理。
- **轨迹回放门控：**在已有失败轨迹 \(F\) 和成功轨迹 \(S\) 上回放编译后的守卫，估计其拦截效果和误拦风险。论文定义失败覆盖率 \(cov(g)\)、有效动作拦截率 \(eff(g)\)，以及成功轨迹上的拦截率 \(ok(g)\)。只有同时满足
  \[
  cov(g)\ge 0.3,\quad eff(g)\le 0.15,\quad ok(g)\le 0.10
  \]
  的候选才通过门控。这里的阈值由作者设定，并在附录中进行门控标准分析。

回放只检查守卫对**已记录动作**会作出什么判断，因此不需要新的环境交互，也不需要额外的模型调用。论文强调，这是一种基于经验轨迹的实证筛选，并非形式化安全证明。

## 2.3 规范搜索与在线维护

候选规则采用迭代搜索方式产生：

1. 模型结合任务类型、失败与成功轨迹，以及上一轮的反例报告，提出新规范；
2. 若规范被回放门控拒绝，系统把误拦的有效动作、漏掉的无效步骤等具体反例反馈给下一轮；
3. 将已有规范、新规范及两者并集都进行回放比较，保留得分较好的版本。论文将并集编译为多个守卫的合取，使互补规则可以累积；
4. 搜索最多进行三轮；达到门控要求且浪费步骤检测率 \(\rho\ge 0.8\) 时可提前停止。

部署后还设置了按实际表现退休规则的监控机制：某条规则至少使用四次后，若观察到的效用低于标准，则可将其移除。不过论文报告中，达到四次使用的 ScienceWorld 规则很少，因此该机制在主要结果中基本没有发挥作用。

# 6. 主要结论与发现

- **总体基准表现：**MetaAct-synth 在 ScienceWorld 主表中取得 0.367 成功率和 62.1 得分；在 ALFWorld 达到 0.955 成功率，与该表中的最佳成功率相同；在 TextCraft 达到 0.950 成功率和 97.5 得分；在 WebShop 得分为 62.1，主表中高于所列基线。
- **文本指导与执行约束的差异：**在匹配证据实验中，ScienceWorld 上文本指导的得分变化约为 −0.15，而 MetaAct 提高约 10.15；WebShop 上 MetaAct 提高约 8.01，文本变体的收益则不显著。
- **规则遵循机制：**论文报告，文本中明确写出规则并未显著降低目标规则违规；编译为动作约束后，ScienceWorld 违规率从约 70% 降至 0%，WebShop 从约 40% 降至约 1%。作者据此认为，文本能改善偏好但不保证服从，动作屏蔽才直接阻止违规动作执行。
- **验证与安全性：**回放筛选后的候选在留出轨迹上的有害拦截率低于被拒候选；其中有效动作拦截率 \(eff(g)\) 对有害行为的预测力较强。但回放仍只是已有轨迹上的经验验证，不保证未见状态下绝对安全。
- **在线学习：**WebShop 连续 100 个回合的在线实验中，MetaAct 报告的违规率为 0.130，低于无学习的 0.310 和文本经验演化的 0.350；后 20 回合的滚动得分也高于前 20 回合。
- **总体结论：**将执行反馈转化为可编译、可回放验证的规则，可以比单纯更新文本更直接地控制动作可执行性；但收益依赖规则表达能力、合成质量和验证轨迹的代表性。

# 7. 优点

- **问题切入明确：**准确区分“改变模型偏好”和“限制动作可执行性”，特别适合动作离散且可能不可逆的任务。
- **实现边界清晰：**模型生成类型化规范，固定编译器负责执行，避免直接运行模型生成代码带来的不确定性。
- **具备离线筛选机制：**利用成功和失败轨迹进行回放，并将具体反例反馈给下一轮；相较仅凭语言描述判断规则是否有效，行为层面的检查更直接。
- **实验关注机制而非仅看得分：**通过违规率、误拦分析、执行策略对照、消融和跨骨干实验，尝试解释性能提升来自哪里。
- **考虑规则的适用范围与代价：**区分漏拦与误拦，并在附录分析复合规则积累后可能出现的过度屏蔽。
- **部署成本有一定优势：**已编译守卫的判断不需要额外模型调用；规则可跨回合复用。

# 8. 不足与局限

- **规则表达能力受限：**GEAR 只能覆盖预定义的六类原语和提取器。论文也承认，有些失败诊断无法映射为现有规则；例如部分“离开任务相关位置”的失败在加入 `revisit block` 后仍未能显著提高整体覆盖率。
- **验证是有限数据上的经验门控：**通过轨迹回放不等同于形式化正确性证明。若新任务分布、环境状态或动作语义与日志不同，守卫仍可能误拦正确动作或漏掉危险动作。
- **合成覆盖和稳定性有限：**作者报告合成规范在不同运行间文本变化较明显；不同运行的门控结论也不完全一致。规则的诊断到参数落地仍是主要难点。
- **规则累积可能导致过度限制：**多个规则合并后，动作拦截率会增加；若规则作用范围重叠，一些回合会出现较高比例动作被屏蔽。规则库规模扩大后的长期维护问题尚未充分解决。
- **消融中的任务表现仍有波动：**去掉不同组件会影响违规率和得分，但部分在线结果并非单调变化，说明性能收益不完全由单一组件决定，且受任务和样本波动影响。
- **跨模型与跨环境验证不足：**跨骨干实验仅在 ScienceWorld 上进行；虽然主结果覆盖四个文本环境，但不能直接推出对真实机器人、视觉输入或连续控制任务同样有效。
- **资源报告不完整：**没有 GPU、运行时长等硬件信息；token 成本虽有报告，但不足以完整衡量训练、合成、推理和环境交互的总成本。
- **结果需结合实验口径解读：**主要结果、匹配对照和三种子分析采用不同配置或统计口径；此外，部分任务的约束触发机会和样本数量有限。论文附录也提示，对复合智能体的指标应限定在被研究的规则范围内，避免将未改变的组件行为混入评价。
