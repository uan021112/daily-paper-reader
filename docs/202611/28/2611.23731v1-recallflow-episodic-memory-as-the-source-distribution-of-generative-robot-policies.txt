Abstract
Diffusion and flow-matching policies have become a stan-
dard choice for visuomotor imitation learning, owing to
their ability to model multimodal action distributions. In
memory-dependent manipulation, the robot must act on in-
formation that is no longer visible. Existing methods feed
the observation history to the policy as an additional con-
dition, while action generation still starts from Gaussian
noise. However, the policy must then pick out the relevant
target from a long and redundant history, leading to spu-
rious correlations and unreliable decisions as the memory
load grows. Additionally, the initial noise carries no in-
formation about what the robot has seen, leaving genera-
tion without guidance toward the remembered target. To
address these issues, we propose RecallFlow, a flow-policy
framework that builds the source distribution from episodic
memory. Recall–Relocalization relates the memory to the
current view through a few recall slots, so that the source
reflects where the remembered targets are now. Recall An-
chors then turns each slot into a Gaussian component of the
source, enabling generation to start close to the intended
action instead of from noise. The transport network then
completes the action from the current observation alone,
keeping inference nearly as cheap as a memoryless pol-
icy. We further build a suite of memory-dependent tasks
grouped by memory load and compare all policies under
a matched protocol. Extensive experiments show that Re-
callFlow achieves a state-of-the-art average success rate
of 80.4% on the public MIKASA-Robo memory benchmark,
and outperforms the strongest baseline by 20.3 points on
our suite and by 18.8 points on four real-robot tasks.

fusion and flow-matching policies [2, 9, 33, 35] transport
samples from a simple source distribution, usually an
isotropic Gaussian, to the distribution of demonstrated
actions, conditioned on the current observation.
To
handle memory-dependent tasks, recent methods extend
this condition with the past: they feed long observation
windows to the policy [39, 57], read the history through
gated cross-attention [15], or maintain structured memory
states [18, 27, 50].
Despite this progress, two issues remain. First, memory
enters only as an additional condition, so a single network
must both pick out the relevant target from a long and redun-
dant history and decide how to move. This invites spurious
correlations [12, 62] and can make such policies fall far be-
low memoryless ones on tasks that need no memory [15].
Second, generation still starts from uninformed noise, leav-
ing it without guidance toward the remembered target.
Learned priors can replace this noise, but existing ones are
derived from dataset statistics, the current observation, re-
cent actions, other episodes, or a compressed history [10,
21, 30, 32, 67], not from the targets seen earlier in the same
episode. Together, these issues make history-conditioned
policies increasingly unreliable as the memory load grows.
We take a different view and argue that the memory of an
episode belongs in the source. Flow matching can transport
any source distribution to the action distribution [33, 35], so
the source is free to carry what the robot remembers. Gen-
eration would then start near the remembered target, and
the network would only need to refine the motion from the
current observation. However, memory cannot simply be
plugged into the source. What was seen earlier must first
be found again in the current view, a problem long studied
in video understanding [6, 16, 47, 56, 60]. It must then be
expressed as a distribution over actions.
To this end, we propose RecallFlow, a flow-policy
framework that builds the source distribution from episodic
memory (Fig. 2). It rests on a division of labor: memory
decides where generation starts, and the present decides
how to get there.
Recall–Relocalization: relating memory to the current
view. RecallFlow keeps an episodic memory bank of patch-
level tokens from earlier frames. Memory attention lets the
current visual tokens read this bank. A few learnable recall
slots then read both the memory and the current view, so that
the source reflects where the remembered targets are now.
Recall Anchors:
starting generation from memory.
Each recall slot is mapped to a Gaussian anchor in action
space, and the anchors, together with a standard Gaussian,
form a mixture source. Generation thus starts close to the
intended action instead of from noise. A transport network
then completes the action chunk from the current observa-
tion alone, keeping inference nearly as cheap as a memory-
less policy.
On RecallSuite, our suite of five memory-dependent
tasks, RecallFlow improves the average success rate by
20.3 points over the strongest of two memoryless and two
history-conditioned policies under the same protocol, with
the largest margins where several items must be remem-
bered (64.7% vs. 15.0% on NOREPEAT-4). On the public
MIKASA-Robo benchmark [8], it reaches 80.4% average
success over five tasks, above the best published result of
75.1% [18]. On RoboMimic [39], where the current ob-
servation suffices, it stays on par with memoryless policies,
whereas long-history policies degrade. On a real xArm 7, it
improves over the strongest baseline by 18.8 points on four
memory-dependent tasks. Ablations show that forming the
source from the episodic memory matches or exceeds con-
ditioning the same transport network on it (97.0% vs. 92.0%
on NOREPEAT), and that relocalization matters most when
the memory load is high. Our contributions are as follows:
• Memory as source. We form the source distribution of
a flow policy from episodic memory as likelihood-trained
Gaussian anchors, so that generation starts close to the
intended action.
• Recall–Relocalization. Memory attention and a few re-
call slots relate the episodic memory to the current view,
so that the anchors reflect where the remembered targets
are now.
• Evaluation. We build a suite of five memory-dependent
tasks grouped by memory load. Under a matched pro-
tocol, RecallFlow achieves the highest average success
rate on it, and it sets the state of the art on the public
MIKASA-Robo benchmark.
2. Related Work
Memory-dependent manipulation. Visuomotor policies
usually condition on a single frame or a short window of
observations [9, 65]. The simplest form of memory extends
this window to a long history [63] or the whole episode,
which raises the training cost and invites spurious corre-
lations [12, 51, 62]. To make long histories usable, one
line of work regularizes or compresses them [15, 57]. An-
other keeps only a few key frames selected by a vision–
language model [51, 53].
A third line maintains struc-
tured memory states: an event-level memory indexed by the
control state [18], a slot memory addressed by the robot’s
trajectory [31], a combination of working and episodic
memory [27], or memory modules inside vision–language–
action models [50, 58]. SAM2Act [13] brings the memory
of a video segmentation model to keyframe-based manip-
ulation, and HAVE [29] ranks the samples of a memory-
less generator with a history-aware verifier. However, they
all use memory as a condition or as a selector of samples,
while generation still starts from uninformed noise. In con-
trast, RecallFlow delivers memory only through the source

Non-Gaussian sources and learned priors. Flow match-
ing and rectified flow [33, 35] can transport any source dis-
tribution, including sources coupled to the target [1]. Be-
yond robotics, generation has been started from another
modality, from data-dependent priors, or from optimized,
predicted, or warped noise [3, 17, 26, 34, 40, 68].
In
driving and robotics, DiffusionDrive [32] starts from an-
chored Gaussians clustered over the dataset, which cuts
the number of denoising steps. Other methods derive the
source from the current observation [10, 14, 36, 66], from
informative prior policies [5, 48], or from previous ac-
tions [21, 23, 24, 41], and a related line steers frozen poli-
cies in their noise space [42, 54, 61]. Closest to ours, Op-
timusVLA [30] averages trajectories retrieved from other
episodes into a prior, Chronos [67] generates a coarse prior
from a compressed history, SL-FM [64] learns a state-
conditioned Gaussian-mixture source by likelihood, and
MOSS [38] builds mode-specific Gaussian sources so that
the starting point selects the behavior mode. However, none
of these sources keeps track of which target was seen ear-
lier in the episode or where it is now. RecallFlow also learns
a mixture source by likelihood, but forms it from episodic
memory relocalized in the current view.
Memory attention in video understanding. Reasoning
about objects that are no longer visible has long been stud-
ied in video understanding [16, 56, 60]. Space-time mem-
ory networks [44] segment objects by letting the current
frame attend to a memory of past frames. XMem [6] or-
ganizes this memory for long videos, Cutie [7] reads it at
the object level, and SAM 2 [47] makes memory attention
the core of promptable video segmentation. Long-video un-
derstanding compresses memory banks by merging similar
entries [19], and set prediction reads one object per learn-
able query [4, 37]. Recall–Relocalization builds on memory
attention and learnable queries, but its output is not a mask:
it defines where action generation starts.

The encoder is SigLIP 2 [59] and the transport network is a

GMP [15]. Without the two components introduced below,
the policy is a memoryless flow policy, denoted FM, which
shares the encoder, transport network, and training recipe
with RecallFlow and serves as its memoryless counterpart.
3.2. Recall–Relocalization
What the robot remembers was seen in the past, but the ac-
tion must be generated for the present. By then the arm has
moved, the wrist camera with it, and the cue itself may be
gone. A memory can therefore guide generation only after
it has been related to the current view. Motivated by this,
Recall–Relocalization proceeds in three steps (Fig. 2, cen-
ter): the present tokens read an episodic memory bank, a
few recall slots read the memory and then the present, and
each slot pools the present-view evidence for what it recalls.
Episodic memory bank. After each executed chunk, Re-
callFlow writes the patch tokens of the frame at which the
chunk started, from both cameras, into a memory bank M.
Keeping the tokens at patch level preserves the spatial de-
tail needed to relate a memory to the current view. Each
token is tagged with learned embeddings of its camera, its
grid position, and its age measured in chunks. An entry thus
corresponds to one real moment of the episode. Entries are
merged only when the bank is full: with a capacity of C
entries, the two most similar adjacent entries are merged
position by position. At the first chunk of an episode the
memory is empty, and all recall slots are masked.
Memory attention. The present tokens first read the mem-
ory, in the same way as the current frame reads past frames
in video object segmentation [44, 47]. Memory attention
has Lm layers, each applying self-attention over the present
tokens, cross-attention from the present tokens to M, and
an MLP. It outputs memory-conditioned present tokens ˆZt.
Recall slots. K learnable queries, the recall slots, are de-
coded by Lq layers. In each layer, the slots attend to each
other, then to M (what is remembered), and then to ˆZt
(where it is now). The output is one embedding ek per slot,
which turns a memory of variable size into a fixed set of
candidates for the source.

This loss moves the anchors towards the demonstrated

the same loss also trains Recall–Relocalization.
We do not train the anchors with the flow loss that trains
the transport network (Sec. 3.4), because it rewards the
wrong property. It asks the network to recover A⋆from
an interpolant between a source sample and A⋆. When the
source is narrow, the source sample is almost known in ad-
vance, so the interpolant gives A⋆away even if the source
carries no information about it. The flow loss would thus
reward anchors for being narrow rather than for being right.
Two regularizers complete the objective: a KL term LKL
pulls each anchor to N(0, I), and a relaxed winner-takes-all
term Lε [49] keeps every slot trained (Sec. A).

4. Experiments
4.1. Experimental Setup
Benchmarks. We evaluate on three simulated benchmarks
and a real robot, each answering one question. RecallSuite,
our suite of five memory-dependent tasks (Fig. 3), tests
how policies cope with a growing memory load and hosts
all protocol-matched comparisons and ablations. MIKASA-
Robo [8] is a public memory benchmark, on which we
compare with published methods; we use its five memory-
intensive tasks with 250 demonstrations each, the setting
in which these methods report their results [15, 18, 50].
RoboMimic [39] contains tasks that the current observation
suffices to solve, on which we test whether memory hurts
when it is not needed. The real-robot experiments are de-
scribed in Sec. 4.5.
Tasks of RecallSuite. The five tasks fall into two groups
of memory load. In the single-item tasks, one remembered
quantity decides the action. In MARKEDPLATE, a marker
descends into one of five identical plates and leaves, and the
robot must place a cube into that plate. In COUNTSWING,
the robot must swing a cube between two pads as many
times as a row of indicators shows, which requires re-
membering how many swings it has made. In the multi-
item tasks, the robot must keep several events in mind.
In NOREPEAT, it must touch each of three identical con-
tainers exactly once, and NOREPEAT-4 uses four contain-
ers. In MARKEDPAIR, a marker hovers over two of four
identical containers in turn, and the robot must then touch
both. Each task comes with 250 scripted demonstrations;
Sec. B gives the details and relates the tasks to those of prior
work [8, 11, 18]. We report the success rate, where a trial
succeeds only if the first choice is correct and the task is
completed, so that trial and error is not rewarded.
Baselines. We compare with two groups of policies. The
memoryless group contains Diffusion Policy (DP) [9]
and FM, the memoryless flow policy of Sec. 3.1, i.e.,
RecallFlow without its memory. The history-conditioned
group contains medium- and long-history DP, which condi-
tion DP on the frames of the past 16 and 120 steps and thus
represent memory used as a condition. All baselines keep
their released hyperparameters (Sec. C). Published memory
methods are compared on MIKASA-Robo (Tab. 2).
Protocol. Within a benchmark, all policies that we train
share the demonstrations and, on each task, the number of
gradient steps. We save checkpoints periodically, evaluate
each on the same 100 episodes in deterministic mode, and
report the best one for every policy. On RecallSuite and
RoboMimic, we train three seeds per method and report the

4.4. Analysis of the Generation Process
RecallFlow rests on a division of labor: memory decides
where generation starts, and the transport network only
completes the motion.
Success rates alone do not show
whether the policy works this way, so we examine the gen-
eration process itself on NOREPEAT (Fig. 5).
The choice is made in the source. At a decision in which
two of the three containers have already been touched, all
30 source samples of RecallFlow head to the remaining
one before any transport step (Fig. 5a). Over 15 decisions,
99.6% of its source samples head to an untouched container
(Fig. 5b). In long-history DP, run on the same observations,
the choice emerges only during generation: 4.0% of the
samples head to an untouched container at the start, 46.7%
after six of the eight denoising steps, and all of them only
at the end. A history-conditioned policy thus has to settle
which target to go to while it generates the motion, the cou-
pling that RecallFlow removes.

4.5. Real-Robot Experiments
We use an xArm 7 with a parallel gripper, a wrist cam-
era, and a third-person camera, using only their color im-
ages (Fig. 6a). We design four tasks (Fig. 6b) that differ
in what must be remembered: a color that was shown, the
robot’s own earlier actions, or a place marked by a person.
In Remember Color, a block of the target color is shown and
then hidden under a board, where three blocks are shuffled;
once the board is lifted, the robot must pick the block of the
shown color. In No Repeat, the real counterpart of NORE-
PEAT, the robot must touch each of three identical cups ex-
actly once. In Marked Plate, it must place a cube into the
plate that a person has set down, and in Shell Game, lift the
cup under which a person has hidden a block. We collect
120 demonstrations per task and train RecallFlow, DP, FM,
and long-history DP for 19,600 steps each. All policies are
evaluated at their last checkpoint on the same 24 initial lay-
outs per task, once per layout in a rotated order, with the
operator unaware of which policy is running (Sec. F). As
shown in Fig. 6c, RecallFlow achieves the highest success
rate on all four tasks, 82.3% on average against 63.5% for
long-history DP, the strongest baseline; the margin is largest
on Remember Color (83.3% vs. 37.5%). Without its mem-
ory, RecallFlow reduces to FM, which reaches 18.8% on
average. The memoryless policies never succeed on No Re-
peat; Fig. 6d illustrates the three behaviors that we observed
on this task.
5. Conclusion
We presented RecallFlow, a flow-policy framework that
builds the source distribution from the episodic memory of
8


the robot. Recall–Relocalization relates the memory to the
current view, and Recall Anchors turns it into likelihood-
trained Gaussian anchors. On a protocol-matched suite, the
public MIKASA-Robo benchmark, and a real robot, this de-
sign is most effective when several items must be remem-
bered, and on RoboMimic it does not hurt tasks that need
no memory. Our memory stores visual tokens of single-arm
tabletop scenes at a fixed capacity, so tasks with a long and
dense relevant past may require a memory that summarizes
the past instead of storing its frames. Extending memory as
source to language-conditioned and multi-task policies is a
natural next step.

A. Implementation Details
Encoder and present tokens. Images of 128×128 are up-
sampled to 256 × 256 and encoded by SigLIP 2-B/16 [59],
fine-tuned end to end with 0.1× the main learning rate. The
16 × 16 patch tokens of each view are average-pooled 2 × 2
to 8 × 8. The present Zt holds the tokens of the current and
the previous step from both cameras (2 × 2 × 64 = 256).
Memory bank. After each executed chunk, the 2 × 64 =
128 tokens of the chunk’s first frame are written with
learned camera, position, and age embeddings. While the
memory is empty, a learned null entry takes its place. The
capacity is C = 32 entries. When it is exceeded, for ev-
ery spatial position the two adjacent entries with the high-
est cosine similarity are averaged into one, so unchanged
positions are merged and changed positions keep their his-
tory. Episodes of RecallSuite have at most 27 chunks and
stay within the capacity; it is exceeded on Square (mh) of

Recall–Relocalization. Memory attention has Lm = 2
layers with width 256; each layer applies self-attention,
cross-attention to M, and an MLP, the layer structure of
the memory attention in SAM 2 [47]. The slot decoder has
Lq = 2 layers and K = 4 slots. Heatmaps are normalized
per camera over the 64 current-frame tokens of that cam-
era, and gk concatenates the two pooled features (2 × 256
dimensions), so the anchor MLP receives [ek; gk] with 768
dimensions.
Recall Anchors. MLPa, MLPℓ, and MLP∅are two-layer
MLPs. Anchors live in the normalized action space of di-
mension H × d, with d = 8 (seven joint targets and the
gripper), and σk = σmin + softplus(·) with σmin = 0.05.
Transport network. The transport network is a DiT [45]
with 16 layers, width 512, and 8 heads, conditioned on
Zt only. The flow time τ ∼U[0, 1) is embedded as 24τ,
and inference uses S = 8 Euler steps. Our implementa-
tion builds on the public code of GMP [15], from which
we remove the history pathway and replace the denoising
objective with rectified flow.

Training. For the first 2,000 steps, the transport network

The image encoder receives gradients only from the flow

applied to every chunk of the window. Each window starts

the end of the episode; chunks beyond the end are padding,

with a peak learning rate of 3 × 10−4.

B. RecallSuite Details
Tab. S2 summarizes the tasks. Scenes are built on Man-
iSkill3 [55] with the MIKASA-Robo framework [8]; the
third-person and wrist cameras and the robot are those of
MIKASA-Robo.
Tasks. All tasks are built in our own simulation; MARKED-
PLATE and NOREPEAT are related to the real-robot tasks
of [18], and COUNTSWING to the SwingXTimes task of
RoboMME [11]. In MARKEDPLATE, a marker without col-
lision geometry descends into one of five identical plates,
12 cm apart, pauses, and rises away; the robot holds a cube
from the start and must place it into the marked plate. In
NOREPEAT, the robot must touch each of three identical
containers, 15 cm apart, exactly once, in any order; touch-
ing leaves no visible trace. NOREPEAT-4 adds a fourth con-
tainer at the same spacing. MARKEDPAIR uses the scene of
NOREPEAT-4: a marker without collision geometry hovers
above two of the four containers in turn, for 8 steps each,
and then disappears; which two are cued, and in which
order, is drawn uniformly. The robot stays still while the
marker is shown and must then touch each cued container
once, in any order. In COUNTSWING, a row of five indi-
cator slots in front of the robot shows N ∈{2, 3, 4, 5},
drawn uniformly, as N red discs followed by gray ones,
lit throughout the episode; the robot starts with the cube in
its gripper, must swing it between a right and a left pad N
times, and then put it on a stop plate. A swing counts when
the held cube enters the zone above the right pad and then
the zone above the left pad, within 3 cm of the pad center
horizontally and below 12 cm; the whole layout is jittered
by up to 2 cm. The memory is written once per chunk of 8
steps, and the history-conditioned baselines subsample their
history at the same rate.
Demonstrations. Each task has 250 demonstrations gener-
ated by a motion-planning script under joint-position con-
trol, the same action space as at evaluation. All rows train
on the same 245 of them; the remaining 2% are held out.
Hidden answers are balanced across demonstrations. While
a cue or event is shown, the expert holds a fixed pose, so
that the arm configuration does not encode the answer. In
COUNTSWING, the expert first waits for 0, 24, or 48 steps,
drawn at random, and its joint angles in the frame before
each decision agree to within 7.6 × 10−6 rad.
Success. We log whether the first choice is correct and
whether the task is completed, and count an episode as suc-
cessful only if both hold. For NOREPEAT and NOREPEAT-
4, the choice is correct if no container is touched twice
and none is skipped.
For MARKEDPAIR, the task is
completed once both cued containers have been touched,
and the choice is correct if by then no other container
has been touched and none has been touched twice. For
COUNTSWING, the choice is correct if exactly N swings
have been made when the cube is first released, and the task
is completed if the cube lands on the stop plate.
Validation. The following checks were run on MARKED-
PLATE, NOREPEAT, and COUNTSWING; MARKEDPAIR
and NOREPEAT-4 reuse the scene, the expert, and the latch-
ing logic of NOREPEAT. Replayed on the evaluation path
with the evaluation seeds, the scripted expert succeeds in
all 100 episodes of every task, and every demonstration
replays as a correct choice and a completed task.
For
COUNTSWING, motion planning succeeds in all 450 gen-
erated episodes, 8 of them through a fallback to RRT, and
none of the 275 replayed episodes fails; 25 of them are
not used because the quota of their N is already filled.
Hidden answers are balanced: in MARKEDPLATE, each
of the five plates is the answer in exactly 50 of the 250
demonstrations; in NOREPEAT, the container the expert
touches first deviates from uniform by at most 3.2% (χ2
test, p = 0.94).
At the decision moment, a CNN that

Evaluation machines. Evaluations are spread over three
machines with different GPUs. On RecallSuite, the same
checkpoint differs by at most 3 points between machines,
and between two of them the outcomes of 98 to 100 of the
100 episodes are identical. On MIKASA-Robo, all seeds
are evaluated on these two machines, whose outcomes
agree in 99 of 100 episodes.
On RoboMimic, the same
checkpoint reaches 91% and 92% on them, with identical
outcomes in 93 of 100 episodes: the initial states differ
at the order of 10−8, and closed-loop control amplifies
the difference. With a deterministic cuBLAS workspace
configuration, RoboMimic evaluations repeat exactly on
the same machine.

mounted RGB-D camera, and a third-person RGB-D cam-
