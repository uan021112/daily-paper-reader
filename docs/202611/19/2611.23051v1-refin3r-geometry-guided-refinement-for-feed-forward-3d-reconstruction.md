## 摘要
前馈式 3D 重建模型可通过单次推理从多张图像预测稠密点图。然而，由于缺乏显式几何约束，其预测结果往往在不同视角间不一致，且精细程度不足。近期方法引入相机位姿或深度等几何先验，但仅将其用作辅助输入、独立处理各个视角，或只在先验可用的位置细化几何。我们提出 Refin3R，利用运动恢复结构（Structure-from-Motion，SfM）点细化前馈点图，并将 SfM 几何传播至图像网格。在其双分支架构中，2D 分支借助几何感知的骨干特征，将 SfM 几何扩展至其覆盖范围之外；3D 分支则对所有视角的 SfM 点进行推理，捕获仅凭图像网格无法表示的多视角结构。两个分支双向交换信息，以联合细化各个视角，从而生成稠密且准确的点图。在 ScanNet++、ETH3D、Tanks&Temples，以及域外的人体和手术场景上，Refin3R 在点图精度方面始终优于前馈式方法和几何引导方法，同时运行速度快于性能最强的几何引导基线。

## Abstract
Feed-forward 3D reconstruction models predict dense point maps from multiple images in a single pass. Without explicit geometric constraints, however, their predictions are often inconsistent across views and lack fine-grained precision. Recent methods incorporate geometric priors such as camera pose or depth, but use them merely as auxiliary inputs, process each view independently, or refine the geometry only where the priors are available. We present Refin3R, which refines feed-forward point maps with Structure-from-Motion (SfM) points, propagating SfM geometry over the image grid. In its dual-branch architecture, a 2D branch extends SfM geometry beyond its coverage using geometry-aware backbone features, while a 3D branch reasons over the SfM points of all views, capturing multi-view structure that the image grid alone cannot represent. The two branches exchange information bidirectionally to jointly refine each view, yielding dense and accurate point maps. Across ScanNet++, ETH3D, Tanks\&Temples, and out-of-domain human and surgical scenes, Refin3R consistently outperforms feed-forward and geometry-guided methods in point map accuracy while running faster than the strongest geometry-guided baseline.

# 1. 核心问题与整体含义

- **研究问题**：如何在保留前馈式多视图 3D 重建速度和稠密输出的同时，提升其几何精度与跨视角一致性？
- **背景与动机**：
  - 前馈模型（如 DA3、Pi3X）能够一次推理生成稠密点图，但依赖学习到的先验，缺少显式的三角测量等几何约束，因而可能出现视角间不一致、局部细节不准确等问题。
  - SfM 通过跨图像匹配与三角测量获得几何上较准确的点，但通常较稀疏；在低纹理、低重叠或宽基线场景中也可能失败或产生离群点。
  - 论文的基本出发点是：**前馈预测“稠密但不够准”，SfM“准确但不完整”，两者互补**。因此，Refin3R 希望以 SfM 几何为锚点，并借助稠密图像特征将几何信息传播到 SfM 未覆盖的区域。

# 2. 方法论

## 2.1 输入与表示

- 对多张输入图像，先用前馈模型得到每个视角的初始相机参数、稠密深度 \(D^{ff}\) 和中间几何感知特征。
- 再运行 SfM 流程：使用 RoMa v2 建立匹配，通过稀疏束调整优化相机，并以多视图三角测量得到稀疏但较准确的 SfM 点及其有效性掩码 \(M\)。
- 将两类重建结果都表示为各视角图像网格上的深度，并在网络中使用对数深度 \(\zeta=\log D\)，以压缩深度动态范围。输入还包含相机射线、前馈深度、SfM 深度、两者差值及有效性掩码。

## 2.2 二维—三维双分支细化

- **2D 分支**：在每张图像的像素网格上运行 U-Net。它融合前馈深度、当前视角的 SfM 深度、相机射线、深度差及有效性掩码，并使用前馈骨干网络提取的稠密几何感知特征作为引导。分支预测对数深度残差，形成稠密的细化深度。它的关键作用是依靠图像上下文，把 SfM 几何传播到没有三角测量点的区域。
- **3D 分支**：将所有视角的 SfM 点投影到当前视角对应的稀疏体素网格中，并用稀疏 3D U-Net 在三维空间中聚合信息。网格以像素位置和离散化对数深度为索引，因此可以表示同一像素射线上来自不同视角的多个 SfM 点，也能利用当前视角不可见或未直接观测到的多视图几何证据。分支在当前视角自己的 SfM 像素上输出细化深度和置信度。

## 2.3 双向信息交互与空间融合

- 两个分支在较粗尺度进行双向交互：
  - **2D→3D 注入**：把像素处的图像特征复制到对应体素，使 3D 分支获得图像语义与局部上下文。
  - **3D→2D 汇聚**：将当前视角相关体素沿深度轴池化，再融合到 2D 特征中，使 2D 分支获得其他视角提供的多视图几何证据。
- 最后使用空间传播网络融合分支输出。以 2D 分支的稠密深度为初值，在 SfM 观测位置用置信度融合 SfM 深度与 3D 分支深度作为锚点，再通过学习得到的邻域权重和偏移迭代传播。论文使用 \(T=6\) 轮传播，输出最终深度，并利用 SfM 相机参数反投影为点图。
- 训练时监督最终输出、2D 分支输出和 3D 分支在自身 SfM 像素上的深度；稠密输出采用带置信度的深度误差损失，3D 分支采用 L1 损失。

## 3.1 数据集与场景

- **评测数据**：
  - 标准多视图评测：ScanNet++、ETH3D、Tanks&Temples。

- **主要指标**：点图相对真实几何的准确率曲线下面积（AUC），以厘米级误差阈值为主；域外手术数据另以毫米级阈值评测。

# 6. 主要结论与发现

- Refin3R 在论文报告的标准测试集和域外场景中总体取得了较好的点图精度，并优于所比较的前馈式和几何引导方法。
- 以 DA3 为骨干时，Refin3R 在 ScanNet++、ETH3D、Tanks&Temples 的 4、8、16 视角主结果中均优于同骨干 GGPT；Pi3X 版本也表现出类似优势。
- 域外实验显示，该方法在人体与手术场景中也能保持较强表现；其结果并非所有单项指标都高于所有基线，例如 MV-dVRK 的部分阈值下 DA3 版本优于 Pi3X 版本。因此，更准确的概括是整体结果有竞争力且多数比较领先，而不是每个配置、每个指标都无条件第一。
- 消融实验表明：图像网格上的几何细化、骨干图像特征、3D 分支的多视图信息交互，以及空间传播融合都对结果有帮助；仅在 SfM 像素处硬替换深度不如带置信度的空间传播。

# 7. 优点

- **针对性明确**：直接利用“稠密但不准”与“准确但稀疏”的互补性，解决 SfM 覆盖之外的细化问题。
- **二维与三维分工合理**：2D 分支负责利用稠密特征扩展覆盖，3D 分支负责聚合跨视角空间证据，弥补单视图深度图无法表达的结构。
- **交互设计细致**：通过注入和汇聚实现双向信息交换，而非简单串联两类输入。
- **融合方式考虑邻域影响**：空间传播不只替换 SfM 覆盖像素，而是将可靠几何锚点自适应传递给周围像素。
- **评测维度较多**：包含多视角数量、多个常规数据集、两类域外数据以及消融和效率评估。
- **实用性有潜力**：论文报告细化模块推理较快，且在性能上优于其比较的 GGPT 版本。

# 8. 不足与局限

- **依赖 SfM 前端质量**：若匹配、相机估计或三角测量失败，错误几何可能成为噪声输入；论文强调利用 SfM 的准确点，但其对严重离群点和前端失效的鲁棒性仍值得进一步验证。
- **仍有数据域覆盖限制**：尽管测试了人体和手术场景，训练仍基于有限的一组数据集；对动态物体、极端光照、低重叠、快速运动和大规模户外场景的适用性，正文证据有限。
- **绝对度量能力展示有限**：评测对齐预测与真值后计算误差，因而不能单独证明系统在未对齐情况下的绝对尺度和全局位姿精度。
- **效率口径不完全端到端**：SfM 前端不计入推理时间，主要结果也排除了 DA3 骨干；完整部署成本可能高于表中“方法自身”时间。
