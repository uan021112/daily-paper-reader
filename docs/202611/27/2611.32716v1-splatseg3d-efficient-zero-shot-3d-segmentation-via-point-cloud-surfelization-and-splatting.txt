Abstract
Open-vocabulary 3D segmentation methods rely on 2D foun-
dation models applied to registered images captured along-
side the 3D point clouds. However, such images may not be
available in many cases, while direct 3D point cloud seg-
mentation methods require semantic class supervision and
are challenging to deploy in a zero-shot manner. To address
these issues, we present SplatSeg3D, which segments a bare
colored point cloud in an open-vocabulary manner without
requiring the accompanying images, camera poses, class
supervision, or instance mask proposals. To achieve this, we
first surfelize the input point cloud and obtain oriented 2D
Gaussians. We then render views of the scene by splatting,
with a view selection strategy that maximizes scene coverage
with as few views as possible. Next, we apply text-prompted
segmentation on the rendered views, giving each 3D point
a set of multi-view semantic cues, fused to produce a 3D
segmentation of the scene. We evaluate SplatSeg3D on se-
mantic segmentation and novel-class instance segmentation
on 4 standard benchmarks: Scannet, Scannet++, Replica,
and S3DIS. Our pipeline not only performs better or on-par
with the state-of-the-art, but we also achieve these results
efficiently across runtime and compute requirements. Code
will be published.

When working with captured images of scans, flexibility
in view selection is limited. In our case, a camera placement
strategy is used to minimize the number of views while max-
imizing point cloud coverage, which is the main driver of
efficiency in SplatSeg3D. We frame this camera placement
as a depth-tested coverage problem over the point cloud, and
design an automatic camera pose selector. Segmentation
masks of the selected views can then be lifted to the point
cloud’s 3D points. The final semantic labels of points then
become the fused votes from the 3D lifted masks, and in-
stances are the connected components of each semantic class,
requiring no supervised 3D training or instance proposal net-
work. Our contributions are summarized as follows:
• SplatSeg3D, an open-vocabulary 3D segmentation method
whose only input is a colored point cloud, without any im-
ages, camera poses, or trained instance proposals. Instead,
SplatSeg3D renders its own virtual views through point
cloud surfelization and splatting.
• View selection algorithm for the splatted views, posed as a
depth-tested view-coverage problem, minimizing the num-
ber of views while maximizing the point cloud coverage.
• Zero-shot semantic and novel-class instance segmentation
on four standard benchmarks, performing on-par with
previous open-vocabulary 3D segmentation methods, and
exceeding all zero-shot baselines.
• Efficiency in compute and runtime: SplatSeg3D performs
3D segmentation while requiring much lower GPU com-
pute and runtime than other methods (Fig. 2). In combina-
tion with our zero-shot capability, the method is also more
efficient to deploy.

2. Related Work
Open-Vocabulary 3D Segmentation.
The most common
open-vocabulary segmentation approaches lift predictions
on 2D images accompanying the point clouds into 3D. Open-
Scene [33] fuses per-pixel vision-language features into
the points of the scene. OpenMask3D [42] queries class-
agnostic 3D proposals from a supervised Mask3D [38] by
aggregating CLIP [36] features over the top views of each
proposal, and JOPP-3D [18] and Open-YOLO 3D [4] re-
fine the same concept further by either exploiting 3D-to-
panorama correspondences or making the 3D segmentation
faster, respectively.
A parallel line of open-vocabulary works [25, 33] trains
a 3D network on supervision signals derived from the scan’s
images (distilled 2D features or captions), so that inference
only requires the point cloud. OpenScene’s [33] 3D variant
distills 2D features into a convolutional backbone. PLA,
RegionPLC, and Lowis3D [10, 11, 48] train on captions
paired with the 3D points of a benchmark. SceneSplat [26]
differs in that it trains and infers on the same Gaussian scenes
reconstructed from captured images. On the other hand,
there are recent methods that can directly operate on point
cloud data with specialized 3D network architectures [1, 24,
47]. These recent methods also perform better because they
extract foundational features directly from 3D data and pair
them with a supervised classifier to segment the point cloud,
whereas the before mentioned open-vocabulary methods
only rely on 2D foundational features.
Zero-shot methods instead lift 2D masks without any
3D training. They merge masks over frames [18, 32], and
fuse 2D detections into 3D instances that a text query re-
trieves by feature similarity [28], or merge superpoints [14]
guided by 2D masks [30]. GoDeep [3] labels points instead
of instances with a VLM that describes each posed image,
parses the description into object names, segments them,
and lifts the masks to 3D. SplatSeg3D builds upon these
concepts of zero-shot methods, so they are our primary com-
parison. However, we provide indicative comparisons with
other open-vocabulary methods that require dataset-specific
training.

Rendering Point Clouds and Splatting.
Rendering 3D
data to train 2D networks has been explored as a concept.
Multi-view CNNs [41] classify shapes from rendered views
and PointCLIP [50, 53] projects point clouds to depth maps
for zero-shot CLIP. These approaches operate on single ob-
jects, where a camera trajectory around them is sufficient.
However, in larger scenes, camera placement requires further
consideration, e.g. due to self-occlusions. The closest prior
work at scene scale is OpenIns3D [17], whose snap module
renders synthetic scene-level images of the point cloud and
a "Lookup" module assigns a class to 3D mask proposals
from 2D detections on them. However, its proposals come
from a trained class-agnostic 3D mask module [38], and its
synthesized images are used to classify them.
On the other hand, Gaussian primitives are usually opti-
mized against images: 3D Gaussian Splatting [20] and its
2D variant [16] fit Gaussian primitives to match target im-
ages. Segmentation via Gaussian splatting [26] is usually
performed via 2D semantics on the same target images used
for optimization. These semantic features are then either
optimized alongside the color [35] or uplifted into an already
optimized Gaussian scene [46]. In SplatSeg3D, segmenta-
tion is performed on the rendered views, from which both
semantics and instances are built, and no 3D network is
trained at any stage.
View Selection & Planning.
View planning has been used
in active reconstruction [7, 39], where next-best-view plan-
ners select sensor poses to look for the unknown geometry in
the scene. Our setting inverts that premise - the geometry is
fully known, and the observation is given, but the objective
is coverage of a scene at sufficient quality which is what a
2D segmenter can process.

4. Experiments
4.1. Implementation Details
Across all datasets we use the same constant values men-
tioned in Sec. 3: kn = 12 and kr = 6 neighbors, and views
are W = 512 px with θfov = 70◦(f = 365.6 px). h = 1 m,
δ = 10 cm, nψ = 8 yaws and ϕ = 20◦. ηmin = 5% of a
sample of Nη = 10,000 points. The resolution limits are
gstr = 0.010 m/px and glen = 0.020 m/px , and |Q| = 20,000
surfel centers. Instances are built on voxels of δI = 5 cm.
No camera, rendering or fusion constant is changed for any
benchmark. All experiments ran on one RTX A6000.

4.4. Efficiency
Table 5 compares time, computations and memory on
Replica, with every method tested on the same hardware
setup. SplatSeg3D takes 14.4 s to load and segment per
scene on average. Open-YOLO 3D [4] loads Mask3D [38] &
YOLO-World [6] and segments in 31.5 s, reading the scene’s
200 posed RGB-D frames and running pre-trained Mask3D
for instance proposals. OVIR-3D [28] takes 49.9 s, running
Detic [52] on every frame, Open3DIS [31] 130.1 s, ground-
ing the text in every frame with Grounding DINO [27].
The compute cost depends mainly on the input each
method uses and the model applied on them. We run the
segmenter, SAM3 [5] on the rendered views at 6.3 × 1013
FLOPs per scene. Open-YOLO 3D runs a convolutional de-
tector [6] instead on the scene’s frames and needs 13% fewer.
OVIR-3D needs 2.7 times FLOPS as ours, SceneSplat 6.3
times, and Open3DIS and OpenMask3D, which run SAM’s
ViT-H [12] encoder on every frame, are very compute heavy.
SplatSeg3D has the lowest memory usage as well. Ours
peaks at 2.3 GB, averaged per scene, 3.6 times less than the
next, Open3DIS, and 7.6 times less than Open-YOLO 3D.

4.6. Limitations
Overall performance is bounded by the segmenter. Classes
that the segmenter fails on, for e.g. refrigerator or bathtub, re-
main undetected at any camera configuration. In some cases,
fine-grained classes are classified as their coarser counter-
parts due to higher segmenter confidence.
Instance boundaries remain challenging. Correlation
clustering on the segmenter’s masks separates many nearby
objects, but labels still leak onto these objects. Methods that
outperform SplatSeg3D, use supervised instance predictors
like Mask3D that have higher fidelity in object boundaries.
The geometry assumptions are mainly valid for indoor
scenes. Normals are oriented toward the centroid, which
assumes a scene is observed from within, and cameras stand
at a fixed eye height above a detected floor, which assumes
indoor scenes.
8


5. Conclusion
We introduced SplatSeg3D, an open-vocabulary 3D segmen-
tation pipeline whose only input is a colored point cloud.
It surfelizes the point cloud and chooses camera views to
splat, followed by accumulating a frozen text-prompted seg-
menter’s masks back to the points. Because no part of it is
trained on 3D labels, every queried class is novel, making the
method fully zero-shot. Through experiments on four bench-
marks, we showed that SplatSeg3D outperforms all other
zero-shot methods and is on par with open-vocabulary meth-
ods that use 3D training or proposals. In terms of efficiency,
SplatSeg3D is deployment-ready with low runtime and com-
pute requirements. The current mentioned limitations also
indicate future research directions such as extending camera
placement beyond indoor scans.
Overall, SplatSeg3D enables open-vocabulary 3D seg-
mentation from point cloud-only data and can potentially
inherit future improvements in foundational 2D segmenters.

B. Details of Evaluation Protocol
Baselines run by us
(† in Tabs. 2 to 4). On Replica, we run
OpenMask3D [42], Open-YOLO 3D [4], and OVIR-3D [28]
with their released code using the Replica configurations on
the same 200 posed RGB-D frames per scene. For SceneS-
plat [26] on Replica we run its released checkpoint, trained
on ScanNet, ScanNet++ and Matterport3D, on SceneSplat-
7K’s Gaussian reconstructions of each scene, prompt each
class as its zero-shot tester does and label every vertex by its
vote over the 25 nearest Gaussians. On ScanNet++ the same
predictions are scored by Mosaic3D’s evaluator like every
other reported method in Tab. 3.
Details on the SAM3D+CLIP baseline.
In Tab. 4(b), we
run a baseline based on only foundation models to com-
pare with SplatSeg3D on ScanNet v2 [8]. This baseline is
implemented similar to the procedure mentioned in JOPP-
3D(f) [18], where SAM3D [32] predicted 3D instance masks
are aligned with CLIP [36] embeddings using the alignment
strategy of OpenMask3D [42]:
With SAM3D we first lift the 2D masks predicted by
SAM [22] into 3D instances on the mesh vertices with 5 cm
voxels. Then, following JOPP-3D(f), we align a VLM em-
bedding to each 3D instance with its top-5 views using CLIP.
C. Efficiency Evalutation Details
Timing protocol.
Every method of Tab. 5 runs on one RTX
A6000 over the 8 Replica scenes, one scene at a time on an
otherwise idle GPU, with its released Replica configuration.
For the methods that require image captures, the same 200
posed RGB-D frames per scene are used. Model load is
timed once, and per-scene times are means over the 8 scenes
after an untimed warm-up scene. SceneSplat’s [26] time ex-
cludes the Gaussian reconstruction its input needs, about 27
GPU-minutes per scene on an L4 for SceneSplat-7K. FLOPs
count the networks’ matrix multiplications, convolutions and
attention from PyTorch’s operator counts, with sparse 3D
convolutions counted from their kernel maps. Memory is
PyTorch’s allocator peak, models included.
Our time per stage.
On Replica, a scene takes 0.5 s for
surfelization, 5.4 s for camera selection, 0.5 s for rendering,
1.5 s for the segmenter, 0.1 s for lifting and 0.6 s for fusion,
8.7 s in total, averaged per scene.
