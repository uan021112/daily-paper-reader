## ABSTRACT 

Generating 3D indoor scenes requires a representation that captures object se-mantics, instance identity, height structure, and orientation while respecting room geometry. Methods that model scenes as sequences of object vectors learn spa-tial constraints implicitly, leaving collisions and boundary violations to losses or post-processing; semantic-map methods make occupancy explicit, but collapse in-stance and directional structure. We introduce RoomTokens, a sliced structured-token representation in which each token stores semantic class, instance-color identity, and facing field. This representation allows a scene to be generated as a discrete grid while preserving cues for instance grouping, orientation estima-tion, and 3D extent prediction. To learn the RoomToken distribution, we pro-pose MD IRT (Masked Diffusion over RoomTokens), a masked discrete diffu-sion model that denoises semantic/instance-color/facing channels jointly with a shared cross-slice backbone. Architectural tokens are clamped as explicit floor-plan constraints, so the model samples furniture layouts that respect room ge-ometry while retaining instance and object-attribute structure. Experiments on 3D-FRONT show that RoomTokens with MD IRT improve layout fidelity and physical consistency over sequence/vector- and map-based methods, suggesting structured spatial tokens as a practical choice for discrete 3D scene synthesis. 

## 1 INTRODUCTION 

Automatic generation of 3D scenes is increasingly important, as it allows for scaling up of training data for 3D scene understanding and embodied AI, and provides content for applications such as augmented reality, gaming, and entertainment. Compositional 3D indoor scene generation (Tam et al., 2026b) formulates the problem as an object arrangement problem, where we must decide on object categories, individual object identities, placement, and orientation while respecting the geometry of the room. To ensure that generated scenes are plausible, it is important to model the spatial structure and object-level semantics together. Most existing methods represent scenes as sets or sequences of object vectors (Paschalidou et al., 2021; Tang et al., 2024; Hu et al., 2026; Lin and Mu, 2024), where each object vector encodes the object category and bounding box of the object. While this representation is compact, it does not make occupancy constraints explicit and cannot ensure that two generated boxes do not occupy the same space. As a result, generated scenes may contain inter-object collisions, wall penetrations, and inadequate clearance for accessing objects and room regions. Prior systems therefore add auxiliary mechanisms, such as intersection penalties in the training objective (Tang et al., 2024), rejection-style resampling of invalid insertions (Ritchie et al., 2019), or optimization-based layout refinement after an initial prediction (Luo et al., 2020). Another line of work (Feng et al., 2023; Yang et al., 2025; Xia et al., 2026) leverages the broad knowledge encoded in LLMs/VLMs for more extensive semantic priors, but their coordinate outputs still require geometric cleanup and potentially multiple passes with a visual critic to ensure a physically plausible scene. Approaches that generate scenes based on semantic-maps (Yang et al., 2021; Sun et al., 2026) cap-ture the spatial arrangements explicitly by assigning semantic labels to cells on a dense grid. Arecent work, SemLayoutDiff (Sun et al., 2026) demonstrated improved floor-plan-conditioned gen-eration with fewer collisions and out-of-boundary objects. It collapses vertical in-formation, merges adjacent objects of the same category under connected-component decoding, and provides no directional cue for estimating object orientation. In this work, we tackle the challenge of how to introduce instance-level and vertical information into these spatial maps. We introduce RoomTokens , a sliced structured-token representation for indoor scenes. We represent a room as a stack of height-aware grids, with each grid cell storing a RoomToken with three fields that capture the semantic class, the instance identity, and facing cues. Encoding the instance identity is challenging as the assignment of a particular ID to an object is arbitrary (i.e., can be permuted or re-assigned), and the number of objects in a scene is not fixed. As our aim is to distinguish spatially adjacent object instances on a planar map (vs. providing an instance ID), we can use four ‘colors’ (following the four-color theorem (Robertson et al., 1997)) to identify different instances. For orientation, the facing field encodes whether a furniture token occupies the body or front half of an object; non-furniture tokens use none. We find that these two furniture labels are sufficient for decoding orientation. Together, these properties provide sufficient information for a model to generate a discrete spatial layout while preserving cues for instance grouping, orientation estimation, and 3D extent prediction. To learn the RoomToken distribution, we propose MD IRT (Masked Diffusion over RoomTokens), a single-stage masked discrete diffusion model for indoor scene generation. Each token property is embedded as a semantic, instance-color, or facing channel. The channels are processed by a shared cross-slice UNet and decoded jointly. The denoising process maps masked RoomTokens to structured 3D scene layouts while conditioning on and clamping the architectural tokens from the floor plan (Fig. 1 (bottom)), so furniture tokens are generated within the valid interior region defined by the architectural condition. Instead of predicting semantics and then instance-level attributes as in prior work (Sun et al., 2026), this multichannel parameterization learns semantic, instance-color, and facing dependencies through shared features in a single reverse process. Experiments on 3D-FRONT (Fu et al., 2021a) show that MD IRT generates more plausible layouts compared with SEM LAYOUT DIFF (Sun et al., 2026). Generated layouts better match reference rooms (FID 50.14 vs. 71.18) and capture more plausible object relations (Pair-Rel 12.09 vs. 20.65). They also contain fewer collisions (COL 12.64 vs. 16.24) and leave doors and windows more unobstructed (OC 82.31 vs. 56.02). In summary, our contributions are: 1) A sliced structured RoomToken representation that stores semantic class, graph-color instance identity, and facing information in each height-aware grid to-ken. 2) A single-stage masked discrete diffusion model, MD IRT, for RoomTokens that clamps the architectural condition throughout denoising so furniture is generated within the valid room 2interior, while jointly modeling semantic/instance-color/facing channels with a shared cross-slice backbone. 3) An empirical analysis showing that explicit instance-color and facing fields improve instance recovery and orientation estimation and provide for physically plausible scene layouts. 

## 2 RELATED WORK 

Object-vector and relational scene synthesis. Many indoor scene synthesis methods represent a room as a set or sequence of objects with attributes specifying the semantic class, position, and orientation of objects. Early neural and graph-based approaches learn spatial priors over object arrangements (Wang et al., 2018; Ritchie et al., 2019; Li et al., 2019; Wang et al., 2019; Zhang et al., 2020), while recent autoregressive and diffusion methods predict the object attributes directly (Wang et al., 2021; Paschalidou et al., 2021; Sun et al., 2024b; Tang et al., 2024; Hu et al., 2026; Maillard et al., 2024; Sun et al., 2025b). Other recent work leverages scene graphs, relational triples, or mixed graph diffusion for improved modeling of object layouts (Lin and Mu, 2024; Zhai et al., 2023; 2024; Bai et al., 2025; Ruiz et al., 2025), and physical or human-aware constraint objectives and optimization (Yi et al., 2023; Yang et al., 2024a; Sun et al., 2024a; Su et al., 2025; Lin et al., 2026). These methods differ in conditioning and priors, but their generated layout is ultimately a set of object bounding boxes. As a result, generated scenes may contain object collisions and boundary overlaps, and additional post-processing is required as the representation does not natively prevent these. MD IRT instead generates a discrete occupancy grid, where each cell has a single semantic assignment and grid-level overlap is therefore explicit. By modeling object occupancy explicitly across height-aware slices, the representation helps reduce inter-object collisions. 

LLM and agent-based scene generation. By leveraging LLMs and VLMs, it is possible to con-dition on language input and access the common sense knowledge of how objects are positioned, stored in these pretrained models. LayoutGPT (Feng et al., 2023) predicts layouts with language models, while Holodeck (Yang et al., 2024b), AnyHome (Wen et al., 2024), SceneTeller ( ¨ Ocal et al., 2024), and open-universe systems (Aguina-Kang et al., 2024) connect text prompts with object re-trieval, constraint solving, or scene assembly. More recent LLM/VLM and agentic methods use program synthesis, visual-language feedback, or multi-agent refinement for broader controllabil-ity (Hu et al., 2024; C ¸ elen et al., 2024; Sun et al., 2025a; Yang et al., 2025; Pfaff et al., 2026; Gao et al., 2025). These systems provide flexible interfaces, but coordinate- or program-level outputs still require geometric cleanup for dense indoor layouts. Our focus is complementary: we learn the layout distribution from annotated 3D-FRONT rooms and make the representation itself carry local occupancy, instance, and orientation structure. 

Discrete spatial representations for scene synthesis. Discrete spatial representations encode the scene by assigning labels directly to locations on a 2D or 3D lattice, making occupancy constraints local and explicit. Yang et al. (2021) use voxel labels, Lee et al. (2023) model scene-scale categorical 3D data, and SemLayoutDiff (Sun et al., 2026) applies multinomial discrete diffusion to a top-down semantic map. This family is closest to ours because it moves generation from unordered boxes toward explicit spatial fields. However, semantic-only spatial grids do not distinguish touching same-class instances, top-down maps collapse vertical structure, and a single class label per cell provides no direct orientation cue. Our representation keeps the grid advantage but upgrades each sliced cell into a structured RoomToken carrying semantic, instance-color, and facing fields. Graph coloring is used to assign instance colors during preprocessing, with the four-color theorem (Appel and Haken, 1977; Robertson et al., 1997) providing the minimum number of colors needed for separating adjacent same-class instances. Similar coloring ideas have been studied for discriminative instance segmentation (Kulikov et al., 2018; Zhang et al., 2025), but remain largely unexplored as compact instance channels for generative modelling. 

Discrete diffusion and masked token modeling. Masked discrete diffusion corrupts categorical data by replacing tokens with absorbing mask states and trains a denoiser to reverse that process. Multinomial and masked variants (Hoogeboom et al., 2021; Shi et al., 2024; Lou et al., 2024; Sahoo et al., 2024; Nie et al., 2025) have become effective for discrete sequences and token grids. Layout-specific diffusion models also use discrete or mixed discrete-continuous variables for structured 2D layouts and indoor scene attributes (Chai et al., 2023; Inoue et al., 2023; Levi et al., 2023; Hui et al., 2023; Choi et al., 2026), but these variables are often organized as layout tokens or object attributes rather than as per-cell scene occupancy fields. ## 3 METHOD 

Given a room type r and an input architectural mask (arch mask), MD IRT generates a complete object-level 3D layout (Fig. 3). With our RoomToken representation, slices at different heights store semantic occupancy with instance and facing cues, allowing objects to be recovered from the grid tokens (Sec. 3.1). We use masked diffusion to generate interior RoomTokens while keeping the architectural tokens fixed (Sec. 3.2). At each reverse step, a multichannel denoising network gθ

predicts the masked fields across height slices (Sec. 3.3). Finally, during scene assembly, the token grid is converted into object records and matching assets are retrieved for the final scene (Sec. 3.4). 3.1 SLICED ROOM TOKENS 

To recover object instances and poses from a discrete occupancy map, we encode each room as a stack of sliced RoomTokens. We discretize the floor plane into an H × W grid and use S selected height slices Z = {ζ1, . . . , ζ S } to capture the vertical extent (Fig. 2). We choose these heights by greedy coverage over furniture height intervals in the training set: each object covers a candidate height h if its vertical interval intersects [h − τ, h + τ ], with τ =0 .10 m matching the rasterization tolerance. Starting from fixed floor and ceiling anchors, we repeatedly add the candidate height that covers the most previously uncovered objects. To accomplish this, we use masked diffusion (Shi et al., 2024). In contrast to regular diffusion models that slowly add noise to the input, masked diffusion gradually replaces and hides the interior RoomToken labels with a mask token during the forward process. We train a multichannel denoising network gθ to predict label probabilities for masked out tokens. The model gθ consists of a shared UNet Uθ which processes the summed field embeddings across height slices, and three prediction heads ( Dy , D c, D f ) for the semantic, instance-color, and fac-ing fields. At each cell i, the three output heads produce the logits ℓyi , ℓci , ℓfi that define the label probabilities used in Sec. 3.2. 

Joint RoomToken denoising. The main denoising step predicts the RoomToken values from a single shared hidden representation hθ , conditioned on the room type r and arch mask a. For channel embeddings Ey , E c, E f , shared UNet Uθ , and output heads Dy , D c, D f , the embedding token et,i at position i for the denoised map at time t is given by: 

et,i = Ey (zyt,i ) + Ec(zct,i ) + Ef (zft,i ), for each grid location i, 

hθ = Uθ (et; t, κ ), ℓρi = Dρ(hθ,i ), ρ ∈ { y, c, f }. (4) Here hθ,i is the hidden feature, ℓρi the logits for channel ρ, and κ = ( r, a) the conditioning input. The clean xi and noisy zt,i variables are discrete categorical states; et,i and hθ,i are continuous vectors, and the three decoders map the shared vector to categorical channel logits. Summed embeddings and a shared hidden state parameterize one RoomToken distribution rather than a semantic-then-attribute pipeline. 

Cross-slice consistency. Cross-slice attention provides information exchange across height slices at the same floor location. The UNet treats the H × W grid as the spatial domain after concatenating 

S slice embeddings per location. At attention resolutions, a cross-slice block reshapes each (u, v )

feature into S tokens, applies attention along the slice dimension, and writes the result back through a residual projection. Thus, predictions for {(u, v, s ) : s = 1 , . . . , S } exchange evidence about object extent and body/front alignment. 

Cross-channel consistency. Cross-channel consistency makes instance-color and facing predictions depend on the semantic prediction. Instance-color and facing logits share the semantic backbone features, and the attribute branch is modulated by a semantic feature branch through learned gates and biases. This makes attributes semantic-aware within the same denoising step, while Sec. 3.2 enforces channel combinations are valid during sampling. 

Training objective. The training objective supervises both token denoising and the geometric quan-tities needed for scene assembly. The main terms denoise the masked RoomToken channels, while auxiliary terms calibrate occupancy and the geometric heads used downstream. We optimize 

L = λy Ly + λcls Lcls + λcLc + λf Lf + λocc Locc + λattr Lattr . (5) Here, each λ is a scalar weight. Ly is masked cross-entropy over semantic classes, while Lcls is an object-count-balanced semantic class loss for the long-tailed furniture distribution. It applies fixed inverse-square-root weights computed from training object counts, keeps architecture/background weights at one, averages semantic cross-entropy over the cells of each ground-truth object, and then averages over objects. This gives rare categories and small instances comparable influence to common or large furniture. Lc and Lf are masked cross-entropy losses for instance-color and facing labels on visible furniture cells. Locc is binary cross-entropy with logits on foreground occupancy derived from the semantic logits. Lattr groups instance-level mean-squared regression losses for yaw (cos θ, sin θ), height, and vertical offset from instance-pooled features. See Sec. D.2 for details. 3.4 INFERENCE AND SCENE ASSEMBLY 

At inference, architectural cells from the input arch mask are clamped throughout the reverse pro-cess, and MD IRT samples semantic, instance-color, and facing slices for the furnished interior. Because these architectural tokens are never overwritten, the masked discrete diffusion design pre-serves the architectural condition throughout generation, enabling the model to learn furniture lay-outs within the valid room interior. In our experiments (Sec. 4.2), we show that there are zero out-of-bounds errors after final asset placement. We group connected RoomTokens with the same semantic and instance-color labels into object instances. Their tokens determine category, horizontal center, and horizontal dimensions; body/front 6labels indicate orientation. MLP heads within MD IRT use denoising features averaged over each instance mask to predict continuous height and vertical offset, with a yaw head providing orientation when body/front labels do not determine it. We instantiate the final scene by retrieving appropriate 3D assets from 3D-FUTURE (Fu et al., 2021b). For each object, we query the 3D database with the object category and select the closest asset based on the 3D extents. The retrieved asset is scaled along each axis to match the estimated extents, rotated to the predicted yaw, and translated to the recovered object position. We use the same category- and size-based asset retrieval and placement process as SemLayoutDiff. After asset placement, there is no clipping, extra optimization, or any hand-designed scene correction. App. F details assembly and the grouping/orientation procedures for the field-removal ablations. 

## 4 EXPERIMENTS 

We evaluate architecture-conditioned generation against recent diffusion methods. Ablations and a user study assess design choices and perceived quality. 4.1 EXPERIMENTAL SETUP 

Dataset. We train and evaluate on 3D-FRONT (Fu et al., 2021a) following splits established in prior work (Paschalidou et al., 2021) with 4,496 train / 274 val / 390 test rooms over three room types (bedroom, living room, and dining room). 

Model details. Following SemLayoutDiff (Sun et al., 2026), we train all methods as a single uni-fied model across room types rather than one model per room type. Each scene is rasterized on a 128 ×128 floor-plane grid, where one pixel/token has side length 0.10 m in the horizontal plane. The grid is repeated over S=8 fixed height slices at (0 .02 , 0.45 , 0.80 , 1.20 , 1.60 , 2.00 , 2.40 , 2.70) m, which are selected once by greedy coverage analysis with a 0.10 m vertical tolerance. For MD IRT, RoomTokens use Ksem =39 semantic classes, C=3 instance colors plus ∅c, and body/front/ ∅f

facing labels; valid semantic–instance-color–facing triples are flattened into a 209-id palette for vi-sualizations and the single-channel ablation. See Sec. D.1 for model details and App. E for data processing details.

## 5 CONCLUSION 

We presented MD IRT, a masked discrete diffusion framework over sliced RoomTokens for indoor scene layouts. RoomTokens add height slices, instance-color cues, and facing cues to semantic occupancy maps. Clamping architectural tokens during denoising preserves the supplied floor plan, keeping room geometry explicit while supporting object grouping, orientation estimation, and scene assembly. On 3D-FRONT, MD IRT achieves competitive distribution quality and the strongest overall spa-tial plausibility among evaluated methods. Controlled comparisons show gains beyond architecture 10 clamping and sparse generation; a blinded human ranking study favors our scenes. Representa-tion checks show little information loss; ablations support factorized RoomToken fields, semantic-priority sampling, and cross-slice attention. Structured occupancy tokens could also support outdoor scenes, objects with parts, and other semantic occupancy tasks. 

Limitations. The fixed grid and height slices can miss fine details and narrow gaps. The small 3D-FRONT training set is uneven across object categories and room types. RoomTokens and valid-ity projection cannot prevent mesh collisions from grouping, continuous pose estimation, scaling, or asset retrieval. Larger, more diverse data and stronger scene assembly could improve distribu-tion matching and retrieval; adaptive-resolution slices and geometry-aware refinement could capture details and reduce collisions.

## A EVALUATION METRICS 

We follow prior work (Sun et al., 2026) and evaluate the distribution similarity of generated scenes to reference scenes, as well as physical layout plausibility with metrics introduced in SceneEval (Tam et al., 2026a). 

Distribution and semantic quality. For FID and KID, we render each generated scene and each 3D-FRONT test scene as a 256 ×256 orthographic top-down image. Objects are colored by semantic category, using the same fixed room-type palette for generated and test scenes. We convert the renders to RGB and white-pad them to 256 ×256 . We extract clean-fid “clean” Inception features and compute FID and KID from these features. For each comparison, we use equal-sized image sets, sample without replacement from the larger set, and average scores over ten draws. The aggregate MD IRT score compares all 390 test renders with 390 renders drawn from 3,000 generated scenes on each draw; per-room scores are computed separately. KID is reported multiplied by 10 3.CKL is DKL (pgt ∥pgen ) between normalized furniture-category counts pooled across test and gen-erated scenes, excluding architectural elements. CKL is reported multiplied by 10 2.

Pairwise layout relations. Our Pair-Rel metric compares the joint distributions of object-pair cat-egories and relative geometry. For every ordered pair (i, j ) of distinct furniture objects with valid bounding boxes, we form a relation tuple rij = ( ki, k j , d ij , b ij ), where ki and kj are the object categories, dij is the direction of object j relative to object i, and bij is a distance bin. Both (i, j )

and (j, i ) contribute. To compute dij , we express the displacement between object centers in object i’s orientation frame. The axis with the larger displacement magnitude determines left, right, front, or back; coincident centers receive the label same. We measure distance as the minimum horizontal separation between the objects’ oriented bounding boxes, assigning zero to intersecting boxes. The distance bins are contact ( ≤ 0.05 m), near ( (0 .05 , 0.5] m), mid ( (0 .5, 1.5] m), and far ( > 1.5 m). We pool relation tuples across all scenes in each set and normalize their counts to obtain generated and ground-truth histograms Pgen and Pgt . Let M = 12 (Pgen + Pgt ). Pair-Rel is 

PairRel = 100 JSD( Pgen , P gt )= 50 [ DKL (Pgen ∥M ) + DKL (Pgt ∥M )] . (6) Lower values indicate closer agreement. Because object categories are included in each tuple, Pair-Rel reflects both pair composition and relative geometry. 

Physical plausibility. OOB S is the fraction of generated scenes containing at least one object outside the room boundary. OOB O is the fraction of generated objects outside the room boundary. COL measures collisions among generated objects after connected-component grouping, orientation estimation, and object placement. NAV evaluates free-space navigability in the final scene. Opening clearance (OC) is the percentage of evaluated room-facing door and window clearance regions that do not intersect a furniture mesh. Mean object count is reported alongside physical metrics to expose empty or unusually sparse generation. All metrics use the final scenes and evaluation protocol described in Sec. 4.1.

Collision sources in the training data. We audit furniture–furniture collisions in the raw 3D-FRONT train and test room records. For each furniture object, we load its 3D-FUTURE asset mesh and apply its recorded scene transform. We test each unordered pair of meshes for intersection using the Flexible Collision Library (FCL) through trimesh and python-fcl ; architectural elements are excluded. When usable contact points are available, we move one mesh by 5 mm toward its centroid from the mean contact point and count the pair only if the collision persists. Otherwise, we retain the initial intersection result. A room record is colliding if it contains at least one counted pair, and an object is colliding if it belongs to at least one pair. In the training records, 2,112 of 4,882 rooms (43.26%) contain a collision, and 6,279 of 31,256 furniture objects (20.09%) participate in one. The 4,096 collision pairs count distinct unordered pairs within room records; one object can belong to multiple pairs. In the test records, 177 of 390 rooms (45.38%) and 840 of 4,965 objects (16.92%) are colliding, across 592 pairs. These raw-record counts differ from the filtered split used to train and evaluate the model. They show that furniture intersections are present in the source data; further intersections can arise when generated objects are reconstructed and placed.

Theorem 1 (Four-color sufficiency for connected regions in a single slice) . Consider one height slice in which each object instance occupies a set of grid cells connected through shared edges. For each semantic class k, connect two instances when their cells share a grid edge. Then there exists an assignment of at most four colors such that every adjacent pair has different colors. 

Proof. The graph connecting cells that share an edge in a single slice is planar. Remove cells belonging to other semantic classes and contract each instance’s connected cells into one vertex. Edge contraction and deletion preserve planarity, so the resulting instance-adjacency graph is planar. The four-color theorem therefore gives the required coloring (Appel and Haken, 1977; Robertson et al., 1997). We use this coloring principle to encode instance information with a compact palette. In prepro-cessing, greedy coloring assigns each instance one consistent color across slices. The combined adjacency graph across slices need not be planar, and greedy coloring is not guaranteed to find a four-color assignment. We choose three colors empirically: 99.08% of adjacent same-category, different-instance token pairs have different colors (App. C), and three colors yield lower COL and higher OC than four colors (Tab. 3). The null label denotes an inapplicable attribute and is not a fourth instance color. 

## F CONDITIONING , I NFERENCE , AND SCENE ASSEMBLY DETAILS 

Arch-mask conditioning. The conditioning tuple in Eq. (4) is written as κ = ( r, a) in the main text to keep the denoising notation compact. Here r is the room type and a is the input arch mask. Cells with ai = 1 are clamped to their architectural labels during both forward masking and reverse denoising, while cells with ai = 0 are generated by the model. This lets MD IRT sample semantic, instance-color, and facing fields for furniture while preserving the supplied room geometry. 

Sampling. The three token fields are generated within one reverse diffusion process. Architectural tokens are fixed throughout; all unfixed cells initially have their semantic, instance-color, and facing fields masked. Each reverse step proceeds as follows: 1. Predict and update masked semantic labels according to the reverse schedule, retaining already revealed labels. 21 2. Recompute instance-color and facing predictions using the updated semantic state and shared denoiser features. 3. Keep both attributes masked if semantics remain masked. For revealed furniture semantics, reveal eligible attribute fields according to the schedule; for architecture/background semantics, assign null attributes. 4. Enforce compatible field values while preserving unresolved masks, and restore the fixed archi-tectural tokens. For example, after a semantic label becomes “chair,” instance color or facing may be revealed in that step or remain masked until a later step. Such partially masked tokens are valid intermediate states. A mask means that a value is unknown; null means that an attribute is inapplicable. App. B reports the denoising trajectory over 256 steps. The final grid preserves the supplied architectural tokens before grouping and asset placement. 

Token-to-object assembly. We group connected RoomTokens with the same semantic and instance-color labels across height slices into object instances. Each instance’s tokens determine its category, horizontal center, and horizontal dimensions at grid resolution. The occupied height slices provide a coarse vertical extent, while the body/front labels indicate orientation. MLP heads within MD IRT estimate continuous height and vertical offset from its denoising fea-tures. For each instance, we form a 2D mask containing every grid cell where it appears in any height slice. We average the denoising features within this mask and feed the resulting vector to the heads. A yaw head provides orientation when the body/front labels do not determine the direc-tion. These predictions, together with the attributes obtained directly from the tokens, specify each object’s category, position, dimensions, and orientation for asset retrieval and placement. 

Scene assembly for field-removal ablations. With RoomTokens, our instance colors allow us to generate object instances with spatial extent and orientation information. Our full model groups tokens by semantic and instance-color labels and uses the body/front cues to predict orientation. To ablate the removal of fields such as instance-color and facing, we follow SemLayoutDiff Sun et al. (2026) on how to handle instance identification and orientation. Without the instance color field, we use connected-component analysis to group connected tokens of the same semantic category into an object. In this case, adjacent same-category tokens are merged into the same instance. Without the facing field, we use an auxiliary instance-level MLP head to predict the yaw from pooled instance features. Note that the yaw is not fixed to zero. Asset retrieval and placement follow the same procedure for all of these variants. 

Asset retrieval. The final scene is instantiated by retrieving assets from 3D-FUTURE Fu et al. (2021b). For each object record, we first filter candidate assets by category, with a fallback to com-patible coarse labels when exact labels are unavailable. We convert the predicted object size (w, d, h )

to 3D-FUTURE half-extents (w/ 2, h/ 2, d/ 2) and select the candidate with the smallest squared er-ror in this 3D size space. The selected asset is scaled along each axis to match the estimated extents, rotated by the predicted yaw, translated to the recovered object position, and exported together with the reconstructed floor, wall, door, and window elements. The category- and size-based retrieval and placement procedure follows SemLayoutDiff. We evaluate the resulting scenes directly, without subsequent clipping, optimization, or hand-designed correction.
