# 3D Occupancy-Language Fields from mmWave Radar 

## Haowen Lai *, Zhiwei Zheng and Mingmin Zhao *

University of Pennsylvania, Philadelphia, PA, 19104, USA. *Corresponding author(s). E-mail(s): hwlai@seas.upenn.edu; mingminz@seas.upenn.edu; 

Abstract 

Radar systems can recover scene geometry and recognize predefined categories, but these outputs do not provide a persistent spatial representation for open-ended language queries. Such queries require linking observations from different viewpoints to the same physical locations. We present 

TextRadar , a framework that constructs a scene-level 3D occupancy-language field from panoramic radar observations. The field combines occupancy with scale-dependent language features at surface locations, allowing the reconstructed scene to be queried with new descriptions. A single-frame radar distillation model predicts aligned ranges and language features from each radar observation. Using radar-estimated poses, we register these predictions to reconstruct the field from radar alone in a new scene. Experiments on approximately 20k synchronized observations across seven buildings demonstrate scene-level natural-language querying and prompt-free semantic visualization. Analysis of camera-to-radar concept transferability shows stronger agreement for structures, materials, and human poses than for colors and printed text.  

> Keywords: Millimeter-wave radar, 3D scene representation, occupancy-language field, natural-language querying, cross-modal distillation

# 1 Introduction 

Recent years have seen rapid progress in mmWave sensing, transforming radars from coarse detectors into high-resolution imaging systems [1–3]. Much of this progress has focused on resolving surfaces and recovering scene geometry [4–6]. Geometry alone, however, cannot tell a robot what a sensed region contains or how it might be used. This information matters for tasks such as region search [7, 8] and semantic navigation [9, 10], where a robot may be asked to find “a place to sit”. Such a request could refer to a chair, a bench, or another suitable surface rather than one predefined object label. RF sensing provides some of this semantic information by recognizing scene categories, materials, and human activities [1, 5, 11–13]. These systems generally choose from predefined labels, which limits the descriptions a person can use to search a scene. Recent radar-language models expand this range by generating descriptions of human motion and scene content [14–16]. Their language, however, is usually tied to an input frame, scene, or motion sequence rather than to physical locations in a shared 3D map. For a moving robot, that spatial link matters: a description of a chair in one view does not tell it where to find the chair later or whether another view shows the same one. Answering such questions requires associating observations from different viewpoints with persistent 3D locations. Vision-based language fields show how this kind of representation supports spatial queries [17, 18]. Can radar provide a comparable representation that links language to reconstructed surfaces across a scene? To address this question, we present TextRadar , a framework for constructing a scene-level 3D occupancy-language field from panoramic radar observations. associates surface locations with language features at multiple context scales. As illustrated in Fig. 1, a robot gathers panoramic radar measurements along a trajectory. For each observation, a learned model predicts distances to surfaces and spatially aligned language features. Camera and LiDAR measurements provide training targets for the model. In a new scene, the trained model predicts both quantities from radar alone. Using radar-estimated poses, TextRadar places these predictions in shared 3D coordinates and combines repeated observations at the same locations. The resulting field retains surfaces and their language features after the robot leaves a region, allowing users to search with new descriptions without rebuilding the map. For example, “things to sit” retrieves relevant seating, illustrated by the highlighted bench in Fig. 1. The same features also support prompt-free semantic visualization, revealing how different scene regions are organized. Finally, we compare radar-predicted features with camera-derived references to assess camera-to-radar concept transferability and characterize the language information available to build the field. Realizing this framework requires three components: spatial language distillation, panoramic super-vision, and reconstruction from radar predictions. 

Distilling spatial language features from vision. To support natural-language querying after recon-struction, a scene-level language field needs features tied to physical locations rather than a single label or caption for an observation. Pretrained image-text models provide language features from camera images, but each feature describes an image region rather than a radar return. We extract overlapping crops at multiple scales so the features describe both local objects and broader scene context. To associate these camera features with radar-observed surfaces, we project LiDAR points into the image using calibrated sensor geometry. At each projected point and crop scale, we bilinearly interpolate the embeddings at the four neighboring crop centers. LiDAR depth also lets us express the physical area covered by each crop, so its context scale can be compared across distances. A single-frame radar distillation model learns to pre-dict these language features alongside LiDAR-supervised ranges on the same panoramic grid. Its aligned outputs provide the surface locations and language observations needed to build the 3D field, without manual RF-language annotations. 

Extending supervision to the radar panorama. The camera provides perspective views of a limited sector, whereas each radar observation spans the full surrounding panorama. Training only on that sector leaves other directions without language targets and biases learning toward the camera’s viewing direction. Without supervision elsewhere, the model may rely on direction-specific shortcuts that do not generalize 2across the panorama. This can produce weak or spurious language features outside the supervised sector, leading to artifacts and uneven semantic coverage in the reconstructed scene. Rotating training samples changes their coordinates but cannot supply the missing targets or remove this bias. To extend coverage, we use robot motion and LiDAR geometry to accumulate camera-derived features in a 3D reference map. For each panoramic surface point, we retrieve nearby features observed at compatible physical context scales. This brings camera observations from different viewpoints into a common training target. The resulting panoramic targets supervise the distillation model alongside LiDAR ranges, extending language learning beyond the camera’s instantaneous view. 

Reconstructing the field from radar predictions. Once trained, the distillation model predicts ranges and language features from each radar observation in a new scene. We use radar-estimated poses to register these predictions from different viewpoints in shared 3D coordinates. The ranges constrain occu-pancy, while the language features supervise the language field at the corresponding surface points. At the same point, however, language features can describe different amounts of context. For example, one feature may describe a chair and another its surrounding seating area, so merging them into one embed-ding would lose that distinction. Following LERF [17], we condition the language field on spatial context scale. We use predicted ranges to express feature scales in physical units and interpolate between neigh-boring scales when fitting the field. Repeated observations thus constrain the same occupancy value and, at a given location and scale, the same language embedding. This shared field retains the reconstructed surfaces and their language features for later queries, including regions outside the robot’s current view. We implement TextRadar on a mobile robot equipped with a rotating mmWave radar, a front-facing camera, and a 3D LiDAR. We collect approximately 20k synchronized observations along 21 trajectories across seven buildings. To test generalization, we hold out each building in turn and train the distillation model on the other six. Across the held-out buildings, the model achieves a mean range error of 16.38 cm and a mean radar-camera feature cosine similarity of 91.92%. These measurements describe the accu-racy of its surface distances and the agreement of its language features with camera-derived references. Using these predictions and radar-estimated poses, we reconstruct scene-level fields that support natural-language querying of extended structures and individual objects. The same fields support prompt-free semantic visualization of the learned features. We further evaluate camera-to-radar concept transferability with 42 descriptive prompts spanning objects and structures, materials, human poses, colors, and printed text. For objects and structures, the mean agreement with the camera’s preference between prompt pairs is 82.5%, compared with a chance baseline of 50%. Together, the category-wise results show stronger agreement for structures, materials, and human poses than for colors and printed text, indicating which semantic cues are more reliably supplied to the field. In summary, our contributions are: 

• A scene-level 3D occupancy-language field that combines radar-derived surface reconstruction with multiscale language features for persistent spatial querying. 

• A single-frame radar distillation model and geometry-aware panoramic supervision that supply aligned range and language predictions for field construction. 

• Natural-language querying of structures and objects, together with prompt-free semantic visualization of the learned language features. 

• Evaluation on approximately 20k synchronized observations across seven buildings, showing stronger camera-to-radar concept agreement for structures, materials, and human poses than for colors and printed text. 

## 1.1 Related work 

Image-text models such as CLIP [19] provide a shared embedding space for visual content and natural lan-guage. Building on this foundation, Distilled Feature Fields [20] and LERF [17] embed pretrained image or language-aligned features into 3D fields for scene decomposition and open-vocabulary queries, while LangSplat [18] and Language Embedded 3D Gaussians [21] attach such features to Gaussian representa-tions. ConceptFusion [22] and OpenScene [23] fuse multiview features into explicit 3D maps or point-cloud representations. Visual Language Maps [24] applies spatially grounded visual-language features to robot navigation. Together, these methods establish language-aligned 3D scene understanding beyond prede-fined categories. distillation model during training, while a new scene’s occupancy and language fields are reconstructed from radar predictions and radar-estimated poses. Producing these observations requires radar to recover both spatial detail and semantic cues. Synthetic-aperture imaging exploits sensor motion to resolve surfaces and indoor layouts [1, 2, 6, 25– 30], while SLAM and 3D mapping aggregate measurements across viewpoints to reconstruct larger-scale environments [3, 31–34]. Besides these systems, learned reconstruction methods recover dense ranges, occupancy, human geometry, and wave propagation from sensor measurements [3, 4, 35–42]. In particular, CartoRadar formulates scene reconstruction through learned occupancy prediction [3]. Beyond geometry, wireless sensing systems recognize scene categories [1, 5, 43, 44], materials [11, 45–47], activities [12, 48– 50], and vital signs [51–55]. However, neither geometric mapping and reconstruction nor task-specific recognition provides a language field that can be queried at arbitrary locations in a 3D scene. TextRadar 

connects these capabilities by integrating radar-predicted geometry and language embeddings within shared 3D coordinates. Recent radar-language systems provide another part of this foundation. Building on large language models [56, 57], they use language models for supervised detection [58], reason over RF features to identify materials [59, 60], or describe human motion and activity [14, 15]. More recently, vision-aligned 4D radar features have also been used to generate structured scene captions [16]. These systems connect radar to language through detections, property estimates, and descriptions. TextRadar instead distills spatially aligned multiscale language features and integrates them with occupancy in a persistent 3D field, allowing the same reconstructed scene to support different spatial queries. 

# 2 Results 

We first examine the scene-level occupancy-language field through 3D reconstruction and natural-language querying, then inspect the features it integrates through prompt-free visualization and camera-to-radar concept transferability. We subsequently evaluate the single-frame radar distillation model that supplies the field’s observations. Experiments use approximately 20k synchronized observa-tions from 21 trajectories in seven buildings, with the hardware, dataset, and training protocol detailed at the end of this section.

## 2.4 Multiscale language-feature distillation 

The preceding results depend on the quality of the radar observations supplied to the scene field. We therefore evaluate the distillation model separately, measuring its range accuracy and its ability to predict camera-derived language features in held-out buildings. The model maps one panoramic RF volume to a dense range image and five spatially aligned CLIP feature maps, each with 768 channels. The scales correspond to camera crop sizes of [128 , 224 , 320 , 416 , 512] pixels and preserve different amounts of surrounding context. We use a ViT-L-14-quickgelu OpenCLIP model [62] pretrained on DFN-2B [63] to construct the targets. The architecture and geometry-aware supervision are described in Section 4.2–4.5. We evaluate the model along two axes: geometric accuracy and language-feature distillation quality. ## 2.5 Experimental setup 

Our data collection platform follows the rotating-radar design of prior high-resolution RF imaging sys-tems [1, 2]. The goal of this design is to convert a compact radar into a large synthetic aperture while keeping the sensor stack small enough for mobile indoor data collection. As shown in Fig. 10, the platform uses a TI MMWCAS-RF-EVM cascaded mmWave radar and an MMWCAS-DSP-EVM data capture board to transmit and receive radio signals. The radar consists of four cascaded chips with 9 TX and 16 RX channels enabled, forming a linear virtual array with 86 antenna elements after accounting for repeated elements. A stepper motor rotates the radar at 2 Hz with a radius of 10.5 cm, producing a syn-thetic cylindrical array of size 86 ×1024. The radar transmits FMCW signals sweeping from 77 to 81 GHz, with a 4 GHz bandwidth and 256 ADC samples per chirp. After beamforming, each panoramic RF obser-vation is a tensor with 64 elevation bins, 512 azimuth bins, and 256 range bins. To pair RF observations with geometry and language supervision, we mount an Ouster OS0-64 3D LiDAR and an IMX219 front-facing RGB camera on the same robot. The LiDAR provides range supervision and geometric ground truth, while the camera provides images for generating multiscale language supervision. The resulting dataset contains 21 trajectories collected across seven buildings constructed between 1900 and 2010. These buildings cover common indoor spaces such as offices, hallways, lounges, classrooms, and open floor areas, with representative examples shown in Fig. 11. In total, the dataset includes approximately 20,000 synchronized radar-LiDAR-camera frames. During data collection, the robot is manually controlled with a joystick and moves at a maximum speed of 0.6 m/s. For each trajectory, we include at least one revisit to support loop closure and pose correction. We also drive the robot through the same area in both directions so that the front-facing camera observes both sides of the environment over the course of a trajectory. We evaluate generalization with a leave-one-building-out protocol. TextRadar contains two learned components with different training scopes. For each split, we train the single-frame radar distillation model on trajectories from six buildings and apply it without adaptation to the held-out building. We initialize its shared backbone and range head on the HoloRadar dataset [2], training for 90k iterations 13 Fig. 11 Example scenarios in our dataset. The dataset spans common indoor environments, including hallways, lounges, offices, classrooms, and open floor areas. These examples are captured by the front-facing camera on the robot and illustrate the visual context used to generate language supervision. 

with AdamW, a momentum-based optimizer [65], a cosine learning-rate scheduler with base learning rate 10 −4, and mixed precision. We then fine-tune the full model on our collected radar-LiDAR-camera dataset for 60k iterations to refine range prediction and learn CLIP-aligned multiscale features. This second stage uses the same optimizer and learning-rate schedule. During training, we apply a random azimuth rotation to every sample and a random horizontal flip with probability 0.5. Once the distillation model has been trained, we optimize the second component, the per-scene occupancy-language field, separately for each trajectory using the predicted ranges, predicted language features, and radar-estimated poses. # 3 Discussion 

TextRadar makes a scene-level 3D occupancy-language field the interface between radar observations and spatial language queries. Within this framework, the single-frame radar distillation model supplies surface and language predictions, while the field integrates them at shared 3D locations. This distinction matters when a robot revisits a region or searches for a concept distributed across several views. In either case, the language feature at a fixed scene location and context scale is independent of the observing viewpoint, and occupancy provides the geometry on which query responses are displayed. The reconstructed scene can therefore be inspected with different prompts without refitting the field. Interpreting the results also requires accounting for the physical differences between radar and cam-eras. A low feature similarity may indicate a prediction error, but it can also arise because the sensors observe different aspects of the same region. Glass provides a representative example. In Fig. 12, the cam-era records surface appearance, reflections, transmitted light, and objects visible beyond the pane, so its CLIP feature mixes several visual cues. By contrast, many common glass surfaces behave as strong first reflectors for the radar configuration used here [1, 66], and content visible behind them may not appear in the RF range image. The resulting difference lowers radar-camera feature similarity around the win-dows. Despite this lower agreement, the query in Fig. 4 responds to the glass region, and the prompt-free visualization in Fig. 8 separates it from the surrounding wall. Radar features can therefore retain useful information about a surface without reproducing all of the visual content observed through it. 14 RGB  Pred range  Cosine sim

Beyond these modality differences, the results also clarify how to obtain useful observations for the field. In particular, the distillation model benefits from coupling range and language-feature prediction. Many feature transitions occur near object boundaries, planar surfaces, or changes in RF reflection behavior. By preserving a common spatial feature hierarchy until the final task-specific heads, the shared decoder lets both outputs draw on these boundaries. Consistent with this interpretation, separating the decoders changes mean range error by only 0.03 cm but reduces radar-camera cosine similarity from 91.92% to 90.08% in Table 4. This supports decoder sharing for language-feature distillation, although it does not demonstrate a corresponding improvement in range accuracy. Alongside the accuracy of individual observations, their spatial coverage matters for scene recon-struction. Panoramic supervision determines the coverage of the language observations available along a trajectory. During development, supervision restricted to the front-facing camera sector produced orga-nized features in the repeatedly supervised region but poor features elsewhere. Azimuth augmentation alone did not remove this behavior, as it changed sample coordinates without supplying the missing lan-guage targets. Accumulation through robot motion addresses this limitation by providing valid targets across the panoramic grid, as detailed in Section 4.5. Several limitations remain in both the field and the distillation model. First, the field describes a predominantly static scene. Moving people and objects can create inconsistent surface and language obser-vations unless dynamic regions are detected or modeled separately [67]. In our current system, people are treated as static scene elements, without persistent tracking or temporal action recognition. Coupling the field with language-conditioned human motion models [68, 69] is a possible route toward querying human movement over time. Second, weak or unresolved reflections can cause compact objects to merge with neighboring surfaces, and shared 3D coordinates cannot recover a distinction absent from the observa-tions. Third, camera-derived features provide a supervisory reference rather than independent semantic ground truth. Conditioning on object class reduces some confounds in the transferability analysis, but material, geometry, and context can remain correlated. Further evaluation with human-annotated 3D query regions [7], controlled objects, and a geometry-only baseline would help distinguish these sources of agreement more directly. Finally, dense 768-dimensional language observations impose substantial mem-ory and storage costs. A compact radar-specific feature representation could reduce these costs while retaining compatibility with text queries and occupancy-language field reconstruction.

## 4.2 Single-frame radar distillation model 

To supply the field with observations at each sensor pose, we train a single-frame radar distillation model on paired geometric and language targets. The model learns ranges from LiDAR supervision and distills language features from a pretrained camera encoder. Given a panoramic RF tensor X, the model fη

jointly predicts a dense range image ˆD and L = 5 multiscale language-feature maps { ˆZℓ}Lℓ=1 . We use a convolutional UNet-style architecture with a shared encoder and decoder. The range and language tasks 17 share the complete encoder-decoder backbone and separate only at the output heads, with one scalar range head and one C-dimensional language head for each scale, where C = 768. This design gives both outputs a common hierarchy of spatial features before their final prediction heads. Before the encoder, a 7 ×7 convolutional stem reduces the input range channels from 256 to 64. This stem captures spatial energy patterns across elevation and azimuth while compressing the 256-channel range dimension of the RF tensor. Within this backbone, both the encoder and decoder contain seven layers linked by skip connections. Each encoder layer has four residual blocks, and each decoder layer has two residual blocks. Feature maps are downsampled by a factor of two at the end of each encoder layer and upsampled correspondingly in the decoder. To preserve elevation resolution (initially Nϕ = 64), we stop downsampling along the elevation dimension after the fourth layer. After the shared backbone extracts RF features from X, task-specific heads produce the final outputs. The range head contains two additional residual blocks, and each scale has a dedicated head with five additional residual blocks. Because CLIP represents semantic similarity through embedding direction, we ℓ2-normalize each predicted language vector ˆZℓ(q) to obtain ˆEℓ(q), where q denotes an elevation-azimuth pixel. The camera-derived target Eℓ(q) is normalized in the same manner during panoramic supervision construction. For geometric supervision, we use the LiDAR range image D. This term complements the pixel-wise range loss by encouraging coherent surfaces and sharper structural boundaries. Alongside these geometric losses, the language objective maximizes cosine similarity between the predicted and camera-derived features at every valid scale and pixel. ## 4.4 Single-view multiscale language supervision 

To pair the RF volumes with language targets, we derive supervision from the synchronized front-facing RGB camera using a pretrained CLIP image encoder [62]. Because CLIP produces an embedding for an image region rather than an individual pixel, we construct an overlapping multiscale crop pyramid following the general strategy of LERF [17]. For each RGB frame, we extract square crops at five pixel scales, pℓ ∈ { 128 , 224 , 320 , 416 , 512 }, using a stride of pℓ/2. The crops are encoded independently and 

ℓ2-normalized to form five spatial grids of CLIP features. Smaller crops preserve localized objects and structures, whereas larger crops encode broader structural and contextual semantics. Associating these image-region features with radar-observed surfaces also requires depth, which the front-facing RGB camera does not directly measure. We therefore use the synchronized 3D LiDAR to associate the image embeddings with physical scene points. For a LiDAR point pi, we transform it into the camera coordinate system as xci = Tc←lpi and project it to image location ui = π(xci ). Here, Tc←l

denotes the calibrated LiDAR-to-camera transformation and π(·) is the camera projection function. We retain points with positive camera depth whose projections fall within the valid image region. The camera and LiDAR are mounted with a small spatial baseline, which reduces parallax and visibility discrepancies between their observations, although minor mismatches can remain near occlusion boundaries. Once these correspondences are established, we bilinearly interpolate the embeddings of the four neighboring crop centers for each valid point and crop scale, then normalize them. This yields five camera-derived 19 language targets for each camera-visible LiDAR point, rather than a dense pixel-wise language map over the panorama. ## 4.5 Panoramic language supervision from robot motion 

The front-facing camera provides language supervision over only a limited azimuthal region, whereas the RF input spans the full 360 ◦ panorama. As a result, supervision restricted to the camera field of view introduces a directional bias: the model receives no language targets for other parts of the same RF panorama. Although stitching camera frames into RGB panoramas could extend this coverage, it is unreliable under robot vibration, turning motion, parallax, and accumulated pose error. Most semantic properties co-occur with particular objects, so we evaluate each non-geometric property within the entity that carries it. For this conditioning, the camera-derived object prompts assign each valid pixel to its most relevant object class, and we retain assignments with relevancy above 0 .5. Colors and materials are evaluated separately within trash-bin, table, chair, and display regions. Similarly, text is evaluated within displays and human actions within person regions. Objects and structures, in contrast, are evaluated over the full frame because their geometry is part of the concept. Each frame, feature scale, and conditioning class defines one entity unit, and units with fewer than 20 valid pixels are discarded. For each prompt, the camera-derived concept region is the top 5% of camera-relevancy values within the unit. We compare radar and camera responses using three complementary measures. First, pairwise dis-crimination considers every prompt pair within a category and the pixels that belong to exactly one of their camera-derived concept regions. It measures how often radar prefers the same prompt as the cam-era, pooling pixels across entity units before averaging equally over prompt pairs. Its chance level is 0 .5. Second, region AUROC treats the camera-derived concept region as positive and the remaining pixels in the same unit as negative. It measures whether radar assigns higher relevancy to the concept region and has a chance level of 0 .5. Scores are computed within each unit and then averaged across units and prompts. Finally, the measure termed instance-level correlation first averages radar and camera relevancy within each entity unit, then computes their Pearson correlation across observations assigned to the same 21 object class. An entity unit is a frame–scale–class region; it does not require tracking a physical object instance across frames. For this measure, a class must contain at least 10 observations, and correlations are averaged over prompts and eligible classes. Its null reference is 0. All three measures include the five CLIP scales and are summarized by category and held-out building. 

## 4.7 Practical system design 

TextRadar separates training the single-frame radar distillation model from reconstructing a new scene. The camera and LiDAR provide supervision for the first stage: camera features supply language targets, and LiDAR geometry supports range targets, cross-modal alignment, and the reference trajectory used to accumulate panoramic supervision. Once trained, the distillation model predicts both ranges and language features from RF measurements. It is reused across environments, while a separate occupancy-language field is fitted to the observations of each new scene. Scene reconstruction also requires knowing sensor poses for radar predictions. For the reported scene-level results, these poses are estimated from radar. Radar odometry provides an initial trajectory, and geometric registration and loop-closure correction can reduce accumulated drift following the mapping strategy of CartoRadar [3]. The occupancy implementation also supports pose refinement through its geometric reconstruction loss. The language loss, by contrast, directly supervises surface features and does not itself optimize the sensor poses. Nevertheless, both fields depend on the correspondence between observations and scene locations, so trajectory quality affects the consistency of the resulting geometry and language features. To keep these training and reconstruction stages practical, the pipeline reuses learned models and extracted features to limit storage and computation. During training-data construction, the panoramic reference map stores links to camera features and their spatial and scale information rather than duplicat-ing every high-dimensional feature at every accumulated point. During scene reconstruction, occupancy samples and language surface observations can be drawn separately, allowing each language batch to reuse features from one cached radar frame. Finally, direct point supervision avoids volume rendering in the field-training losses, while occupancy-based rendering remains available for inspecting the fitted scene.
