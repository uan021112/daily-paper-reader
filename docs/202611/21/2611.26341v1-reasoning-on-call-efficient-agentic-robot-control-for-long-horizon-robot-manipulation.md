## 摘要
大型多模态模型能够支持长时程机器人操作，但频繁调用模型会带来显著的延迟和 token 成本。核心挑战在于判断何时需要智能体辅助或介入，以及出现错误时需要修正的是机器人执行、子任务规划，还是两者兼顾。为解决这一问题，我们提出 RoC（Reasoning on Call，按需推理），这是一种高效框架，通过在线任务状态监视器协调低层策略与高层推理智能体。该监视器结合时序视觉观测与有序交互记忆，联合估计当前子任务的进展并预测后续子任务。这些预测用于指导事件触发式智能体审查，以协调执行修复与计划修订。经验证的结果决定记忆更新和子任务转换，使常规执行仍由策略负责，而推理则专注于需要进一步评估的决策。在 RMBench 上，与表现最强的基于智能体的基线相比，RoC 将任务成功率提高了 24.0 个百分点，并将 token 消耗降低了 65.3%。与表现最强的基于策略的基线相比，其任务成功率也提高了 15.1 个百分点。真实世界实验进一步验证了 RoC 在三项长时程操作任务中的有效性。总体而言，RoC 能够在长时程机器人操作中实现高效的智能体介入，并协调执行与规划层面的恢复。

## Abstract
Large multimodal models can support long-horizon robot manipulation, but frequent model calls incur substantial latency and token costs. The central challenge is determining when agent assistance or intervention is needed and whether errors require correcting robot execution, subtask planning, or both. To address this problem, we propose RoC (Reasoning on Call), an efficient framework that coordinates a low-level policy and a high-level reasoning agent through an online task-state monitor. The monitor combines temporal visual observations with ordered interaction memory to jointly estimate progress within the active subtask and predict its successor. These predictions guide event-triggered agent review for coordinated execution repair and plan revision. Verified outcomes govern memory updates and subtask transitions, allowing routine execution to remain with the policy while reasoning focuses on decisions requiring additional assessment. On RMBench, RoC improves task success rate by 24.0 percentage points and reduces token consumption by 65.3% compared with the strongest agent-based baseline. It also outperforms the strongest policy-based baseline by 15.1 percentage points in task success rate. Real-world experiments further validate its effectiveness across three long-horizon manipulation tasks. Overall, RoC supports efficient agent intervention and coordinated recovery across execution and planning for long-horizon robot manipulation.

## 1. 核心问题与整体含义

- **研究背景**：长时程机器人操作由多个相互依赖的子任务构成，机器人不仅要执行动作，还要判断当前子任务是否完成、是否执行失败，以及下一步应做什么。视觉—动作策略（VLA/WAM）能够承担常规动作执行，多模态推理智能体则能提供任务理解、规划与错误恢复能力。
- **核心矛盾**：若频繁调用推理智能体审核每一步，虽然可能获得帮助，但会引入较高的推理延迟与 token 开销；若完全依赖策略，又可能难以发现执行失败、错误推进子任务或及时调整计划。
- **论文问题**：如何判断**何时需要智能体介入**，以及出错时应修正**机器人执行、子任务规划，还是两者兼顾**。
- **整体思路**：提出 RoC（Reasoning on Call），以在线任务状态监视器筛选需要进一步判断的时刻，让低层策略处理常规执行，只在出现进度异常、子任务转换请求或关键接触动作等事件时调用推理智能体。

## 2. 方法论

### 核心架构

RoC 由三个协同部分组成：

1. **低层机器人策略**：根据当前子任务、机器人状态和视觉历史，生成一段候选动作序列。
2. **在线任务状态监视器**：结合任务指令、当前子任务、视觉历史及有序交互记忆，估计当前子任务进度、判断是否应请求转换，并提出候选后继子任务或任务终止建议。
3. **高层推理智能体**：在触发审核时，判断是否继续执行、修复当前执行、修订子任务计划，或同时处理执行与规划问题。

### 监视器输入与预测

- 输入包括任务指令 \(g\)、当前子任务 \(\ell_k\)、已验证的交互记忆 \(M_t\)，以及视觉历史 \(H_t\)。
- 视觉历史采用**阶段感知采样**：从任务较早阶段稀疏抽取图像，保留场景和历史参照；从当前子任务阶段较密集抽取图像，呈现局部执行变化。
- 有序交互记忆保存子任务指令、执行动作、结果描述及相关观测时间戳；同一指令重复出现时仍记录为不同子任务实例。
- 监视器输出三项信息：
  - 子任务进度估计 \(p_t\)：由十档离散进度预测取期望得到；
  - 转换请求概率 \(s_t\)：预测是否应请求审核子任务转换；
  - 后继提议 \(e_{\ell_t}\)：指定候选下一子任务或任务终止。
- 后继子任务生成仅在转换请求概率超过阈值时启动；监视器训练时联合优化后继文本生成、进度分类和转换请求预测，并在子任务边界附近加密采样，以提高对转换时机的学习。

### 事件触发与控制流程

- 智能体审核由三类事件触发：
  1. **转换事件**：转换请求概率超过阈值；
  2. **进度事件**：出现明显进度下降、反复振荡或长时间停滞；
  3. **关键接触事件**：候选动作即将执行抓取闭合或放置释放，需要检查物体身份、相对位置和操作前提。
- 若未触发审核，机器人执行策略动作块的前缀，并继续获取观测。
- 若触发审核，智能体可选择：
  - 允许继续执行；
  - 缩短待执行动作前缀；
  - 局部修正末端执行器位姿或夹爪命令；
  - 接管当前子任务，直至结果得到验证；
  - 拒绝过早转换，保留未完成子任务；
  - 修订错误的后继子任务。
- 子任务完成后，智能体根据观测和动作验证结果；只有经确认的结果才写入交互记忆，获批准的后继任务才会正式提交。若智能体接管，恢复策略执行前会丢弃过期动作，并根据新观测重新生成动作块。

## 6. 主要结论与发现

- 在 RMBench 智能体基线比较中，RoC 平均成功率为 **99.6%**，较 GPT-as-Policy 高 **24.0 个百分点**，平均 token 消耗降低 **65.3%**。
- 在策略基线比较中，RoC 平均成功率为 **98.1%**，比最强策略基线 MemoryWAM 的 **83.0%** 高 **15.1 个百分点**。
- 消融结果显示，仅增加视觉历史，平均成功率从 **5.9%** 提升至 **14.7%**；再加入监视器后提升至 **63.7%**；完整 RoC 达到 **98.1%**。这表明状态监视有助于子任务推进，但要有效修复执行错误或错误转换，仍需要智能体介入。
- 真实机器人上，完整 RoC 在 Drawer Sorting、Cover and Reveal、Tabletop Cleanup 上分别达到 **70%、80%、70%**，总体 **73.3%**；高于 Policy + History + Monitor 的 **56.7%** 和 Policy Only 的 **30.0%**。
- 因而，论文支持这样一个结论：将智能体推理集中在需要额外判断的时刻，并让其同时审查执行和计划，有望兼顾长时程任务成功率与推理开销。

## 7. 优点

- **问题定义明确**：不只关注“何时调用智能体”，还把执行修复与计划修订纳入同一介入决策。
- **模块分工清晰**：低层策略执行常规动作，监视器在线筛选事件，智能体处理需要语义判断或恢复的情形。
- **监视与记忆互补**：同时利用阶段性视觉信息和按时间排序、经过验证的交互记录，减少仅靠稀疏图像历史可能造成的信息缺失。
- **介入方式具体**：提供动作前缀缩短、局部动作修正、子任务接管、拒绝转换和改写后继任务等操作，不局限于泛化的“重新规划”。
- **验证较全面**：包含多任务仿真、组件消融和真实机器人测试；同时报告成功率与 token 消耗，体现性能和推理成本之间的权衡。
- **具有一定可插拔性**：作者称该框架原则上可配合不同预训练低层策略使用，监视器与策略执行相对解耦。
