## 摘要
多模态基础模型正在推动具身导航的发展，但频繁推理会带来巨大的计算开销。我们提出认知视界动作分块（Cognitive-Horizon Action Chunking，CHAC），这是一种无需训练的框架，可利用记忆引导冻结导航策略进行自适应推理。保留的视觉上下文、完成提示和控制器反馈共同决定认知视界，即机器人在刷新预测前执行多少个缓存航点。当策略发出停止请求时，局部访问历史会引导一次有界修正，最多额外移动一次，且无需调用模型。在 HM3D-OVON 和 R2R-CE 上，CHAC 将视觉语言模型调用次数分别减少 33.4% 和 64.7%，成功率分别下降 0.63 和 10.82 个百分点。在两个基准上，按模型调用次数计算的成功率和路径长度加权成功率均有所提升。在四项实体导航任务中，每种方法进行 40 次运行，CHAC 成功 18 次，而原生执行成功 14 次；模型调用次数减少 54.9%，GPU 推理时间减少 49.7%。

## Abstract
Multimodal foundation models are advancing embodied navigation, but frequent inference incurs substantial computational cost. We present Cognitive-Horizon Action Chunking (CHAC), a training-free framework for memory-guided adaptive reasoning with a frozen navigation policy. Retained visual context, completion cues, and controller feedback determine the cognitive horizon, or how many cached waypoints the robot executes before refreshing its prediction. At the policy's stop request, local visitation history guides a bounded correction with at most one extra movement and no additional model calls. CHAC reduces vision-language model calls by 33.4% on HM3D-OVON and 64.7% on R2R-CE, with success-rate decreases of 0.63 and 10.82 percentage points, respectively. Success rate and success weighted by path length improve per model call on both benchmarks. Across four physical navigation tasks with 40 runs per method, CHAC achieves 18 successes versus 14 for native execution, reducing model calls by 54.9% and GPU inference time by 49.7%.

# 1. 核心问题与整体含义

- **研究背景：**具身导航中的视觉语言模型（VLM）需要反复接收图像、理解指令并生成动作，频繁推理带来较高计算成本。动作分块可以让机器人一次预测并执行多个航点，但固定执行长度难以兼顾效率与可靠性：执行太短会频繁调用模型，执行太长则可能在环境或运动状态变化后继续使用过时预测。
- **核心问题：**在不重新训练导航策略的前提下，如何利用已有的视觉上下文和执行反馈，判断何时继续复用缓存动作、何时刷新预测；以及当策略请求停止时，能否利用已经访问过的位置改善最终停靠位置。
- **整体方案：**论文提出 **CHAC（Cognitive-Horizon Action Chunking，认知视界动作分块）**。它在冻结导航策略外增加轻量级的在线调度机制：一方面动态决定缓存航点的执行长度；另一方面在原策略请求停止时，依据局部访问历史进行有界终点修正。方法不训练新的策略或调度器，目标是在减少模型调用的同时尽量维持导航表现。

# 2. 方法论

## 2.1 动态动作复用与认知视界

- 论文以冻结的 **OmniNav-Fast** 为导航策略。每次模型调用生成一段有序航点序列，默认包含 **5 个航点**。CHAC 的“认知视界”表示当前预测刷新前，最多继续执行多少个缓存航点。
- CHAC 按执行过程检查以下信息，遇到触发条件便放弃剩余缓存航点并重新调用策略：
  - **完成线索与控制器支持情况（Commitment boundary）：**
    - 若当前航点的到达分数大于 0.5，则在继续执行下一个缓存 MOVE 前刷新预测。
    - 对控制器即将执行的动作，比较请求位移与控制器预览位移在请求方向上的投影。若控制器预览显示沿请求方向没有正向进展，则刷新预测。
  - **视觉变化（Visual boundary）：**
    - 在推理时保存若干低分辨率灰度视觉参考，并记录视觉覆盖角度。
    - 执行中检查新观察到的动作方向是否超出原有视觉覆盖；若是，再比较该方向区域与其他图像区域的外观差异。若动作方向出现更明显的新视觉差异，则刷新预测。
  - **运动执行反馈（Motor feedback）：**
    - 若发生碰撞、动作被拒绝，或实际位移未沿请求方向产生正向进展，则缓存失效。
- 因此，缓存执行长度可理解为：**从当前预测开始，直到首次出现视觉、任务/控制器或运动反馈触发条件为止**，且不会超过预测航点数量及任务动作预算。刷新会替换剩余航点，但保留导航历史。
- 论文强调一个闭环特性：单看同一预测上的事件，增加刷新条件只会缩短或维持该预测的执行长度；但在完整导航过程中，刷新会改变后续动作、观察与停止时机。因此，增加某个边界并不必然增加总模型调用次数。

## 2.2 停止时的历史引导修正

- 当原生策略发出 STOP 请求时，CHAC 从局部范围内选取历史访问位置，并把当前视点作为零偏移记录加入计算。
- 对这些位置在当前水平坐标系中的偏移取均值，再投影到一个半径受限的圆盘中，得到候选修正位移。论文报告的修正上限为 **0.25 米**；局部历史筛选范围约 **2.12 米**。
- 候选修正必须通过原生控制器的正向进展预览，且动作预算至少还允许执行一次修正 MOVE 和随后 STOP，才会执行。否则直接停止。
- 该修正最多额外增加 **一次移动**，无需新增 VLM 或 flow-head 调用。历史只提供局部几何信息，并不带有目标标签。

## 2.3 算法流程概括

1. 调用冻结策略生成航点序列并保存视觉参考。
2. 按航点顺序执行动作；在继续复用缓存前检查完成线索、控制器预览与视觉变化。
3. 执行动作后根据实际运动反馈决定是否使缓存失效。
4. 缓存失效或耗尽时重新调用策略；导航位置历史持续保留。
5. 收到原生 STOP 请求时，计算受限的历史几何修正；若通过控制器和预算检查，则执行一次修正动作后停止。

# 3. 实验设计

## 3.1 仿真基准

- **HM3D-OVON Val-Unseen：**3,000 个开放词汇物体目标导航任务。成功要求实际发出 STOP，且终点距目标小于 **0.25 米**。
- **R2R-CE Val-Unseen：**1,839 个连续环境指令导航任务。成功要求实际发出 STOP，且终点距目标小于 **3 米**。
- 两个主基准均允许每个 episode 最多执行 **500 个环境动作**。论文报告成功率（SR）、路径长度加权成功率（SPL）、VLM 调用次数、FlowEq（flow 更新等价量）和环境动作数，并计算单位模型调用的导航表现。

# 6. 主要结论与发现

- **仿真调用成本明显下降，但导航性能有任务相关代价：**
  - HM3D-OVON：VLM 调用减少 **33.4%**，SR 从 32.17% 降至 31.53%，下降 **0.63 个百分点**；SPL 从 21.92% 降至 16.82%，环境动作数增加。
  - R2R-CE：调用减少 **64.7%**，SR 从 57.04% 降至 46.22%，下降 **10.82 个百分点**；SPL 从 49.30% 降至 34.17%。
  - 两个基准上，CHAC 的 SR 和 SPL 相对于 VLM 调用数的效率指标均高于原生执行，但这并不意味着绝对成功率或路径效率全面优于原生策略。
- **不同任务中的比较结果不同：**HM3D 上 CHAC 在动作分块基线中表现突出；R2R 上 ChunkTrust-AHS 以更少调用达到相近的成功率，说明 CHAC 并非所有操作点上的最优方案。
- **边界之间存在闭环交互：**在关闭 Commitment 时，加入视觉边界增加了 1,297 次调用；启用 Commitment 后，加入视觉边界反而减少 1,052 次调用。这说明刷新规则对总成本的影响取决于后续动作与终止过程。
- **终点历史有方向信息：**在匹配的终点干预中，局部共识方案取得 29.6% SR，优于沿最新位移继续的 16.2% 和反向的 26.4%；相较原始 STOP 的 23.0%，增加 82 次成功、出现 16 次退化。
- **实机结果有积极信号但样本有限：**CHAC 在 40 次运行中成功 18 次，原生执行成功 14 次，Fixed-3 成功 16 次；相对原生执行，调用次数减少 **54.9%**，GPU 推理时间减少 **49.7%**。

# 7. 优点

- **无需训练且可插入冻结策略：**方法主要由运行时边界判断和简单几何计算构成，避免额外训练调度器或改变基础导航模型。
- **考虑闭环执行而非只看动作块：**同时利用视觉变化、任务完成线索、控制器可执行性和实际运动反馈，比单纯固定步数复用更贴近导航运行过程。
- **区分视觉触发与控制反馈：**使用动作方向上的新视觉证据判断上下文变化，并通过控制器预览及实际反馈识别运动失败。
- **把历史用于两个不同阶段：**视觉上下文服务于预测刷新，访问位置历史服务于终点修正，且终点修正设有位移上限与控制器检查。
- **评估成本维度较完整：**除模型调用数外，同时报告 FlowEq、环境动作和实机 GPU 推理时间，并通过消融与配对分析尝试解释机制。
- **仿真之外提供真实机器人结果：**虽然规模较小，但为执行时域调度在真实硬件上的可行性提供了初步证据。

# 8. 不足与局限

- **仿真中的绝对导航表现会下降：**尤其在 R2R-CE 上，成功率和 SPL 都有明显下降；更多环境动作也可能抵消模型调用节省带来的实际效率收益。
- **终点修正依赖若干条件：**只有策略已经请求 STOP，且局部历史、动作预算和控制器预览都满足条件时才生效；它不能纠正所有错误路径或错误停止。
- **历史几何可能有偏差：**访问位置受里程计/位姿估计误差、局部采样分布及历史路线影响，局部均值不一定指向真实目标；论文也指出实机的终点修正机制主要通过仿真配对干预验证。
- **视觉边界较依赖实现细节：**低分辨率灰度图、区域划分和角度覆盖是轻量启发式，可能对光照、纹理、相机选取或细小场景变化敏感。论文给出扰动稳定性分析，但不等同于跨设备与复杂环境的充分鲁棒性验证。
- **实机证据规模有限：**只有 4 项室内任务，每项每种方法 10 次；成功数随任务变化，例如 A2 中 CHAC 少于两种基线，A3 中也低于原生执行，不能据此断言普遍提升。
- **成本指标不等同于总延迟或总能耗：**减少 VLM 调用和 GPU 推理时间未必意味着端到端任务时间、机器人动作时间或整体能耗同步下降。论文提到单摄像头需要顺序转动采集三视图，这一硬件延迟尚未被完整纳入性能比较。
- **泛化范围有限：**主要仿真评测围绕 OmniNav-Fast 展开，尚未证明 CHAC 在其他策略架构、不同机器人底盘、动态拥挤环境或更长时程任务中同样有效。
