## 摘要
物理人工智能要求模型能够理解空间关系和动态环境，并在有限的机载算力条件下将观测转化为行动。我们提出 TuringPAI，这是一组面向端侧物理人工智能的模型，包括用于通用视觉—语言理解的 TuringPAI-VL、用于自动驾驶的 TuringPAI-Drive，以及用于机器人操作的 TuringPAI-Embodied。TuringPAI-VL 是一个基于 HybridViT-MLQ 构建的 0.65B 模型；HybridViT-MLQ 将卷积局部聚合与基于 Transformer 的全局建模相结合。多尺度潜在查询（Multi-scale Latent Queries）在同一个视觉 Transformer 中整合空间特征与观测历史，为语言模型提供紧凑、结构化的接口。训练过程结合了通用视觉—语言数据，以及几何、跨视角和时间监督。TuringPAI-VL 支持通用多模态理解，在定量几何感知方面优于 Qwen2-VL-2B，同时为两个下游视觉—语言—动作（VLA）模型提供共享初始化。在自动驾驶方面，TuringPAI-Drive 借助 MLQ 接口，在所有评估的 ADE/FDE 指标上与完整 token 的 HybridViT 基线模型相差不超过 1.2%，并在内部仿真评估中取得了相当的综合得分。使用 XPeng Native Runtime（XNRT）在单个 NVIDIA Orin-X SoC 上运行时，TuringPAI-Drive 可在车载环境中以 12 Hz 生成轨迹。在机器人操作方面，TuringPAI-Embodied 在四个 LIBERO 套件上的平均成功率达到 96.8%。这些结果表明，在实际端侧约束下，共享的视觉—语言基础能够支持自动驾驶和机器人操作。

## Abstract
Physical AI requires models that understand spatial relationships and dynamic environments and translate observations into actions under limited onboard compute. We present TuringPAI, a family of models for on-device Physical AI comprising TuringPAI-VL for shared vision-language understanding, TuringPAI-Drive for autonomous driving, and TuringPAI-Embodied for robotic manipulation. TuringPAI-VL is a 0.65B model built on HybridViT-MLQ, which combines convolutional local aggregation with Transformer-based global modeling. Multi-scale Latent Queries integrate spatial features and observation history within the same visual Transformer, providing a compact, structured interface to the language model. Training combines general vision-language data with geometric, cross-view, and temporal supervision. TuringPAI-VL supports general multimodal understanding and improves quantitative geometric perception over Qwen2-VL-2B, while providing a shared initialization for the two downstream VLA models. For autonomous driving, TuringPAI-Drive maintains all evaluated ADE/FDE metrics within 1.2\% of a full-token HybridViT baseline using the MLQ interface and achieves comparable aggregate scores in an in-house simulation evaluation. Using XPeng Native Runtime (XNRT) on a single NVIDIA Orin-X SoC, TuringPAI-Drive generates trajectories at 12\,Hz in on-vehicle operation. For robotic manipulation, TuringPAI-Embodied achieves a 96.8\% average success rate across the four LIBERO suites. These results demonstrate a shared vision-language foundation for driving and robotic manipulation under practical on-device constraints.

# 1. 核心问题与整体含义

- **研究问题**：物理人工智能（Physical AI）系统需要从多摄像头、连续时序等视觉观测中理解空间关系和环境变化，并据此生成驾驶或操作动作；但这类系统通常部署在车载或机器人设备上，受到算力、延迟和输入长度限制。
- **研究动机**：常见视觉语言模型（VLM）将图像编码为大量密集视觉 token，多帧输入又会重复携带相似场景信息，带来较高计算成本。与此同时，通用图文训练不一定能让模型掌握距离、姿态、跨视角对应或运动变化等对实际行动重要的信息。
- **整体方案**：论文提出 TuringPAI 模型系列，以一个紧凑的共享视觉语言基础模型 **TuringPAI-VL** 为核心，并将其分别扩展为自动驾驶模型 **TuringPAI-Drive** 和机器人操作模型 **TuringPAI-Embodied**。目标是在端侧资源约束下兼顾多模态理解、几何与时序感知，以及下游动作生成。

# 2. 方法论

## 2.1 TuringPAI-VL 与 HybridViT

- TuringPAI-VL 总参数量约 **0.65B**，由约 **156M 参数的 HybridViT-MLQ 视觉编码器**和 Qwen2.5-0.5B 语言模型构成。
- **HybridViT**先通过卷积前端聚合图像局部内容，再由视觉 Transformer 建模全局关系。输入分辨率会动态调整至 128 的倍数，并划分为 \(128\times128\) 的区域；卷积特征总步长为 32。
- 对尺寸为 \(\tilde H\times\tilde W\) 的图像，卷积特征图产生的 token 数约为
  \[
  N=\frac{\tilde H\tilde W}{32^2}.
  \]
  相比同分辨率、patch size 为 16 的普通 ViT，视觉 Transformer 接收的 patch token 数约为四分之一。

## 2.2 多尺度潜在查询（MLQ）

- MLQ 在**同一个视觉 Transformer**中构造由粗到细的多尺度查询网格。查询由当前帧特征池化并线性投影得到，因而能针对输入尺寸和特征布局形成不同尺度的空间表示。
- 对视频输入，模型使用四帧观测窗口，以最后一帧作为当前帧；查询由当前帧初始化，再从当前帧及历史帧的 patch 特征中聚合信息。
- patch token 与查询 token 使用统一的三维旋转位置编码（3D RoPE）：空间坐标按网格单元中心归一化到 \([-1,1]^2\)，时间坐标使用实际采集时间戳。查询使用当前帧时间戳，patch 保留各自帧的时间戳。
- 注意力采用非对称掩码：patch 之间维持原有注意力结构，不读取查询状态；查询则可读取输入 patch 和自身及此前较粗尺度的查询。最终**只将更新后的查询 token 传给语言模型**。
- 对 \(T\) 帧输入，视觉 Transformer 处理序列长度为 \(TN+N_q\)，而语言模型接收的视觉 token 数为 \(N_q\)。实验配置中 \(T\in\{1,4\}\)，且 \(N_q\approx0.3N\)。固定查询布局时，增加历史帧不会增加传给语言模型的视觉 token 数。

## 2.3 面向物理智能的训练

- 训练数据包含三类：通用多模态理解、空间与几何感知、多图像与时序理解。
- 几何与空间监督包括像素深度、摄像机条件下的 3D 目标定位、空间关系、跨视角像素对应和相机相对位姿；时序监督涉及多视角问答、视频、交通场景和机器人操作过程中的运动及状态变化。
- VLM 采用两阶段训练：
  1. **对齐阶段**：使用通用图文数据，冻结语言模型，只训练视觉编码器和适配器。
  2. **联合训练阶段**：在更广的图像／视频文本数据上训练全部参数，并加入较大型 TuringViT VLM 的 logit 蒸馏。

## 2.4 下游模型

- **TuringPAI-Drive**：以七路环视摄像头的四帧输入为条件，预测未来 6 秒、共 72 个 waypoint 的自车轨迹，并添加轨迹规划头。
- **TuringPAI-Embodied**：将 TuringPAI-VL 与 π0 风格的 flow-matching 动作专家结合。输入包括两个 \(256\times256\) 相机视角和 80 维机器人状态，使用 10 步去噪生成一段 6 个连续动作。

# 6. 主要结论与发现

- TuringPAI-VL 将卷积局部聚合、多尺度查询、时空位置编码和面向物理任务的训练结合起来，试图在压缩视觉 token 的同时保留空间与历史信息。
- 在若干几何评测中，TuringPAI-VL 表现突出：例如 NYU Depth V2 的 AbsRel 为 **0.146**，优于表中两个参照模型；7-Scenes 相对位姿 AUC@30° 为 **19.99**，明显高于公开模型基线。
- 驾驶方面，HybridViT-MLQ 的所有已评估 ADE／FDE 指标与完整 token 的 HybridViT 相差不超过 **1.2%**；内部仿真综合成本总体接近，但个别子项存在权衡。
- 在单颗 Orin-X 上，XNRT 使 VLM prefill 延迟降至约 70 ms，并保有较高数值相似度；系统在车载运行中达到 12 Hz 轨迹生成。
- TuringPAI-Embodied 在 LIBERO 四套任务上的平均成功率为 **96.8%（1,936／2,000 次）**，与论文引用的 OpenPI π0.5 已发表结果接近。
- 论文据此主张，一个共享视觉语言基础可以迁移到驾驶和操作等不同物理智能任务，并在端侧计算预算下运行。

# 7. 优点

- **架构与部署目标一致**：通过局部卷积聚合降低视觉 token 数，再用 MLQ 限定传给语言模型的 token 预算，直接针对端侧算力和上下文开销。
- **时空信息设计明确**：查询层次、跨尺度空间位置和真实时间戳共同参与表示；四帧历史信息可以被聚合，而不增加传给语言模型的查询 token 数量。
- **训练监督较全面**：除通用图文对齐外，还纳入深度、3D 定位、跨视角对应、相机位姿和时序任务，覆盖与物理交互相关的能力。
- **同一基础模型支持多种下游任务**：既验证自动驾驶，也验证机器人操作，体现了共享初始化的可迁移性。
- **报告了实际硬件测量**：不仅给出模型 benchmark，也提供 Orin-X 上的运行时、精度和阶段延迟数据，并区分部分测量边界。
- **结论有所限定**：驾驶章节指出部分指标改善、部分指标退化，碰撞失败率也略有增加；定性归因仅作为观察，不把它当成因果证明。

# 8. 不足与局限

- **公开可复现性受限**：关键驾驶数据、仿真套件、训练数据构成细节和完整训练方案来自企业内部；外部研究者难以独立复现或核查主要驾驶结论。
- **外部比较不足**：驾驶主要与自家完整 token HybridViT 比较，没有在统一公开数据和统一协议下与代表性外部驾驶 VLA 进行系统比较。机器人结果与 π0.5 的对照引用了已发表结果，执行条件并不完全相同。
- **部分 benchmark 结论需谨慎**：3D 目标定位中参照模型没有有效分数，因而不能据此得出相对领先结论；TuringPAI-VL 在 ERQA、RoboSpatial、VSI 等任务上并未全面领先。通用多模态能力也呈现任务间强弱不一。
- **缺少更细的因果消融**：文中重点比较完整 HybridViT 与 HybridViT-MLQ，但没有充分分离卷积 token 化、MLQ 多尺度结构、时序查询、3D RoPE 和几何训练数据各自的贡献。
- **统计与安全证据有限**：未报告多次训练或随机种子的方差、置信区间与显著性检验。内部仿真指标和失败率不能替代大规模真实道路安全验证，也不能证明系统在罕见危险场景下可靠。
- **延迟口径不等同于端到端能力**：驾驶的 69.773 ms 是特定 GPU 侧 VLM prefill 统计，排除了若干处理阶段；机器人 168.3 ms 也从 CNN patch embedding 之后开始计时。12 Hz 车载运行提供了系统级证据，但论文没有完整给出各环节延迟分布、最坏时延和长期稳定性。
- **不同模型的速度比较存在配置差异**：图中跨 VLM 的 TensorRT 延迟使用模型特定输入，未做精度匹配；机器人模型的计时也不完全处于相同的模型和输入条件，不能将速度差异完全归因于架构。
- **机器人评测仍偏基准化**：LIBERO 成绩较高，但尚不足以说明对真实长时程任务、接触丰富操作、跨平台迁移和失败恢复的能力；论文也将异步动作执行及感知—执行时序错位列为后续工作。
