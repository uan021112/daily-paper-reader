Abstract
Large multimodal models can support long-horizon robot
manipulation, but frequent model calls incur substantial la-
tency and token costs. The central challenge is determin-
ing when agent assistance or intervention is needed and
whether errors require correcting robot execution, subtask
planning, or both. To address this problem, we propose
RoC (Reasoning on Call), an efficient framework that coor-
dinates a low-level policy and a high-level reasoning agent
through an online task-state monitor. The monitor com-
bines temporal visual observations with ordered interac-
tion memory to jointly estimate progress within the active
subtask and predict its successor. These predictions guide
event-triggered agent review for coordinated execution re-
pair and plan revision. Verified outcomes govern memory
updates and subtask transitions, allowing routine execu-
tion to remain with the policy while reasoning focuses on
decisions requiring additional assessment. On RMBench,
RoC improves task success rate by 24.0 percentage points
and reduces token consumption by 65.3% compared with
the strongest agent-based baseline. It also outperforms the
strongest policy-based baseline by 15.1 percentage points
in task success rate. Real-world experiments further vali-
date its effectiveness across three long-horizon manipula-
tion tasks. Overall, RoC supports efficient agent interven-
tion and coordinated recovery across execution and plan-
ning for long-horizon robot manipulation.
1. Introduction
Long-horizon robot manipulation requires both reliable ex-
ecution and effective planning.
A robot must carry out
individual subtasks, assess their outcomes, and determine
which goal to pursue next. Visuomotor policies, such as
VLAs [9] and WAMs [22], provide action execution ca-
pability, but successful long-horizon manipulation also re-

quires coordinating these actions with task-level decisions.
Recently, agentic robot control approaches such as GPT-
as-Policy [18] and Harness VLA [25] introduce multimodal
reasoning agents to interpret task context, coordinate sub-
tasks, and guide recovery. However, repeated agent calls
incur substantial token costs and inference latency [11, 17].
These costs accumulate as the agent repeatedly processes
visual observations and execution history. When execution
must wait for its decisions, agent intervention becomes a
bottleneck even during routine behavior that the policy can
handle independently. The challenge is therefore to deter-
mine when agent intervention is needed and how it should
guide execution repair and plan revision, without repeatedly
querying the agent itself.
To address this challenge, we propose RoC (Reasoning
on Call), an efficient framework that coordinates a low-level
policy and a reasoning agent through an online task-state
monitor. The monitor integrates stage-aware visual context

Progress anomalies, transition requests, and
critical contact events in candidate actions selectively trig-

the agent can authorize continued policy execution, shorten
or refine candidate actions, take over subtask execution, or

Three long-horizon

To summarize, our main contributions are twofold:
• We propose RoC, an efficient agentic robot control frame-
work for long-horizon manipulation that couples monitor-
triggered agent review with coordinated execution repair
and plan revision.
• We develop an online task-state monitor that serves as a
plug-in module to guide selective agent intervention, re-
ducing redundant agent calls and reasoning overhead.
2. Related Work
2.1. Long-Horizon Manipulation
Long-horizon manipulation requires robots to execute in-
terdependent subtasks while retaining historical observa-
tions and interaction outcomes. Policy-based approaches
address this by incorporating task history into action gen-
eration and subtask selection.
MEM [19] and Memory-
WAM [21] equip policies with short- and long-term mem-
ory, while MemER [16] and PAL [14] use learned hierar-
chical policies to retrieve historical observations or orga-
nize them into executable subtasks.
These methods im-
prove memory-conditioned decisions, but recovery still de-
pends on the learned policies’ ability to correct failed in-
teractions and inappropriate subtask choices. RoC comple-
ments these policies with selective agent intervention for
execution repair and plan revision, expanding recovery ca-
pabilities while preserving efficient routine execution.
2.2. Agentic Robot Control
Recent advances in general-purpose multimodal mod-
els have enabled agentic robot control through visual
understanding and semantic reasoning.
Specifically,
RoboICL [13] generates actions using demonstrations and
interaction memory, while CaP-X [6] synthesizes exe-
cutable robot-control programs.
GPT-as-Policy [18] ex-
plores both direct agent control and a hybrid mode in which
the agent reviews and corrects actions proposed by π0.5.
Harness VLA [25] combines agent reasoning with learned
manipulation skills by composing VLA and analytic primi-
tives for task orchestration and recovery.
However, frequent agent calls introduce latency and to-
ken costs. Cocurrent work reduces this overhead through
selective assistance [11, 17], feedback-driven replanning [3,
10], and learned monitors for progress, failures, and task
transitions [1, 2, 7]. Detecting a problem or predicting a
task transition does not, by itself, determine whether recov-
ery requires correcting execution, revising the plan, or both.
RoC makes this coordination explicit: the agent jointly re-
views the current execution and proposed next goal, allow-
ing execution repair and plan revision within the same in-
tervention.
2.3. Reward and Progress Models in Robotics
Reward and progress models provide intermediate feedback
for evaluating robot execution and improving policies [24].
For multi-stage tasks, VICtoR [8] identifies task stages and
evaluates progress within each stage.
SARM [4] jointly
predicts task stage and fine-grained progress, using esti-
mated rewards to filter and reweight demonstrations for be-
havior cloning. Robometer [12] combines within-trajectory
progress supervision with cross-trajectory preference learn-
ing, leveraging successful and failed executions for reward
modeling, policy optimization, and failure detection. Build-
ing on Robometer, RoC’s online task-state monitor jointly
estimates subtask progress, predicts transition requests, and
proposes next goals, guiding selective agent intervention for
coordinated execution repair and plan revision.
3. Method
RoC follows a monitoring–execution–review loop. At ini-
tialization, the online task-state monitor proposes the first
subtask from the task instruction and initial observation,
using empty subtask and interaction-memory inputs. The
reasoning agent confirms this proposal before policy ex-
ecution begins. During execution, the monitor estimates
the active subtask progress and predicts transition requests
and next goals.
Transition requests, progress anomalies,
and critical contact events trigger agent review for coor-
dinated execution repair and plan revision. Verified out-
comes and approved transitions govern memory updates
and task progression. We formulate the component inter-
faces in Sec. 3.1, then describe the online task-state mon-
itor in Sec. 3.2 and the agent intervention mechanism in
Sec. 3.3.

3.2. Progress Monitoring and Subtask Prediction
Interaction Memory and Visual Context.
The monitor
conditions on g, ℓk, Mt, and observations selected from
Ht. Each entry in Mt contains a subtask instruction, exe-
cuted actions, an outcome description, and timestamps cor-
responding to supporting observations in Ht. Records fol-


low execution order, with repeated instructions retained as
distinct subtask instances. Their generation and commit-
ment are described in Sec. 3.3.
We select visual context from Ht using stage-aware sam-
pling. Sparse observations uniformly sampled from the ini-
tial time step to the start of the current subtask provide a
persistent scene reference and historical context. Denser
observations are uniformly sampled from the start of ℓk to
time t, capturing local execution changes. This balances
historical coverage and local detail under a fixed visual in-
put budget, while Mt preserves interaction outcomes that
sparse observations may miss, as illustrated in Figure 3.
Online Task-State Monitor.
We initialize Fϕ from
Robometer [12], a general-purpose robotic reward model.
Its pretraining combines progress supervision with trajec-
tory comparisons involving successful, suboptimal, and
failed executions, providing a pretrained basis for assessing
execution progress.
Visual observations sampled from Ht, together with g,
ℓk, and the ordered subtask list recorded in Mt, form a
shared context for the monitor’s predictions. Specifically,
learnable progress tokens and densely sampled observa-
tions are causally interleaved. The contextual hidden state
of the current observation’s progress token feeds both the
progress head and the transition-request head. The progress
head predicts a categorical distribution pt over ten discrete
progress values in [0, 1], whose expectation gives the scalar
estimate pt. This estimate describes the relative execution
stage within ℓk and is used for progress-anomaly detection.
The transition-request head predicts st directly from the
same contextual representation. Although the two heads
share their underlying features, they have different supervi-
sion and control roles: pt identifies abnormal progress pat-
terns, while st requests a change of subtask. An autoregres-
sive language generation branch proposes eℓt or task termi-
nation from the shared context. The request head therefore
predicts whether a transition should be reviewed, while the
generation branch specifies which subtask should follow.
During execution, the generation branch is activated only
when st exceeds the transition threshold; otherwise, succes-
sor generation is skipped. Progress and transition-request
predictions are read from context positions preceding the
successor text, preventing the target instruction from leak-
ing into these predictions during training. Completion is
verified by the reasoning agent during review, as described
in Sec. 3.3.
Training Objective.
Subtask transitions are temporally
sparse, so uniform sampling yields far more training exam-
ples within subtasks than near their boundaries. This imbal-
ance can make accurate transition timing difficult to learn.
We therefore halve the interval between sampled training
timesteps around annotated subtask boundaries, doubling
the local sampling density and increasing the monitor’s
exposure to states immediately before and after a transi-
tion. We jointly supervise progress estimation, transition
requests, and next goal generation:

the transition-request label. Training inputs contain only
observations and verified interaction records available up to
time t.
3.3. Event-Triggered Agent Intervention
Event Triggers.
We define three event types. (1) Tran-
sition events occur when st exceeds the request threshold.
The candidate eℓt specifies the next goal or task termination
to be reviewed; it does not independently trigger a transi-
tion. (2) Progress events occur when pt exhibits signifi-
cant declines, repeated oscillations, or stagnation within the
same subtask instance ℓk. (3) Critical contact events occur
before grasp closure or placement release in At, prompting
checks of object identity, relative geometry, and interaction
prerequisites.
Agent Intervention and Control Handoff.
Using shared
task and execution context, the agent jointly determines
whether execution repair, plan revision, or both are needed.
Execution repair supports three modes: (1) prefix shorten-
ing, which executes fewer actions from At before obtain-
ing new observations; (2) local refinement, which adjusts
end-effector poses or gripper commands; and (3) subtask
takeover, in which the agent directly controls the robot until
the subtask outcome is verified. Plan revision supports two
modes: (1) transition rejection, which retains an unfinished
ℓk; and (2) successor revision, which replaces an invalid eℓt
with an appropriate next subtask. If neither correction is
needed, the agent authorizes continued policy execution.
Following review or repair, the agent checks observa-
tions and executed actions to verify subtask completion,
generating an outcome description when completion is con-
firmed. RoC stops executing the completed ℓk and retains
its outcome while reviewing the successor. Once the suc-
cessor or task termination is approved, RoC updates the
ordered interaction memory Mt with the verified interac-
tion record and commits the transition. If the successor is
rejected, RoC replans without repeating the completed in-
teraction.
Policy commands are suspended during agent
takeover. Before policy execution resumes, RoC discards
stale actions and generates a new action chunk from fresh
observations and the confirmed subtask.

4. Experiments
4.1. Experimental Setup
Environments and Tasks.
In simulation, we evaluate
RoC on all nine tasks in RMBench [5], where an M(1)
task requires recalling a key past observation (e.g., the ini-
tial position of an object), while an M(n) task requires
tracking multiple past interactions (e.g., previous attempts
or completed operations) to guide subsequent actions. For
real-robot evaluation, we instantiate RoC on the 5-DoF SO-
ARM101 platform, with a fixed external RGB camera and
a wrist-mounted RGB camera.
We evaluate three long-
horizon manipulation tasks, Drawer Sorting, Cover and Re-
veal, and Tabletop Cleanup.
Baselines.
We organize the baselines into two groups and
evaluate them separately. Agent-based baselines include di-
rect agent control and hybrid control in GPT-as-Policy [18].
These baselines retain their original configurations with
GPT-6 Astra (xhigh), while RoC uses GPT-6.1 Sol (xhigh)
for agent intervention.
Seven policy-based baselines in-
clude standard policies and memory-augmented policies, as
listed in Table 2.
Evaluation Protocol.
We measure task success rate (SR)
and average token consumption per episode (Tok.). In sim-
ulation, comparisons with agent-based methods use 30 in-
dependent trials per task, while comparisons with policy-
based methods use 100 independent trials per task.
We
report per-task results and averages across the nine tasks.
Each real-robot task is evaluated over 10 independent trials,
with success defined as completing all required subtasks in
the specified order and achieving the target final state.
4.2. Implementation Details
In simulation, we train the online task-state monitor for one
epoch across all nine RMBench tasks. RoC supports any
pretrained low-level policy in theory. In our experiments,
we initialize the policy from pretrained FastWAM [23]. The
policy receives the current subtask instruction, robot state
and three visual observations: the initial frame o0, a recent
frame from the active subtask, and the current frame ot.
During inference, the monitor operates at 7.10 Hz with-
out subtask generation and 0.53 Hz when generating a sub-
task, with an overall measured throughput of 2.77 Hz. The
low-level policy uses 50 diffusion denoising steps to predict
a 32-step action chunk. During agent review, the reasoning
agent can approve an execution prefix of 1–32 steps or ap-
ply local corrections over 1–5 steps. For progress anomaly
detection, we first smooth progress estimates using a me-
dian filter and then detect decline, oscillation, or stagnation
within a 64-step lookback window. The decline threshold is
set to 0.2. Oscillation is detected when the progress range
exceeds 0.25 with more than three reversals in the direction
of meaningful progress changes, while stagnation is identi-
fied when the progress range remains within 0.1.

4.5. Real-Robot Evaluation
Tasks.
We evaluate three tabletop manipulation tasks on
the real robot, illustrated in Figure 6(a). In Drawer Sorting,
the robot observes the initial color-to-drawer associations
and then closes the drawers. It is then given a randomly
selected yellow, blue, or red block, which it places in the
drawer at the corresponding level. In Cover and Reveal, the
robot memorizes the randomized initial locations of three
colored blocks, covers them with cups from left to right,
and then reveals the red, blue, and yellow blocks in that
order. In Tabletop Cleanup, the robot places a white power
adapter, a small transparent tape roll, a large white tape roll,
and a white handheld fan into the orange box.
Results and Analysis.
Figure 6(b) reports success over
10 trials per task for three variants of RoC: Policy Only,
Policy + History + Monitor, and RoC. RoC achieves suc-
cess rates of 70%, 80%, and 70% on Drawer Sorting, Cover
and Reveal, and Tabletop Cleanup, respectively. Its over-
all success rate is 73.3%, compared with 56.7% for Policy
+ History + Monitor and 30.0% for Policy Only. Adding
history and monitoring improves task progression, but the
resulting system still relies on the policy to recover from
unsuccessful interactions. Agent intervention yields addi-
tional gains of 10, 20, and 20 percentage points across the
three tasks, respectively.
These results show how selec-
tive agent intervention complements task-state monitoring
by enabling execution repair and plan revision before errors
propagate to later stages. Further efficiency comparisons
with agent-based methods are provided in the appendix.
Failure Analysis.
Failures primarily involve difficult
grasps that remain unsuccessful despite agent intervention.
In these cases, the current reasoning agent fails to translate
visual evidence into effective grasp corrections, highlight-
ing agent capability as a remaining bottleneck. RoC decou-
ples agent reasoning from task-state monitoring and policy
execution, allowing more capable agents to be integrated
without redesigning the control framework. Stronger vi-
sually grounded manipulation reasoning may therefore im-
prove recovery within the same architecture.
5. Conclusion
In this work, we presented RoC, an efficient agentic control
framework for long-horizon robot manipulation. RoC coor-
dinates a low-level policy, an online task-state monitor, and
a reasoning agent to enable selective agent intervention and
coordinated execution repair and plan revision. By tracking
subtask progress and verifying execution outcomes, RoC al-
lows routine manipulation to remain with the policy while
invoking higher-level reasoning when needed. Experiments
on RMBench demonstrate improved task success over rep-
resentative agent-based and policy-based methods, together
