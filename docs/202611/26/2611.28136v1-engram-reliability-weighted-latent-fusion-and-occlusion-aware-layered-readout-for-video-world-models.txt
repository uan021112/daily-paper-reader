Abstract
Camera-conditioned video world models aim to generate 3D-consistent videos from a single image along specified cam-
era trajectories. However, set-union updates in latent spatial memory leave repeated observations unconsolidated, while
frontmost-only readout limits simultaneous access to stored evidence at different depths. To address these limitations, we
present ENGRAM, a latent spatial memory framework combining reliability-weighted latent fusion and occlusion-aware
layered readout. Specifically, recursive fusion integrates geometrically and visually compatible observations in a channel-
normalized latent space, consolidating repeated evidence into a shared scene representation. Layered readout exposes multi-
ple depth-ordered latent candidates with their reliability and availability at each target cell. This gives the generator access
to information from multiple surfaces as visibility changes. Explicit camera rays provide viewpoint information independently
of memory coverage, while geometric consistency constraints guide memory updates. Memory retrieval uses a single projec-
tion at latent resolution, avoiding intermediate RGB rendering and VAE re-encoding. We adapt a pretrained video generator
using only 256 training scenes. On 100 RealEstate10K test scenes, ENGRAM improves novel-view-synthesis and closed-loop
PSNRs over Spatia by 0.82 and 4.48 dB, respectively. On a 200-case WorldScore evaluation subset, it achieves an aver-
age score of 67.78, exceeding Spatia by 3.31 points. Project page: https://wchkoutian.github.io/engram-
website/.

1. Introduction
Large-scale video diffusion models synthesize photorealistic sequences and provide a foundation for generative world mod-
els [8, 19, 22]. Geometric drift is what separates a world model from a per-frame generator: driven along a camera trajectory,
a model produces frames that are individually plausible and jointly inconsistent, and the inconsistency compounds from
chunk to chunk. Explicit spatial memory removes the drift by preserving observed geometry and appearance and by showing
each newly generated chunk a view of that memory from the target camera.
Existing systems keep explicit 3D representations, including colored point clouds [11, 25] and Gaussian scene representa-
tions [2, 24], render them at every step, and pass the render back into the conditioning path through a variational autoencoder
(VAE) [2, 11, 25], paying for the render and for a second lossy encode. LSM-World [20] removes the intermediate by storing
scene features in the diffusion latent space, lifting latent tokens to 3D with depth-guided back-projection and reading them
back with a projection at latent resolution. We retain this direct latent-space projection. Removing the render, however, does
not decide what such a store should hold. What does a slot represent once the same surface has been observed many times?
And which stored slot should the generator be shown when several surfaces project to the same target cell?
Set-union accumulation, the natural update for such a store, makes every valid back-projection its own record. A surface
seen across a hundred overlapping views therefore occupies a hundred competing entries whose features differ only by depth
noise and per-view estimation error. Nothing in the store decides which of them is right, so the decision falls to readout,
and readout is where it fails: a small change in estimated depth moves the choice to a different record of the same surface,
and a revisit renders that surface inconsistently with the visit that already recorded it. The failure is structural rather than
occasional, because overlapping views are precisely what a memory is built to collect. Fusion resolves the competition where
it can still be resolved, at write time against a shared scene representation, instead of deferring it to every query. It must also
decide what not to store: a generated record can project in front of an initial surface that it never observed, and writing it
there destroys the only evidence of that surface.
A second difficulty concerns which records the generator can address. Frontmost selection exposes only the nearest surface
at each target cell, leaving other projected candidates unavailable to the generator in that readout. A revisit at a shallower
angle, or a ray that grazes an occlusion boundary, exposes the gap, and a single-layer readout has no place to put the answer.
Figure 2 illustrates two requirements: retaining generated history for revisits and exposing multiple stored candidates to the
generator.
A third challenge is learning spatial-memory conditioning. Training a generator from scratch would require learning both

video synthesis and memory use. Our two-stage adaptation reuses pretrained synthesis capabilities, first learning the memory

We introduce ENGRAM, a latent spatial memory that resolves both questions inside the read–generate–update cycle illus-
trated in Figure 1. Reliability-weighted latent fusion consolidates compatible observations within a voxel into a single slot,
weighted by depth reliability and gated so that a generated record cannot enter in front of an initial surface it never observed.
Occlusion-aware layered readout returns depth-ordered candidates per cell together with their reliability and availability, so
the answer stays addressable after the nearest surface stops being the right one. Explicit Pl¨ucker camera rays carry camera
information independently of memory coverage. Generated frames are written back through the same cycle, so a view sur-
vives its departure from the context window and is still available when the camera returns. We adapt a pretrained Wan2.2
backbone using 256 training scenes. We evaluate ENGRAM on RealEstate10K [30] and WorldScore [5], covering novel-view
synthesis, closed-loop revisits, and camera-controlled world generation.
Contributions. (i) We introduce a reliability-weighted latent fusion operator that consolidates compatible multi-view
observations of a surface into a single slot, weighted by depth reliability and gated against writing a generated record in front
of an initial surface. The store stops accumulating competing records, and readout stops having to adjudicate among them.
(ii) We propose an occlusion-aware layered readout that returns multiple depth-ordered candidates per cell together with
their reliability and availability, so that evidence behind the nearest surface remains addressable to the generator as visibility
changes. (iii) We demonstrate data-efficient spatial-memory adaptation through a two-stage strategy that learns the memory
interface before adapting the generator, enabling consistent generation with limited training data.
2. Related Work
Video diffusion world models.
Video diffusion transformers [8, 17, 19, 22] generate temporally coherent video and are
increasingly treated as world models when conditioned on a camera trajectory. Without a persistent representation they drift
geometrically over long rollouts, which motivates explicit spatial memory.
Spatial memory for consistent generation.
Existing methods maintain explicit 3D representations and render target views
for generation [2, 3, 6, 11, 23–25], while view-memory methods retrieve past frames [14, 29]. Volumetric and learned latent
fusion have been studied for reconstruction [4, 10, 16, 21]. Our closest baseline, LSM-World [20], stores diffusion features in
3D using set-union updates and frontmost readout. We retain direct latent-space projection and introduce reliability-weighted
latent fusion and occlusion-aware layered readout within the generation loop.
Camera conditioning and calibration.
Pl¨ucker coordinates [18] are used for camera conditioning [9]. We use these
coordinates to provide viewpoint information independently of memory coverage. Confidence calibration aligns classification
probabilities with empirical correctness [7]. Our memory fusion uses geometric and temporal precision proxies to weight
observations.

4. The ENGRAM Model
4.1. Overview
ENGRAM initializes a persistent latent spatial memory and a clean prefix from the input image. It then generates successive
video chunks through a read–generate–update cycle (Algorithm 1). At each chunk, the memory provides depth-ordered scene
features for the target viewpoints, while explicit camera rays supply viewpoint information independently of memory cover-
age. The conditioned video generator synthesizes the next chunk, whose latent observations are integrated into memory using
estimated geometry and reliability weights. The two central operators are reliability-weighted latent fusion and occlusion-
aware layered readout, supported by geometric consistency constraints and a two-stage adaptation strategy. Figure 3 shows
the full cycle, while Fig. 4 details the two operators.

4.3. Occlusion-aware layered readout
For each target view, we project memory slots with positive camera depth onto the latent grid and order them by depth within
each cell. We first select up to K frontmost slots. If none originates from the initial observation, the nearest projected slot
from that observation replaces the last selected slot, when available.
Each selected layer provides a latent feature (C channels), a bounded reliability value, a validity mask, and a normalized
inverse depth. Features are restored to their original latent coordinates before conditioning, and missing layers are filled with
zeros and marked invalid. The resulting memory conditioning has K(C + 3) channels, giving 102 channels for C = 48 and
K = 2. This layered representation provides the generator with stored information at multiple depths as visibility changes.

4.6. Training and implementation
We adapt the pretrained generator in two stages. Stage 1 trains the conditioning branch while keeping the generation backbone
and VAE fixed. Stage 2 freezes the conditioning branch and optimizes all parameters of the generation Transformer. The
VAE remains fixed throughout. Both stages use the flow-matching objective in Eq. (1), with the clean prefix retained as
unperturbed context and excluded from the prediction loss.
Training uses 256 scenes, each providing five forward windows and four return windows, yielding 2,304 training windows.
Training memories are constructed from observed video history using precomputed geometry. Each window includes a text
caption, which is dropped with probability 0.1 during training.
The two stages run for 4,000 and 8,000 optimization steps, respectively, with an effective batch size of four across four
NVIDIA H200 GPUs. We use AdamW, bfloat16 mixed precision, and gradient checkpointing. At inference, depth is esti-
mated from decoded frames using MapAnything [13], and video chunks are sampled with UniPC [28] using 40 steps.

5. Experiments
We evaluate complete-system performance on WorldScore and RealEstate10K, and isolate the effects of memory writing,
layered readout, and two-stage adaptation through ablations.
5.1. Main comparisons and shared protocol
We compare complete systems using released checkpoints, except for LSM-World [20], which we reproduce. Wan2.2-TI2V-
5B [19] serves as a backbone reference with image and text conditioning rather than pose tensors; its comparison with
ENGRAM is not an isolated memory ablation.
WorldScore.
We evaluate on a 200-case WorldScore subset using its ten official metrics [5]. WonderWorld’s motion
metrics and dependent aggregates are not applicable. General video models receive image and camera-text prompts, whereas
pose-conditioned methods receive numeric camera poses. Table 1 shows that ENGRAM achieves the highest aggregate score
of 67.78. Relative to Spatia, motion smoothness, camera control, and subjective quality improve by 17.31, 11.25, and 9.61
points, respectively. Its 3D consistency is nearly unchanged, while motion accuracy and magnitude remain lower. Detailed
protocols are provided in Supplementary Sec. C.1.
RealEstate10K.
We evaluate all methods on the same 100 held-out scenes [27, 30]. NVS scores frames 1–80 against
ground truth; closed-loop evaluation compares frame 152 with the initial image. Methods share target camera trajectories,
field of view, frame times, and scoring resolution. Each task starts from the real input image and uses only generated
observations as subsequent visual history. Table 2 reports mean per-scene scores.
Table 2 shows that ENGRAM achieves the best PSNR, SSIM, and LPIPS on both tasks among the compared methods.
Relative to Spatia, NVS PSNR improves by 0.82 dB to 17.568 dB, while closed-loop PSNR improves by 4.48 dB to 20.455
dB. Closed-loop SSIM increases from 0.6827 to 0.7692, and LPIPS falls from 0.3373 to 0.2200, showing gains in both
structural and perceptual similarity. The larger improvements on revisits highlight the model’s ability to recover previously
observed views after exploration. This pattern aligns with the ablations in Sec. 5.3, where disabling history writing or masking
the second readout layer produces larger PSNR drops on closed-loop reconstruction than on NVS.
5.2. Computational cost
Figure 5 summarizes the recorded quality–cost trade-off and adaptation cost. Our two-stage adaptation uses 80.8 GPU hours
of logged updates: 17.0 for Stage 1 and 63.8 for Stage 2. Direct latent-memory readout avoids intermediate RGB rendering
and VAE encoding when constructing spatial conditions.

Closed-loop scoring returns to the real initial image, which can reward initial-view anchoring rather than memory. We

5.5. Discussion and limitations
Both NVS and closed-loop evaluation use multi-chunk generation. Removing generated-history writing or masking the
second readout layer causes a larger PSNR drop in closed-loop reconstruction than in NVS. These results highlight the role
of persistent memory when returning to earlier viewpoints. History writing preserves earlier observations across chunks,
while layered readout supplies candidates from multiple surfaces as visibility changes. We report the two tasks separately to
distinguish novel-view reconstruction from revisit consistency.
ENGRAM relies on estimated geometry. Depth is predicted from decoded frames and determines where latent observations
are written in the world coordinate system. Errors in these estimates can therefore propagate through later memory queries,
displacing stored observations and altering the depth ordering of readout candidates. Compatibility checks and bounded
accumulation regulate memory updates, but systematic depth bias remains a limitation. Memory grows as new regions are
explored: the per-voxel slot limit bounds local density, not total storage. Moving surfaces are not explicitly modelled.
6. Conclusion
We presented ENGRAM, a latent spatial memory framework combining reliability-weighted latent fusion and occlusion-aware
layered readout. The framework consolidates compatible observations and exposes multiple depth-ordered candidates within
a read–generate–update cycle. Generated-history write-back retains scene evidence beyond the current context window,
while explicit camera rays provide viewpoint information independently of memory coverage. Adapted with 256 training
scenes, ENGRAM improves novel-view synthesis and closed-loop reconstruction on RealEstate10K and achieves the highest
aggregate score among the compared systems on the 200-case WorldScore subset. The gains are particularly pronounced for
closed-loop revisits. Ablation comparisons highlight the role of generated-history writing and layered memory conditioning
in closed-loop reconstruction, as well as the benefit of second-stage adaptation. Future work will extend the framework to
dynamic scenes and memory management under fixed storage budgets.

B. Implementation and Training Details
Memory configuration.
The latent has C = 48 channels, and each voxel accommodates at most L = 8 slots. The
compatibility thresholds are τf = 3 and τp = 1, with position distances divided by the voxel side length. The accumulated
weight is capped at Wmax = 20. Scene coordinates are normalized by the median metric depth s0 of the initial image.
A voxel side length of 0.005 metres therefore becomes hvox = (0.005 m)/s0 in normalized coordinates. A generated slot
adopts the incoming candidate position only when the candidate weight exceeds the stored weight before the update.
Normalization and reliability.
Channel normalization uses fixed statistics and a variance stabilizer of 10−5. The angular
factor in Eq. (4) uses ϵ = 10−3, and the temporal discount base is γ = 0.98. The angular exponent is 1/2, and the temporal
factor is γri. Here, ri = ⌊si/4⌋, where si is the global RGB-frame index measured from the rollout start. Initial-observation
weights are multiplied by four. Generated observations are fused into separate slots, while the initial-observation slots remain
fixed.
Layered conditioning.
The readout returns up to K = 2 layers. Each layer contains C feature channels, one reliability
channel, one validity mask, and one inverse-depth channel. The memory representation therefore has 102 channels; append-
ing the six Pl¨ucker ray channels gives 108. The reliability channel is

The readout cap of five is applied separately from the fusion weight cap Wmax = 20. The inverse-depth channel is 1/(1+d),

The conditioning branch uses blocks copied from backbone layers {0, 4, 8, 12, 16, 20, 24, 28}.
Generation and memory updates.
Each chunk contains nine latent frames corresponding to 33 RGB frames. Consecutive
chunks overlap by one RGB frame, giving a stride of 32 frames. Sampling uses UniPC [28] with 40 steps. Depth is estimated
from decoded frames using MapAnything [13]. Writes require finite positive depth. A candidate projecting onto valid initial-

latent refinement in Eq. (8) uses Adam for 50 steps with learning rate 0.02 and mean absolute RGB reconstruction error.
Optimization details.
Both training stages use a learning rate of 5×10−6. The learning rate is constant in Stage 1; Stage 2
uses a 100-step linear warm-up followed by a constant learning rate.
Recorded training cost.
The logged training-update costs are 17.0 GPU hours for Stage 1 and 63.8 GPU hours for Stage 2,
totaling 80.8 GPU hours. These costs exclude data preparation, initialization, and checkpoint saving.

C.2. Ablation settings
Table 3 includes inference interventions, a separately trained No-read model, and a Stage 1 checkpoint comparison.
Inference interventions.
No-write and second-layer masked reuse the same ENGRAM checkpoint as the full row and
change only the runtime path. No-write retains the initial-image cache, the camera conditioning and the generated-prefix
rule, and suppresses the write-back of generated observations, so the memory never grows beyond the first view. Second-
layer masked zeroes the second-layer conditioning channels (51:102) while leaving selection depth K = 2, the first layer, the

both rows reuse the full checkpoint, their differences from the full model are attributable to the removed component without
retraining variance, but they cannot be read as the performance of a system designed without that component.
Retrained variant.
No-read removes the memory condition from the architecture and is trained separately under the same
data, schedule and objective, with the 102 memory channels set to zero and the six camera channels retained.
Stage 2 adaptation.
Stage 1 only loads the Stage 1 side-branch checkpoint on the unmodified pretrained backbone, retain-
ing the full model’s memory operators, inference path, hyperparameters and score normalization. This comparison evaluates
the benefit of Stage 2 adaptation.
Sharing.
All five rows use the same 100 test scenes, camera trajectories, target resolution, sampler and scoring code. Scenes
are scored individually and then averaged, so no row benefits from a different subset.
