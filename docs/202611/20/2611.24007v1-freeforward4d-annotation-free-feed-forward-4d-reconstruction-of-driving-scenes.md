## 摘要
前馈式 4D 重建能够高效创建可渲染的自动驾驶仿真场景。然而，现有大多数方法严重依赖数据集提供的相机参数、LiDAR 深度或 3D 边界框标注，因此难以应用于未标注的驾驶视频。预训练视觉模型仅凭 RGB 图像即可预测相机参数、深度和目标轨迹，但这些几何信息彼此并不一致：多视图预测以较短时间窗口为单位生成，各窗口的尺度和坐标系彼此独立；单目深度则仅在单张图像范围内具有度量尺度。我们的核心洞见是，将这些先验信息统一到一个度量坐标系后，便可用它们替代数据集标注，实现前馈式 4D 重建。我们提出了 \textbf{FreeForward4D}，通过使用单目度量深度校准相互重叠的预测窗口，并将其跨时间注册到同一坐标系中。在此几何基础上，我们将跨相机的 2D 轨迹关联到 3D 中，并采用分层运动模型描述物体运动：该模型结合共享的物体速度与局部高斯修正，使训练和推理都仅需 RGB 视频。在 Waymo 数据集上，FreeForward4D 在无需尺度对齐的情况下恢复了度量尺度的相机参数和深度，并取得 27.66 dB 的 PSNR 和 0.836 的 SSIM。与依赖数据集标注的 STORM、SLARM-F、UFO、DGGT 和 StreetForward 相比，该方法在全图像 PSNR 上表现更优，并在 8 秒时间窗口上取得最佳 RGB 保真度。仅使用 RGB 进行微调，还可使该框架适配 nuScenes 和 Argoverse 2。代码即将发布。

## Abstract
Feed-forward 4D reconstruction enables efficient creation of renderable driving scenes for autonomous driving simulation. However, most existing methods rely heavily on dataset-provided cameras, LiDAR depth, or 3D box annotations, limiting their applicability to unannotated driving videos. Pretrained visual models can predict cameras, depth, and object tracks from RGB alone, but their geometry is mutually inconsistent: multi-view predictions come in short windows with independent scales and frames, while monocular depth is metric only per image. Our key insight is that, once reconciled into a single metric frame, these priors can replace dataset annotations for feed-forward 4D reconstruction. We present \textbf{FreeForward4D}, which calibrates overlapping prediction windows against monocular metric depth and registers them into one frame across time. On this geometry, 2D tracks are associated across cameras in 3D, and objects move through hierarchical motion that combines a shared object velocity with local Gaussian corrections, so that both training and inference use only RGB videos. On Waymo, FreeForward4D achieves 27.66 dB PSNR and 0.836 SSIM while recovering metric-scale cameras and depth without scale alignment. It surpasses STORM, SLARM-F, UFO, DGGT, and StreetForward, which rely on dataset annotations, in full-image PSNR and attains the best RGB fidelity on 8-second windows. RGB-only fine-tuning further adapts the framework to nuScenes and Argoverse 2. Code will be released.

- **核心挑战：**预训练视觉模型可以从 RGB 预测相机、深度和目标轨迹，但这些预测并不能直接拼在一起使用：多视图模型以短时间窗口预测相对尺度几何，不同窗口的尺度和坐标系可能不同；单目模型提供的度量深度则是逐图像的；相机内参还可能对应不同图像尺寸或裁剪方式。
- **论文主张：**如果先将这些视觉先验校准并统一到一个度量坐标系，就可以用它们替代数据集标注，为前馈式 4D 重建提供几何条件和动态建模依据。论文据此提出 **FreeForward4D**。

# 2. 方法论

## 2.1 整体流程

FreeForward4D 分成两部分：

1. **度量一致的几何先验整合：**从 RGB 生成相机、深度和目标轨迹等先验，并统一其尺度、坐标系和图像网格。
2. **几何引导的动态重建：**在统一几何基础上预测 3D 高斯，将不同相机观察到的同一目标关联起来，并建模目标运动与跨时间信息融合。

方法使用四种冻结的预训练模型：VGGT-Ω 估计多视图相机与相对深度，MoGe-2 估计单目度量深度，Grounding DINO 检测目标，SAM 2 生成并传播目标掩码。它们不在本文数据上微调。

## 2.2 几何先验的度量校准与统一

- **跨模型尺度校准：**对每个多视图时间窗口，利用该窗口与其他窗口共享的图像作为锚点，将窗口相对深度 \(D_w^i(p)\) 与单目度量深度 \(M_i(p)\) 拟合。每个窗口估计尺度 \(s_w\)，每张图像估计偏移 \(b_i\)，使其近似满足：
  \[
  M_i(p)\approx s_wD_w^i(p)+b_i,\qquad s_w>0.
  \]
  通过带 Huber 鲁棒损失和偏移正则项的联合优化估计这些量。偏移用于吸收单目深度偏差；最终用拟合尺度调整相机平移，深度监督本身不加偏移。
- **跨窗口坐标系对齐：**利用重叠窗口中的共享相机估计刚性 \(SE(3)\) 变换，将窗口注册到同一场景坐标系。刚性变换保持已经校准的度量尺度；重复估计的相机参数再进行融合。
- **图像网格对齐：**根据预处理中的缩放、裁剪和填充，将预测内参转换到重建所用的图像网格，并将 RGB、深度和目标掩码同步重采样。这样相机射线与重建输入图像保持一致。

## 2.3 高斯重建与动态建模

- **前馈式高斯预测：**Transformer 编码图像块、Plücker 射线图和时间信息，并聚合上下文帧特征，解码出与像素对齐的 3D 高斯。高斯中心由相机射线起点、射线方向和预测深度确定；模型还预测其尺度、朝向、不透明度、颜色及生命周期。
- **跨相机目标关联：**Grounding DINO 与 SAM 2 分别为各相机生成 2D 目标轨迹。对每条轨迹，取其掩码内高斯中心的坐标中位数作为 3D 中心；比较不同相机在共享时间上的中心距离，通过互为最近邻及距离阈值形成跨相机关联组。每组至多包含每个相机的一条轨迹，未关联区域作为背景处理。
- **分层运动模型：**对同一关联组的多视角、多时刻特征进行聚合，由速度 MLP 预测共享物体速度 \(v_g\)，表示目标整体平移。局部运动头再预测每个高斯的残差速度 \(\delta v_j\)、加速度 \(a_j\) 和 jerk \(j_j\)，使运动既有物体级一致性，也能表达局部差异。其位置随时间变化为：
  \[
  \mu_j(t)=\tilde{\mu}_j+(v_g+\delta v_j)\Delta t_j+
  \tfrac12a_j\Delta t_j^2+\tfrac16j_j\Delta t_j^3.
  \]
  其中，局部修正主要用于描述车辆转向等空间上不均匀的运动；背景高斯保持静止。
- **源时间感知融合：**将来自不同上下文时间的高斯运动到目标时间后，按其源时间与目标时间的距离加权。权重在该物体被观测到的上下文时间之间归一化，避免目标在外推时因离所有观测时刻都较远而整体淡出。背景高斯则依据其预测生命周期衰减不透明度。
- **训练目标：**联合使用 RGB 重建损失、LPIPS 感知损失、MoGe-2 伪深度监督，以及限制局部运动过大的正则项；目标掩码区域在 RGB 损失中获得更高权重。

# 3. 实验设计

## 3.1 数据集与评测场景

- **Waymo Open Dataset：**主要评测数据集，覆盖验证集 202 个场景，使用 front-left、front、front-right 三个摄像头。  
  - **2 秒设置：**每段选取 4 个上下文时刻，评估插值和外推目标帧；最终统计 96,360 张目标图像。
  - **8 秒设置：**使用 16 个上下文帧及 64 个目标时间戳，共统计 387,648 张目标图像；窗口之间存在重叠，目标图像不去重。
- **nuScenes 与 Argoverse 2：**用于跨数据集适配。模型从 Waymo 训练模型出发，仅利用 RGB 派生条件进行微调，并在各数据集验证场景上评估 2 秒和 8 秒设置。

## 3.2 Benchmark 与对比方法

- **指标：**全图及动态区域的 PSNR、SSIM；深度使用有效 LiDAR 像素上的 D-RMSE，且不进行尺度对齐。数据集相机、LiDAR 和 3D 框只用于评估。
- **对比方法：**
  - 位姿条件前馈方法：STORM、SLARM-F、UFO、PointForward。
  - 位姿自由方法：DGGT、StreetForward。
  - 8 秒实验还与 3DGS、PVG、Street Gaussians、DeformableGS、GS-LRM 等进行比较。
- **主要指标结果：**Waymo 2 秒设置下，FreeForward4D 的全图 PSNR 为 **27.66 dB**、SSIM 为 **0.836**；动态区域 PSNR 为 **24.36 dB**、SSIM 为 **0.729**。其 D-RMSE 为 **7.06 m**。Waymo 8 秒设置下，全图 PSNR 为 **27.57 dB**、SSIM 为 **0.836**。

# 6. 主要结论与发现

- 将相机、深度和目标轨迹等 RGB 视觉先验统一到同一度量坐标系，是无数据集标注前馈重建的关键；消融实验中，移除几何先验整合后，全图 PSNR 下降 **3.93 dB**。
- 几何引导的共享物体速度和局部高阶运动修正改善了动态区域重建。去掉目标运动后，动态区域 PSNR 下降 **1.59 dB**。
- 在 Waymo 上，方法获得较高的全图 RGB 保真度，并在 8 秒窗口评测中优于所列对比方法的 RGB 指标。
- 方法无需尺度对齐即可输出度量尺度几何，但其深度误差并非所有对比方法中最低；Waymo 2 秒 D-RMSE 为 7.06 m，低于部分方法的深度表现。
- 仅用 RGB 微调可以适配 nuScenes 和 Argoverse 2，表明该框架可迁移到不同数据集与摄像头配置，但结果仍受预训练先验和数据域变化影响。

# 7. 优点

- **降低标注依赖：**把 RGB 预训练模型的输出作为替代几何与目标先验，避免在 FreeForward4D 的训练和推理中依赖数据集相机、LiDAR 深度或 3D 框。
- **明确处理先验不一致：**分别针对尺度、坐标系和图像网格问题设计校准、注册和内参转换步骤，方法逻辑清晰。
- **动态建模兼顾整体与局部：**共享速度建立目标级运动一致性，局部高斯轨迹进一步表达非刚性或空间变化的运动。
- **实验维度较广：**涵盖多数据集、不同时间窗口、相机精度、模块消融和定性结果，并报告无尺度对齐的深度误差。
- **推理速度较快：**在先验已预计算的前提下，单段重建和目标时间渲染耗时较短，适合高效生成可渲染场景。

# 8. 不足与局限

- **度量几何仍受先验质量约束：**相机、深度和尺度来自冻结的视觉模型；论文也指出深度精度受预训练先验限制。遇到极端光照、遮挡、动态模糊或视觉先验失效时，几何误差可能影响后续高斯重建和目标关联。
- **深度精度不是最强项：**虽然方法实现了无需尺度拟合的度量深度，但 D-RMSE 并未全面优于使用数据集标注的方法，说明“度量尺度恢复”不等同于“几何精度领先”。
- **目标关联仍有漏检风险：**补充材料报告跨相机目标关联的 pairwise precision/recall 为 **0.867/0.647**；召回率有限，且 3D 中心受高斯预测误差影响。
- **依赖离线全视频处理：**相机先验和轨迹利用全视频信息，适用于离线重建，不等同于在线因果系统；先验生成的计算成本也未完整计入所报告的重建与渲染速度。
- **评测协议存在比较边界：**若基线使用数据集相机而本文使用估计相机，或结果来自不同论文协议，指标差异可能同时反映相机条件、数据处理和评测协议差异。论文补充评测缓解了部分问题，但不能消除所有异质性。
- **预训练数据可能带来数据关联风险：**MoGe-2 的训练数据包含部分驾驶数据的 LiDAR 信息，且数据划分未在本文所给材料中明确；这不等同于本文训练使用标注，但限制了对“完全未接触相关数据分布”的强解释。
- **动态表达范围有限：**运动模型主要通过高斯中心随时间移动，尺度、朝向和颜色保持固定；对强烈形变、外观变化或复杂拓扑变化的物体，表达能力可能不足。
- **算力报告不完整：**未披露 H200 GPU 数量、总训练时间和完整预处理耗时，因而难以全面评估训练成本及端到端部署效率。
