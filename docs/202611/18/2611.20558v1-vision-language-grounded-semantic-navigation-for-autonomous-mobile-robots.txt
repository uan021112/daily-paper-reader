# Vision-Language Grounded Semantic Navigation for Autonomous Mobile Robots 

Ravindran Vasoor Saravanan 1, Chittin Varunav Ravi 1, Thirulok Sundar Mohan Rasu 2, Madhumita Singh 1

> 1

Department of Mechanical Engineering, 2Department of Electrical Engineering and Computer Science University of Michigan, Ann Arbor, MI, USA

Abstract —Language-guided navigation enables mobile robots to interpret natural language commands and navigate toward user-specified targets in unstructured environments. However, integrating open-vocabulary visual perception with classical robotics pipelines for mapping and navigation remains a chal-lenging problem. In this work, we present a complete ROS2-based system that combines frontier-based exploration, open-vocabulary object detection using Grounding DINO, depth-based 3D localization, and semantic mapping to enable end-to-end vision-language grounded navigation in simulation. The system accepts natural language commands such as “go to the yellow box,” detects candidate objects from RGB images using text prompts, estimates their positions in the world frame, and generates navigation goals executed by the Nav2 stack. In a Gazebo-based indoor environment with a TurtleBot3 robot, the system autonomously explored the room, detected three of the five target objects, and successfully executed both natural language navigation commands tested, without task-specific training. The results indicate that open-vocabulary grounding models can be integrated into classical navigation pipelines, though performance is limited by detection uncertainty, depth-based localization error, and incomplete exploration coverage. These findings highlight both the feasibility and current limitations of deploying vision-language grounded navigation systems using lightweight, CPU-only architectures. 

Index Terms —Semantic navigation, vision-language grounding, open-vocabulary object detection, Grounding DINO, frontier-based exploration, ROS2, mobile robotics, autonomous explo-ration 

I. I NTRODUCTION 

Autonomous mobile robots in human environments must do more than move from point A to point B: they must understand their surroundings in terms that humans naturally use. When a user says “go to the blue box” or “find the red cylinder,” the robot needs to understand both the spatial layout of the environment and the semantic properties of the objects within it. This problem, known as vision-language grounded navigation, combines simultaneous localization and mapping (SLAM), open-vocabulary computer vision, and natural lan-guage processing (NLP). Traditional navigation systems model the world as a geo-metric entity consisting of walls, obstacles, and free space. Semantic mapping extends this by adding labels to objects, but most systems can only recognize a fixed set of object types learned during training [1]. This leads to two key limitations. First, adapting a closed-vocabulary system to a new domain requires collecting labeled data and retraining the detector. Second, the system can only recognize objects it was trained on, making it difficult to handle new or unseen object descriptions at runtime. Recent vision-language models, especially Grounding DINO [2], address this by allowing open-vocabulary object detection using text prompts. Users can describe objects in natural language, and the model attempts to find them in im-ages. When combined with language-driven planning systems such as SayPlan [3] and LM-Nav [4], these capabilities open the door to robots that can be instructed in ordinary English. However, integrating these models with standard navigation systems is still challenging. Grounding DINO is slow on CPU (about 5–10 seconds per image), detections can be noisy when multiple objects are present, and keeping detections consistent with the SLAM map and user commands requires careful system design. In this work, we focus on addressing these challenges within a unified system. 

A. Contributions 

This work presents an integrated system that combines open-vocabulary perception with classical robotics compo-nents. Our main contributions are: 1) ROS2-based integrated pipeline: We implement aROS2 Humble–based system combining frontier-based exploration, Grounding DINO object detection, depth-based 3D localization, semantic mapping, and command parsing. These components are coordinated through a state machine managing transitions between exploration, perception, and navigation. 2) Frontier selection with failure handling: We imple-ment a frontier selection strategy that scores candidate frontiers based on size and distance. The system tracks repeated navigation failures and adjusts behavior to reduce the likelihood of getting stuck in difficult regions, such as concave areas or unreachable goals. 3) Rule-based natural language command parsing: We implement a simple regex-based parser to extract key elements such as action, object category, and visual attributes (e.g., color), enabling consistent interpretation of navigation commands. 4) Experimental validation in simulation: The system runs on Ubuntu 22.04 with ROS2 Humble using CPU-only PyTorch, without requiring GPU acceleration. We arXiv:2611.20558v1 [cs.RO] 16 Nov 2026 demonstrate end-to-end operation from autonomous ex-ploration to language-guided navigation in a Gazebo-based indoor environment with geometric objects.

B. System Overview 

The system operates in two main phases. During the explo-ration phase , the robot autonomously navigates an unknown environment using a frontier-based strategy. At regular in-tervals (approximately every 1.5 meters), Grounding DINO processes the current camera image to detect objects, which are then localized in 3D using depth-based projection and added to a semantic map. During the query phase , the user issues natural language commands that are parsed and matched against the semantic map to generate navigation goals, which are executed by the Nav2 stack. II. R ELATED WORK 

A. Frontier-Based Exploration 

The frontier exploration algorithm, originally proposed by Yamauchi [5], defines frontiers as boundaries between known free space and unknown space in an occupancy grid. The robot iteratively navigates to frontier centroids, expanding the mapped region until no frontiers remain. This foundational approach has been extended with methods that use informa-tion gain [6], coordinated multi-robot exploration to reduce overlap [7], and strategies that balance exploration benefit with navigation cost. Our work builds on the classical Yamauchi approach with two modifications. First, we use a weighted scoring function that balances frontier size (as a proxy for information gain) against Euclidean distance from the robot, favoring large nearby frontiers. Second, we implement an adaptive failure-escalation policy that switches between selection strategies based on consecutive navigation failures, preventing the robot from becoming permanently stuck. 

B. Semantic Mapping 

Semantic mapping systems associate semantic labels with geometric map representations. Early approaches relied on convolutional neural networks trained on fixed sets of ob-ject categories. More sophisticated systems like SemanticFu-sion [8] fuse convolutional neural network predictions with dense SLAM to produce 3D semantic reconstructions. Recent work on ConceptFusion [9] demonstrates open-vocabulary 3D mapping using multimodal foundation models, allowing arbitrary text queries against the reconstructed scene. Our approach differs in two ways. First, we use Grounding DINO’s open-vocabulary 2D detection combined with depth-image projection, rather than dense 3D reconstruction, which significantly reduces computational cost. Second, our semantic map is lightweight (a list of labeled 3D points with confidence scores and observation counts), making it easy to store in JSON and query using simple string matching. 

C. Vision-Language Models for Robotics 

The integration of large vision-language models into robotics has gained significant momentum. CLIP [10] enabled zero-shot visual recognition from text descriptions by train-ing on 400 million image-text pairs. Grounding DINO [2] brings open-vocabulary recognition to object detection: it fuses language into the transformer-based DINO detector through grounded pre-training, so that it predicts bounding boxes for arbitrary text phrases. SayPlan [3] and LM-Nav [4] demon-strate language-driven navigation using large language models for task planning and landmark grounding. Our approach takes a simpler direction. Rather than using large language models for runtime planning, we use Ground-ing DINO only for perception and process natural language commands with regex-based parsing. This makes the system deterministic, fast to debug, and deployable without API dependencies or GPU requirements. 

D. Object-Goal Navigation 

Object-goal navigation refers to the task of navigating to an instance of a specified object category in an unknown environment [11]. Methods for this problem range from modular systems that build semantic maps and use classical planning [12] to end-to-end reinforcement learning approaches that learn navigation policies directly from visual input. Our system considers a related setting where targets are specified using natural language descriptions, including attributes such as color. The robot first explores the environment to build a semantic map and then uses it to navigate to the requested object. III. S YSTEM ARCHITECTURE 

A. Simulation Environment 

Experiments are conducted in Gazebo Classic 11 using a TurtleBot3 Waffle Pi differential-drive robot. The robot is equipped with (i) a 360 ◦ HLS-LFCD LiDAR (0.12–3.5 m range), (ii) an RGB camera ( 640 × 480 , 62.2 ◦ horizontal field of view), and (iii) a co-located depth camera publishing 32-bit float depth images. The simulation runs in real time using ODE physics with a 0.001 s step size. The environment consists of an 8 m × 8 m indoor room enclosed by 2.5 m walls. Five geometric objects are placed at fixed locations: red cylinder (−2, 2) , blue box (2 , 2) , green cylinder (−2, −2) , yellow box (2 .5, −2.5) , and white cylinder 

(2 .5, 0.5) . Objects use distinct solid colors to ensure clear visual separation. The robot is initialized at the origin.

Adaptive failure recovery. An important addition to our frontier explorer is the failure-escalation policy. C. Object Detection with Grounding DINO 

The GroundingDINODetector module wraps the HuggingFace implementation of Grounding DINO (model ID: IDEA-Research/grounding-dino-base , approx-imately 232 M parameters). The model weights are down-loaded once and cached locally for subsequent use. Inference takes approximately 5–10 seconds per image on CPU, which is acceptable for the 1.5-meter detection interval but not suitable for real-time operation without GPU acceleration. Detection is triggered during exploration whenever the robot has traveled more than 1.5 meters since the last detection. The detection prompt consists of a set of candidate object descriptions tailored to the simulation environment. Grounding DINO returns a list of bounding boxes with per-box confidence scores and text labels. A minimum confidence threshold of 0.28 (empirically tuned) filters spurious detec-tions. Detections are sorted by descending confidence before being passed to the 3D localization stage. 

Label cleaning. A subtle issue with Grounding DINO is that when multiple objects appear in a single image frame, the detector sometimes concatenates multiple prompt tokens into a single label (e.g., “red cylinder blue box green cylinder”). Our label cleaning heuristic matches the detected label against all prompt terms and returns the longest matching single term. This partially resolves the multi-object label concatenation problem but is not a complete solution.

E. Semantic Map 

The SemanticMap module maintains a list of 

SemanticObject entries, each containing a label (string), a 3D world position (list of 3 floats), a confidence score, a timestamp, and an observation count. When a new detection arrives, the system first checks for existing objects with the same label within a merge distance threshold dmerge = 0 .5 m. If a match is found, the existing object’s position is updated via weighted running average:

The map supports several query types: fuzzy substring (case-insensitive substring matching, so “blue” matches “blue box”), exact match, nearest to position (within a maximum distance), and spatial region (all objects within a spherical ra-dius). The map serializes to JSON for persistence across runs, enabling incremental map building over multiple exploration sessions. 

F. Natural Language Command Parser 

The CommandParser module processes natural language navigation commands using a cascade of regular expressions. This design choice is deliberate: it avoids large language model inference, makes the parser deterministic and easy to debug, and eliminates external API dependencies. The parsing pipeline proceeds through four stages: 1) Action detection: Patterns match action verbs such as 

go to , navigate to , move to , find , locate , where is , and 

explore .2) Spatial relation extraction: Patterns match spatial prepositions (e.g., near , behind ) followed by a reference object name. 3) Attribute extraction: A color modifier is extracted from a vocabulary of five colors (red, blue, green, yellow, white). 4) Target extraction: The text remaining after the above elements are removed becomes the target object label; in our environment this is a shape descriptor (box or cylinder). The parser produces a structured ParsedCommand 

with fields for raw_text , target_object ,

target_attribute , spatial_relation ,

spatial_reference , location , and action .The combined attribute + target (e.g., “blue box”) forms the 

query_text used to query the semantic map. 

G. Mission Controller 

The MissionControllerNode orchestrates the full au-tonomous pipeline via a finite state machine utilizing five states: IDLE , EXPLORING , DETECTING , NAVIGATING , and 

> FAILED

. Upon initialization, the system rests in IDLE until an explicit text command (e.g., “start exploration”) is received via the /user_command topic, at which point the node tran-sitions to EXPLORING . During this phase, Grounding DINO detection runs periodically (every 1.5 m of travel) alongside the frontier explorer to populate the semantic map. When an operator issues a specific natural language naviga-tion directive (e.g., “Go to the green cylinder”), the controller parses the string, queries the stored semantic map for the object’s spatial coordinates, and transitions to NAVIGATING .These target coordinates are dispatched to the Nav2 framework using the /navigate_to_pose action interface, which assumes responsibility for global path planning and local costmap-based obstacle avoidance. Upon task completion (suc-cess or failure), the controller returns to IDLE .Throughout the mission, the controller subscribes to /camera/image_raw ,

/depth_camera/depth/image_raw , and /odom ,while publishing human-readable telemetry and task outcomes to /navigation_status and newly detected objects as JSON to /semantic_map/add . To ensure robustness against memory constraints or system crashes, the mission controller automatically serializes and saves the semantic map to disk after every successful detection cycle. IV. I MPLEMENTATION 

A. Development Environment 

The complete system is developed and tested on Ubuntu 22.04 LTS with ROS2 Humble Hawksbill, using VSCode as the primary development environment. Gazebo and RViz run natively on the desktop with standard X11 display. 

B. Software Dependencies 

The system depends on ROS2 Humble pack-ages (turtlebot3 , turtlebot3_gazebo ,

cartographer_ros , navigation2 , nav2_bringup )and Python 3.10 with a dedicated virtual environment containing PyTorch (CPU build), transformers ≥4.35, Pillow, OpenCV, SciPy, and spaCy (an optional dependency of the command parser). Grounding DINO model weights are downloaded automatically from HuggingFace on first use. The ROS2 workspace uses colcon for building with 

symlink-install mode to enable rapid iteration. 

C. Parameter Tuning 

Several parameters were empirically tuned for the single-room environment: minimum frontier size kmin = 3 cells; goal timeout 60 s; physical stuck timeout 45 s; detection interval 1.5 m; merge distance 0.5 m; Grounding DINO box threshold 0.30; text threshold 0.25; and a minimum confidence of 0.28 for adding detections to the semantic map. The exploration phase has a configurable time limit (default 900 s) to prevent indefinite exploration. V. E XPERIMENTS AND RESULTS

VI. D ISCUSSION 

A. Key Findings 

Our experiments suggest three findings. First, a complete vision-language navigation pipeline is achievable on com-modity CPU hardware without GPU acceleration, though with inference latency of 5–10 seconds per image. Second, the weighted frontier strategy with adaptive failure recovery mitigates a critical failure mode observed during development: the closest-frontier strategy frequently selected goals within Nav2’s 0.25 m goal tolerance, causing the robot to report “success” without moving. The weighted strategy, by balanc-ing frontier size against distance, avoids this degenerate case. Third, regex-based command parsing was sufficient for the navigation commands we tested, and avoids the latency and deployment complexity of LLM-based parsers. 

B. Limitations 

Multi-object label concatenation is the most significant issue in our current detection pipeline. When many objects appear in one frame, Grounding DINO returns merged labels, causing incorrect 3D localization and preventing proper duplicate merging. Depth-based 3D localization error of 0.3–2.4 m is significant relative to the object sizes, and is compounded by a mismatch between the Gazebo camera HFOV and the intrinsics used in the code. Exploration covered only about 60% of the room, which left one object undetected. Finally, all results come from a single exploration run and two navigation commands; they demonstrate feasibility but do not provide statistically meaningful performance estimates. 

C. Future Work 

Five directions would significantly improve the system. First, a principled solution to multi-object label concatenation could be implemented by prompting Grounding DINO with one object category at a time and aggregating results, at the cost of additional inference calls. Second, GPU acceleration via CUDA would bring detection to real-time rates suitable for physical robot deployment. Third, hierarchical semantic maps that organize objects by room would enable room-level navigation commands such as “go to the kitchen table.” Fourth, replacing the regex parser with a small on-device language model would enable more complex spatial and compositional queries. Fifth, extension to a multi-room house environment would test the system’s scalability beyond the single-room environment. VII. C ONCLUSION 

We presented a complete vision-language grounded navi-gation system integrating frontier-based exploration, Ground-ing DINO open-vocabulary detection, depth-based 3D lo-calization, semantic mapping with duplicate merging, and regex-based natural language command parsing in a unified ROS2 Humble pipeline. Experiments in a Gazebo single-room simulation containing five geometric objects demonstrated autonomous exploration covering approximately 60% of the room in about 8 minutes, detection of three of the five objects with confidence scores up to 0.51, and successful execution of both natural language navigation commands tested. The weighted frontier selection with adaptive failure recovery prevented the robot from becoming permanently stuck during the run. The system operates entirely on CPU-only commod-ity hardware without GPU acceleration. The key remaining challenges are reducing multi-object label confusion from Grounding DINO, correcting the camera intrinsics mismatch to improve 3D localization accuracy, improving exploration coverage, and scaling the system to multi-room environments.
