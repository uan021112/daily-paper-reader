## 摘要
语言引导导航使移动机器人能够理解自然语言指令，并在非结构化环境中导航至用户指定的目标。然而，将开放词汇视觉感知与用于建图和导航的经典机器人技术流程相结合，仍是一项具有挑战性的问题。在本研究中，我们提出了一套完整的 ROS2 系统，将基于前沿点的探索、使用 Grounding DINO 进行的开放词汇目标检测、基于深度的三维定位以及语义建图相结合，从而在仿真环境中实现端到端的视觉—语言接地导航。该系统能够接收“去黄色箱子那里”等自然语言指令，利用文本提示从 RGB 图像中检测候选目标，估计其在世界坐标系中的位置，并生成由 Nav2 导航栈执行的导航目标。在基于 Gazebo 的室内环境中，搭载 TurtleBot3 机器人的系统自主探索了房间，检测到五个目标物体中的三个，并成功执行了测试的两条自然语言导航指令，且无需针对特定任务进行训练。结果表明，开放词汇接地模型能够集成到经典导航技术流程中，但其性能受检测不确定性、基于深度的定位误差以及探索覆盖不完整等因素限制。这些发现既凸显了采用轻量级纯 CPU 架构部署视觉—语言接地导航系统的可行性，也揭示了其当前局限。

## Abstract
Language-guided navigation enables mobile robots to interpret natural language commands and navigate toward user-specified targets in unstructured environments. However, integrating open-vocabulary visual perception with classical robotics pipelines for mapping and navigation remains a challenging problem. In this work, we present a complete ROS2-based system that combines frontier-based exploration, open-vocabulary object detection using Grounding DINO, depth-based 3D localization, and semantic mapping to enable end-to-end vision-language grounded navigation in simulation. The system accepts natural language commands such as ``go to the yellow box,'' detects candidate objects from RGB images using text prompts, estimates their positions in the world frame, and generates navigation goals executed by the Nav2 stack. In a Gazebo-based indoor environment with a TurtleBot3 robot, the system autonomously explored the room, detected three of the five target objects, and successfully executed both natural language navigation commands tested, without task-specific training. The results indicate that open-vocabulary grounding models can be integrated into classical navigation pipelines, though performance is limited by detection uncertainty, depth-based localization error, and incomplete exploration coverage. These findings highlight both the feasibility and current limitations of deploying vision-language grounded navigation systems using lightweight, CPU-only architectures.

## 1. 核心问题与整体含义

- **研究问题**：如何让移动机器人理解诸如“去黄色箱子那里”的自然语言指令，并将语言描述对应到视觉中的物体、物体在地图中的位置，以及实际导航目标。
- **研究背景与动机**：传统导航系统主要利用几何地图表示可通行区域和障碍物；语义导航进一步识别物体，但常依赖固定类别和专用训练数据，难以处理新类别或用户临时提出的描述。开放词汇视觉模型能够通过文本提示检测物体，但要将检测结果稳定地接入 SLAM、语义地图和经典路径规划系统，仍有工程与精度上的挑战。
- **论文的整体思路**：不构建端到端导航模型，而是将开放词汇目标检测与经典机器人模块组合成 ROS2 系统：先探索环境并建立语义地图，再解析用户指令、查询地图，并由 Nav2 导航至目标位置。论文重点是验证这种模块化集成在仿真中是否可行，而非提出新的视觉语言模型或导航算法。

## 2. 方法论

### 2.1 系统流程

系统由探索、感知、语义建图和指令导航等模块组成，并通过有限状态机协调：

1. **环境探索**：TurtleBot3 使用 Cartographer 处理激光雷达数据，生成 2D 占据栅格地图；前沿探索模块选择目标点，逐步探索未知区域。
2. **定期物体检测**：机器人每移动约 1.5 米，使用 Grounding DINO 对当前 RGB 图像进行文本提示目标检测。
3. **三维定位**：将检测框与深度图结合，估计物体在世界坐标系中的位置。
4. **语义地图更新**：保存物体标签、三维位置、检测置信度、时间戳和观测次数；对标签相同且距离小于 0.5 米的条目进行合并。
5. **语言指令执行**：通过基于正则表达式的解析器提取动作、颜色、目标类别及空间关系，查询语义地图，并把目标坐标交给 Nav2 执行导航。

### 2.2 前沿探索与失败恢复

- 在占据栅格中，将自由区域与未知区域的边界识别为前沿，并通过连通区域聚类形成候选探索目标；小于 3 个栅格单元的聚类会被过滤。
- 论文比较了四种前沿选择策略：
  - **最近优先**：选择距离机器人最近的前沿。
  - **最大前沿优先**：选择规模最大的前沿。
  - **最远优先**：选择距离最远的前沿。
  - **加权策略**：按前沿规模与距离的比值排序，概念上为  
    \[
    \text{score}_i=\frac{|F_i|}{d(r,c_i)+1},
    \]
    其中 \(|F_i|\) 是前沿簇规模，\(d(r,c_i)\) 是机器人与前沿中心的距离。
- 系统根据连续导航失败次数升级恢复策略：失败增多时切换到最远前沿、清除已访问前沿记录，或重置探索策略。若机器人在 45 秒内移动不足 0.3 米，则触发卡滞检测与恢复。

### 2.3 开放词汇检测与三维定位

- Grounding DINO 使用文本提示检测目标，模型约 2.32 亿参数；检测置信度经过阈值筛选。
- 对每个检测框，在其中央区域提取有效深度的中位数作为目标深度，再用针孔相机模型将像素中心投影到相机坐标系：
  \[
  p_c=\left[\frac{(u-c_x)d}{f_x},\frac{(v-c_y)d}{f_y},d\right]^\top .
  \]
- 随后通过 ROS2 TF 树中的相机到世界变换 \(T_{cw}\)，得到世界坐标：
  \[
  \begin{bmatrix}p_w\\1\end{bmatrix}
  =T_{cw}\begin{bmatrix}p_c\\1\end{bmatrix}.
  \]
  若 TF 查询失败，则使用里程计位姿和固定相机外参作为回退方案。
- 论文指出相机内参存在不一致：仿真相机视场角为 62.2°，而代码采用 69.4° 的默认值，导致焦距估计约有 13% 的差异，可能造成定位误差。
- 作者还实现了标签清理启发式，以处理 Grounding DINO 偶尔将多个提示类别拼接成一个检测标签的问题；但该策略不能完全解决多物体混合标注。

### 2.4 语义地图与命令解析

- 语义地图以轻量级物体条目列表实现，支持模糊子串、精确匹配、最近目标和空间范围查询，并可保存为 JSON。
- 同标签物体若在合并距离阈值内，则用按观测次数加权的运行平均更新位置；置信度取新旧观测中的较大值。
- 命令解析使用规则而非大型语言模型，识别动作动词、颜色属性、目标类别及部分空间关系。解析后将属性与目标类别组合成查询文本，例如“blue box”。

## 3. 实验设计

### 3.1 场景与测试对象

- 实验在 **Gazebo Classic 11 单房间仿真环境**中进行，房间约为 8 米 × 8 米，机器人从原点出发。
- 机器人为 TurtleBot3 Waffle Pi，配备 360° 激光雷达、RGB 相机和深度相机。
- 场景中放置五个不同颜色、形状的几何物体：红色圆柱、蓝色箱子、绿色圆柱、黄色箱子和白色圆柱。
- Cartographer 生成分辨率为 0.05 米的 2D 占据栅格地图，Nav2 执行导航任务。

### 3.2 Benchmark 与对比方法

- 论文没有采用标准公开数据集或正式的通用 benchmark，而是在自建 Gazebo 单房间场景中进行端到端功能验证。
- 前沿探索部分比较了最近、最大、最远和加权四种选择策略，并报告加权策略与失败恢复机制的运行表现。
- **没有报告与其他完整语义导航系统或开放词汇导航基线的定量对比**，也没有将系统与 GPU 版本、替代检测器或不同定位方案进行系统比较。

### 3.3 主要结果

- 一次代表性探索运行约持续 8 分钟，发送 16 个导航目标，其中 12 个成功、4 个失败，报告的目标成功率为 75%。
- 房间最终覆盖约 60%，仍存在未探索区域。
- 语义地图记录 21 条检测条目；按类别统计，正确检测到五个目标中的三个：黄色箱子、红色圆柱和绿色圆柱。蓝色箱子未被检测到；白色圆柱对应的记录是误检。
- 目标定位误差约为 0.3–2.4 米：黄色箱子和绿色圆柱估计较接近真实位置，红色圆柱的位置偏差较大。
- 测试了两条自然语言指令：“去黄色箱子那里”和“去红色圆柱那里”，两条命令都成功使 Nav2 到达语义地图中记录的位置。需要注意，Nav2 报告到达的是**存储的位置**，并不等于抵达真实物体；红色圆柱的地图位置与真实位置相差约 2.4 米。

## 6. 主要结论与发现

- 开放词汇目标检测可以接入传统 ROS2 导航流程，形成从探索、检测、语义建图到语言指令导航的完整系统。
- 在本实验环境中，系统能够在纯 CPU 条件下自主探索、检测部分目标，并执行简单自然语言导航命令，无需任务专属训练。
- 加权前沿选择与失败恢复策略在该次运行中改善了探索过程，缓解了机器人反复选择近距离目标或陷入困难区域的问题。
- 当前系统的主要瓶颈不是单一的导航规划，而是感知与空间定位链条中的不确定性，以及探索没有覆盖全部环境。

## 7. 优点

- **系统集成完整**：将开放词汇检测、深度定位、语义地图、命令解析和 Nav2 连接起来，展示了端到端流程。
- **模块化且易部署**：基于常见 ROS2 组件和轻量级语义地图，避开了大型语言模型的运行时依赖与外部 API。
- **强调可复现实现**：论文说明了系统环境、关键阈值、状态机、消息交互和地图数据结构，并提供公开代码仓库信息。
- **考虑运行故障**：加入连续失败升级和卡滞检测，而非只报告理想条件下的导航流程。
- **如实呈现局限**：明确披露单次运行、定位误差、漏检、误检、标签拼接和覆盖不完整等问题，避免将“到达地图点”混同于“到达真实物体”。

## 8. 不足与局限

- **实验规模小且场景单一**：仅有单房间、单次代表性探索和两条命令，缺少多场景、多轮次和统计评估；对复杂环境的泛化能力未知。
- **目标定位误差可能破坏任务成功判定**：部分物体位置偏差较大，Nav2 到达地图坐标并不能证明机器人到达实际目标。
- **检测输出不稳定**：多物体标签拼接影响类别归属、定位和重复目标合并；标签清理启发式只提供部分修补。
- **探索覆盖不足**：约 60% 的房间区域被覆盖，至少一个目标因轨迹未覆盖而漏检，另有白色物体受低对比度等因素影响。
- **传感器模型存在已知不匹配**：相机视场角与代码中的焦距参数不一致，可能系统性影响三维坐标估计。
- **指令理解能力有限**：正则解析主要面向预先设定的颜色、形状和动作表达，尚不足以处理丰富的同义表达、复杂组合指令或稳健的空间关系推理。
- **实时性和部署证据有限**：CPU 检测延迟为每张图像 5–10 秒，不适合高频实时感知；论文未提供真实机器人测试或完整硬件配置。
- **基线与消融不足**：缺少与其他语义导航系统的直接比较，也未通过消融实验量化各模块的贡献，因此结论更适合作为可行性展示，而非性能优越性证明。
