Abstract 

When a vision-and-language navigation policy generates an action sequence autoregressively, the robot waits for a chain of dependent predictions. A small discrete action vo-cabulary makes it possible to score all short-horizon plans in parallel. We introduce VLN-Flash, a training-free de-coder that evaluates the complete action-prefix tree in a sin-gle forward pass. Branch-specific attention and matched token positions preserve the original policy’s conditional action distribution for each prefix in exact arithmetic. We use the score margin between the stepwise-greedy prefix and its strongest alternative at each depth to decide how many actions to execute. The robot then executes the plan with the highest joint score at the chosen depth before observing again. On matched inputs, VLN-Flash achieves a nearly 

3× speedup in action decoding over native autoregression on Uni-NaVid and StreamVLN. Compared with the native autoregressive decoders, it improves success rate and suc-cess weighted by path length (SPL) on R2R-CE and RxR-CE, with success gains up to 2.7 percentage points. On a Unitree GO2, VLN-Flash improves navigation success and cuts the mean wait between actions by about 160 ms after subtracting network transmission time. 

1. Introduction 

Vision-and-language navigation (VLN) requires an agent to follow an instruction through an unseen environment using first-person observations. Recent policies fine-tune video-based large language models to emit low-level actions as tokens [23, 29], improving performance on R2R-CE and RxR-CE [1, 6, 7]. In autoregressive decoding, each pre-dicted action becomes part of the input for the next pre-diction. The robot waits for these successive model calls before it can execute the plan. That delay recurs each time the robot uses a new observation to plan its next actions. Uni-NaVid and StreamVLN predict up to four actions per decision. Uni-NaVid executes at most two [29], while StreamVLN executes the full prediction [23]. In both poli-cies, the execution limit is set in advance, regardless of how strongly the policy favors a particular plan given the current observations. This motivates using the policy’s predictions to decide how much of a plan to execute before observing again. The small navigation action space lets us enumerate all prefixes needed to score short plans. We introduce VLN-Flash (Figure 1), a training-free decoder that packs these prefixes into a tree and scores them together in one for-ward pass through the navigation policy. Tree attention lets branches share the observed context while keeping each candidate’s own action history. Matching the visible history and position indices to autoregressive decoding preserves the corresponding conditional distributions in exact arith-metic. The original language-model head reads out the ac-tion distribution for every branch. Scoring the whole tree lets the robot choose how many actions to execute at each decision. Execution length de-termines when new observations can influence the policy. Longer blocks reduce the number of decisions along a route, while shorter blocks allow earlier replanning with fresh vi-sual feedback. Since the tree already scores all depths, se-lecting a shorter execution prefix requires no additional pre-diction pass. VLN-Flash uses these readouts for joint-probability plan selection and margin-based adaptive execution. Joint prob-abilities rank candidate action sequences using the policy’s conditional predictions. To determine the execution length, we scan the score margin between the fixed stepwise-greedy branch and its strongest alternative from shallow to deep. The scan stops when the greedy branch’s lead falls below a 1arXiv:2611.19287v1 [cs.RO] 14 Nov 2026 threshold, or when that branch ends. At the selected depth, the agent executes the highest-scoring branch and then ob-serves again. The same tree scores thus determine both which plan to execute and how long to follow it. We measure decoding on identical inputs and ablate plan selection and adaptive execution. On Uni-NaVid and StreamVLN, VLN-Flash accelerates action decoding by nearly 3× over native autoregressive decoding and im-proves success rate (SR) and success weighted by path length (SPL) on both R2R-CE and RxR-CE, with SR gains up to 2.7 percentage points. On a Unitree GO2, the same StreamVLN policy completes 52 of 60 instructions with VLN-Flash versus 49 with autoregressive decoding. Our main contributions are as follows. 1. One-pass action-tree decoding. VLN-Flash scores all short-horizon action prefixes in a single forward pass without retraining, preserving autoregressive conditional distributions in exact arithmetic. 2. Shared scores for planning and execution. Joint prob-abilities rank candidate plans, and score margins de-termine how many actions to execute before observing again. 3. Faster decoding and better navigation. VLN-Flash decodes actions nearly 3× faster, improves SR and SPL on both benchmarks, and reduces action waiting time on a Unitree GO2. 

2. Related Work 

Efficient vision-and-language navigation. Early VLN benchmarks let agents select reachable viewpoints on pre-defined navigation graphs [1, 7]. VLN-CE replaces graph transitions with low-level actions in continuous 3D envi-ronments [6]. In this setting, NaVid predicts the next ac-tion from egocentric video [28], while Uni-NaVid predicts a short action sequence [29]. Other policies use different action representations. NaVILA issues mid-level language commands for a locomotion controller [3], and OmniNav predicts continuous waypoints [25]. JanusVLN stores vi-sual semantics and spatial geometry in separate compact memories [26]. StreamVLN combines SlowFast context modeling with cross-decision KV reuse [23], and Efficient-VLN processes new frames incrementally using cache reuse and contiguous rotary positions [31]. MemVLN com-bines pyramidal visual memory with a learned vocabulary of single-token mid-level actions [13]. LiveVLN reduces robot waiting by overlapping observation processing with action execution [22]. We focus on speeding up plan gener-ation once the observation history is available. 

Parallel decoding for language and actions. Specula-tive decoding verifies proposals from a smaller model [8]. Draft & Verify drafts by skipping layers [27], while Prompt Lookup retrieves candidate continuations from the input [17]. Jacobi decoding updates token guesses by fixed-point iteration [16]; Lookahead uses these updates to build and verify candidate continuations [4]. SpecInfer and Medusa verify branches with tree attention [2, 14], and EAGLE-2 uses draft confidence to build the tree [9]. Parallel decoding has also been studied for robot ac-tions. PD-VLA reformulates autoregressive action decod-ing as a nonlinear system solved by parallel fixed-point it-erations [19]. Spec-VLA adapts draft-and-verify decoding to action tokens with a relaxed acceptance criterion [21]. OFT combines parallel decoding, action chunking, and continuous-action regression in a fine-tuning recipe [5], while Discrete Diffusion VLA generates discrete action chunks through iterative refinement [12]. For short navi-gation plans, the small action set lets us enumerate valid prefixes directly and score the complete tree in one pass. We use the resulting joint scores to select a plan and decide when to observe again. 

Adaptive action execution. Adaptive chunk execution de-termines how many predicted actions to apply before incor-porating new observations. AAC estimates action entropy from sampled chunks to select the execution length at infer-ence time [11]. Attention-based methods derive execution horizons from the policy’s internal structure. AutoHorizon uses action self-attention [20], while cross-attention dynam-ics provide a truncation signal when action predictions lose grounding in the current observation [24]. Other approaches use the predicted motion or its consequences. PACE identi-fies low-speed transitions in the predicted chunk as replan-ning boundaries [15]; CA 3C uses a world model to compare the imagined consequences of candidate chunks and com-mits while those futures agree [10]. In reinforcement learn-ing, ACH learns action values for multiple chunk lengths and selects the horizon according to the current state [18]. We derive execution depth from the joint-score margin be-tween navigation branches, reusing the scores produced by parallel action decoding. 

3. Method 

Given the policy input x, VLN-Flash computes the condi-tional action distributions needed to score all valid plans of up to K actions in one masked forward pass. These distribu-tions support joint-probability plan selection (Section 3.3) and adaptive execution (Section 3.4). Figure 1 shows how the tree is packed, masked, and read out.

3.2. Parallel action decoding 

Autoregressive decoding follows one action prefix at a time. Given a candidate prefix s, a causal forward on (x, s ) gives the distribution of the next action at its last position. VLN-Flash constructs the candidate prefixes in advance and packs them into one sequence. A tree mask then gives each read-out the same context as its separate causal forward (Fig-ure 1).

Navigation baselines. Reproduced uses each backbone’s released autoregressive decoding configuration. Metrics. Success rate (SR) is the fraction of episodes in which the agent stops within 3 m of the goal. SPL weights each success by the shortest-path length divided by the larger of the shortest-path and traveled lengths. Oracle suc-cess (OS) is the fraction of trajectories that enter the success region at any point, and navigation error (NE) is the final distance to the goal in meters. We report SR, SPL and OS in percent, and decoding latency in milliseconds. 

Implementation details. Each timed run uses one A800-80 GB GPU with batch size one, after warm-up and with CUDA synchronization. For a given input, all decoders run on the same GPU. We retain each backbone’s inference pre-cision, using fp16 for Uni-NaVid and bf16 for StreamVLN.

4.5. Real-world deployment 

We deploy StreamVLN on a Unitree GO2 and compare its native autoregressive decoder with VLN-Flash in separate runs with matched instructions and start poses. An onboard Jetson Orin NX 16 GB captures RGB frames and sends ve-locity and stop commands through ROS2. The navigation policy runs on an A800-80 GB cloud GPU. Following NaVILA [3], we test 20 instructions each in a corridor with indoor and outdoor sections, a classroom, and an office. 

Navigation success. A trial succeeds if the robot stops within 1.5 m of the target. VLN-Flash completes 52 of 60 trials (86.7%), compared with 49 (81.7%) for native autore-gression (Figure 4). Both methods complete all 20 corridor trials. VLN-Flash completes 17 classroom and 15 office tri-als, compared with 16 and 13 for native autoregression.

5. Conclusion 

VLN-Flash speeds up navigation decoding by scoring the full tree of short-horizon action prefixes in one forward pass. The branches share the observation context while retaining their own action histories and the corresponding autoregressive position indices. The resulting scores also guide plan selection and determine how many actions to ex-ecute before observing again. This design speeds up action decoding by nearly 3× over native autoregression on Uni-NaVid and StreamVLN. On a Unitree GO2, the mean wait between actions drops by about 160 ms. C. Decoding latency replay 

C.1. Replay protocol 

For the latency comparison in Table 1, all decoders replay the same frames and observation histories within each back-bone. Each input is run on the same A800-80 GB GPU at batch size one, with two warm-up runs and five timed runs per decoder. GPU synchronization brackets each call. The timer starts with preprocessed images and prompt tokens on the GPU and includes visual encoding and complete reply generation. The full-vocabulary baselines use deterministic generation, so their replies can be compared token by token with native autoregression. 

Uni-NaVid. We replay 48 decisions from eight R2R-CE val-unseen trajectories in fp16. Each decoder processes the full query from the same visual history. The five full-vocabulary comparison decoders match all 240 native replies per method. VLN-Flash averages 3.08 actions per reply with δ = 0 .35 .

StreamVLN. We replay 15 decisions from three trajecto-ries in bf16 with SDPA. All decoders start from the same continuation state. The full-vocabulary baselines use the na-tive repetition penalty of 1.05. VLN-Flash applies the same penalty to actions already present in each candidate prefix before normalization and selects with K = 4 and δ = 0 .Speculative decoding uses TinyLlama-1.1B-Chat-v1.0 for Uni-NaVid and Qwen2-0.5B-Instruct for StreamVLN. The text draft proposes one token per round; the target ver-ifies it with the full visual input. 

C.2. Baseline configurations 

Jacobi initializes its token guesses from the preceding re-ply. Lookahead uses level 4, window 5, and five guesses. Prompt Lookup matches up to two tokens and proposes at most three. Draft & Verify drafts up to three tokens, skip-ping the attention and MLP blocks at layers 2–5, 7–10, 12– 15, 17–20, and 22–25 (zero-based). We choose the settings with the lowest mean latency on six separate StreamVLN inputs and use those settings for Uni-NaVid.
