## 摘要
与人协同工作的机器人应能够在出现新请求时利用此前观察到的信息。同一段经验日后可能用于识别某个物体，或将其送回原来的位置，尽管观察时并不知道这些用途。ReuseMem 学习如何利用一份视觉记忆来支持之后的多个操作目标。它独立于未来目标记录视觉特征，为每项请求检索互补证据，并通过轻量级动作接口将其与当前场景相结合。检索过程由候选证据在不同当前状态下支持专家动作预测的能力进行监督，从而将记忆选择与其在操作中的用途联系起来。重复的视觉特征只存储一次，动作生成过程中保持不变的记忆计算则会被复用。在四项仿真任务和两个真实物理场景上的实验表明，同一份记录可以用于处理不同请求。在动作适配方式一致的条件下，与均匀记忆相比，ReuseMem 在基准任务上的联合目标完成率提高了 24.5 个百分点。这些发现表明，随着场景变化，一份记忆可以支持之后的多个操作目标。

## Abstract
Robots that work alongside people should be able to use what they have seen when new requests arise. The same experience may later support identifying an object or returning it to its original location, although these uses were unknown during observation. ReuseMem learns to use one visual memory for multiple later manipulation goals. It records visual features independently of future goals, retrieves complementary evidence for each request, and combines it with the current scene through a lightweight action interface. Retrieval is supervised by how well candidate evidence supports expert-action prediction across different current states, linking memory selection to its use in manipulation. Repeated visual features are stored once, and memory computations that remain unchanged during action generation are reused. Experiments on four simulation tasks and two physical scenarios demonstrate reuse of a common recording across different requests. With matched action adaptation, ReuseMem improves joint goal completion on the benchmark tasks by 24.5 percentage points over uniform memory. These findings show that one memory can support multiple later manipulation goals as the scene changes.

## 1. 核心问题与整体含义

- **研究问题**：机器人观察一段经历时，通常还不知道未来会收到什么请求；但之后，同一段经历可能被用于不同目的。例如，先前观察到的物品内容可用于识别目标物，记录的原始位置则可用于将物品放回原处。机器人需要在未来目标尚未知晓时保存经验，并在场景变化后按请求调用。
- **研究动机**：已有记忆增强策略可以检索历史信息并用于控制，但在不同任务上分别成功，并不等于它们能让**同一份记录**支持多个不同的后续操作。关键困难是：既要选出适合当前请求的历史证据，也要让策略根据当前场景把这些证据转化为动作。
- **整体含义**：ReuseMem提出一套“先记录、后按目标读取并行动”的方法。它让机器人对同一历史记录进行不同的目标条件检索，并结合当前观察生成动作；同时通过共享重复视觉特征和缓存固定计算来控制存储与推理开销。

## 2. 方法论

### 2.1 整体架构

ReuseMem由三个部分构成：

1. **Writer（写入器）**：在未来目标未知时记录视觉经验，并保留每次观察对应的时间信息。
2. **Reader（读取器）**：收到请求后，从同一历史记忆中检索对该请求有用的互补证据。
3. **动作接口**：把检索结果与当前观察、机器人状态和近期执行历史结合，交给冻结的预训练策略生成动作。

### 2.2 记忆写入与特征共享

- 每帧由冻结视觉编码器产生 \(16\times1024\) 的视觉特征。
- 对相似帧，系统可让多个时间条目引用同一份视觉特征原型；是否共享不仅检查池化特征相似度，还要求逐 token 距离不超过阈值，以避免忽略局部差异。
- **视觉特征共享不等于合并时间记录**：每次观察仍保留独立的帧序号、元数据、有效性和检索键，因而可保留事件顺序。
- 记忆检索键由当前及此前的记录因果地计算；写入阶段不使用未来请求或专家动作。

### 2.3 按请求检索互补证据

- Reader将请求编码为查询，并在历史记录中依次执行：
  - 搜索 **8 个候选锚点**；
  - 选择 **4 个参考观察**；
  - 为每个参考观察选择 **3 个支持观察**；
  - 补充 **8 个均匀覆盖时间线的观察**。
- 检索结果去重并按需要填充为 **24 个历史槽位**。这样既允许集中选择与目标相关的证据，也保留整段记录的时间覆盖。
- 训练时会比较最多 4 种候选检索选择；部署时则按学习到的分数贪心选择。

### 2.4 用专家动作预测学习检索

- 对同一目标，训练数据包含多个不同的当前场景。历史事实相同，但当前物体状态、可用动作和所需操作可能不同。
- 对每种候选记忆选择，使用冻结的策略与固定动作接口快照，计算其在这些当前场景上的专家动作预测损失，并按场景权重汇总。
- **损失较低的候选选择获得较高偏好**；Reader据此更新检索策略。这使检索学习不只依赖“看起来相关”，而是依赖证据能否支持后续动作。
- 更新Reader后，再使用其新的贪心检索结果训练动作接口。离散检索步骤不接收动作损失的梯度。

### 2.5 结合当前场景生成动作与效率设计

- 动作输入包含 **24 个检索历史帧、7 个严格早于当前决策的执行历史帧和当前帧**，共形成 512 个视觉 token。
- 通过宽度为 32 的轻量残差融合模块，利用当前视觉、机器人状态和近期上下文调整历史与近期特征；当前帧 token 则绕过该融合模块。
- 基础策略保持冻结，只训练融合模块和 18 个策略层上的 rank-8 低秩调制参数。
- 在一次动作采样调用中，记忆输入不变，因此每层的记忆键和值只计算一次；去噪过程仍会重新计算动作查询。新观察或新请求到来时，相关计算会刷新。

## 3. 实验设计

### 仿真基准

论文使用四项基于 **RoboMME** 的任务，每项包含 50 段共同记录、每段记录配有两个后续目标：

- **VideoPlaceButton**：根据按钮事件确定事件前后的位置。
- **VideoPlaceOrder**：根据记录中的先后顺序确定目标位置。
- **VideoUnmaskSwap**：在遮挡及交换后识别并揭开指定颜色的物体。
- **PickHighlight**：在短暂视觉提示消失后，操作先后被标记的物体。

总计为 **400 次独立目标执行**，并在 **200 段记录**上评估两个目标的联合成功率和连续执行成功率。All-goal 指两个目标在分别恢复到同一初始后续场景的分支中都成功；Sequence 则要求两个目标不重置场景、连续完成。

### 真实机器人场景

使用 SO101 桌面机器人评估两个场景，每个场景有 20 段记录、三个后续请求：

- **案例准备与归还**：根据记录的内容选择案例转移，并依据原始位置归还。
- **玩具移动、清扫与复原**：根据原始位置选择玩具，清扫其原位置，最后复原玩具。

论文报告独立请求、三个请求全部成功率，以及不重置场景的连续序列成功率。

### 对比方法

- **No-Memory（π0.5）**：只使用当前输入。
- **Uniform-Memory（π0.5）**：从同一记忆库均匀选择 24 个历史观察，并使用匹配的动作适配。
- **MME-VLA（π0.5）**：使用发布的 FrameSamp+Modul 权重，不做本文的重新训练。
- **MemER（RoboMME）**：采用基准复现配置，以记忆图像和 VLM 生成的子目标进行控制。
- 消融实验还比较：不学习检索、单当前状态监督、去除当前场景融合、去除特征共享、去除 KV 缓存，以及使用充分历史证据的诊断控制。

## 6. 主要结论与发现

- 在仿真中，ReuseMem 的独立目标平均成功率为 **74.5%**，All-goal 成功率为 **60.5%**，连续序列成功率为 **58.0%**。
- 与 Uniform-Memory 相比，All-goal 成功率从 **36.0% 提升至 60.5%**，提高 **24.5 个百分点**；连续序列成功率从 35.0% 提升至 58.0%，提高 23 个百分点。
- 去除检索学习后，All-goal 成功率从 60.5% 降至 **36.5%**；只用单个当前状态监督时为 53.0%；去除当前融合时为 55.5%，且连续序列成功率降至 47.0%。这表明检索学习与当前场景融合都对复用有贡献。
- ReuseMem 的证据覆盖率为 **90.0%**，高于 Uniform-Memory 的 80.5%。移除相关历史证据或替换为不匹配的记录，会显著降低成功率，说明策略确实依赖历史信息。
- 在两个真实场景中，ReuseMem 每个场景均有 **14/20** 段记录的三个独立目标全部成功，并在每个场景中完成 **13/20** 个连续序列。
- 总体上，论文支持这样的结论：对同一段目标无关的视觉记录进行目标条件检索，并把证据与当前场景结合，能够比均匀读取历史更有效地支持多种后续操作。

## 7. 优点

- **研究问题贴近真实协作**：明确研究“观察时不知道未来目标，但未来要复用同一经历”的情形，而非只在不同任务间使用不同记忆。
- **检索与动作目标直接关联**：用专家动作预测损失评价候选证据，在多个当前状态上比较其效用，使记忆选择面向操作结果。
- **区分历史事实与当前状态**：历史用于提供身份、顺序、原始位置等信息；当前观察用于确定物体现在在哪里、如何抓取，架构上明确处理两者差异。
- **评估维度较完整**：同时考察单目标、多个目标联合成功、连续执行、证据覆盖、干预、时延和存储。
- **效率设计有明确测量**：特征共享减少保留存储，KV 缓存降低持续请求的响应时间；并报告了对应的消融与数据。
- **内部基线较可比**：核心方法与均匀记忆等对比共享策略适配设置和历史槽位预算，较有助于判断“学习检索”的作用。

## 8. 不足与局限

- **真实世界规模有限**：两个桌面场景各 20 段测试记录，尚不足以证明方法在更复杂环境、更多物体类别或更长任务链上的泛化能力。
- **任务与记忆范围受限**：实验主要针对明确设计的事件线索、顺序、遮挡身份和短暂视觉提示；Writer 的容量上限为 2,048 条记录，检索和动作输入预算也固定，长时开放环境中的表现尚未验证。
- **依赖视觉对应与精细操作**：作者明确指出视觉对应、精确操控仍是限制；遮挡后身份交换任务也是仿真中最困难的一项，ReuseMem 的 All-goal 成功率为 30%。
- **训练成本信息不完整**：未报告训练使用的 GPU 数量、训练时长和总算力；部署时延虽有测量，但不能替代训练资源报告。
