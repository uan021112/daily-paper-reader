Recent embodied agents construct and adapt robot behavior through executable programs, tool
use, and interaction feedback. Studying these systems in mobile manipulation calls for physical
worlds that connect agent-directed execution with its physical consequences and reusable interaction
experience. We introduce γ-Scape, an agent-centric simulation and benchmark platform for mobile
embodied intelligence. Agents compose motion tools and learned skills to carry out complete tasks that
combine navigation and manipulation in a persistent physical world. BenchForge grounds structured
objectives in physical task instances with instructions, reference programs, and goal evaluators,
defining task goals while preserving agents’ choice of valid solutions. An agentic collection harness
further enables agents to produce demonstrations by carrying out contact-rich interactions through
sustained control and physical feedback. Assisted reference execution and human guidance provide
complementary experience. The resulting tool traces and aligned observation–action records support
program refinement and policy learning, with common task-goal criteria for subsequent evaluation.
We benchmark representative agent systems on complete tasks and demonstrate contact collection
and trace-informed program revision. Together, these workflows provide infrastructure for research on
embodied recursive self-improvement.

Introduction
Recent advances in embodied agents have broadened how robot behavior is constructed and adapted. Agents
generate executable programs over perception and control interfaces (Liang et al., 2023; Fu et al., 2026), use
execution feedback to revise programs and retain reusable skills (Lu et al., 2026; Huang et al., 2026b), and
combine learned action skills with analytic motion tools (Zhang et al., 2026e). Mobile agents use multimodal
observations and action interfaces to pursue goals across multiple locations (Chen et al., 2025).
In mobile manipulation, each action changes the conditions for the next. Opening a cabinet changes access,
grasping occupies a hand, and transport changes the conditions for placement. To retrieve supplies from
storage and deliver them elsewhere, an agent must coordinate these interactions and respond to their measured
outcomes. Existing activity benchmarks and generative environments provide valuable tasks and demonstration
resources (Li et al., 2023; Dai et al., 2026; Nasiriany et al., 2026). We ask how a physical world can support
complete-task evaluation while retaining the interaction context needed to construct and revise behavior.
We introduce γ-Scape, an agent-centric simulation and benchmark platform for complete mobile manipulation
tasks (figure 1). The platform combines 370 indoor scenes with 11,073 interactive object assets for task
construction. Task agents compose their own programs and tool calls, combining motion tools and learned
skills according to the states reached during execution. BenchForge turns structured task requirements into

conditions. This separation lets researchers compare agent-chosen solutions under a fixed task definition and
retain the same goals when revising behavior. Different embodiments and shared-space participants provide
additional physical contexts for studying these behaviors.
γ-Scape also supports agents as producers of experience for behavior development. In this complementary
workflow, native planning handles routine motion while a dedicated collection agent uses privileged physical
feedback to control contact interactions. It retains control through extraction, release, and withdrawal
before task execution resumes from the measured state. Each interaction yields both tool traces for program
refinement and aligned robot observations and actions for skill adaptation. Assisted reference execution and
human guidance provide complementary demonstrations with explicit control-source and assistance labels.
The execution interfaces accept revised programs and learned skills for further runs under unchanged task
goals, providing infrastructure for research on embodied recursive self-improvement.
We construct a fixed benchmark of 22 task families and 220 task instances spanning delivery, organization,
storage and access, preparation and restoration, and carrying and coordination. We compare representative
agent systems as integrated into the platform, using common physical instances and task-goal criteria while
retaining each system’s reasoning and execution interfaces. Complete-task success measures the requested
outcome, while semantic progress records accumulated intermediate accomplishment. Our experiments connect
these results to execution traces and show how a failed contact interaction informs an executed program
revision. Our contributions are threefold:
• Aworldforagent-directedmobilemanipulation. We combine task-driven physical construction with composable
execution interfaces, allowing agents to pursue explicit goals through programs, motion tools, and learned
skills grounded in measured physical outcomes.
• Experience production for behavior development. We provide sustained agentic contact collection within
complete tasks, alongside assisted and human-guided experience. We demonstrate contact collection and
trace-informed program revision, retaining tool feedback and temporally aligned observation–action records
for further adaptation.
• A benchmark of complete embodied agent systems. We construct a 22-family, 220-instance suite and examine
representative systems through complete-task success, semantic progress, and physical execution analysis.

Related Work
Embodied agents and behavior construction.
Embodied agents use executable programs, tools, and interaction
feedback to organize robot behavior. Code as Policies (Liang et al., 2023) represents behavior through programs
over perception and control interfaces, while CaP-X (Fu et al., 2026) studies coding agents through interface
abstractions and execution feedback. ASPIRE (Lu et al., 2026) and RAX (Huang et al., 2026b) develop
reusable behavior through program refinement and online exploration, respectively. Harness VLA (Zhang
et al., 2026e) combines a frozen vision-language-action model with analytic primitives and execution memory.
Mobile systems such as HomeRobot (Yenamandra et al., 2023), BUMBLE (Shah et al., 2025), and OWMM-
Agent (Chen et al., 2025) integrate perception, reasoning, and action interfaces for tasks spanning multiple
locations. Vision-and-language navigation (VLN) studies instruction following in visual environments, spanning
individual navigation and multi-robot coordination (Zhang et al., 2024, 2025a; Deng et al., 2026; Wang et al.,
2026b; Zhou et al., 2026; Huang et al., 2025; Zhang et al., 2026a,b; Su et al., 2026; Zhang et al., 2026c,d).
For learned navigation, WNM-3D (Huang et al., 2026c) conditions joint future-view and navigation-action
generation on 3D scene representations. γ-Scape complements these architectures with grounded tasks and a
runtime for executing agent-chosen behavior under common goal criteria.
Interactive worlds and embodied benchmarks.
ALFRED (Shridhar et al., 2020), Habitat 2.0 (Szot et al.,
2021), and BEHAVIOR-1K (Li et al., 2023) provide settings for instruction following, rearrangement, and
everyday physical activities. For navigation, GN0 (Li et al., 2026) connects data generation and policy learning
with GN-Bench, a 3D Gaussian Splatting-based simulator and benchmark supporting closed-loop evaluation
and dynamic human actors. EMMOE (Li et al., 2025) focuses on mobile manipulation in open environments,
while VLABench (Zhang et al., 2025b) studies language-conditioned manipulation with long-horizon reasoning.
RoboCasa365 (Nasiriany et al., 2026) combines household mobile manipulation with demonstration data and
policy evaluation, and LocoManiLab (Wang et al., 2026a) brings together humanoid tasks, data, policies,
controllers, and deployment. We focus on complete-task behavior: agents select and compose operations while
their physical effects persist across navigation, object handling, and fixture use.
Task generation and experience production.
ManiTaskGen (Dai et al., 2026) generates feasible mobile
manipulation tasks for both evaluation and agent improvement. RoboTwin (Mu et al., 2025) and RoboTwin
2.0 (Chen et al., 2026) connect simulated execution to demonstration synthesis; RoboTwin 2.0 further uses
language models and simulation feedback to refine expert programs. TEACh (Padmakumar et al., 2022)
studies task-driven embodied interaction with a human partner, while EmbodiedCLBench (Huang et al.,
2026a) examines how accumulated experience transfers to new tasks.
γ-Scape couples task generation
with agent-directed execution and dedicated contact collection in a shared physical runtime. The resulting
records preserve task context, tool feedback, and observation–action pairs for subsequent program and skill
development.
3
Method
γ-Scape connects task construction, execution, and experience production through a common task definition.
BenchForge grounds the physical instance and goal conditions; the runtime supports independent task-agent
execution and reference-guided collection, retaining measured outcomes within the enclosing task.
3.1
Simulation Environment
γ-Scape provides indoor environments that combine travel between interaction sites with object handling and
fixture operation. Scenes contain navigable floor space, furniture, movable objects, and articulated fixtures.
Meshes or Gaussian representations (Kerbl et al., 2023) provide visual context; collision geometry, rigid bodies,
and articulated assets enable physical interaction in an Isaac-based backend (NVIDIA, 2025b,a). A task can
reuse suitable scene-native objects or insert selected assets, allowing its source, destination, and intervening
interactions to be instantiated within one environment.

3.2
Agent Execution
For public task execution, agent-facing integrations expose observations, perception calls, motion tools, and
learned skills while retaining each system’s reasoning and memory mechanisms (Liang et al., 2023; Fu et al.,
2026). The agent organizes its own task solution through these interfaces. A common runtime operates at
robot-action boundaries while allowing agent-specific high-level tools. A generated program can sequence
and branch over tool calls; a learned skill can supply an action chunk within that program or act as a direct
policy. Motion tools, including those built on cuRobo (Sundaralingam et al., 2023), translate spatial goals
into trajectories, and embodiment adapters convert trajectory samples or policy outputs into the robot’s
control commands. These execution forms share the loaded task and physical state.
Each command advances physics and updates task monitors from measured samples, possibly over multiple
control steps. Tools return observations, execution status, and terminal results; subsequent commands continue
from the state actually reached.

The simulation clock also governs shared-space participants. In step-driven execution, physics pauses during
model inference and advances with actions; during real-time teleoperation, physics advances continuously.
A human actor’s route, speed, and departure time determine its root transform at the current simulation
time. That transform drives both appearance and a kinematic collision volume; the actor remains at the route
endpoint after arrival. Task construction checks the actor’s final occupancy against required access while
permitting temporary obstruction along its route. Multi-robot variants assign acquisition-to-release chains to
individual robots, add their connecting navigation, and retain cross-robot prerequisites and shared-resource
ordering.
3.3
Task Generation
Task specification and construction variables.
BenchForge constructs tasks from an author-defined catalog of
parameterized task-family templates (Fig. 2a). Templates specify object and workspace roles, conditional
phases and dependencies, allowed variants, and requested final-state and process conditions. Instantiation
activates the selected phases and expands repeated operations into a structured specification Γ = (D, R, Φ),
where D = (V, E) is the operation graph, R contains object and workspace roles, and Φ specifies initial
relations, final goals, and required processes. Nodes in D represent navigation, acquisition, placement, fixture
actuation, or handover; edges encode prerequisites. Given scene and asset resources E and robot embodiment
b, a construction candidate is x = (β, z, q): β binds roles to concrete resources, z contains initial layouts and
reference object or fixture configurations, and q contains robot approaches and local interaction configurations.
For storage deposit, the roles identify an object, a source support, and a receiving compartment; opening
and closing phases follow the requested fixture conditions. Physical grounding resolves these configurations
and the navigation connections between interaction sites. The operation graph organizes construction and
reference execution; the evaluated agent determines its own behavior.

3.4
Experience-Driven Adaptation
Experience for program and skill development comes from public agent execution and dedicated collection
workflows. During agentic collection, the scheduler follows the task’s reference structure through navigation
and transport, then supplies a contact objective and privileged physical context to the collection agent (Fig. 2c).
With manipulation assistance disabled, the collection agent uses object and fixture geometry, receiving regions,
and measured feedback to choose and revise robot-motion calls. For example, an articulation-aware sweep
uses the fixture’s live joint geometry to guide wrist motion and returns the observed articulation and contact
state. Control remains with the agent through extraction or release and withdrawal, capturing the state left
for subsequent task actions. The scheduler resumes from the measured state once the operation’s endpoint
conditions hold; auxiliary interactions retain the parent objective. Task success and collection completion are
recorded separately; Appendix B.2 specifies return conditions and deferred success termination.
Public execution supplies the observations and feedback exposed by each integration. For program refinement,
collection traces retain task context, ordered tool calls, arguments, returned feedback, and measured outcomes.
For skill adaptation, each executed action is paired with its pre-action observations; operation and segment
boundaries preserve the scope of the recorded behavior. Assisted execution by the reference executor (Oracle)
and immersive human teleoperation contribute complementary demonstrations of complete tasks or focused
interactions.
Control-source and assistance labels identify how each behavior was produced and guide
experience selection. Recording, temporal alignment, and export selection are specified in Appendix D.
Integrated agent methods determine how execution feedback and tool traces inform program refinement.
Demonstration export and environment adapters connect learning systems such as LeRobot (Cadène et al.,
2026) and RLinf (Zang et al., 2026) to recorded observation–action samples and further interaction. Revised
programs run through the program interface, while learned policies use observation and action adapters to act
directly or as skills invoked by a program. Subsequent runs are assessed against unchanged task-goal criteria.
Sections 4.3–4.4 demonstrate contact collection and an executed program revision informed by retained
experience. These interfaces provide infrastructure for studying experience-driven embodied development and
recursive self-improvement.

5
Conclusion
We introduced γ-Scape, an agent-centric simulation and benchmark platform for mobile embodied intelligence.
The platform connects grounded task construction, agent-directed execution, and reusable experience within
persistent physical worlds. BenchForge compiles task objectives into physical instances and explicit goal
criteria. Shared interfaces let agents compose programs, motion tools, and learned skills, with different
solutions evaluated against the same task-goal criteria.
The benchmark results show that broad task-family coverage can coexist with low instance-level completion.
Carrying and coordination remain particularly challenging across the evaluated systems, while recorded
episodes reveal how contact quality, reachability, and base stability affect subsequent actions. Complete-task
success and accumulated semantic progress distinguish satisfaction of task conditions from intermediate
accomplishments, supporting analysis of both completed tasks and partial execution.
The collection studies connect local contact outcomes with subsequent transport and placement, and show how
a retained failure record can inform an executable program revision. Tool traces support program refinement,
while aligned observation–action records from agentic, assisted, and human-guided execution provide material
for skill adaptation. Together, these capabilities connect behavior construction with experience reuse under
common task goals. They provide infrastructure for studying repeated adaptation and embodied recursive
self-improvement.

A
Simulation Environment and Shared-Space Interaction
A.1
Scene Representation and Runtime
Scene loaders support InteriorGS and VLNVerse visual assets together with occupancy maps and physical
representations. Task roles identify bodies, supports, cavities, links, joints, and handles. Geometry queries
use current object or link frames, so a drawer’s receiving region follows its motion. Embodiment adapters
define camera placement, action channels, units, frames, rates, and command decoding.
The runtime uses Isaac Sim 5.1.0 (NVIDIA, 2025b), Isaac Lab 2.3.0 (NVIDIA, 2025a), and Python 3.11 on
Linux. R1 uses 120 Hz physics and 30 Hz control, with four physics substeps per action. Goal monitors are
updated from physical samples at each substep; navigation arrival and termination use the latest measurements
at action boundaries. Each observation includes its episode step and simulation time. Cameras capture at
30 Hz or on request; timestamps distinguish fresh from retained frames. Explicit sensor refresh preserves the
current simulation time and physical state. Step-driven execution pauses physics between actions, including
during model inference and rendering outside an action; during real-time teleoperation, physics advances
continuously.
Resources and reproduction inputs.
We provide a reproducible evaluation package for the fixed 220-instance
suite, including the simulator and BenchForge code, task templates, fixed-suite definitions, compiled task
packages, evaluators, and baseline adapters. Each fixed package contains its instruction, reset state and
seed, reference program, and scoring conditions; the suite index maps task IDs to package locations. The
accompanying resource documentation and setup instructions identify the required scene and asset dependencies,
explain how to obtain them from their source collections, and specify their resource mounts. These dependencies
follow the access and licensing terms of their source collections. Interactive assets include resources from
RoboCasa (Nasiriany et al., 2024) and SAPIEN’s PartNet-Mobility collection (Xiang et al., 2020; Mo et al.,
2019; Chang et al., 2015). With the resources mounted, evaluation loads the frozen packages to reproduce the
specified instances.

B
Agentic Contact Collection
B.1
Contact-Collection Interface
Collection agent.
The collection cases in Secs. 4.3–4.4 use the system-installed Codex CLI with GPT-6-Astra
at high reasoning effort, independently of the four benchmark baselines. The harness starts one Codex
process with the task instruction, compiled contact objectives, robot description, and tool definitions. Codex
receives the privileged context in Table 3, inspects images and measured contacts, writes numerical helpers,
and invokes the existing motion and gripper tools. Native scheduling handles travel between interactions;
Codex retains one conversation across the task’s contact operations. These trials allow up to 200 episode-tool
requests and impose no additional collection wall-time limit; physics pauses during reasoning. An operator
launches each trial and supplies its initial brief. Within the rollout, Codex selects and executes the contact
adjustments without manual robot control. A new RESET starts a new agent workspace and conversation;
prior experience is supplied explicitly, as in Sec. D.1. The initial prompt, tool requests and replies, generated
helpers, action records, and camera streams are retained.

B.2
Operation Lifecycle and Session Completion
For acquisition, a contact operation continues through lifting the object and leaving the source; for placement,
it continues through release and withdrawal. Fixture interaction covers the requested articulation, and transfer
covers the corresponding multi-hand goal. The agent can request supporting operations while the runtime
retains the parent objective and its monitoring. When the scheduler accepts the return from a supporting
operation, it resumes the parent operation; task credit remains unchanged. It advances beyond the top-level
operation only after the original physical endpoint predicates are satisfied, continuing from the measured
state.

task success, while collection completion indicates that all scheduled operations have returned and all child

E.2
Termination, Budget Clocks, and Scoring
The standard environment evaluates physical samples during each action and determines termination at the
action boundary. Automatic success and irrecoverable-failure termination are enabled by default; final scoring
uses the latest measured outcome and retained process and endpoint history. Contact collection uses the
deferred-success procedure in Sec. B.2.
The final evaluator state and accumulated endpoint credit are frozen when the episode ends. Runner-side
stop reasons are retained separately from the environment’s terminal reason.
Automatic success. At the action boundary, current success satisfies the configured consecutive-success
count and success termination is enabled. Default count: one action. Valid success; accumulated
semantic progress is retained.
Agent / runner finish. Return an already finalized report unchanged. If the episode is still running without
qualifying success, close it as a policy stop. In explicitly deferred mode, current stable success can
be finalized. Success only if finalized from current evaluator success; otherwise valid failure with
accumulated progress.
Irrecoverable task violation. An explicitly monitored irreversible condition fails and failure termination
is enabled. This takes precedence over success. Valid failure with accumulated semantic progress.
Simulation-time or action limit. At the action boundary, apply the enabled limit. Qualifying current
success takes precedence over a limit reached on that same boundary; otherwise truncate. Success if
already achieved under that precedence; otherwise valid failure with accumulated progress.
Invalid physical action. A decoded action violates the configured action space or joint limits before
execution. Valid failure with previously accumulated semantic progress.
Explicit disqualification. A configured safety-violation terminal category is invoked. Ordinary incidental
contact alone does not create this category. Disqualified; success is false and progress is zero.

Simulation failure. Physical runtime, observation, or evaluator processing fails. Invalid run; success and
progress are recorded as unavailable.
Model / transport failure. The runner records the service or infrastructure failure and cleans up the
worker. The runner’s error classification determines run validity, independently of any cleanup-generated
stop report.
Physical limits.
Each package specifies a simulation-time limit and may also specify an action-count limit.
The execution profile determines which limits are enabled. These limits count physical execution at the rates
in Sec. A.1, excluding model waiting. The consecutive-success count is separate from the physical settling
window of a placement predicate.

CaP-X and RAX convert B to ⌈30B⌉control actions at 30 Hz, counting simulated execution; model waiting

available package action limit and ⌊30Tmax⌋, where Tmax is the package simulation-time limit. Its attempt
launcher leaves per-attempt wall time uncapped; outer service timeouts remain infrastructure safeguards.
Aggregation.
For each system–task pair, three valid trials are obtained and one result is retained according
to lexicographic order: successful trials rank above unsuccessful trials, and semantic progress breaks ties
among trials with the same success status. Success and semantic progress are aggregated over one retained
result per task. The denominator is 220 task instances overall and ten instances within each family. Overall
success therefore equals the mean of the 22 family rates; group summaries are weighted by instance count.
Task-budget exhaustion and unsatisfied goals are scored as unsuccessful trials. Interruptions that prevent a
valid evaluator result are recorded separately from scored task outcomes and do not count toward the three
trials. Invalid runs are replaced until three valid results are available for every system–task pair. CaP-X’s
launcher resumes unfinished trials after relay outages and permits one retry for designated service faults,
preserving completed outcomes. This recovery rule applies exclusively to infrastructure faults and is separate
from policy repetitions; task failures and budget exhaustion retain their scored outcomes.
Evaluation-time memory.
Each evaluation trial starts from its initial agent context and the same compiled
physical state. Histories, new memory, and program revisions produced during a scored trial remain local to
that trial and are reset between trials. Within-trial reasoning and feedback remain available to the system
throughout that episode. The frozen development-stage skills or exploration artifacts are restored as initial
inputs for each scored trial.
Assistance and action interfaces.
All four baseline integrations use public observations and contact-driven
execution, with virtual grasp and fixture attachments disabled. OWMM-Agent’s prompted vocabulary
comprises tour-frame navigation, point navigation, pick, and place; CaP-X, ASPIRE, and RAX expose
lower-level motion calls that permit agent-written interaction sequences.
