# ABSTRACT 

Moving objects introduce cross-frame inconsistencies that complicate camera es-timation and static geometry recovery in driving scenes. Recent feed-forward Gaussian methods explicitly separate static and dynamic primitives, but often es-timate camera parameters and geometry from shared features that jointly encode both components, leaving static reconstruction susceptible to dynamic interfer-ence. To address this challenge, we propose S2D-Splat , a feed-forward frame-work for static-first Gaussian reconstruction with layer-wise feature guidance .Our framework separates static and dynamic features before camera and geome-try estimation, enabling the static branch to recover camera parameters and static 3D Gaussians with reduced dynamic interference. Intermediate static features are cached at each layer and reused as fixed conditioning at corresponding layers of the dynamic branch. This asymmetric information flow preserves the established static representations while providing stable geometric context for reconstruct-ing dynamic 3D Gaussians. An instance-level motion decoder further queries the fused static and dynamic representations to estimate object trajectories, support-ing motion-aligned Gaussian fusion and temporal interpolation. Experiments on Waymo and zero-shot evaluations on nuScenes and the MM-AU accident dataset demonstrate that S2D-Splat outperforms existing approaches on most evaluated metrics and generalizes to highly dynamic pre-collision driving scenes.

Reconstructing dynamic driving scenes from image sequences provides a geometric basis for au-tonomous driving simulation, accident analysis, and near-miss replay. A useful reconstruction must recover camera motion, preserve the static environment, and represent moving agents coherently in a common 3D space. These requirements become particularly challenging in dense traffic and accident scenarios, where abrupt object motion and changing occlusions disrupt cross-frame corre-spondences. Errors in camera estimation can then distort static geometry and confound object mo-tion, while fragmented dynamic reconstructions compromise the fidelity of scene replay. Reliable reconstruction therefore requires carefully managing the interaction between static scene recovery and dynamic object modeling. Per-scene optimization has enabled high-quality reconstruction through methods such as 3DGS (Kerbl et al., 2023), EmerNeRF (Yang et al., 2024a), and DeformableGS (Yang et al., 2024b). However, substantial scene-specific computation and reliance on camera poses limit their scalability and complicate their application to uncalibrated driving videos. Feed-forward Gaussian methods address the computational burden by directly predicting renderable 3D representations from input images (Charatan et al., 2024; Chen et al., 2024). Approaches such as MVSplat (Chen et al., 2024), NoPoSplat (Ye et al., 2025), and DepthSplat (Xu et al., 2025) primarily target static scenes, leaving moving objects challenging to reconstruct consistently. STORM (Yang et al., 2025) extends feed-forward reconstruction to dynamic driving scenes through motion-based Gaussian aggregation, but requires known camera parameters and operates within short temporal windows. More recent methods, including DGGT (Chen et al., 2026) and StreetForward (Yu et al., 2026b), support reconstruction from unposed images and explicitly distinguish static and dynamic Gaussian primitives. DGGT predicts dynamic masks to partition Gaussian maps, while StreetForward uses motion-aware features to predict velocities and dynamic probabilities for Gaussian separation and temporal aggregation. Despite their dedicated dynamics modules, camera parameters and Gaussian geometry are estimated from backbone features that jointly aggregate static and dynamic image con-tent. Their Gaussian-level decomposition therefore does not explicitly isolate the static features used by these earlier estimation stages. Moving objects can still influence the representations from which camera parameters and static geometry are recovered, even when the resulting Gaussian primitives are subsequently assigned to separate components. This observation points to an asymmetric dependency between static and dynamic reconstruction. Static scene recovery benefits from suppressing interference from moving objects, whereas dynamic reconstruction benefits from the geometric reference provided by the static environment. Early fea-ture separation addresses the first requirement, but effective reconstruction also requires controlled interaction between the separated representations. In particular, static information should remain available to the dynamic branch without allowing dynamic updates to modify the established static representations. This motivates a static-first design that combines feature separation before camera and geometry estimation with directed, layer-wise guidance from static to dynamic features. To this end, we propose S2D-Splat , a feed-forward framework for static-first Gaussian recon-struction of dynamic driving scenes with layer-wise feature guidance . As illustrated in Figure 1, an initial encoder extracts image features, which are partitioned using instance masks obtained with SAM2 (Ravi et al., 2025). A feature separator uses masked attention to restrict interactions from dynamic regions and deformable attention to refine dynamic features and recover static cues from mixed boundary tokens. By separating features before camera estimation and Gaussian reconstruc-tion, the framework reduces dynamic interference during the recovery of static scene structure. The static branch processes the separated features through an alternating-attention backbone (Wang et al., 2026a) to estimate camera parameters and reconstruct static 3D Gaussians. Its intermedi-ate static features are cached at each layer and subsequently reused to guide the dynamic branch. Specifically, at every layer of dynamic reconstruction, static token positions are replaced with the corresponding cached static tokens, while dynamic tokens are updated through attention to the com-bined representation. This mechanism preserves the static representations established at each layer while allowing dynamic features to draw on their geometric context. The recovered camera parame-ters further place static and dynamic Gaussians in a common coordinate system, connecting the two reconstruction branches through a consistent geometric reference. 2To recover object motion, we introduce an instance-level decoder that queries the fused static and dynamic representations. Each query specifies an instance and timestep, enabling selective decod-ing of instance poses. The estimated poses provide shared transformations for aligning an instance’s Gaussians across frames, allowing complementary observations to be fused in a common object reference frame. This supports temporal interpolation and coherent reconstruction of an object’s overall motion under partial observations, extending the static-first geometry framework into a dy-namic scene representation. We train S2D-Splat on the Waymo Open Dataset (Sun et al., 2020) and evaluate its zero-shot gen-eralization on nuScenes (Caesar et al., 2020) and the MM-AU accident dataset (Fang et al., 2024). Experiments demonstrate improved rendering quality and depth accuracy on Waymo, together with strong reconstruction and temporal interpolation performance on nuScenes. Evaluation on MM-AU further examines generalization to pre-collision clips of accident scenarios beyond the training dis-tribution. Ablation studies investigate the effects of static-first decoupling, asymmetric layer-wise feature guidance, and instance-level motion decoding. Our main contributions are: • We introduce a static-first feed-forward Gaussian reconstruction framework that separates static and dynamic features before camera and geometry estimation, reducing dynamic interference during static scene recovery. • We propose asymmetric layer-wise feature guidance that reuses cached static features as fixed conditioning for the dynamic branch, preserving the established static representations while providing geometric context for dynamic reconstruction. • We develop an instance-level motion decoder that queries the fused scene representation to estimate object poses, enabling motion-aligned Gaussian fusion across frames and temporal interpolation. • We demonstrate the effectiveness of S2D-Splat on Waymo and its zero-shot generaliza-tion to nuScenes and MM-AU, covering both conventional driving scenes and pre-collision accident clips. 

# 2 RELATED WORK 

Feed-forward Geometry and Gaussian Reconstruction. Neural 3D scene representations sup-port diverse robotic tasks (Deng et al., 2025a); Gaussian representations further enable large-scale SLAM (Deng et al., 2025b) and driving world models (Deng et al., 2026a;b). NeRF-based methods (Deng et al., 2026c; Yang et al., 2024a) and Gaussian-based driving reconstruction ap-proaches (Zhou et al., 2024; Yan et al., 2024) achieve high visual fidelity through per-scene opti-mization, but incur substantial per-scene computation. Feed-forward methods instead learn trans-ferable reconstruction priors across scenes. DUSt3R and VGGT establish generalizable geometric representations (Wang et al., 2024; 2025a), while VGGT-Ω improves reconstruction across static and dynamic scenes through scaled training (Wang et al., 2026a). Driving-specific models further incorporate sensor configurations and scene priors (Jia et al., 2025; Zuo et al., 2026a;b). In parallel, generalizable Gaussian methods directly predict renderable primitives from one or a few images (Xu et al., 2025; Ye et al., 2025; Zhang et al., 2025; Jiang et al., 2025; Zhang et al., 2024; Szymanowicz et al., 2025). For driving scenes, limited camera overlap and incomplete visibility motivate joint depth–pose learning (Tian et al., 2025), complementary pixel–volume representations (Wei et al., 2025), and volumetric fusion (Miao et al., 2025). Sparse LiDAR observations (Song et al., 2025) and pretrained geometry models (Lin et al., 2025; 2026) provide additional geometric constraints. 

Static–Dynamic Separation and Feature Guidance. Existing methods address static–dynamic interaction at different stages of reconstruction. DrivingRecon (Lu et al., 2026) separates static and dynamic rendering supervision to exploit temporal observations. DGGT (Chen et al., 2026) pre-dicts dynamic masks to partition Gaussian maps, while StreetForward (Yu et al., 2026b) constructs motion-aware features through causal attention and predicts velocities and dynamic probabilities for Gaussian separation and temporal aggregation. In both methods, camera parameters and Gaussian geometry are recovered from backbone features that jointly aggregate static and dynamic image con-tent without explicitly static features isolation. Other approaches intervene earlier. MUT3R (Shen et al., 2025) derives motion cues from attention maps and suppresses dynamic interference in early 3Figure 2: Overview of S2D-Splat . DrivingScene (Hou et al., 2026) adopts a staged learning strat-egy that first establishes a static scene prior and subsequently trains a residual flow network with the static backbone frozen. S2D-Splat combines feature separation before camera and geometry estima-tion with directed, layer-wise static-to-dynamic guidance. After recovering camera parameters and static Gaussians, it reuses cached intermediate static features as fixed conditioning at corresponding layers of the dynamic branch. This preserves the established static representations while allowing dynamic tokens to use their geometric context throughout reconstruction. 

Motion Modeling in Dynamic Scenes. Feed-forward dynamic reconstruction methods represent temporal changes through several complementary mechanisms. STORM, Flux4D, and UFO-4D predict motion fields to align dynamic geometry (Yang et al., 2025; Wang et al., 2025c; Hur et al., 2026). ReconDrive models Gaussian motion via segment-wise velocities (Yu et al., 2026a), while Instant NuRec predicts piecewise-linear trajectories (NVIDIA, 2026). UniSplat fuses observations within a 3D latent scaffold (Shi et al., 2026), and Ground4D performs localized temporal Gaussian aggregation for off-road scenes (Wang et al., 2026b). Object-centric approaches offer another form of temporal organization: UFO uses object poses to guide dynamic modeling (Tan et al., 2026), while PointForward uses 3D boxes and scene graphs for instance-level motion propagation (Chi et al., 2026). D4RT (Zhang et al., 2026b) introduces a query-based formulation that independently decodes point positions across time from a global spatio-temporal representation, supporting both sparse and dense queries. Following this formulation, our motion decoder operates at the instance level, by querying fused static and dynamic features to estimate a selected instance’s pose at a re-quested timestep. The resulting transformations align its Gaussians across observations, supporting motion-aligned fusion and temporal interpolation. 

# 3 S2D-S PLAT 

We propose S2D-Splat , a pose-free feedforward reconstruction framework that achieves decoupling of static and dynamic reconstruction. To prevent dynamic noise from contaminating the static recon-struction, we first design a Motion-Static Separator that decouples the dynamic and static features (§ 3.1). Building on these separated features, we adopt a two-stage reconstruction strategy that con-structs the static and dynamic Gaussian fields separately: once static reconstruction is shielded from 4dynamic objects, the dynamic objects are in turn reconstructed with reference to this clean static scene information (§ 3.2). The framework is static-first : separation precedes camera and geometry estimation, and the two stages are coupled by asymmetric layer-wise feature guidance . Finally, inspired by D4RT (Zhang et al., 2026b), we introduce a target-driven motion decoder that directly estimates each dynamic object’s overall relative motion between frames, rather than aggregating point-wise motion (§ 3.3). Once the static and dynamic tokens have been separated, we initiate a two-stage reconstruction pro-cess: a static reconstruction stage, referred to as Stage 1 below, followed by a dynamic reconstruction stage, referred to as Stage 2 below. 5Static Reconstruction Stage 1 takes the static tokens ˜F ts from the Motion-Static Separator and processes them through L layers of alternating attention (Wang et al., 2026a). Because direct atten-tion to dynamic key positions is masked, the static branch is less exposed to dynamic content and can focus on static scene geometry, although residual dynamic information may remain. At every layer, the camera and static tokens are cached into the Tokens Bank , later reused by Stage 2 to condition dynamic reconstruction. The resulting multi-layer tokens are decoded by three dedicated heads. The 

camera head refines the camera and register tokens through a cross-frame self-attention trunk to de-code each frame’s camera-to-world extrinsics and intrinsics. The depth head and Gaussian head 

instead operate on the patch tokens: both fuse features from several intermediate backbone layers through a shared DPT-style multi-scale fusion pyramid, before a final convolutional layer predicts, at every pixel, a depth value with confidence for the depth head and a set of Gaussian attributes for the Gaussian head, namely opacity, spherical-harmonic color, scale, and rotation. The predicted depth is combined with the camera pose and intrinsics and back-projected to obtain each Gaussian’s 3D center in world coordinates, which, with the remaining attributes, instantiates the static 3D Gaussian field. 

Dynamic Reconstruction Stage 2 reconstructs the dynamic tokens from the Motion-Static Sep-arator. To fully exploit the static features from Stage 1, the clean static tokens and the dynamic tokens are first fused into combined tokens, which serve as the initial input to L layers of alternating attention. After each layer’s attention computation, only the dynamic tokens are extracted and fused with the cached static tokens retrieved from the Tokens Bank, to form the input to the next layer; the attention outputs at the camera and static positions are discarded rather than carried forward. We term this asymmetric layer-wise feature guidance : the cached static tokens act as fixed condition-ing the dynamic branch attends to but never modifies, so the static representations from Stage 1 are preserved while dynamic tokens draw on their geometric context:

We adopt a three-stage training strategy that mirrors the three-stage reconstruction pipeline (Sec-tion 3.2 and Section 3.3): Stage 1 supervises the static reconstruction together with camera esti-mation, Stage 2 supervises the dynamic reconstruction, and Stage 3 supervises the instance-level motion decoder once static and dynamic reconstruction are complete. 

Static-region loss. In Stage 1, we supervise the static reconstruction with the loss function: 

Lstatic = λ1 ℓstatic rgb + λ2 ℓstatic depth + λ3 ℓcamera . (5) Here, ℓstatic rgb is the rendering loss used to supervise the static region, computed between the rendered and ground-truth frames restricted to static pixels; it mainly consists of an ℓ1 term, an SSIM term, and an LPIPS perceptual term (Zhang et al., 2018). ℓstatic depth supervises the static point cloud with a log-space ℓ1 regression term combined with a multi-scale gradient-consistency term; the supervision is applied in a scale-normalized space, with the ground-truth depth normalized by the scene’s median LiDAR depth. ℓcamera supervises the camera by comparing the predicted pose encoding to the ground truth with an ℓ1 loss on the translation and focal-length components and a quaternion-based cosine loss on the rotation component. 

Dynamic-region and motion loss. In Stage 2, we train the model to reconstruct the dynamic region. In Stage 3, once static and dynamic reconstruction are complete, we train the instance-level motion decoder. The two objectives are 

Ldynamic = λ1 ℓdynamic rgb + λ2 ℓdynamic depth , Lmotion = ℓmotion . (6) Here, ℓdynamic rgb and ℓdynamic depth take the same form as ℓstatic rgb and ℓstatic depth (Eq. 5) in Stage 1, but are evaluated only over the dynamic region. ℓmotion supervises the motion of each dynamic instance: we compute the ℓ1 distance between the rigid motion predicted by the instance-level motion de-coder (Section 3.3) and the ground-truth relative rotation and translation of that instance between consecutive frames, and average the result over all instances. 

# 4 EXPERIMENTS 

4.1 EXPERIMENTAL SETTINGS 

We train the feed-forward model on the original training split of the Waymo Open Dataset (Sun et al., 2020), a widely used autonomous driving benchmark comprising real-world driving logs collected across diverse urban scenarios (798 scenes, approximately 190–200 frames each), and evaluate on the test split (202 scenes). To assess generalization , we conduct zero-shot experiments on both the nuScenes dataset (Caesar et al., 2020) and the MM-AU traffic accident dataset (Fang et al., 2024). MM-AU is the largest and most fine-grained multimodal accident dataset, comprising 58 accident categories, from which we select one scene per category for evaluation. To measure visual quality, we used standard image quality metrics including PSNR, SSIM (Wang et al., 2004), and LPIPS (Zhang et al., 2018); depth accuracy is measured with depth RMSE (D-RMSE), computed after scale alignment between the predicted and ground-truth depth. Camera pose accuracy is mea-sured with the standard AUC for camera pose estimation (Wang et al., 2025b) , computed as the area under the curve of the fraction of image pairs whose elative rotation and translation errors fall below angular thresholds of 3◦ and 30 ◦ (AUC@3 ◦ and AUC@30 ◦). Asymmetric layer-wise feature guidance. Table 5 evaluates our asymmetric layer-wise feature guidance, which at every layer fuses the dynamic tokens produced by the current layer with the corresponding cached static tokens retrieved from the Tokens Bank into a complete token set for the next layer. Removing this Tokens Bank fusion causes the dynamic branch to lose access to clean, accurate static priors, so it can no longer exploit this useful information when rendering the dynamic region, visibly lowering the fidelity of that region. 

Layer-wise guidance vs. input-only fusion. We compare layer-wise guidance with an input-only fusion baseline, where cached static tokens are injected into the dynamic branch only at its input and not in subsequent layers; all other settings remain unchanged. As shown in Table 5, layer-wise guidance performs better than input-only fusion. This gap may arise because layer-wise reinjection allows dynamic tokens at every layer to attend to the corresponding clean static tokens cached from the static branch, which provide a reliable geometric and camera reference during dynamic feature refinement, whereas in the input-only baseline, the static tokens gradually drift away from the accurate static background in subsequent layers. 

Instance-level motion decoder. To evaluate the motion decoder’s contribution, we replace it with a commonly used alternative: instance point clustering combined with TAPIP3D (Zhang et al., 2026a), an external point-tracking model, to estimate motion instead. Removing the decoder de-grades performance across all evaluated metrics (Table 5). This indicates that the motion decoder’s direct prediction of instance-level motion is more accurate than the alternative approach of geomet-ric cluster centroids tracked by an external pure-translation tracker, since the latter not only fails to predict rotation but is also prone to being biased by noise points from dynamic objects. 

# 5 CONCLUSION 

We presented S2D-Splat , a pose-free, feed-forward framework for static-first Gaussian reconstruc-tion of dynamic driving scenes. By separating static and dynamic features before camera and geome-try estimation, our method reduces dynamic interference during static scene recovery. Cached static features then provide fixed guidance to corresponding layers of the dynamic branch, preserving the established static representations while supplying geometric context for dynamic reconstruction. An instance-level motion decoder further queries the fused scene features to estimate object poses, sup-porting motion-aligned Gaussian fusion and temporal interpolation. Experiments on Waymo and zero-shot evaluations on nuScenes and MM-AU demonstrate the effectiveness and cross-domain generalization of this design, including on highly dynamic pre-collision clips. 

Limitations and Future Work. Our pipeline requires a 2D box prompt for each dynamic instance when standard 3D boxes are unavailable; these prompts must be drawn manually or selected from a 2D detector, which limits scalability. Moreover, reconstruction errors are not fed back to revise the initial instance masks, so segmentation errors may affect both reconstruction stages. Instance-level motion estimation also still has substantial room for improvement. Future work will develop an agent-driven workflow to automate prompt generation or selection, jointly refine masks with reconstruction feedback, and further improve motion estimation. 10 AI U SE STATEMENT

# A SKY MODELING 

The sky has no finite depth and no rigid 3D structure, so folding it into the static or dynamic Gaussian field would force those networks to explain infinite-depth content with a finite-depth representation. We instead exclude the sky entirely from the scene branch, masking the predicted opacity of scene Gaussians to zero at every sky pixel, and model it with a separate sky Gaussian model, following the sky representation of DGGT (Chen et al., 2026), shared across all frames in the input window. Sky Gaussians lie on a sphere of fixed radius R centered at the world origin, with N =90 ,000 points 

{di} drawn from a Fibonacci sphere sampling scheme for an approximately uniform angular distri-bution, giving means μi = R di. Each point’s scale is fixed (not learned) from the average distance to its 3 nearest neighbors on the sphere, so neighboring sky Gaussians overlap smoothly; opacities and orientations are likewise fixed, so only color is estimated from the input images. Each μi is projected into every view of the window, and a sample is valid only if it lands in front of the camera, inside the image bounds, and on a pixel labeled sky by that view’s sky mask; the raw color ¯ci is the average of valid samples across views, and points with no valid sample in any view are discarded. # B CAMERA POSES AND GAUSSIAN FUSION AT UNOBSERVED TIMESTAMPS 

Camera pose construction. Beyond the world-coordinate transformation described in Sec-tion 3.3, the camera pose at an unobserved timestamp is constructed from the predicted camera-to-world (c2w) extrinsics of the two adjacent reconstructed keyframes, where the c2w extrinsic denotes the rigid transform that maps points from the camera coordinate frame to the world frame. 15 For a target timestamp t bracketed by keyframe timestamps t0 and t1, we first compute its relative position α = ( t − t0)/(t1 − t0). The translation is linearly interpolated as 

Tt = (1 − α) T0 + α T1

The rotation is not interpolated at the matrix level: the endpoint rotation matrices are first projected back onto the space of valid rotations via SVD orthogonalization (with a sign correction on the sin-gular vectors when the determinant is negative), converted to unit-quaternion form, and interpolated with spherical linear interpolation (SLERP) to obtain Rt. The interpolated rotation and translation are then assembled into the target c2w pose, which is inverted to obtain the world-to-camera (w2c) transform required for rasterization. Since the camera poses and the Gaussians are predicted in the same coordinate system, the target camera can directly render the predicted scene without estimating any additional rigid registration. 

Motion-aligned Gaussian fusion and deduplication. Rendering an unobserved timestamp re-quires, for each dynamic instance, fusing the Gaussians predicted at the two bracketing keyframes, while removing duplicated copies that would otherwise appear as ghosting. The Gaussians of the two bracketing keyframes are first aligned to the target timestamp using the instance’s predicted rigid motion, which consists of a translation offset and a rotation around the instance center, so that the fusion depends only on the instance’s relative motion. The motion is applied fractionally in time, forward from keyframe t0 with the fraction α or backward from keyframe t1 with the fraction 

1 − α: the Gaussian means are transformed accordingly, and each Gaussian’s orientation quaternion is composed with the corresponding rotation via quaternion multiplication, which is equivalent to rotating its covariance as 

Σ 7 → R Σ R⊤,

and keeps anisotropic Gaussians correctly oriented under the warp. Deduplication then follows a nearest-first, visibility-gated scheme: the warped Gaussians from the temporally nearer keyframe (α < 0.5 selects t0, otherwise t1) constitute the main render, and those from the farther keyframe are composited only at pixels where the accumulated alpha of the main render falls below a hole thresh-old ( 0.2). The gate distinguishes the two cases that require opposite treatments: surfaces visible in both keyframes are represented solely by the nearer, more reliable copy, while surfaces observed in only one keyframe, such as those occluded in the near view, are still filled by the farther copy, avoiding the missing regions that a hard selection alone would introduce. If the gate is removed and the two sources instead receive complementary time weights (1 − α) and α, the scheme degenerates into a linear cross-fade of the two reconstructions, in which both copies remain semi-transparent at intermediate times; the visibility-gated selection instead keeps each surface sharp at any α.

# C IMPLEMENTATION DETAILS 

Each frame is encoded by a frozen DINOv3 (Siméoni et al., 2025) image encoder. Training uses the same single-camera input configuration as evaluation: 8 input frames sampled at a stride of 5, with the intermediate frames held out and used as interpolated novel views for supervision. At inference, each dynamic instance only needs a single 2D box in one frame, and SAM2 is prompted with this box to obtain that instance’s dynamic mask across all frames; during training, we instead project each instance’s annotated 3D bounding box in the training set into a 2D box to speed up data processing. The Motion-Static Separator’s alternating-attention backbone consists of 3 layers, while the backbone used in the static and dynamic reconstruction stages consists of 21 layers; both are initialized from frozen VGGT-Ω (Wang et al., 2026a) weights and fine-tuned with LoRA adapters. The Gaussian head shares its architecture with the depth head, and the motion decoder consists of 6 cross-attention layers. Training follows a three-stage scheme: Stage 1 trains the static Gaussian reconstruction network while caching intermediate features in a Tokens Bank; Stage 2 trains the dy-namic Gaussian reconstruction network conditioned on these static priors once static reconstruction reaches sufficient quality; and Stage 3 trains the motion decoder on the resulting static and dynamic global features to estimate each instance’s overall motion. All stages use the AdamW optimizer with a base learning rate of 1 × 10 −4 and weight decay of 1 × 10 −4, and are trained on 8 H20 GPUs with a batch size of 8. The backbone itself remains frozen throughout and is only adapted through its LoRA parameters. All three stages are trained for 50 epochs each. In Stage 1, the static loss weights (Eq. 5) are set to λ1=1 .0, λ2=0 .8, λ3=2 .0, with the rendering term ℓstatic rgb itself combin-ing an ℓ1 term, an SSIM term, and an LPIPS term with weights 1, 0.5, and 0.3, respectively. In 16 Stage 2, the dynamic loss weights (Eq. 6) are set to λ1=1 .0, λ2=0 .8, with ℓdynamic rgb using the same 

ℓ1/SSIM/LPIPS weighting as Stage 1. 

Box prompts at test time. Since all metrics are computed on the test split of each benchmark, the ground-truth 3D bounding boxes can be directly exploited to generate box prompts by project-ing them into the image plane. For practical applications where ground-truth 3D annotations are unavailable, we adopt a purely 2D alternative: an off-the-shelf 2D detector such as YOLO first produces all candidate boxes in the video; since objects with small motion amplitude or at long distances have limited influence on reconstruction quality, a human operator can filter out the key moving instances from these candidates; the 2D detection box of a randomly selected frame is then used as the prompt for SAM2 (Ravi et al., 2025), which generates the instance’s 2D masks across all frames. 

Target view construction on Waymo. In the Waymo evaluation, the target views are the inter-mediate frames between each pair of adjacent reconstructed keyframes. As part of offline prepro-cessing, SegFormer (Xie et al., 2021) is run on every RGB frame used in the benchmark, including both the reconstruction keyframes and the intermediate target frames; the resulting sky masks are archived by frame index. The keyframe masks are used when constructing the sky model, while the target-view mask is read together with the frame’s ground-truth intrinsics and the ground-truth camera pose computed from the ego pose when the intermediate-frame data is loaded, and is used only for sky compositing. The rendering, however, does not directly use the ground-truth pose of the target frame: following Section B, the target camera is interpolated from the predicted cameras of the two bracketing reconstructed keyframes according to its timestamp, with the rotation obtained by SLERP and the translation and intrinsics obtained by linear interpolation, which keeps the target camera in the same coordinate system as the predicted Gaussian scene. Consequently, no addi-tional rigid alignment of the target camera is needed: the camera is itself derived by interpolating the predicted camera parameters of the two reconstructed keyframes, and therefore shares the same predicted coordinate frame with the Gaussian field back-projected from those cameras. In practical deployment, when no pre-generated sky mask is available for the target view, we instead adopt the sky-Gaussian fusion strategy described in Appendix A: sky regions correspond to the locations where the accumulated opacity of the static and dynamic Gaussians is insufficient, and the final image is obtained by blending the scene rendering with the sky rendering at these locations. 

Baseline settings. Since most of the selected baselines were originally trained on the Waymo dataset, we initialize them directly with their released pretrained weights. For the methods that require adaptation, we fine-tune them following each baseline’s own training recipe without any additional architectural modification; their input consists only of multi-frame RGB images, and their motion supervision follows their respective motion modeling.
